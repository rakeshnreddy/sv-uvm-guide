  ## Lab Setup

  Launch the interactive Hang Lab below to reproduce three common deadlocks:
  1. **Missing `item_done()`** – Driver forgets to release the sequencer.
  2. **Stuck objection** – Component keeps a phase [objection](/curriculum/T2_Intermediate/I-UVM-1C_UVM_Phasing) raised after stimulus ends.
  3. **Sequencer `grab()` leak** – A still-running interrupt sequence never calls `ungrab()`.

  For each scenario, read the log first, then probe the testbench before you name a suspect: which process is blocked, who holds an objection, and whether the sequencer is grabbed.

  <DebuggingSimulator scenario="hang" />

  Each scenario gives you the simulation log (rerun it with `+UVM_OBJECTION_TRACE`), three probes of the testbench state at the end of the run, and a set of fixes that the model reruns. Your task: name the component that owns the hang, choose the fix, and confirm the run now ends on its own.

  ## Guided Checklist

  - Enable `+UVM_OBJECTION_TRACE` and inspect which component holds the phase open; `phase.get_objection().display_objections()` prints the same answer as a table.
  - Check how the run ended: a `PH_TIMEOUT` fatal means something kept the run phase open until the timeout (`+UVM_TIMEOUT` or `uvm_top.set_timeout()`).
  - Look at driver logs to ensure every `get_next_item()` is paired with `item_done()`. A second `get_next_item()` without `item_done()` reports "Get_next_item called twice without item_done or get in between".
  - For `grab()` leaks, ask the sequencer: `is_grabbed()` and `current_grabber()` name the sequence holding it; `print()` on the sequencer shows its state.

  ## Reflection Prompts

  - Which log or trace gave you the decisive clue?
  - Could a custom watchdog or callback detect the issue earlier?
  - How would you write a regression check to prevent the bug from reappearing?

  ## Next Steps

  - Integrate lessons learned into your base test: set a run-phase timeout, keep objection tracing one switch away, and raise objections in tests and sequences (a scoreboard may hold one while a compare is pending) — never per item in a driver. Every raise needs a drop on every code path.
  - Share a short retro with your team—document the symptom, signal, and resolution so future debugging starts faster.
  - Continue with [E-DBG-1: Advanced UVM Debug Methodologies](/curriculum/T4_Expert/E-DBG-1_Advanced_UVM_Debug_Methodologies) for broader instrumentation patterns.
