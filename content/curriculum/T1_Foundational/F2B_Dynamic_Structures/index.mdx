## Quick Take
- **What it is:** SystemVerilog collections that resize at run time (`dynamic array`), grow and shrink at either end (`queue`), or map sparse keys (`associative array`).
- **Why it matters:** Choosing the wrong structure wastes sim time, hides ordering bugs, or burns memory. Most real bugs here are silent: a wiped array, a dropped queue entry, or a default value read from a missing key.
- **The Analogy:** A dynamic array is a tray you replace (`new[N]`) rather than stretch. A queue is a conveyor belt, optionally with a hard end stop. An associative array is a drawer cabinet that is always sorted by label.
- **The Standard:** IEEE 1800-2023 §7.4–§7.10 (arrays) and §7.12 (array manipulation methods).

### Decision Matrix: Which Structure For What?

| Scenario | Best Choice | Why | Avoid |
|----------|-------------|-----|-------|
| Scoreboard tracking outstanding TXNs by ID | **Associative array** (keyed by ID) | Sparse lookup by ID, `exists()` checks, explicit cleanup with `delete(id)` | Dynamic array (wastes memory for sparse IDs) |
| Driver stimulus sequence of packets | **Queue** | Preserves arrival order, push/pop at ends | Associative array (ordered by key, not by arrival) |
| Per-lane results, lane count read from a plusarg | **Dynamic array** | `new[n_lanes]` once, then write any index in any order | Queue (writing past `size()` is an invalid index) |
| Monitor collecting variable-length bursts | **Queue** | Unknown length, `push_back` grows it by one | Dynamic array (no `push_back`; every resize is `new[n+1](arr)`) |
| Protocol field lookup table | **Associative array** (keyed by enum/string) | Self-documenting, sparse | Queue (linear search for every lookup) |

What the lab should have taught you:

- `arr = new[N]` is a fresh array: every element restarts at its type's default, which is `x` for 4-state `logic` and `0` for 2-state `int` (§7.5.1, Table 7-1). Only `arr = new[N](arr)` keeps the old values.
- An invalid index never stops the simulation. A read returns the default value; a write does nothing. Either may warn (§7.4.5).
- Associative arrays do not remember insertion order. `first()`, `next()` and `foreach` follow index order, and `"Gamma"` comes before `"alpha"` because uppercase letters have smaller character codes (§7.8.2).
- Reading a missing key returns the default with a warning and does **not** create the entry; `exists()` asks without warning (§7.8.6, §7.9.3).

### Bounded Queues: What Gets Thrown Away?

The same program runs on `int q[$]` and on `int bq[$:N]`. Predict what the bounded queue keeps, then find the first step where the two diverge. Pay attention to which end loses an element.

<QueueOperationLab />

The rule (§7.10.5): every write to a bounded queue first behaves as if the queue were unbounded; then every element beyond index N is discarded and a warning is issued. So `push_back` on a full queue loses the **new** item, but `push_front` and a middle `insert()` lose the **old last** item. Nothing blocks. If you need backpressure, check `size()` yourself before you push.

### Packed vs. Unpacked: One Rule

Packed dimensions sit before the name; unpacked dimensions sit after it. When you index, you write the unpacked indices first, then the packed ones. In that list the rightmost index varies fastest, and every packed dimension varies faster than every unpacked one (§7.4.4). For `bit [3:0][7:0] joe [1:10];`, `joe[9]` is a 32-bit element, `joe[9][3]` is its top byte, and `joe[9][3][7]` is a single bit.

Set the dimensions below, then pick indices and press **Find bit**. The 2D view lists every unpacked element as a row and its packed bits from MSB to LSB. The 3D view draws the same order, but it is a picture of index order, not of simulator memory: the LRM defines how arrays are indexed and assigned, not how they are stored.

## Code Patterns You'll Use Daily

### Dynamic Array — Resize and Preserve

```systemverilog
// IEEE 1800-2023 §7.5.1 — dynamic array new[]
logic [7:0] buffer [];

initial begin
  buffer = new[4];           // 4 elements, each 8'hxx (logic is 4-state)
  foreach (buffer[i]) buffer[i] = i * 10;

  buffer = new[8](buffer);   // Grow to 8, PRESERVE the first 4 elements
  // buffer[0..3] = {0, 10, 20, 30}, buffer[4..7] = {8'hxx, 8'hxx, 8'hxx, 8'hxx}

  buffer = new[2](buffer);   // Shrink to 2, TRUNCATES
  // buffer = {0, 10} — elements [2..7] are LOST

  buffer.delete();           // Empty the array; buffer.size() == 0
end
```

> [!WARNING]
> **Common bug:** `buffer = new[8]` without the initializer `(buffer)` allocates a fresh array and **discards all existing data** (§7.5.1). Pass the old array whenever you resize and want to keep its contents. New slots get the type default: `x` for 4-state types such as `logic`, `0` for 2-state types such as `int`.

### Queue — Bounded Buffer With Your Own Backpressure

```systemverilog
// IEEE 1800-2023 §7.10, §7.10.5
typedef struct { int id; bit [31:0] data; } txn_t;

txn_t pending_q [$:63];  // bound 63 is the last legal index: at most 64 entries

function automatic bit enqueue(txn_t t);
  if (pending_q.size() == 64) begin
    $warning("Queue full, dropping TXN id=%0d", t.id);  // your message, with context
    return 0;
  end
  pending_q.push_back(t);  // without the check, a 65th item is discarded with only a tool warning
  return 1;
endfunction

task automatic dequeue(output txn_t t);
  wait (pending_q.size() > 0);  // queues never block on their own
  t = pending_q.pop_front();
endtask
```

> [!TIP]
> **Performance:** §7.10 describes a queue as supporting constant-time insertion and removal at either end and constant-time access to every element. It promises nothing for `insert()` or `delete(i)` in the middle, which simulators typically implement by moving elements. Profile before you build a hot path on them.

### Associative Array — Transaction Tracking

```systemverilog
// IEEE 1800-2023 §7.8, §7.9 — associative array with int key
class scoreboard extends uvm_component;
  `uvm_component_utils(scoreboard)
  txn_t expected_txns [int];  // keyed by transaction ID

  function new(string name, uvm_component parent);
    super.new(name, parent);
  endfunction

  function void add_expected(txn_t t);
    if (expected_txns.exists(t.id)) begin
      `uvm_error("DUPE", $sformatf("TXN id=%0d already pending", t.id))
      return;                     // keep the original expectation
    end
    expected_txns[t.id] = t;
  endfunction

  function void check_actual(txn_t actual);
    if (!expected_txns.exists(actual.id)) begin   // exists() never warns
      `uvm_error("UNEXPECTED", $sformatf("TXN id=%0d not in expected map", actual.id))
      return;
    end
    // Compare fields...
    expected_txns.delete(actual.id);  // Clean up after match
  endfunction

  function void check_phase(uvm_phase phase);
    if (expected_txns.num() > 0)
      `uvm_error("LEAK", $sformatf("%0d unmatched TXNs remain", expected_txns.num()))
  endfunction
endclass
```

> [!IMPORTANT]
> **Memory leak pattern:** If you never `delete()` matched entries, the associative array grows without bound during long regressions. Always clean up completed transactions. And never read `expected_txns[id]` for an ID that might be missing: you get a default-valued struct and a warning, not an error (§7.8.6).

### Array Manipulation Methods

```systemverilog
// IEEE 1800-2023 §7.12
module array_methods_demo;
  int       data_q [$] = '{3, 1, 4, 1, 5, 9, 2, 6};  // module scope: initializers allowed
  bit [7:0] bytes  [$] = '{200, 100};
  int       total;
  int       idx [$], mx [$], uniq [$];

  initial begin
    // Reductions return the element type, or the type of the with expression (§7.12.3)
    total = data_q.sum();                        // 31
    total = bytes.sum();                         // 44: 300 wraps to 8 bits BEFORE it reaches total
    total = bytes.sum() with (int'(item));       // 300
    total = data_q.sum() with (int'(item > 4));  // 3: counts matches

    // Locators always return a queue, even for one value (§7.12.1)
    idx  = data_q.find_index with (item > 4);    // '{4, 5, 7}
    mx   = data_q.max();                         // '{9}   (int m = data_q.max(); does not compile)
    uniq = data_q.unique();                      // one copy of each value; order unspecified

    // Ordering methods are void, work in place, and are illegal on associative arrays (§7.12.2)
    data_q.sort();                               // '{1, 1, 2, 3, 4, 5, 6, 9}
    data_q.rsort();                              // '{9, 6, 5, 4, 3, 2, 1, 1}
    data_q.reverse();                            // '{1, 1, 2, 3, 4, 5, 6, 9}
    data_q.shuffle();                            // random permutation
  end
endmodule
```

Now predict before you look. Pick a method and a `with` clause, commit to an answer, and check the return type the explorer reports. Try `sum()` on `bit [7:0]` first, then `max()`, then `sort()` on `data[string]`.

## Deeper Understanding

### Common Implementation Characteristics by Structure

Only the queue rows marked † are described by the LRM (§7.10). Everything else is a rule of thumb about typical simulators, not an IEEE guarantee.

| Operation | Dynamic Array | Queue | Associative Array |
|-----------|:---:|:---:|:---:|
| Random access `[i]` | O(1) | O(1) † | O(log N) or O(1) amortized |
| `push_back` / `push_front` | N/A (no such method) | O(1) † | N/A |
| `insert(mid)` | N/A | O(N) | N/A |
| `delete(key)` | N/A | O(N) | O(1) amortized |
| Resize / `new[N]` | O(N) copy | N/A | N/A |
| Memory overhead | Often low | Implementation-dependent | Implementation-dependent |
| `foreach` iteration | O(N) | O(N) | O(N), index order |

### Corner Cases Interviewers Love

1. **What happens if you pop from an empty queue?**
   §7.10.2.4 and §7.10.2.5 define it: the call returns the value Table 7-1 gives for a nonexistent entry (`'0` for `int`, `'x` for `logic`), leaves the queue unchanged, and may issue a warning. Nothing stops, so check `size() > 0` before popping.

2. **Can a dynamic array hold classes?**
   Yes. `my_class handles [];` is valid. But `new[N]` creates N null handles, not N objects (the default for a class is `null`). You must `new()` each element individually.

3. **What is the iteration order of an associative array?**
   `foreach`, `first()` and `next()` follow index order: signed or unsigned numeric order for integral keys (§7.8.4) and lexicographic character-code order for strings, so `"Zed"` comes before `"apple"` (§7.8.2). Insertion order is not kept.

4. **Can you assign a queue to a dynamic array?**
   Yes. A queue, dynamic array or fixed-size array of equivalent element type is assignment compatible, and a dynamic-array or queue target is resized to the source (§7.6). `int da []; int q [$] = '{1,2,3}; da = q;` leaves `da` with 3 elements. Associative arrays are the exception: they only assign to associative arrays (§7.9.9).

5. **What is a bounded queue and when should you use one?**
   Declared as `type q [$:N]`, it holds at most N+1 elements. §7.10.5 defines overflow: after any write, elements beyond the bound are discarded and a warning is issued. `push_back` on a full queue loses the new element, while `push_front` loses the old last one. Use a bound to model a fixed-depth FIFO, and still check `size()` when you need to count or report drops yourself.

## Make It Work

A checklist for every container you declare:

1. **Unknown count, ordered:** use a queue and `push_back`. **Count known at run time, random writes:** a dynamic array sized once with `new[N]`. **Sparse keys:** an associative array.
2. **Resize to keep data** only with `arr = new[N](arr)`. Plain `new[N]` wipes the array.
3. **A bound is not backpressure.** `[$:N]` discards and warns. If the producer must wait or count drops, check `size()` before you push.
4. **Never read an associative array blindly.** Call `exists()` first, or declare a default such as `int hits[string] = '{default: 0};` so missing keys read as 0 without a warning (§7.9.11).
5. **Capture locator results in a queue** (`int r[$] = q.max();`) and **cast inside `with`** whenever a sum can outgrow the element type.
6. **Delete matched scoreboard entries** and check `num()` at the end of the test.

## Push Further

- **Never resize what you are iterating.** If a dynamic array, queue or associative array changes size inside a `foreach` over it, the results are undefined (§12.7.3). Collect the keys first, then delete: `int done[$] = exp.find_index with (item.matched); foreach (done[i]) exp.delete(done[i]);`. For an associative array, `find_index` returns a queue of the index type (§7.12.1).
- **Queues of class handles store handles, not copies.** A monitor that reuses one transaction object and pushes it every cycle fills the queue with the same handle, so every entry shows the last value (§8.4, §8.12). Create or clone a new object per item before `push_back`.
- **Defaults change the warning story.** An associative array declared with `'{default: v}` returns `v` for a missing key without a warning (§7.9.11), and `a[k]++` on a missing key allocates the entry with that default first (§7.8.7). That is the idiom for hit counters.
- **What the models above do not cover:** iterator and index arguments (`find(x) with (x.id > 4)`), struct elements, multidimensional dynamic arrays, and wildcard `[*]` indices. Use a simulator for those.
