  ## Elevator Pitch

  A `uvm_sequence_library` is itself a sequence. It holds a list of sequence types and, when started, runs a number of them, chosen by its selection mode. Register your scenario sequences once and a test can run a random mix of them with one `start()` call.

  ## Building a Library

  ```systemverilog
  // The library: a uvm_sequence_library parameterized by the item type
  class mem_seq_lib extends uvm_sequence_library #(mem_item);
    `uvm_object_utils(mem_seq_lib)
    `uvm_sequence_library_utils(mem_seq_lib)

    function new(string name = "mem_seq_lib");
      super.new(name);
      init_sequence_library();        // copies the registered types into this instance
    endfunction
  endclass

  // Each member registers itself with the library type
  class mem_atomic_write extends uvm_sequence #(mem_item);
    `uvm_object_utils(mem_atomic_write)
    `uvm_add_to_seq_lib(mem_atomic_write, mem_seq_lib)

    function new(string name = "mem_atomic_write");
      super.new(name);
    endfunction
    // body() as on the Layered Sequences page
  endclass

  // In the test: configure the selection, then start the library like any sequence
  task run_phase(uvm_phase phase);
    mem_seq_lib lib = mem_seq_lib::type_id::create("lib");
    lib.selection_mode   = UVM_SEQ_LIB_RANDC;   // every member once before any repeats
    lib.min_random_count = 5;
    lib.max_random_count = 10;
    if (!lib.randomize())                        // picks sequence_count in [5:10]
      `uvm_error("RAND", "library randomization failed")
    phase.raise_objection(this);
    lib.start(env.agt.sqr);
    phase.drop_objection(this);
  endtask
  ```

  **Walkthrough pointers**
  - `` `uvm_sequence_library_utils(mem_seq_lib) `` gives the library type its own static list of member types. `` `uvm_add_to_seq_lib(seq, lib) `` adds a sequence type to that list. `init_sequence_library()` in the constructor copies the list into the instance; forget it and the library reports `SEQLIB/NOSEQS` "Sequence library does not contain any sequences".
  - Members can also be added in code: `mem_seq_lib::add_typewide_sequence(mem_burst_program::get_type())` for every instance, or `lib.add_sequence(...)` for one instance.
  - `lib.start(sqr)` runs `sequence_count` member sequences on that sequencer. `randomize()` picks `sequence_count` between `min_random_count` and `max_random_count` (both 10 by default).

  ## Selection Modes

  | `selection_mode` | What the library runs |
  | --- | --- |
  | `UVM_SEQ_LIB_RAND` | a random member each time (repeats possible) |
  | `UVM_SEQ_LIB_RANDC` | random order, every member once before any repeats |
  | `UVM_SEQ_LIB_ITEM` | no member sequences: just `sequence_count` random items of the request type |
  | `UVM_SEQ_LIB_USER` | your `select_sequence(max)` override returns the index of the next member |

  There is no built-in per-sequence weight. To bias the mix, use `UVM_SEQ_LIB_USER` and override `select_sequence()`, or register a sequence type more than once. Library selection is also unrelated to sequencer arbitration: the library runs its members one after another on one sequencer, so `UVM_SEQ_ARB_WEIGHTED` and `set_priority()` only matter when other sequences compete with it.

  ## grab()/ungrab(): Use Sparingly

  - `grab()` puts a lock request at the front of the arbitration queue. When granted, every other sequence is blocked until `ungrab()`. It cannot take the sequencer away from a sequence that already holds a lock; it only waits at the front of the line.
  - Keep `grab()` … `ungrab()` short and in one task, with nothing in between that can block forever. SystemVerilog has no exceptions or `finally` block, so a killed process or a `disable` skips the `ungrab()`.
  - Prefer `lock()` or priorities when you do not need to jump the queue.
