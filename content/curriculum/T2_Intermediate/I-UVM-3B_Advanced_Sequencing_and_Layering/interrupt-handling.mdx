  ## Elevator Pitch

  Real silicon fires interrupts at awkward times. Turn each interrupt into a transaction, queue it, and let a virtual sequence service the queue: acknowledge, recover, resume. No `#delay` guesses and no lost interrupts.

  ## Event-Driven Interrupt Flow

  The monitor detects the interrupt and publishes it. A router subscribes and queues a copy. A background virtual sequence takes interrupts from the queue and starts the recovery sequences.

  ```systemverilog
  class irq_monitor extends uvm_monitor;
    `uvm_component_utils(irq_monitor)
    uvm_analysis_port #(irq_tr) ap;
    virtual irq_if vif;                         // set in build_phase

    function new(string name, uvm_component parent);
      super.new(name, parent);
    endfunction

    function void build_phase(uvm_phase phase);
      super.build_phase(phase);
      ap = new("ap", this);
    endfunction

    virtual task run_phase(uvm_phase phase);
      forever begin
        irq_tr tr;                              // declarations come first in a block
        @(vif.mon_cb iff vif.mon_cb.irq);
        tr = irq_tr::type_id::create("tr");     // a new object per interrupt
        tr.vector = vif.mon_cb.irq_vector;
        ap.write(tr);
      end
    endtask
  endclass

  class irq_router extends uvm_subscriber #(irq_tr);
    `uvm_component_utils(irq_router)
    mailbox #(irq_tr) pending = new();          // unbounded

    function new(string name, uvm_component parent);
      super.new(name, parent);
    endfunction

    // write() is a function: it may not call the put() task, so use try_put()
    virtual function void write(irq_tr t);
      irq_tr copy;
      $cast(copy, t.clone());                   // clone() returns uvm_object
      void'(pending.try_put(copy));             // always succeeds on an unbounded mailbox
    endfunction
  endclass

  class soc_vsqr extends uvm_sequencer;
    `uvm_component_utils(soc_vsqr)
    cfg_sequencer  cfg_sqr;
    data_sequencer data_sqr;
    irq_router     router;                      // all three assigned in env.connect_phase

    function new(string name, uvm_component parent);
      super.new(name, parent);
    endfunction
  endclass

  class irq_recover_vseq extends uvm_sequence;
    `uvm_object_utils(irq_recover_vseq)
    `uvm_declare_p_sequencer(soc_vsqr)

    function new(string name = "irq_recover_vseq");
      super.new(name);
    endfunction

    virtual task body();
      irq_tr tr;
      if (p_sequencer.router == null)
        `uvm_fatal("IRQ", "env did not assign soc_vsqr.router")
      forever begin
        p_sequencer.router.pending.get(tr);     // blocks until an interrupt is queued
        handle_irq(tr);
      end
    endtask

    task handle_irq(irq_tr tr);
      clear_irq_seq clear  = clear_irq_seq::type_id::create("clear");
      replay_seq    replay = replay_seq::type_id::create("replay");
      clear.vector = tr.vector;
      clear.start(p_sequencer.cfg_sqr);         // clear_irq_seq can grab() cfg_sqr to jump the queue
      if (tr.requires_replay)
        replay.start(p_sequencer.data_sqr);
    endtask
  endclass

  // env.connect_phase
  //   mon.ap.connect(router.analysis_export);
  //   vsqr.cfg_sqr = cfg_agt.sqr;  vsqr.data_sqr = data_agt.sqr;  vsqr.router = router;
  ```

  **What to notice**
  - The monitor creates a new `irq_tr` for every interrupt. Reusing one object would make every queued entry point at the same, changing object.
  - `write()` must not block. That is why the router copies the transaction and uses `try_put()`; the waiting happens in the sequence, in `get()`.
  - `irq_recover_vseq` runs forever. Start it in the background from the test (`fork … join_none`) and do **not** let it hold the test's objection, or the test never ends.
  - If the recovery must pre-empt normal traffic on `cfg_sqr`, let `clear_irq_seq` call `grab()` before its items and `ungrab()` after. A grab waits at the front of the arbitration queue, ahead of every waiting request and lock.

  ## Design Patterns

  - **Debounce and coalesce:** track timestamps or vector history in the router to fold bursts of identical interrupts into one recovery action.
  - **Prioritize:** keep one queue per priority level (or sort in the router) when certain vectors must be serviced first.
  - **Coverage:** sample interrupt coverage in the router. It is a subscriber fed by the monitor, so it measures interrupts that really happened.
  - **Timeouts:** in the virtual sequence, race `get()` against a timer (`fork … join_any`, then `disable fork`) to flag an expected interrupt that never arrives.

  ## Checklist

  - [ ] Monitors own interrupt detection and publish one new transaction per interrupt.
  - [ ] Subscribers never block in `write()`.
  - [ ] Virtual sequences wait on queues or events instead of `#delays`.
  - [ ] Every handle the virtual sequence uses is assigned in `connect_phase` and checked for `null`.
