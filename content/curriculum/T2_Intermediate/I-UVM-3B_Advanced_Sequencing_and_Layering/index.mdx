## Quick Take
- **What it is:** Advanced sequencing coordinates several agents from one virtual sequence, controls which of several competing sequences a sequencer serves (arbitration, priority, `lock()`, `grab()`), layers one protocol on another (for example IP packets carried in Ethernet frames), and reacts to asynchronous events such as interrupts.
- **Why it matters:** As testbenches grow from blocks to SoCs, stimulus must stay coordinated and maintainable. A single `` `uvm_do `` loop on one agent no longer describes the test.

### Virtual sequences vs virtual sequencers

A **virtual sequence** controls other sequences across several agents. It sends no items to a driver itself; it starts sub-sequences on the agents' sequencers.

A **virtual sequencer** is one way to give the virtual sequence those sequencer handles: a `uvm_sequencer` with no driver that holds the handles, assigned in the env's `connect_phase`. The other common way skips the virtual sequencer: the test copies the handles into the virtual sequence and starts it with `vseq.start(null)`. Both are standard; page 2 shows each.
