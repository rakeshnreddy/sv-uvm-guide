## The "Why" of Virtual Sequences

In a complex DUT, several interfaces must work together. For example, you might need to write a configuration register over a slow I2C bus and then send a high-speed packet over Ethernet. Each interface has its own agent with its own sequencer. A **virtual sequence** is one sequence that starts and orders the sequences on all of them.

## Level 1: The Orchestra Conductor Analogy

- **Agent sequencers** are the musicians. Each plays its own instrument (drives its own interface).
- **The virtual sequencer** is the conductor's podium: it plays nothing, but it knows where every musician sits.
- **The virtual sequence** is the score: it says who plays when.

## Level 2: Core Mechanics

### The virtual sequencer

A virtual sequencer is a plain `uvm_sequencer` with no driver. It gives the virtual sequence a place to run and holds handles to the real agent sequencers. Those handles are ordinary class references, assigned in the env's `connect_phase`. There is no TLM connection between the virtual sequencer and the agents.

### The virtual sequence

A virtual sequence runs on the virtual sequencer, sends no items itself, and starts child sequences on the agent sequencers. A child runs on the sequencer passed to its `start()`.

## Level 3: Expert Insights

**Without a virtual sequencer.** Because a virtual sequence sends no items, it does not need a sequencer at all. Give the sequence its own handle fields, have the test assign them, and call `vseq.start(null)`. Do not use `p_sequencer` in that style: it only exists when the sequence runs on a typed sequencer.

**Ordering is your job.** `fork…join` runs children concurrently; sequential `start()` calls order them; `fork…join_none` returns immediately, so `body()` (and the test's `vseq.start()`) can finish before any item is driven. [UVM Virtual Sequencer: Dispatch Order](/curriculum/T2_Intermediate/I-UVM-3B_Advanced_Sequencing_and_Layering/uvm-virtual-sequencer) lets you predict and compare all three on a timeline.

**Retention tip:** Virtual sequencer = podium (holds handles). Virtual sequence = score (decides who plays when). Agent sequencers = musicians (each arbitrates its own items).
