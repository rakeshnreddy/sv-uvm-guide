## Quick Take
- **What it is:** UVM policy classes are pluggable strategies that define *how* an object's field data is processed — without touching the object's core logic.
- **Why it matters:** Without understanding policies, you are stuck with the default `print()` / `compare()` / `pack()` / `record()` / `copy()` behavior and cannot customize debug output, comparison tolerance, serialization layout, transaction recording, or deep-copy semantics.
- **The rule that bites:** `compare()` runs the field macros **and** your `do_compare()`. With the default comparer it stops counting after the **first** miscompare, and it reports miscompares as `UVM_INFO`, not errors. Your scoreboard must check the return value.
- **The Analogy:** Think of policy classes as lenses on a camera. The subject (your `uvm_object`) stays the same, but each lens reveals a different view: wide-angle for printing, macro for comparison, fisheye for packed transport.

> **Signal:** If you find yourself writing `$sformatf` wrappers around object fields instead of using `print()`, or manually copying fields one-by-one instead of `copy()`, it is time to learn policy classes.

## Build Your Mental Model

### The Five Policies

Every `uvm_object` has user hooks (`do_*`) that the policy operations call after the field automation:

| Policy Class | Hook Method | What It Does |
| --- | --- | --- |
| `uvm_printer` | `do_print()` | Formats the object's fields into a debug string (table, tree, or line) |
| `uvm_comparer` | `do_compare()` | Walks two objects field-by-field and counts miscompares |
| `uvm_packer` | `do_pack()` / `do_unpack()` | Serializes fields into a flat bitstream and back |
| `uvm_recorder` | `do_record()` | Writes transaction attributes to a recording database |
| `uvm_copier` | `do_copy()` | Copies registered fields. Object fields are deep-copied unless flagged `UVM_REFERENCE`; a hand-written `do_copy()` copies exactly what you write |

> **IEEE 1800.2-2020 reference:** `uvm_object` is §5.3. The policies are §16.2 (`uvm_printer`), §16.3 (`uvm_comparer`), §16.4 (`uvm_recorder`), §16.5 (`uvm_packer`) and §16.6 (`uvm_copier`). The field macros are in Annex B.

### How Policies Interact with Objects

When you call `pkt.print()`, UVM picks the default printer, prints the object header, runs the field automation, then calls your hook:

```systemverilog
// Simplified from uvm_object::print / sprint and uvm_printer::print_object (uvm-core 2020.3.1)
function void print(uvm_printer printer = null);
  if (printer == null) printer = uvm_printer::get_default();
  // printer.print_object(get_name(), this) then:
  //   1. prints the header row for this object
  //   2. runs the field macros            (do_execute_op with UVM_PRINT)
  //   3. calls YOUR hook                  (do_print(printer))
  // and finally emits the formatted text
endfunction
```

The same order holds for `compare()`, `copy()`, `pack()` and `record()`: **field macros first, then your `do_*` hook**. Adding a `do_compare()` to a class that has field macros does not turn the macros off; both run.

### Field Macros vs Manual Overrides

UVM provides two ways to wire fields into policy processing:

**1. Declarative macros (quick but heavy):**

```systemverilog
class my_packet extends uvm_sequence_item;
  `uvm_object_utils_begin(my_packet)
    `uvm_field_int(addr,   UVM_ALL_ON)
    `uvm_field_int(data,   UVM_ALL_ON)
    `uvm_field_int(parity, UVM_ALL_ON | UVM_NOCOMPARE) // skip in compare
    `uvm_field_int(id,     UVM_ALL_ON | UVM_NOPACK)    // skip in pack
  `uvm_object_utils_end
endclass
```

The macros implement field automation (`do_execute_op`). They do **not** write your `do_*` methods; those stay yours. Two flag rules matter:

- In IEEE 1800.2 a flag enables an operation only if it includes it. `UVM_NOCOMPARE` **alone** enables nothing: the field disappears from print, copy and compare, and UVM warns `UVM/FIELDS/NO_FLAG`. Always write `UVM_ALL_ON | UVM_NOCOMPARE`.
- `UVM_REFERENCE` on an object field makes copy share the handle and compare check handles, not contents.

**2. Manual overrides (precise and performant):**

```systemverilog
class my_packet extends uvm_sequence_item;
  `uvm_object_utils(my_packet)

  rand bit [31:0] addr;
  rand bit [31:0] data;
  rand bit        parity;
  rand bit [7:0]  id;

  function new(string name = "my_packet");
    super.new(name);
  endfunction

  virtual function void do_print(uvm_printer printer);
    super.do_print(printer);
    printer.print_field_int("addr",   addr,   32, UVM_HEX);
    printer.print_field_int("data",   data,   32, UVM_HEX);
    printer.print_field_int("parity", parity, 1,  UVM_BIN);
    printer.print_field_int("id",     id,     8,  UVM_DEC);
  endfunction

  virtual function bit do_compare(uvm_object rhs, uvm_comparer comparer);
    my_packet rhs_;
    if (!$cast(rhs_, rhs)) return 0;
    do_compare = super.do_compare(rhs, comparer);
    // Use the comparer so each miscompare is counted and reported
    do_compare &= comparer.compare_field_int("addr", addr, rhs_.addr, 32);
    do_compare &= comparer.compare_field_int("data", data, rhs_.data, 32);
    do_compare &= comparer.compare_field_int("id",   id,   rhs_.id,   8);
    // parity deliberately excluded from compare
  endfunction

  // ... do_pack, do_copy, do_record similarly
endclass
```

> **Trade-off:** many teams prefer hand-written `do_*` methods for speed and control, and keep field macros for prototypes. Whichever you choose, do not mix the two for the same field, or it is compared (and printed) twice.

## Make It Work

1. **Start with macros, graduate to manual:** Use `uvm_field_*` macros during early development, then replace them with manual `do_*` overrides in production code for performance and control.
2. **Decide what "equal" means for your scoreboard:** exclude infrastructure fields (sequence ids, timestamps) with `UVM_ALL_ON | UVM_NOCOMPARE`, or compare only the right fields in `do_compare()`. Then check the return value: `compare()` reports miscompares as `UVM_INFO`, so the scoreboard must raise its own `uvm_error`.
3. **Use a dedicated comparer to see every miscompare:** the default comparer has `threshold = 1` and `show_max = 1`, so it counts and prints only the first one. `cmp.set_threshold(0); cmp.set_show_max(10);` gives you the full list in `cmp.get_miscompares()`.
4. **Use `do_pack` for DPI export:** When interfacing with C/C++ reference models via DPI, `pack()` / `unpack()` give you a clean serialization boundary.
5. **Swap the default printer for debug:** call `uvm_printer::set_default(uvm_tree_printer::get_default());` at the start of your test. The UVM 1.2 global variable `uvm_default_printer` is not part of IEEE 1800.2.
6. **Copy before mutation, and know what the copy shares:** `clone()` is `create()` plus `copy()`. Nested objects are only duplicated if the copy implementation duplicates them; a hand-written `cfg = rhs_.cfg;` shares one object between both copies.

**Checklist before moving on:**
- [ ] You can name all five policy classes and their `do_*` hooks.
- [ ] You can explain the order: field macros first, then the `do_*` hook.
- [ ] You know that `UVM_NOCOMPARE` must be combined with `UVM_ALL_ON`.
- [ ] You can predict when `copy()` shares a nested object (`UVM_REFERENCE`, a hand-written handle assignment) and when it creates a new one.

## Push Further: Advanced Policy Customization

### Custom Comparer with Tolerance

```systemverilog
class tolerant_comparer extends uvm_comparer;
  `uvm_object_utils(tolerant_comparer)
  int unsigned tolerance = 2;

  function new(string name = "tolerant_comparer");
    super.new(name);
  endfunction

  // Same signature as uvm_comparer::compare_field_int (IEEE 1800.2 §16.3.3.2)
  virtual function bit compare_field_int(string name,
                                         uvm_integral_t lhs,
                                         uvm_integral_t rhs,
                                         int size,
                                         uvm_radix_enum radix = UVM_NORADIX);
    if (name == "data") begin
      longint diff = longint'(lhs) - longint'(rhs);   // signed difference
      if (diff < 0) diff = -diff;
      if (diff <= tolerance) return 1;                 // within ±tolerance: equal
    end
    return super.compare_field_int(name, lhs, rhs, size, radix);
  endfunction
endclass

// Use it explicitly: if (!exp.compare(act, tol_cmp)) `uvm_error(...)
```

The field macros pass the field name (here `"data"`) to `compare_field_int`, so the override can treat one field specially and leave every other field to the base class.

### Custom Recorder for Coverage Correlation

Override `do_record()` to attach extra metadata — like coverage-bin names or test phase — that your waveform correlation scripts can consume.

```systemverilog
function void do_record(uvm_recorder recorder);
  super.do_record(recorder);
  recorder.record_string("test_phase", "main_sequence");
  recorder.record_field_int("latency_ns", latency, 32, UVM_DEC);
endfunction
```
