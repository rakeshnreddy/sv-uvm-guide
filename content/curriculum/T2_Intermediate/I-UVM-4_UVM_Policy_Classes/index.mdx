## Quick Take

- **What it is:** When you call `print()`, `compare()`, `copy()`, `pack()` or `record()` on a UVM object, the work is done by a **policy object**: a `uvm_printer`, `uvm_comparer`, `uvm_copier`, `uvm_packer` or `uvm_recorder` (IEEE 1800.2-2020 §16.1–§16.6). The policy walks the object's fields. The object tells it which fields exist in two ways: the `` `uvm_field_* `` **field macros**, and the `do_*` **hooks** you write yourself (§5.3).
- **Why it matters:** a **scoreboard**, the testbench component that checks the design under test (DUT) against expected results, decides pass or fail with `compare()`, logs are only as useful as `print()` and `convert2string()`, a copy that secretly shares a sub-object corrupts expected data, and a pack/unpack pair that disagrees on field order scrambles every value. All of these fail silently unless you know the rules.
- **The rule that bites:** `compare()` returns a bit and logs each **miscompare** (one field whose two values differ) as a `UVM_INFO` line, not as an error. With the default comparer, the field macros stop comparing after the **first** miscompare (its **threshold**, the miscompare count at which the macros stop, is 1), and only one miscompare line is printed (its **`show_max`**, the most per-field lines it prints, is 1). Your scoreboard must check the return value and raise its own `` `uvm_error ``.
- **The Analogy:** Policies are lenses on a camera. The subject (your object) stays the same; the printer lens shows it as a table, the comparer lens lays it over another object, the packer lens flattens it into a stream. *Where it breaks:* a lens only looks, but `copy()` and `unpack()` **write** into the object, and the comparer lens can stop looking after its first finding.

**You will be able to:**
1. **Explain** how `print`, `compare`, `copy`, `pack` and `record` reach an object's fields: the policy, then the field macros (inside `do_execute_op`), then your `do_*` hook.
2. **Predict** what `compare()` returns, what `get_result()` counts and which `MISCMP` lines appear, for given field flags, threshold and `show_max`.
3. **Write** `do_compare`, `do_copy`, `do_print` and `convert2string` with the policy APIs, and a `do_pack`/`do_unpack` pair that round-trips.
4. **Configure** a comparer and a printer for a scoreboard or a log: threshold, `show_max`, severity and verbosity; table, tree or line printer.
5. **Choose** field macros (with `UVM_ALL_ON | UVM_NO*` flags) or hand-written hooks for a class, by performance, control and debuggability.

## Build Your Mental Model

**How to read this lesson.** You already met the object methods in [I-UVM-1A](/curriculum/T2_Intermediate/I-UVM-1A_Components/index): you call `compare()` and customise it in `do_compare()`. This lesson opens the box. The **core path** is the first five sections: how one call reaches your fields, the field-macro flags, `compare()` and its comparer, the Policy Explorer, and printing. **Practitioner depth** follows: copying, packing, choosing macros or hooks, and the common mistakes. Make It Work runs all of it in one test, and Push Further holds the expert corner cases.

Four terms, defined once:
- A **policy** is an object that carries out one operation on another object and holds that operation's settings (§16.1). One comparer can compare many objects; its settings, such as how many miscompares to print, are its **knobs**.
- A **hook** is a virtual method that UVM calls at a fixed point and that you override: `do_print`, `do_compare`, `do_copy`, `do_pack`, `do_unpack`, `do_record` (§5.3).
- **Field automation** is the code the `` `uvm_field_* `` macros generate between `` `uvm_object_utils_begin `` and `` `uvm_object_utils_end ``. It lives in a method called `do_execute_op`, and it applies the current operation to every registered field (§5.3.13, Annex B.2.2).
- A **flag** is the second argument of a field macro, such as `UVM_ALL_ON | UVM_NOCOMPARE`. It says which operations the field joins, which radix to print it in, and how to treat object handles (Annex B.2.2, F.2.1.8–F.2.1.9).

### One call, three layers: from compare() to your fields

Every object operation has the same three layers. You call the public method; it picks a policy; the policy asks the object for its fields twice, first through field automation, then through your hook.

| You call | Policy (IEEE 1800.2-2020) | Your hook | What the policy does |
| --- | --- | --- | --- |
| `print()`, `sprint()` | `uvm_printer` (§16.2) | `do_print(printer)` | Formats fields as a table, tree or one line |
| `compare(rhs)` | `uvm_comparer` (§16.3) | `do_compare(rhs, comparer)` | Compares two objects field by field and counts miscompares |
| `record(recorder)` | `uvm_recorder` (§16.4) | `do_record(recorder)` | Writes fields as attributes of a transaction record; with no recorder the call is silently ignored (§5.3.7.1). Recording flow: [I-UVM-6](/curriculum/T2_Intermediate/I-UVM-6_UVM_Recording_Classes/index) |
| `pack_bytes()`, `unpack_bytes()` | `uvm_packer` (§16.5) | `do_pack(packer)`, `do_unpack(packer)` | Serialises fields into a stream and back |
| `copy(rhs)`, `clone()` | `uvm_copier` (§16.6) | `do_copy(rhs)` | Copies fields from `rhs` into this object |

All five classes derive from `uvm_policy` (§16.1). The one carrying out the current operation travels inside a small **`uvm_field_op`** object (§5.7), which records the operation type (`get_op_type()`), the policy (`get_policy()`) and, for copy and compare, the other object (`get_rhs()`).

The same shape holds for every operation (§5.3.6.1, §5.3.8.1, §5.3.9.1, §5.3.10.1, §16.3.3.4, §16.5.4.2, §16.6.4.1):
1. For print, copy, compare, pack and unpack: if you pass no policy, the method uses the default one (`uvm_comparer::get_default()` and its siblings). `record()` has no default: with no recorder it does nothing (§5.3.7.1).
2. For print, copy, compare, pack and unpack: if the policy is not already working on an outer object (its active object depth is 0), the method calls the policy's `flush()` to clear old results.
3. The policy calls `do_execute_op()` with a `uvm_field_op`. Field automation runs here, base-class fields first, because the generated `do_execute_op` calls `super.do_execute_op` before its own fields.
4. If the op still has its **user hook enabled** (§5.7.2.7), the policy calls your `do_*` hook.

**The classic mistake.** "Once I write `do_compare()`, the macros stop comparing." Wrong: both run, and `compare()` returns 0 if the macros counted a miscompare **or** your hook returned 0 (§16.3.3.4 e). A field that appears in both is compared twice.

### Field macros and flags

The field macros sit between `` `uvm_object_utils_begin(T) `` and `` `uvm_object_utils_end ``. There is one per kind of member: `` `uvm_field_int ``, `` `uvm_field_enum(T, ARG, FLAG) ``, `` `uvm_field_string ``, `` `uvm_field_real ``, `` `uvm_field_object ``, and array, queue and associative-array forms such as `` `uvm_field_array_int `` and `` `uvm_field_aa_int_string `` (Annex B.2.2).

```systemverilog
// snippet: the field-macro bus_item used throughout this lesson
class bus_item extends uvm_sequence_item;
  rand bit [15:0] addr;
  rand bit [31:0] data;
  bit      [15:0] id;  // tracking number from the sequence, not DUT behaviour

  `uvm_object_utils_begin(bus_item)
    `uvm_field_int(addr, UVM_ALL_ON | UVM_HEX)
    `uvm_field_int(data, UVM_ALL_ON | UVM_HEX)
    `uvm_field_int(id,   UVM_ALL_ON | UVM_NOCOMPARE | UVM_DEC)
  `uvm_object_utils_end

  function new(string name = "bus_item");
    super.new(name);
  endfunction
endclass
```

A flag combines four kinds of bits:

| Kind | Values | Rule |
| --- | --- | --- |
| Operations (positive) | `UVM_COPY`, `UVM_COMPARE`, `UVM_PRINT`, `UVM_RECORD`, `UVM_PACK`; `UVM_ALL_ON` = all of them; `UVM_DEFAULT` = `UVM_ALL_ON` | A field joins an operation **only if** its flag includes it (F.2.1.8–F.2.1.10). B.2.2 pairs pack and unpack: `UVM_PACK` enables both, `UVM_NOPACK` disables both. uvm-core 2020.3.1 tests a separate `UVM_UNPACK` bit, so write `UVM_PACK \| UVM_UNPACK` (or `UVM_ALL_ON`) when you list operations explicitly (tool-dependent) |
| Exclusions (negative) | `UVM_NOCOPY`, `UVM_NOCOMPARE`, `UVM_NOPRINT`, `UVM_NORECORD`, `UVM_NOPACK` | A `UVM_NO*` bit wins over its positive bit, `UVM_ALL_ON` included (B.2.2) |
| Radix | `UVM_HEX`, `UVM_DEC`, `UVM_BIN`, … | How print, record and compare messages show the value; one radix per field |
| Recursion (object fields) | `UVM_DEEP` (the default), `UVM_SHALLOW`, `UVM_REFERENCE` | `UVM_REFERENCE`: copy shares the handle, compare checks the handle; uvm-core also leaves the field out of pack |

**The 1800.2 flag rule.** A flag with no positive operation bit enables **nothing**. So `` `uvm_field_int(id, UVM_NOCOMPARE) `` does not mean "everything except compare": `id` disappears from print, copy, compare and pack. The same happens to a radix-only flag such as `` `uvm_field_int(addr, UVM_HEX) `` and to a recursion-only `` `uvm_field_object(cfg, UVM_REFERENCE) ``. UVM 1.2 libraries silently added `UVM_ALL_ON`; 1800.2 does not (B.2.2, F.2.1.9). uvm-core 2020.3.1 warns once per field with ID `UVM/FIELDS/NO_FLAG`. Always write the positive part: `UVM_ALL_ON | UVM_NOCOMPARE`.

| Flag written | print | copy | compare | pack | uvm-core warning |
| --- | --- | --- | --- | --- | --- |
| `UVM_ALL_ON` (or no flag: `UVM_DEFAULT`) | yes | yes | yes | yes | — |
| `UVM_ALL_ON \| UVM_NOCOMPARE` | yes | yes | no | yes | — |
| `UVM_NOCOMPARE` | no | no | no | no | `UVM/FIELDS/NO_FLAG` |
| `UVM_HEX` | no | no | no | no | `UVM/FIELDS/NO_FLAG` |
| `UVM_COMPARE \| UVM_PRINT` | yes | no | yes | no | — |

### compare() and the comparer

`compare()` returns **1 if every compared field matches and 0 otherwise**. It never fails the test by itself. Each miscompare goes through the comparer's `print_msg()` (§16.3.3.7), which adds 1 to the count you read with `get_result()` (§16.3.3.9), appends a line to `get_miscompares()` (§16.3.3.8) and, if the count is still within `show_max`, reports it with ID `MISCMP`. When the top-level comparison fails, `compare()` then reports one summary line.

| Knob | Setter | Default | What it controls |
| --- | --- | --- | --- |
| Threshold | `set_threshold(n)` | 1 | Field macros and `` `uvm_compare_* `` macros skip the remaining fields once `get_result()` reaches `n`; 0 means compare everything (§16.3.6) |
| Messages shown | `set_show_max(n)` | 1 | How many per-field `MISCMP` lines are printed (uvm-core: 0 prints all). It never limits counting (§16.3.5.1) |
| Verbosity | `set_verbosity(v)` | `UVM_LOW` | Verbosity of the `MISCMP` messages; at `+UVM_VERBOSITY=UVM_NONE` they vanish (§16.3.5.2) |
| Severity | `set_severity(s)` | `UVM_INFO` | Severity of the `MISCMP` messages (§16.3.5.3) |
| Type check | `set_check_type(b)` | 1 | Compare the two objects' types before their fields (§16.3.4.2) |
| Recursion | `set_recursion_policy(p)` | `UVM_DEFAULT_POLICY` (deep) | How object fields are compared (§16.3.4.1) |

Two details decide most predictions:
- **The threshold gate is in the macros, not in the comparer.** Each field macro checks `get_result() < get_threshold()` before comparing (uvm-core 2020.3.1, `uvm_comparer_defines.svh`). A `do_compare` that calls `comparer.compare_field_int()` directly always compares and always counts, so a hand-written hook with two differing fields gives `get_result()` = 2 even with the default comparer.
- **`show_max` limits printing, never counting.** With `show_max` 1 and two counted miscompares, you see one per-field line and the summary `2 Miscompare(s) (1 shown) for object exp@… vs. act@…`, and `get_miscompares()` still holds both.

This is what the default comparer prints for the sequence diagram above (illustrative: file and line elided as `...`, object ids vary by simulator):

```text
UVM_INFO ... @ 0: reporter [MISCMP] Miscompare for exp.addr: lhs = 'h10 : rhs = 'h14
UVM_INFO ... @ 0: reporter [MISCMP] 1 Miscompare(s) for object exp@41 vs. act@42
```

**A dedicated comparer for a scoreboard.** To see every miscompare, give the scoreboard its own comparer rather than changing the default one that every other `compare()` call shares:

```systemverilog
// snippet: inside a scoreboard
uvm_comparer cmp = new("cmp");
cmp.set_threshold(0);    // macros compare every field (uvm-core keeps this across compare() calls)
cmp.set_show_max(10);    // print up to 10 MISCMP lines
if (!exp.compare(act, cmp))
  `uvm_error("SCB", {"mismatch:\n", cmp.get_miscompares()})
```

The comment matters: IEEE 1800.2 §16.3.6 says `get_threshold()` returns 1 again after `flush()`, and `compare()` flushes the comparer first (§5.3.9.1 a). uvm-core 2020.3.1 keeps the threshold, so the code above works there. Make It Work shows the portable version, a comparer subclass that re-applies the threshold in `flush()`.

### Try it: the Policy Explorer

The explorer uses its own small `packet` class (fields `addr`, `data`, `parity`, `tag` and a `pkt_cfg` handle `cfg`). In **compare** mode you pick a scenario, change a flag, the threshold or `show_max`, and then predict both numbers: what `exp.compare(act, cmp)` returns and what `cmp.get_result()` counts. Write your prediction down before you look at the answer. Work through:
1. **Two fields differ** with threshold 1, then with threshold 0.
2. **Exclude tag**, then switch `tag` to the `UVM_NOCOMPARE`-only flag and watch the `NO_FLAG` warning appear.
3. **Macros + do_compare()**: the hook passes, the macros fail. (The explorer writes this hook with `==` to stay short; in your code, compare through `comparer.compare_field_int` as §5.3.9 requires.)
4. In **copy** mode, predict `p1.cfg`'s `burst_len` after `p2.cfg.burst_len` changes, for each of the four `cfg` implementations, before you pick them. This is the shared-handle bug.
5. In **print** mode, predict which rows the table shows when `tag` uses the `UVM_NOCOMPARE`-only flag, then compare the table, tree and line printers.

### print(), sprint() and convert2string()

Three ways to turn an object into text, for three jobs:

| Method | Returns or writes | Built by | Use it for |
| --- | --- | --- | --- |
| `print(printer)` | Writes multi-line text straight to the printer's file, **not** through the report server (the UVM reporting system that filters messages by verbosity), so verbosity never filters it (§5.3.6.1; uvm-core writes with `$fwrite` to the printer's `get_file()`) | the printer: field macros, then `do_print` | Interactive debug, a one-off dump |
| `sprint(printer)` | Returns the same text as a string (§5.3.6.2) | as `print` | Putting a dump inside a `` `uvm_info `` message |
| `convert2string()` | Returns a string; the `uvm_object` default returns `""` (§5.3.6.4) | **only you**: the field macros do not implement it | One-line log messages from monitors and scoreboards |

The printer decides the layout. uvm-core 2020.3.1 uses a `uvm_table_printer` by default; 1800.2 leaves the default to the implementation (F.4.1.4.13). Choose another with `uvm_printer::set_default(uvm_line_printer::get_default());`, or pass a printer to one call: `exp.print(uvm_tree_printer::get_default())`. The UVM 1.2 global `uvm_default_printer` still compiles in uvm-core (it is kept for compatibility) but is not part of 1800.2; `set_default()` is the portable form.

Printer knobs you will use (§16.2.5): `set_default_radix()` for fields printed with `UVM_NORADIX` (default `UVM_HEX`, §16.2.5.7), `set_max_depth()` to stop recursing into nested objects (default −1, everything, §16.2.5.10), and `set_file()` to send `print()` to a file (§16.2.5.11). In uvm-core the tree and line printers turn off the type and size columns.

The same `exp` from Make It Work, three ways (illustrative; column widths and the object id vary):

```text
--------------------------------------
Name    Type      Size  Value
--------------------------------------
exp     bus_item  -     @41
  addr  integral  16    'h10
  data  integral  32    'hcafe0001
  id    integral  16    'd1
--------------------------------------
exp: (bus_item@41) { addr: 'h10  data: 'hcafe0001  id: 'd1  }
UVM_INFO ... @ 0: uvm_test_top [DEMO] addr=0x0010 data=0xcafe0001 id=1
```

The first block is `exp.print()` (table), the second line `exp.print(uvm_line_printer::get_default())`, the third `` `uvm_info("DEMO", exp.convert2string(), UVM_LOW) ``. In a hand-written `do_print`, call `printer.print_field_int("addr", addr, $bits(addr), UVM_HEX)` (§16.2.3.9) and `printer.print_string(...)` (§16.2.3.10), never `$display`: §5.3.6 requires the policy's API so that every printer can lay the field out.

**The classic mistake.** `` `uvm_info("MON", item.convert2string(), UVM_MEDIUM) `` prints an empty message. The class uses field macros and never overrides `convert2string()`. Override it, or log `item.sprint()`.

### copy() and clone(): what the copy shares

`copy(rhs)` fills an object you already have; `clone()` creates a new object with `create(get_name())`, copies this object into it, and returns the new object as a `uvm_object` for you to `$cast` (§5.3.5.2, §5.3.8.1). Integral fields are copied by value. The question is what happens to a field that is a **handle**, such as the explorer's `cfg`:

| Implementation of `cfg` in the copy | After `p2.copy(p1)` | Changing `p2.cfg.burst_len` changes `p1`? |
| --- | --- | --- |
| `` `uvm_field_object(cfg, UVM_ALL_ON) `` | uvm-core creates a new `pkt_cfg` if `p2.cfg` is null, otherwise copies into `p2`'s existing one | no |
| `` `uvm_field_object(cfg, UVM_ALL_ON \| UVM_REFERENCE) `` | `p2.cfg = p1.cfg`: one shared object | **yes** |
| hand-written `cfg = rhs_.cfg;` | one shared object | **yes** |
| hand-written `$cast(cfg, rhs_.cfg.clone());` (null-checked) | a new object | no |

So "`copy()` is always deep" is wrong. The field macros copy deep unless you flag `UVM_REFERENCE`; a hand-written `do_copy` copies exactly what you wrote, and a handle assignment shares the object. That is right when the sub-object is meant to be shared (a read-only configuration) and a bug when the copy must be independent (a scoreboard's saved expected item). The explorer's copy mode shows all four rows.

A correct hand-written `do_copy` calls `super.do_copy(rhs)` and casts `rhs` to your type first (§5.3.8.2):

```systemverilog
// snippet: inside class packet (the explorer's class)
virtual function void do_copy(uvm_object rhs);
  packet rhs_;
  if (!$cast(rhs_, rhs))
    `uvm_fatal("PACKET", "do_copy: rhs is not a packet")
  super.do_copy(rhs);              // base-class fields first
  addr = rhs_.addr;
  if (rhs_.cfg == null) cfg = null;
  else $cast(cfg, rhs_.cfg.clone());  // independent sub-object
endfunction
```

### pack() and unpack(): the symmetry rule

`pack_bytes()` (and `pack()`, `pack_ints()`, `pack_longints()`) serialises an object into an array; `unpack_bytes()` and its siblings restore it (§5.3.10.1, §5.3.11.1). The one rule: **unpack the same fields, in the same order, with the same widths, as you packed them.** §5.3.10.2 puts it this way: the unpacking order needs to match the packing order, but the packing order need not match the declaration order. The packer stores no field names, so it cannot notice a mismatch.

A hand-written pair, using the packing macros (B.2.4.6, B.2.5.6) that call `packer.pack_field_int()` and `packer.unpack_field_int()` (§16.5.4.9, §16.5.4.17):

```systemverilog
// snippet: inside a class with addr [15:0], data [31:0], id [15:0]
virtual function void do_pack(uvm_packer packer);
  super.do_pack(packer);
  `uvm_pack_int(addr);   // 16 bits
  `uvm_pack_int(data);   // 32 bits
  `uvm_pack_int(id);     // 16 bits
endfunction

virtual function void do_unpack(uvm_packer packer);
  super.do_unpack(packer);
  `uvm_unpack_int(addr); // same order, same widths
  `uvm_unpack_int(data);
  `uvm_unpack_int(id);
endfunction
```

| 68–83 | 8–10 | `addr`, bit 0 first | `'h0010` |
| 84–115 | 10–14 | `data`, bit 0 first | `'hcafe0001` |
| 116–131 | 14–16 | `id`, bit 0 first | `'d1` |
| 132–135 | high half of byte 16 | padding, masked to 0 | — |

Count it through: `flush()` sets both iterators to 64; the marker moves the pack iterator to 68 and the 64 field bits to 132. `pack_bytes()` returns the number of bits that can be unpacked, 132 − 64 = **68**, and fills (132 + 7) / 8 = **17** bytes: `84 00 00 00 40 00 00 00 0f 01 10 00 e0 af 1c 00 00`. A C model that expects `addr`, `data`, `id` in its first 8 bytes reads nonsense: the fields are not even byte-aligned. §5.3.10.1 warns about exactly this: the stream may contain metadata, so the return value may differ from the stream size.

So use pack and unpack for **SystemVerilog-to-SystemVerilog round trips** through a compatible packer (§16.5.3.1): saving and restoring an object, or moving it between SV components. To hand fields to a C reference model, pass them, or a packed struct, through the Direct Programming Interface, DPI ([I-SV-7](/curriculum/T2_Intermediate/I-SV-7_DPI_and_Foreign_Language_Interfaces/index)), or build the bytes yourself with the streaming operators (IEEE 1800-2023 §11.4.14).

**The classic mistake: a mis-ordered unpack.** Swap two lines in `do_unpack` so it reads `data` before `addr`, and trace it on the same stream:

| Step | `do_unpack` line | Reads stream bits | Value read | Correct value |
| --- | --- | --- | --- | --- |
| 1 | `` `uvm_unpack_int(data) `` (32 bits) | 68–99 | `data` = `'h00010010` | `'hcafe0001` |
| 2 | `` `uvm_unpack_int(addr) `` (16 bits) | 100–115 | `addr` = `'hcafe` | `'h0010` |
| 3 | `` `uvm_unpack_int(id) `` (16 bits) | 116–131 | `id` = `'d1` | `'d1` |

Step 1 takes the 16 bits of `addr` plus the low 16 bits of `data`; step 2 takes the high half of `data`. No error is reported, the bit count still matches, and only a `compare()` against the original reveals the damage. With two fields of equal width the values would simply swap; with different widths they are scrambled.

**Nested objects.** Pack a sub-object with `packer.pack_object(cfg)`, which writes a 4-bit null/non-null marker before its fields (§16.5.4.2). On unpack, `unpack_object` needs an allocated object, or `null` if the stream holds a null (§16.5.4.3–§16.5.4.4), so peek first:

```systemverilog
// snippet: in do_unpack, for a pkt_cfg handle cfg
if (packer.is_null()) cfg = null;
else if (cfg == null) cfg = pkt_cfg::type_id::create("cfg");
packer.unpack_object(cfg);   // also consumes the marker when the object was null
```

uvm-core reports `UVM/BASE/PACKER/UNPACK/NN2N` if you pass a null handle for a non-null object.

### Field macros or hand-written hooks?

Here is the same item without field macros. Everything the macros did is now explicit:

```systemverilog
// snippet: needs import uvm_pkg::*; and `include "uvm_macros.svh"
class bus_item_hooks extends uvm_sequence_item;
  `uvm_object_utils(bus_item_hooks)   // no _begin: no field automation

  rand bit [15:0] addr;
  rand bit [31:0] data;
  bit      [15:0] id;

  function new(string name = "bus_item_hooks");
    super.new(name);
  endfunction

  virtual function void do_copy(uvm_object rhs);
    bus_item_hooks rhs_;
    if (!$cast(rhs_, rhs))
      `uvm_fatal("BUS_ITEM", "do_copy: rhs is not a bus_item_hooks")
    super.do_copy(rhs);
    addr = rhs_.addr;
    data = rhs_.data;
    id   = rhs_.id;
  endfunction

  // Through the comparer, so every difference is counted and reported.
  // id is deliberately not compared.
  virtual function bit do_compare(uvm_object rhs, uvm_comparer comparer);
    bus_item_hooks rhs_;
    if (!$cast(rhs_, rhs)) return 0;
    do_compare = super.do_compare(rhs, comparer);
    do_compare &= comparer.compare_field_int("addr", addr, rhs_.addr, $bits(addr), UVM_HEX);
    do_compare &= comparer.compare_field_int("data", data, rhs_.data, $bits(data), UVM_HEX);
  endfunction

  virtual function void do_print(uvm_printer printer);
    super.do_print(printer);
    printer.print_field_int("addr", addr, $bits(addr), UVM_HEX);
    printer.print_field_int("data", data, $bits(data), UVM_HEX);
    printer.print_field_int("id",   id,   $bits(id),   UVM_DEC);
  endfunction

  virtual function void do_record(uvm_recorder recorder);
    super.do_record(recorder);
    `uvm_record_int("addr", addr, $bits(addr), UVM_HEX)
    `uvm_record_int("data", data, $bits(data), UVM_HEX)
  endfunction

  virtual function void do_pack(uvm_packer packer);
    super.do_pack(packer);
    `uvm_pack_int(addr);
    `uvm_pack_int(data);
    `uvm_pack_int(id);
  endfunction

  virtual function void do_unpack(uvm_packer packer);
    super.do_unpack(packer);
    `uvm_unpack_int(addr);
    `uvm_unpack_int(data);
    `uvm_unpack_int(id);
  endfunction

  virtual function string convert2string();
    return $sformatf("addr=0x%04h data=0x%08h id=%0d", addr, data, id);
  endfunction
endclass
```

One behaviour differs from the macro version: with the default comparer and both `addr` and `data` different, this `do_compare` counts **2** (no threshold gate on direct calls), prints one `MISCMP` line and the summary `2 Miscompare(s) (1 shown)`. The macro `bus_item` counts 1.

| Criterion | Field macros | Hand-written hooks |
| --- | --- | --- |
| Effort | One line per field gives print, copy, compare, pack, record | One line per field **per hook**; easy to forget a field |
| Run time | "may not be as run-time efficient" (B.2.2 NOTE): generic code with a `case` on the operation for every field | Only the code you need |
| Control | Flags only: in or out, radix, recursion | Anything: tolerances, computed fields, conditional fields, custom order |
| Debugging | Macro expansion is hard to step through; errors point at the macro line | Ordinary code you can breakpoint |
| `convert2string` | Not provided | You write it either way |
| Mixing | Allowed: macros run first, then hooks. Never register a field in both, or it is compared and printed twice | — |

A common team rule: field macros for quick prototypes and low-rate configuration objects; hand-written hooks for high-rate sequence items in production, as the B.2.2 NOTE recommends when "specific run-time semantics or efficiency are required". Whatever you choose, you write `convert2string()` yourself.

**Awareness: `do_execute_op` and `uvm_field_op`.** The field macros are a generated `do_execute_op(uvm_field_op op)` (§5.3.13). You can write that one method yourself instead of six hooks: read `op.get_op_type()` (§5.7.2.4), `op.get_policy()` (§5.7.2.5) and `op.get_rhs()` (§5.7.2.6), and call `op.disable_user_hook()` (§5.7.2.8) to stop the policy calling your `do_*` hook for this operation. Because `` `uvm_object_utils_begin `` already defines `do_execute_op`, only a class registered with plain `` `uvm_object_utils `` can define its own. Push Further has an example.

### Common mistakes and how to debug them

| Symptom | Cause | Fix |
| --- | --- | --- |
| The test passes although the data differ; the log shows `MISCMP` lines | The scoreboard ignored `compare()`'s return value; `MISCMP` is `UVM_INFO` | Test the return value and raise `` `uvm_error `` when it is 0 |
| `compare()` returns 1 although a field differs; the field is also missing from `print()` | Its flag has no positive bit (`UVM_NOCOMPARE` or `UVM_HEX` alone); look for `UVM/FIELDS/NO_FLAG` in the log | `UVM_ALL_ON \| UVM_NOCOMPARE` (or `UVM_ALL_ON \| UVM_HEX`) |
| `compare()` returns 1 although a field differs; no warning | A hand-written `do_compare` never compares that field, or compares with `==` and returns 1 | Compare every field through `comparer.compare_field_int` |
| Only one miscompare reported when you know there are several | Default threshold 1 (macros) and `show_max` 1 (printing) | A dedicated comparer: threshold 0, `show_max` 10 |
| No `MISCMP` lines at all, yet `compare()` returns 0 | Regression run at `+UVM_VERBOSITY=UVM_NONE`; the lines are `UVM_LOW` | `cmp.set_verbosity(UVM_NONE)`, or print `cmp.get_miscompares()` in your own error |
| Comparing an `err_item` with a `bus_item` reports only a type miscompare | The type check counts 1 and the threshold then skips every field | Compare like with like, or use a comparer whose `flush()` re-applies `set_check_type(0)` (uvm-core's `flush()` resets it; see Push Further) |
| Changing a copy changes the original | A shared sub-object: `UVM_REFERENCE`, or `cfg = rhs_.cfg` in `do_copy` | Clone the sub-object, or drop `UVM_REFERENCE` |
| Unpacked fields hold scrambled values | `do_unpack` order or widths differ from `do_pack` | Mirror `do_pack` line by line |
| A field packs, but comes back 0 after unpack | Its flag lists operations explicitly with `UVM_PACK` but not `UVM_UNPACK` (uvm-core tests a separate unpack bit) | `UVM_PACK \| UVM_UNPACK`, or `UVM_ALL_ON \| UVM_NO*` |
| `` `uvm_info `` with `convert2string()` prints an empty message | `convert2string()` not overridden | Override it |

## Push Further

### Expert: Where the threshold lives, and why it may not survive compare()

§16.3.6 describes the threshold as permission: `do_compare` or `do_execute_op` "may return as quickly as possible" once `get_result()` reaches it. In uvm-core 2020.3.1 the only code that honours it is the gate in the field macros and the `` `uvm_compare_* `` macros (`m_uvm_compare_threshold_begin` in `uvm_comparer_defines.svh`). `compare_field_int()`, `compare_object()` and your `do_compare()` never stop on their own, and `print_msg()` keeps counting.

The portability trap: §16.3.6 says `get_threshold()` returns 1 if `set_threshold` has not been called "since the last call to flush", and `compare()` calls `flush()` at depth 0 (§5.3.9.1 a). A literally conforming library would therefore undo `cmp.set_threshold(0)` on every `compare()`. uvm-core's `flush()` resets the result, the miscompare string and `check_type`, but keeps the threshold, `show_max`, verbosity, severity and recursion policy. **Tool-dependent.** The robust pattern is the Make It Work `scb_comparer`, whose `flush()` calls `super.flush()` and re-applies the threshold.

### Expert: Tolerance and filtering, two ways

There is no tolerance knob on `uvm_comparer`. Two designs work.

**1. A comparer subclass.** The field macros pass the field's name to `compare_field_int`, so an override can treat one field specially (§16.3.3.2):

```systemverilog
// snippet: needs import uvm_pkg::*; and `include "uvm_macros.svh"
class tolerant_comparer extends uvm_comparer;
  `uvm_object_utils(tolerant_comparer)
  int unsigned tolerance = 2;

  function new(string name = "tolerant_comparer");
    super.new(name);
  endfunction

  virtual function bit compare_field_int(string name, uvm_integral_t lhs, uvm_integral_t rhs,
                                         int size, uvm_radix_enum radix = UVM_NORADIX);
    // Only "data", and only known values: an X or Z must still miscompare.
    if (name == "data" && !$isunknown(lhs) && !$isunknown(rhs)) begin
      longint diff = longint'(lhs) - longint'(rhs);
      if (diff < 0) diff = -diff;
      if (diff <= tolerance) return 1;   // within tolerance: nothing counted
    end
    return super.compare_field_int(name, lhs, rhs, size, radix);
  endfunction
endclass
```

The `$isunknown` guard matters: `uvm_integral_t` is `logic signed [63:0]`, and the `longint'` cast turns X and Z bits into 0 (IEEE 1800-2023 §6.11.2), so without it an X-valued actual could land within tolerance. The weakness of this design is that it keys on a name string: rename the field and the tolerance silently stops applying.

**2. A policy extension** (§16.1.2.3). Any object can ride along with a policy through `set_extension()`, and the item's own hook asks for it with `get_extension()`. Extensions are not cleared by `flush()`.

```systemverilog
// snippet: the scoreboard attaches an extension; the item's do_compare reads it
class ignore_ts_ext extends uvm_object;
  `uvm_object_utils(ignore_ts_ext)
  function new(string name = "ignore_ts_ext");
    super.new(name);
  endfunction
endclass

// scoreboard, once:  void'(cmp.set_extension(ignore_ts_ext::type_id::create("ext")));
// item's do_compare:
if (comparer.get_extension(ignore_ts_ext::get_type()) == null)
  do_compare &= comparer.compare_field_int("ts", ts, rhs_.ts, $bits(ts), UVM_DEC);
```

The extension keeps the rule with the item that owns the field, and the same item can compare strictly in one scoreboard and loosely in another.

### Expert: Packed streams are implementation-defined

The normative facts are short: a stream is only guaranteed to unpack in a **compatible** packer, meaning one whose state retrieval returns identical streams for identical fields (§16.5.3.1), and its "length and contents … are implementation dependent" (§16.5.3.2). The details below are uvm-core 2020.3.1 (`uvm_packer.svh`, `uvm_object.svh`) and are **tool-dependent**:
- `flush()` sets both iterators to 64; `get_packed_*` writes them into bits 0–63, and `set_packed_*` reads them back from there. That is why the stream starts with `84 00 00 00 40 00 00 00`.
- `pack_object` writes `4'hF` before every object (`4'h0` for null), the top-level one included.
- Fields are stored least significant bit first, with no padding between them. The UVM 1.2 knobs `big_endian` and `use_metadata` are gone.
- The `` `uvm_field_object `` macro (and the `` `uvm_pack_object `` macro, which is not in Annex B.2.4) packs through `pack_object_with_meta`: a 32-bit reference id and the type name before the fields, so unpack can create the right type. It is not compatible with a hand-written `is_null`/`unpack_object` reader.
- The kit's `uvm_compat_pkg::uvm_compat_packer` reproduces UVM 1.2 streams; install it with `uvm_packer::set_default(compat_packer)` when old stream bytes must stay identical (uvm-core `compat/README.md`).

So the same item can pack to different bytes under UVM 1.2 and 1800.2 libraries, while each library still round-trips its own streams. For a C model, pass a packed struct or the fields through DPI, or build the bytes with streaming operators (IEEE 1800-2023 §11.4.14), so you own the format.

### Expert: Field-macro semantics changed in IEEE 1800.2

B.2.2 and F.2.1.8–F.2.1.9 make operations opt-in: a field joins only the operations its flag names, and negative flags beat positive ones. UVM 1.2 treated a flag without positive bits as if `UVM_ALL_ON` were added. The uvm-core warning `UVM/FIELDS/NO_FLAG` (Mantis 7187) names the change; it appears once per field macro, the first time the macro runs an operation. Two uvm-core escape hatches, both **tool-dependent**:
- Compile with `+define+UVM_LEGACY_FIELD_MACRO_SEMANTICS` to get the 1.2 behaviour back (the kit README spells it `UVM_LEGACY_FIELD_SEMANTICS`, a typo: the source tests `UVM_LEGACY_FIELD_MACRO_SEMANTICS`).
- Silence the warning with `set_report_severity_id_action(UVM_WARNING, "UVM/FIELDS/NO_FLAG", UVM_NO_ACTION)` once you have audited the fields.

The real fix is to add `UVM_ALL_ON`. When migrating a legacy code base, grep for field macros whose flag has no `ALL_ON`, `DEFAULT` or explicit operation: radix-only (`UVM_HEX`) and recursion-only (`UVM_REFERENCE`) flags are the ones people miss.

### Expert: Recursion policies and type checks

§16.3.4.1 and §16.6.3 define three recursion policies for object fields: `UVM_DEEP` (recurse), `UVM_SHALLOW` (copy or compare the sub-object's own object fields as references) and `UVM_REFERENCE` (the handle only). Three uvm-core behaviours, all **tool-dependent**:
- The field macros special-case only `UVM_REFERENCE`. A field flagged `UVM_SHALLOW` is created or copied into, and its own object fields are still deep-copied and deep-compared.
- `uvm_comparer::flush()` sets `check_type` back to 1, and `compare()` flushes at depth 0, so `cmp.set_check_type(0); a.compare(b, cmp)` still checks types. To compare a derived item with a base item field by field, override `flush()` as in `scb_comparer`, or compare through a common base `do_compare` yourself.
- The type check counts as a miscompare. With threshold 1, comparing an `err_item` with a `bus_item` reports `Miscompare for exp.type: lhs = "err_item" : rhs = "bus_item"`, then the summary line, and no field results.

Cycles are detected per policy: a comparer asked to compare a pair it has already seen in this operation warns `UVM/COPIER/LOOP` (sic), and a copy loop warns `UVM/COPY/LOOP`. And the copy macro copies **into** an existing destination sub-object; it creates one only when the destination handle is null (`uvm_copy_object` in `uvm_copier_defines.svh`), so a pre-built destination keeps its identity.

### Expert: do_execute_op as one hook for every operation

A class registered with plain `` `uvm_object_utils `` can implement all operations in one place (§5.3.13, §5.7.2):

```systemverilog
// snippet: in class lean_item (plain `uvm_object_utils), field addr [15:0]
virtual function void do_execute_op(uvm_field_op op);
  uvm_comparer cmp;
  lean_item    rhs_;
  super.do_execute_op(op);
  if (op.get_op_type() == UVM_COMPARE && $cast(cmp, op.get_policy())
      && $cast(rhs_, op.get_rhs())) begin
    void'(cmp.compare_field_int("addr", addr, rhs_.addr, $bits(addr), UVM_HEX));
    op.disable_user_hook();   // do_compare will not be called for this op
  end
endfunction
```

This is how the field macros themselves work, and it suits code generators: one generated method can serve copy, compare, print, pack and record. The cost is a dispatch on every operation, the same cost the macros pay. Keep the `void'`: the result is already counted by the comparer, which is what `compare_object` checks.

### Expert: Scale and performance

The B.2.2 NOTE is the only normative statement: field macros "may not be as run-time efficient nor as flexible" as direct `do_*` code. How much slower depends on the simulator and the class; measure it in your own regression before you rewrite (any figure is tool-dependent). Habits that keep policy work cheap in large runs:
- Build log text only when it will print: `` `uvm_info `` evaluates its message only if the verbosity passes, but a `sprint()` assigned to a variable first is always paid for. Prefer `convert2string()` for per-transaction lines.
- Print `MISCMP` details only on failure paths, and keep `show_max` small in regressions.
- Keep one comparer per scoreboard instead of creating one per comparison.
- Do not pack items just to compare or copy them; `compare()` and `copy()` are cheaper and keep field names in the messages.

Start from the Make It Work `bus_item`, and work each step before you open the solution.
1. Add `time ts;` (when the monitor saw the transfer) and register it so it is printed and copied but never compared.
2. Write `tolerant_comparer` yourself, before you read Push Further: a `uvm_comparer` subclass that lets `data` differ by up to 2 but still miscompares when either value holds X or Z.
3. Now the hand-written version. Add `time ts;` to `bus_item_hooks`, then write its `do_compare` (compare through `comparer.compare_field_int`, and exclude `id` and `ts`) and its `convert2string()` (show all four fields).
4. Predict `compare()` and `get_result()` for the macro `bus_item` and these three pairs, first with the default comparer, then with a comparer whose threshold is 0:
   - (a) `addr` differs, `data` equal, `ts` differs;
   - (b) `addr` equal, `data` differs by 1, `id` differs;
   - (c) `addr` differs, `data` differs by 5.
5. Predict `compare()` and `get_result()` for pair (c) with your `bus_item_hooks` and the **default** comparer.

<details>
<summary>Worked solution</summary>

1. `` `uvm_field_int(ts, UVM_ALL_ON | UVM_NOCOMPARE | UVM_TIME) ``. Writing `UVM_NOCOMPARE` alone would drop `ts` from print and copy too, with a `UVM/FIELDS/NO_FLAG` warning.
2. The key lines override `compare_field_int`, which the field macros call with the field's name (§16.3.3.2):

```systemverilog
// snippet: inside class tolerant_comparer extends uvm_comparer (int unsigned tolerance = 2;)
virtual function bit compare_field_int(string name, uvm_integral_t lhs, uvm_integral_t rhs,
                                       int size, uvm_radix_enum radix = UVM_NORADIX);
  if (name == "data" && !$isunknown(lhs) && !$isunknown(rhs)) begin
    longint diff = longint'(lhs) - longint'(rhs);
    if (diff < 0) diff = -diff;
    if (diff <= tolerance) return 1;   // within tolerance: nothing counted
  end
  return super.compare_field_int(name, lhs, rhs, size, radix);
endfunction
```

   The full class, with its registration and constructor, is in Push Further. Use it in the scoreboard and raise `` `uvm_error `` when `exp.compare(act, tol_cmp)` returns 0. Give it threshold 0 if you also want every macro field counted.
3. The hook version:

```systemverilog
// snippet: inside class bus_item_hooks, which now also declares time ts;
virtual function bit do_compare(uvm_object rhs, uvm_comparer comparer);
  bus_item_hooks rhs_;
  if (!$cast(rhs_, rhs)) return 0;
  do_compare = super.do_compare(rhs, comparer);
  do_compare &= comparer.compare_field_int("addr", addr, rhs_.addr, $bits(addr), UVM_HEX);
  do_compare &= comparer.compare_field_int("data", data, rhs_.data, $bits(data), UVM_HEX);
  // id and ts are bookkeeping: deliberately not compared
endfunction

virtual function string convert2string();
  return $sformatf("addr=0x%04h data=0x%08h id=%0d ts=%0t", addr, data, id, ts);
endfunction
```

4. Predictions for the macro `bus_item`, plain comparers (field order `addr`, `data`, `id`, `ts`; `id` and `ts` are not compared):

| Pair | Default comparer: `compare()`, `get_result()` | Threshold 0: `compare()`, `get_result()` |
| --- | --- | --- |
| (a) | 0, 1 (`addr`) | 0, 1 (`addr`) |
| (b) | 0, 1 (`data`) | 0, 1 (`data`) |
| (c) | 0, 1 (`addr`, then the gate skips `data`) | 0, 2 (`addr` and `data`) |

   With `tolerant_comparer` (threshold 0), pair (b) becomes 1, 0, because a difference of 1 is within tolerance; pair (c) stays 0, 2, because 5 is not. The expected log for (c) with threshold 0 and `show_max` 10 has two per-field lines: `Miscompare for exp.addr: …` and `Miscompare for exp.data: …`, then `2 Miscompare(s) for object exp@… vs. act@…`.
5. `compare()` returns 0 and `get_result()` is **2**, even with the default comparer: your direct `compare_field_int` calls have no threshold gate. With `show_max` 1 the log shows one line, `Miscompare for exp.addr: …`, then `2 Miscompare(s) (1 shown) for object exp@… vs. act@…`. Because `compare_field_int` is virtual, `tolerant_comparer` also applies to your hook: pair (b) would compare equal through it.
</details>

### Kata 2: a round trip that breaks, then works

Write `do_pack` and `do_unpack` for `bus_item_hooks` without looking back, then check them against Build Your Mental Model. Then:
1. Swap the `addr` and `data` lines in `do_unpack` only. Pack `exp` (`addr` `'h0010`, `data` `'hcafe0001`, `id` 1), unpack into `rx`, and predict `rx`'s fields and `rx.compare(exp)`.
2. Fix it, and add a check you can keep in a unit test.

<details>
<summary>Worked solution</summary>

1. `rx.data` = `'h00010010` (the 16 bits of `addr`, then the low half of `data`), `rx.addr` = `'hcafe`, `rx.id` = 1. `unpack_bytes` still returns 68 and reports nothing. `rx.compare(exp)` returns 0. The hook counts both fields (`get_result()` = 2); with the default `show_max` 1 you see one line, `Miscompare for rx.addr: lhs = 'hcafe : rhs = 'h10`, then `2 Miscompare(s) (1 shown) for object rx@… vs. exp@…`.
2. Restore the order so `do_unpack` mirrors `do_pack`. A reusable check:

```systemverilog
// snippet: round-trip self-check
byte unsigned bytes[];
void'(exp.pack_bytes(bytes));
void'(rx.unpack_bytes(bytes));
if (!rx.compare(exp))
  `uvm_error("PACK", "round trip changed the item")
```
</details>

### Debug challenge: compare() passes, but data differs

A legacy item declares `` `uvm_field_int(addr, UVM_ALL_ON | UVM_HEX) `` and `` `uvm_field_int(data, UVM_HEX) ``. The scoreboard checks the return value, yet two items with different `data` compare equal. The `print()` table lists `addr` but not `data`. What is wrong, and which log line would have told you?

<details>
<summary>Answer</summary>

`data`'s flag is radix-only: it has no positive operation bit, so under 1800.2 semantics `data` joins no operation. It is not compared, printed, copied or packed. uvm-core logs `UVM_WARNING … [UVM/FIELDS/NO_FLAG] Field macro for ARG uses FLAG without or'ing any explicit UVM_xxx actions. …` once per field. The words `ARG` and `FLAG` appear literally, because a macro argument is not substituted inside a string literal (IEEE 1800-2023 §22.5.1), so the text does not name the field: find it by grepping for field macros without `UVM_ALL_ON`. Fix: `` `uvm_field_int(data, UVM_ALL_ON | UVM_HEX) ``. You can reproduce the same symptom in the Policy Explorer by setting a field to the `UVM_NOCOMPARE`-only flag.
</details>
