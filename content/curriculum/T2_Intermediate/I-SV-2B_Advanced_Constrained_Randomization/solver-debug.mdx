## The Problem: When `.randomize()` Fails
*IEEE 1800-2023, Clause 18.6: Randomization methods*

When you call `obj.randomize()`, you are asking the constraint solver (often an SAT or BDD solver under the hood) to find a set of values for your random variables that satisfies ALL active constraints.

If no combination satisfies every active constraint, `randomize()` returns `0`, the random variables keep their previous values, and `post_randomize()` is not called (IEEE 1800-2023 §18.6.3). **This is a critical failure.** If you do not check the return value, your testbench will continue running using stale, non-randomized data! The opposite is also true: when a solution exists, `randomize()` never fails by bad luck.

## Triage Strategies

### 1. Read the Solver Output
Modern simulators (VCS, Xcelium, Questa) will print a detailed "constraint contradiction" report when randomization fails. It will list the exact variable values and constraints that couldn't be satisfied together. Read this first!

*Example Contradiction Report:*
```text
=======================================================
Solver failed when trying to satisfy the following constraints:
  c_size: size > 10;
  c_len: payload.size() < 5;
  c_match: payload.size() == size;
=======================================================
```
Here, you can easily read that $c\\_size$ forces $size > 10$, but $c\\_len$ restricts $payload$ to $< 5$, and $c\\_match$ requires them to be equal.

### 2. Disable Constraints Incrementally
If the solver output is too complex, use `constraint_mode(0)` to turn off constraints one at a time (or half at a time) until randomization succeeds. The last constraint you turned off is part of *a* conflict, but a conflict usually needs several constraints together, a *minimal conflicting set*. Turning one member off breaks that conflict without naming its partners, and a second conflict may still remain. Use the report to see the whole set.

```systemverilog
// Turn off the suspicious constraint
p.c_size.constraint_mode(0); 
if (!p.randomize()) $display("Still failing...");
```

### 3. Disable Random Variables
You can also use `rand_mode(0)` to turn off randomization for specific variables. This treats them as state variables (constants during the solve phase) based on their current value.
```systemverilog
p.size.rand_mode(0); // size will retain whatever value it currently holds
p.randomize(); 
```

### 4. Beware of Signed Types
A rand variable takes the signedness of its declared type (§6.11.3). `int`, `shortint`, `longint`, `byte` and `integer` are **signed**; `bit` and `logic` vectors are unsigned. So `rand int len;` can be negative, the usual source of "negative length" bugs. If any operand of an expression is unsigned, the whole expression is evaluated unsigned, and negative values wrap to huge ones. Prefer `bit [N:0]` or `int unsigned` for sizes and lengths, and bound them.

### 5. Check Active Overrides
Are `pre_randomize` or parent class variables altering state? Check if a base class has constraints you forgot about.
