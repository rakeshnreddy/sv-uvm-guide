## Level 1: Hooking the Solver
*IEEE 1800-2023, §18.6.2: pre_randomize() and post_randomize() · §18.6.3: behavior of randomization methods*

**The Analogy:** `pre_randomize` sets the table before guests arrive; `post_randomize` writes the bill after the meal. Neither one cooks: the solver does.

## Level 2: Core Mechanics

<InteractiveCode language="systemverilog" code={`class frame;
  rand bit [7:0] len;
  rand bit [7:0] payload[];
  bit      [7:0] crc;                           // derived, so not rand

  constraint c_len  { len inside {[1:32]}; }
  constraint c_size { payload.size() == len; }  // the solver sizes AND fills payload

  function void pre_randomize();
    // Runs before solving: set non-random knobs or switch constraints
    // with constraint_mode() for this call.
  endfunction

  function void post_randomize();
    // Runs only after a successful solve: compute derived fields.
    crc = 0;
    foreach (payload[i]) crc ^= payload[i];
  endfunction
endclass

program test;
  frame f = new();
  initial begin
    repeat (2) begin
      if (!f.randomize()) $fatal(1, "frame randomize() failed");
      $display("len=%0d crc=%02h payload=%p", f.len, f.crc, f.payload);
    end
  end
endprogram`} />

**Anti-pattern to avoid:** deleting `payload` in `pre_randomize()` and refilling it in `post_randomize()` with fixed values such as `payload[i] = i`. That throws away the randomization, ignores every constraint on the elements, and leaves your payload coverage stuck on one pattern. Let the constraints size and fill the array; keep the hooks for what the solver cannot do.

## Level 3: Expert Tips

- Use `pre_randomize` to set non-random knobs or to switch constraints with `constraint_mode()` before solving.
- `post_randomize` runs only when `randomize()` succeeds. If the solve fails, it is not called and the random variables keep their previous values (§18.6.3).
- If a derived class overrides either hook, it must call `super.pre_randomize()` or `super.post_randomize()`. Otherwise the base class's steps are skipped (§18.6.2).
- Keep `post_randomize` for derived, non-random fields such as a CRC or parity, and keep it light.
