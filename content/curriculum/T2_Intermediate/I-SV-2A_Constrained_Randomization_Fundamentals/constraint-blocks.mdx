## Level 1: Defaults and Dependencies
*IEEE 1800-2023, §18.5.13: soft constraints · §18.5.9: variable ordering*

**The Analogy:** A constraint block is a set of road signs. Hard constraints close roads. A `soft` sign is a default route that is always followed unless a stronger sign closes it. `solve...before` never opens or closes a road; it only changes which open roads traffic tends to take.

## Level 2: Core Mechanics

### Basic Constraint Block

<InteractiveCode language="systemverilog" code={`class addr_range;
  rand bit [7:0] low, high;
  constraint c_order { low < high; }
endclass`} />

### Soft Constraints

<InteractiveCode language="systemverilog" code={`class cfg;
  rand bit [7:0] timeout;
  constraint c_default { soft timeout == 8'd16; }
endclass

program test;
  cfg c = new();
  initial begin
    c.randomize();
    $display("timeout=%0d", c.timeout); // uses soft default
    c.randomize() with { timeout == 8'd4; }; // override default
    $display("timeout=%0d", c.timeout);
  end
endprogram`} />

### Bound every array size

<InteractiveCode language="systemverilog" code={`class packet;
  rand bit [7:0] len;                   // its type bounds it: 0..255
  rand bit [7:0] data[];
  constraint c_len  { len inside {[1:64]}; }
  constraint c_size { data.size() == len; }
endclass`} />

Two things to notice. First, the size is bounded. A `rand int size` with only `data.size() == size` lets the solver choose any size up to 2,147,483,647, which can exhaust memory or stall the run. Second, there is no `solve...before`. An array's size constraints are always solved before its element constraints (§18.5.7.1), so `len` is uniform over 1..64 no matter how many payloads each length allows.

### Ordering with `solve...before`

Use `solve...before` when a rare mode would otherwise almost never be picked:

<InteractiveCode language="systemverilog" code={`class txn;
  rand bit       is_err;
  rand bit [7:0] len;
  constraint c_err   { is_err -> len == 0; }
  constraint c_order { solve is_err before len; }
endclass`} />

Without `c_order` there are 257 legal `(is_err, len)` pairs and only one has `is_err = 1`, so errors appear on 1 call in 257. With it, `is_err` is drawn first, 50/50 over its legal values, then `len`. The legal pairs are exactly the same; only the odds change (§18.5.9).

## Level 3: Expert Tips

- `soft` gives a default that holds on every call until a hard constraint, an inline `with` constraint or a later soft constraint contradicts it (§18.5.13.1). Then it is dropped completely; it never becomes "less likely".
- `solve...before` is never needed for correctness. The solver handles dependencies in both directions on its own. Add it only to reshape the odds, as in the `is_err` example, and never on `randc` variables.
