## Quick Take

- **What it is:** The second page of I-SV-3A. The [module page](/curriculum/T2_Intermediate/I-SV-3A_Functional_Coverage_Fundamentals/index) taught covergroups, bins and crosses. This page covers the two decisions every covergroup still needs. **When does it sample?** That is fixed by its coverage event, or by the code that calls `sample()`. **How are its bins built, counted and reported?** That is set by its **options**: `option.*` members that belong to one instance, and `type_option.*` members that belong to the covergroup type (IEEE 1800-2023 §19.3, §19.7, §19.7.1).
- **Why it matters:** Sampling and option mistakes produce numbers that look healthy. A covergroup that samples idle cycles, samples twice, or reads a value one clock stale can report 100% on traffic that never happened; an option set at the wrong level silently changes every coverpoint's threshold. None of these errors makes the simulator complain.
- **The Analogy:** a covergroup is a camera and its bins are the photo album. The coverage event is the shutter button, and the options are the album's rules: how many photos of a scene count (`at_least`), how much each page weighs (`weight`), what the caption says (`comment`). *Where it breaks:* a clocked covergroup clicks on every clock edge, including idle cycles, unless an `iff` guard covers the lens, and the album counts every click. Press the button twice for one scene and the album shows two scenes.

**You will be able to:**
1. **Choose** a sampling method (clocking event, built-in `sample()`, `sample()` with arguments, block event, `iff` guard), and **predict** when and how often a covergroup samples, including when it reads through a clocking block.
2. **Configure** `at_least`, `auto_bin_max`, `weight`, `goal`, `per_instance` and `comment` at the right level, **predict** which covergroup-level options reach coverpoints and crosses, and **explain** `option` versus `type_option`.
3. **Debug** coverage numbers that mislead because of sampling or options: idle-cycle samples, double samples, stale clocking-block reads, and options set at the wrong level.

## Build Your Mental Model

**How to read this page.** First, what triggers a sample and how to sample a bus without a race. Then guards, the options table and the difference between `option` and `type_option`. Make It Work runs one covergroup with every common option and traces its numbers. Push Further holds the corner cases.

### When does a covergroup sample?

Options do not decide when a covergroup samples. Its **coverage event** does, or the code that calls `sample()` (§19.3). Only one type option, `strobe`, moves clocked samples within a time step. A covergroup never samples just because the variables it covers changed.

| Coverage event | When it samples | Typical use |
| --- | --- | --- |
| Clocking event: `covergroup cg @(posedge clk);` | Every time the event fires, as if the process that triggered the event had called `sample()`. Several events in one time step give several samples | A covergroup inside an interface, on a signal-level view |
| None: `covergroup cg;` | Only when code calls the built-in `cov.sample()` (no arguments) | Covering variables the calling code has just updated |
| `covergroup cg with function sample(bus_item t);` | Only when code calls `cov.sample(t)` and passes the data in (§19.8.1) | Coverage collectors fed by a monitor: the usual testbench style |
| Block event: `covergroup cg @@(begin drive_item);` | Just before the named task, function or block starts (`begin`) or just after it ends (`end`) | Rare; covering calls to a task |

**Sampling with arguments** (§19.8.1) is the most common style in class-based testbenches, because the monitor hands each observed transaction straight to the covergroup. Three rules apply: a sample argument may appear only in coverpoint expressions and `iff` guards (not, for example, in an option), it may not be an `output`, and it may not reuse the name of one of the covergroup's own `new()` arguments.

**Never mix styles on one covergroup.** A clocked covergroup that a monitor also samples with `cov.sample()` on the same edge counts every transfer twice. Hit counts double, so a bin with `at_least = 2` closes on half the real traffic, and transition bins see repeated values that never happened: with every value sampled twice, a bin such as `(0 => 1 => 2)` can never match.

What you just saw:

- **`@(posedge clk) iff (valid)`** sampled every edge, but only the three edges with `valid` = 1 counted, and only one of them carried a `high` address: 1 hit, so `high` is not covered, and the coverpoint honestly reads 50%.
- **`@(posedge clk)` with no `iff`** counted 6 hits in `high`, most of them idle cycles where `addr` held a leftover value. The coverpoint reads 100% from a single real transfer to the high range.
- **`@(posedge clk)` plus `sample()`** counted every valid edge twice: 2 hits from one transfer, again a false 100%.
- **`with function sample()` from a monitor** counted exactly the transfers: 1 hit. One transfer, one sample.

The two false closures happen only because `at_least` is 2. With the default `at_least = 1`, the percentages would agree, and only the hit counts and transition bins would betray the extra samples.

### Sampling through a clocking block

A **clocking block** ([F4C](/curriculum/T1_Foundational/F4C_Clocking_Blocks/index)) samples each of its inputs at its clocking event and keeps the value in a **clockvar** such as `mon_cb.addr`. With the default `#1step` input skew, the clockvar holds the value from the **Preponed** region, the start of the time slot before anything has changed ([F3B](/curriculum/T1_Foundational/F3B_Scheduling_Regions/index)). That is exactly the stable, pre-edge value coverage should see (§19.5, §14.13).

The trap is *when you read the clockvar*. The clocking block updates its clockvars at the clock edge and then triggers its own **clocking block event**, `@(mon_cb)`, in the Observed region (§14.10). A process that waits on `@(mon_cb)` is guaranteed to read the updated values. A process that waits on `@(posedge clk)` and then reads `mon_cb.addr` races with that update: §14.13 says it "may display the old or the newly updated sampled value". So a covergroup clocked on `@(posedge clk)` whose coverpoints read clockvars can count values one clock stale, with no message.

What you just saw: `@(cb)` followed by `cb.dout` always reads the clocking block's sample of that edge. `@(posedge clk)` followed by `cb.dout` is marked as a race (old or new), and reading the raw signal after `@(posedge clk)` is safe only while nothing writes it with a blocking assignment at the edge. Coverage inherits the same rules.

There are two race-free ways to sample a bus through a clocking block, and both read the clockvars:

```systemverilog
// snippet
// Form 1: the covergroup lives in the interface and samples on the clocking block event
interface bus_if (input logic clk);
  logic [3:0] addr;
  logic       valid;

  clocking mon_cb @(posedge clk);
    input addr, valid;            // default #1step: pre-edge values
  endclocking

  covergroup cg_bus @(mon_cb);    // fires in Observed, after mon_cb has updated
    cp_addr: coverpoint mon_cb.addr iff (mon_cb.valid === 1'b1) {
      bins low  = {[0:3]};
      bins high = {[12:15]};
    }
  endgroup

  cg_bus cov = new();
endinterface

// Form 2: a monitor waits on the clocking block event, then calls sample()
//   forever begin
//     @(vif.mon_cb);
//     if (vif.mon_cb.valid === 1'b1) cov.sample(vif.mon_cb.addr);
//   end
```

Two more pitfalls belong here. A covergroup clocked on `@(mon_cb)` that reads the **raw** signals (`addr` instead of `mon_cb.addr`) sees post-edge values, because the clocking block event fires in Observed, after this edge's nonblocking updates. And `type_option.strobe = 1` moves clocked samples to the Postponed region at the end of the time slot, at most one per slot: raw signals then hold their post-edge values too, while clockvars still hold the clocking block's pre-edge sample.

### Guards: iff on coverpoints, bins and crosses

An **`iff` guard** is a condition evaluated at each sample (§19.5, §19.6). When it is false, the guarded item ignores that sample.
- On a coverpoint, `coverpoint addr iff (valid)` ignores the whole coverpoint for that sample. This is how a clocked covergroup skips idle cycles.
- On a bin, `bins burst_hi = {[12:15]} iff (burst);` makes only that bin conditional.
- On a cross, `cross cp_addr, cp_op iff (!reset)` ignores the cross for that sample, and each cross bin may have its own `iff`.

A guard only filters samples that happen; it never causes one. A guard that is always false is a common reason for a coverpoint stuck at 0%.

### Options: what you can set, and where

Options are written inside the covergroup definition, at the level they apply to (§19.7, Table 19-1, Table 19-2):

```systemverilog
// snippet
covergroup cg_pkt with function sample(pkt_t pkt);
  option.per_instance = 1;          // covergroup level
  cp_len: coverpoint pkt.length {
    option.at_least = 3;            // coverpoint level
    bins len_small = {[0:63]};
  }
endgroup
```

| Option | Default | Allowed at | A covergroup-level value is the default for coverpoints and crosses? | Can be assigned after `new`? | Why you use it |
| --- | --- | --- | --- | --- | --- |
| `option.per_instance` | 0 | covergroup | no | no: definition only | Save and report this instance's coverage separately from the type |
| `option.get_inst_coverage` | 0 | covergroup | no | no: definition only | Keep per-instance numbers when `type_option.merge_instances = 1` (see I-SV-3B) |
| `option.goal` | 100 | all levels | **no** | yes | Target percentage for dashboards and regressions |
| `option.weight` | 1 | all levels | **no** | yes | How much this item counts in the weighted average above it |
| `option.comment` | `""` | all levels | **no** | yes | Plan IDs or notes saved with the data |
| `option.at_least` | 1 | all levels | **yes** | yes | Hits a bin needs before it counts as covered |
| `option.auto_bin_max` | 64 | covergroup, coverpoint | **yes** | no: definition only | Maximum number of automatic bins |
| `option.detect_overlap` | 0 | covergroup, coverpoint | **yes** | no: definition only | Warn when two bins of a coverpoint overlap |
| `option.cross_num_print_missing` | 0 | covergroup, cross | **yes** | yes | How many missing cross bins the report lists |
| `option.cross_retain_auto_bins` | 1 | covergroup, cross | **yes** | no: definition only | Keep automatic cross bins next to user-defined ones |
| `option.name` | generated | covergroup | no | yes | The instance's name in reports |
| `type_option.weight`, `goal`, `comment` | 1, 100, `""` | all levels | no | yes, through `::` | Weight, target and comment for the type (cumulative) number |
| `type_option.strobe` | 0 | covergroup | no | no: definition only | Take clocked samples at the end of the time slot, at most one per slot |
| `type_option.merge_instances` | 0 | covergroup | no | yes, through `::` | Compute the type number as the union of all instances' bins (see I-SV-3B) |
| `type_option.distribute_first` | 0 | covergroup | no | yes, through `::` | Distribute values to bins before a bin's `with` filter is applied |
| `type_option.real_interval` | 1.0 | covergroup, coverpoint | **yes** (the only type option that is) | no: definition only | Interval width for real-valued bins |

Read the fourth column carefully. **Except for `weight`, `goal`, `comment` and `per_instance`, an option set at covergroup level is the default for every coverpoint and cross**, which can override it (§19.7). So `option.at_least = 2` at covergroup level raises the threshold of every coverpoint and every cross; `option.goal = 90` at covergroup level changes only the covergroup's own goal. Type options set at covergroup level are never defaults for lower levels, except `real_interval` (§19.7.1).

Three more rules from §19.7: option assignments in the definition are evaluated when the instance is built with `new`, so a covergroup argument can set an option (`option.at_least = arg;`); setting the same option twice in one definition is an error; and `auto_bin_max`, `detect_overlap` and `cross_retain_auto_bins` cannot be assigned procedurally. The options that can be assigned after `new` use the instance's hierarchy, as in `cov.option.comment = "agent 0";` or `cov.cp_len.option.weight = 3;`.

### option versus type_option

`option` is a built-in member of every covergroup, coverpoint and cross **instance**: each instance has its own copy, and different instances can hold different values. `type_option` is a built-in **static** member, like a static class property: there is one copy per covergroup type, and it is set with constant expressions in the definition or assigned through the type with `::`, as in `cg_bus::type_option.merge_instances = 1;` or `cg_bus::cp_addr::type_option.weight = 3;` (§19.7.1, §19.10).

Two consequences follow. First, `option.per_instance` defaults to 0: unless you set it to 1, a tool is not required to save each instance's numbers, and only the type number is guaranteed in the database (Table 19-1). Second, two instances can never hold different `type_option` values, which is why the standard makes type options constant expressions. How the type number is computed from the instances, with and without `merge_instances`, and how to query both numbers while the test runs, is [I-SV-3B Coverage APIs](/curriculum/T2_Intermediate/I-SV-3B_Advanced_Functional_Coverage/coverage-apis)' topic. In one line: by default the type number is the weighted average of the instances (§19.11.3).

### Mistakes to avoid

1. **A clocked covergroup with no `iff`** on a bus that idles: idle edges sample leftover values.
2. **Two sampling styles on one covergroup**: every transfer counts twice.
3. **Reading clockvars after `@(posedge clk)`**: a race that can read the previous edge's sample. Trigger on `@(cb)`.
4. **Reading raw signals after `@(cb)` or with `strobe`**: you see post-edge values.
5. **Setting `at_least` at covergroup level for one coverpoint's sake**: it reaches every coverpoint and cross.
6. **Assuming `per_instance` is on**: it defaults to 0.

## Make It Work

### Worked example: one packet covergroup, every option at its level

The covergroup below has no clocking event; the bench calls `sample()` once per packet, and an `iff` guard skips packets whose `valid` bit is 0. Read the comments to see which level each option lives at.

```systemverilog
// compile
module tb_top;
  typedef struct packed {
    bit       valid;
    bit [1:0] kind;
    bit [7:0] length;
  } pkt_t;

  // No coverage event: code calls sample() once per packet (§19.8.1)
  covergroup cg_pkt with function sample(pkt_t pkt);
    option.per_instance = 1;    // save this instance's numbers (default 0)
    option.goal         = 90;   // this covergroup's goal only; items keep 100
    option.weight       = 2;    // this instance's weight in the overall total only
    option.comment      = "VP-3.1";
    option.auto_bin_max = 16;   // default for every coverpoint; definition only
    cp_kind: coverpoint pkt.kind iff (pkt.valid);   // min(2^2, 16) = 4 automatic bins
    cp_len:  coverpoint pkt.length iff (pkt.valid) {
      option.at_least = 3;              // this coverpoint only
      bins len_small    = {[0:63]};
      bins len_large[4] = {[64:255]};   // 4 bins of 48 values
    }
  endgroup

  cg_pkt cov = new();
  pkt_t  stream[6] = '{'{1, 0, 10}, '{1, 1, 70}, '{1, 2, 200},
                       '{0, 3, 5},  '{1, 0, 30}, '{1, 0, 40}};

  initial begin
    foreach (stream[i]) cov.sample(stream[i]);
    $display("cp_kind: %6.2f%%", cov.cp_kind.get_inst_coverage());
    $display("cp_len : %6.2f%%", cov.cp_len.get_inst_coverage());
    $display("cg_pkt : %6.2f%% (goal 90)", cov.get_inst_coverage());
  end
endmodule
```

**Predict first.** Which bins does each packet hit, which bins reach their `at_least`, and what are the three percentages? Packet 4 has `valid` = 0.

| # | valid, kind, length | `cp_kind` | `cp_len` | `len_small` hits (needs 3) |
| --- | --- | --- | --- | --- |
| 1 | 1, 0, 10 | `auto[0]` | `len_small` | 1 |
| 2 | 1, 1, 70 | `auto[1]` | `len_large[0]` (64–111) | 1 |
| 3 | 1, 2, 200 | `auto[2]` | `len_large[2]` (160–207) | 1 |
| 4 | 0, 3, 5 | guard false: ignored | guard false: ignored | 1 |
| 5 | 1, 0, 30 | `auto[0]` | `len_small` | 2 |
| 6 | 1, 0, 40 | `auto[0]` | `len_small` | 3: covered |

**Expected output** (illustrative: computed by hand from IEEE 1800-2023 §19.7 and §19.11, not captured from a simulator run):

```text
cp_kind:  75.00%
cp_len :  20.00%
cg_pkt :  47.50% (goal 90)
```

Why these numbers:
- `cp_kind` has 4 automatic bins and 3 were hit (`at_least` 1, the default). Kind 3 did appear, in packet 4, but the guard was false, so `auto[3]` is still a hole: 3 of 4 = 75%.
- `cp_len` has 5 bins and needs 3 hits per bin. Only `len_small` reached 3; `len_large[0]` and `len_large[2]` have one hit each and do not count yet: 1 of 5 = 20%.
- The covergroup is the average of its two items, each with weight 1, because the covergroup-level `weight = 2` does not propagate: (75 + 20) ÷ 2 = 47.5%. The goal of 90 is also the covergroup's own; each coverpoint's goal stays 100.

Try one change in your head: move `option.at_least = 3` from `cp_len` to the covergroup level. Then `cp_kind` also needs 3 hits per bin, only `auto[0]` reaches it, and `cp_kind` drops to 25%.

### How to choose sampling and options

1. **Pick one sampling style per covergroup.** In class-based testbenches, use `with function sample(…)` and call it from the monitor or collector once per observed transaction.
2. **If the covergroup is clocked, guard it** with `iff` on the "transfer happened" condition, and trigger on the clocking block event `@(cb)` when it reads clockvars.
3. **Set options at the lowest level that needs them.** Put `at_least` on the coverpoint that the plan row is about, not on the covergroup.
4. **Set `per_instance = 1`** whenever you need numbers per agent, per port or per channel.
5. **Write plan IDs into `option.comment`** on the coverpoint or cross that measures them.
6. **Predict the percentages for a short directed stream** before trusting a regression number.

### Debugging sampling and options

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| Counts far above the number of transfers; early 100% | Clocked covergroup without `iff` samples idle edges | Add `iff (valid)` or sample from the monitor |
| Every count exactly doubled; multi-step transition bins never hit | A clocking event and a manual `sample()` on the same edge | Keep one style |
| Coverage looks one transfer behind, or differs between simulators | Clockvars read after `@(posedge clk)`: a race with the clocking block's update | Trigger on `@(cb)` |
| Values look like the *next* transfer's | Raw signals read after `@(cb)`, or with `strobe = 1` | Read the clockvars (`cb.x`) |
| One coverpoint needs more hits than planned | `at_least` set at covergroup level propagated to it | Move `at_least` to the coverpoint |
| Changing `goal` or `weight` on the covergroup did not change any coverpoint | Those four options never propagate | Set them on each coverpoint or cross |
| No per-agent numbers in the report | `per_instance` left at its default 0 | Set `option.per_instance = 1` in the definition |
| Compile error assigning `cov.option.per_instance` or `cov.option.auto_bin_max` after `new` | Definition-only options | Set them in the covergroup definition |

**Checklist before moving on:**
- [ ] You can say when each of the four coverage-event forms samples, and why a covergroup never samples just because its variables changed.
- [ ] You can sample a bus through a clocking block without a race, and say which values the raw signals hold at that point.
- [ ] You can name the four options that never act as defaults for coverpoints and crosses.
- [ ] You can say which options must be set in the definition.
- [ ] You can explain `option` versus `type_option`, and what `per_instance` defaults to.

## Push Further

### Expert: sampling corner cases

From §19.3, §19.5, §19.8.1 and §14.13:
- **Several events in one time step** give several samples of a clocked covergroup (a glitching clock, or an event triggered twice). `type_option.strobe = 1` filters them to one sample per time slot, but it has no effect on `sample()` calls or block events.
- **Block events:** `@@(end task_name)` is not triggered if the task is disabled, so a covergroup on the end of a task misses aborted calls.
- **Virtual interfaces:** coverpoint expressions and guards are evaluated in a procedural context, so a covergroup inside a class can read `vif.mon_cb.addr` directly (§19.5). It still samples only on its event or `sample()` call.
- **`#0` input skew:** a coverpoint on a clockvar with an explicit `#0` input skew reads Observed-region values, not Preponed ones (§19.5, §14.13).
- **A clocking event may use covergroup arguments,** for example `covergroup cg (ref logic clk) @(posedge clk);`.
- **Assertion coverage:** because a `sample()` with arguments can be called from anywhere, a concurrent assertion's match item can call it and pass an assertion local variable, as in §19.8.1's `@(posedge clk) (a, x = b) ##1 (c, cg1.sample(a, x))`. Assertions and local variables are taught in [I-SV-4A](/curriculum/T2_Intermediate/I-SV-4A_SVA_Fundamentals/index) and I-SV-4B.

Interview angle: "Your clocked covergroup and your monitor disagree by exactly one transfer on some simulators and not others. Why?" (A clockvar read after `@(posedge clk)` races with the clocking block's update.)

### Expert: weights, zero denominators and counting only the cross

From §19.7, §19.7.1 and §19.11:
- **A covergroup's number is the weighted average** of its coverpoints and crosses, using each item's `option.weight`. `option.weight = 0` on coverpoints that exist only to feed a cross makes the cross the only number that counts (the explorer's "Count only the cross" toggle on the [module page](/curriculum/T2_Intermediate/I-SV-3A_Functional_Coverage_Fundamentals/index) does exactly this).
- **The type number weighs differently.** With the default `merge_instances = 0`, type coverage is the instances' average weighted by `option.weight`. With `type_option.merge_instances = 1`, items are weighted by `type_option.weight`, so set `type_option.weight = 0` too if the cross alone should count there (§19.11.3; details in I-SV-3B).
- **Zero denominators:** an item or covergroup whose denominator is zero (every bin empty, every weight zero, or no items) contributes nothing; it reports 0.0 if its own weight is nonzero and 100.0 if its weight is zero (§19.11, §19.11.1, §19.11.2).
- **Option arguments:** because options are evaluated at `new`, `covergroup cg (int w) …; option.weight = w;` gives each instance its own weight, but `type_option.weight = w` is a syntax error: type options take constant expressions only (§19.7.1).
- **Merged `at_least`:** when instances are merged, a bin counts as covered only if its total hits reach the largest `at_least` of all instances (§19.11.1).

### Debug challenge: the regression that closed too early

A team's bus covergroup reached 100% in an hour. A colleague rewrote it to sample from the monitor, and the same tests now stall at 50%. The original was:

```systemverilog
// snippet
covergroup cg_addr @(posedge clk);
  option.at_least = 2;
  cp_addr: coverpoint addr {
    bins low  = {[0:3]};
    bins high = {[12:15]};
  }
endgroup
```

Open the sampling tab above, pick the style that reproduces the 100%, and decide which number to trust before you open the answer.

<details>
<summary>Answer</summary>

The original matches the tab's *`@(posedge clk)`, no iff* style. It samples every clock edge, including idle cycles where `addr` still holds the last transfer's value, so one real transfer to the high range collects six hits and the bin passes `at_least = 2`. The monitor-based number (50%) is the honest one: only one real transfer reached `high`. Fix the original by adding `iff (valid)` to the coverpoint, or keep the monitor version; then add stimulus for a second high-range transfer. Never add a manual `sample()` to the clocked version: that doubles every count instead.

</details>
