  ## Elevator Pitch
  *IEEE 1800-2023, Clauses 16.3 and 16.5: Immediate and concurrent assertions*

  Immediate assertions execute like regular procedural statements and check a condition, on current values, at the moment they run.

  Assertions catch bugs by checking that design behavior meets expectations. **Immediate** assertions fire instantly within procedural code. **Concurrent** assertions start an attempt at every tick of their clock, use values sampled just before the edge (§16.5.1), and can span many cycles.

  ## Practical Explanation

  ```systemverilog
  // Immediate assertion: procedural, checks current values when it executes
  always_ff @(posedge clk) begin
    if (!rst_n)
      assert (req == 0) else $error("req high during reset");
  end

  // Concurrent assertion: temporal, needs a clocking event
  property p_req_ack_within3;
    @(posedge clk) disable iff (!rst_n)
      req |-> ##[1:3] ack;
  endproperty
  a_req_ack_within3: assert property (p_req_ack_within3)
    else $error("ack did not arrive 1-3 cycles after req");
  ```

  Immediate assertions live in [procedural blocks](/curriculum/T1_Foundational/F2C_Procedural_Code_and_Flow_Control/index). Concurrent assertions sit outside procedural code (or inside it, as procedural concurrent assertions) and observe signal sequences, enabling checks like "req must be followed by ack within 3 cycles." A concurrent property needs a clocking event: write `@(posedge clk)` in the property, or declare a `default clocking` block in the scope. Without either, the property above would not compile. See [multi-clocking](/curriculum/T2_Intermediate/I-SV-4B_Advanced_Temporal_Logic/multi-clocking) for multi-clock properties.

  ## Advanced Notes

  * Concurrent assertions express time with `##` delays and repetition operators.
  * Use `disable iff` to discard attempts during reset: a disabled attempt is neither a pass nor a fail.
  * Remember: **Immediate = instant, current values; Concurrent = every clock tick, sampled values**.

  Concurrent assertions monitor temporal behavior across clock cycles using sequences and properties.

  <InteractiveCode>
  ```systemverilog
  sequence s_req_then_ack;
    req ##1 ack;
  endsequence

  property p_req_ack;
    @(posedge clk) req |-> s_req_then_ack;
  endproperty

  assert_req_ack: assert property (p_req_ack)
    else $error("Ack did not follow req");
  ```
  </InteractiveCode>

  ### Advanced Tips

  - Use immediate assertions for quick sanity checks inside procedural code.
  - Named sequences and properties can be declared in packages and reused (§16.12). The `assert property` statements themselves belong in modules, interfaces, programs, generate blocks, checkers or procedures (§16.14), often in a bind file.
