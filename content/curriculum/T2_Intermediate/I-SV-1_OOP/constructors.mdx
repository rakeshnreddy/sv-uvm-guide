  ## Constructors
  *IEEE 1800-2023, §8.7 Constructors and §8.17 Chaining constructors*

  SystemVerilog uses the `new` function as a constructor to create and initialize
  class objects. Constructors can accept arguments, letting you configure an
  object at creation time. If a class declares no `new`, an implicit one is
  provided (§8.7).

  <InteractiveCode>
  ```systemverilog
  class Packet;
    int addr;
    int data;

    // Constructor with arguments
    function new(int addr = 0, int data = 0);
      this.addr = addr;
      this.data = data;
    endfunction
  endclass

  module demo;
    Packet p;                    // a handle, null for now

    initial begin
      p = new(16'h10, 8'hFF);    // calls Packet::new
      $display("addr=%0h data=%0h", p.addr, p.data);
    end
  endmodule
  ```
  </InteractiveCode>

  ### What `new` does, in order (§8.7)

  1. The base-class constructor runs first: your explicit `super.new(...)`, or one the compiler inserts.
  2. Each property of this class is set to its declared initial value (for example `int count = 5;` or `header hdr = new;`).
  3. The rest of the constructor body runs.

  A shallow copy (`p2 = new p1;`) is the exception: it allocates the object without running any of these steps and copies the source's properties instead (§8.12). See [Copying and Cloning Objects](./copying-and-cloning).

  ## Using `this`

  The `this` keyword refers to the current object: the object whose method is running (§8.11). It disambiguates between
  member variables and constructor arguments or local variables with the same
  name, as in `this.addr = addr;` above.

  Inside a non-static method, `this` is never null: the method only runs because it was called on an object. A `static` method has no `this` at all (§8.10).

  ## Calling the Parent with `super`

  When a class extends another, its constructor can invoke the parent
  constructor using `super.new()`. The same keyword allows a method to call the
  overridden version in the parent (§8.15).

  <InteractiveCode>
  ```systemverilog
  class Base;
    int id;
    function new(int id);
      this.id = id;
    endfunction
    function void print();
      $display("Base id=%0d", id);
    endfunction
  endclass

  class Child extends Base;
    string name;
    function new(int id, string name);
      super.new(id); // must be the first statement (§8.17)
      this.name = name;
    endfunction
    function void print();
      super.print(); // call Base::print
      $display("  Child name=%s", name);
    endfunction
  endclass

  module demo;
    Child c;
    initial begin
      c = new(1, "pkt");
      c.print();
    end
  endmodule
  ```
  </InteractiveCode>

  If every subclass passes the same constant arguments, you can put them in the `extends` clause instead, for example `class EtherPacket extends Packet(5);`, and the compiler inserts the `super.new` call (§8.17).

  ## Common Pitfalls

  - **Omitting `super.new(...)` does not skip the base constructor.** The compiler inserts an argument-less `super.new()` as the first statement (§8.15). If the base constructor has an argument without a default, that inserted call does not compile. If every base argument has a default, it compiles and you silently get those defaults. Pass the arguments you mean.
  - **`super.new(...)` must be the first statement** in the constructor (§8.17).
  - **Calling through a null handle**, not using `this`, is the real null pitfall: `p.print()` or `p.addr = 1` when `p` was never constructed is illegal and stops the simulation (§8.4).
  - **A virtual call inside a base constructor runs the subclass override** (§8.17, §8.20), but at that moment the subclass's own properties have not been initialized yet; their values are undefined (§8.7). Keep constructors free of virtual calls that read subclass state.
