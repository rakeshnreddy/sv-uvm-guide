  ## The Assignment Operator vs. Copying
  *IEEE 1800-2023, §8.12 Assignment, renaming, and copying*

  In SystemVerilog, assigning one object handle to another (`p2 = p1`) **does not** copy the object. It copies the handle. Both variables now refer to the same object.

  <InteractiveCode>
  ```systemverilog
  class Packet;
    int data = 10;
  endclass

  module demo;
    Packet p1, p2;
    initial begin
      p1 = new();
      p2 = p1;            // p2 refers to the SAME object
      p2.data = 20;
      $display(p1.data);  // prints 20
    end
  endmodule
  ```
  </InteractiveCode>

  ## Shallow Copy: `p2 = new p1;`

  `new` followed by a handle makes a shallow copy (§8.12). Precisely:

  1. A new object of the **source object's class** is allocated. Through a base-class handle that holds a subclass object, the copy is a subclass object too.
  2. The constructor does **not** run, and neither do declaration initializers such as `header hdr = new;`. A counter incremented in `new()` therefore does not count shallow copies.
  3. Every property is copied, including the random-number state and `rand_mode`/`constraint_mode` settings. Integers, strings, queues and dynamic arrays get their own copies, because assigning an array copies its elements (§7.6).
  4. Class-handle properties are copied **as handles**. The nested objects are shared, not duplicated.

  A typed constructor call (`Packet::new`) cannot be combined with a shallow copy (§8.12).

  <InteractiveCode>
  ```systemverilog
  class Header;
    int id = 1;
  endclass

  class Packet;
    int data = 10;
    int q[$] = {1, 2};
    Header hdr = new;
  endclass

  module demo;
    Packet p1, p2;
    initial begin
      p1 = new();
      p2 = new p1;          // shallow copy

      p2.data = 20;         // safe: p2 has its own data
      p2.q.push_back(3);    // safe: the queue's elements were copied
      p2.hdr.id = 5;        // danger: p1.hdr and p2.hdr are the SAME Header
      $display("%0d %p %0d", p1.data, p1.q, p1.hdr.id);  // 10 '{1, 2} 5
    end
  endmodule
  ```
  </InteractiveCode>

  The same rule covers mailboxes, semaphores and any other object a class holds a handle to: after a shallow copy, both objects share them.

  ## Deep Copy and the `copy()` Method

  To duplicate an object together with the objects it refers to, write a `copy()` method. The language does not provide one. Copy the **contents** of each nested object, never just its handle, and guard against null handles on either side.

  <InteractiveCode>
  ```systemverilog
  class Header;
    int id = 1;

    function void copy(Header rhs);
      id = rhs.id;
    endfunction
  endclass

  class Packet;
    int data = 10;
    Header hdr = new;

    function void copy(Packet rhs);
      data = rhs.data;
      if (rhs.hdr == null) hdr = null;      // nothing to copy
      else begin
        if (hdr == null) hdr = new;         // make sure we have our own Header
        hdr.copy(rhs.hdr);                  // deep: copy contents, not the handle
      end
    endfunction
  endclass
  ```
  </InteractiveCode>

  Writing `hdr = rhs.hdr;` inside `copy()` would quietly turn it back into a shallow copy for that field.

  ## The `clone()` Method: copy that keeps the object's real type

  `copy()` fills an object that already exists; `clone()` creates the object and then copies into it. To clone correctly through a base-class handle, **both** methods must be virtual, each subclass must override both, and the subclass `copy()` must call `super.copy()` and use `$cast` to reach its own fields.

  <InteractiveCode>
  ```systemverilog
  class header;
    int len = 4;
    function void copy(header rhs);
      len = rhs.len;
    endfunction
  endclass

  class packet;
    int data;
    header hdr = new;

    virtual function void copy(packet rhs);
      data = rhs.data;
      if (rhs.hdr == null) hdr = null;
      else begin
        if (hdr == null) hdr = new;
        hdr.copy(rhs.hdr);
      end
    endfunction

    virtual function packet clone();
      packet c = new;      // class methods are automatic, so this runs on every call
      c.copy(this);
      return c;
    endfunction
  endclass

  class crc_packet extends packet;
    bit [7:0] crc;

    virtual function void copy(packet rhs);
      crc_packet r;
      super.copy(rhs);                         // copy the base part first
      if (!$cast(r, rhs))                      // rhs must really be a crc_packet
        $fatal(1, "crc_packet::copy: rhs is not a crc_packet");
      crc = r.crc;                             // then the subclass part
    endfunction

    virtual function packet clone();           // overrides keep the return type
      crc_packet c = new;                      // build the subclass object
      c.copy(this);
      return c;
    endfunction
  endclass

  module demo;
    packet p, q;
    crc_packet orig, back;
    initial begin
      orig = new;
      orig.crc = 8'h5a;
      p = orig;                     // base handle, subclass object
      q = p.clone();                // virtual: runs crc_packet::clone
      if (!$cast(back, q)) $fatal(1, "clone lost the subclass");
      $display("%h", back.crc);     // 5a
    end
  endmodule
  ```
  </InteractiveCode>

  If `clone()` were not virtual, `p.clone()` would run `packet::clone()` and return a plain `packet`: the `crc` field would be lost and the `$cast` would fail. UVM's `clone()` and `do_copy()` follow the same shape, with `uvm_object` as the base class.
