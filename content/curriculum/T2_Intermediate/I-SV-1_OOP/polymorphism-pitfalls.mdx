  ## Method Resolution: Virtual vs Non-Virtual
  *IEEE 1800-2023, §8.14 Overridden members and §8.20 Virtual methods*

  When you call a method through a base class handle, SystemVerilog must decide which version of the method to execute.
  - If the method is **non-virtual**, the compiler binds the call to the declaration it sees from the **handle's declared class** (§8.14).
  - If the method is **virtual**, the call binds at run time to the **class of the object** the handle refers to: the latest override in that object's class (§8.20).
  - Once a method is virtual, every override of it in a subclass is virtual too, with or without the keyword (§8.20).

  <InteractiveCode>
  ```systemverilog
  class Base;
    function void print(); $display("Base print"); endfunction
    virtual function void v_print(); $display("Base v_print"); endfunction
  endclass

  class Child extends Base;
    function void print(); $display("Child print"); endfunction
    virtual function void v_print(); $display("Child v_print"); endfunction
  endclass

  module demo;
    Base b;
    Child c;
    initial begin
      c = new();
      b = c;       // upcast: b refers to a Child object

      b.print();   // "Base print": resolved by the handle's class
      b.v_print(); // "Child v_print": resolved by the object's class
    end
  endmodule
  ```
  </InteractiveCode>

  Members that a subclass adds are invisible through a base-class handle. If `Child` declared a new method `crc()`, then `b.crc()` would not compile even though the object is a `Child` (§8.14). You must first get a `Child` handle, which is what `$cast` is for.

  ## Upcasting vs. Downcasting
  *IEEE 1800-2023, §8.16 Casting and §6.24.2 $cast dynamic casting*

  ### Upcasting (always legal)
  Assigning a subclass handle to a superclass variable is always legal and needs no cast (§8.16).

  ```systemverilog
  Child c;
  Base  b;
  initial begin
    c = new();
    b = c;              // implicit upcast
    b = Child::new();   // also legal: a typed constructor call (§8.8)
  end
  ```

  ### Downcasting (checked at run time)
  Assigning a superclass handle directly to a subclass variable is illegal, **whatever object it holds**: the compiler only knows the handle's declared class (§8.16). Use `$cast`, which checks the object at run time and succeeds only when the object is the destination class or a subclass of it.

  `$cast` has two forms, and they fail differently (§6.24.2):
  - **As a function** (`if ($cast(dst, src))`), a failed cast returns 0, leaves `dst` unchanged, and reports nothing. Always test the result.
  - **As a task** (`$cast(dst, src);`), a failed cast is a run-time error, and `dst` is unchanged.

  <InteractiveCode>
  ```systemverilog
  module demo;
    Base  b1, b2;
    Child c;
    initial begin
      b1 = Child::new();  // b1 holds a Child
      b2 = new();         // b2 holds a Base

      // c = b1;          // compile error: no implicit downcast

      if ($cast(c, b1))
        $display("Cast successful: c now refers to the Child object.");
      else
        $fatal(1, "Cast failed!");

      if (!$cast(c, b2))
        $display("Cast failed: b2 does not hold a Child. c is unchanged.");
    end
  endmodule
  ```
  </InteractiveCode>

  ## Interview Pitfall: Default Arguments on Virtual Methods

  A popular trick question gives a base virtual method and its override **different default argument values**, then asks which default a call through a base handle uses. Here is what IEEE 1800-2023 actually says:

  - An override must match the **presence** of each default, but the default **expressions** may differ (§8.20).
  - A default expression is evaluated in the scope of the subroutine declaration each time a call uses it (§13.5.3).

  The standard does not say which override's declaration supplies the default when you call through a base-class handle. "The handle's type wins" is the C++ rule; it is not stated for SystemVerilog, so do not rely on it. Treat differing defaults as a portability bug: keep the default identical in every override, or pass the argument explicitly.
