  ## Multi-Clocking and disable-iff
  *IEEE 1800-2023, Clause 16.13: Multiclock support, and Clause 16.12: Declaring properties (disable iff)*

  Designs often cross clock domains. SVA lets you relate events on different clocks within one property.

  <InteractiveCode>
  ```systemverilog
  // Every write on wr_clk must be followed by a read on rd_clk
  property p_wr_followed_by_rd;
    @(posedge wr_clk) disable iff (!rst_n)
      wr_en |=> @(posedge rd_clk) rd_en;
  endproperty

  a_wr_then_rd: assert property (p_wr_followed_by_rd)
    else $error("Read did not follow write across clocks");
  ```
  </InteractiveCode>

  For each `wr_clk` edge where `wr_en` is sampled high, `|=>` advances to the nearest strictly later `posedge rd_clk` and checks `rd_en` there (§16.13.2). Edges where `wr_en` is low are vacuous. Asserting the multiclock *sequence* `@(posedge wr_clk) wr_en ##1 @(posedge rd_clk) rd_en` directly would be a bug: a sequence used as a property has no antecedent, so it fails on every `wr_clk` edge where `wr_en` is 0 (§16.12.2).

  ### Understanding `disable iff`

  `disable iff (expr)` gives a property a reset condition (§16.12):
  - If the condition is true at any time between the start of an attempt and its end, the attempt is **disabled**: it reports neither a pass nor a failure, and no action block runs. Attempts already in flight are aborted, not just new ones.
  - The condition uses **current** values, not sampled values, so an asynchronous reset takes effect as soon as it changes. Use `$sampled(rst)` if you want the sampled value (§16.9.3).
  - Do not put `$past`, `$rose` or other sampled-value functions in the condition without an explicit clocking event, and do not nest `disable iff` (§16.12). A guard such as "skip the first cycle after reset" belongs in the antecedent: `!$past(rst) |-> ...`.

  <InteractiveCode>
  ```systemverilog
  property p_ack_within3;
    @(posedge clk) disable iff (!rst_n)
      req |-> ##[1:3] ack;
  endproperty
  ```
  </InteractiveCode>

  ### Tips

  - Use an `@` clocking event inside a sequence or property to hop to another clock. The clock flows left to right until a new clocking event replaces it (§16.13.3).
  - In a multiclock concatenation, `##1` moves to the nearest tick of the new clock *strictly after* the current tick. `##0` moves to the nearest tick *at or after* it: time stays put only when both clocks tick in the same time step; otherwise `##0` behaves like `##1` (§16.13.1).
  - Always guard cross-domain assertions with `disable iff` for asynchronous resets.
