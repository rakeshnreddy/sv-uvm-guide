  ## Level 1: The Big Idea
  *IEEE 1800-2023, Clause 15.3: Semaphores*

  A **semaphore** is like a set of keys. Processes must take a key (`get`) before using a shared resource and return it (`put`) when done. If no keys are available, the process waits.

  ## Level 2: Practical Usage

  ### Getting and Putting Keys

  -   `semaphore sem = new(1);` creates a semaphore with one key.
  -   `sem.get(n);` acquires `n` keys, blocking until `n` are free at once. Waiters are queued first-in first-out and resume by themselves (IEEE 1800-2023 §15.3.3).
  -   `sem.put(n);` releases keys. It never checks who took them, and it can raise the count above the initial value (§15.3.1).
  -   `sem.try_get(n);` attempts to get keys without blocking: positive if it got them, 0 otherwise (§15.3.4).

  <InteractiveCode>
  ```systemverilog
  semaphore bus_sem = new(1);

  // automatic: each concurrent call gets its own copy of name.

    #10;
    bus_sem.put(1);        // release
  endtask

  initial begin
    fork
      master("A");
      master("B");
    join
  end
  ```

  ## Failure Modes: Key Leaks and Deadlock

  **The Lost Key / Leak:** 
  The most common semaphore bug is acquiring a key and failing to return it. If a thread takes an early `return`, or is killed by `disable fork` or `process::kill()` before it calls `sem.put(...)`, that key is gone forever. SystemVerilog has no exceptions and no automatic cleanup: nothing returns the key for you. Subsequent threads calling `get()` will hang, starving the system. To avoid this, make every exit path of the critical section call `put()`.

  Find the line that loses the key, then choose a fix. The model reruns the whole test and checks three things: nobody is left blocked, two senders never share the bus, and the bus ends with all its keys.

  **Deadlock (Circular Wait):**
  If Thread A holds Semaphore 1 and waits for Semaphore 2, while Thread B holds Semaphore 2 and waits for Semaphore 1, the simulation halts indefinitely. 
  
  **The Fix:** Always acquire multiple semaphores in a strict, globally agreed-upon order, or use `try_get` with timeouts and randomized backoffs to break the cycle.

  **Coordinating Random Stimulus:** When multiple threads generate randomized transactions, semaphores ensure only a safe number run concurrently. For more on stimulus generation, revisit [Constrained Randomization](/curriculum/T2_Intermediate/I-SV-2A_Constrained_Randomization_Fundamentals/index).
