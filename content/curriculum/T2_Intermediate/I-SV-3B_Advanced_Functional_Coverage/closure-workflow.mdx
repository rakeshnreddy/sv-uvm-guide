## Level 1: The Infinite Loop Warning
If you write a completely unconstrained random test and let it run forever, will you hit 100% coverage? 

Only if every bin has a nonzero chance per sample. Even then, the wait is set by the rarest bin: a bin hit once in 10,000 samples needs about 10,000 samples on its own, and a 3-event corner case can be far rarer. A bin your constraints make impossible never closes, however many seeds you run. You cannot achieve closure purely by running more random seeds. You must actively participate in a **Closure Loop**.

## Level 2: The Canonical Workflow

Coverage closure is a repetitive engineering process:

1. **Run Regressions:** Run your test suite with many random seeds.
2. **Merge Databases:** The CI/CD system merges all the individual test coverage databases (UCDB/UCIS) into one master database.
3. **Identify Holes:** Open the master database in a viewer. Look for bins with 0 hits.
4. **Analyze the Unhit Bins:** Why wasn't this bin hit?
   - Is it impossible by the spec? Exclude it: `illegal_bins` if it must never happen (you then get an error if it ever does), `ignore_bins` if it simply does not matter. Then update the V-Plan.
   - Is it legal, but the generator constraints make it extremely rare?
   - Is it legal, but a constraint makes it impossible? That is a generator bug.
   - Is the testbench missing a directed sequence to set up the precise conditions?
5. **Adjust Stimulus:** Change constraint weights (`dist`), write a new directed sequence, or create a specific test to target the hole.
6. **Repeat:** Re-run the regression and verify the hole is filled.

The same hole needs a different fix depending on the spec. Pick the spec, then try each fix: the model reruns the same seed and checks whether coverage closes and whether the fix is faithful to the spec.

## Level 3: Practice Makes Perfect

Reading about closure is easy; actually doing it requires an intuition for interpreting coverage data and translating it back into generator constraints. 

In the upcoming lab, you will be handed a mostly-working ALU testbench. You will run it, analyze the coverage holes in the report, and then modify the constraints using `dist` weighting and edge-case generation to hit 100% without rewriting the whole environment.

**Count the bins before you change anything.** In `alu_cov_mon.sv`:

- `cp_op` has 7 automatic bins, one per `op_t` constant. Its `ignore_bins unused = {7}` changes nothing, because 7 is not an `op_t` value.
- `cp_a` and `cp_b` each have 2 counted bins, `zero` and `max`. `others` is a default bin: it is not counted and not crossed.
- `cross_max_op` crosses `cp_op` with `cp_a`: 7 × 2 = 14 cross bins, one for every operation with `a == 0` and one for every operation with `a == 8'hFF`.

The starter run finishes well short of 100% (about 70% on average): `DIV` is never generated, and each `a == 0` or `a == 8'hFF` value shows up only once in 256 samples. The lab's steps add `DIV` and weight `8'hFF`, but that is **not enough**: `a == 0` stays at 1 in 256, so most of the seven `op` × `zero` cross bins stay empty after 500 samples. Weight **both** edge values, for `a` and for `b`, for example:

```systemverilog
a dist {0 := 1, 8'hFF := 1, [1:254] :/ 2};
b dist {0 := 1, 8'hFF := 1, [1:254] :/ 2};
```

Each edge value then appears in a quarter of the samples, and 500 samples close all 14 cross bins with near certainty.
