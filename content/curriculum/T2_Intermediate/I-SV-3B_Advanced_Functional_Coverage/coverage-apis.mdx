## Level 1: Why Query Coverage at Runtime?
*IEEE 1800-2023, Clause 19.8: Predefined coverage methods*

Normally, coverage is analyzed *after* the simulation finishes by loading the database (UCDB/UCIS) into a viewer. But what if you want your testbench to be smart enough to stop running as soon as 100% is reached, saving server compute time? What if you want to switch to a different random seed dynamically if coverage gets stuck? 

To do this, the testbench needs to read its own coverage score while it is running.

## Level 2: Core Mechanics

### 1. `get_inst_coverage()`
This method returns the coverage percentage (0.0 to 100.0) for a specific *instance* of a covergroup. Set `option.per_instance = 1` whenever you rely on per-instance numbers: it is what makes the tool save each instance's data in the database and report it separately (§19.7, Table 19-1). One trap: once `type_option.merge_instances = 1` is set, `get_inst_coverage()` returns the merged type number unless the instance also sets `option.get_inst_coverage = 1`.

<InteractiveCode language="systemverilog" code={`class monitor;
  bit [1:0] state;

  covergroup cg;
    option.per_instance = 1;   // keep this instance's data separately
    cp_state: coverpoint state;
  endgroup

  function new();
    cg = new();
  endfunction

  function void check_done();
    // Get the score for this specific instance
    real score = cg.get_inst_coverage();

    $display("Current instance coverage: %0.2f%%", score);
    if (score == 100.0) begin
      $display("Goal reached! Stopping simulation.");
      $finish; // Early exit saves compute!
    end
  endfunction
endclass`} />

### 2. `get_coverage()`
There are two ways to ask for more than one instance.
1. `cg.get_coverage()` (or the static form through the type, `type::get_coverage()`) returns the **type** coverage: every instance of that covergroup type together. By default (`type_option.merge_instances = 0`) it is the **weighted average** of the instances, not a union: two instances at 100% and 50% give 75%. With `type_option.merge_instances = 1` it is the coverage of the union of all instances' bins (§19.11.3).
2. `$get_coverage()`: a system function that returns the overall coverage of all covergroup types in the simulation (§19.9).

### 3. `set_inst_name()`
By default, every instance of a covergroup in the database gets a tool-generated name. If you have 10 channels, you cannot tell their rows apart. With `option.per_instance = 1` set, give each instance a name during creation:

```systemverilog
function new(string name);
  cg = new();
  cg.set_inst_name(name); // Now they appear as "tx_chan_cg", "rx_chan_cg", etc.
endfunction
```

## Level 3: Real-world Usage

You can query individual items down to the coverpoint or cross level, using the coverpoint's label.
- `cg.cp_state.get_inst_coverage()`: the score of the `cp_state` coverpoint in this instance.
- `cg.cp_state.get_coverage()`: the same coverpoint across every instance of the type.

Both methods also accept two `int` arguments passed by reference, which receive the number of covered bins and the number of bins: `cg.cp_state.get_inst_coverage(covered, total);` (§19.8).

**Warning on Performance:**
Calculating coverage scores takes CPU cycles. Do not call `.get_inst_coverage()` every single clock cycle or every transaction. A common best practice is to query it on a slower heartbeat thread (e.g., every 1 millisecond of simulation time) or only during phase wrap-up.
