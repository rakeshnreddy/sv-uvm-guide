## Quick Take

- **What it is:** Every covergroup comes with a small set of built-in methods and three coverage system routines (IEEE 1800-2023 §19.8, §19.9). With them the testbench can read coverage *while it runs*: one instance's number with `get_inst_coverage()`, the number for every instance of the type with `get_coverage()`, the number for the whole design with `$get_coverage()`, and the bin counts behind each item. It can also name instances (`set_inst_name()`), pause and resume collection (`stop()`, `start()`) and choose the database file the run saves.
- **Why it matters:** These numbers drive decisions: when to stop sending stimulus, when to switch to a stimulus mode that targets the holes, which lane is lagging. Read the wrong number and the decision is wrong. The classic slips are reading the type number as if it were this instance's, trusting a bin ratio that is not the percentage, freezing coverage with a `stop()` that never gets its `start()`, and calling `$finish` the moment coverage reaches 100 % so the checks never finish.
- **The Analogy:** A chain of shops all use the same stock-count form (the covergroup type). Each shop fills in its own copy (an instance), and each line on the form (a coverpoint or cross) lists the shelves (bins) to tick. A shop manager reads her own copy (`get_inst_coverage()`). Head office reads one figure for the whole chain (`get_coverage()`): by default the *average* of the shops' scores, or, if it chooses, one merged form where a shelf ticked by any shop counts (`merge_instances`). A shop that is closed for a stock-take pauses its counting (`stop()`) and resumes when it reopens (`start()`). *Where it breaks:* the form records only that a shelf was visited, never whether the stock on it was right. That judgement belongs to the checks, so a full form never proves the shop is in order.

**You will be able to:**
1. Predict what `get_inst_coverage()`, `get_coverage()` and `$get_coverage()` return for a set of covergroup instances, both under the default weighted average and with `type_option.merge_instances = 1`.
2. Choose `per_instance`, `option.get_inst_coverage`, `merge_instances`, goals and weights so that the number you read is the number you need, and calculate how a weight change moves it.
3. Write run-time queries and controls (item-level `get_inst_coverage(covered, total)`, `set_inst_name()`, `start()`/`stop()` and the §19.9 system tasks) and use them to end the stimulus at a goal without cutting off the checks.
4. Debug coverage numbers that look wrong: coverage that freezes, 100.0 at time 0, a healthy type number that hides a weak instance, and a `(covered, total)` pair that disagrees with the percentage.

## Build Your Mental Model

**How to read this lesson.** The core path is the first two sections: what an instance number and a type number are, and how the two ways of computing the type number differ. Practitioner depth follows: every method and where you may call it, the bin counts, goals and weights, pausing collection, ending stimulus at a goal, and the system tasks. Make It Work runs one small bench that prints every number on this page, and Push Further holds the corner cases.

One running example serves the whole lesson. It is a trimmed version of the ALU collector used throughout this module: a class `alu_cov` whose embedded covergroup `cg` has three **coverage items** (an item is a coverpoint or a cross):

| Item | Plan row | Bins | Count |
|---|---|---|---|
| `cp_op` | ALU-1, every operation | one bin per operation: `ADD`, `SUB`, `MUL`, `DIV`, `AND`, `OR`, `XOR` | 7 |
| `cp_a` | ALU-2, operand `a` at its edges | `zero` (`8'h00`) and `max` (`8'hFF`); every other value lands in no bin | 2 |
| `x_op_a` | ALU-4, every operation with each edge of `a` | the cross of the two: 7 × 2 | 14 |

A **collector** is the class that owns the covergroup and calls its `sample()` once per transaction. A bin is **covered** once it has been hit at least `option.at_least` times (default 1). The module's full collector also covers operand `b` (ALU-3); it is left out here to keep the arithmetic short.

### Type coverage and instance coverage

A covergroup declaration defines a **covergroup type**. Each `new()` creates an **instance** of that type, with its own bin counts. A covergroup declared inside a class is an **embedded covergroup**: the declaration creates an *anonymous* type plus one instance variable, so every object of the class owns one instance of the same type (§19.4).

Three numbers come out of that structure, each a percentage from 0.0 to 100.0 returned as a `real` (a floating-point number):

- **Instance coverage**, from `get_inst_coverage()`, is the weighted average of the item percentages *of this one instance* (§19.11). Each item's percentage is its covered bins divided by its bins (§19.11.1, §19.11.2), and each item's `option.weight` (default 1) weights it.
- **Type coverage** (the LRM also calls it cumulative coverage), from `get_coverage()`, considers *every instance of the type* (§19.8, §19.11). Calling `lane0.cg.get_coverage()` does not give lane0's number; it gives the type's number, and `lane1.cg.get_coverage()` returns exactly the same value.
- **Overall coverage**, from the system function `$get_coverage()`, is the overall coverage of every covergroup type in the design (§19.9).

**The mistake everyone makes:** reading `cg.get_coverage()` inside a collector as "this collector's coverage". It is the type's number. For this instance's number, call `get_inst_coverage()`; it can only be called through an instance, with `.` (§19.8).

### Average or union: `merge_instances` and `option.get_inst_coverage`

The type number can be computed two ways, chosen by the type option `type_option.merge_instances` (§19.7.1, Table 19-3; §19.11.3):

| `merge_instances` | Type number (`get_coverage()`) | Our two lanes |
|---|---|---|
| 0 (default) | **weighted average** of the instance numbers | (66.67 + 52.38) / 2 = 59.52 |
| 1 | coverage of the **union** of every instance's bins, as if all instances were merged into one; bins are matched by name and their counts add | `cp_op` 7/7, `cp_a` 2/2, `x_op_a` 6/14, so (100 + 100 + 42.86) / 3 = 80.95 |

The union is higher here because lane1 hit the operations lane0 missed. A union answers "has the design as a whole seen this?"; an average answers "how far is a typical instance?". Neither answers "is *every* lane done?"; for that you read each instance.

Merging has a trap. With `merge_instances = 1`, `get_inst_coverage()` returns **the merged type number**, the same value from every instance, unless the covergroup definition also sets `option.get_inst_coverage = 1` (Table 19-1). Three options are easy to confuse:

| Option | Where it may be set | What it does |
|---|---|---|
| `option.per_instance` (default 0) | only in the covergroup definition (§19.7) | Saves this instance's data in the coverage database and shows it in the report. When 0, tools need not save instance data (Table 19-1). The LRM ties `get_inst_coverage()` to the next option, not to this one; still, set it whenever you read instance numbers, so the saved report has the same rows your test read. |
| `option.get_inst_coverage` (default 0) | only in the covergroup definition (§19.7) | Matters only when `merge_instances` is set: keeps per-instance tracking so `get_inst_coverage()` returns this instance's own number (Table 19-1). |
| `type_option.merge_instances` (default 0) | in the definition, or procedurally through a named type: `cg_t::type_option.merge_instances = 1;` (§19.7.1) | Chooses average or union for the whole type. Type options are one value per type; instances cannot differ (§19.7.1). |

The **coverage database** is the file the simulator writes at the end of the run, holding the bin counts that reports and merge tools read; its format is tool-specific.

Two consequences for the ALU collector. First, because its covergroup is embedded, its type has no name, so `cg_t::type_option...` is impossible: put `type_option.merge_instances = 1;` inside the covergroup definition. Second, because `per_instance` and `get_inst_coverage` are definition-only, a procedural `lane0.cg.option.get_inst_coverage = 1;` after `new()` is wrong; set both in the definition.

```systemverilog
// snippet: the alu_cov covergroup header when the type number must be a union
// and each port must still read its own number
covergroup cg with function sample(alu_txn t);
  option.per_instance        = 1;  // each lane's rows in the saved report
  option.get_inst_coverage   = 1;  // keep per-instance numbers while merging
  type_option.merge_instances = 1; // type number = union of all lanes' bins
  // ... the coverpoints and cross as before
endgroup
```

With those three lines, lane0 and lane1 still return 66.67 and 52.38 from `get_inst_coverage()`, while `get_coverage()` returns 80.95.

### The methods, and where you may call them

Table 19-5 of IEEE 1800-2023 lists every built-in coverage method. All can be called procedurally at any time (§19.8):

| Method | covergroup | coverpoint | cross | What it does |
|---|---|---|---|---|
| `void sample()` | yes | no | no | Samples the covergroup now. With `with function sample(...)` it takes your arguments (§19.8.1). |
| `real get_coverage()`, `real get_coverage(ref int, ref int)` | yes | yes | yes | Type coverage. A **static** method: call it on a type with `::` or on an instance with `.` |
| `real get_inst_coverage()`, `real get_inst_coverage(ref int, ref int)` | yes | yes | yes | Coverage of the instance it is called on; `.` only |
| `void set_inst_name(string)` | yes | no | no | Names this instance in the database and the report |
| `void start()` | yes | yes | yes | Starts (resumes) collecting coverage |
| `void stop()` | yes | yes | yes | Stops collecting coverage |

There is no method that clears counts, lists holes or returns illegal-bin hits. To call a method on an item, go through the instance and the item's label: `lane0.cg.x_op_a.get_inst_coverage()`.

A **static** method belongs to the type, so it can be called with the type's name and `::`. That works only when the type has a name, which an embedded covergroup's type does not (§19.4). For a covergroup declared in a module, interface or package:

```systemverilog
// snippet: a named covergroup type, declared in a module that imports alu_pkg
covergroup op_cg with function sample(op_t op);
  cp_op: coverpoint op { bins ops[] = {ADD, SUB, MUL, DIV, AND, OR, XOR}; }
endgroup
op_cg u0 = new();
op_cg u1 = new();

initial begin
  // ... calls to u0.sample(...) and u1.sample(...)
  $display("type  %0.2f", op_cg::get_coverage());         // the type, via ::
  $display("item  %0.2f", op_cg::cp_op::get_coverage());  // one item of the type
  $display("u0    %0.2f", u0.get_inst_coverage());         // an instance, via .
end
```

`set_inst_name()` gives the instance a readable, stable name, such as its place in the testbench hierarchy. Without it the tool generates a unique name (Table 19-1, `option.name`). Nothing requires a generated name to be the same in every test, so rows from different tests may not line up when their databases are merged (tool-dependent). Assigning `option.name` procedurally does the same job; `set_inst_name()` is the method form.

### Reading `(covered, total)` correctly

Both query methods accept two `int` arguments passed by reference (`ref`): the method writes the number of covered bins into the first and the number of bins into the second (§19.8). Those two numbers are the true numerator and denominator of the percentage **only** when `get_inst_coverage()` is called on a coverpoint or a cross. Everywhere else they are sums of bins (§19.8):

| Call | `(covered, total)` | Percentage returned | Ratio matches? |
|---|---|---|---|
| `lane0.cg.x_op_a.get_inst_coverage(c, t)` | 4, 14 | 28.57 | yes: 4/14 |
| `lane0.cg.get_inst_coverage(c, t)` | 11, 23: summed over `cp_op`, `cp_a` and `x_op_a` | 66.67 | no: 11/23 = 47.8 % |
| `lane0.cg.cp_op.get_coverage(c, t)` | 8, 14: `cp_op`'s bins summed over both instances | 57.14 | here, by luck |
| `lane0.cg.get_coverage(c, t)` | 18, 46: every item in every instance | 59.52 | no: 18/46 = 39.1 % |

The covergroup percentage is an average of item percentages, so a 2-bin item counts as much as a 14-bin one, while the summed pair counts bins. The `cp_op` row matches only because both instances have the same 7 bins and the same weight. When instances have different bins, for example bins built from covergroup arguments, the summed pair stops matching too: in the §19.8 example, a coverpoint with 2 bins in one instance and 4 in the other reports a type total of 6.

**Rule:** print `(covered, total)` per coverpoint and cross with `get_inst_coverage()`, and print percentages for covergroups and types. Never divide a covergroup-level pair yourself.

### Goals and weights: what moves the number

[I-SV-3A](/curriculum/T2_Intermediate/I-SV-3A_Functional_Coverage_Fundamentals/coverage-options) introduced `option.goal` and `option.weight`. Here is what each does to the number you query:

- **`option.goal`** (default 100) is the *target* for an instance or an item (Table 19-1). It does not change the number. Your code and the tool's report compare against it.
- **`option.weight`** on a coverpoint or cross (default 1) weights that item inside its instance's average. On the covergroup it weights the instance in the type average (§19.11.3). Weights are non-negative integers (Table 19-1).

Traced on lane0 (bins as above), changing only the cross's weight:

| Item | Item % | Default | `x_op_a.option.weight = 2` | `x_op_a.option.weight = 0` |
|---|---|---|---|---|
| `cp_op` | 71.43 | × 1 | × 1 | × 1 |
| `cp_a` | 100.00 | × 1 | × 1 | × 1 |
| `x_op_a` | 28.57 | × 1 | × 2 | × 0 (dropped) |
| **`get_inst_coverage()`** | | (71.43 + 100 + 28.57) / 3 = **66.67** | (71.43 + 100 + 57.14) / 4 = **57.14** | (71.43 + 100) / 2 = **85.71** |
| with `option.goal = 80` | | below goal | below goal | "reached" |

The last column is the trap. Setting the cross's weight to 0 lifts lane0 from 66.67 to 85.71 and past an 80 % goal, yet not one more scenario ran: the 10 empty cross bins are still empty, only hidden. **Excluding an item is not covering it.** Weight 0 is right for an item that only feeds a cross and was never a plan goal of its own; used to reach a number, it hides holes. When an item truly cannot be reached, record that as a justified exclusion, as [The Coverage Closure Loop](/curriculum/T2_Intermediate/I-SV-3B_Advanced_Functional_Coverage/closure-workflow) shows.

One more rule from §19.11.1: an item whose bins have no values left (for example, every value ignored with `ignore_bins`) has a denominator of 0. It drops out of its instance's average, yet its own `get_inst_coverage()` returns 0.0 (or 100.0 if its weight is 0). A dashboard can therefore show a 0 % item that is not pulling the group down. Push Further lists the other zero cases.

### Pausing collection: `start()` and `stop()`

`stop()` stops collecting coverage; `start()` starts collecting again (Table 19-5). Each can be called on a covergroup instance or on one of its coverpoints or crosses. Three facts follow from the method definitions:

- **Collected counts stay.** `stop()` stops *new* collection; nothing in §19.8 clears what has been counted, and there is no method that does.
- **Calls to `sample()` still happen.** The collector keeps calling `cg.sample(t)`; while the instance is stopped, nothing is collected.
- **It is per instance or per item.** Unlike `get_coverage()`, §19.8 does not make `start()` and `stop()` static, so `lane0.cg.stop()` acts on lane0's instance, not on lane1's.

Typical uses are a reset window, an initialization sequence and an error-injection window: periods where the traffic is real but should not count toward the plan. `lane0` in the running example enters reset after three transactions:

| Step | Call | lane0's `cp_op` bins covered |
|---|---|---|
| 1–3 | `write` with `ADD`, `SUB`, `MUL` | 3 |
| 4 | `lane0.cg.stop()` | 3 |
| 5–6 | `write` with `DIV`, `AND` | 3 (not collected) |
| 7 | `lane0.cg.start()` | 3 |
| 8–10 | `write` with `DIV`, `ADD`, `XOR` | 5 |

Without the `stop()`/`start()` pair, `AND` would also count, and lane0 would read 76.19 instead of 66.67 (you will check this in Make It Work).

There are three ways to keep samples out of the coverage, and each fits a different owner:

| Tool | Who decides | Use it when |
|---|---|---|
| `iff (expr)` on a coverpoint or cross | the covergroup, at each sample | the condition is visible to the covergroup when it samples, such as a `valid` bit in the transaction (see [I-SV-3A](/curriculum/T2_Intermediate/I-SV-3A_Functional_Coverage_Fundamentals/coverage-options)) |
| not calling `sample()` | the collector | the collector itself knows the transaction must not count |
| `stop()` / `start()` | another part of the bench, such as reset handling or an error-injection sequence | the window is decided outside the collector and spans many transactions |

**The classic mistake is a `stop()` with no matching `start()`.** Coverage then freezes at its last value while traffic keeps flowing and checks keep passing; nothing in the log says so. Debug challenge D1 below is exactly this bug.

### Ending the stimulus at a goal, and why the checks must finish

The most common reason to query coverage while the test runs is to stop sending stimulus once the goal is reached, or to switch to a mode that targets the holes ([closure-workflow](/curriculum/T2_Intermediate/I-SV-3B_Advanced_Functional_Coverage/closure-workflow) teaches steering). The order of calls matters. The diagram shows one bench that does three things: it pauses lane0's collection during a reset, it polls coverage every 50 items, and when the goal is reached it ends the *stimulus* and waits for the checker before it ends the *simulation*.

The same loop in code:

```systemverilog
// snippet: parts of tb_top. lane0 (alu_cov), chk (a checker with write(),
// wait_for_drain(), pass and fail) and next_item(), which returns a new
// randomized alu_txn, are declared elsewhere in tb_top.
localparam int BUDGET = 2000;  // most items this test may send
localparam int POLL   = 50;    // query every 50 items, not after every item

initial begin : stimulus
  bit done;
  for (int n = 1; n <= BUDGET && !done; n++) begin
    automatic alu_txn t = next_item();
    lane0.write(t);  // coverage: was the scenario exercised?
    chk.write(t);    // check: was the result right?
    if (n % POLL == 0)
      done = (lane0.cg.get_inst_coverage() >= lane0.cg.option.goal);
  end
  chk.wait_for_drain();  // the goal ends the stimulus, not the checks
  $display("PASS=%0d FAIL=%0d", chk.pass, chk.fail);
  $finish;               // only after the last comparison
end
```

Four rules are packed into it:

1. **Coverage measures; checks verify.** Coverage counts sampled values and never compares them with an expected result (§19.5, §19.11), so a wrong result is counted like a right one. 100 % coverage with an unfinished or failing checker proves nothing.
2. **Never `$finish` from the collector.** `$finish` makes the simulator exit at once (§20.2): transactions still in flight are never compared and no summary prints. In UVM it also skips the extract, check and report phases, because `run_test()` prints the report summary only after the phases finish (IEEE 1800.2-2020 §9.8.1; uvm-core 2020.3.1 `uvm_root.svh`). In UVM, the test drops its objection instead (an **objection** is UVM's count of activities still in progress; the run phase ends when the last one is dropped), and the remaining phases run normally ([I-UVM-1C](/curriculum/T2_Intermediate/I-UVM-1C_UVM_Phasing/index)).
3. **Compare with `>=` against the goal**, not `== 100.0`: the goal may be below 100, and a `real` compared for equality is fragile.
4. **Poll every N items, not every item.** Each query asks the simulator to compute a percentage; its cost is tool-dependent. For a plan with several items, check each planned item rather than one covergroup number: with a goal below 100, a group can pass while one item lags.

Stuck coverage is not a reason to reseed. The **seed** is the starting value of a random-number generator; a new seed (`srandom()`) changes *which* values come out, not their probabilities, so a hole the constraints make rare stays rare ([I-SV-2B](/curriculum/T2_Intermediate/I-SV-2B_Advanced_Constrained_Randomization/randomization-methods)). When the polled number stops rising, switch to a stimulus mode that targets the holes; that is the next lesson's subject.

### The coverage system tasks

§19.9 defines two system tasks and one system function (a **system task** or **system function** is a built-in routine whose name starts with `$`; a function returns a value):

| Routine | What the LRM says | In practice |
|---|---|---|
| `$set_coverage_db_name(filename)` | sets the file name of the coverage database saved at the end of the run | name the database after the test and seed, so that the databases of a **regression** (a batch of tests and seeds run together, whose coverage is merged into one report) never overwrite each other. Tool support varies; many flows set the name with a simulator switch instead (tool-dependent) |
| `$load_coverage_db(filename)` | loads the cumulative coverage of every covergroup type from that file | lets one run start from the coverage of earlier runs. Support and database format are tool-dependent |
| `$get_coverage()` | returns, as a `real` from 0 to 100, the overall coverage of all covergroup types | one number for the design; read the instance or the item for decisions |

`$get_coverage()` has one rule that surprises everyone: it returns **100.0 when the design has no covergroup instances**, or when every covergroup has weight 0 (§19.11). Traced on the running example:

| When | `$get_coverage()` | Why |
|---|---|---|
| time 0, before `lane0` and `lane1` are constructed | 100.00 | no instance exists yet (§19.11) |
| right after both `new()` calls | 0.00 | instances exist, nothing is covered |
| after both streams | 59.52 | the only type's number |

A loop that runs `while ($get_coverage() < 100.0)` before any collector exists never starts. Debug challenge D2 is this bug.

### Pitfalls and debugging

| Symptom | Likely cause | Fix |
|---|---|---|
| Coverage stops rising after a mid-test reset; traffic and checks continue | `stop()` with no matching `start()` | Call `start()` on every reset release, in the same task that calls `stop()`; log both calls |
| `$get_coverage()` reads 100.0 at the start and the closure loop never runs | no covergroup instance exists yet (§19.11) | Construct every collector before the first query; refuse a "closed" result with zero items sent |
| The type number looks healthy but one lane is missing states | `merge_instances = 1` (a union), a zero instance weight, or reading the average | Read each instance: set `option.get_inst_coverage = 1` in the definition when merging, and `per_instance = 1` for the report |
| Every instance returns the same `get_inst_coverage()` | `merge_instances = 1` without `option.get_inst_coverage = 1` (Table 19-1) | Add `option.get_inst_coverage = 1;` to the definition |
| A dashboard's covered/total disagrees with the percentage | the pair came from a covergroup or from `get_coverage()`, where it is a sum (§19.8) | Read pairs per item with `get_inst_coverage(c, t)`; report percentages for groups |
| Report rows named `cg`, `cg_1`, `cg_2`, different in every test | no `set_inst_name()` | Name each instance from its hierarchy path in the collector's constructor |
| Compile error on `cg.option.per_instance = 1;` after `new()` | `per_instance` and `get_inst_coverage` are definition-only (§19.7) | Move the assignment into the covergroup definition |
| `cg_t::get_coverage()` will not compile for an embedded covergroup | the embedded covergroup's type is anonymous (§19.4) | Call it through an instance: `lane0.cg.get_coverage()` |
| The run slows down after coverage polling was added | querying after every item | Poll every N items or at phase boundaries; the cost is tool-dependent |
| The number jumps after a weight change, with no new stimulus | weights changed the average, not the coverage | Treat weight changes as plan changes: review them, never use them to reach a goal |

### Recap

- `get_inst_coverage()` is this instance. `get_coverage()` is the type: the same value from every instance, an average by default and a union with `merge_instances = 1`. `$get_coverage()` is the whole design, and 100.0 when no instance exists.
- With `merge_instances = 1`, per-instance numbers need `option.get_inst_coverage = 1` in the definition. `per_instance` only controls what is saved and reported.
- `(covered, total)` is a true ratio only from `get_inst_coverage()` on a coverpoint or cross.
- `goal` is a target; `weight` moves the number; weight 0 hides an item, it never covers it.
- `stop()` keeps the counts and pauses collection until `start()`.
- Reach the goal, stop the stimulus, let the checks finish, then `$finish` from the top.

## Make It Work

### Two lanes, one covergroup type, every number checkable by hand

This bench feeds the two collectors fixed streams, so every number it prints can be traced with a pencil. It prints item pairs, instance numbers, the type number and the overall number, and it pauses lane0 during a reset window. There is no design under test (DUT) and no check: it tests the coverage instrument only, which is exactly why it must not print PASS.

```systemverilog
// compile
// File: tb_top.sv. One covergroup type, two instances, fixed streams.
package alu_pkg;
  typedef enum bit [2:0] {ADD, SUB, MUL, DIV, AND, OR, XOR} op_t;

  class alu_txn;
    op_t      op;
    bit [7:0] a;
    function new(op_t op, bit [7:0] a);
      this.op = op;
      this.a  = a;
    endfunction
  endclass

  class alu_cov;
    // An embedded covergroup declares an anonymous type plus one instance
    // variable (IEEE 1800-2023 19.4): every alu_cov object owns one instance.
    covergroup cg with function sample(alu_txn t);
      option.per_instance = 1;  // save and report each port's own numbers
      cp_op: coverpoint t.op {
        option.comment = "ALU-1";
        bins ops[] = {ADD, SUB, MUL, DIV, AND, OR, XOR};  // 7 bins
      }
      cp_a: coverpoint t.a {
        option.comment = "ALU-2";
        bins zero = {8'h00};
        bins max  = {8'hFF};  // any other value lands in no bin
      }
      x_op_a: cross cp_op, cp_a {
        option.comment = "ALU-4";  // 7 x 2 = 14 cross bins
      }
    endgroup

    function new(string inst_name);
      cg = new();                   // the only place it may be constructed
      cg.set_inst_name(inst_name);  // stable, hierarchy-based report name
    endfunction

    function void write(alu_txn t);
      cg.sample(t);
    endfunction
  endclass
endpackage

module tb_top;
  import alu_pkg::*;

  alu_cov lane0, lane1;

  function automatic void send(alu_cov c, op_t op, bit [7:0] a);
    alu_txn t = new(op, a);
    c.write(t);
  endfunction

  // Item pairs are true numerators and denominators. The covergroup pair is
  // a sum of bins over all items (19.8), so it is printed beside the number.
  function automatic void report(string name, alu_cov c);
    int  covered, total;
    real pct;
    void'(c.cg.cp_op.get_inst_coverage(covered, total));
    $display("%s ALU-1 cp_op   %0d/%0d", name, covered, total);
    void'(c.cg.cp_a.get_inst_coverage(covered, total));
    $display("%s ALU-2 cp_a    %0d/%0d", name, covered, total);
    void'(c.cg.x_op_a.get_inst_coverage(covered, total));
    $display("%s ALU-4 x_op_a  %0d/%0d", name, covered, total);
    pct = c.cg.get_inst_coverage(covered, total);
    $display("%s get_inst_coverage() = %0.2f  pair = %0d/%0d",
             name, pct, covered, total);
  endfunction

  initial begin
    int  covered, total;
    real pct;

    $display("before new: $get_coverage() = %0.2f", $get_coverage());
    lane0 = new("tb_top.lane0");
    lane1 = new("tb_top.lane1");
    $display("after new:  $get_coverage() = %0.2f", $get_coverage());

    send(lane0, ADD, 8'h00);
    send(lane0, SUB, 8'hFF);
    send(lane0, MUL, 8'h00);
    lane0.cg.stop();          // lane 0 enters reset: pause collection
    send(lane0, DIV, 8'h00);  // not collected
    send(lane0, AND, 8'hFF);  // not collected
    lane0.cg.start();         // reset released: collect again
    send(lane0, DIV, 8'hFF);
    send(lane0, ADD, 8'h00);  // a repeat: no new bin
    send(lane0, XOR, 8'h42);  // 8'h42 is in no cp_a bin, so no cross bin

    send(lane1, ADD, 8'hFF);
    send(lane1, ADD, 8'hFF);
    send(lane1, OR,  8'h10);
    send(lane1, AND, 8'h00);

    report("lane0", lane0);
    report("lane1", lane1);

    pct = lane0.cg.get_coverage(covered, total);
    $display("type  get_coverage() = %0.2f  pair = %0d/%0d", pct, covered, total);
    $display("type  via lane1      = %0.2f", lane1.cg.get_coverage());
    pct = lane0.cg.cp_op.get_coverage(covered, total);
    $display("type  cp_op          = %0.2f  pair = %0d/%0d", pct, covered, total);
    $display("design $get_coverage() = %0.2f", $get_coverage());
    $finish;
  end
endmodule
```

It needs no plusargs. Covergroup support in open-source simulators varies, and no simulator was run for this page: the log below was derived by hand from §19.8 and §19.11.

### How to use the coverage API in your own bench

1. **Name every instance** in the collector's constructor with `set_inst_name()`, from its place in the hierarchy, so report rows are stable across tests.
2. **Decide which number answers your question** before writing the query: this instance (`get_inst_coverage()`), the type (`get_coverage()`), or one plan item (`cg.<item>.get_inst_coverage(c, t)`).
3. **Set definition-only options in the definition:** `option.per_instance = 1` when the report needs per-instance rows, and `option.get_inst_coverage = 1` whenever the type uses `merge_instances = 1`.
4. **Wrap reset, initialization and error-injection windows** in `stop()` and `start()` in the code that owns the window, and make sure every path that calls `stop()` reaches `start()`.
5. **Poll every N items** in the code that owns the stimulus (in UVM, the test or the top sequence), compare with `>=` against `option.goal`, and check every planned item.
6. **End the stimulus, not the simulation**, when the goal is reached: let the checker drain, print the PASS/FAIL line, then `$finish` from `tb_top` (in UVM, drop the objection).
7. **Print item pairs and percentages in a fixed format** (as `report()` does above), so a regression script can parse them.
8. **Name the database** after the test and seed with `$set_coverage_db_name()` or the tool's switch, so every run's coverage can be merged later.

**Checklist before moving on:**
- [ ] I can say which of `get_inst_coverage()`, `get_coverage()` and `$get_coverage()` my decision needs, and why the other two are wrong for it.
- [ ] Every covergroup that merges instances also sets `option.get_inst_coverage = 1` if anything reads instance numbers.
- [ ] No code divides a covergroup-level `(covered, total)` pair.
- [ ] Every `stop()` has a `start()` on every path.
- [ ] No collector or monitor calls `$finish`; the goal ends the stimulus and the checks still run to completion.
- [ ] Every collector exists before the first coverage query, and a "closed" result with zero items sent is treated as a failure.
- [ ] Weight changes are reviewed as plan changes, never used to reach a goal.

## Push Further

### Expert: Merging instances: bin names, different bin sets and the largest `at_least`

With `merge_instances = 1`, the union is computed **by bin name**, and the counts of bins with the same name add (§19.11.3). That works cleanly when every instance has the same bins. When bins come from covergroup arguments, instances can have different bin sets. The LRM's own example: `covergroup gt (int l, h); coverpoint a {bins b[] = {[l:h]};} endgroup`, with `gv1 = new(0,1)` (bins `b[0]`, `b[1]`) and `gv2 = new(1,2)` (bins `b[1]`, `b[2]`). The type has three bins, and `b[1]` is shared:

| Sampled | `gv1` | `gv2` | Type (merged) |
|---|---|---|---|
| `a == 0` by `gv1`; `a == 1` by both | `b[0]`, `b[1]` covered | `b[1]` covered | `b[0]`, `b[1]` covered of 3; `b[1]` count = 2 |
| `get_coverage()` | | | 66.6667 |
| `get_inst_coverage()`, `option.get_inst_coverage = 0` | 66.6667 | 66.6667 | |
| `get_inst_coverage()`, `option.get_inst_coverage = 1` | 100.0 | 50.0 | |

Three further corner cases:
- **Automatic bins are named by their range.** Two instances with different `auto_bin_max` have differently named bins, so nothing overlaps: the §19.11.3 example with 64 and 32 automatic bins has 96 cumulative bins. Varying bin layouts per instance makes a union meaningless.
- **Merged bins use the largest `at_least`.** A merged bin counts as covered only when its summed count reaches the largest `at_least` of all accumulated instances (§19.11.1). An instance with `at_least = 1` can show a bin covered while the merged type, held to another instance's `at_least = 4`, does not: the type number can be lower than an instance's.
- **Type options are one value per type.** They are set with constant expressions, so different instances cannot assign different values (§19.7.1). `merge_instances` is a decision for the whole type, made where the type is defined.

### Expert: Which weight applies where

Four weights affect coverage numbers, and they are easy to mix up:

| Option | Set on | Weights | Source |
|---|---|---|---|
| `option.weight` | covergroup | this instance, in the type average (default mode) and in the overall instance coverage of the simulation | Table 19-1, §19.11.3 |
| `option.weight` | coverpoint or cross | this item, inside its instance's number; in the default mode, also in that item's type number | Table 19-1, §19.11.3 |
| `type_option.weight` | covergroup | the type, in the overall cumulative coverage of the saved database | Table 19-3 |
| `type_option.weight` | coverpoint or cross | the item, in the type's cumulative number | Table 19-3, §19.7.1 |

The §19.7.1 example shows the split: with `merge_instances = 1`, each instance is computed with the items' `option.weight` values, while the type is computed from the merged items with their `type_option.weight` values. And in the default averaging mode, "the covergroup type coverage depends on the instances only, not its coverpoints or crosses" (§19.11.3): item weights act inside each instance, before the average. If two reports disagree about the same run, check which weight each one used.

### Expert: Zero denominators and empty designs

§19.11, §19.11.1 and §19.11.2 define what happens when a percentage has nothing to divide by:

- **An item** with nothing left to count has a denominator of 0: a coverpoint none of whose bins has a value or transition left (for example, all removed by `ignore_bins`), or a cross whose every cross product sits in `ignore_bins` or `illegal_bins`. It does not contribute to its covergroup; its own `get_coverage()` and `get_inst_coverage()` return 0.0, or 100.0 if its weight is 0; the `(covered, total)` form writes 0 and 0.
- **A covergroup** has a zero denominator when every item is excluded that way, when every item weight is 0, or when it has no items. It then does not contribute to the overall number and returns 0.0, or 100.0 if the covergroup's own weight is 0.
- **The design:** `$get_coverage()` returns 100.0 when there is no covergroup instance, or when every covergroup has weight 0.

The practical rules: a closure check must also require at least one sample (or one item sent), and a dashboard that shows 0 % for an excluded item should mark it as excluded, not failing.

### Expert: Sampling coverage from assertions

An overridden `sample()` can be called from a sequence match item inside a property, with the assertion's local variables as arguments (§19.8.1, §16.10, §16.11). The arguments carry values computed from the assertion's sampled values (concurrent assertions sample in the Preponed region), which makes this the way to cover quantities that only the assertion knows, such as a measured latency:

```systemverilog
// snippet: inside a module with clk, req and ack
covergroup lat_cg with function sample(int unsigned lat);
  cp_lat: coverpoint lat { bins fast = {[1:2]}; bins slow = {[3:8]}; }
endgroup
lat_cg lat_cov = new();

property p_req_ack;
  int unsigned n;  // local variable: one copy per attempt
  @(posedge clk) (req, n = 1) ##1 (!ack, n++)[*0:7] ##1 (ack, lat_cov.sample(n));
endproperty
c_req_ack: cover property (p_req_ack);  // n = cycles from req to ack
```

Two limits: §16.11 forbids attaching a match item to a sequence that can match empty, which is why `n++` sits inside the parentheses before the repetition; and the formal arguments of an overridden `sample()` may be used only in coverpoint expressions and `iff` guards (§19.8.1). `cover property` itself counts property matches; the covergroup adds bins over the values. [I-SV-4A](/curriculum/T2_Intermediate/I-SV-4A_SVA_Fundamentals/index) teaches `cover property`.

### Expert: The cost of querying and collecting

Everything in this section is **tool-dependent**: the LRM defines what the numbers are, not what they cost.

- **Queries.** A covergroup-level query walks every item. Poll every N items, at the end of a phase, or when a stimulus mode changes, never after every sample.
- **Crosses multiply.** A cross has as many automatic bins as the product of its coverpoints' bin counts (§19.6, §19.11.2). Three 16-bin coverpoints crossed give 4,096 bins per instance; with `per_instance = 1` on a 32-port design, the database stores that 32 times.
- **Reports.** `option.cross_num_print_missing` (Table 19-1, default 0) sets how many uncovered cross products are saved and printed; raise it only for the crosses you are actively closing.
- **Switching collection off.** `stop()` stops collection; whether it also saves simulation time depends on the tool. Long performance regressions often switch coverage off with a simulator option instead.

### Expert: The database routines in a regression

The LRM gives the bench only two hooks into a regression's coverage flow (§19.9): `$set_coverage_db_name()` chooses where this run's database is saved, and `$load_coverage_db()` loads cumulative coverage from an earlier database. How databases are merged, what format they use and how instance rows line up are all **tool-dependent**; stable names from `set_inst_name()` are what make rows line up at all. UCIS 1.0 (Accellera, 2012) standardizes an API and an XML interchange format for exchanging coverage data between tools; which parts a given tool supports is tool-dependent. Two traps: a merge across a constraint change mixes stimulus that may no longer occur, and whether illegal-bin hits sampled while an instance is stopped are still reported is not stated by the LRM, so check your tool before relying on `illegal_bins` inside a `stop()` window (§19.5.6 says only that a run-time error is issued when an illegal value occurs).

### Debug challenge D1: coverage that freezes

A test runs 4,000 items with two resets: power-on, and one in the middle of the test. Every check passes. The polled coverage climbs to 63.10 by item 1,800, the second reset happens at item 1,900, and from then on every poll prints 63.10. The reset handler is:

```systemverilog
// snippet: called on every reset in tb_top
bit first_reset_done;

task automatic handle_reset();
  lane0.cg.stop();             // pause collection while rst_n is low
  @(posedge rst_n);
  if (!first_reset_done) begin // written when only power-on reset existed
    lane0.cg.start();
    first_reset_done = 1;
  end
endtask
```

Find the bug before you open the solution.

<details>
<summary>Reveal the worked solution</summary>

**Cause.** `start()` runs only after the first reset. After the mid-test reset, `stop()` runs again but `start()` never does, so lane0 collects nothing for the rest of the test (Table 19-5). The counts from before stay, which is why the number freezes at 63.10 instead of dropping. Checks still pass because checking does not depend on coverage collection.

**Fix.** Pair the calls unconditionally, in one place:

```systemverilog
// snippet: the fixed handler
task automatic handle_reset();
  lane0.cg.stop();
  $display("[%0t] COV lane0 stopped for reset", $time);
  @(posedge rst_n);
  lane0.cg.start();
  $display("[%0t] COV lane0 started", $time);
endtask
```

**What to take away.** A frozen number with healthy traffic points at collection, not stimulus: look for `stop()` calls first, then for a collector that no longer calls `sample()`. The two log lines make the window visible in every regression log.

</details>

### Debug challenge D2: 100 % at time 0

A new test reports `items=0 coverage=100.00` and ends in a few microseconds. Its stimulus block is:

```systemverilog
// snippet: tb_top; make_txn() returns a new randomized alu_txn
alu_cov lane0;  // built when the first transaction arrives

initial begin : stimulus
  int n;
  while ($get_coverage() < 100.0 && n < 1000) begin
    automatic alu_txn t = make_txn();
    if (lane0 == null) lane0 = new("tb_top.lane0");
    lane0.write(t);
    n++;
  end
  $display("items=%0d coverage=%0.2f", n, $get_coverage());
end
```

Explain the log before you open the solution.

<details>
<summary>Reveal the worked solution</summary>

**Cause.** At the first test of the `while` condition no `alu_cov` exists, so the design has no covergroup instance and `$get_coverage()` returns 100.0 (§19.11). The loop body never runs, so the collector is never created and the number never changes.

**Fix.** Create the collector before the loop, ask the question you mean, and refuse an empty result:

```systemverilog
// snippet: the fixed stimulus block
alu_cov lane0;

initial begin : stimulus
  int n;
  lane0 = new("tb_top.lane0");  // every collector exists before any query
  while (lane0.cg.get_inst_coverage() < lane0.cg.option.goal && n < 1000) begin
    automatic alu_txn t = make_txn();
    lane0.write(t);
    n++;
  end
  if (n == 0) $error("closure loop sent no items");
  $display("items=%0d coverage=%0.2f", n, lane0.cg.get_inst_coverage());
end
```

**What to take away.** A coverage number is only meaningful once the instances it describes exist and have been sampled. Construct collectors early (in UVM, in `build_phase`), query the instance or item your decision depends on, and treat "closed with zero items" as a failure.

</details>
