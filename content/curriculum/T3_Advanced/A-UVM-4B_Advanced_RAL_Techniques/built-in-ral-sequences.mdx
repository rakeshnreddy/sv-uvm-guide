  ## Elevator Pitch

  RAL ships with ready-made test sequences (IEEE 1800.2-2020 Annex E): `uvm_reg_hw_reset_seq`, `uvm_reg_bit_bash_seq`, `uvm_reg_access_seq`, `uvm_mem_walk_seq` and more. Use them to prove the model and the silicon (or emulation) agree. You control them with **resource attributes**, not by overriding methods: each sequence skips any block, register or memory that has a `NO_REG_*` / `NO_MEM_*` bit resource in the `"REG::"` scope.

  ## Reset & Mirror Validation

  ```systemverilog
  class soc_reset_test extends base_test;
    `uvm_component_utils(soc_reset_test)

    function new(string name, uvm_component parent);
      super.new(name, parent);
    endfunction

    task run_phase(uvm_phase phase);
      uvm_reg_hw_reset_seq reset_seq;
      phase.raise_objection(this);

      // STRAP_CFG resets to a pin-strapped value: skip it in the reset check.
      uvm_resource_db#(bit)::set({"REG::", env.ral.STRAP_CFG.get_full_name()},
                                 "NO_REG_HW_RESET_TEST", 1, this);

      reset_seq       = uvm_reg_hw_reset_seq::type_id::create("reset_seq");
      reset_seq.model = env.ral;
      reset_seq.start(null);   // register sequences run their items on each map's sequencer
      phase.drop_objection(this);
    endtask
  endclass
  ```

  **What it does**
  - `uvm_reg_hw_reset_seq` resets the model, then reads every register that has a reset value through **every map** it is in, with `mirror(status, UVM_CHECK, UVM_FRONTDOOR, map)`. Fields with no reset or with `UVM_NO_CHECK` (volatile fields by default) are not compared.
  - `NO_REG_HW_RESET_TEST` (or the catch-all `NO_REG_TESTS`) can name a block, a register, or for this sequence a single field.

  ## Bit-Bash, Access and Memory Walk

  - `uvm_reg_bit_bash_seq`: for every register and map, inverts each bit through a frontdoor write, reads it back and compares with `get()`, then inverts it again and repeats the check. It skips WO, WOC, WOS, WO1 and NOACCESS fields and fields set to `UVM_NO_CHECK`. Exclude whole registers that have side effects (W1C interrupt status, GO bits, FIFOs) with `NO_REG_BIT_BASH_TEST`.
  - `uvm_reg_access_seq`: for each register, writes through the frontdoor and checks through the **backdoor**, then writes through the backdoor and checks through the frontdoor. It needs HDL paths and a working prediction path, and it skips registers whose fields are all RO. Exclude with `NO_REG_ACCESS_TEST`.
  - `uvm_mem_walk_seq`: a walking pattern over every memory, through each map (write `~k` at address k, read it back on the next step). Exclude with `NO_MEM_WALK_TEST` or `NO_MEM_TESTS`.

  ```systemverilog
  // In the test, before starting the sequence:
  // never bit-bash the interrupt status (W1C) register
  uvm_resource_db#(bit)::set({"REG::", env.ral.INT_STATUS.get_full_name()},
                             "NO_REG_BIT_BASH_TEST", 1, this);
  // skip every register of the DMA sub-block in all built-in tests
  uvm_resource_db#(bit)::set({"REG::", env.ral.dma.get_full_name(), ".*"},
                             "NO_REG_TESTS", 1, this);

  bash_seq       = uvm_reg_bit_bash_seq::type_id::create("bash_seq");
  bash_seq.model = env.ral;
  bash_seq.start(null);
  ```

  **Why attributes and not overrides**
  - The sequences look up these resources for each block and register (`uvm_resource_db#(bit)::get_by_name({"REG::", rg.get_full_name()}, "NO_REG_BIT_BASH_TEST")`), so exclusions live with the test, and the library code stays untouched.
  - The scope is a glob, so `".*"` after a block name covers everything below it.

  ## Checklist

  - [ ] Registers with side effects or unpredictable resets carry the matching `NO_REG_*` attribute.
  - [ ] HDL paths exist before running `uvm_reg_access_seq`.
  - [ ] Coverage/scoreboards observe these sequences to collect reset/bit coverage metrics.
  - [ ] Register model and adapters are synchronized before running memory walk tests.
