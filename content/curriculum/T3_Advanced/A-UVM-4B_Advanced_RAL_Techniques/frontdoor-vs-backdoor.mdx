  ## Elevator Pitch

  Frontdoor access flows through the bus agent, exercising arbitration and verifying protocol logic. Backdoor access reads or deposits the HDL storage directly, in zero time. Most teams blend both: backdoor for bring-up and fast state set-up, frontdoor for checks and coverage.

  ## Trade-off Table

  | Mode | Pros | Cons |
  | --- | --- | --- |
  | Frontdoor | Exercises the full bus stack, triggers monitors and coverage, honours every access policy | Slower; needs an adapter and a sequencer; the mirror follows only if a predictor or auto-predict is set up |
  | Backdoor  | Instant `peek()`/`poke()`; each call updates the mirror itself (`do_predict()` with the `UVM_BACKDOOR` door) | Needs an HDL path; bypasses access policies (`poke()` writes RO bits) and side effects (`peek()` does not clear RC fields); monitors and monitor-fed predictors never see it |

  **Backdoor set-up:** a register needs an HDL path before `peek()` or `poke()` works. Give it one with the third argument of `uvm_reg::configure()` or with `add_hdl_path_slice()`, and give the block its root with `add_hdl_path()`. Without a path, `poke()` reports "No backdoor access available to poke register" and returns `UVM_NOT_OK`.

  ## Hybrid Sequence Example

  ```systemverilog
  class hybrid_reg_seq extends uvm_reg_sequence #(uvm_sequence #(uvm_reg_item));
    `uvm_object_utils(hybrid_reg_seq)

    function new(string name = "hybrid_reg_seq");
      super.new(name);
    endfunction

    virtual task body();
      codec_block    blk;
      uvm_status_e   status;
      uvm_reg_data_t data;

      if (!$cast(blk, model)) `uvm_fatal("CAST", "model is not a codec_block")

      // Backdoor initialisation: zero time, and poke() updates the mirror itself.
      blk.control.poke(status, 'h1, .parent(this));

      // Frontdoor check: a real bus read, compared with the mirror.
      blk.control.mirror(status, UVM_CHECK, UVM_FRONTDOOR, .parent(this));

      blk.status.read(status, data, UVM_FRONTDOOR, .parent(this));
      `uvm_info(get_type_name(), $sformatf("status via frontdoor = 'h%0h", data), UVM_LOW)
    endtask
  endclass
  ```

  **Hybrid strategy**
  - Local variables are declared at the top of `body()`, before any statement, as SystemVerilog requires.
  - `poke()` deposits the value and predicts it, so no `predict()` call follows. The monitor sees nothing, so a scoreboard fed by the monitor will not hear about this change.
  - The frontdoor `mirror(UVM_CHECK)` then proves the bus path and the DUT agree with the model.

  ## Checklist

  - [ ] Registers used with `peek()`/`poke()` have HDL paths, and a test of the backdoor (for example `uvm_reg_access_seq`) runs once per DUT.
  - [ ] Scoreboards that depend on monitor traffic are told about backdoor changes, or do not need them.
  - [ ] Critical coverage goals (e.g., bus bursts) use frontdoor sequences.
  - [ ] Regression plan documents which tests run in hybrid mode versus pure frontdoor.
