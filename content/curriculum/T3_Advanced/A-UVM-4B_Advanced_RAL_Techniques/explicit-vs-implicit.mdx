  ## Elevator Pitch

  Prediction keeps the RAL mirror aligned with the DUT. Implicit prediction lets the register map predict the accesses the register model itself starts. Explicit prediction puts a `uvm_reg_predictor` on the bus monitor so every transfer on the bus is predicted, whoever started it. Knowing which one you have, and never running both, is key to accurate checking.

  ## Definitions

  - **Implicit (auto) prediction:** `map.set_auto_predict(1)`. When a frontdoor `read()` or `write()` completes, the register calls `do_predict()` with the value it wrote, or with the read data the adapter handed back. Accesses from firmware, DMA or other masters are never seen.
  - **Explicit prediction:** a `uvm_reg_predictor` whose `bus_in` is connected to the bus monitor's analysis port. It converts each observed item with `adapter.bus2reg()`, finds the register with `map.get_reg_by_offset()`, and calls `do_predict()`, applying the field access policies.
  - **Passive:** an explicit predictor on a bus that the register model never drives, for example one that only a CPU model uses.
  - **The default is neither:** `uvm_reg_map` starts with auto-predict at 0, and no predictor exists until you build one.
  - **Not prediction modes:** `poke()` and `peek()` update the mirror themselves after the backdoor access, and `predict()` sets it directly. You use `predict()` for changes the bus never shows, such as a hardware event.

  ## Connection Example

  ```systemverilog
  class soc_env extends uvm_env;
    `uvm_component_utils(soc_env)

    apb_agent                     agent;
    codec_block                   ral;
    apb_reg_adapter               adapter;
    uvm_reg_predictor #(apb_item) predictor;

    function new(string name, uvm_component parent);
      super.new(name, parent);
    endfunction

    function void build_phase(uvm_phase phase);
      super.build_phase(phase);
      agent     = apb_agent::type_id::create("agent", this);
      ral       = codec_block::type_id::create("ral");
      ral.build();                      // codec_block::build() ends with lock_model()
      ral.reset();
      adapter   = apb_reg_adapter::type_id::create("adapter");
      predictor = uvm_reg_predictor #(apb_item)::type_id::create("predictor", this);
    endfunction

    function void connect_phase(uvm_phase phase);
      ral.default_map.set_sequencer(agent.sqr, adapter);
      ral.default_map.set_auto_predict(0);      // the default; prediction is explicit
      predictor.map     = ral.default_map;
      predictor.adapter = adapter;
      agent.mon.ap.connect(predictor.bus_in);
    endfunction
  endclass
  ```

  **Hooking it up**
  - `build_phase` creates the agent, builds and resets the register model, and creates the adapter and the predictor component.
  - `set_sequencer()` tells the map where frontdoor items run. Without it, `write()` cannot reach the bus.
  - The predictor needs `map` (to decode addresses) and `adapter` (to call `bus2reg()`). A null adapter stops the run with `UVM_FATAL REG/WRITE/NULL` at the first observed transfer.
  - `connect()` is the line that makes prediction explicit. If it is missing, nothing reports an error: the mirror just never changes.

  ## When to Use Which

  - **Explicit suits:** any bus where something other than the register model can write registers (firmware, DMA, another agent), and every production environment where the monitor exists.
  - **Implicit suits:** bring-up before a monitor exists, or an environment where the register model is the only master on that bus and the adapter round trip is trusted.
  - **Never both on one map:** each RAL access would be predicted twice. Idempotent policies (RW, W1C) hide it; a W1T toggle field ends up back where it started.
  - **Hardware events:** neither mode can see a change made by the DUT's own logic. Call `predict()` when your testbench knows the new value, or configure the field as volatile and read it when you need it.

  ```systemverilog
  // In the env: the interrupt line tells the testbench that hardware set status.error.
  task sync_error_bit();
    @(posedge vif.irq);
    void'(ral.status.error.predict(1));   // UVM_PREDICT_DIRECT: mirror = desired = 1, no bus access
  endtask
  ```

  **Why `predict()` here, and not after a poke?**
  - `predict()` exists for changes no access path reports. After `poke()` the mirror is already updated, because `poke()` calls `do_predict()` itself.

  ## Checklist

  - [ ] Every bus that touches the register model has a predictor bound to that bus's map, or auto-predict is on and the RAL is the only master.
  - [ ] Auto-predict and a connected predictor are never active on the same map.
  - [ ] Hardware-side changes are handled with `predict()` or volatile fields, not by hoping a mirror() fixes them.
