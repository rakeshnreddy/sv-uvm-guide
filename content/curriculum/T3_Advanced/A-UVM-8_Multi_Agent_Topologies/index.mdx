## Quick Take
- **What it is:** Multi-agent topologies are testbench architectures where multiple protocol agents (AXI master, AXI slave, APB, interrupt controller, DMA) operate concurrently within a single UVM environment, coordinated through virtual sequences running on a virtual sequencer.
- **Why it matters:** Real SoC verification involves 10–50 protocol interfaces running simultaneously. Without a structured coordination mechanism, test scenarios devolve into uncoordinated concurrent traffic that never exercises cross-protocol interactions — the exact class of bugs that escapes to silicon.
- **The Standard:** IEEE 1800.2-2020 does not define a `uvm_virtual_sequencer` class. The virtual sequencer pattern is a community convention built from the standard `uvm_sequencer` base class with sub-sequencer handles.

## The Virtual Sequencer Pattern

A virtual sequencer is a plain `uvm_sequencer` that holds **handles** to typed sub-sequencers. It does not process sequence items itself — it serves as a coordination point.

```systemverilog
class soc_virtual_sequencer extends uvm_sequencer;
  `uvm_component_utils(soc_virtual_sequencer)

  // Handles to per-protocol sub-sequencers
  axi_sequencer  axi_sqr;
  apb_sequencer  apb_sqr;
  irq_sequencer  irq_sqr;
  dma_sequencer  dma_sqr;

  function new(string name, uvm_component parent);
    super.new(name, parent);
  endfunction
endclass
```

In the environment's `build_phase` and `connect_phase`:

```systemverilog
class soc_env extends uvm_env;
  `uvm_component_utils(soc_env)

  axi_agent          axi_agt;
  apb_agent          apb_agt;
  irq_agent          irq_agt;
  dma_agent          dma_agt;
  soc_virtual_sequencer v_sqr;
  soc_scoreboard     scoreboard;

  function new(string name, uvm_component parent);
    super.new(name, parent);
  endfunction

  function void build_phase(uvm_phase phase);
    super.build_phase(phase);
    axi_agt  = axi_agent::type_id::create("axi_agt", this);
    apb_agt  = apb_agent::type_id::create("apb_agt", this);
    irq_agt  = irq_agent::type_id::create("irq_agt", this);
    dma_agt  = dma_agent::type_id::create("dma_agt", this);
    v_sqr    = soc_virtual_sequencer::type_id::create("v_sqr", this);
    scoreboard = soc_scoreboard::type_id::create("scoreboard", this);
  endfunction

  function void connect_phase(uvm_phase phase);
    super.connect_phase(phase);
    // Wire virtual sequencer handles to actual sub-sequencers.
    // irq_agt is PASSIVE in this test, so irq_agt.sequencer is null:
    // the irq handle stays null and nothing may start a sequence on it.
    v_sqr.axi_sqr = axi_agt.sequencer;
    v_sqr.apb_sqr = apb_agt.sequencer;
    v_sqr.irq_sqr = irq_agt.sequencer;
    v_sqr.dma_sqr = dma_agt.sequencer;

    // Wire monitors to scoreboard
    axi_agt.monitor.ap.connect(scoreboard.axi_fifo.analysis_export);
    apb_agt.monitor.ap.connect(scoreboard.apb_fifo.analysis_export);
  endfunction
endclass
```

## Virtual Sequence Construction

A virtual sequence runs on the virtual sequencer and dispatches child sequences to specific sub-sequencers:

```systemverilog
class dma_transfer_with_irq_vseq extends uvm_sequence;
  `uvm_object_utils(dma_transfer_with_irq_vseq)
  `uvm_declare_p_sequencer(soc_virtual_sequencer)

  function new(string name = "dma_transfer_with_irq_vseq");
    super.new(name);
  endfunction

  task body();
    apb_config_dma_seq  cfg_seq;
    dma_transfer_seq    xfer_seq;
    axi_read_verify_seq verify_seq;
    uvm_event           dma_done;

    // Step 1: Configure DMA via APB registers
    cfg_seq = apb_config_dma_seq::type_id::create("cfg_seq");
    cfg_seq.src_addr  = 32'h1000_0000;
    cfg_seq.dst_addr  = 32'h2000_0000;
    cfg_seq.length    = 256;
    cfg_seq.start(p_sequencer.apb_sqr, this);

    // Step 2: Trigger DMA transfer
    xfer_seq = dma_transfer_seq::type_id::create("xfer_seq");
    xfer_seq.start(p_sequencer.dma_sqr, this);

    // Step 3: Wait for the completion interrupt. irq_agt is PASSIVE (the DUT
    // drives the interrupt line), so it has no sequencer. Its monitor triggers
    // a named event instead; wait_on() returns at once if it already fired.
    dma_done = uvm_event_pool::get_global("dma_done_irq");
    dma_done.wait_on();

    // Step 4: Verify data via AXI reads
    verify_seq = axi_read_verify_seq::type_id::create("verify_seq");
    verify_seq.addr   = 32'h2000_0000;
    verify_seq.length = 256;
    verify_seq.start(p_sequencer.axi_sqr, this);
  endtask
endclass
```

**Key pattern:** Each `start()` call targets a **specific sub-sequencer** via the virtual sequencer's handle, and passes `this` as the parent so the child inherits the virtual sequence's context. The virtual sequence orchestrates the cross-protocol scenario; each child sequence only knows about its own protocol.

**Never start a sequence on a passive agent.** A passive agent never builds its sequencer, so `p_sequencer.irq_sqr` is null. `irq_wait_seq.start(null)` runs its `body()`, and the first `start_item()` stops the test with `UVM_FATAL [SEQ] neither the item's sequencer nor dedicated sequencer has been supplied…` (uvm-core `uvm_sequence_base.svh`). Wait through the passive agent's monitor: an event it triggers, or an analysis subscriber.

The order of the steps is the virtual sequence's job: the DUT drops data that arrives before it is configured. Pick a `body()` structure, predict what the run reports, then read the timeline cycle by cycle. The last two structures reproduce bugs this lesson used to contain.

## Cross-Agent Synchronization

### Using Events

When sequences on different agents must synchronize without a full handshake, one thread triggers a `uvm_event` and another waits for it. Keep two rules in mind:
- `wait_trigger()` waits for the **next** trigger. If the trigger already happened, it waits forever. `wait_on()` returns at once when the event is already on (IEEE 1800.2-2020 §10.1.1.2.2), and `wait_ptrigger()` covers a trigger earlier in the same time step.
- `fork…join` waits for **every** branch. A background branch that never ends, such as a responder sequence, keeps `body()` from returning, so the test never drops its objection.

```systemverilog
class synchronized_vseq extends uvm_sequence;
  `uvm_object_utils(synchronized_vseq)
  `uvm_declare_p_sequencer(soc_virtual_sequencer)

  uvm_event dma_config_done;

  function new(string name = "synchronized_vseq");
    super.new(name);
    dma_config_done = new("dma_config_done");
  endfunction

  task body();
    apb_config_dma_seq cfg_seq;
    dma_transfer_seq   xfer_seq;
    irq_responder_seq  irq_seq;   // irq_agt is ACTIVE here: it answers interrupts

    cfg_seq  = apb_config_dma_seq::type_id::create("cfg_seq");
    xfer_seq = dma_transfer_seq::type_id::create("xfer_seq");
    irq_seq  = irq_responder_seq::type_id::create("irq_seq");

    // Background: runs for the whole test, so it must not be part of the join
    fork
      irq_seq.start(p_sequencer.irq_sqr, this);
    join_none

    // Foreground: configure, then transfer; body() returns when both are done
    fork
      begin
        cfg_seq.start(p_sequencer.apb_sqr, this);
        dma_config_done.trigger();
      end
      begin
        dma_config_done.wait_on();
        xfer_seq.start(p_sequencer.dma_sqr, this);
      end
    join
    // irq_seq keeps running until the run phase ends and kills it
  endtask
endclass
```

An earlier version of this example put the background responder inside the same `fork…join`. Every data item matched, and the test still never ended. Find the line, then try the fixes; `join_any` and `join_none` look plausible and fail differently.

### Using Semaphores for Resource Arbitration

When multiple sequences compete for a shared resource (e.g., a shared bus):

```systemverilog
class arbitrated_vseq extends uvm_sequence;
  `uvm_object_utils(arbitrated_vseq)
  `uvm_declare_p_sequencer(soc_virtual_sequencer)

  semaphore bus_lock;

  function new(string name = "arbitrated_vseq");
    super.new(name);
    bus_lock = new(1); // Binary semaphore: one user at a time
  endfunction

  task body();
    fork
      run_axi_traffic();
      run_dma_traffic();
    join
  endtask

  task run_axi_traffic();
    axi_write_seq wr;  // declarations first: SV does not allow them after statements
    repeat (10) begin
      bus_lock.get(1); // Acquire bus
      wr = axi_write_seq::type_id::create("aw");
      wr.start(p_sequencer.axi_sqr, this);
      bus_lock.put(1); // Release bus
    end
  endtask

  task run_dma_traffic();
    dma_transfer_seq xfer;
    repeat (5) begin
      bus_lock.get(1); // Acquire bus
      xfer = dma_transfer_seq::type_id::create("dx");
      xfer.start(p_sequencer.dma_sqr, this);
      bus_lock.put(1); // Release bus
    end
  endtask
endclass
```

The semaphore only serializes these two threads of this one virtual sequence. It does nothing about other sequences running on the same sequencers; inside one sequencer that is the job of the arbitration mode and of `lock()`/`grab()` ([Sequencer Arbitration](/curriculum/T2_Intermediate/I-UVM-3B_Advanced_Sequencing_and_Layering/sequence-arbitration)).

## Topology Configuration with `uvm_config_db`

Configure multi-agent topologies from the test level. The agents here follow the A-UVM-7 VIP pattern: each reads a config object, copies `cfg.is_active` into its `is_active` field, and builds its driver and sequencer only when `get_is_active() == UVM_ACTIVE`. (A VIP without a config object takes the mode from a `uvm_config_db#(uvm_active_passive_enum)` entry named `"is_active"` instead, which `uvm_agent::build_phase` reads.)

```systemverilog
class dma_stress_test extends uvm_test;
  `uvm_component_utils(dma_stress_test)

  soc_env env;

  function new(string name, uvm_component parent);
    super.new(name, parent);
  endfunction

  function void build_phase(uvm_phase phase);
    axi_agent_config axi_cfg = axi_agent_config::type_id::create("axi_cfg");
    apb_agent_config apb_cfg = apb_agent_config::type_id::create("apb_cfg");
    irq_agent_config irq_cfg = irq_agent_config::type_id::create("irq_cfg");
    super.build_phase(phase);

    axi_cfg.is_active = UVM_ACTIVE;   // bus master
    apb_cfg.is_active = UVM_ACTIVE;   // register access
    irq_cfg.is_active = UVM_PASSIVE;  // the DUT drives the interrupt lines
    // (virtual interfaces are set in the same objects by tb_top / the base test)

    uvm_config_db#(axi_agent_config)::set(this, "env.axi_agt", "cfg", axi_cfg);
    uvm_config_db#(apb_agent_config)::set(this, "env.apb_agt", "cfg", apb_cfg);
    uvm_config_db#(irq_agent_config)::set(this, "env.irq_agt", "cfg", irq_cfg);

    env = soc_env::type_id::create("env", this);
  endfunction

  task run_phase(uvm_phase phase);
    dma_transfer_with_irq_vseq vseq;
    phase.raise_objection(this);

    vseq = dma_transfer_with_irq_vseq::type_id::create("vseq");
    vseq.start(env.v_sqr);

    phase.drop_objection(this);
  endtask
endclass
```

## Worked Example: 2-Agent AXI+APB Environment

Here is a minimal SoC environment with two agents (agent, sequencer and scoreboard classes as in the earlier modules):

```systemverilog
// Minimal SoC environment: AXI master + APB slave
class mini_soc_env extends uvm_env;
  `uvm_component_utils(mini_soc_env)

  axi_agent axi_master;
  apb_agent apb_slave;
  soc_virtual_sequencer v_sqr;
  soc_scoreboard scoreboard;

  function new(string name, uvm_component parent);
    super.new(name, parent);
  endfunction

  function void build_phase(uvm_phase phase);
    super.build_phase(phase);
    axi_master = axi_agent::type_id::create("axi_master", this);
    apb_slave  = apb_agent::type_id::create("apb_slave", this);
    v_sqr      = soc_virtual_sequencer::type_id::create("v_sqr", this);
    scoreboard = soc_scoreboard::type_id::create("scoreboard", this);
  endfunction

  function void connect_phase(uvm_phase phase);
    super.connect_phase(phase);
    v_sqr.axi_sqr = axi_master.sequencer;
    v_sqr.apb_sqr = apb_slave.sequencer;

    axi_master.monitor.ap.connect(scoreboard.axi_fifo.analysis_export);
    apb_slave.monitor.ap.connect(scoreboard.apb_fifo.analysis_export);
  endfunction
endclass
```
