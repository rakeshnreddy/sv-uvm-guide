## Quick Take

- **What it is:** **Verification IP (VIP)** is a protocol agent packaged so that other teams can use it without reading its source. It ships a **package** of classes (a configuration object, a sequence item, a driver, a monitor, a sequencer, a coverage collector and ready-made sequences), plus an **interface** that holds the protocol's signals, its clocking blocks and its protocol assertions. The interface sits outside the package, because a SystemVerilog package cannot contain an interface. A VIP also ships a self-test, a version number and a user guide.
- **Why it matters:** One VIP, written once, drives a bus at block level (an **active** agent) and only watches the same bus at chip level, where real hardware drives it (a **passive** agent). The settings that make this switch live in one configuration object, so nobody edits the VIP to reuse it. A VIP also decides whether its protocol checks count: assertion failures reach the UVM report summary only if the VIP reports them through UVM, and a regression that reads only `UVM_ERROR :    0` passes protocol violations it never counted.
- **The Analogy:** A bench protocol exerciser with an analyzer mode, the kind of box you plug into one connector standard. In exerciser mode it generates traffic (active); in analyzer mode it only listens (passive). It comes with compliance checks, a coverage report, a manual and a firmware version. *Where it breaks:* a passive agent is not the same box with the generator switched off. Its driver and sequencer are never constructed, so their handles are `null`. And a real analyzer's red light is always visible, while a VIP's checks count only if they report through the UVM report server.

**You will be able to:**
1. **Write** a VIP configuration object (`vif`, `is_active`, `has_coverage`, `checks_enable`, protocol and policy knobs) and an agent that builds from it, so one setting makes it active or passive and a passive build never constructs a driver or a sequencer.
2. **Write** a driver and a monitor that use the interface's clocking blocks through the virtual interface: the driver recovers from reset (stop, release the item, idle, resume) and the monitor publishes a new object per observed transfer. **Write** a responder driver and the reactive sequence that feeds it.
3. **Write** the VIP's package (include order, the interface outside the package, a parameterized interface with a virtual-interface typedef) and **integrate** it into a new environment through `uvm_config_db`.
4. **Debug** a run whose interface assertion fired but whose summary says `UVM_ERROR :    0`: route assertion failures through UVM reporting, and gate checks and coverage from the configuration object.
5. **Evaluate** a third-party VIP before integrating it: virtual-interface type and parameters, configuration paths, item and sequencer compatibility, version support and self-test evidence.

## Build Your Mental Model

### What a VIP contains, and what it leaves out

You already know the parts of an **agent** from [I-UVM-2A](/curriculum/T2_Intermediate/I-UVM-2A_Component_Roles/index): a **sequencer** that hands sequence items to a **driver**, which turns each item into pin activity, and a **monitor** that turns pin activity back into transactions and publishes them on an **analysis port** (a broadcast output, [I-UVM-2B](/curriculum/T2_Intermediate/I-UVM-2B_TLM_Connections/index)). The driver and monitor reach the pins through a **virtual interface**, a class-side handle to an interface instance (IEEE 1800-2023 §25.9), and they time their reads and writes with the interface's **clocking blocks** ([F4C](/curriculum/T1_Foundational/F4C_Clocking_Blocks/index)).

A VIP is that agent made reusable by someone who has never seen your testbench. That adds four things: a **configuration object** that is the VIP's only settings API, **sequences** that test writers start instead of building items by hand, **checks and coverage** that work in any environment, and the **shipping material**: package file, version, self-test and documentation.

| Part | Where it lives | Job |
|---|---|---|
| `apb_if` interface | outside the package, instantiated in `tb_top` | signals, clocking blocks `drv_cb`, `rsp_cb`, `mon_cb`, and the protocol assertions |
| `apb_agent_config` | `apb_pkg` | every setting: `vif`, `is_active`, `role`, `has_coverage`, `checks_enable`, responder policy |
| `apb_item` | `apb_pkg` | the data API: request fields, response fields, `do_copy`, `do_compare`, `convert2string` |
| `apb_agent` with `sqr`, `drv`, `mon`, `cov` | `apb_pkg` | builds what the configuration asks for; publishes observed transfers on `ap` |
| `apb_base_seq`, `apb_rw_seq`, `apb_reactive_seq` | `apb_pkg` | stimulus that test writers start and extend |
| self-test, version, user guide | shipped beside the package | proof that the VIP works, and the contract for its users |

What stays **outside** the VIP matters as much. A **scoreboard** compares what went into the design under test (DUT) with what came out, which needs at least two interfaces, so it belongs to the environment that uses the VIP ([A-UVM-6](/curriculum/T3_Advanced/A-UVM-6_Scoreboards_and_Reference_Models/index)). The VIP's monitor feeds scoreboards; it never contains one.

### The APB3 subset this VIP speaks

The example protocol is **APB**, Arm's simple register bus (Arm IHI 0024C). It has no dedicated lesson yet (a B-APB-1 module is planned), so this section defines the subset the VIP implements. IHI 0024C calls the revision with wait states and error reporting **APB3** and the one that adds `PPROT` and `PSTRB` **APB4** (§1.2). This VIP implements APB3 signals with 32-bit buses, the maximum the specification allows (§2.1.1).

The **master** (the requester, usually a bridge) drives `PSEL`, `PENABLE`, `PWRITE`, `PADDR` and `PWDATA`. The **slave** (the completer) drives `PREADY`, `PRDATA` and `PSLVERR`. Later Arm issues call these roles manager and subordinate. Every transfer has two phases (§4.1):

- **SETUP:** `PSEL` = 1, `PENABLE` = 0. It always lasts exactly one clock cycle; the bus moves to ACCESS at the next rising edge. Address, direction and write data must not change between SETUP and ACCESS.
- **ACCESS:** `PSEL` = 1, `PENABLE` = 1. The slave ends it by driving `PREADY` high. While `PREADY` is low the transfer waits, and the master holds `PADDR`, `PWRITE`, `PSEL`, `PENABLE` and, for writes only, `PWDATA` unchanged (§3.1.2, §3.3.2). Any number of wait states is legal, from zero upwards (§3.3.2). `PREADY` may take any value while `PENABLE` is low (§3.1.2).
- **Completion:** the transfer completes at the edge where `PSEL`, `PENABLE` and `PREADY` are all 1. `PSLVERR` counts only at that edge (§3.4); `PRDATA` is valid there for reads. `PENABLE` falls after completion (§3.1.1).

APB has **no bursts**: every transfer is a separate SETUP and ACCESS, so it takes at least two cycles. In the waveform, each value is the one **sampled at that rising edge**, which is what a clocking block reads and what the slave's flops capture.

### The configuration object is the VIP's API

A test writer should change a VIP's behaviour in one place, with one type, without knowing the VIP's internal paths. That place is the **configuration object**, a `uvm_object` that the test creates, fills and hands to the agent through the **configuration database** (`uvm_config_db`, [I-UVM-2C](/curriculum/T2_Intermediate/I-UVM-2C_Configuration_and_Resources/index)).

```systemverilog
// snippet: from apb_pkg (complete version in Make It Work)
typedef virtual apb_if #(.AW(32), .DW(32)) apb_vif_t;  // the one vif type of this VIP
typedef enum {APB_MASTER, APB_RESPONDER} apb_role_e;

class apb_agent_config extends uvm_object;
  `uvm_object_utils(apb_agent_config)

  apb_vif_t               vif;                        // which interface instance
  uvm_active_passive_enum is_active     = UVM_ACTIVE; // build drv and sqr?
  apb_role_e              role          = APB_MASTER; // active only: which side to play
  bit                     has_coverage  = 1;          // build cov?
  bit                     checks_enable = 1;          // interface assertions on?
  int unsigned            max_wait      = 3;          // responder: most wait states
  int unsigned            slverr_pct    = 10;         // responder: PSLVERR rate, 0..100

  function new(string name = "apb_agent_config");
    super.new(name);
  endfunction
endclass
```

The flow has a fixed order. `tb_top` publishes the interface instance before the test exists; the test reads it during its `build_phase`, creates the configuration object and sets it for the agent's path; the agent gets it once in its own `build_phase` and hands the **same handle** to its children. Because the build phase runs top-down (IEEE 1800.2-2020 §9.8.1.1), each step happens before the step that needs it.

**Misconception: "VIP settings should be many scalar `config_db` fields."** It is tempting to give every knob its own `uvm_config_db` entry. With nine knobs and four agents that is 36 untyped lookups by string. A typo in a field name, or a `set` with `int` where the `get` uses `int unsigned`, makes the `get()` return 0 with no message, and the agent quietly runs on its defaults. One configuration object means one typed lookup that fails loudly (`NO_CFG`), defaults that live in one class, a `convert2string` that prints every setting, and an object you can randomize or copy for a second agent. The standard `"is_active"` entry still exists (§13.4.2.2); the next section shows how this VIP treats it.

The same silence happens when the interface's **parameters** differ, which is why this VIP declares its vif type once, as `apb_vif_t`, and uses it on both sides.

### Active and passive: what the agent builds

The agent's `build_phase` decides the topology. It fetches the configuration, copies the mode into `uvm_agent`'s `is_active`, always builds the monitor, builds the coverage collector only when asked, and builds the sequencer and driver only when the agent is active.

```systemverilog
// snippet: apb_agent::build_phase and connect_phase (complete class in Make It Work)
function void build_phase(uvm_phase phase);
  super.build_phase(phase);   // uvm-core reads a scalar "is_active" setting here
  if (!uvm_config_db#(apb_agent_config)::get(this, "", "cfg", cfg))
    `uvm_fatal("NO_CFG", {"no apb_agent_config named cfg for ", get_full_name()})
  if (cfg.vif == null)
    `uvm_fatal("NO_VIF", {"cfg.vif is null for ", get_full_name()})
  is_active = cfg.is_active;  // the config object wins (uvm-core member, see below)
  ap  = new("ap", this);
  mon = apb_monitor::type_id::create("mon", this);
  mon.cfg = cfg;
  if (cfg.has_coverage) cov = apb_coverage::type_id::create("cov", this);
  if (get_is_active() == UVM_ACTIVE) begin   // passive: sqr and drv stay null
    sqr = apb_sequencer::type_id::create("sqr", this);
    sqr.cfg = cfg;
    if (cfg.role == APB_MASTER) drv = apb_master_driver::type_id::create("drv", this);
    else                        drv = apb_responder_driver::type_id::create("drv", this);
    drv.cfg = cfg;
  end
endfunction

function void connect_phase(uvm_phase phase);
  super.connect_phase(phase);
  mon.ap.connect(ap);         // the env connects to agt.ap, never to agt.mon.ap
  if (cfg.has_coverage) mon.ap.connect(cov.analysis_export);
  if (get_is_active() == UVM_ACTIVE) begin   // same test as build: handles may be null
    drv.seq_item_port.connect(sqr.seq_item_export);
    if (cfg.role == APB_RESPONDER) mon.req_ap.connect(sqr.req_fifo.analysis_export);
  end
  cfg.vif.checks_enable = cfg.checks_enable;
endfunction
```

**Misconception: "a passive agent is an active agent with an idle driver."** Passive means *never constructed*. The `if` branch is skipped, `create()` is never called, and `sqr` and `drv` stay `null`. An idle driver would still own clocking-block outputs on the bus. Anything that touches `agt.sqr` in a passive agent meets a `null` handle: starting a sequence on it ends in a fatal error (uvm-core 2020.3.1 reports `UVM_FATAL ... [SEQ] neither the item's sequencer nor dedicated sequencer has been supplied to start item`).

**One mode, two places to set it.** IEEE 1800.2-2020 §13.4.2.2 defines `get_is_active()` and a configuration setting named `"is_active"`. In uvm-core, `uvm_agent` stores the mode in a member variable `is_active`, which `uvm_agent::build_phase` fills from that setting; the member itself is an implementation detail, not part of the standard. This agent copies `cfg.is_active` into the member *after* `super.build_phase()`, so `get_is_active()` gives one answer everywhere, and **a scalar `"is_active"` setting, or `+uvm_set_config_string=<path>,is_active,UVM_PASSIVE`, is silently ignored**. The VIP's user guide must say so. A portable alternative is to override the virtual `get_is_active()` to return `cfg.is_active`, which §13.4.2.2 explicitly allows.

Its agent is a simpler `spi_agent` that takes the mode from the scalar `"is_active"` setting, not from a configuration object, but what gets built is the same. **Predict** which components exist in passive mode, then switch levels. ### The driver: clocking-block drives and reset

A driver must do two things right: drive the pins only through its clocking block, and survive a reset in the middle of a transfer.

**Clocking-block drives.** A synchronous drive such as `vif.drv_cb.psel <= 1'b1;` with zero output skew, executed in the time step of a clock edge, changes the signal in the Re-NBA region of that time step (a late scheduling region, after every flop has sampled the edge; see [F3B](/curriculum/T1_Foundational/F3B_Scheduling_Regions/index)), so the value is sampled at the **next** edge (IEEE 1800-2023 §14.16). That is why the master below waits for an edge first, then drives, then waits for the edge that samples what it drove. It reads `PREADY` from `vif.drv_cb.pready`, the value sampled just before the edge (input skew `1step` by default, §14.3).

```systemverilog
// snippet: apb_master_driver::drive_item (complete class in Make It Work)
virtual task drive_item(apb_item it);
  @(vif.drv_cb);                            // start just after an edge
  vif.drv_cb.psel    <= 1'b1;               // SETUP: sampled at the next edge
  vif.drv_cb.penable <= 1'b0;
  vif.drv_cb.pwrite  <= it.write;
  vif.drv_cb.paddr   <= it.addr;
  if (it.write) vif.drv_cb.pwdata <= it.wdata;
  @(vif.drv_cb);                            // the SETUP edge
  vif.drv_cb.penable <= 1'b1;               // ACCESS
  @(vif.drv_cb);                            // first ACCESS edge
  it.wait_cycles = 0;
  while (vif.drv_cb.pready !== 1'b1) begin  // wait states: hold everything
    it.wait_cycles++;
    @(vif.drv_cb);
  end
  if (!it.write) it.rdata = vif.drv_cb.prdata;  // valid at the completion edge only
  it.slverr = vif.drv_cb.pslverr;
  drive_idle();                             // PSEL, PENABLE low at the next edge
endtask
```

**Reset: stop, release, idle, resume.** Reset can arrive in the middle of a wait state. The driver must stop driving at once, release the item it holds so the sequence is not stuck, put the bus in its idle state, and start again only after reset ends. The rule that makes this safe is **one `item_done()` per `get_next_item()`, always**: `finish_item()` in the sequence returns only after the driver signals that the item is done (IEEE 1800.2-2020 §14.2.6.3). This VIP writes the recipe once, in a base class shared by the master and the responder; each role supplies only `drive_item` and `drive_idle`.

```systemverilog
// snippet: apb_driver_base::run_phase (complete class in Make It Work)
task run_phase(uvm_phase phase);
  drive_idle();
  forever begin
    seq_item_port.get_next_item(req);
    wait (vif.preset_n === 1'b1);           // never start an item during reset
    fork
      begin : guard                         // keeps disable fork local to this block
        fork
          drive_item(req);
          wait (vif.preset_n === 1'b0);     // reset asserted mid-item
        join_any
        disable fork;
      end
    join
    if (vif.preset_n !== 1'b1) begin
      drive_idle();                         // takes effect at the next clock edge
      `uvm_info("APB_RST", {"aborted by reset: ", req.convert2string()}, UVM_MEDIUM)
    end else begin
      apb_item done;
      $cast(done, req.clone());
      done_ap.write(done);                  // the completed item, as this driver saw it
    end
    seq_item_port.item_done();              // exactly one per get_next_item
  end
endtask
```

Three details are easy to miss:
- **`disable fork` kills every child process of the calling process** (IEEE 1800-2023 §9.6.3), not just the two in this `fork`. The `guard` block makes the `drive_item` and `wait` threads children of a fresh process, so the `disable fork` cannot reach anything else `run_phase` may have started.
- **Reset is read directly from `vif.preset_n`, not through the clocking block**, because it is asynchronous: a clocking block would see it only at the next edge.
- **`get_next_item()` is never inside the killed fork.** Killing a driver while it waits inside the sequencer's handshake leaves the sequencer's bookkeeping to the implementation; this structure never does it.

**Pitfalls.**
- *A blocking assignment to a DUT input at the clock edge* (`vif.psel = 1;`) races with the flops that sample it ([F3C](/curriculum/T1_Foundational/F3C_Delta_Cycles_and_Race_Conditions/index)). Drive through the clocking block.
- *Killing the transfer without `item_done()`.* The sequence waits in `finish_item()` forever, so its parent never ends and the test's **objection** (the counter that keeps the run phase alive until every raiser drops it, [I-UVM-1C](/curriculum/T2_Intermediate/I-UVM-1C_UVM_Phasing/index)) is never dropped. The symptom is a hang until the global timeout. This applies to drivers that use `get_next_item()`; a driver that uses `get()` has already completed the handshake when `get()` returns (§14.2.6.3 NOTE).
- *Who else might flush the sequencer.* If the environment also calls `sqr.stop_sequences()` on reset, the in-flight item has two owners; see the expert item on reset ownership in Push Further.

### The monitor: sample, build a new item, publish

The monitor watches the bus through `mon_cb`, which samples every signal, including `preset_n`, at each edge. It recognizes a SETUP edge, publishes the request at once for any responder on the same bus, then waits for the completion edge, counts wait states on the way, and publishes the finished transfer.

```systemverilog
// snippet: apb_monitor (complete class in Make It Work)
task run_phase(uvm_phase phase);
  forever begin
    @(vif.mon_cb);
    if (vif.mon_cb.preset_n === 1'b1 && vif.mon_cb.psel === 1'b1
        && vif.mon_cb.penable === 1'b0)
      collect_transfer();                   // a SETUP edge
  end
endtask

protected task collect_transfer();
  apb_item rq, tr;
  rq = apb_item::type_id::create("rq");     // the request, for responders, right now
  rq.write = vif.mon_cb.pwrite;
  rq.addr  = vif.mon_cb.paddr;
  rq.wdata = vif.mon_cb.pwdata;
  req_ap.write(rq);
  tr = apb_item::type_id::create("tr");     // a NEW object for every transfer
  tr.copy(rq);
  forever begin
    @(vif.mon_cb);
    if (vif.mon_cb.preset_n !== 1'b1) return;               // reset: discard
    if (vif.mon_cb.psel !== 1'b1 || vif.mon_cb.penable !== 1'b1) return;  // SVA reports
    if (vif.mon_cb.pready === 1'b1) break;                  // completion edge
    tr.wait_cycles++;
  end
  if (!tr.write) tr.rdata = vif.mon_cb.prdata;
  tr.slverr = vif.mon_cb.pslverr;           // counts only at this edge (IHI 0024C §3.4)
  ap.write(tr);
endtask
```

**Why a new object every time.** `ap.write(tr)` passes a **handle**, not a copy: every subscriber receives a reference to the same object (IEEE 1800-2023 §8.4, §8.12). A subscriber may not modify what it receives (IEEE 1800.2-2020 §12.2.10.2), but nothing stops the *monitor* from modifying it later. If the monitor created `tr` once in `build_phase` and refilled it for each transfer, every handle a scoreboard stored would point at one object, which holds the last transfer.

Trace three transfers to addresses `0x10`, `0x14` and `0x18` into a scoreboard that stores each handle it receives:

| After transfer | Monitor reuses one `tr`: what the stored handles show | Monitor creates `tr` per transfer: what the stored handles show |
|---|---|---|
| 1 (`0x10`) | `[0x10]` | `[0x10]` |
| 2 (`0x14`) | `[0x14, 0x14]`: both handles point at the one object | `[0x10, 0x14]` |
| 3 (`0x18`) | `[0x18, 0x18, 0x18]` | `[0x10, 0x14, 0x18]` |

Scoreboards should still copy before they store ([A-UVM-6](/curriculum/T3_Advanced/A-UVM-6_Scoreboards_and_Reference_Models/index)), but a VIP cannot rely on every user doing so.

**Reset in the monitor.** A transfer cut by reset never completed, so the monitor publishes nothing for it. Publishing a partial transfer would give the scoreboard a false mismatch.

### Responder agents and reactive sequences

So far the VIP plays the master. To verify an APB **master** DUT, such as a bridge, the VIP must play the **slave**: answer each request with wait states, read data and errors that a test can control. A **responder agent** (also called a slave or reactive agent) does that. Its stimulus cannot be generated in advance, because it depends on requests the DUT has not made yet, so it comes from a **reactive sequence**: a sequence that waits for a request, then produces the response.

The pattern uses three pieces:
1. The monitor publishes each request at its SETUP edge on a second analysis port, `req_ap`.
2. The agent's sequencer holds a `uvm_tlm_analysis_fifo #(apb_item) req_fifo`, an unbounded FIFO with an `analysis_export` (IEEE 1800.2-2020 §12.2.8.3). In the responder role the agent connects `mon.req_ap` to it.
3. The reactive sequence reaches that FIFO through `p_sequencer`, the typed handle to its sequencer that `` `uvm_declare_p_sequencer `` declares (Annex B.3.3). It blocks in `req_fifo.get()`, then creates a response item and sends it to the responder driver.

```systemverilog
// snippet: apb_reactive_seq::body and apb_responder_driver (Make It Work has both)
task body();                                // apb_reactive_seq
  apb_item obs, rsp;
  forever begin
    p_sequencer.req_fifo.get(obs);          // a request seen at a SETUP edge
    rsp = apb_item::type_id::create("rsp");
    start_item(rsp);
    rsp.write = obs.write;
    rsp.addr  = obs.addr;
    rsp.wdata = obs.wdata;
    rsp.c_aligned.constraint_mode(0);       // the DUT chose addr: do not re-check it
    if (!rsp.randomize(wait_cycles, rdata, slverr) with {  // only these are random
          wait_cycles <= p_sequencer.cfg.max_wait;
          slverr dist {1 := p_sequencer.cfg.slverr_pct,
                       0 := 100 - p_sequencer.cfg.slverr_pct};
        })
      `uvm_fatal("RAND", "response randomization failed")
    finish_item(rsp);
  end
endtask

virtual task drive_item(apb_item it);       // apb_responder_driver
  repeat (it.wait_cycles) @(vif.rsp_cb);    // PREADY stays low: wait states
  vif.rsp_cb.pready  <= 1'b1;
  vif.rsp_cb.pslverr <= it.slverr;
  if (!it.write) vif.rsp_cb.prdata <= it.rdata;
  @(vif.rsp_cb);                            // the completion edge
  drive_idle();                             // PREADY and PSLVERR low again
endtask
```

`randomize(wait_cycles, rdata, slverr)` makes only those three fields random for this call; the request fields keep the observed values (IEEE 1800-2023 §18.11). The item's own constraints still apply to those state variables, and a constraint that fails on them makes `randomize()` fail. That is why the sequence first turns off `c_aligned`, the item's word-alignment rule for generated addresses: a responder must answer whatever address the DUT sends, not only the ones this VIP would have generated. Test writers change the responder's behaviour by extending this sequence or overriding it with the factory, never by editing the driver.

Two design decisions make the responder robust:
- **`PREADY` is low by default.** The responder raises it only to complete a transfer. If a reactive sequence is slow, for example because it waits for a reference model, the master simply sees more wait states, which APB allows in any number (IHI 0024C §3.3.2). A responder that held `PREADY` high by default would complete transfers it had not answered yet.
- **`PSLVERR` is driven low when it is not sampled.** IHI 0024C §3.4 recommends this but does not require it, so a monitor must ignore `PSLVERR` outside the completion edge.

**Pitfall: an objection in a `forever` sequence.** A reactive sequence never ends. If it raises an objection, or the test turns on its automatic phase objection, the objection is never dropped and the run phase never ends; IEEE 1800.2-2020 §14.2.4.4 warns against exactly this. Start it without an objection, in a `fork ... join_none`, and let the test's own traffic hold the objection. The AXI and AHB verification lessons, [B-AXI-6](/curriculum/T3_Advanced/B-AXI-6_AXI_Verification_Performance/index) and [B-AHB-3](/curriculum/T3_Advanced/B-AHB-3_AHB_Verification/index), apply the same pattern to responders with random `READY` signals, out-of-order answers and error injection.

### The sequences a VIP ships

A test writer should never have to write `start_item` for a plain register write. The VIP ships a **base sequence** with helper tasks, and every other sequence extends it.

```systemverilog
// snippet: apb_base_seq (complete version in Make It Work)
class apb_base_seq extends uvm_sequence #(apb_item);
  `uvm_object_utils(apb_base_seq)
  `uvm_declare_p_sequencer(apb_sequencer)   // p_sequencer.cfg: the agent's settings

  function new(string name = "apb_base_seq");
    super.new(name);
  endfunction

  task apb_write(bit [31:0] addr, bit [31:0] data, output bit slverr);
    apb_item it = apb_item::type_id::create("it");
    start_item(it);
    if (!it.randomize() with { write == 1; addr == local::addr; wdata == data; })
      `uvm_fatal("RAND", "apb_write: randomization failed")
    finish_item(it);
    slverr = it.slverr;   // the master driver filled the response before item_done
  endtask
endclass
```

`local::addr` names the task's argument rather than the item's field of the same name inside the inline constraint (IEEE 1800-2023 §18.7.1). The helpers return the response because the master driver writes `rdata`, `slverr` and `wait_cycles` into the same item before it calls `item_done()`.

Practitioner notes:
- **Constraints layer.** Put protocol-legal defaults in the item (`addr` word-aligned) and test intent in derived sequences or inline `with` blocks.
- **Error injection is a sequence, gated by configuration.** A sequence that makes the responder return `PSLVERR` is legal APB and needs no special permission. A sequence that makes the *master* break the protocol must run with checks configured for it (see the interface checks below), and the reset and error-injection strategy for a whole environment is a separate topic (a planned A-UVM-9 module).
- **`uvm_sequence_library`** (IEEE 1800.2-2020 §14.4) is a specific class that picks registered sequences at random. It is an option for soak tests, not a synonym for "the sequences a VIP ships".

### The coverage model

A VIP's coverage collector measures how much of the *protocol* a test has exercised, whatever the DUT. It is a `uvm_subscriber #(apb_item)`: a component with a built-in `analysis_export` whose `write()` method the subclass implements (IEEE 1800.2-2020 §13.9). The agent builds and connects it only when `cfg.has_coverage` is 1.

```systemverilog
// snippet: apb_coverage (complete class in Make It Work)
class apb_coverage extends uvm_subscriber #(apb_item);
  `uvm_component_utils(apb_coverage)
  apb_item tr;

  covergroup cg_apb;
    cp_dir:   coverpoint tr.write { bins read = {0}; bins write = {1}; }
    cp_waits: coverpoint tr.wait_cycles { bins none = {0}; bins one = {1};
                                          bins many = {[2:$]}; }
    cp_err:   coverpoint tr.slverr;
    x_dir_err: cross cp_dir, cp_err;
  endgroup

  function new(string name, uvm_component parent);
    super.new(name, parent);
    cg_apb = new();               // an embedded covergroup is built in new()
  endfunction

  function void write(apb_item t);
    tr = t;
    cg_apb.sample();
  endfunction
endclass
```

Trace which bins fill after four observed transfers. Each row adds hits; "x" marks the first hit of a bin.

| Transfer | `cp_dir` | `cp_waits` | `cp_err` | `x_dir_err` |
|---|---|---|---|---|
| write, 1 wait, `PSLVERR` 0 | write x | one x | 0 x | (write, 0) x |
| read, 0 waits, `PSLVERR` 1 | read x | none x | 1 x | (read, 1) x |
| write, 3 waits, `PSLVERR` 0 | | many x | | |
| read, 0 waits, `PSLVERR` 0 | | | | (read, 0) x |

After four transfers every coverpoint bin is hit but the cross still misses (write, 1): no write has completed with an error. That gap tells you what the next test, or the responder's `slverr_pct`, must do. Covergroups are taught in [I-SV-3A](/curriculum/T2_Intermediate/I-SV-3A_Functional_Coverage_Fundamentals/index); what a VIP adds is the gate. At SoC level dozens of passive agents may sample coverage nobody reads, so `has_coverage` lets the integrator switch it off.

### Interface checks that count

Protocol rules about signal timing belong in the interface as **concurrent assertions** ([I-SV-4A](/curriculum/T2_Intermediate/I-SV-4A_SVA_Fundamentals/index)): they check every clock edge, whatever the test does, including at SoC level where the agent is passive and no driver exists. Rules about transactions (address maps, error accounting) belong in the monitor or in a subscriber.

```systemverilog
// snippet: the checks inside apb_if (complete interface in Make It Work)
bit checks_enable = 1'b1;   // the agent copies cfg.checks_enable here

a_setup_then_access: assert property (
  @(posedge pclk) disable iff (!preset_n || !checks_enable)
    (psel && !penable) |=> (psel && penable && $stable(paddr) && $stable(pwrite)
                            && (!pwrite || $stable(pwdata))))
  else `uvm_error("APB_SVA", $sformatf("%m: SETUP not followed by a stable ACCESS"))

a_wait_stable: assert property (
  @(posedge pclk) disable iff (!preset_n || !checks_enable)
    (psel && penable && !pready) |=> (psel && penable && $stable(paddr)
                                      && $stable(pwrite) && (!pwrite || $stable(pwdata))))
  else `uvm_error("APB_SVA", $sformatf("%m: transfer changed during a wait state"))
```

The complete interface has four properties: SETUP is followed by a stable ACCESS (§4.1), `PENABLE` rises only after SETUP, nothing changes during a wait state (§3.1.2, §3.3.2), and `PENABLE` falls after completion (§3.1.1). They are a **subset** of IHI 0024C: they say nothing about `PSTRB`, `PPROT`, or unknown values on the buses. A real VIP documents which rules it checks.

**Misconception: "`$error` in an interface assertion increments `UVM_ERROR`."** An assertion with no `else`, or with `else $error(...)`, reports through the simulator's own messages (IEEE 1800-2023 §16.14.1, §20.10). The UVM report server never sees them, so the summary says `UVM_ERROR :    0` and a regression that checks only that line passes. `` `uvm_error `` works in an interface once the interface imports `uvm_pkg`: outside a class, the macro reports through `uvm_get_report_object()`, which returns `uvm_root` (IEEE 1800.2-2020 F.3.2.1), and the server counts it. The message's source then shows as `reporter`, with no component path, which is why each message adds `%m`, the hierarchical name of the interface instance.

**Gating checks from the configuration.** Error-injection tests break the protocol on purpose, so the VIP must let them turn checks off. Three controls exist, from most to least VIP-friendly:

| Control | Who sets it | Effect |
|---|---|---|
| `checks_enable` in `disable iff` | the agent, from `cfg.checks_enable`, through the vif | per interface instance; an attempt that is disabled runs no action block (IEEE 1800-2023 §16.14.1), and attempts in flight are disabled too |
| `$assertoff`, `$asserton`, `$assertkill`, `$assertcontrol` | a module, usually `tb_top` | by hierarchical scope or assertion name (§20.11). `$assertoff` stops new attempts; attempts already running finish. `$assertkill` also aborts those |
| severity override or report catcher on the ID `APB_SVA` | the test, on `uvm_root` | the assertion still fires, but the message is demoted or caught (IEEE 1800.2-2020 §6.3.7, §6.6). Works only because the VIP reports through UVM |

A test class cannot call `$assertoff(0, tb_top.bus)` itself: items in a package may not contain hierarchical references to the design (IEEE 1800-2023 §26.2). That is why the VIP exposes `checks_enable` through the configuration, and why `$assertoff` lives in `tb_top`, typically behind a plusarg the test documents:

```systemverilog
// snippet: tb_top; +APB_SVA_OFF is this testbench's own plusarg, not a UVM one
initial if ($test$plusargs("APB_SVA_OFF")) $assertoff(0, tb_top.bus);
```

When several agents share one interface, as in the self-test, they all write the same `checks_enable` bit. Give them the same setting, or the last agent to connect wins.

```systemverilog
  `include "src/apb_agent.svh"       // after every class it creates
  `include "src/seq/apb_base_seq.svh"
  `include "src/seq/apb_rw_seq.svh"
  `include "src/seq/apb_back_to_back_seq.svh"
  `include "src/seq/apb_reactive_seq.svh"
endpackage
```

Three rules explain this shape:
- **The interface stays outside the package.** A package is a named scope for shared types, classes, tasks and functions; its grammar has no place for an interface declaration (IEEE 1800-2023 §26.2). The package refers to the interface only through the virtual-interface type `apb_vif_t`.
- **Include order is declaration order.** A class must be declared before another class uses it as a base class or in most other ways, so the package includes base classes and used types first. When two classes refer to each other, a forward declaration `typedef class apb_agent;` (§8.27) breaks the cycle.
- **Compile order follows from that:** uvm-core (or the simulator's built-in UVM library), then `apb_if.sv`, then `apb_pkg.sv` with the VIP's root directory on the include path, then the user's test package, then `tb_top.sv`.

### Parameterized interfaces and virtual-interface typedefs

Buses come in widths. An interface can take parameters just like a module (IEEE 1800-2023 §25.8):

```systemverilog
// snippet
interface apb_if #(int AW = 32, int DW = 32) (input logic pclk, input logic preset_n);
  wire [AW-1:0] paddr;
  wire [DW-1:0] pwdata, prdata;
  // ...
endinterface
```

The catch is the virtual-interface **type**. §25.9: the type of an interface includes its actual parameter values, default or overridden, and they must match for an interface instance and a virtual interface to be the same type; a selected modport is also part of the type. `uvm_config_db` looks values up by their exact type, and a lookup of another type returns 0 without a message (uvm-core 2020.3.1). So:

| `set` with | `get` with | Same type? | Result |
|---|---|---|---|
| `virtual apb_if #(32, 32)` | `virtual apb_if #(32, 32)` | yes | found |
| `virtual apb_if` (defaults are 32, 32) | `apb_vif_t` (`virtual apb_if #(32, 32)`) | yes: the defaults are the actual values | found |
| `virtual apb_if #(16, 32)` | `virtual apb_if #(32, 32)` | no | `get()` returns 0 silently; the VIP's `NO_VIF` fatal fires |
| `virtual apb_if` | `virtual apb_if.some_mp` | no | `get()` returns 0, although SystemVerilog allows *assigning* the plain vif to the modport vif (§25.9) |

That is why the VIP declares the type **once**, `typedef virtual apb_if #(.AW(32), .DW(32)) apb_vif_t;`, and both `tb_top` and the VIP use `apb_vif_t`. A typedef is only a new name for the same type, so it never causes a mismatch.

This VIP supports one specialization, 32 by 32, because APB buses are at most 32 bits wide; a narrower peripheral connects to the low bits. A VIP that must support several specializations has two choices: carry `AW` and `DW` as parameters through every class (an agent declared with `` `uvm_component_param_utils ``), or keep one maximum-width interface type and put the used width in the configuration. Push Further compares them.

### Integrating the VIP into a new environment

To use the VIP with a DUT, three files change, and none of them is the VIP's. The example is an APB register block `apb_regs` (an APB slave), so the agent plays the active master.

```systemverilog
// snippet: tb_top.sv for a DUT that is an APB slave
module tb_top;
  import uvm_pkg::*;
  import apb_pkg::*;
  import regs_test_pkg::*;

  logic pclk = 1'b0;
  logic preset_n;
  always #5 pclk = ~pclk;

  apb_if bus (.pclk(pclk), .preset_n(preset_n));

  // Connect DUT ports to the interface's nets at instantiation: one driver per net.
  apb_regs dut (.pclk(pclk), .presetn(preset_n), .psel(bus.psel), .penable(bus.penable),
                .pwrite(bus.pwrite), .paddr(bus.paddr), .pwdata(bus.pwdata),
                .prdata(bus.prdata), .pready(bus.pready), .pslverr(bus.pslverr));

  initial begin
    preset_n = 1'b0;
    repeat (3) @(posedge pclk);
    preset_n <= 1'b1;
  end

  initial begin
    uvm_config_db#(apb_vif_t)::set(null, "uvm_test_top", "vif", bus);  // before run_test
    run_test();
  end
endmodule
```

The test reads `vif`, builds an `apb_agent_config` with `is_active = UVM_ACTIVE` and `role = APB_MASTER`, and sets it for `"env.apb_agt"`. The env creates `apb_agt` with `apb_agent::type_id::create` and connects `apb_agt.ap` to its scoreboard. Two mistakes are common here:
- **Assigning into the DUT's hierarchy**, as in `assign dut.u_core.psel = bus.psel;`, adds a second driver to a net the DUT already drives through its port, and on a variable that has another writer it is illegal (IEEE 1800-2023 §6.5). Connect the interface's nets to the DUT's ports, as above.
- **Setting the vif after `run_test()`**, or in an `initial` block that races with it. The test's `build_phase` runs inside `run_test()`, so the `set` must come first.

### Passive reuse at SoC level

At SoC level the same APB bus is driven by the chip's own bridge. The block-level VIP is reused **unchanged**: the SoC test sets `cfg.is_active = UVM_PASSIVE`, and `tb_top` feeds the interface from the RTL instead of connecting the DUT to it.

```systemverilog
// snippet: SoC tb_top observes an internal APB bus (hierarchical names are examples)
apb_if soc_apb (.pclk(dut.u_apb_bridge.pclk), .preset_n(dut.u_apb_bridge.presetn));
assign soc_apb.psel    = dut.u_apb_bridge.psel;     // one-way: RTL drives the
assign soc_apb.penable = dut.u_apb_bridge.penable;  // interface's nets, nothing
assign soc_apb.pready  = dut.u_uart.pready;         // drives back into the RTL
// ... the other APB signals the same way

// snippet: tb_top publishes it before run_test(), with the type the VIP uses
initial begin
  uvm_config_db#(apb_vif_t)::set(null, "uvm_test_top", "uart_apb_vif", soc_apb);
  run_test();
end

// snippet: in the SoC test's build_phase
if (!uvm_config_db#(apb_vif_t)::get(this, "", "uart_apb_vif", soc_vif))
  `uvm_fatal("NO_VIF", "tb_top did not set uart_apb_vif")
cfg = apb_agent_config::type_id::create("uart_apb_cfg");
cfg.vif          = soc_vif;
cfg.is_active    = UVM_PASSIVE;   // monitor (and coverage) only
cfg.has_coverage = 1;
uvm_config_db#(apb_agent_config)::set(this, "env.uart_apb", "cfg", cfg);
```

The hierarchical references stay in `tb_top`. An interface that itself contains hierarchical references to signals outside it may not be used for a virtual interface (§25.9). The proof that reuse worked is the topology: the passive agent lists `ap`, `cov` and `mon`, and no `drv` or `sqr`. The SoC application of this pattern, with an SPI agent and a CPU running firmware, is the `soc-vip-reuse` lab of [E-SOC-1](/curriculum/T4_Expert/E-SOC-1_SoC-Level_Verification_Strategies/index), linked under Practice & Reinforce.

**Misconception: "my sequences must extend the vendor's base sequence because it implements protocol-specific `start_item` and `finish_item`."** Protocol timing lives in the driver. `start_item` and `finish_item` are `uvm_sequence_base` tasks that ask the sequencer for a grant, send the item, and wait for the driver's `item_done()` (IEEE 1800.2-2020 §14.2.6.2, §14.2.6.3). They are virtual, so a vendor *could* override them, but vendor base sequences normally add helpers, configuration access and `p_sequencer`. What actually has to match is the **item type**: a sequence that sends an unrelated item type to the vendor's `uvm_sequencer #(vendor_item)` fails when the sequencer casts it (uvm-core 2020.3.1: `UVM_FATAL ... [SQRSNDREQCAST] send_request failed to cast sequence item`; the standard specifies no message for this case). Extending the vendor's base sequence is the documented way to get its helpers; it is good practice, not a UVM rule.

The full evaluation checklist is in Push Further. The licensing point belongs here: commercial VIP needs a run-time license, and a regression that falls back to a stub VIP when the checkout fails reports a pass with no protocol checks. A checkout failure is an infrastructure error; retry or queue the job, never pass it.

### Shipping a VIP: self-test, version and documentation

A VIP is a product, and its users need three things beside the code.

- **A self-test.** The VIP's own environment, with no DUT: an active master and an active responder on one interface, plus a passive observer agent. A scoreboard compares what the master intended with what the observer saw. A second test injects a protocol violation and must fail with exactly one `APB_SVA` error, which proves the checks fire and are counted. Make It Work builds both.
- **A version.** A semantic version (`1.0.0`) in a `VERSION` file and in the package parameter `APB_VIP_VERSION`, printed once at the start of simulation together with the UVM version string, so every log says which VIP and which UVM produced it. The UVM library provides `` `UVM_VERSION ``, the parameter `uvm_pkg::UVM_VERSION_STRING` and the "ladder" defines such as `` `UVM_VERSION_POST_2017 `` for conditional compilation (IEEE 1800.2-2020 Annex B.7.1 to B.7.3). Keep a changelog and a compatibility list of simulators, UVM versions and the protocol issue implemented (here IHI 0024C).
- **A user guide.** It states: the vif type and parameters; every configuration field with its default; the `uvm_config_db` field name (`"cfg"`) and where to set it; that a scalar `"is_active"` setting is ignored; the sequences and their knobs; the report IDs (`APB_SVA`, `APB_RST`, `NO_CFG`, `NO_VIF`); which protocol rules the assertions check; and known limitations (here: no `PSTRB`, no `PPROT`, one idle cycle between master transfers).

### Recap: the mistakes everyone makes

| Mistake | Why it is wrong | Fix |
|---|---|---|
| Interface assertions with `$error` | the UVM summary never counts them | `` `uvm_error `` with `%m`, interface imports `uvm_pkg` |
| "Passive" agent with an idle driver | the driver still owns bus outputs; at SoC level the bus has two drivers | build `drv` and `sqr` only when `get_is_active() == UVM_ACTIVE` |
| One `config_db` entry per knob | silent misses on typos and type mismatches | one configuration object, one typed `get`, fatal if missing |
| Monitor refills one object | every stored handle shows the last transfer | `type_id::create` per transfer |
| Reset kills the transfer without `item_done()` | the sequence hangs in `finish_item` | one `item_done()` per `get_next_item()` |
| Reactive sequence with an objection | the run phase never ends | start it in `fork ... join_none`, no objection |
| `set` and `get` with different vif parameters or modport | `get()` returns 0 silently | one typedef, used on both sides |

```systemverilog
// compile
// apb_vip_selftest.sv: needs uvm-core 2020.3.1 (uvm_pkg) compiled first.
`timescale 1ns/1ps
`include "uvm_macros.svh"

// ---------------------------------------------------------------- interface
interface apb_if #(int AW = 32, int DW = 32) (input logic pclk, input logic preset_n);
  import uvm_pkg::*;   // lets the assertions report with `uvm_error

  // Nets, not variables: the master side and the responder side each drive some of
  // them, and a clocking output on a net is a 'z driver until its first drive.
  wire          psel, penable, pwrite;
  wire [AW-1:0] paddr;
  wire [DW-1:0] pwdata, prdata;
  wire          pready, pslverr;

  bit checks_enable = 1'b1;   // written by apb_agent from apb_agent_config

  clocking drv_cb @(posedge pclk);   // master driver
    output psel, penable, pwrite, paddr, pwdata;
    input  pready, prdata, pslverr;
  endclocking

  clocking rsp_cb @(posedge pclk);   // responder driver
    output pready, prdata, pslverr;
    input  psel, penable, pwrite, paddr, pwdata;
  endclocking

  clocking mon_cb @(posedge pclk);   // monitor: samples everything, drives nothing
    input psel, penable, pwrite, paddr, pwdata, prdata, pready, pslverr, preset_n;
  endclocking

  // Signal-timing rules from Arm IHI 0024C (a subset). Reported through UVM so they
  // count in the report summary.
  a_setup_then_access: assert property (
    @(posedge pclk) disable iff (!preset_n || !checks_enable)
      (psel && !penable) |=> (psel && penable && $stable(paddr) && $stable(pwrite)
                              && (!pwrite || $stable(pwdata))))
    else `uvm_error("APB_SVA", $sformatf("%m: SETUP not followed by a stable ACCESS"))

  a_enable_after_setup: assert property (
    @(posedge pclk) disable iff (!preset_n || !checks_enable)
      $rose(penable) |-> $past(psel && !penable))
    else `uvm_error("APB_SVA", $sformatf("%m: PENABLE rose without a SETUP cycle"))

  a_wait_stable: assert property (
    @(posedge pclk) disable iff (!preset_n || !checks_enable)
      (psel && penable && !pready) |=> (psel && penable && $stable(paddr)
                                        && $stable(pwrite)
                                        && (!pwrite || $stable(pwdata))))
    else `uvm_error("APB_SVA", $sformatf("%m: transfer changed during a wait state"))

  a_enable_falls: assert property (
    @(posedge pclk) disable iff (!preset_n || !checks_enable)
      (psel && penable && pready) |=> !penable)
    else `uvm_error("APB_SVA", $sformatf("%m: PENABLE still high after completion"))
endinterface

// ---------------------------------------------------------------- the VIP
package apb_pkg;
  import uvm_pkg::*;

  parameter string APB_VIP_VERSION = "1.0.0";
  typedef virtual apb_if #(.AW(32), .DW(32)) apb_vif_t;
  typedef enum {APB_MASTER, APB_RESPONDER} apb_role_e;

  // The VIP's data API: request fields, then response fields.
  class apb_item extends uvm_sequence_item;
    `uvm_object_utils(apb_item)
    rand bit          write;
    rand bit [31:0]   addr;
    rand bit [31:0]   wdata;
    rand int unsigned wait_cycles;   // response: chosen by a responder, counted by mon
    rand bit [31:0]   rdata;
    rand bit          slverr;

    constraint c_aligned { addr[1:0] == 2'b00; }
    constraint c_waits   { wait_cycles <= 15; }

    function new(string name = "apb_item");
      super.new(name);
    endfunction

    virtual function void do_copy(uvm_object rhs);
      apb_item r;
      if (!$cast(r, rhs)) `uvm_fatal("APB_ITEM", "do_copy: rhs is not an apb_item")
      super.do_copy(rhs);
      write = r.write;  addr = r.addr;  wdata = r.wdata;
      wait_cycles = r.wait_cycles;  rdata = r.rdata;  slverr = r.slverr;
    endfunction

    // PWDATA means something only for writes, PRDATA only for reads.
    virtual function bit do_compare(uvm_object rhs, uvm_comparer comparer);
      apb_item r;
      if (!$cast(r, rhs)) return 0;
      return super.do_compare(rhs, comparer) && write == r.write && addr == r.addr
             && (!write || wdata == r.wdata) && (write || rdata == r.rdata)
             && slverr == r.slverr && wait_cycles == r.wait_cycles;
    endfunction

    virtual function string convert2string();
      return $sformatf("%s addr=%08h data=%08h waits=%0d slverr=%0b",
                       write ? "WR" : "RD", addr, write ? wdata : rdata,
                       wait_cycles, slverr);
    endfunction
  endclass

  class apb_agent_config extends uvm_object;
    `uvm_object_utils(apb_agent_config)
    apb_vif_t               vif;
    uvm_active_passive_enum is_active     = UVM_ACTIVE;
    apb_role_e              role          = APB_MASTER;
    bit                     has_coverage  = 1;
    bit                     checks_enable = 1;
    int unsigned            max_wait      = 3;    // responder: most wait states
    int unsigned            slverr_pct    = 10;   // responder: PSLVERR rate, 0..100

    function new(string name = "apb_agent_config");
      super.new(name);
    endfunction

    virtual function string convert2string();
      return $sformatf("%s %s coverage=%0b checks=%0b max_wait=%0d slverr_pct=%0d",
                       is_active.name(), role.name(), has_coverage, checks_enable,
                       max_wait, slverr_pct);
    endfunction
  endclass

  class apb_sequencer extends uvm_sequencer #(apb_item);
    `uvm_component_utils(apb_sequencer)
    apb_agent_config                   cfg;       // handed over by apb_agent
    uvm_tlm_analysis_fifo #(apb_item)  req_fifo;  // responder role: requests at SETUP

    function new(string name, uvm_component parent);
      super.new(name, parent);
      req_fifo = new("req_fifo", this);
    endfunction
  endclass

  // The reset recipe, written once for both roles.
  class apb_driver_base extends uvm_driver #(apb_item);
    `uvm_component_utils(apb_driver_base)
    apb_agent_config              cfg;       // handed over by apb_agent::build_phase
    apb_vif_t                     vif;
    uvm_analysis_port #(apb_item) done_ap;   // each completed item, as this driver saw it

    function new(string name, uvm_component parent);
      super.new(name, parent);
      done_ap = new("done_ap", this);
    endfunction

    function void build_phase(uvm_phase phase);
      super.build_phase(phase);
      vif = cfg.vif;   // the agent set cfg before this build_phase ran (top-down)
    endfunction

    task run_phase(uvm_phase phase);
      drive_idle();
      forever begin
        seq_item_port.get_next_item(req);
        wait (vif.preset_n === 1'b1);         // never start an item during reset
        fork
          begin : guard                       // keeps disable fork local
            fork
              drive_item(req);
              wait (vif.preset_n === 1'b0);   // reset asserted mid-item
            join_any
            disable fork;
          end
        join
        if (vif.preset_n !== 1'b1) begin
          drive_idle();                       // takes effect at the next clock edge
          `uvm_info("APB_RST", {"aborted by reset: ", req.convert2string()}, UVM_MEDIUM)
        end else begin
          apb_item done;
          $cast(done, req.clone());
          done_ap.write(done);
        end
        seq_item_port.item_done();            // exactly one per get_next_item
      end
    endtask

    virtual task drive_item(apb_item it);
    endtask

    virtual function void drive_idle();
    endfunction
  endclass

  class apb_master_driver extends apb_driver_base;
    `uvm_component_utils(apb_master_driver)

    function new(string name, uvm_component parent);
      super.new(name, parent);
    endfunction

    virtual function void drive_idle();
      vif.drv_cb.psel    <= 1'b0;
      vif.drv_cb.penable <= 1'b0;
    endfunction

    virtual task drive_item(apb_item it);
      @(vif.drv_cb);                          // start just after an edge
      vif.drv_cb.psel    <= 1'b1;             // SETUP: sampled at the next edge
      vif.drv_cb.penable <= 1'b0;
      vif.drv_cb.pwrite  <= it.write;
      vif.drv_cb.paddr   <= it.addr;
      if (it.write) vif.drv_cb.pwdata <= it.wdata;
      @(vif.drv_cb);                          // the SETUP edge
      vif.drv_cb.penable <= 1'b1;             // ACCESS
      @(vif.drv_cb);                          // first ACCESS edge
      it.wait_cycles = 0;
      while (vif.drv_cb.pready !== 1'b1) begin
        it.wait_cycles++;
        @(vif.drv_cb);
      end
      if (!it.write) it.rdata = vif.drv_cb.prdata;
      it.slverr = vif.drv_cb.pslverr;
      drive_idle();
    endtask
  endclass

  class apb_responder_driver extends apb_driver_base;
    `uvm_component_utils(apb_responder_driver)

    function new(string name, uvm_component parent);
      super.new(name, parent);
    endfunction

    virtual function void drive_idle();
      vif.rsp_cb.pready  <= 1'b0;   // low by default: a slow answer adds wait states
      vif.rsp_cb.pslverr <= 1'b0;   // recommended low when not sampled (IHI 0024C 3.4)
    endfunction

    // Called in the time step of the SETUP edge (see apb_reactive_seq).
    virtual task drive_item(apb_item it);
      repeat (it.wait_cycles) @(vif.rsp_cb);
      vif.rsp_cb.pready  <= 1'b1;
      vif.rsp_cb.pslverr <= it.slverr;
      if (!it.write) vif.rsp_cb.prdata <= it.rdata;
      @(vif.rsp_cb);                          // the completion edge
      drive_idle();
    endtask
  endclass

  class apb_monitor extends uvm_monitor;
    `uvm_component_utils(apb_monitor)
    apb_agent_config              cfg;
    apb_vif_t                     vif;
    uvm_analysis_port #(apb_item) ap;       // completed transfers
    uvm_analysis_port #(apb_item) req_ap;   // requests, at their SETUP edge

    function new(string name, uvm_component parent);
      super.new(name, parent);
      ap     = new("ap", this);
      req_ap = new("req_ap", this);
    endfunction

    function void build_phase(uvm_phase phase);
      super.build_phase(phase);
      vif = cfg.vif;
    endfunction

    task run_phase(uvm_phase phase);
      forever begin
        @(vif.mon_cb);
        if (vif.mon_cb.preset_n === 1'b1 && vif.mon_cb.psel === 1'b1
            && vif.mon_cb.penable === 1'b0)
          collect_transfer();
      end
    endtask

    protected task collect_transfer();
      apb_item rq, tr;
      rq = apb_item::type_id::create("rq");
      rq.write = vif.mon_cb.pwrite;
      rq.addr  = vif.mon_cb.paddr;
      rq.wdata = vif.mon_cb.pwdata;
      req_ap.write(rq);
      tr = apb_item::type_id::create("tr");   // a new object for every transfer
      tr.copy(rq);
      forever begin
        @(vif.mon_cb);
        if (vif.mon_cb.preset_n !== 1'b1) return;               // reset: discard
        if (vif.mon_cb.psel !== 1'b1 || vif.mon_cb.penable !== 1'b1) return;
        if (vif.mon_cb.pready === 1'b1) break;                  // completion edge
        tr.wait_cycles++;
      end
      if (!tr.write) tr.rdata = vif.mon_cb.prdata;
      tr.slverr = vif.mon_cb.pslverr;
      ap.write(tr);
    endtask
  endclass

    `uvm_component_utils(apb_coverage)
    apb_item tr;

    covergroup cg_apb;

      cp_waits: coverpoint tr.wait_cycles { bins none = {0}; bins one = {1};
                                            bins many = {[2:$]}; }

      super.new(name, parent);

    `uvm_component_utils(apb_agent)

  class apb_base_seq extends uvm_sequence #(apb_item);
    `uvm_object_utils(apb_base_seq)
    `uvm_declare_p_sequencer(apb_sequencer)

    function new(string name = "apb_base_seq");
      super.new(name);
    endfunction

    task apb_write(bit [31:0] addr, bit [31:0] data, output bit slverr);
      apb_item it = apb_item::type_id::create("it");
      start_item(it);
      if (!it.randomize() with { write == 1; addr == local::addr; wdata == data; })
        `uvm_fatal("RAND", "apb_write: randomization failed")
      finish_item(it);
      slverr = it.slverr;
    endtask

    task apb_read(bit [31:0] addr, output bit [31:0] data, output bit slverr);
      apb_item it = apb_item::type_id::create("it");
      start_item(it);
      if (!it.randomize() with { write == 0; addr == local::addr; })
        `uvm_fatal("RAND", "apb_read: randomization failed")
      finish_item(it);
      data   = it.rdata;
      slverr = it.slverr;
    endtask
  endclass

  class apb_rw_seq extends apb_base_seq;
    `uvm_object_utils(apb_rw_seq)
    rand int unsigned n_transfers;
    constraint c_n { n_transfers inside {[1:100]}; }

    function new(string name = "apb_rw_seq");
      super.new(name);
    endfunction

    task body();
      for (int i = 0; i < n_transfers; i++) begin
        apb_item it = apb_item::type_id::create($sformatf("it%0d", i));
        start_item(it);
        if (!it.randomize()) `uvm_fatal("RAND", "apb_rw_seq: randomization failed")
        finish_item(it);
      end
    endtask
  endclass

  class apb_reactive_seq extends apb_base_seq;
    `uvm_object_utils(apb_reactive_seq)

    function new(string name = "apb_reactive_seq");
      super.new(name);
    endfunction

    task body();
      apb_item obs, rsp;
      forever begin
        p_sequencer.req_fifo.get(obs);
        rsp = apb_item::type_id::create("rsp");
        start_item(rsp);
        rsp.write = obs.write;
        rsp.addr  = obs.addr;
        rsp.wdata = obs.wdata;
        rsp.c_aligned.constraint_mode(0);   // the DUT chose addr: do not re-check it
        if (!rsp.randomize(wait_cycles, rdata, slverr) with {
              wait_cycles <= p_sequencer.cfg.max_wait;
              slverr dist {1 := p_sequencer.cfg.slverr_pct,
                           0 := 100 - p_sequencer.cfg.slverr_pct};
            })
          `uvm_fatal("RAND", "apb_reactive_seq: randomization failed")
        finish_item(rsp);
      end
    endtask
  endclass

  class apb_selftest_sb extends uvm_component;
    `uvm_component_utils(apb_selftest_sb)
    uvm_tlm_analysis_fifo #(apb_item) exp_fifo;   // from master.drv.done_ap
    uvm_tlm_analysis_fifo #(apb_item) act_fifo;   // from observer.ap

      super.new(name, parent);

      act_fifo = new("act_fifo", this);

      forever begin
        exp_fifo.get(exp);
        act_fifo.get(act);

        else begin

      super.check_phase(phase);
      if (exp_fifo.used() != 0 || act_fifo.used() != 0)

                                         exp_fifo.used(), act_fifo.used()))
    endfunction

    function void report_phase(uvm_phase phase);
      super.report_phase(phase);
      `uvm_info("SELFTEST", $sformatf("transfers=%0d mismatches=%0d slverr=%0d",
                matches + mismatches, mismatches, slverrs), UVM_LOW)
    endfunction
  endclass
```

### How to build a VIP, step by step

1. **Write the interface** with nets for every signal, one clocking block per role (`drv_cb`, `rsp_cb`, `mon_cb`), the protocol assertions reporting with `` `uvm_error `` and `%m`, and a `checks_enable` bit in every `disable iff`.
2. **Declare the vif type once** in the package: `typedef virtual apb_if #(...) apb_vif_t;`.
3. **Write the item** with request fields, response fields, `do_copy`, `do_compare` and `convert2string`.
4. **Write the configuration object** with every knob and its default.
5. **Write the drivers** on a shared base class that owns the reset recipe: one `item_done()` per `get_next_item()`, drives only through clocking blocks.
6. **Write the monitor**: sample through `mon_cb`, create a new item per transfer, publish requests at SETUP on `req_ap` and completed transfers on `ap`, discard transfers cut by reset.
7. **Write the agent**: get `cfg` once, copy the mode, build `drv` and `sqr` only when active and `cov` only when asked, connect `mon.ap` to the agent's `ap`, apply `checks_enable`.
8. **Write the sequences**: a base sequence with helpers and `p_sequencer`, traffic sequences, and the reactive sequence.
9. **Write the self-test**: master, responder and passive observer on one interface, a scoreboard fed by the master's `done_ap` and the observer's `ap`, and an error-injection test that must fail with one `APB_SVA` error.
10. **Ship it**: package file, version parameter and banner, changelog, user guide.

### Debugging a VIP: symptom, cause, fix

| Symptom in the log | Likely cause | Fix |
|---|---|---|
| `UVM_FATAL ... [NO_CFG] no apb_agent_config named cfg for uvm_test_top.env.agt` | the test set `cfg` on another path, or after the agent's build | set it in the test's `build_phase`, on the agent's exact relative path; trace with `+UVM_CONFIG_DB_TRACE` (uvm-core) |
| `UVM_FATAL ... [NO_VIF]` in the test, although `tb_top` calls `set` | the `set` and `get` use different vif types (parameters or modport) | use `apb_vif_t` on both sides |
| A null-handle fatal at the first `vif.drv_cb` access | a component reads `vif` before anyone assigned it | the agent assigns `cfg` right after `create`, and children copy `cfg.vif` in their own `build_phase` |
| `UVM_FATAL ... [SEQ] neither the item's sequencer nor dedicated sequencer has been supplied to start item` | a sequence was started on `agt.sqr` of a passive agent (uvm-core message) | start stimulus only on active agents; check `print_topology` |
| The waveform shows a protocol violation, but the summary says `UVM_ERROR :    0` | the assertion reports with `$error`, or `checks_enable` is 0 | report with `` `uvm_error ``; check what wrote `checks_enable` |
| Every item the scoreboard stored shows the last transfer's values | the monitor reuses one object | `type_id::create` per transfer |
| The test hangs until the global timeout after a reset | the driver dropped an item without `item_done()`, or a reactive sequence holds an objection | one `item_done()` per item; start reactive sequences without an objection |
| `UVM_FATAL ... [SQRBADITMDN] Item_done() called with no outstanding requests` | the driver called `item_done()` for an item the environment already flushed with `stop_sequences()` (uvm-core message) | give the in-flight item one owner (Push Further) |
| X on `PSEL` and `PENABLE` at SoC level during transfers, and `print_topology` shows a `drv` in the "passive" agent | the agent ignored the passive setting (missing `is_active = cfg.is_active;`, or the test set the scalar `"is_active"` that this VIP ignores) | set `cfg.is_active`; fix the agent |
| `UVM_FATAL ... [SQRSNDREQCAST] send_request failed to cast sequence item` | a sequence sends an item type the sequencer does not accept (uvm-core message) | send the VIP's item type, or a subclass of it |

**Checklist before moving on:**
- [ ] The configuration object is the only place a test sets mode, role, coverage, checks and responder policy.
- [ ] `print_topology` shows the passive agent with `mon` (and `cov` if enabled) and no `drv` or `sqr`.
- [ ] Every driver drives only through its clocking block and calls `item_done()` exactly once per `get_next_item()`, also on reset.
- [ ] The monitor creates a new item per transfer and publishes nothing for a transfer cut by reset.
- [ ] The responder's wait states and errors come from a sequence, and that sequence holds no objection.
- [ ] Interface assertions report with `` `uvm_error `` and obey `checks_enable`.
- [ ] `tb_top` and the VIP use the same vif typedef.
- [ ] The self-test passes, and the error-injection test fails with exactly one `APB_SVA` error.

### Expert: Where interface-assertion messages go, and how to control them

`` `uvm_error `` expands to `` `uvm_report_begin `` with the default report object `uvm_get_report_object()` (uvm-core 2020.3.1 `src/macros/uvm_message_defines.svh`). Outside a class that is the package-level function, which returns `uvm_root` (IEEE 1800.2-2020 F.3.2.1), and the message is issued by the package-level `uvm_report_error` (F.3.2.3). Consequences a staff engineer is expected to know:
- **No instance path.** The message's source is `reporter`; put `%m` in the text, or the interface's instance name in the ID.
- **Component settings do not reach it.** `env.set_report_id_action("APB_SVA", ...)` changes nothing. Control the ID on `uvm_root::get()` (§6.3.5.2, §6.3.7), or with a report catcher, which sees every message the server issues (§6.6).
- **Expected errors.** An error-injection test that *wants* one violation should demote or catch exactly that ID and count it, rather than turn all checks off, so that an unexpected second violation still fails. The full strategy for expected errors is environment scope (planned A-UVM-9).
- **Assertion control semantics** (IEEE 1800-2023 §20.11): `$assertoff` is `$assertcontrol` with control type 4 (Off): no new attempts start, while attempts in flight and their action blocks continue. `$assertkill` (5) also aborts attempts in flight. `$assertfailoff` stops only fail action blocks. A `disable iff` condition, by contrast, disables attempts in flight as soon as it becomes true, and a disabled attempt runs no action block (§16.14.1).
- **Tool-dependent:** some simulators can be configured to count assertion failures or `$error` calls in their exit status. Never rely on that for UVM pass or fail; the report summary is the contract.

### Expert: A UVM-free interface that still counts

Importing `uvm_pkg` into the interface ties it to UVM, and some teams share one interface between UVM benches, formal and non-UVM benches. That is why some lessons and vendors keep `$error` in the interface. The fix is to move the *reporting*, not the *checking*: the action block records the failure in the interface, and a UVM component reports it.

```systemverilog
// snippet: inside a UVM-free apb_if
int unsigned sva_fails;   // read by the monitor through the vif
a_wait_stable: assert property (/* as before */)
  else begin sva_fails++; $error("%m: transfer changed during a wait state"); end

// snippet: in apb_monitor; check_phase runs after the run phase
function void check_phase(uvm_phase phase);
  super.check_phase(phase);
  if (vif.sva_fails != 0)
    `uvm_error("APB_SVA", $sformatf("%0d interface assertion failure(s), see the log",
                                    vif.sva_fails))
endfunction
```

The trade-off: the UVM error arrives at the end of the run, not at the failure time, and several monitors on one interface would report the same count, so only one should. This is a methodology pattern, not a standard clause.

### Expert: Parameterized VIPs and the virtual-interface type

When a VIP must support several widths, the type rules of IEEE 1800-2023 §25.9 drive the design. Three designs are in use:
1. **Parameters through every class.** `class apb_agent #(int AW = 32, int DW = 32) extends uvm_agent;` with `` `uvm_component_param_utils(apb_agent #(AW, DW)) `` and `typedef virtual apb_if #(AW, DW) vif_t;` inside. The param macros register no type name with the factory, so name-based lookup is impossible (IEEE 1800.2-2020 B.2.1.3): `+uvm_set_type_override` (G.2.7), which is name-based, cannot target these classes, and overrides must be by type (§8.2.3.2.5, §8.3.1.4.2). Every specialization is a separate type, and the parameters spread into items, sequences and tests.
2. **One maximum-width interface.** The interface and every class use the widest width; the configuration carries the used width, and the monitor masks unused bits. One type, no parameter plumbing, at the cost of checks that must know the used width.
3. **An abstract bus-functional API.** The package declares an abstract class with tasks such as `drive_setup()` and `wait_ready()`; the parameterized interface contains a class that implements it, and hands a handle to the VIP through the configuration. Classes see only the abstract handle, so they need no virtual-interface type at all. This is a methodology pattern (sometimes called a polymorphic interface), not a standard clause; its cost is an extra layer that is harder to debug.

The standard's own §25.9 example shows the trap: a virtual-interface declaration with default parameter values that no instance uses is legal, but nothing can be assigned to it.

### Expert: Nets or variables in a multi-role interface

The same interface serves a master driver, a responder driver and a passive monitor, so who drives each signal changes with the role. A `logic` **variable** may have one continuous driver, and a port connection counts as one, and it may not mix continuous and procedural writes (IEEE 1800-2023 §6.5). A clocking block's output is a synchronous drive, so a `logic` signal that the DUT drives through a port and a clocking block also lists as an output is a conflict. Whether a simulator reports it at elaboration when the clocking output is never written is tool-dependent.

On a **net** (`wire`), each clocking-block output creates its own driver that is `'z` until the first synchronous drive (§14.16), so the unused role's driver never interferes. That is why the Make It Work interface uses `wire`, and why contention at SoC level shows up as X: two drivers on one net. For observation-only hookups, use one-way continuous assignments from RTL into the interface, or `bind` an interface instance into the RTL (§23.11) and pass the signals through its ports, because an interface that contains hierarchical references cannot be used for a virtual interface (§25.9).

### Expert: Who owns the in-flight item at reset

This lesson keeps reset handling inside the agent: the driver aborts, releases the item with `item_done()`, idles and waits. Environments often add a second reaction: on reset, a test or virtual sequence calls `sqr.stop_sequences()`, which kills the sequences on the sequencer and removes all queued requests, locks and responses (IEEE 1800.2-2020 §15.3.2.14). Both react to the same reset edge, so their order is a race. In uvm-core 2020.3.1, `stop_sequences()` empties the request FIFO, and a later `item_done()` from the driver finds no outstanding request and ends the run with `UVM_FATAL [SQRBADITMDN] Item_done() called with no outstanding requests` (`src/seq/uvm_sequencer.svh`).

The rule is **one owner for the in-flight item**. Either the driver releases it and nothing else flushes, as in this lesson, or the environment flushes and the driver must not call `item_done()` for a flushed item (for example, it waits for the environment's "flushed" event and skips the release). A driver that uses `get()` instead of `get_next_item()` completes the handshake inside `get()` (§14.2.6.3 NOTE), so it has nothing to release, at the price of not being able to return a response through the same item. Scoreboard flushing, objections across reset and phase jumps are environment strategy, for the planned A-UVM-9 module.

### Expert: Configuration API design

- **One object or scalar knobs** is the misconception discussed earlier; the staff-level answer adds that objects nest. An env configuration can hold one agent configuration per agent, and the env sets each on its agent's path, so a test configures a whole subsystem with one object ([A-UVM-8](/curriculum/T3_Advanced/A-UVM-8_Multi_Agent_Topologies/index)).
- **Source of truth for the mode.** Copying `cfg.is_active` into uvm-core's `is_active` member works but relies on an implementation member and silently ignores the standard `"is_active"` setting. Overriding the virtual `get_is_active()` to return `cfg.is_active` is portable (§13.4.2.2 says the agent developer may override it). Whichever you choose, write the precedence in the user guide.
- **Validate early.** Check the configuration in the agent's `build_phase` (null vif, `slverr_pct` above 100, a responder role on a passive agent) and stop with a clear fatal. A wrong setting found at time 0 costs seconds; found after an hour of simulation it costs the hour.
- **Debug aids** (uvm-core 2020.3.1, not in IEEE 1800.2-2020): `+UVM_CONFIG_DB_TRACE` logs every `set` and `get`, and `check_config_usage()` lists settings nobody read, which catches path typos.

### Expert: Versioning and release qualification

`` `UVM_VERSION ``, `uvm_pkg::UVM_VERSION_STRING` and the `` `UVM_VERSION_POST_2017 `` ladder are required by IEEE 1800.2-2020 Annex B.7.1 to B.7.3. uvm-core 2020.3.1 defines `` `UVM_VERSION `` as 2020, ladder defines up to `` `UVM_VERSION_POST_2020_2_0 ``, and `UVM_VERSION_STRING` as `"Accellera:1800.2:UVM:2020.3.1"` (`src/base/uvm_version.svh`, `src/macros/uvm_version_defines.svh`). A VIP that must also build against an older library guards the differences with these defines.

A release qualification regression, run on every supported simulator and UVM version, contains at least:
- the loopback self-test with many seeds;
- one error-injection test per assertion, each expecting exactly its own ID once, so that a check that silently stopped firing fails the release;
- closure of the VIP's own covergroups;
- a `print_topology` golden file per configuration (active master, active responder, passive), compared textually (F.7.4.2).

### Expert: Evaluating a third-party VIP

A staff-level evaluation, before the purchase order:
- **Protocol:** which issue of the specification, which optional features, and which rules the checkers cover.
- **Virtual-interface type:** parameters and modports, and whether its interface can be connected to your DUT ports and to internal RTL for passive use.
- **Configuration API:** objects or scalar settings, field names, paths and defaults, and what happens on a missing setting (fatal, or silent defaults?).
- **Items and sequences:** item type and its fields, base sequences and helpers, response handling, and how you add your own sequences (the item type must match, see above).
- **Extension points:** callbacks and factory-overridable components, documented by hook and order ([A-UVM-5](/curriculum/T3_Advanced/A-UVM-5_UVM_Callbacks/index)).
- **Reporting:** report IDs, and whether its checkers report through UVM. A VIP whose assertions use `$error` will pass your regression with violations.
- **Coverage:** its model, and the cost of sampling it on every passive instance.
- **Debug visibility:** encrypted source, transaction recording, waveform access.
- **Support matrix and evidence:** simulators, UVM versions, and its own self-test results.
- **Licensing in CI:** a checkout failure must fail as an infrastructure error.

### Expert: Passive VIPs at SoC scale

At SoC level one environment may hold dozens of passive VIP instances. Their cost grows with the number of objects created per transfer, analysis fan-out (every `write` calls every subscriber in turn), covergroup sampling, transaction recording and assertion attempts. Gate each one from the configuration (`has_coverage`, `checks_enable`, recording), do configuration lookups once in `build_phase`, and measure before optimizing; the numbers depend on the simulator and the design ([E-PERF-1](/curriculum/T4_Expert/E-PERF-1_UVM_Performance/index)). This section gives no figures because none were measured for this lesson.

### Kata: make an `$error` interface assertion count

Start from this interface fragment, used by a UVM test whose driver violates the wait-state rule once.

```systemverilog
// snippet: the starting point
interface simple_apb_if (input logic pclk, input logic preset_n);
  wire psel, penable, pready;
  wire [31:0] paddr;

  a_wait_stable: assert property (
    @(posedge pclk) disable iff (!preset_n)
      (psel && penable && !pready) |=> $stable(paddr))
    else $error("PADDR changed during a wait state");
endinterface
```

1. Predict the report summary's `UVM_ERROR` count and what else the log shows.
2. Change the interface so the failure is counted as a UVM error with the ID `APB_SVA` and the interface's instance name in the message.
3. Add an enable bit that a VIP agent can set from its configuration object, and predict the summary when the error-injection test clears it.
4. Explain why clearing the bit is a poor way to write an error-injection test.

<details>
<summary>Worked solution</summary>

1. `UVM_ERROR :    0`. The log also has one simulator-format error line from `$error`, which a summary-only regression ignores.
2. and 3.

```systemverilog
// snippet: the fixed interface
`include "uvm_macros.svh"
interface simple_apb_if (input logic pclk, input logic preset_n);
  import uvm_pkg::*;                  // uvm_report_error and friends for the macro
  wire psel, penable, pready;
  wire [31:0] paddr;
  bit checks_enable = 1'b1;           // the agent writes cfg.checks_enable here

  a_wait_stable: assert property (
    @(posedge pclk) disable iff (!preset_n || !checks_enable)
      (psel && penable && !pready) |=> $stable(paddr))
    else `uvm_error("APB_SVA", $sformatf("%m: PADDR changed during a wait state"))
endinterface
```

   With the bit set: `UVM_ERROR :    1`, and the message reads `reporter [APB_SVA] <instance path>...: PADDR changed during a wait state`. With the bit cleared: the attempt is disabled, no action block runs (IEEE 1800-2023 §16.14.1), and the summary shows `UVM_ERROR :    0`.
4. With the bit cleared, the test passes even if the injected violation never happened, or if a *different* violation happened too. A better error test keeps checks on and demotes or catches exactly the expected `APB_SVA` message on `uvm_root`, counting it, so it can also fail when the count is wrong. The enable bit is for tests that break the protocol on purpose in ways too varied to count.

</details>

### Debug challenge: the SoC run with X on PSEL

A SoC test reuses the block team's `apb_agent` on an internal APB bus with `cfg.is_active = UVM_PASSIVE`. On the interface's nets the run shows X on `PSEL` and `PENABLE` whenever the SoC's bridge starts a transfer, and the SoC scoreboard misses transfers. This is part of the agent you were given:

```systemverilog
// snippet: the given agent's build_phase
function void build_phase(uvm_phase phase);
  super.build_phase(phase);
  if (!uvm_config_db#(apb_agent_config)::get(this, "", "cfg", cfg))
    `uvm_fatal("NO_CFG", "no cfg")
  mon = apb_monitor::type_id::create("mon", this);
  mon.cfg = cfg;
  if (get_is_active() == UVM_ACTIVE) begin
    sqr = apb_sequencer::type_id::create("sqr", this);
    sqr.cfg = cfg;
    drv = apb_master_driver::type_id::create("drv", this);
    drv.cfg = cfg;
  end
endfunction
```

1. What would `print_topology` show under the agent, and why?
2. Why X, rather than a wrong but known value?
3. Give two fixes, one in the agent and one in the test, and say which one the VIP's user guide should require.

<details>
<summary>Answers</summary>

1. `drv`, `mon` and `sqr`. The agent never copies `cfg.is_active`, so `is_active` keeps its default `UVM_ACTIVE` (no scalar `"is_active"` setting exists either), and `get_is_active()` returns `UVM_ACTIVE`.
2. The interface signals are nets. The driver's clocking-block outputs drive `PSEL` and `PENABLE` low from its first `drive_idle()` (no sequence ever runs on it), while the one-way assigns drive the bridge's values. While both sides drive 0 the net is 0; when the bridge drives 1 against the driver's 0, two strong drivers with different values resolve to X (IEEE 1800-2023 §6.5, §14.16). The monitor then never sees `PSEL === 1`, so it publishes nothing and the scoreboard misses transfers. `PWRITE`, `PADDR` and `PWDATA` stay correct, because the idle driver never drove them and their clocking drivers are still `'z`.
3. In the agent, add `is_active = cfg.is_active;` after `super.build_phase(phase)`, or override `get_is_active()` to return `cfg.is_active`. In the test, a scalar `uvm_config_db#(uvm_active_passive_enum)::set(this, "env.uart_apb", "is_active", UVM_PASSIVE)` would also work with this broken agent, but it would be ignored by the fixed one. The user guide should name one source of truth, the configuration object, and the agent should implement it.

</details>
