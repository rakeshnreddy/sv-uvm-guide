## Quick Take

- **What it is:** An AHB **verification environment** is the testbench (TB) code around an AHB design under test (DUT) that answers two questions for every transfer: was it legal, and was it right? It has five parts. A **master driver** and a **slave responder** produce traffic with every legal timing (wait states, BUSY cycles, ERROR responses). A **monitor** watches the pins and turns each completed transfer into a transaction object. A **protocol checker**, written as SystemVerilog Assertions (SVA), judges every clock edge against Arm IHI0033B.b. A **coverage model** records which planned situations actually happened, and a **scoreboard** checks that the data is correct.
- **Why it matters:** AHB bugs live in the pipeline: in wait states, BUSY cycles and the two-cycle ERROR response. A checker that fires on legal behaviour (a master cancelling after an ERROR) gets switched off by the team, and one that misses a one-cycle ERROR gives false confidence. An environment that passes because nothing was checked, or because its assertion messages never reach the UVM report summary, is worse than no environment.
- **The Analogy:** A railway station. The clerk (monitor) pairs each ticket (address phase) with the passenger who actually boards later (data phase), however long the platform delay (wait states). A signal box (checker) checks every signal against the rulebook, a census taker (coverage) counts which kinds of journeys happened, and the luggage office (scoreboard) checks that every bag reached the right place. *Where it breaks:* the signal box sees only the track, the pins. A slave that writes the same data twice inside its memory during a wait state breaks no rule on the pins (the double-write pitfall of [B-AHB-2](/curriculum/T3_Advanced/B-AHB-2_AHB_Pitfalls_and_Deadlocks/index)), so only a scoreboard or a white-box check can see it. And AHB has no ticket numbers: the clerk must work out which data belongs to which address from timing alone.

**You will be able to:**
1. **Write** an AHB transaction item and a passive monitor that pairs each accepted address phase with its (possibly waited) data phase, flushes on reset, and **predict** the edge at which each transfer is published.
2. **Write** a protocol checker whose assertions accept every legal transfer (wait-state exceptions, BUSY, cancel after ERROR) and flag illegal ones (one-cycle ERROR, address or write data not held, 1KB crossing, misalignment), each tagged **[Protocol §x]** or **[Integration policy]**, and that reports through UVM.
3. **Write** a coverage model over transfer type × burst × size × wait states × response, mapped to verification-plan items, and **show** that each assertion's antecedent was exercised.
4. **Choose** what the checker, the scoreboard and the coverage each own, and **design** a byte-lane scoreboard for an AHB slave (and outline the interconnect version).
5. **Debug** an AHB failure from the waveform and the log with the HREADY trace, the transaction-boundary finder, ERROR forensics and a latency budget, and **configure** the stimulus (random wait states, BUSY, error injection) that provokes it.

## Build Your Mental Model

### Words you need first

Terms from earlier lessons are linked; the AHB terms are used exactly as Arm IHI0033B.b (the AMBA 5 AHB specification) uses them, and section numbers on this page are IHI0033B.b numbers. The later issue IHI0033C (2021) says *manager* and *subordinate* for master and slave and renumbers chapter 3 from §3.5 onwards; the section map is in [B-AHB-1](/curriculum/T3_Advanced/B-AHB-1_AHB_Design_Timing_Mechanics/index).

- **Transfer, address phase, data phase:** one AHB read or write. In its **address phase** the master drives the address and control signals (HADDR, HWRITE, HSIZE, HBURST, HTRANS); in its **data phase** the data moves (HWDATA or HRDATA) and the slave answers on HREADY and HRESP. The next transfer's address phase overlaps the current data phase (IHI0033B.b §3.1); that overlap is the **pipeline**.
- **Accepted:** an address phase is accepted at a rising edge of HCLK where HREADY is high and HTRANS is NONSEQ or SEQ. Until then it is only *on the bus*.
- **Wait state:** a cycle in which the slave holds HREADY low, so the current data phase does not end, and the address phase waiting behind it is not accepted (§3.6).
- **HREADYOUT and HREADY:** each slave drives its own HREADYOUT; the interconnect's **multiplexor** picks the one belonging to the slave that owns the current data phase and sends it to the master and to every slave as HREADY (§4.3). The **decoder** turns the address into one select, HSELx, per slave (§4.2).
- **IDLE, BUSY, NONSEQ, SEQ:** the four HTRANS values (§3.2 Table 3-1). NONSEQ starts a transfer or a burst, SEQ is a later beat of a burst, BUSY is a pause inside a burst, IDLE means no transfer. Only NONSEQ and SEQ move data (HTRANS[1] = 1).
- **Beat, burst:** a burst is a sequence of transfers (beats) with related addresses, described by HBURST: SINGLE, INCR (undefined length), INCR4/8/16 and WRAP4/8/16 (§3.5).
- **Agent, driver, sequencer, active and passive:** a UVM **agent** groups the components for one interface. Its **driver** turns sequence items into pin activity, its **sequencer** passes items from running sequences to the driver, and its monitor watches the pins. An **active** agent has all three; a **passive** agent has only the monitor ([I-UVM-2A](/curriculum/T2_Intermediate/I-UVM-2A_Component_Roles/index), [I-UVM-3A](/curriculum/T2_Intermediate/I-UVM-3A_Fundamentals/index)).
- **Monitor, analysis port:** a UVM monitor is a passive component that only watches pins; it publishes each transaction through an **analysis port**, which calls `write()` on every connected subscriber ([I-UVM-2B](/curriculum/T2_Intermediate/I-UVM-2B_TLM_Connections/index)).
- **Subscriber, scoreboard, reference model:** a `uvm_subscriber` is a component with one analysis export, `analysis_export`, whose `write()` receives every published item (IEEE 1800.2-2020 §13.9). A **scoreboard** checks the DUT's data against a **reference model**, code that computes what the DUT should have done ([A-UVM-6](/curriculum/T3_Advanced/A-UVM-6_Scoreboards_and_Reference_Models/index)).
- **Concurrent assertion, antecedent, vacuous success:** an SVA property such as `a |=> b` is checked at every clock edge; `a` is the **antecedent**. When the antecedent is false, the attempt succeeds **vacuously**: it passes without checking anything (IEEE 1800-2023 §16.14.8; [I-SV-4A](/curriculum/T2_Intermediate/I-SV-4A_SVA_Fundamentals/index)).
- **bind:** a statement that instantiates a checker module inside a design module without editing the design's source (IEEE 1800-2023 §23.11; [I-SV-4C](/curriculum/T2_Intermediate/I-SV-4C_Checkers/index)).
- **Clocking block:** a block in an interface that samples inputs just before a clock edge and drives outputs just after it, so the TB and the DUT never race ([F4C](/curriculum/T1_Foundational/F4C_Clocking_Blocks/index)).
- **Verification plan (vplan):** the list of features and situations that must be shown to work, each mapped to a check and a coverage item ([I-SV-3A](/curriculum/T2_Intermediate/I-SV-3A_Functional_Coverage_Fundamentals/index)).
- **Responder:** a slave-side TB component that answers transfers (wait states, OKAY or ERROR, read data) instead of starting them.

Each layer owns one question, and no two layers own the same one:

| Concern | Checker | Monitor | Scoreboard | Coverage |
|---|---|---|---|---|
| Hold rules in wait states, the two-cycle ERROR, zero-wait OKAY for IDLE and BUSY | **owns** (pin-level protocol) | — | — | covers that each situation happened |
| SEQ address and control continuity, alignment, the 1KB rule, HSIZE within the bus | **owns** | — | — | covers bursts, sizes, 1KB distance |
| Turning pins into transfers (which data belongs to which address) | — | **owns**, with no judgement | — | — |
| Data correctness: the right bytes come back from the right address | — | — | **owns** | — |
| Routing through an interconnect, default-slave ERROR for unmapped addresses (§4.2.1), order of completion per interface | — | — | **owns** | covers the routes and responses |
| Which planned situations ran | — | — | — | **owns** |

**Misconception: "the checker and the scoreboard both own data ordering, so each double-checks the other."** They do not. The checker owns **pin-level protocol legality** (including multi-cycle rules such as hold-in-wait and the ERROR pair) and never data correctness; it cannot know what data *should* be at an address. The scoreboard owns **which data belongs to which transfer** and where each transfer went; it never re-checks pin timing. If both owned a rule, a failure would be reported twice with two different messages, and a fix to one would leave the other silently out of date. Each AHB interface has at most one data phase in flight and completes transfers in the order it accepts them (§3.1), so ordering on a single interface is a pin-level fact the monitor relies on; ordering *across* an interconnect is the scoreboard's job.

**Debrief of the prediction:** the scoreboard reports the wrong read data; the checker stays silent, because no pin rule was broken.

### Transactions: beat items and burst items

The **transaction item** is the object the monitor publishes. This page publishes one item per **beat** (one NONSEQ or SEQ transfer), because the scoreboard checks data beat by beat; coverage of whole bursts reads the burst fields of each beat.

```systemverilog
// snippet: the item's fields (the full class is in Make It Work)
typedef enum logic [1:0] {IDLE, BUSY, NONSEQ, SEQ} htrans_e;                  // Table 3-1
typedef enum logic [2:0] {SINGLE, INCR, WRAP4, INCR4,
                          WRAP8, INCR8, WRAP16, INCR16} hburst_e;            // Table 3-3

class ahb_item extends uvm_sequence_item;
  rand logic [31:0] addr;         // address phase, sampled at the accepting edge
  rand logic        write;
  rand logic [2:0]  size;         // HSIZE: 2**size bytes
  rand hburst_e     burst;
  htrans_e          trans;        // NONSEQ (first beat) or SEQ (later beat)
  logic [31:0]      data;         // HWDATA or HRDATA at the completing edge
  logic             resp;         // HRESP at the completing edge: 0 OKAY, 1 ERROR
  int unsigned      waits;        // HREADY-low edges in the data phase
  int unsigned      beat_index;   // 0 for NONSEQ, then +1 per SEQ
  int unsigned      busy_before;  // BUSY cycles (at HREADY-high edges) just before this beat

  constraint c_legal {
    (8 << size) <= 32;                     // §3.4: no wider than this 32-bit bus
    (addr & ((32'd1 << size) - 1)) == 0;   // §3.5: every transfer is aligned
  }
  // ... constructor, convert2string and `uvm_object_utils in Make It Work
endclass
```

Three choices in this class matter:

- **Sampled fields are 4-state (`logic`).** A 2-state `bit` turns an X on HRDATA into 0, so a scoreboard compare with `!==` can never see the X. With `logic`, an undriven read data bus fails the compare.
- **Stimulus fields are constrained.** The same item can drive an active master. Without `c_legal`, `randomize()` produces unaligned or oversized transfers, which the checker would reject. The 1KB rule is a *burst* constraint (no beat of an incrementing burst may leave the first beat's 1KB block, §3.5), so it belongs in the burst sequence, not in a beat.
- **Beat versus burst.** Per-beat items suit the scoreboard; per-burst items suit burst coverage and a burst-level predictor. A monitor can publish both through two analysis ports. Here the beat item carries `beat_index` and `busy_before`, which is enough for this page's coverage.

Here is how one INCR4 write with a BUSY cycle and one wait state becomes four beat items. Read the Monitor action column with the definitions above: *accept* means the address phase is accepted, *publish* means the transfer completes and its item goes out; the monitor rule that produces these actions is taught step by step in the next subsection. The values come from the Make It Work run, where edge k is the rising edge at 10k − 5 ns (edges 7 to 13 are 65 to 125 ns); `pending` is the item the monitor holds between the accepting edge and the completing edge.

| Edge | HTRANS, HADDR on the bus | HREADY | Monitor action |
|---|---|---|---|
| 7 | NONSEQ 0x10 (INCR4) | 1 | accept: new item, `beat_index` = 0 |
| 8 | SEQ 0x14 | 1 | publish beat 0; accept beat 1 |
| 9 | SEQ 0x18 | 1 | publish beat 1; accept beat 2 |
| 10 | BUSY 0x1C | 0 | wait: beat 2 `waits` = 1; the BUSY is not accepted |
| 11 | BUSY 0x1C | 1 | publish beat 2 (`waits` = 1); the BUSY's address phase ends here, but it is not a transfer: the monitor only notes one BUSY before the next beat |
| 12 | SEQ 0x1C | 1 | accept beat 3 with `busy_before` = 1 (the BUSY noted at edge 11) |
| 13 | NONSEQ 0x01 | 1 | publish beat 3; accept the next transfer |

Four beat items, one burst: the BUSY cycles produce no item, and the waited edge produces no item either.

### The pipelined monitor

A **passive monitor** never drives a pin. Its whole job is the pairing rule from [B-AHB-1](/curriculum/T3_Advanced/B-AHB-1_AHB_Design_Timing_Mechanics/index):

1. **Accept** an address phase at an edge where HREADY is high and HTRANS is NONSEQ or SEQ (§4.2: a slave samples address and control only when HREADY is high). Store it as the pending item.
2. **Count** each later edge with HREADY low as a wait state of the pending item. The first ERROR cycle is one of them.
3. **Complete** the pending item at the next edge with HREADY high: take HWDATA (write) or HRDATA (read) and HRESP at that edge (§3.1, §6.1.1, §6.1.2), publish it, and only then accept the next address phase at the same edge.
4. **Flush** on reset: a transfer that reset cuts off never completes (§7.1.2), so drop it.

**Predict before you look at the picture:** write A is accepted at edge 1, the slave holds HREADY low at edge 2 and high at edge 3, and B is already on the bus at edges 2 and 3. At which edge does the monitor publish A, and with which HWDATA?

| Edge | HTRANS, HADDR | HREADY | Pending before | Monitor action | Pending after |

| 0 | IDLE | 1 | none | nothing to accept | none |

The core of the monitor loop, sampling through the clocking block `mon_cb`:

```systemverilog
// snippet: ahb_mon run_phase core (full class in Make It Work)
forever begin
  @(vif.mon_cb);                                   // values sampled at this edge
  if (!vif.mon_cb.HRESETn) begin pending = null; continue; end   // 4. flush
  if (pending != null) begin
    if (vif.mon_cb.HREADY === 1'b1) begin          // 3. data phase ends here
      pending.data = pending.write ? vif.mon_cb.HWDATA : vif.mon_cb.HRDATA;
      pending.resp = vif.mon_cb.HRESP;
      ap.write(pending);
      pending = null;
    end else pending.waits++;                      // 2. a wait state
  end
  if (vif.mon_cb.HREADY === 1'b1 && vif.mon_cb.HTRANS[1] === 1'b1) begin
    pending = ahb_item::type_id::create("tr");     // 1. accepted at this same edge
    pending.addr = vif.mon_cb.HADDR;               // ... and the other address fields
  end
end
```

**Pitfalls, each with why it is wrong:**

- **Pairing the address and data of one transfer at the same edge** (the misconception "the monitor can sample address and data on the same edge"). At one edge the monitor *does* sample two things: the data of the transfer that completes there and the address of the transfer accepted there. They belong to *different* transfers. Taking A's data at A's accepting edge records the previous transfer's HWDATA.
- **Accepting during a wait.** Capturing NONSEQ B at edge 2 produces a duplicate of B at edge 3, and a transfer cancelled after an ERROR (which was never accepted) appears as if it had happened.
- **2-state sampled fields** hide X (see the item above).
- **Raw `@(posedge vif.HCLK)` reads** are correct only while every driver of those signals uses nonblocking assignments. The clocking block samples just before the edge (`#1step`, IEEE 1800-2023 §14.13), so the result never depends on process order.
- **No reset flush.** During reset every slave drives HREADYOUT high (§7.1.2), so a monitor without a flush "completes" the cut-off transfer at a reset edge where HREADY is high (the first one, for an asynchronously reset slave such as `ahb_sram_slave`) with reset-time data, and the scoreboard reports a false mismatch (see [Reset behaviour](#reset-behaviour)).

### The protocol checker

The checker is a module of concurrent assertions. Each property is tagged:
- **[Protocol §x]**: a rule in IHI0033B.b. A failure means a master or slave broke the specification.
- **[Integration policy]**: a budget your system chooses. A slow but legal slave must never be reported as a protocol violation.
- **[Simulation check]**: the X check. Real wires are never X, so this is not a rule of the specification, but an X on HTRANS, HREADY or HRESP in simulation makes every antecedent that uses that signal false, and those properties then pass vacuously (IEEE 1800-2023 §16.6: x, z and 0 are false).

The per-pitfall derivation of each property is in [B-AHB-2](/curriculum/T3_Advanced/B-AHB-2_AHB_Pitfalls_and_Deadlocks/index); here they are assembled into one reusable module, with four additions (the X checks, HWDATA hold, HSIZE within the bus, and a reset check that respects the component's minimum reset time) and UVM reporting.

```systemverilog
// snippet: the two properties that most often go wrong (full module in Make It Work)
// [Protocol §3.6.1, §3.6.2, §3.5.2; Table 2-2 and §3.4 for HWRITE and HSIZE]
// A waited NONSEQ/SEQ is held, unless the master cancels after the first ERROR cycle.
property p_hold_in_wait;
  @(posedge HCLK) disable iff (!HRESETn)
    (!HREADY && HTRANS inside {NONSEQ, SEQ}) |=>
        ($stable(HTRANS) && $stable(HADDR) && $stable({HWRITE, HSIZE, HBURST}))
     || ($past(HRESP) && HTRANS == IDLE);
endproperty

// [Protocol §5.1.3, Table 5-2] an ERROR completion needs its first cycle.
// This is the property that catches a one-cycle ERROR.
property p_error_second_needs_first;
  @(posedge HCLK) disable iff (!HRESETn)
    (HRESP && HREADY) |-> $past(HRESP && !HREADY);
endproperty
```

**Why these forms and not simpler ones:**

- **`p_hold_in_wait`** replaces a plain `$stable(HTRANS)`, which fires on legal behaviour. A waited NONSEQ or SEQ must not change (§3.6.1, §3.6.2), except that a master cancelling after the first ERROR cycle drives IDLE and may change the address (§3.5.2, §3.6.2). A waited IDLE may become NONSEQ, and a waited BUSY may become SEQ (or, in an undefined-length INCR, IDLE or NONSEQ) (§3.6.1), so IDLE and BUSY never start this property; BUSY has its own, `p_busy_in_wait`.
- **Misconception: "HTRANS must be stable through every wait state."** Only a waited NONSEQ or SEQ is held, and even that one may become IDLE in the second ERROR cycle. Writing the naive rule produces false failures on the legal traffic of §3.6.1 Figures 3-13 to 3-15 and on every cancel after ERROR.
- **`p_error_second_needs_first`** is the only one of the two ERROR properties that sees a slave driving ERROR for a single cycle with HREADY high. The forward property, `p_error_first_then_second`, needs HREADY low to start, so on that bug it never starts an attempt and passes vacuously.
- **`$past(expr, 1, beat_accepted)`** in the SEQ checks returns the value at the most recent earlier edge where a beat was accepted (IEEE 1800-2023 §16.9.3), which is the previous beat even if BUSY cycles or wait states came between.
- **The 1KB check runs per beat**, with WRAP bursts exempt. A start-address formula fires on legal WRAP bursts and cannot size an undefined-length INCR. The rule itself is taught in [B-AHB-1](/curriculum/T3_Advanced/B-AHB-1_AHB_Design_Timing_Mechanics/index).

**Three predictions:**
1. **BUSY in a burst.** Keep one BUSY cycle and set *Wait states on A0* to 2. Which property fails: `p_busy_in_wait` or `p_ctrl_stable (old)`, the naive "nothing changes in a wait state" check?
2. **Two-cycle ERROR.** With the master set to *cancels*, what is on HTRANS in the second ERROR cycle, and does `p_hold_in_wait` fail?
3. **Debug: one-cycle ERROR.** Which of the two ERROR properties fails?

**Debrief:**
1. The waited BUSY changes to SEQ while HREADY is still low. That is legal for a fixed-length burst (§3.6.1, Figure 3-14). `p_ctrl_stable (old)` fails on it; `p_busy_in_wait` passes, and it is not vacuous: its antecedent, a waited BUSY, actually occurred.
2. IDLE: the master saw ERROR with HREADY low and cancels the transfer waiting on the address bus (§3.5.2, §5.1.3). `p_hold_in_wait` passes through its cancel exception; the naive check fails.
3. Only `p_error_second_needs_first`. `p_error_first_then_second` never starts, which is why a checker needs both directions.

**Attaching the checker to the design.** Three ways, from most to least common:
- **`bind`** it into the DUT module, as Make It Work does: `bind ahb_sram_slave ahb_protocol_checker u_chk (.HCLK, .HRESETn, ...);`. The port expressions are resolved inside the target module, so the checker reads the slave's own ports and the RTL source is never touched (IEEE 1800-2023 §23.11).
- **Instantiate** it in `tb_top` on the interface signals.
- **Write it as an interface or a `checker`.** A module can be bound into a module but not into an interface: when the bind target is an interface, the bound instance must be an interface or a checker (§23.11, footnote 4 to Syntax 23-9).

**Reporting through UVM.** An action block such as `else $error("...")` reports through the simulator, not through the UVM report server, so the UVM summary can say `UVM_ERROR :    0` while the log is full of assertion failures ([A-UVM-7](/curriculum/T3_Advanced/A-UVM-7_VIP_Construction/index) teaches this in detail; pass/fail rules are in [I-UVM-1D](/curriculum/T2_Intermediate/I-UVM-1D_Reporting_and_Run_Control/index)). This page's checker imports `uvm_pkg` and reports with `` `uvm_error ``, which a module may call: outside a class the macro calls the global reporting functions, which report through `uvm_root` (IEEE 1800.2-2020 F.3.2). Each assertion has a label (`a_hold_in_wait:`), so `$assertoff` and `$assertcontrol` can name it (IEEE 1800-2023 §20.11), and messages print `$sampled(HADDR)`, not `HADDR`: action blocks run in the Reactive region ([F3B](/curriculum/T1_Foundational/F3B_Scheduling_Regions/index)) and would otherwise print the *current* value, which at an edge with HREADY high is already the next beat's address (§16.9.3, the `a1_bad`/`a2_ok` example).

**Vacuity.** In simulation an assertion checks only the traffic that ran. A property whose antecedent never happened has checked nothing, and its "no failures" proves nothing. Each important antecedent therefore gets a `cover property` (§16.14.3), shown in [The coverage model](#the-coverage-model).

### The coverage model

**Functional coverage** records which situations the tests actually produced, so you know which assertions and which scoreboard compares were really exercised. It does not prove anything about traffic that did not run. Coverage lives in two places:

- **Pin level, in the checker:** `cover property` statements on assertion antecedents and on short sequences such as "cancel after ERROR", plus a small covergroup on HTRANS × HREADY. These see cycles, which no transaction item records.
- **Transaction level, in a `uvm_subscriber`:** a covergroup sampled once per published item, over direction, size, burst, beat position, wait states, response, BUSY before a beat and the distance to the next 1KB boundary.

Every coverage item maps to a vplan line:

| Vplan item | Coverage item | Where | Hit by the Make It Work run? |
|---|---|---|---|
| Every burst type in both directions | `cx_write_burst` (direction × burst) | `ahb_cov` | SINGLE and INCR4 only |
| Every legal size in every burst type; no size wider than the bus | `cx_burst_size`; `illegal_bins wider_than_bus` on `cp_size` (IEEE 1800-2023 §19.5.6) | `ahb_cov` | 3 of 24 legal cells |
| Wait states on each burst type: 0, 1, 2–4, 5–16, more than 16 | `cx_waits_burst` | `ahb_cov` | 0 and 1 |
| ERROR on a first beat and on a later beat, per burst type | `cx_resp_burst_beat`, with `ignore_bins` for SEQ beats of a SINGLE (§19.6.1) | `ahb_cov` | ERROR on a SINGLE |
| BUSY before a beat: none, one, several | `cp_busy_before` (SEQ beats only) | `ahb_cov` | none, one |
| Incrementing burst starting near, mid-way or far from a 1KB boundary | `cp_kb_room`: bytes to the next 1KB boundary, 1–16, 17–64, 65–1024 | `ahb_cov` | far only |
| A waited NONSEQ/SEQ (antecedent of `a_hold_in_wait`) | `c_waited_nonseq_seq` | checker | yes (edges 16 and 20) |
| A waited BUSY (antecedent of `a_busy_in_wait`) | `c_waited_busy` | checker | yes (edge 10) |
| A waited write (antecedent of `a_hwdata_hold`) | `c_waited_write` | checker | yes (edges 10 and 20) |
| Master cancels after ERROR, and master continues after ERROR | `c_error_cancel`, `c_error_continue` | checker | cancel only |
| Reset while a data phase is open; first transfer after reset | `c_reset_in_data_phase`, `c_first_after_reset` | checker | first-after-reset only |
| Every HTRANS value with and without a wait state | `htrans_cov.cx_trans_waited` | checker | 8 of 8 cells |

The last column is the honest report of one directed test: most of the plan is still open. The mid-test reset and the continuing master are holes a reset test ([A-UVM-9](/curriculum/T3_Advanced/A-UVM-9_Reset_and_Error_Injection/index)) and a second master configuration must fill.

The "cancel after ERROR" cover property, shaded on the ERROR forensics waveform in the [debug patterns](#debug-patterns) below, needs care: it must name a clock, and it must require a NONSEQ or SEQ on the bus in the first ERROR cycle, or it also matches when IDLE was already on the bus and nothing was cancelled.

```systemverilog
// snippet: from ahb_protocol_checker (full module in Make It Work)
c_error_cancel: cover property (@(posedge HCLK) disable iff (!HRESETn)
  (HRESP && !HREADY && HTRANS inside {NONSEQ, SEQ}) ##1
  (HRESP && HREADY && HTRANS == IDLE));
c_error_continue: cover property (@(posedge HCLK) disable iff (!HRESETn)
  (HRESP && !HREADY && HTRANS inside {NONSEQ, SEQ}) ##1
  (HRESP && HREADY && HTRANS inside {NONSEQ, SEQ}));
```

**Pitfalls:** sampling a pin-level covergroup on every clock edge, when the plan item means "accepted beats" (gate it with `iff`, or sample per item); reading 100% on a cross and assuming the related assertion ran (cover its antecedent); and a covergroup declared but never constructed (an embedded covergroup is created with `new` in the class constructor, IEEE 1800-2023 §19.4).

### The scoreboard

The **scoreboard** checks data. For a memory-like slave its **reference model** is a memory of expected bytes: each completed OKAY write updates it, each completed OKAY read is compared with it.

IHI0033B.b defines no write strobes (none in Table 2-2): the active byte lanes come from HADDR and HSIZE. On a little-endian bus, a byte at address `a` travels on lane `a mod (bus bytes)` (§6.2.1), and a wider transfer puts its least significant byte at the transfer address and increasingly significant bytes at increasing addresses. So the model stores **bytes**, and a byte write at 0x1001 is visible to a later word read at 0x1000. (IHI0033C later adds optional write strobes, HWSTRB; see [B-AHB-1](/curriculum/T3_Advanced/B-AHB-1_AHB_Design_Timing_Mechanics/index).)

| HWDATA bits | [31:24] | [23:16] | [15:8] | [7:0] |
|---|---|---|---|---|
| Byte lane (little-endian, 32-bit bus) | 3 | 2 | 1 | 0 |
| Address offset (`addr mod 4`) | 3 | 2 | 1 | 0 |

Traced example on an empty model:

| Step | Transfer | Lanes used | Model after | Result |
|---|---|---|---|---|
| 1 | write byte 0xAB to 0x1001 (HSIZE = 0, HWDATA = 0x0000AB00) | lane 1 = HWDATA[15:8] | `mem_model[0x1001]` = 0xAB | write counted |
| 2 | read word 0x1000, HRDATA = 0x1122AB44 | lanes 0–3 | unchanged | byte 0x1001 matches (0xAB); bytes 0x1000, 0x1002 and 0x1003 were never written, so the read is **unchecked** (counted as pending, with a warning) |

Three rules make the scoreboard trustworthy:

- **Error policy.** A read that completes with ERROR carries no valid data (§6.1.2), so it is not compared. What a slave does with a write that gets ERROR is not fixed by the protocol: this scoreboard forgets those bytes. If your slave guarantees "no write on ERROR", check that instead.
- **End-of-test accounting.** An analysis port with nothing connected drops every item silently (its `write()` loops over zero subscribers), and the test then passes with zero checks. `check_phase` therefore fails the test when no read was compared, and `report_phase` prints `SCB_SUMMARY matches=N mismatches=0 pending=0` ([A-UVM-6](/curriculum/T3_Advanced/A-UVM-6_Scoreboards_and_Reference_Models/index) covers end-of-test accounting).
- **Reset policy.** Registers in the DUT return to their reset values; memory contents may or may not survive, as the DUT specification says. The model must do the same on reset, or the first reads after reset mismatch.

**The interconnect version (outline).** For an interconnect DUT, put a monitor on every master port and every slave port. The scoreboard predicts each slave-port transfer from the master-port transfer through the address map: same address, direction, size and data, appearing on the slave the decoder selects. An unmapped NONSEQ or SEQ must get ERROR from the default slave, and IDLE or BUSY to an unmapped address a zero-wait OKAY (§4.2.1). Each interface completes in the order it accepts (§3.1), so match per interface in order, and across interfaces by address and master.

### Stimulus side: master driver and slave responder

The checker can only judge traffic that happens, so the stimulus must produce every legal timing. Which side the TB plays depends on the DUT: for a **slave DUT** the TB is the master (it chooses HTRANS, bursts and BUSY), and wait states and ERROR come from the DUT; for a **master DUT** the TB is a slave **responder** that chooses wait states and ERROR responses; an interconnect needs both.

| Side | Knob | Legal range and rule |
|---|---|---|
| Master | IDLE cycles between transfers | 0 (fully pipelined) to many; IDLE gets a zero-wait OKAY (Table 3-1) |
| Master | Back-to-back pipelining | the next address phase during the current data phase (§3.1) |
| Master | BUSY insertion | only inside a burst: between beats, or, in an undefined-length INCR only, as its last cycle before an IDLE or NONSEQ; never after a SINGLE; a fixed-length burst ends with SEQ, not BUSY (§3.5.1, Table 3-1) |
| Master | Changes during a wait | IDLE may become NONSEQ; BUSY may become SEQ (in INCR also IDLE or NONSEQ); a waited NONSEQ/SEQ is held (§3.6.1, §3.6.2) |
| Master | After an ERROR | cancel (IDLE in the second ERROR cycle) or continue the burst; both legal (§3.5.2) |
| Master | Write data | held valid until the transfer completes (§6.1.1) |
| Slave | Random wait states | any number, OKAY during each, up to the slave's predetermined maximum; at most 16 recommended (§5.1.2) |
| Slave | Error injection | two-cycle ERROR: HREADYOUT low with HRESP high, then both high; OKAY waits may come first (§5.1.3) |
| Slave | IDLE and BUSY | always a zero-wait OKAY (Table 3-1) |
| Slave | Reset | HREADYOUT high during reset (§7.1.2) |

The `ahb_master_bfm` in Make It Work exercises the master knobs: back-to-back transfers, a BUSY inside an INCR4, and a cancel after ERROR. For the slave side, here is a responder agent with random wait states and error injection, the application of the responder pattern from [A-UVM-7](/curriculum/T3_Advanced/A-UVM-7_VIP_Construction/index) (the AXI counterpart is in [B-AXI-6](/curriculum/T3_Advanced/B-AXI-6_AXI_Verification_Performance/index)).

```systemverilog
// snippet: responder item, sequence and driver. The agent's sequencer is a plain
// uvm_sequencer #(ahb_rsp_item) named rsp_sqr. The slave-side interface ahb_slv_if has
// a clocking block rsp_cb with inputs HSEL, HTRANS, HREADY and outputs HREADYOUT, HRESP.
class ahb_rsp_item extends uvm_sequence_item;
  `uvm_object_utils(ahb_rsp_item)
  rand int unsigned waits;   // OKAY wait states before the response
  rand bit          error;   // answer with the two-cycle ERROR
  int unsigned      max_wait  = 15;   // this slave's predetermined maximum (§5.1.2)
  int unsigned      error_pct = 5;    // error-injection rate; both copied from the sequence
  constraint c_waits { waits <= max_wait;
                       waits dist {0 :/ 60, [1:3] :/ 30, [4:max_wait] :/ 10}; }
  constraint c_error { error dist {1 := error_pct, 0 := 100 - error_pct}; }
  function new(string name = "ahb_rsp_item"); super.new(name); endfunction
endclass

class ahb_rsp_seq extends uvm_sequence #(ahb_rsp_item);
  `uvm_object_utils(ahb_rsp_seq)
  int unsigned max_wait  = 15;                     // knobs: the test sets them before start()
  int unsigned error_pct = 5;
  function new(string name = "ahb_rsp_seq"); super.new(name); endfunction
  task body();
    forever begin                                  // one response per transfer
      req = ahb_rsp_item::type_id::create("req");
      start_item(req);
      req.max_wait  = max_wait;                    // the item's constraints read these
      req.error_pct = error_pct;
      if (!req.randomize()) `uvm_fatal("RAND", "ahb_rsp_item randomization failed")
      finish_item(req);
    end
  endtask
endclass

class ahb_slv_drv extends uvm_driver #(ahb_rsp_item);
  `uvm_component_utils(ahb_slv_drv)
  virtual ahb_slv_if vif;                          // fetched in build_phase (not shown)
  function new(string name, uvm_component parent); super.new(name, parent); endfunction
  task run_phase(uvm_phase phase);
    vif.rsp_cb.HREADYOUT <= 1'b1;                  // ready by default, from the first rsp_cb edge (§14.16);
                                                   // a real responder drives it high from reset (§7.1.2)
    vif.rsp_cb.HRESP     <= 1'b0;
    forever begin
      seq_item_port.get_next_item(req);            // chosen before the transfer arrives
      // The accepting edge may be the edge that ended the previous transfer
      // (=== so that X before the first edge never looks like an accepted transfer)
      while (!(vif.rsp_cb.HSEL === 1'b1 && vif.rsp_cb.HREADY === 1'b1 &&
               vif.rsp_cb.HTRANS[1] === 1'b1))
        @(vif.rsp_cb);
      repeat (req.waits) begin                     // OKAY wait states (§5.1.2)
        vif.rsp_cb.HREADYOUT <= 1'b0;
        vif.rsp_cb.HRESP     <= 1'b0;
        @(vif.rsp_cb);
      end
      if (req.error) begin                         // two-cycle ERROR (§5.1.3)
        vif.rsp_cb.HREADYOUT <= 1'b0;
        vif.rsp_cb.HRESP     <= 1'b1;
        @(vif.rsp_cb);
        vif.rsp_cb.HRESP     <= 1'b1;
      end
      vif.rsp_cb.HREADYOUT <= 1'b1;                // last cycle of the data phase
      if (!req.error) vif.rsp_cb.HRESP <= 1'b0;
      @(vif.rsp_cb);                               // edge m: the transfer completes
      vif.rsp_cb.HRESP <= 1'b0;                    // IDLE/BUSY next: zero-wait OKAY
      seq_item_port.item_done();
    end
  endtask
endclass
```

**Debrief:** in the time step of edge k itself. In the picture, the drives to `vif.rsp_cb` (steps 6 to 8) follow the edge-k divider with no clock wait before the first of them; for an ERROR with no OKAY waits, step 7 is that first drive. The clocking-block drive takes effect at that edge (IEEE 1800-2023 §14.16), so the cycle sampled at edge k + 1 is the first ERROR cycle. A driver that waits for edge k + 1 to look at the address leaves HREADYOUT high in the first data-phase cycle, and the transfer completes with OKAY at k + 1: too late.

The test configures the responder and starts it. The sequence never ends, so it must not hold an objection: start it in a `fork ... join_none` and let the test's own traffic hold the objection, or the run phase never ends ([A-UVM-7](/curriculum/T3_Advanced/A-UVM-7_VIP_Construction/index) explains the pitfall).

```systemverilog
// snippet: in the test's run_phase, for a master DUT (rsp_agt is the slave-side responder agent)
ahb_rsp_seq rsp_seq = ahb_rsp_seq::type_id::create("rsp_seq");
rsp_seq.max_wait  = 4;                    // short waits for this test
rsp_seq.error_pct = 20;                   // error-injection test
fork rsp_seq.start(env.rsp_agt.rsp_sqr); join_none   // no objection: it runs forever
```

A master-side BFM or sequence exposes BUSY the same way: a knob such as a BUSY percentage per beat, read where the burst is built.

This responder chooses waits and errors **before** it sees the address, which is enough for random wait states and error injection. A responder that must decide from the address (an ERROR for a read-only register, read data from a memory model) is **reactive**: its monitor writes the address phase into a `uvm_tlm_analysis_fifo` in the sequencer, and the sequence reads it, decides and sends the response. All of that must finish in the time step of edge k, so it may not consume time; read data is then driven on HRDATA from the driver's memory model. A reset-aware version of this driver releases its item and drives HREADYOUT high when HRESETn falls ([A-UVM-9](/curriculum/T3_Advanced/A-UVM-9_Reset_and_Error_Injection/index)).

### Reset behaviour

Reset (HRESETn, the only active-low AHB signal) can be asserted asynchronously, but is released synchronously after a rising edge of HCLK (§7.1.2). During reset every master drives IDLE with address and control at valid levels, and every slave drives HREADYOUT high. Each component defines how many reset cycles it needs before its outputs reach those values.

What each layer does about it:

- **Monitor:** drop the pending item while HRESETn is low, and accept nothing (`continue` in the loop above).
- **Checker:** `disable iff (!HRESETn)` stops every attempt in flight when reset is asserted: an attempt that started at edge 2 (for example `a_hwdata_hold`, if A is a write) neither passes nor fails. The reset-value check is the one property without `disable iff`, and it is checked only after the component's minimum number of reset edges (`MIN_RESET_CYCLES`), because before that a slave with a synchronous reset may legally show X on HREADYOUT (§7.1.2), and X is false (IEEE 1800-2023 §16.6).
- **Scoreboard:** apply the DUT's reset policy to the model (registers back to reset values; memory kept or cleared as specified).
- **Driver:** drive IDLE during reset and restart after release.
- **Coverage:** `c_reset_in_data_phase` (reset while a transfer is open) and `c_first_after_reset`.

1. Find the edge where HRESP and HREADY are both high: the ERROR completes there (edge 4). The edge before must be HRESP high with HREADY low; if it is not, `a_error_second_needs_first` has already named a slave bug.
2. Walk back over the data phase (the first ERROR cycle and any OKAY waits before it) to the last edge with HREADY high where a NONSEQ or SEQ was accepted (edge 1). That transfer, A, failed. In the monitor log it is the item with `resp` = ERROR; with OKAY waits before the ERROR it is more than two cycles back.
3. Check the address map: is A's address mapped? An unmapped NONSEQ or SEQ gets ERROR from the default slave (§4.2.1). Which slave was selected at edge 1?
4. Check whether the access is legal for that slave: direction (a write to a read-only location is the specification's own example, §5.1.3), size, and HPROT (privileged or user, data or opcode, §3.7). This page's item does not record HPROT, so read it from the waveform, or add a `prot` field to the item and the monitor.
5. Check what the master did next: cancel (IDLE in the second ERROR cycle, as here) or continue; both are legal (§3.5.2). The scoreboard's error policy decides what happens to A's data.

**4. The latency budget (the "starvation detector").** IHI0033B.b defines no request or grant signals on a master (Table 2-2): arbitration between masters happens inside an interconnect, which the specification leaves out of scope (§4.1). So there is no "grant" to sort a waveform by. Instead, in a multi-master system with a multi-layer interconnect, put a monitor on each **master port** and measure, for every transfer, the cycles from the edge where its NONSEQ is first on that port to the edge where it **completes** there (the end of its data phase, HREADY high at that port). Counting only to acceptance would miss the usual case: a NONSEQ after an IDLE is always accepted at once, because the IDLE's data phase must be a zero-wait OKAY (Table 3-1), so an interconnect that makes this master wait can only do it in the data phase. Report the worst case against a per-master budget, tagged **[Integration policy]**: no AHB rule bounds it. A master whose latency grows without bound while others are served is starved. Remember that a locked sequence (HMASTLOCK) must be processed before any other transfer (§3.3), so a budget must allow for the longest legal locked sequence.

The measurement fits in a few lines beside the checker at each master port. It notes the edge where a NONSEQ or SEQ first appears, carries that edge into the data phase when the address is accepted, and compares at completion:

```systemverilog
// snippet: [Integration policy] latency at one master port (beside the checker,
// same port names; LAT_BUDGET is a parameter chosen per master)
longint unsigned edge_n;        // rising edges since reset
longint unsigned first_seen;    // edge where the waiting NONSEQ/SEQ first appeared
longint unsigned dp_start;      // first appearance of the transfer in its data phase
bit              addr_waiting;  // a NONSEQ/SEQ is on the bus but not accepted yet
bit              dp_open;       // a NONSEQ/SEQ transfer is in its data phase

// plain always, not always_ff: functions called from always_ff may not write variables
// that other processes write (IEEE 1800-2023 §9.2.2.4), and the UVM report call does
always @(posedge HCLK or negedge HRESETn)
  if (!HRESETn) begin
    edge_n <= 0; addr_waiting <= 0; dp_open <= 0;
  end else begin
    edge_n <= edge_n + 1;
    if (HREADY) begin                                 // the open data phase ends here
      if (dp_open && edge_n - dp_start > LAT_BUDGET)
        `uvm_warning("AHB_POLICY", $sformatf("%m: latency %0d > budget %0d",
                                             edge_n - dp_start, LAT_BUDGET))
      dp_open      <= HTRANS[1];                      // accepted now: its data phase opens
      dp_start     <= addr_waiting ? first_seen : edge_n;
      addr_waiting <= 0;
    end else if (!HTRANS[1]) addr_waiting <= 0;       // IDLE or BUSY (or a cancel)
    else if (!addr_waiting) begin                     // first waited edge of this address
      addr_waiting <= 1;
      first_seen   <= edge_n;
    end
  end
```

On the figure above: at edge 1, `dp_start` becomes 1; at edge 5, `edge_n - dp_start` = 4, which is compared with `LAT_BUDGET`. Each `ahb_item` already records its `waits`, so a master-port monitor can report the same number per transfer. **Pitfall:** a budget measured at the *slave* port misses the time a transfer spent waiting at the master port for the interconnect, which is exactly where starvation shows.

## Make It Work

### The complete bench, file by file

The bench verifies `ahb_sram_slave`, a 256-word AHB-Lite SRAM that inserts one OKAY wait state on every 4th accepted transfer and answers addresses at or above 0x400 with ERROR. `ahb_master_bfm` runs a fixed plan: a SINGLE write, an INCR4 write with a BUSY cycle, a byte write, an INCR4 read, an ERROR write, and a read that the master cancels and re-issues after the ERROR. **2. The DUT** (`ahb_sram_slave.sv`):

```systemverilog
// compile (part of the bench)
`timescale 1ns/1ps
module ahb_sram_slave #(parameter int DEPTH = 256) (   // DEPTH 32-bit words
  input  logic        HCLK,
  input  logic        HRESETn,
  input  logic        HSEL,
  input  logic [31:0] HADDR,
  input  logic [1:0]  HTRANS,
  input  logic        HWRITE,
  input  logic [2:0]  HSIZE,
  input  logic [2:0]  HBURST,
  input  logic [31:0] HWDATA,
  input  logic        HREADY,      // multiplexed: the previous transfer has ended
  output logic        HREADYOUT,
  output logic        HRESP,
  output logic [31:0] HRDATA
);
  localparam int AW = $clog2(DEPTH);
  typedef enum logic [1:0] {S_OKAY, S_ERR1, S_ERR2} resp_e;

  logic [31:0] mem [DEPTH];
  logic [31:0] addr_reg;      // address of the transfer in its data phase
  logic [3:0]  lanes_reg;     // its byte lanes (§6.2.1)
  logic        wr_reg;        // it is a write to a mapped address
  logic        waiting;       // this cycle is an inserted OKAY wait state
  logic [1:0]  cnt;           // accepted transfers, modulo 4
  resp_e       rstate;

  // A NONSEQ/SEQ is accepted at an edge with HSEL and HREADY high (§4.2)
  wire accept = HSEL && HREADY && HTRANS[1];
  wire bad    = accept && (HADDR >= DEPTH * 4);    // unmapped: answer with ERROR

  function automatic logic [3:0] lanes(logic [1:0] a, logic [2:0] sz);
    case (sz)
      3'd0:    return 4'b0001 << a;
      3'd1:    return 4'b0011 << {a[1], 1'b0};
      default: return 4'b1111;
    endcase
  endfunction

  always_ff @(posedge HCLK or negedge HRESETn) begin
    if (!HRESETn) begin
      addr_reg <= '0;  lanes_reg <= '0;  wr_reg <= 1'b0;
      waiting  <= 1'b0; cnt <= '0;
      rstate   <= S_OKAY; HRESP <= 1'b0;
    end else begin
      // The data phase ends at an edge with HREADY high: write once, never per wait
      if (HREADY && wr_reg)
        for (int i = 0; i < 4; i++)
          if (lanes_reg[i]) mem[addr_reg[AW+1:2]][8*i +: 8] <= HWDATA[8*i +: 8];
      if (HREADY) begin                       // register the next data phase
        addr_reg  <= HADDR;
        lanes_reg <= lanes(HADDR[1:0], HSIZE);
        wr_reg    <= accept && HWRITE && !bad;
      end
      // One OKAY wait state on every 4th accepted transfer
      waiting <= accept && (cnt == 2'd3);
      if (accept) cnt <= cnt + 2'd1;
      // Two-cycle ERROR (§5.1.3): HREADYOUT low, then high; HRESP high in both cycles
      case (rstate)
        S_OKAY: if (bad) begin rstate <= S_ERR1; HRESP <= 1'b1; end
        S_ERR1: rstate <= S_ERR2;             // HRESP stays high
        S_ERR2: if (bad) rstate <= S_ERR1;    // the ERROR completes at this edge
                else begin rstate <= S_OKAY; HRESP <= 1'b0; end
        default: begin rstate <= S_OKAY; HRESP <= 1'b0; end
      endcase
    end
  end

  assign HREADYOUT = !waiting && (rstate != S_ERR1);   // high during reset (§7.1.2)
  assign HRDATA    = mem[addr_reg[AW+1:2]];
endmodule
```

**3. The master BFM** (`ahb_master_bfm.sv`). It is a module, not a UVM agent, to keep the example short; it drives only through `mst_cb`.

```systemverilog
// compile (part of the bench)
`timescale 1ns/1ps
module ahb_master_bfm (ahb_if bus);
  localparam logic [1:0] IDLE = 2'b00, BUSY = 2'b01, NONSEQ = 2'b10, SEQ = 2'b11;
  localparam logic [2:0] SINGLE = 3'b000, INCR4 = 3'b011;
  localparam logic [2:0] BYTE = 3'd0, WORD = 3'd2;

  typedef struct {
    logic [1:0]  trans;
    logic [31:0] addr;
    logic        write;
    logic [2:0]  size;
    logic [2:0]  burst;
    logic [31:0] wdata;
  } step_t;
  step_t plan[$];

  function automatic void add(logic [1:0] trans, logic [31:0] addr, logic write,
                              logic [2:0] size, logic [2:0] burst,
                              logic [31:0] wdata = '0);
    plan.push_back('{trans, addr, write, size, burst, wdata});
  endfunction

  task automatic drive_addr(step_t s);
    bus.mst_cb.HTRANS <= s.trans;
    bus.mst_cb.HADDR  <= s.addr;
    bus.mst_cb.HWRITE <= s.write;
    bus.mst_cb.HSIZE  <= s.size;
    bus.mst_cb.HBURST <= s.burst;
  endtask

  // Back to back: the next address phase overlaps the current data phase (§3.1)
  task automatic run_plan();
    int unsigned i = 0;                       // plan[i] is on the address bus
    drive_addr(plan[0]);
    while (i < plan.size()) begin
      @(bus.mst_cb);
      if (bus.mst_cb.HREADY === 1'b1) begin
        // plan[i] is accepted here; a write's data goes out for its data phase
        if (plan[i].trans != BUSY && plan[i].write) bus.mst_cb.HWDATA <= plan[i].wdata;
        i++;
        if (i < plan.size()) drive_addr(plan[i]);
        else                 bus.mst_cb.HTRANS <= IDLE;
      end else if (bus.mst_cb.HRESP === 1'b1) begin
        // First ERROR cycle: cancel what waits on the address bus by driving IDLE in
        // the second ERROR cycle (§3.5.2), and drop the rest of a burst.
        bus.mst_cb.HTRANS <= IDLE;
        while (i < plan.size() && plan[i].trans != NONSEQ) i++;
        do @(bus.mst_cb); while (bus.mst_cb.HREADY !== 1'b1);
        if (i < plan.size()) drive_addr(plan[i]);   // re-issue: this BFM's policy
      end
      // otherwise an OKAY wait state: hold everything (§3.6, §6.1.1)
    end
    do @(bus.mst_cb); while (bus.mst_cb.HREADY !== 1'b1);   // last data phase ends
  endtask

  initial begin
    bus.mst_cb.HTRANS <= IDLE;                // IDLE during reset (§7.1.2)
    bus.mst_cb.HADDR  <= '0;
    bus.mst_cb.HWRITE <= 1'b0;
    bus.mst_cb.HSIZE  <= WORD;
    bus.mst_cb.HBURST <= SINGLE;
    bus.mst_cb.HWDATA <= '0;
    add(NONSEQ, 32'h000, 1, WORD, SINGLE, 32'hA000_0000);
    add(NONSEQ, 32'h010, 1, WORD, INCR4,  32'hB000_0010);
    add(SEQ,    32'h014, 1, WORD, INCR4,  32'hB000_0014);
    add(SEQ,    32'h018, 1, WORD, INCR4,  32'hB000_0018);
    add(BUSY,   32'h01C, 1, WORD, INCR4);              // BUSY carries the next address
    add(SEQ,    32'h01C, 1, WORD, INCR4,  32'hB000_001C);
    add(NONSEQ, 32'h001, 1, BYTE, SINGLE, 32'h0000_AB00);  // byte lane 1
    add(NONSEQ, 32'h010, 0, WORD, INCR4);
    add(SEQ,    32'h014, 0, WORD, INCR4);
    add(SEQ,    32'h018, 0, WORD, INCR4);
    add(SEQ,    32'h01C, 0, WORD, INCR4);
    add(NONSEQ, 32'h400, 1, WORD, SINGLE, 32'hDEAD_BEEF);  // unmapped: ERROR
    add(NONSEQ, 32'h000, 0, WORD, SINGLE);   // cancelled in the ERROR, then re-issued
    do @(bus.mst_cb); while (bus.mst_cb.HRESETn !== 1'b1);
    run_plan();
    bus.bfm_done <= 1'b1;
  end
endmodule
```

**4. The protocol checker** (`ahb_protocol_checker.sv`):

```systemverilog
// compile (part of the bench)
`timescale 1ns/1ps
`include "uvm_macros.svh"

module ahb_protocol_checker #(
  parameter int DATA_W           = 32,   // HWDATA width in bits
  parameter int MAX_WAIT         = 16,   // [Integration policy] wait-state budget
  parameter int MIN_RESET_CYCLES = 1     // from the slave's documentation (§7.1.2)
) (
  input logic              HCLK,
  input logic              HRESETn,
  input logic [31:0]       HADDR,
  input logic [1:0]        HTRANS,
  input logic [2:0]        HBURST,
  input logic [2:0]        HSIZE,
  input logic              HWRITE,
  input logic [DATA_W-1:0] HWDATA,
  input logic              HREADY,
  input logic              HRESP
);
  import uvm_pkg::*;     // so the action blocks can report with `uvm_error

  localparam logic [1:0] IDLE = 2'b00, BUSY = 2'b01, NONSEQ = 2'b10, SEQ = 2'b11;
  localparam logic [2:0] SINGLE = 3'b000, INCR = 3'b001,
                         WRAP4 = 3'b010, WRAP8 = 3'b100, WRAP16 = 3'b110;
  localparam int BYTES = DATA_W / 8;

  // A beat's address phase is accepted at an edge where this is true
  wire beat_accepted = HREADY && (HTRANS inside {NONSEQ, SEQ});

  // Data-phase bookkeeping, updated only at edges with HREADY high
  logic              dp_active;    // a NONSEQ/SEQ is in its data phase
  logic              dp_write;     // ... and it is a write
  logic [DATA_W-1:0] dp_bits;      // its active byte lanes, as a bit mask

  function automatic logic [DATA_W-1:0] lane_bits(logic [31:0] addr, logic [2:0] size);
    int unsigned first = addr % BYTES;           // lane of the first byte (§6.2.1)
    lane_bits = '0;
    for (int unsigned b = 0; b < (32'd1 << size) && first + b < BYTES; b++)
      lane_bits[8*(first + b) +: 8] = 8'hFF;
  endfunction

  always_ff @(posedge HCLK or negedge HRESETn)
    if (!HRESETn) begin
      dp_active <= 1'b0;
      dp_write  <= 1'b0;
      dp_bits   <= '0;
    end else if (HREADY) begin
      dp_active <= beat_accepted;
      dp_write  <= beat_accepted && HWRITE;
      dp_bits   <= lane_bits(HADDR, HSIZE);
    end

  // Reset edges already seen in the current reset
  int unsigned rst_edges;
  always_ff @(posedge HCLK)
    rst_edges <= HRESETn ? 0 : (rst_edges < MIN_RESET_CYCLES ? rst_edges + 1 : rst_edges);

  // ---- [Simulation check] X falsifies every antecedent that uses it: catch it first ----
  a_no_x_ctrl: assert property (@(posedge HCLK) disable iff (!HRESETn)
    !$isunknown({HTRANS, HREADY, HRESP}))
    else `uvm_error("AHB_CHK", $sformatf("%m: X/Z on HTRANS, HREADY or HRESP"))
  a_no_x_addr: assert property (@(posedge HCLK) disable iff (!HRESETn)
    HTRANS[1] |-> !$isunknown({HADDR, HWRITE, HSIZE, HBURST}))
    else `uvm_error("AHB_CHK", $sformatf("%m: X/Z on address or control of a transfer"))

  // ---- Wait states: hold, with the specification's exceptions ----
  // [Protocol §3.6.1, §3.6.2, §3.5.2; Table 2-2, §3.4] a waited NONSEQ/SEQ is held,
  // unless the master cancels after the first ERROR cycle
  property p_hold_in_wait;
    @(posedge HCLK) disable iff (!HRESETn)
      (!HREADY && HTRANS inside {NONSEQ, SEQ}) |=>
          ($stable(HTRANS) && $stable(HADDR) && $stable({HWRITE, HSIZE, HBURST}))
       || ($past(HRESP) && HTRANS == IDLE);
  endproperty
  a_hold_in_wait: assert property (p_hold_in_wait)
    else `uvm_error("AHB_CHK", $sformatf("%m: waited NONSEQ/SEQ changed (no cancel)"))

  // [Protocol §3.6.1, §3.5.2] what a waited BUSY may change into
  property p_busy_in_wait;
    @(posedge HCLK) disable iff (!HRESETn)
      (!HREADY && HTRANS == BUSY) |=>
          (HTRANS inside {BUSY, SEQ} && $stable(HADDR))
       || ($past(HBURST) == INCR && HTRANS inside {IDLE, NONSEQ})
       || ($past(HRESP) && HTRANS == IDLE);
  endproperty
  a_busy_in_wait: assert property (p_busy_in_wait)
    else `uvm_error("AHB_CHK", $sformatf("%m: illegal change of a waited BUSY"))

  // [Protocol §6.1.1] a waited write holds its data on its active byte lanes
  property p_hwdata_hold;
    @(posedge HCLK) disable iff (!HRESETn)
      (dp_write && !HREADY) |=> $stable(HWDATA & dp_bits);
  endproperty
  a_hwdata_hold: assert property (p_hwdata_hold)
    else `uvm_error("AHB_CHK", $sformatf("%m: HWDATA changed before the write completed"))

  // ---- Two-cycle ERROR response, both directions ----
  // [Protocol §5.1.3, Table 5-2] first ERROR cycle -> second ERROR cycle
  a_error_first_then_second: assert property (@(posedge HCLK) disable iff (!HRESETn)
    (HRESP && !HREADY) |=> (HRESP && HREADY))
    else `uvm_error("AHB_CHK", $sformatf("%m: ERROR first cycle without a second"))

  // [Protocol §5.1.3, Table 5-2] an ERROR completion needs its first cycle
  property p_error_second_needs_first;
    @(posedge HCLK) disable iff (!HRESETn)
      (HRESP && HREADY) |-> $past(HRESP && !HREADY);
  endproperty
  a_error_second_needs_first: assert property (p_error_second_needs_first)
    else `uvm_error("AHB_CHK", $sformatf("%m: one-cycle ERROR (no first cycle)"))

  // ---- [Protocol §3.2 Table 3-1] IDLE and BUSY get a zero-wait OKAY ----
  a_idle_busy_zero_wait_okay: assert property (@(posedge HCLK) disable iff (!HRESETn)
    (HREADY && HTRANS inside {IDLE, BUSY}) |=> (HREADY && !HRESP))
    else `uvm_error("AHB_CHK", $sformatf("%m: IDLE/BUSY did not get a zero-wait OKAY"))

  // ---- Bursts, sizes and addresses ----
  // [Protocol §3.2 Table 3-1] a SEQ beat has the control of the previous beat
  a_seq_ctrl_matches: assert property (@(posedge HCLK) disable iff (!HRESETn)
    (HREADY && HTRANS == SEQ) |->
      {HWRITE, HSIZE, HBURST} == $past({HWRITE, HSIZE, HBURST}, 1, beat_accepted))
    else `uvm_error("AHB_CHK", $sformatf("%m: control changed inside a burst"))

  // [Protocol §3.2 Table 3-1] incrementing SEQ address = previous address + size
  a_seq_addr_increments: assert property (@(posedge HCLK) disable iff (!HRESETn)
    (HREADY && HTRANS == SEQ && !(HBURST inside {WRAP4, WRAP8, WRAP16})) |->
      HADDR == $past(HADDR, 1, beat_accepted) + (32'd1 << HSIZE))
    else `uvm_error("AHB_CHK", $sformatf("%m: SEQ address 0x%08h is not previous + size",
                                         $sampled(HADDR)))

  // [Protocol §3.5, §4.2] an incrementing burst never crosses 1KB; checked per beat,
  // so undefined-length INCR is covered; WRAP bursts are exempt
  a_incr_no_1kb_cross: assert property (@(posedge HCLK) disable iff (!HRESETn)
    (HREADY && HTRANS == SEQ && !(HBURST inside {WRAP4, WRAP8, WRAP16})) |->
      HADDR[31:10] == $past(HADDR[31:10], 1, beat_accepted))
    else `uvm_error("AHB_CHK", $sformatf("%m: burst crossed 1KB at 0x%08h",
                                         $sampled(HADDR)))   // the failing beat's address

  // [Protocol §3.5] every transfer of a burst is aligned to its size
  a_aligned: assert property (@(posedge HCLK) disable iff (!HRESETn)
    HTRANS[1] |-> ((HADDR & ((32'd1 << HSIZE) - 32'd1)) == 32'd0))
    else `uvm_error("AHB_CHK", $sformatf("%m: unaligned: addr=0x%08h size=%0d",
                                         $sampled(HADDR), $sampled(HSIZE)))

  // [Protocol §3.4 Note] HSIZE is never wider than the data bus
  a_size_le_bus: assert property (@(posedge HCLK) disable iff (!HRESETn)
    HTRANS[1] |-> ((32'd8 << HSIZE) <= DATA_W))
    else `uvm_error("AHB_CHK", $sformatf("%m: HSIZE wider than the %0d-bit bus", DATA_W))

  // [Protocol §3.5.1] a SINGLE is followed by IDLE or NONSEQ, never BUSY or SEQ
  a_no_busy_after_single: assert property (@(posedge HCLK) disable iff (!HRESETn)
    (HREADY && HTRANS == NONSEQ && HBURST == SINGLE) |=> HTRANS inside {IDLE, NONSEQ})
    else `uvm_error("AHB_CHK", $sformatf("%m: BUSY or SEQ after a SINGLE"))

  // ---- [Protocol §7.1.2] reset values, after the component's minimum reset time ----
  // Checked during reset, so there is no disable iff
  a_reset_values: assert property (@(posedge HCLK)
    (!HRESETn && rst_edges >= MIN_RESET_CYCLES) |-> (HTRANS == IDLE && HREADY))
    else `uvm_error("AHB_CHK", $sformatf("%m: not IDLE, or HREADY low, during reset"))

  // ---- [Integration policy] wait-state budget: legal if exceeded, so a warning ----
  // The specification only recommends at most 16 wait states (§5.1.2 Note)
  a_wait_budget: assert property (@(posedge HCLK) disable iff (!HRESETn)
    $fell(HREADY) |-> ##[1:MAX_WAIT] HREADY)
    else `uvm_warning("AHB_POLICY", $sformatf("%m: HREADY low > %0d cycles", MAX_WAIT))

  // ---- Coverage of antecedents and key sequences (§16.14.3) ----
  c_waited_nonseq_seq: cover property (@(posedge HCLK) disable iff (!HRESETn)
    !HREADY && HTRANS inside {NONSEQ, SEQ});
  c_waited_busy: cover property (@(posedge HCLK) disable iff (!HRESETn)
    !HREADY && HTRANS == BUSY);
  c_waited_write: cover property (@(posedge HCLK) disable iff (!HRESETn)
    dp_write && !HREADY);
  c_error_cancel: cover property (@(posedge HCLK) disable iff (!HRESETn)
    (HRESP && !HREADY && HTRANS inside {NONSEQ, SEQ}) ##1
    (HRESP && HREADY && HTRANS == IDLE));
  c_error_continue: cover property (@(posedge HCLK) disable iff (!HRESETn)
    (HRESP && !HREADY && HTRANS inside {NONSEQ, SEQ}) ##1
    (HRESP && HREADY && HTRANS inside {NONSEQ, SEQ}));
  c_reset_in_data_phase: cover property (@(posedge HCLK)
    (HRESETn && (beat_accepted || (dp_active && !HREADY))) ##1 !HRESETn);
  c_first_after_reset: cover property (@(posedge HCLK)
    $rose(HRESETn) ##[1:$] beat_accepted);

  // Every HTRANS value with and without a wait state, sampled out of reset
  covergroup htrans_cg @(posedge HCLK iff HRESETn);
    cp_trans:  coverpoint HTRANS { bins idle = {IDLE}; bins busy = {BUSY};
                                   bins nonseq = {NONSEQ}; bins seq = {SEQ}; }
    cp_hready: coverpoint HREADY { bins waited = {1'b0}; bins ready = {1'b1}; }
    cx_trans_waited: cross cp_trans, cp_hready;
  endgroup
  htrans_cg htrans_cov = new();
endmodule
```

```systemverilog
                            WRAP8, INCR8, WRAP16, INCR16} hburst_e;          // Table 3-3

  // One beat: a NONSEQ or SEQ transfer and its data phase
  class ahb_item extends uvm_sequence_item;
    `uvm_object_utils(ahb_item)
    rand logic [31:0] addr;
    rand logic        write;
    rand logic [2:0]  size;
    rand hburst_e     burst;
    htrans_e          trans;
    logic [31:0]      data;
    logic             resp;
    int unsigned      waits;
    int unsigned      beat_index;
    int unsigned      busy_before;

    constraint c_legal {
      (8 << size) <= 32;                     // §3.4
      (addr & ((32'd1 << size) - 1)) == 0;   // §3.5
    }

    function new(string name = "ahb_item");
      super.new(name);
    endfunction

    function string convert2string();
      return $sformatf("%s %s addr=%08h data=%08h size=%0d beat=%0d waits=%0d %s",
                       write ? "WR" : "RD", trans.name(), addr, data, size,
                       beat_index, waits, resp ? "ERROR" : "OKAY");
    endfunction
  endclass

  // Passive monitor: one item per completed beat
  class ahb_mon extends uvm_monitor;
    `uvm_component_utils(ahb_mon)
    uvm_analysis_port #(ahb_item) ap;
    virtual ahb_if vif;
    protected ahb_item     pending;     // accepted, data phase not yet complete
    protected int unsigned next_beat;   // beat_index for the next SEQ
    protected int unsigned busy_run;    // BUSY cycles at HREADY-high edges since the last beat

    function new(string name, uvm_component parent);
      super.new(name, parent);
    endfunction

    function void build_phase(uvm_phase phase);
      super.build_phase(phase);
      ap = new("ap", this);
      if (!uvm_config_db#(virtual ahb_if)::get(this, "", "vif", vif))
        `uvm_fatal("NOVIF", "no virtual interface 'vif' in the configuration database")
    endfunction

    task run_phase(uvm_phase phase);
      forever begin
        @(vif.mon_cb);
        if (!vif.mon_cb.HRESETn) begin               // reset kills the open transfer
          if (pending != null)
            `uvm_info("AHB_MON", {"reset: dropped ", pending.convert2string()}, UVM_LOW)
          pending  = null;
          busy_run = 0;
          continue;
        end
        if ($isunknown({vif.mon_cb.HTRANS, vif.mon_cb.HREADY}))
          `uvm_error("AHB_MON", "X/Z on HTRANS or HREADY outside reset")
        // 1. The data phase of the pending beat ends at an edge with HREADY high
        if (pending != null) begin
          if (vif.mon_cb.HREADY === 1'b1) begin
            pending.data = pending.write ? vif.mon_cb.HWDATA : vif.mon_cb.HRDATA;
            pending.resp = vif.mon_cb.HRESP;
            `uvm_info("AHB_MON", pending.convert2string(), UVM_MEDIUM)
            ap.write(pending);
            pending = null;
          end else begin
            pending.waits++;
          end
        end
        // 2. The address phase on the bus is accepted at this edge if HREADY is high
        if (vif.mon_cb.HREADY === 1'b1) begin
          if (vif.mon_cb.HTRANS[1] === 1'b1) begin   // NONSEQ or SEQ
            pending = ahb_item::type_id::create("tr");
            pending.addr        = vif.mon_cb.HADDR;
            pending.write       = vif.mon_cb.HWRITE;
            pending.size        = vif.mon_cb.HSIZE;
            pending.burst       = hburst_e'(vif.mon_cb.HBURST);
            pending.trans       = htrans_e'(vif.mon_cb.HTRANS);
            pending.beat_index  = (pending.trans == NONSEQ) ? 0 : next_beat;
            pending.busy_before = busy_run;
            next_beat = pending.beat_index + 1;
            busy_run  = 0;
          end else if (vif.mon_cb.HTRANS === BUSY) begin
            busy_run++;
          end
        end
      end
    endtask
  endclass

  // Transaction coverage: sampled once per published item
  class ahb_cov extends uvm_subscriber #(ahb_item);
    `uvm_component_utils(ahb_cov)
    int unsigned n_items;

    covergroup ahb_txn_cg with function sample(ahb_item t);
      cp_write: coverpoint t.write { bins read = {1'b0}; bins write = {1'b1}; }
      cp_size: coverpoint t.size {
        bins byte_sz = {3'd0}; bins half_sz = {3'd1}; bins word_sz = {3'd2};
        illegal_bins wider_than_bus = {[3'd3:3'd7]};      // §3.4, 32-bit bus
      }
      cp_burst: coverpoint t.burst;                       // one bin per hburst_e value
      cp_beat:  coverpoint t.trans { bins first = {NONSEQ}; bins later = {SEQ}; }
      cp_waits: coverpoint t.waits {                // includes the first ERROR cycle
        bins zero = {0}; bins one = {1}; bins few = {[2:4]};
        bins many = {[5:16]}; bins over_16 = {[17:$]};    // legal, above §5.1.2's advice
      }
      cp_resp: coverpoint t.resp { bins okay = {1'b0}; bins error = {1'b1}; }
      cp_busy_before: coverpoint t.busy_before iff (t.trans == SEQ) {
        bins none = {0}; bins one = {1}; bins several = {[2:$]};
      }
      // Bytes from an incrementing burst's start to the next 1KB boundary (§3.5)
      cp_kb_room: coverpoint (11'd1024 - t.addr[9:0])
        iff (t.trans == NONSEQ && t.burst inside {INCR, INCR4, INCR8, INCR16}) {
        bins near = {[1:16]}; bins mid = {[17:64]}; bins far = {[65:1024]};
      }
      cx_write_burst: cross cp_write, cp_burst;
      cx_burst_size:  cross cp_burst, cp_size;
      cx_waits_burst: cross cp_waits, cp_burst;
      cx_resp_dir:    cross cp_resp, cp_write;
      cx_resp_burst_beat: cross cp_resp, cp_burst, cp_beat {
        ignore_bins single_has_no_seq = binsof(cp_burst) intersect {SINGLE} &&
                                        binsof(cp_beat.later);
      }
    endgroup

    function new(string name, uvm_component parent);
      super.new(name, parent);
      ahb_txn_cg = new();
    endfunction

    function void write(ahb_item t);
      ahb_txn_cg.sample(t);
      n_items++;
    endfunction

    function void report_phase(uvm_phase phase);
      `uvm_info("COV_SUMMARY", $sformatf("COV_SUMMARY items=%0d", n_items), UVM_NONE)
    endfunction
  endclass

  // Byte-lane scoreboard: the reference model is a memory of expected bytes
  class ahb_sb extends uvm_scoreboard;
    `uvm_component_utils(ahb_sb)
    uvm_analysis_imp #(ahb_item, ahb_sb) item_imp;
    localparam int unsigned BUS_BYTES = 4;
    protected logic [7:0] mem_model [bit [31:0]];     // one entry per byte address
    int unsigned n_writes, n_errors, matches, mismatches, pending;

    function new(string name, uvm_component parent);
      super.new(name, parent);
    endfunction

    function void build_phase(uvm_phase phase);
      super.build_phase(phase);
      item_imp = new("item_imp", this);
    endfunction

    function void write(ahb_item t);
      int unsigned nbytes = 1 << t.size;
      bit          ok = 1, known = 1;
      if (t.resp) begin
        // Error policy: an ERROR read has no valid data (§6.1.2); forget failed writes
        if (t.write)
          for (int unsigned i = 0; i < nbytes; i++) mem_model.delete(t.addr + i);
        n_errors++;
        return;
      end
      for (int unsigned i = 0; i < nbytes; i++) begin
        bit [31:0]  a    = t.addr + i;
        logic [7:0] lane = t.data[8*(a % BUS_BYTES) +: 8];   // §6.2.1
        if (t.write)                   mem_model[a] = lane;
        else if (!mem_model.exists(a)) known = 0;
        else if (lane !== mem_model[a]) begin
          ok = 0;
          `uvm_error("SCB_MISMATCH", $sformatf("byte 0x%08h: expected %02h, read %02h",
                                               a, mem_model[a], lane))
        end
      end
      if (t.write)  n_writes++;
      else if (!ok) mismatches++;
      else if (!known) begin
        pending++;
        `uvm_warning("SCB_UNCHECKED", {"read of unwritten bytes: ", t.convert2string()})
      end
      else matches++;
    endfunction

    function void check_phase(uvm_phase phase);
      if (matches + mismatches == 0)
        `uvm_error("SCB_EMPTY", "no read was compared: is the monitor connected?")
    endfunction

    function void report_phase(uvm_phase phase);
      `uvm_info("SCB_SUMMARY", $sformatf(
        "SCB_SUMMARY matches=%0d mismatches=%0d pending=%0d writes=%0d errors=%0d",
        matches, mismatches, pending, n_writes, n_errors), UVM_NONE)
    endfunction
  endclass

  class ahb_agent extends uvm_agent;
    `uvm_component_utils(ahb_agent)
    ahb_mon mon;
    function new(string name, uvm_component parent);
      super.new(name, parent);
    endfunction

      super.build_phase(phase);
      mon = ahb_mon::type_id::create("mon", this);
      // An active master agent would also create its driver and sequencer here
      // when get_is_active() == UVM_ACTIVE (see "Stimulus side").
    endfunction
  endclass

  class ahb_env extends uvm_env;

    ahb_sb    sb;
    ahb_cov   cov;

    endfunction

      super.build_phase(phase);

    endfunction
    function void connect_phase(uvm_phase phase);

      agt.mon.ap.connect(cov.analysis_export);
    endfunction
  endclass

  class ahb_smoke_test extends uvm_test;
```

### Prove it can fail

A green run proves something only if the same bench goes red on a bug. Try each mutant, one at a time, and predict the first failing line before you run:

| Mutant | What should fail first |
|---|---|
| In `ahb_sram_slave`, write on every edge with `wr_reg`, not only when HREADY is high | Nothing on the pins, and no read mismatch: the master holds HWDATA through the wait (§6.1.1), so the extra write at 95 ns stores the same value. Only a white-box count of memory writes sees it; this is why the lab adds one. |
| In the slave's `S_OKAY` branch, go to `S_ERR2` instead of `S_ERR1` (a one-cycle ERROR) | `a_error_second_needs_first` at 195 ns |
| In `run_plan`, treat every edge as if HREADY were high | `a_hold_in_wait` and `a_seq_addr_increments` at 155 ns. Skipping the waited BUSY is still legal (BUSY may become SEQ in a wait), but it moves the run one edge earlier; then the SEQ of 0x18, waiting behind the read of 0x14, changes to 0x1C during the wait |
| In `ahb_mon`, accept an address phase without checking HREADY | at 165 ns a read of 0x18 is published with 0x14's data and `SCB_MISMATCH` fires: the waiting SEQ overwrote the pending item of the read of 0x14 |
| In `ahb_env`, delete `agt.mon.ap.connect(sb.item_imp)` | `SCB_EMPTY` in `check_phase` |
| In the checker, replace `` `uvm_error `` with `$error` in `a_error_second_needs_first`, together with the one-cycle ERROR mutant | the simulator's own error line at 195 ns, but `UVM_ERROR :    0`: the regression passes |

### Debug walkthrough: symptom → cause → fix

| Symptom in the log | Cause | Fix |
|---|---|---|
| A write is published with the previous transfer's data | address and data of one transfer paired at the same edge | complete each transfer at the next edge with HREADY high |
| Two items with the same address for one waited transfer | address phase accepted during a wait | accept only when HREADY is high |
| `a_hold_in_wait` fires when a master cancels after ERROR | the property lacks the §3.5.2 exception | add `$past(HRESP) && HTRANS == IDLE` to the consequent |
| `[AHB_CHK]` lines in the log, but `UVM_ERROR :    0` and the test passes | the action block uses `$error` | report with `` `uvm_error ``, or make the regression fail on assertion failures |
| A property never failed, and the bug was in that area | it never started: vacuous | add a `cover property` on its antecedent and read the cover report |
| A failure message names the wrong address | the action block printed the current HADDR | print `$sampled(HADDR)` |
| An extra item, with garbage data, right after a reset | the monitor did not flush its pending item | drop the pending item while HRESETn is low |
| Everything passes with HREADY stuck at X | X antecedents are false; the monitor publishes nothing | `a_no_x_ctrl`, the monitor's X check, and `SCB_EMPTY` |
| The bus hangs with HREADY low | a slave holds HREADYOUT low | the HREADY trace: find the data-phase owner |
| `SCB_EMPTY` although transfers ran | the analysis port is not connected | connect `ap` in `connect_phase` |
| The test never ends (a master-DUT bench with a responder) | the `forever` responder sequence raised an objection | start it in `fork ... join_none` with no objection |

### How to build an AHB environment of your own

1. **Write the interface** with every AHB signal as `logic`, a monitor clocking block (`mon_cb`, inputs only) and one clocking block per driving role.
2. **Write the item** with 4-state sampled fields and legal-stimulus constraints; decide whether you publish beats, bursts or both.
3. **Write the monitor**: accept at HREADY-high edges with HTRANS[1], complete at the next HREADY-high edge, count waits, flush on reset, check for X. Get `vif` from `uvm_config_db` in `build_phase`, with `` `uvm_fatal `` on failure.
4. **Assemble the checker** from the properties above, tag each one, label each assertion, report with `` `uvm_error `` and `$sampled`, and add a `cover property` per important antecedent. `bind` it into the DUT.
5. **Write the scoreboard**: a byte-lane model, an error policy, a reset policy, and accounting with a failure when nothing was checked.
6. **Write the coverage subscriber** and map every coverpoint and cover property to a vplan line.
7. **Add the stimulus** for the side the TB plays: pipelined master traffic with BUSY and cancel, or a responder with random waits and error injection.

## Push Further

### Expert: master-port versus slave-port checking

- **Acceptance differs by side.** At a master port, a transfer is accepted at an edge with HREADY high and HTRANS[1]. At a slave port it is accepted only if that slave's HSELx is also high: a slave "must only sample the HSELx, address, and control signals when HREADY is HIGH", and HSELx may be high while HREADY is low and then change before the transfer completes (IHI0033B.b §4.2).
- **Slave obligations need data-phase ownership.** The two-cycle ERROR (§5.1.3), the zero-wait OKAY for IDLE and BUSY (Table 3-1) and HREADYOUT high in reset (§7.1.2) are obligations of one slave, so check them on *that* slave's HREADYOUT and HRESP (§2.3), and only while that slave owns the data phase: register its HSELx at each edge with HREADY high, as the multiplexor does with its select (§2.4 Note). Without that gate, the checks fire on slaves that are not selected and drive whatever they like.
- **Beat counts differ by side.** A master must deliver every beat of a fixed-length burst unless an ERROR cancels it, but a multi-layer interconnect may terminate a burst at a slave port so another master can reach that slave, and "slaves must be designed to work correctly if the burst is not completed" (§3.5.2). A beat counter that is legal at a master port fires on legal traffic at a slave port behind such an interconnect.
- **Interview angle (answer it before you read on):** "Where do you put the protocol checker in a two-master, three-slave multi-layer system, and which rules go where?" The three bullets above hold every part of the answer.

### Expert: burst tracking

The checker above checks each beat against the previous one. Rules about the *whole* burst need a small state machine beside the properties:
- **Beat count:** INCR4/8/16 and WRAP4/8/16 have exactly 4, 8 or 16 beats (Table 3-3), counted at accepting edges; only an ERROR cancel (§3.5.2) or, at a slave port, interconnect termination ends one early.
- **Burst ends:** a fixed-length burst ends with SEQ, never BUSY, and no BUSY follows a SINGLE (§3.5.1); BUSY appears only inside a burst: between beats, or, in an undefined-length INCR only, as its last cycle before an IDLE or NONSEQ (Table 3-1, §3.5.1); SEQ appears only inside a burst.
- **Constant control:** HWRITE (Table 2-2), HSIZE (§3.4) and HPROT (§3.7) stay constant through a burst; the SEQ check covers HWRITE and HSIZE beat by beat.
- **WRAP addresses:** the next SEQ address wraps inside the block of `beats × size` bytes (§3.5). With `blk` = beats × 2^HSIZE, next = `(prev & ~(blk - 1)) | ((prev + 2^HSIZE) & (blk - 1))`. Check: a WRAP4 of words from 0x34 gives 0x38, 0x3C, then 0x30, exactly the example in §3.5.
- **Interview angle (answer it before you read on):** "Your checker accepted an INCR4 with only three beats. Which property was missing, and when is three beats legal?" Check your answer against the beat-count bullet above and Kata part 2 below.

### Expert: formal reuse with assume-guarantee

The same checker can drive a formal tool. For a **slave DUT**, the master-side rules (hold in wait, SEQ address and control, alignment, the 1KB rule, HSIZE within the bus) describe the *environment*, so they become `assume property` (IEEE 1800-2023 §16.14.2), while the slave's obligations (the ERROR pair, zero-wait OKAY, HREADYOUT high in reset) stay `assert property`. Split `a_reset_values` for this: its `HTRANS == IDLE` half is a master obligation (§7.1.2) and becomes an `assume` for a slave DUT. For a master DUT it is the other way round. A `ROLE` parameter selects which, through generate blocks.

Two practical points:
- **Reporting:** a checker that imports `uvm_pkg` cannot be read unchanged by most formal tools. Hide the reporting behind a macro chosen by a define (for example `` `uvm_error `` in simulation, a plain `$error` or nothing in formal). Which tools accept what is **tool-dependent**.
- **Vacuity:** formal tools report unreachable antecedents directly; in simulation, the `cover property` statements play that role (§16.14.3, §16.14.8). Over-constraining assumptions make assertions pass vacuously in formal too, so cover the antecedents there as well.

Formal integration with UVM is the subject of [E-INT-1](/curriculum/T4_Expert/E-INT-1_Integrating_UVM_with_Formal_Verification/index).

### Expert: assertions in a UVM regression

- **Counting.** Only messages issued through UVM reach the report server; `$error` and the default action of a failing assertion do not, so `UVM_ERROR :    0` can sit under a log full of failures. Report with `` `uvm_error ``, or make the regression script also fail on the simulator's assertion count ([I-UVM-1D](/curriculum/T2_Intermediate/I-UVM-1D_Reporting_and_Run_Control/index)).
- **Expected violations.** An error-injection test that drives an illegal master on purpose must not fail on the violations it planned. Options, from coarsest to finest: a `checks_enable` bit in every `disable iff`; `$assertoff`/`$assertcontrol` on named assertions (IEEE 1800-2023 §20.11), which is why every assertion here has a label; or a `uvm_report_catcher` that demotes exactly the expected ID, from the expected reporter, a counted number of times (IEEE 1800.2-2020 §6.6, `catch` §6.6.5). A catcher cannot see `$error`, because it sees only UVM reports: another reason to report through UVM. Expected-error accounting is taught in [A-UVM-9](/curriculum/T3_Advanced/A-UVM-9_Reset_and_Error_Injection/index).
- **Messages.** Action blocks run in the Reactive region, so they print current values unless they use `$sampled` (IEEE 1800-2023 §16.9.3). `%m` in the message gives the bound instance's hierarchical name, because the report itself comes from `uvm_root`.
- **Interview angle (answer it before you read on):** "The UVM summary is clean but the log has assertion errors. Explain, and fix it." The counting bullet above explains it; the last mutant in "Prove it can fail" reproduces the failure that the fix prevents.

### Expert: specification corner cases

- **IDLE alignment.** IHI0033B.b §3.5 requires the address of IDLE transfers to be aligned too, "otherwise during simulation it is likely that bus monitors could report spurious warnings"; IHI0033C makes it a recommendation ([B-AHB-1](/curriculum/T3_Advanced/B-AHB-1_AHB_Design_Timing_Mechanics/index) lists the Issue C changes). This page's `a_aligned` checks NONSEQ and SEQ only.
- **"Stable" means at rising edges.** Signals required to be stable must have the same value when sampled at successive rising edges; they may glitch between edges unless the AHB5 Stable_Between_Clock property is True (§7.1.1). `$stable` matches that meaning exactly.
- **Endianness and the scoreboard.** BE8 (byte-invariant big-endian) uses the same lanes as little-endian for a byte access; BE32 (word-invariant) does not (§6.2.2, §6.2.3). The scoreboard's per-byte-address model with lane = `addr mod bus bytes` is therefore correct for little-endian and BE8 systems (every byte address keeps its lane), but not for BE32.
- **Locked sequences.** A locked sequence (HMASTLOCK) is indivisible and must be processed before any other transfer (§3.3); it is recommended that an IDLE follows it (§3.3 Note, Table 3-1). A checker can bound the length of locked sequences as **[Integration policy]**.
- **WRAP16 of 1024-bit beats.** Its wrap block is 16 × 128 = 2048 bytes, so it spans two 1KB regions; for transfers up to 512 bits a WRAP block is at most 1KB. This is derived from Table 3-2 and §3.5 (the specification states the 1KB rule only for incrementing bursts), so treat it as a design-review question.
- **Awareness:** exclusive transfers (Chapter 8) and secure transfers with HNONSEC (§3.9) add their own rules and signals when the corresponding AHB5 properties are True.

### Expert: scale and performance

The semantics below are from IEEE 1800-2023; how much each one costs in run time is **tool-dependent** (simulator and options), so measure before you optimize.

- **Sample only what the plan means.** Pin-level covergroups sampled on every edge cost time on long tests; sample per item, or gate with `iff` on accepted beats.
- **Beats and bursts.** Publish per-beat items for the scoreboard and, if burst coverage needs it, a second per-burst analysis port, rather than reconstructing bursts in every subscriber.
- **Cheap antecedents.** A concurrent assertion outside procedural code starts a new evaluation attempt at every occurrence of its clock event (IEEE 1800-2023 §16.14.5); antecedents that are false on most edges (`HTRANS == SEQ && HREADY`) end those attempts at once. A gated `$past(x, 1, beat_accepted)` costs one stored value; an auxiliary register does the same and is easier to debug in a waveform.
- **Sparse models.** An associative array keyed by byte address grows only with the bytes written, which suits a 4GB address space with a few kilobytes of traffic.
- **Long-lived attempts and messages.** An unbounded `##[1:$]` in a cover or assertion keeps every attempt that has not matched alive, so attempts pile up on a long test; bound the delay by the vplan's real limit. The `` `uvm_info `` macro tests the verbosity before it formats the message (`uvm_report_begin` in uvm-core 2020.3.1 `src/macros/uvm_message_defines.svh`), so a filtered message is cheap, but a per-edge message that passes the test formats and prints a line at every edge. Keep per-edge messages at `UVM_DEBUG`, and replace per-edge `$display` prints, which no verbosity filters.
- **Interview angle (answer it before you read on):** "Your regression slowed by 30% after adding the AHB checker. Where do you look first?" The 30% is an illustrative premise; the bullets above list the usual suspects.

### Kata: an HWDATA hold check, a beat counter and a coverage line

**Task.**
1. Using the checker's `dp_write` and `dp_bits`, write `p_hwdata_hold` yourself (§6.1.1) without looking above. Then predict, edge by edge, whether it passes on the AHB pipeline lab's **WRAP vs INCR** scenario (a write burst with one wait state on the first beat), and whether it can ever start on the **BUSY in a burst** scenario.
2. Write an INCR4 beat counter: a property that fails if an INCR4 burst is followed by a new NONSEQ or an IDLE before its fourth beat, unless an ERROR completed in between. Predict its result on **BUSY in a burst** with the default settings.
3. Write the `cover property` that proves `a_busy_in_wait` started at least once.
4. Add the vplan line "INCR8 and INCR16 bursts, with a wait state on a later beat" to `ahb_txn_cg`: write a coverpoint or two with exactly the bins the line needs and a cross, and exclude the cells the line does not ask for. Then predict how many of its cells the Make It Work run hits.

<details>
<summary>Worked solution</summary>

**1.** The property is the one in the checker: `(dp_write && !HREADY) |=> $stable(HWDATA & dp_bits)`. On **WRAP vs INCR**, beat A0 is accepted, its data phase waits one edge, and the master holds A0's data through that edge (the model drives it until completion), so the one attempt that starts (at the waited edge) passes at the next edge. Every other edge has HREADY high, so no other attempt starts. On **BUSY in a burst** the burst is a *read*: `dp_write` is never 1, so the property never starts; it would pass vacuously there, which is why you cover `c_waited_write`.

**2.** One possible counter, beside the checker's other bookkeeping:

```systemverilog
// snippet: INCR4 beat counter (master-port rule; see "master-port versus slave-port")
int unsigned beats_left;          // beats still owed by the INCR4 in progress
always_ff @(posedge HCLK or negedge HRESETn)
  if (!HRESETn) beats_left <= 0;
  else if (HRESP && HREADY) beats_left <= 0;          // ERROR: may cancel (§3.5.2)
  else if (beat_accepted)
    beats_left <= (HTRANS == NONSEQ && HBURST == 3'b011) ? 3    // INCR4 started
                : (beats_left > 0 ? beats_left - 1 : 0);

a_incr4_four_beats: assert property (@(posedge HCLK) disable iff (!HRESETn)
  (beats_left > 0 && HREADY && !HRESP) |-> HTRANS inside {SEQ, BUSY})
  else `uvm_error("AHB_CHK", $sformatf("%m: INCR4 ended before its 4th beat"))
```

At an edge with HREADY high, the transfer on the bus is accepted (a beat) or not (IDLE, BUSY). While beats are owed, only SEQ or BUSY may appear. On **BUSY in a burst** (NONSEQ, BUSY, SEQ, SEQ, SEQ) the counter goes 3, then stays 3 across the BUSY, then 2, 1, 0, and the property passes. It checks something (non-vacuously) at each HREADY-high edge after the NONSEQ, up to the edge that accepts the fourth beat; at the waited edge of A2 its antecedent is false. The `HRESP && HREADY` reset clears the count after an ERROR, because a master may cancel the rest of the burst there; the `!HRESP` in the antecedent matters at that same edge, the second ERROR cycle, where a cancelling master already shows IDLE while the count (sampled before the edge) is still non-zero.

**3.** `c_waited_busy: cover property (@(posedge HCLK) disable iff (!HRESETn) !HREADY && HTRANS == BUSY);` On **BUSY in a burst** with *Wait states on A0* set to 2, the BUSY waits, so the cover is hit; with the defaults (no wait on A0) it is not, and `a_busy_in_wait` has checked nothing.

**4.** One possible answer, inside `ahb_txn_cg` (it reuses `cp_beat`):

```systemverilog
// snippet: one vplan line as coverage
cp_long_burst: coverpoint t.burst { bins incr8 = {INCR8}; bins incr16 = {INCR16}; }
cp_waited:     coverpoint (t.waits > 0) { bins waited = {1'b1}; }
cx_long_waited_later: cross cp_long_burst, cp_waited, cp_beat {
  ignore_bins first_beat = binsof(cp_beat.first);   // the line asks for later beats only
}
```

The cross has 2 × 1 × 2 = 4 cells; `ignore_bins` (IEEE 1800-2023 §19.6.1) removes the two first-beat cells, so the line is two cells: INCR8 and INCR16, each with a waited later beat. The Make It Work run sends only SINGLE and INCR4 bursts, so it hits **0 of 2**: the line is a hole that a burst test with random waits must fill. Gating the whole cross with `iff (t.trans == SEQ)` is an equally good alternative to `ignore_bins`.

</details>
