# AHB Verification Methodology

You now understand how AHB *should* work (Module B-AHB-1) and how it *breaks* (Module B-AHB-2).
This module closes the loop: **how do you prove the design is correct?**

We will build up a complete AHB verification methodology from first principles — the same approach used by VIP teams at ARM, Synopsys, and Cadence to verify AHB interconnects and slave controllers.

<QuickTake>
- **Transaction modeling** converts raw pin-level AHB signals into high-level objects for scoreboarding.
- **Monitor + Checker** is the core passive verification component — it watches and validates without driving.
- **Protocol assertions** catch violations in real time; functional **coverage** proves you exercised enough scenarios.
- **Debug patterns** turn a failing waveform into a root cause in minutes, not days.
</QuickTake>

## 1. Transaction Modeling

The first step in any bus verification environment is defining a **transaction object** that captures everything about a single AHB transfer.

```systemverilog
class ahb_transaction extends uvm_sequence_item;
  `uvm_object_utils(ahb_transaction)

  // Address phase fields
  rand bit [31:0] addr;
  rand bit        write;
  rand bit [2:0]  size;      // HSIZE encoding
  rand bit [2:0]  burst;     // HBURST encoding
  rand bit [1:0]  trans;     // HTRANS encoding

  // Data phase fields
  rand bit [31:0] data;
  bit             resp;       // 0=OKAY, 1=ERROR
  int unsigned    wait_cycles; // number of wait states observed

  // Burst tracking
  int unsigned    beat_index;  // which beat within a burst (0..N-1)
  bit             is_last_beat;

  function new(string name = "ahb_transaction");
    super.new(name);
  endfunction

  function string convert2string();
    return $sformatf("%s addr=0x%08h data=0x%08h size=%0d burst=%0d waits=%0d resp=%s",
      write ? "WR" : "RD", addr, data, size, burst, wait_cycles,
      resp ? "ERROR" : "OKAY");
  endfunction
endclass
```

> [!NOTE]
> The `wait_cycles` field is critical for performance analysis.
> By tracking how many wait states each transfer accumulates, you can build latency distribution coverage and identify slow slaves.

## 2. Monitor Architecture

The AHB monitor is a **passive** component.  It observes the bus without driving any signals.
Its job is to reconstruct complete transactions from the raw signal waveforms.

### The Challenge: Pipelining

Because AHB pipelines the address and data phases, the monitor must **buffer** the address phase information and pair it with the data phase that arrives one or more cycles later.

```systemverilog
class ahb_monitor extends uvm_monitor;
  `uvm_component_utils(ahb_monitor)

  uvm_analysis_port #(ahb_transaction) ap;
  virtual ahb_if vif;

  // Pipeline buffer: stores the address phase until data phase completes
  ahb_transaction pending_txn;

  function new(string name, uvm_component parent);
    super.new(name, parent);
    ap = new("ap", this);
  endfunction

  task run_phase(uvm_phase phase);
    forever begin
      @(posedge vif.HCLK);

      // ── Data phase sampling (for the PREVIOUS address phase) ──
      if (pending_txn != null && vif.HREADY) begin
        // Data phase is complete
        if (pending_txn.write)
          pending_txn.data = vif.HWDATA;
        else
          pending_txn.data = vif.HRDATA;
        pending_txn.resp = vif.HRESP;

        ap.write(pending_txn);  // broadcast to scoreboard
        pending_txn = null;
      end else if (pending_txn != null && !vif.HREADY) begin
        pending_txn.wait_cycles++;
      end

      // ── Address phase capture (for the CURRENT cycle) ──
      if (vif.HTRANS inside {NONSEQ, SEQ} && vif.HREADY) begin
        pending_txn = ahb_transaction::type_id::create("txn");
        pending_txn.addr  = vif.HADDR;
        pending_txn.write = vif.HWRITE;
        pending_txn.size  = vif.HSIZE;
        pending_txn.burst = vif.HBURST;
        pending_txn.trans = vif.HTRANS;
      end
    end
  endtask
endclass
```

### Key Design Decision: When to Sample

The monitor **only samples the address phase when `HREADY` is high**.
This is because during a wait state, the address phase of the next transfer hasn't actually been accepted yet — the master is just holding it stable.

> [!IMPORTANT]
> A common VIP bug is to capture the address phase on every cycle regardless of `HREADY`.
> This produces duplicate transactions in the analysis stream and corrupts the scoreboard.

## 3. Checker: Protocol Compliance

The checker runs alongside the monitor and validates every cycle against the AHB specification rules.
A production AHB checker typically contains 20–40 SVA properties. Each one below is tagged **[Protocol §x]** (a rule in Arm IHI0033B.b) or **[Integration policy]** (a budget your system chooses). Keep the two apart: a slow but legal slave must never be reported as a protocol violation.

### 3A. Core Protocol Assertions

```systemverilog
module ahb_protocol_checker #(parameter int MAX_WAIT = 16) (
  input logic        HCLK,
  input logic        HRESETn,
  input logic [31:0] HADDR,
  input logic [1:0]  HTRANS,
  input logic [2:0]  HBURST,
  input logic [2:0]  HSIZE,
  input logic        HWRITE,
  input logic        HREADY,
  input logic        HRESP
);
  localparam logic [1:0] IDLE = 2'b00, BUSY = 2'b01, NONSEQ = 2'b10, SEQ = 2'b11;
  localparam logic [2:0] SINGLE = 3'b000, INCR = 3'b001,
                         WRAP4 = 3'b010, WRAP8 = 3'b100, WRAP16 = 3'b110;

  // A beat's address phase ends (is accepted) at this edge
  wire beat_accepted = HREADY && (HTRANS inside {NONSEQ, SEQ});

  // ═══════════════════════════════════════════════
  // 1. Wait states: hold, with the spec's exceptions
  // ═══════════════════════════════════════════════
  // [Protocol §3.6.1, §3.6.2, §3.5.2] a waited NONSEQ/SEQ holds,
  // unless the master cancels after an ERROR first cycle
  property p_hold_in_wait;
    @(posedge HCLK) disable iff (!HRESETn)
      (!HREADY && HTRANS inside {NONSEQ, SEQ}) |=>
          ($stable(HTRANS) && $stable(HADDR) && $stable({HWRITE, HSIZE, HBURST}))
       || ($past(HRESP) && HTRANS == IDLE);
  endproperty
  assert property (p_hold_in_wait)
    else $error("[AHB-CHK] Waited NONSEQ/SEQ changed without an ERROR to cancel it");

  // [Protocol §3.6.1, §3.5.2] what a waited BUSY may change into
  property p_busy_in_wait;
    @(posedge HCLK) disable iff (!HRESETn)
      (!HREADY && HTRANS == BUSY) |=>
          (HTRANS inside {BUSY, SEQ} && $stable(HADDR))
       || ($past(HBURST) == INCR && HTRANS inside {IDLE, NONSEQ})
       || ($past(HRESP) && HTRANS == IDLE);
  endproperty
  assert property (p_busy_in_wait)
    else $error("[AHB-CHK] Illegal change of a waited BUSY");

  // ═══════════════════════════════════════════════
  // 2. Two-cycle ERROR response, both directions
  // ═══════════════════════════════════════════════
  // [Protocol §5.1.3, Table 5-2] first ERROR cycle -> second ERROR cycle
  property p_error_first_then_second;
    @(posedge HCLK) disable iff (!HRESETn)
      (HRESP && !HREADY) |=> (HRESP && HREADY);
  endproperty
  assert property (p_error_first_then_second)
    else $error("[AHB-CHK] ERROR first cycle not followed by the second");

  // [Protocol §5.1.3, Table 5-2] an ERROR completion needs a first cycle.
  // This is the property that catches a one-cycle ERROR.
  property p_error_second_needs_first;
    @(posedge HCLK) disable iff (!HRESETn)
      (HRESP && HREADY) |-> $past(HRESP && !HREADY);
  endproperty
  assert property (p_error_second_needs_first)
    else $error("[AHB-CHK] One-cycle ERROR: no first cycle with HREADY low");

  // ═══════════════════════════════════════════════
  // 3. IDLE and BUSY get a zero-wait OKAY
  // ═══════════════════════════════════════════════
  // [Protocol §3.2 Table 3-1]
  property p_idle_busy_zero_wait_okay;
    @(posedge HCLK) disable iff (!HRESETn)
      (HREADY && HTRANS inside {IDLE, BUSY}) |=> (HREADY && !HRESP);
  endproperty
  assert property (p_idle_busy_zero_wait_okay)
    else $error("[AHB-CHK] IDLE/BUSY did not get a zero-wait OKAY");

  // ═══════════════════════════════════════════════
  // 4. Burst rules
  // ═══════════════════════════════════════════════
  // [Protocol §3.2 Table 3-1] a SEQ beat has the same control as the previous beat
  property p_seq_ctrl_matches;
    @(posedge HCLK) disable iff (!HRESETn)
      (HREADY && HTRANS == SEQ) |->
        {HWRITE, HSIZE, HBURST} == $past({HWRITE, HSIZE, HBURST}, 1, beat_accepted);
  endproperty
  assert property (p_seq_ctrl_matches)
    else $error("[AHB-CHK] Control changed inside a burst");

  // [Protocol §3.2 Table 3-1] incrementing SEQ address = previous address + size
  property p_seq_addr_increments;
    @(posedge HCLK) disable iff (!HRESETn)
      (HREADY && HTRANS == SEQ && !(HBURST inside {WRAP4, WRAP8, WRAP16})) |->
        HADDR == $past(HADDR, 1, beat_accepted) + (32'd1 << HSIZE);
  endproperty
  assert property (p_seq_addr_increments)
    else $error("[AHB-CHK] SEQ address is not the previous address + size");

  // [Protocol §3.5, §4.2] incrementing bursts never cross 1KB.
  // Per beat, so undefined-length INCR is covered; WRAP bursts are exempt.
  property p_incr_no_1kb_cross;
    @(posedge HCLK) disable iff (!HRESETn)
      (HREADY && HTRANS == SEQ && !(HBURST inside {WRAP4, WRAP8, WRAP16})) |->
        HADDR[31:10] == $past(HADDR[31:10], 1, beat_accepted);
  endproperty
  assert property (p_incr_no_1kb_cross)
    else $error("[AHB-CHK] Incrementing burst crossed a 1KB boundary at 0x%08h", HADDR);

  // [Protocol §3.5] every transfer in a burst is aligned, not just the first
  property p_aligned;
    @(posedge HCLK) disable iff (!HRESETn)
      (HTRANS inside {NONSEQ, SEQ}) |-> ((HADDR & ((32'd1 << HSIZE) - 32'd1)) == 32'd0);
  endproperty
  assert property (p_aligned)
    else $error("[AHB-CHK] Unaligned transfer: addr=0x%08h size=%0d", HADDR, HSIZE);

  // [Protocol §3.5.1] a SINGLE is followed by IDLE or NONSEQ, never BUSY or SEQ
  property p_no_busy_after_single;
    @(posedge HCLK) disable iff (!HRESETn)
      (HREADY && HTRANS == NONSEQ && HBURST == SINGLE) |=> HTRANS inside {IDLE, NONSEQ};
  endproperty
  assert property (p_no_busy_after_single)
    else $error("[AHB-CHK] BUSY or SEQ after a SINGLE");

  // ═══════════════════════════════════════════════
  // 5. Reset values
  // ═══════════════════════════════════════════════
  // [Protocol §7.1.2] checked DURING reset, so there is no disable iff
  property p_reset_values;
    @(posedge HCLK)
      !HRESETn |-> (HTRANS == IDLE && HREADY);
  endproperty
  assert property (p_reset_values)
    else $error("[AHB-CHK] Not IDLE, or HREADY low, during reset");

  // ═══════════════════════════════════════════════
  // Integration policy (not protocol)
  // ═══════════════════════════════════════════════
  // The spec only recommends at most 16 wait states (§5.1.2), so this is a warning.
  property p_wait_budget;
    @(posedge HCLK) disable iff (!HRESETn)
      $fell(HREADY) |-> ##[1:MAX_WAIT] HREADY;
  endproperty
  assert property (p_wait_budget)
    else $warning("[AHB-CHK] HREADY low for > %0d cycles (policy budget)", MAX_WAIT);

endmodule
```

`$past(expr, 1, beat_accepted)` returns the value at the most recent earlier edge where a beat was accepted (IEEE 1800-2023 §16.9.3), which is the previous beat even if BUSY cycles or wait states came in between.

Why these forms and not simpler ones:

- **`p_error_second_needs_first`** is the one that catches a slave driving ERROR for a single cycle with `HREADY` high. `p_error_first_then_second` alone never even starts on that bug, because its antecedent needs `HREADY` low.
- **`p_hold_in_wait`** replaces a plain `$stable(HTRANS)` check, which fires on legal behaviour: BUSY→SEQ during a wait (§3.6.1) and IDLE after an ERROR (§3.5.2). `p_busy_in_wait` covers the BUSY cases.
- **`p_incr_no_1kb_cross`** checks each beat. A start-address formula fires on legal WRAP bursts and cannot size an undefined-length INCR.

Still missing from this list, and worth adding next: the beat count of fixed-length bursts (INCR4 must deliver four beats unless an ERROR cancels it, §3.5.2), and no fixed-length burst ending in BUSY (§3.5.1). Both need a small burst-tracking state machine beside the properties.

### 3B. Assertion Severity Strategy

| Severity | When to Use | Example |
|---|---|---|
| `$error` | Definite protocol violation | Address changed during wait state |
| `$warning` | Suspicious but legal behavior | Wait state count > 8 cycles |
| `$info` | Telemetry and debug tracing | Transfer completed with 0 wait states |

## 4. Functional Coverage

Protocol assertions prove the design *doesn't violate rules*.
Functional coverage proves you *exercised enough scenarios* to trust the assertions.

### 4A. Pin-Level Transfer Coverage

```systemverilog
// Every HTRANS value with and without a wait state, plus the transitions
// the spec singles out (BUSY inside bursts, burst end or cancel after ERROR).
covergroup ahb_htrans_cg @(posedge HCLK iff HRESETn);
  cp_trans: coverpoint HTRANS {
    bins idle   = {2'b00};
    bins busy   = {2'b01};
    bins nonseq = {2'b10};
    bins seq    = {2'b11};
  }
  cp_waited: coverpoint HREADY {
    bins waited = {1'b0};
    bins ready  = {1'b1};
  }
  // e.g. IDLE->NONSEQ or BUSY->SEQ while the slave waits (§3.6.1)
  cx_trans_waited: cross cp_trans, cp_waited;

  cp_trans_seq: coverpoint HTRANS {
    bins nonseq_busy = (2'b10 => 2'b01);
    bins busy_seq    = (2'b01 => 2'b11);
    bins seq_busy    = (2'b11 => 2'b01);
    bins seq_idle    = (2'b11 => 2'b00);   // burst end, or cancel after ERROR
  }

  // First ERROR cycle while the next SEQ beat waits on the address bus
  cp_error_mid_burst: coverpoint (HRESP && !HREADY && HTRANS == 2'b11) {
    bins hit = {1'b1};
  }
endgroup
```

### 4B. Transaction Coverage: Bursts, Waits and Errors

The monitor samples this once per completed transfer. Declare it in your coverage package and call `cg.sample(txn)` from the subscriber's `write()`.

```systemverilog
covergroup ahb_txn_cg with function sample(ahb_transaction t);
  cp_write: coverpoint t.write {
    bins read  = {1'b0};
    bins write = {1'b1};
  }
  cp_size: coverpoint t.size {
    bins byte_txn = {3'b000};
    bins half_txn = {3'b001};
    bins word_txn = {3'b010};
  }
  cp_burst: coverpoint t.burst {
    bins single = {3'b000};  bins incr   = {3'b001};
    bins wrap4  = {3'b010};  bins incr4  = {3'b011};
    bins wrap8  = {3'b100};  bins incr8  = {3'b101};
    bins wrap16 = {3'b110};  bins incr16 = {3'b111};
  }
  cp_beat: coverpoint t.trans {
    bins first_beat = {2'b10};   // NONSEQ
    bins later_beat = {2'b11};   // SEQ
  }
  // The monitor counts every HREADY-low cycle, including the first ERROR cycle.
  cp_wait_cycles: coverpoint t.wait_cycles {
    bins zero_wait  = {0};
    bins one_wait   = {1};
    bins few_waits  = {[2:4]};
    bins many_waits = {[5:16]};
    bins over_16    = {[17:$]};  // legal, but above the spec's recommendation (§5.1.2)
  }
  cp_resp: coverpoint t.resp {
    bins okay  = {1'b0};
    bins error = {1'b1};
  }

  cx_write_burst: cross cp_write, cp_burst;
  cx_write_size:  cross cp_write, cp_size;
  cx_wait_burst:  cross cp_wait_cycles, cp_burst;
  cx_resp_dir:    cross cp_resp, cp_write;
  cx_resp_burst:  cross cp_resp, cp_burst;
  cx_resp_beat:   cross cp_resp, cp_beat;   // ERROR on a first beat vs mid-burst
endgroup
```

> [!TIP]
> **Coverage closure strategy:** Run your random test suite until you hit 100% on `cx_write_burst`.
> Then write targeted directed tests for any remaining holes in `cx_resp_burst` (error during WRAP8 read, etc.).

## 5. Scoreboard Strategy

For an AHB slave verification environment, the scoreboard compares expected vs. actual memory contents.
AHB has no write strobes: the active byte lanes come from `HADDR` and `HSIZE` (little-endian lane = address modulo bus bytes, §6.2.1). So the reference model stores **bytes**, and a byte write at `0x1001` is visible to a later word read at `0x1000`.

```systemverilog
class ahb_scoreboard extends uvm_scoreboard;
  `uvm_component_utils(ahb_scoreboard)

  uvm_analysis_imp #(ahb_transaction, ahb_scoreboard) ap;

  // Reference model: one entry per BYTE address (32-bit, little-endian bus)
  bit [7:0] shadow_mem [bit [31:0]];

  function new(string name, uvm_component parent);
    super.new(name, parent);
    ap = new("ap", this);
  endfunction

  function void write(ahb_transaction txn);
    int unsigned nbytes = 1 << txn.size;
    for (int unsigned i = 0; i < nbytes; i++) begin
      bit [31:0]   a    = txn.addr + i;
      int unsigned lane = a % 4;                    // byte lane on a 32-bit bus
      if (txn.resp == 1) begin
        // Policy choice: a failed write leaves the byte unknown.
        // A failed read carries no valid data (§6.1.2).
        if (txn.write) shadow_mem.delete(a);
        continue;
      end
      if (txn.write) begin
        shadow_mem[a] = txn.data[8*lane +: 8];
      end else if (!shadow_mem.exists(a)) begin
        `uvm_warning("SCB", $sformatf("Read of unwritten byte 0x%08h: cannot check", a))
      end else if (shadow_mem[a] !== txn.data[8*lane +: 8]) begin
        `uvm_error("SCB", $sformatf("MISMATCH at byte 0x%08h: expected 0x%02h, read 0x%02h",
                                    a, shadow_mem[a], txn.data[8*lane +: 8]))
      end
    end
  endfunction
endclass
```

> [!NOTE]
> What a slave does with a write that gets an ERROR response is not fixed by the protocol. This scoreboard forgets those bytes. If your slave guarantees "no write on ERROR", check that instead.

## 6. Debug Patterns

When a test fails, the waveform can be overwhelming.  These patterns let you triage AHB failures quickly.

### Pattern 1: The "HREADY Trace"

**Always start by finding `HREADY` transitions.**  If `HREADY` drops, find *which slave* pulled it low and *why*.
In a multi-slave system, each slave's `HREADYOUT` feeds the multiplexor that drives `HREADY` (§4.3). The decoder's `HSELx` (§4.2), registered at the last edge where `HREADY` was high, tells you which slave owns the current data phase.

### Pattern 2: The "Transaction Boundary Finder"

Look for `HTRANS = NONSEQ` transitions — these mark the start of every new transfer or burst.
Count `SEQ` beats after each `NONSEQ` to reconstruct the burst structure.

### Pattern 3: The "ERROR Forensics"

When you see `HRESP = ERROR`:
1. Find the address phase that was accepted at the last edge with `HREADY` high before the ERROR started. With OKAY wait states before the ERROR, that is more than two cycles back.
2. Check whether the address falls within the slave's address range.
3. Check whether the access type (read/write) and size are legal for that register.
4. Check whether a protection violation (`HPROT`) occurred.

### Pattern 4: The "Starvation Detector"

In multi-master systems, sort the waveform by master ID.
Measure the time between successive grants for each master.
If one master's inter-grant time grows without bound, you have a starvation bug.

## 7. Interview Questions & Answers

These are real questions asked in verification engineer interviews at semiconductor companies:

**Q1: How does the AHB monitor handle the pipeline when reconstructing transactions?**

> The monitor buffers address-phase information (HADDR, HTRANS, HWRITE, HSIZE, HBURST) and pairs it with the data-phase signals (HWDATA/HRDATA, HRESP) that arrive one or more cycles later. The monitor only captures the address phase when HREADY is high, because during a wait state the pending address hasn't been accepted yet.

**Q2: Why does AHB use a 1 KB burst boundary while AXI uses 4 KB?**

> Both rules keep a burst inside one slave. In AHB, the smallest address region a slave can own is 1 KB, and masters never perform incrementing transfers over a 1 KB boundary, so a burst never crosses an address decode boundary (IHI0033B.b §4.2, §3.5). WRAP bursts are exempt because they stay inside their own beats × size block. AXI forbids any burst from crossing a 4 KB boundary; the spec says this prevents a burst from crossing a boundary between two slaves and limits the number of address increments a slave must support (IHI0022E A3.4.1). Every 4 KB boundary is also a 1 KB boundary, so a legal AHB burst never crosses 4 KB either.

**Q3: How would you verify that locked transfers cannot starve a high-priority master forever?**

> A locked sequence is indivisible and must be processed before any other transfers (§3.3), so a high-priority master that wants the same slave legitimately waits for the whole sequence, wait states included. The test is therefore about *bounds*, not about pre-emption:
> (1) a low-priority master runs the longest locked sequence your software uses, to the slowest slave;
> (2) higher-priority masters request continuously;
> (3) measure every master's worst-case wait and compare it with the latency budget.
> That budget is integration policy. The arbiter is not defined by the AHB5 spec (§4.1), and it must never break a lock to meet a budget.

**Q4: What is the minimum set of protocol assertions for an AHB VIP?**

> Protocol: (1) hold during wait states *with* the §3.6 exceptions, (2) the two-cycle ERROR in both directions, (3) zero-wait OKAY for IDLE and BUSY, (4) SEQ control and address consistency, (5) the per-beat 1 KB check for incrementing bursts, (6) alignment of every transfer, (7) IDLE and HREADY high during reset. Integration policy, reported separately: the wait-state budget and lock-duration budget. A production VIP adds burst beat counting, early-termination handling and `HMASTLOCK` rules.

## Summary

A complete AHB verification environment has four layers:

| Layer | Component | Purpose |
|---|---|---|
| **Observation** | Monitor | Reconstruct pin-level signals into transactions |
| **Compliance** | Protocol Checker | SVA assertions catch rule violations in real time |
| **Correctness** | Scoreboard | Compare DUT behavior against a reference model |
| **Completeness** | Coverage | Prove you exercised enough scenarios to trust the results |
