## Quick Take

- **What it is:** The set of testbench components that verify an AXI interface: a **monitor** that rebuilds transactions from the five channels, a **predictor** that computes what each transaction should return, a **scoreboard** that compares the two with one ordered queue per ID, a **protocol checker** of assertions on the pins, a **coverage** collector, a **responder** that plays a misbehaving-on-purpose slave, and a **performance** monitor for latency, bandwidth and outstanding depth.
- **Why it matters:** AXI lets responses with different IDs overtake each other, lets read data of different IDs interleave beat by beat, lets write data arrive before its address, and lets either side stall at any time (IHI0022E §A3.3, §A5.3, §A5.3.1). A naive monitor or scoreboard fails on correct hardware or, worse, passes broken hardware. This lesson is the gate of milestone M6: out-of-order, ID-aware protocol verification.
- **The Analogy:** A restaurant kitchen that numbers orders by table. Each table's dishes come out in the order that table ordered them; different tables are served in any order; and a waiter may carry one course for table 2 between two courses for table 1. The pass (the counter where finished plates are inspected; here, the checker) checks every plate leaves properly; the head waiter (the scoreboard) checks each table got what it ordered. *Where it breaks:* AXI4 write data never interleaves (it always follows the write-address order, §A5.4), and reads and writes are two separate kitchens with no order between them, even for the same table number (§A5.3.4).

**You will be able to:**
1. Write a channel-level AXI4 monitor that rebuilds reads (beats collected per RID, interleaving, RLAST) and writes (W bursts paired with AWs in order, W before AW) without overwriting same-ID outstanding transactions.
2. Write a per-ID read scoreboard, fed by a predictor at the AR handshake, that accepts legal cross-ID reordering and rejects same-ID reordering, a missing RLAST, an extra beat and a wrong RID, with end-of-test accounting.
3. Write protocol assertions (R only after AR, burst legality, X checks only on valid lanes) and a coverage model over burst length, ID reuse, outstanding depth, response and backpressure.
4. Configure a reordering responder with random READY, interleaving and error injection, and measure latency, bandwidth, stalls and outstanding depth from monitor timestamps.
5. Decide where each check belongs (checker, monitor, predictor or scoreboard), including the error-response policy: SLVERR and DECERR are recorded and judged against a prediction, never flagged by the monitor.

### Words you need first

- A **master** starts transactions and a **slave** answers them. IHI0022E uses these words; later Arm issues say **manager** and **subordinate** for the same roles.
- AXI has five **channels**: write address (AW), write data (W), write response (B), read address (AR) and read data (R). A **handshake** is the rising edge of the clock ACLK at which a channel's VALID and READY are both HIGH; that edge transfers one item (§A3.2.1). A channel is **stalled** at an edge where VALID is HIGH and READY is LOW.
- A **burst** is one transaction's data: AxLEN + 1 **beats**, one beat per handshake on W or R (§A3.4.1). The last beat carries WLAST or RLAST (§A3.2.2).
- A transaction is **outstanding** from its address handshake until its last beat (reads) or its B response (writes). AXI masters keep many outstanding at once.
- The **ID** (AWID, ARID) names an ordering stream; the slave copies it to BID or RID ([B-AXI-3](/curriculum/T3_Advanced/B-AXI-3_AXI_Ordering_and_IDs/index)).
- **Backpressure** is a receiver holding READY LOW; it slows the sender but never changes what is sent.
- In a UVM testbench (TB), a **monitor** is a passive component that watches pins and publishes one new transaction object per observed transaction through an **analysis port**, a zero-time broadcast to every connected subscriber ([I-UVM-2B](/curriculum/T2_Intermediate/I-UVM-2B_TLM_Connections/index)). A **subscriber** is a component with one `write()` input for those objects (`uvm_subscriber`).
- A **reference model** computes what the design under test (DUT) should do; a **predictor** is the component that calls it for each observed request and publishes an **expected** transaction. The monitor's output is the **actual** transaction. A **scoreboard** pairs and compares them ([A-UVM-6](/curriculum/T3_Advanced/A-UVM-6_Scoreboards_and_Reference_Models/index)).
- A **clocking block** samples signals just before a clock edge and drives them just after it, so testbench code never races the design ([F4C](/curriculum/T1_Foundational/F4C_Clocking_Blocks/index)).

Three design decisions hide in that picture:
- **The monitor is passive and judges no data values.** It turns handshakes into transactions, checks only the framing it must understand to build them (RLAST position, an RID that matches nothing), and publishes. Everything else is someone else's job.
- **Prediction happens at the request.** The predictor builds the expected read when the AR handshake is seen, not when data returns, so a read that never returns is still expected and is counted at the end of the test.
- **Both ends of the bus are verification components here.** The master driver and the responder talk to each other back to back, which is how a VIP proves its own monitor and scoreboard (a **VIP self-test**, [A-UVM-7](/curriculum/T3_Advanced/A-UVM-7_VIP_Construction/index)). To verify a real slave, replace `rsp` with the DUT; to verify a real master, replace `drv`. The monitor, scoreboard, checker and coverage stay as they are. The reference model must then describe the DUT instead of the responder (its memory contents and its error map), and the `+MUTANT` switches no longer apply, because they live in the responder.

### Who checks what: the responsibility matrix

Each check needs some information. A check that needs only the pins at a few edges belongs in an assertion. A check that needs the request (its ID, length or address) to interpret later beats belongs in the monitor. A check that needs the expected data belongs in the scoreboard. Put a check in the wrong place and it either cannot see what it needs, or it fires on legal traffic.

Use the table as a map: each row is explained in a section below, and the Recap at the end of this part repeats it.

| RVALID only after an AR handshake; BVALID only after the AW and WLAST handshakes | checker | handshake counters are enough | §A3.3.1 |

| No 4KB crossing for INCR | checker | visible on one AR or AW ([B-AXI-2](/curriculum/T3_Advanced/B-AXI-2_AXI_Burst_Math/index) owns the property) | §A3.4.1 |

**Pitfall: checking data in the monitor.** A monitor that compares RDATA with a model has to know what the model knows, and then it cannot be reused at a point where the model differs, such as the far side of an interconnect. Keep the monitor a recorder.

**Pitfall: an assertion that needs history it does not have.** "Same-ID reads come back in order" looks like a pin rule, but the pins show only RID; whether the data belongs to the older or the younger read is visible only to something that knows the expected data. That is why it lives in the scoreboard.

### The read monitor: beats collected per ID

**The problem.** Reads A (ARID 1, two beats), B (ARID 2, two beats) and C (ARID 1, one beat) are outstanding together. The slave may return B before A, may alternate beats of A and B, but must return all of A before any of C, because A and C share an ID (§A5.3.1). The monitor sees only a stream of R beats, each tagged with RID. Which read does each beat belong to?

**The rule that answers it.** A beat with RID n belongs to the **oldest outstanding read with ARID n**, because same-ID data returns in issue order and the beats of two same-ID reads never mix (§A5.3.1). So the monitor keeps, for each ID, a queue of open reads in AR order, appends each beat to the head of its RID's queue, and closes the head when RLAST arrives.

The heart of the read monitor is short. `open_q` is an associative array of queues (IEEE 1800-2023 §7.8, §7.10): `open_q[id]` is the queue for one ID, and `open_q[id][0]` its oldest read. The full class is in Make It Work.

```systemverilog
// snippet: axi_rd_monitor::on_r_beat, called at each R handshake
function void on_r_beat();
  int unsigned id = vif.mon_cb.RID;
  axi_rd_item  t;
  bit          last_expected;
  if (!open_q.exists(id) || open_q[id].size() == 0) begin
    `uvm_error("UNEXPECTED_R",
               $sformatf("RID %0d with no outstanding read (A5.3.1)", id))
    return;
  end
  t = open_q[id][0];                // same-ID data returns in order (A5.3.1)
  t.data.push_back(vif.mon_cb.RDATA);
  t.resp.push_back(vif.mon_cb.RRESP);       // recorded here, judged later
  last_expected = (t.data.size() == t.len + 1);
  if (vif.mon_cb.RLAST != last_expected)
    `uvm_error("RLAST", $sformatf("RID %0d: RLAST=%0b on beat %0d of %0d (A3.2.2)",
               id, vif.mon_cb.RLAST, t.data.size(), t.len + 1))
  // Close on RLAST or on the last expected beat: one fault, one error.
  if (vif.mon_cb.RLAST || last_expected) begin
    t.last_cycle = cycle;
    void'(open_q[id].pop_front());
    n_open--;
    ap.write(t);                    // a new object per read, never reused
  end
endfunction
```

Details that matter:
- `exists()` is tested before `open_q[id]` is read, because reading a missing associative-array entry issues a warning and returns a default (IEEE 1800-2023 §7.8.6).
- At each edge the monitor processes R **before** AR. A beat at edge k can belong only to a read whose AR handshake came at an earlier edge, since RVALID may rise only after the AR handshake (§A3.3.1). Processing AR first would make a just-accepted read eligible for a beat at the same edge, so a slave that answers in the same cycle as the AR handshake would not be flagged.
- The monitor samples through its clocking block `mon_cb`, so it reads the values just before the edge, whichever process drove them ([F4C](/curriculum/T1_Foundational/F4C_Clocking_Blocks/index), IEEE 1800-2023 §14.13).
- It publishes the read on the RLAST beat, not on each beat. A per-beat publisher hands the scoreboard pieces it cannot compare.
- When the length and RLAST disagree, the monitor reports once and closes the read anyway. If it kept the read open, every later beat of that ID would be attributed to the wrong read and one fault would cascade into dozens of errors.
- During reset it empties `open_q` without publishing. IHI0022E §A3.1.2 defines only the interface during reset (VALIDs LOW), not what happens to transactions in flight, so dropping open reads is this testbench's reset policy, not a protocol rule. The scoreboard must apply the same policy and flush its expected queues on the same reset, or it reports reads the monitor dropped; [A-UVM-9](/curriculum/T3_Advanced/A-UVM-9_Reset_and_Error_Injection/index) teaches the reset protocol between components.

**The mistake everyone makes: one slot per ID.** The obvious structure is `axi_rd_item open[int]`, one entry per ID. It works until two reads with one ID are outstanding, which AXI allows and real masters do constantly. Then `open[1] = C` overwrites A, A's beats are appended to C, and the next RLAST publishes the wrong read. The same bug in a write monitor (`pending_writes[AWID] = txn`) makes the first B complete the second write and the second B report "no pending write". A queue per ID is the fix, not an optimisation.

**Pitfall: one queue for all IDs.** The opposite mistake keeps a single first-in, first-out list of open reads. It works until a slave reorders across IDs, which is legal, and then beat B0 is appended to A.

### The write monitor: W follows AW, and may arrive first

Writes are harder than reads for two reasons:
- **AXI4 W carries no ID.** "All write data must be in the same order as the associated write addresses" (§A5.4.1), and all beats of one write are consecutive (§A5.4). So the n-th complete W burst belongs to the n-th AW.
- **W may come before its AW.** The protocol defines no relationship between AW and W apart from the B dependency, "this means, for example, that the write data can appear at an interface before the write address" (§A3.3).

So the monitor keeps two FIFOs that wait for each other: AWs waiting for data, and complete W bursts waiting for an address. When one of each is present, it pairs them, checks that the burst had AWLEN + 1 beats (the WLAST check must wait for the AW, because only the AW carries AWLEN), and moves the write to a per-AWID queue that waits for B. A B with BID n completes the oldest paired write with AWID n, because responses to same-ID writes are issued in order (§A6.4).

What the write monitor cannot see: B carries only BID and BRESP (§A3.4.4), so if a slave swaps the B responses of two same-ID writes and both say OKAY, the pins look exactly the same. Popping the oldest write per BID accounts for every response but cannot detect that swap. Same-ID write order is checked end to end instead, by reading the data back after the last B, or by making the two responses differ; [B-AXI-3](/curriculum/T3_Advanced/B-AXI-3_AXI_Ordering_and_IDs/index) gives both remedies.

Both B responses are legal for AXI4: each comes after its write's AW and WLAST handshakes (§A3.3.1).

```systemverilog
// snippet: write reassembly in an AXI4 monitor (W carries no ID)
// axi_wr_item fields: id, addr, len (from the AW); data[$], strb[$] (from W);
// bresp (from B). run_phase calls, at each edge and in this order:
//   on_b(BID, BRESP) if B handshakes; on_aw(item) if AW handshakes;
//   on_w_beat(WDATA, WSTRB, WLAST) if W handshakes (all sampled via mon_cb).
axi_wr_item aw_q[$];                   // AWs still waiting for their data
axi_wr_item w_bursts[$];               // complete W bursts waiting for an AW
axi_wr_item open_b[int unsigned][$];   // per AWID: paired writes waiting for B
axi_wr_item w_cur;                     // the W burst being collected

function void on_aw(axi_wr_item aw);   // at each AW handshake
  if (w_bursts.size() > 0) pair(aw, w_bursts.pop_front());   // W came first
  else aw_q.push_back(aw);
endfunction

function void on_w_beat(logic [31:0] data, logic [3:0] strb, logic last);
  if (w_cur == null) w_cur = axi_wr_item::type_id::create("w_cur");
  w_cur.data.push_back(data);
  w_cur.strb.push_back(strb);          // WSTRB per beat: the byte mask
  if (!last) return;
  if (aw_q.size() > 0) pair(aw_q.pop_front(), w_cur);   // oldest AW (A5.4.1)
  else w_bursts.push_back(w_cur);      // W before AW is legal (A3.3)
  w_cur = null;
endfunction

function void pair(axi_wr_item aw, axi_wr_item w);
  aw.data = w.data;
  aw.strb = w.strb;
  // Deferred check: only the AW knows AWLEN (A3.2.2, A3.4.1).
  if (w.data.size() != aw.len + 1)
    `uvm_error("WLAST", $sformatf("AWID %0d: WLAST on beat %0d of %0d",
               aw.id, w.data.size(), aw.len + 1))
  open_b[aw.id].push_back(aw);         // same AWID may repeat: a queue
endfunction

function void on_b(int unsigned bid, logic [1:0] bresp);
  axi_wr_item t;
  if (!open_b.exists(bid) || open_b[bid].size() == 0) begin
    `uvm_error("UNEXPECTED_B", $sformatf("BID %0d with no completed write", bid))
    return;
  end
  t = open_b[bid].pop_front();         // same-ID responses in order (A6.4)
  t.bresp = bresp;                     // one response per burst (A3.4.4)
  ap.write(t);
endfunction
```

Process B before AW and W at each edge, for the same reason as R before AR: a B can only complete a write whose AW and WLAST handshakes came at earlier edges (§A3.3.1). The Practice section has a kata that makes you trace these four functions, and the lab's stretch step has you write them.

**Pitfall: keying W by AWID.** AXI3 had WID, so AXI3-era code looks up the write by WID. In AXI4 there is no WID (§A5.4.1); the only link is order. **Pitfall: assuming AW comes first.** A monitor that drops W beats seen while `aw_q` is empty loses the data of every write whose address path has more register stages than its data path.

In `check_phase`, which runs after the run phase ends (IEEE 1800.2-2020 §9.8.1.7), the scoreboard reports every expected read still queued, and `report_phase` prints the milestone signature `SCB_SUMMARY matches=N mismatches=0 pending=0`.

**How each bug shows up.** A scoreboard is only as good as the bugs it catches. The responder in Make It Work can break one rule on purpose (a **mutant**, selected with `+MUTANT=`), and each must produce at least one named error:

| Mutant (what the slave does wrong) | What catches it | Log |
|---|---|---|
| `SAME_ID_SWAP`: answers the younger of two same-ID reads first | scoreboard: each read's data or responses are compared with the other's prediction | equal lengths: two `SCB_MISMATCH ... beat 0 data` (`beat 0 resp` when only one of the two reads starts in the SLVERR window). Different lengths: two `RLAST` errors from the monitor, one `SCB_MISMATCH ... beat count` and one `... beat 0 data` (or `resp`), then `UNEXPECTED_R` for the leftover beats (or a further mismatch if another read with that ID is open) |
| `DROP_RLAST`: last beat without RLAST | monitor: beat AxLEN + 1 without RLAST | `RLAST ... RLAST=0 on beat 4 of 4` |
| `EXTRA_BEAT`: one more beat, with RLAST, after a read is complete | monitor: no read of that ID is open; checker: the extra RLAST unbalances its counters | `UNEXPECTED_R`, and `AXI_CHK` errors from `a_r_after_ar` |
| `WRONG_RID`: every beat of one read answered with an ID never issued; the responder waits for the last AR and picks a read that is the last with its ID | monitor, then end-of-test accounting | `UNEXPECTED_R` for each beat of that read, then `SCB_PENDING`, `[EOT] 39 of 40 reads compared` and `pending=1` |
| none, but the slave reorders across IDs and interleaves | nothing: it is legal | `SCB_SUMMARY matches=40 mismatches=0 pending=0` |

Why `WRONG_RID` is timed that way: the monitor never receives a beat with the answered read's ID, so that read stays at the head of `open_q[ID]`. If a later read used the same ID, its beats would be appended to that stale entry (a read the slave has already answered), and the log would fill with `SCB_MISMATCH` (and `RLAST`) errors on later reads of that ID instead of one clean `SCB_PENDING`. Debug the first error of a run, not the cascade after it.

**Lane-aware comparison.** The Make It Work reads use the whole 32-bit bus on every beat. With narrow or unaligned transfers only some byte lanes carry data, and the others may hold anything (§A3.4.1, §A3.4.3), so the compare must mask them. For reads, compare only the active lanes of each beat; for writes, the reference memory must update only the bytes whose WSTRB bit is 1. The narrow-write waveform under "Protocol assertions" below shows what inactive lanes look like, and the memory-math visualizer in [B-AXI-2](/curriculum/T3_Advanced/B-AXI-2_AXI_Burst_Math/index) lists the active byte lanes of every transfer of a burst you enter.

### Error responses: legal, recorded, judged elsewhere

AXI has four responses, on RRESP for every read beat and on BRESP once per write (§A3.4.4):

| RRESP or BRESP | Name | Meaning |
|---|---|---|
| `2'b00` | OKAY | normal access succeeded (or an exclusive access failed) |
| `2'b01` | EXOKAY | an exclusive access succeeded ([B-AXI-4](/curriculum/T3_Advanced/B-AXI-4_AXI_Expert_Features_Cache_Atomics/index)) |
| `2'b10` | SLVERR | the access reached the slave, and the slave reports an error |
| `2'b11` | DECERR | no slave at that address, usually from the interconnect's default slave |

Two rules shape every checker. A read may have a different response on each beat, and a write has one response for the whole burst. And "the required number of data transfers must be performed, even if an error is reported" (§A3.4.4): an error never shortens a burst.

**Debrief.** No to both. All four beats still transfer and RLAST comes on beat 4, because an error never shortens a burst (§A3.4.4). And SLVERR is a legal response: the monitor records it on beat 2 and reports nothing.

Who decides what about that SLVERR:

| Component | Its job for responses |
|---|---|
| monitor | records RRESP per beat and BRESP per write; flags nothing |
| predictor (reference model) | predicts the response: SLVERR if the test programmed an error window, DECERR for an unmapped address |
| scoreboard | compares the actual response with the prediction, beat by beat |
| checker | flags only protocol misuse, such as a burst cut short after an error, or EXOKAY on a normal (non-exclusive) access, which has no defined meaning (§A3.4.4, §A7.2) |
| test | decides whether an *unpredicted* error fails the run, or is an expected error the test injected ([A-UVM-9](/curriculum/T3_Advanced/A-UVM-9_Reset_and_Error_Injection/index)) |

**No RDATA compare on an error beat.** §A3.4.4 requires every beat of a failed read to transfer, but it places no requirement on RDATA for a beat whose RRESP is SLVERR or DECERR. So the scoreboard compares each beat's response first, and a difference is reported as a response mismatch. When the predicted and actual responses are both SLVERR or DECERR (`resp[1]` is 1), it compares nothing more for that beat. Comparing RDATA there would fail a legal slave that returns zeros or stale data with its SLVERR, and the message would name the data instead of the response. The Make It Work responder returns the reference data on its SLVERR beats only as a convenience of the self-test; the scoreboard does not rely on it, so a real slave can replace `rsp` unchanged. AHB states the same rule outright for HRDATA on an ERROR response ([B-AHB-1](/curriculum/T3_Advanced/B-AHB-1_AHB_Design_Timing_Mechanics/index)). One cost follows: two same-ID reads of equal length answered SLVERR on every beat cannot be told apart. To stay simple, the `SAME_ID_SWAP` mutant skips every pair whose reads both start in the error window, a wider rule than that case needs, so it swaps only a pair in which at least one read starts outside the window.

**The misconception: "SLVERR is a protocol error, so the monitor should flag it."** SLVERR is a defined, legal response. A monitor that raises `uvm_error` on it fails every error-injection test and every test of a slave's error path, and it gets switched off, taking its real checks with it. The monitor records; the scoreboard decides whether the error was expected.

### Protocol assertions: rules on the pins

The checker is a set of concurrent assertions ([I-SV-4A](/curriculum/T2_Intermediate/I-SV-4A_SVA_Fundamentals/index)) attached to the interface with `bind`, which inserts an instance into a design scope without editing it ([I-SV-4C](/curriculum/T2_Intermediate/I-SV-4C_Checkers/index), IEEE 1800-2023 §23.11). [B-AXI-1](/curriculum/T3_Advanced/B-AXI-1_AXI_Channel_Architecture/index) already wrote the five-channel hold, stability, reset and dependency checks; reuse them. The Make It Work checker leaves them out to stay short, so on its own it cannot see a responder that drops RVALID before the handshake; the kata "Close the hold gap" in Practice has you add the read-path ones. This lesson adds the read-path checks an M6 environment needs on top of B-AXI-1's, and labels each one:
- `[Protocol §]`: a rule of IHI0022E. It is never wrong to fire.
- `[Policy]`: a rule this testbench adds because a violation almost always means a bug, although the specification does not forbid it. A policy check must be easy to switch off for a block that legitimately breaks it.

```systemverilog
// snippet: from axi_rd_checker (Make It Work has all of it)
// [Protocol A3.3.1] RVALID only after the AR handshake of its read.
a_r_after_ar: assert property (RVALID |-> ar_done > rlast_done)
  else `uvm_error("AXI_CHK", "RVALID with no read outstanding (A3.3.1)")
// [Protocol A3.4.1] A WRAP burst has 2, 4, 8 or 16 beats.
a_wrap_len: assert property (ARVALID && ARBURST == 2'b10
                             |-> ARLEN inside {1, 3, 7, 15})
  else `uvm_error("AXI_CHK", "WRAP length not 2, 4, 8 or 16 (A3.4.1)")
// [Policy] While VALID is HIGH, the control it qualifies is known.
a_r_known: assert property (RVALID |-> !$isunknown({RID, RRESP, RLAST}))
  else `uvm_error("AXI_CHK", "X on RID, RRESP or RLAST while RVALID")
```

`|->` is overlapping implication: when the left side holds at an edge, the right side must hold at the same edge (IEEE 1800-2023 §16.12.7). The checker's `default disable iff (!ARESETn)` turns every check off during reset. `ar_done` and `rlast_done` are handshake counters updated by an `always_ff`; an assertion samples them just before the edge, so at the first R beat the AR handshake of the previous edge is already counted.

**X checks only where data is valid.** IHI0022E has no rule about X; an X check is always `[Policy]`. And on W, only the byte lanes whose WSTRB bit is 1 carry valid data: "a master must ensure that the write strobes are HIGH only for byte lanes that contain valid data" (§A3.4.3). The other lanes may legally hold anything, including X in simulation.

```systemverilog
// snippet: [Policy] X on WDATA only in strobed lanes; WSTRB itself known
for (genvar i = 0; i < DATA_BYTES; i++) begin : g_lane
  a_wdata_known: assert property (WVALID && WSTRB[i]
                                  |-> !$isunknown(WDATA[8*i +: 8]))
    else `uvm_error("AXI_CHK", $sformatf("X on strobed WDATA lane %0d", i))

  else `uvm_error("AXI_CHK", "X on WSTRB while WVALID")
```

`$isunknown` returns 1 if any bit is X or Z (IEEE 1800-2023 §20.9). For R, the same idea needs the lanes of each beat, which depend on the AR, so a lane-aware RDATA X check belongs in the monitor, which knows the AR and samples the 4-state pins. It cannot move to the scoreboard: the item's `data` fields are 2-state `bit`, and converting a 4-state value to 2-state turns every X or Z bit into 0 (IEEE 1800-2023 §6.11.2).

**Pitfall: checks that need history.** RLAST on the right beat needs the length of the oldest open read of that RID; a pin-level checker can do it only by keeping per-ID queues of lengths, which duplicates the monitor. Most environments leave it to the monitor, as the matrix says, and keep the checker to rules a few counters can decide.

### The coverage model

Coverage answers "did the stimulus reach the cases that matter?" A **covergroup** samples values into **bins**, and a **cross** counts combinations ([I-SV-3A](/curriculum/T2_Intermediate/I-SV-3A_Functional_Coverage_Fundamentals/index)). For AXI the cases that matter are the ones that break naive components: long bursts, same-ID reuse, deep outstanding windows, errors and stalls. The coverage subscriber samples once per completed read, with values the monitor recorded at the AR handshake and during the data phase.

| Coverpoint | Bins | Why it matters |
|---|---|---|
| `cp_len` (ARLEN) | `single` 0; `short_b` 1–3; `long_b` 4–7 | single-beat reads hide beat-accounting bugs |
| `cp_ahead` (same-ID reads open at this AR) | `fresh` 0; `one` 1; `two_plus` 2 or more | same-ID ordering is tested only when a read queues behind another |
| `cp_depth` (reads open at this AR, all IDs) | `idle` 0; `some` 1–3; `deep` 4 or more | reordering and buffers are exercised only when many reads are open |
| `cp_err` | no error; at least one SLVERR or DECERR beat | the error path |
| `cp_stall` | no stall; at least one RVALID-and-not-RREADY edge | the slave's hold logic |
| `x_len_ahead` | `cp_len` × `cp_ahead` | same-ID reuse with short and long bursts |
| `x_err_len` | `cp_err` × `cp_len` | errors on single and multi-beat reads |

A full AXI model also covers what the Make It Work bench holds fixed. That bench issues only INCR, 4-byte, aligned reads, so these bins would stay empty there by design:

| Coverpoint | Bins | Why it matters |
|---|---|---|
| `cp_burst` (ARBURST) | FIXED; INCR; WRAP; `2'b11` as `illegal_bins` | each burst type has its own address sequence (§A3.4.1) |
| `cp_size` (ARSIZE) | 1, 2 and 4 bytes; wider than the bus as `illegal_bins` | narrow transfers use only some byte lanes |
| `cp_align` (start address) | aligned; unaligned; last byte just below a 4KB boundary | unaligned starts and the 4KB rule |

Use `illegal_bins` for values the protocol forbids, so a hit is reported as an error: on one coverpoint's values (IEEE 1800-2023 §19.5.6), or on a combination, such as a WRAP burst whose length is not 2, 4, 8 or 16 (§19.6.3). A cross can only be as precise as its bins, so the length coverpoint below has one bin per length:

```systemverilog
// snippet: burst type, size and WRAP length for a full model, with burst and
// size added to sample(). A WRAP burst has 2, 4, 8 or 16 beats (A3.4.1).
cp_burst: coverpoint burst { bins fixed = {2'b00}; bins incr = {2'b01};
                             bins wrap  = {2'b10}; illegal_bins rsvd = {2'b11}; }
cp_size:  coverpoint size  { bins b1 = {0}; bins b2 = {1}; bins b4 = {2};
                             illegal_bins wider = {[3:7]}; }   // 32-bit bus
cp_beats: coverpoint len   { bins n[] = {[0:15]}; bins more = {[16:255]}; }
x_wrap:   cross cp_burst, cp_beats {
  // ! binsof(...) intersect {...} selects the bins that do NOT hold those values
  illegal_bins bad_wrap = binsof(cp_burst.wrap) &&
                          ! binsof(cp_beats) intersect {1, 3, 7, 15};
}
```

Keep crosses targeted: the full product of eight coverpoints with three to five bins each has tens of thousands of cells, most unreachable or uninteresting.

### Stimulus: the outstanding window, random READY and the responder

**The master side.** The master driver issues ARs up to an **outstanding window** (`max_outstanding`), counting AR handshakes up and RLAST handshakes down. The window is the master's own choice; the protocol sets no limit. ARVALID never waits for ARREADY (§A3.3.1): the driver raises it when it has an item and room in the window, and holds it until the handshake.

**Random RREADY.** The master's RREADY is random. That is legal, because "the master can wait for RVALID to be asserted before it asserts RREADY" (§A3.3.1), and it forces the slave to hold its data, which exercises the slave's stall logic. A master may hold RREADY HIGH by default only if it can always accept read data at once (§A3.2.2).

**The slave side: a responder.** To verify a master, the testbench must play the slave. [A-UVM-7](/curriculum/T3_Advanced/A-UVM-7_VIP_Construction/index) taught the general **responder agent** for APB: the monitor publishes each request, a **reactive sequence** waits for it and produces a response item, and a responder driver drives it. An AXI responder needs more, because it may have many reads open and must choose which to answer:
- **Per-ID queues.** Accepted ARs go to `pend[ARID]`, in arrival order.
- **Choice of the next beat.** Only the head of each ID's queue may send (same-ID order); any ID may go next (overtaking); with `interleave` set, the ID may change between beats of one burst. All three are legal (§A5.3.1).
- **Random READY and gaps.** ARREADY is random each cycle. It may fall before ARVALID rises: "if READY is asserted, it is permitted to deassert READY before VALID is asserted" (§A3.2.1). R has random idle cycles. Once RVALID is HIGH, it and the beat are held until RREADY (§A3.2.1, §A3.2.2).
- **Error injection.** Beats whose address falls in a configured window answer SLVERR; every beat still transfers.
- **Knobs in one configuration object.** `ar_ready_pct`, `r_gap_pct`, `interleave`, `err_lo`/`err_hi`, plus the master's `rready_pct` and `max_outstanding`. A test changes behaviour by changing knobs, never by editing the responder.

**Driver-based or sequence-based?** The responder in Make It Work is one component that takes data from the shared memory model and policy from the configuration object. A production VIP usually adds A-UVM-7's reactive sequence in front of it, so a test can override the *content* of a response (data, error, delay) through the factory while the driver keeps the *protocol* (holding, ordering, interleaving). **Pitfall: a responder that cannot misbehave.** A slave model that always answers in order, with READY tied HIGH and no errors, makes every monitor and scoreboard look correct. Its first job is to produce every legal ordering and stall, so that the checks are tested against them.

### Performance: latency, bandwidth, stalls and outstanding depth

Performance numbers are measured from the same monitor that feeds the scoreboard, in **ACLK cycles**, not in nanoseconds. `$time` returns an integer scaled to the time unit of the module that calls it (IEEE 1800-2023 §20.3.1), and a package can be compiled under a different time unit from the interface it watches (§3.14.2.3), so the same edge can print as different, or rounded, numbers. Counting edges avoids the question.

The definitions must separate the slave's delay from the master's:
- **Slave read latency:** from the AR handshake edge to the first edge with RVALID HIGH for that read.
- **Master stall cycles:** edges with RVALID HIGH and RREADY LOW. They are the master's backpressure and must not inflate the slave's latency.
- **Write response latency:** from the later of the AW handshake and the WLAST handshake to BVALID. The write is not complete until B: "sending all of the write data for the transaction must not be taken as indicating completion" (§A5.3.4).
- **Bandwidth:** bytes transferred divided by the cycles of a stated window. On W, count the strobed bytes (the 1 bits of WSTRB, `$countones`, IEEE 1800-2023 §20.9); on R, the active lanes of each beat.
- **Outstanding depth:** reads open at each AR handshake (a coverage value), and the mean over the run: the sum of each read's open time divided by the window. That mean equals throughput × mean time in system, Little's law, a queueing result rather than an AXI rule; [B-AXI-3](/curriculum/T3_Advanced/B-AXI-3_AXI_Ordering_and_IDs/index) uses it to size the window.

### Recap

| Component | Keeps | Checks | Never |
|---|---|---|---|
| monitor | per-ID queues of open reads; AW and W FIFOs; per-AWID queues for B | RLAST/WLAST position, RID/BID with nothing open, X on active R lanes | judges data values or responses |
| predictor | the reference memory | — | predicts at data time |
| scoreboard | per-ID queues of expected reads | responses per beat, data on OKAY and EXOKAY beats, same-ID order, leftovers in `check_phase` | uses one queue for all IDs or one slot per ID |
| checker | handshake counters | pin rules, burst legality, X on strobed W lanes | needs expected data |
| responder | per-ID queues of accepted requests | — | answers in only one order |
| performance | cycle counts | contracts from the product spec | mixes master stalls into slave latency |

### The M6 read-path environment

This is one complete file, `tb_top.sv`, for the read path of an AXI4 interface with a 32-bit data bus and 4-bit IDs. It contains every component in the architecture picture: the interface with three clocking blocks, the bound checker, and a package with the configuration object, the reference memory, the item and sequence, the master driver, the reordering responder, the monitor, the predictor, the per-ID scoreboard, coverage, performance, the environment and the test. Reads are INCR with 4-byte beats, so every byte lane is active on every beat. The write path follows the same pattern with the write monitor above. The lab's stretch step has you write the W-to-AW pairing logic as a plain-SystemVerilog class and check it against a replayed trace; a UVM write path (write monitor, write responder, WSTRB-masked memory) is left as an extension.

Read it in this order: `axi_rd_monitor`, `axi_rd_predictor`, `axi_rd_scoreboard`, then `axi_rd_responder`, then the rest. The checker holds the read-path burst and X checks; the hold and stability checks come from B-AXI-1 (Practice has a kata that adds the read-path ones).

```systemverilog
interface axi_rd_if (input logic ACLK, input logic ARESETn);
  // Handshake signals start LOW: VALIDs must be LOW during reset (A3.1.2).
  logic        ARVALID = 1'b0, ARREADY = 1'b0;
  logic        RVALID  = 1'b0, RREADY  = 1'b0;
  logic [3:0]  ARID, RID;
  logic [31:0] ARADDR, RDATA;
  logic [7:0]  ARLEN;
  logic [2:0]  ARSIZE;
  logic [1:0]  ARBURST, RRESP;

  clocking mon_cb @(posedge ACLK);

  clocking mst_cb @(posedge ACLK);

    output ARVALID, ARID, ARADDR, ARLEN, ARSIZE, ARBURST, RREADY;
  endclocking

  clocking slv_cb @(posedge ACLK);
    default input #1step output #1;
    input  ARESETn, ARVALID, ARID, ARADDR, ARLEN, RREADY;
    output ARREADY, RVALID, RID, RDATA, RRESP, RLAST;
  endclocking

// Pin-level read checks, bound into every axi_rd_if instance. The bind
// target is an interface, so the checker is an interface too (1800-2023 23.11).
// [Protocol] = a rule of IHI0022E. [Policy] = a rule this testbench adds.
interface axi_rd_checker #(int unsigned DATA_BYTES = 4) (
  input logic        ACLK, ARESETn,
  input logic        ARVALID, ARREADY, RVALID, RREADY, RLAST,
  input logic [3:0]  ARID, RID,
  input logic [31:0] ARADDR,
  input logic [7:0]  ARLEN,
  input logic [2:0]  ARSIZE,
  input logic [1:0]  ARBURST, RRESP
);
  import uvm_pkg::*;
  int unsigned ar_done, rlast_done;   // handshakes seen so far

  always_ff @(posedge ACLK or negedge ARESETn)
    if (!ARESETn) begin
      ar_done    <= 0;
      rlast_done <= 0;
    end else begin
      if (ARVALID && ARREADY)        ar_done    <= ar_done + 1;
      if (RVALID && RREADY && RLAST) rlast_done <= rlast_done + 1;
    end

  default clocking @(posedge ACLK); endclocking
  default disable iff (!ARESETn);

  // [Protocol A3.3.1] RVALID only after the AR handshake of its read.
  a_r_after_ar: assert property (RVALID |-> ar_done > rlast_done)
    else `uvm_error("AXI_CHK", "RVALID with no read outstanding (A3.3.1)")
  // [Protocol A3.4.1] A WRAP burst has 2, 4, 8 or 16 beats ...
  a_wrap_len: assert property (ARVALID && ARBURST == 2'b10
                               |-> ARLEN inside {1, 3, 7, 15})
    else `uvm_error("AXI_CHK", "WRAP length not 2, 4, 8 or 16 (A3.4.1)")
  // ... and a start address aligned to the transfer size.
  a_wrap_align: assert property (ARVALID && ARBURST == 2'b10
                                 |-> (ARADDR & ((1 << ARSIZE) - 1)) == 0)
    else `uvm_error("AXI_CHK", "unaligned WRAP start (A3.4.1)")
  // [Protocol A3.4.1] A transfer is never wider than the data bus.
  a_size_fits: assert property (ARVALID |-> (1 << ARSIZE) <= DATA_BYTES)
    else `uvm_error("AXI_CHK", "ARSIZE wider than the bus (A3.4.1)")
  // [Protocol Table A3-3] AxBURST 2'b11 is reserved.
  a_burst_enc: assert property (ARVALID |-> ARBURST != 2'b11)
    else `uvm_error("AXI_CHK", "reserved ARBURST encoding (Table A3-3)")
  // [Policy] Handshake signals are never X after reset; IHI0022E has no X
  // rule, but an X here means an undriven or uninitialised port.
  a_hs_known: assert property (!$isunknown({ARVALID, ARREADY, RVALID, RREADY}))
    else `uvm_error("AXI_CHK", "X on a VALID or READY")
  // [Policy] While VALID is HIGH, the control it qualifies is known.
  a_ar_known: assert property (ARVALID
                               |-> !$isunknown({ARID, ARADDR, ARLEN, ARSIZE, ARBURST}))
    else `uvm_error("AXI_CHK", "X on AR control while ARVALID")
  a_r_known: assert property (RVALID |-> !$isunknown({RID, RRESP, RLAST}))
    else `uvm_error("AXI_CHK", "X on RID, RRESP or RLAST while RVALID")
endinterface

package axi_rd_pkg;
  import uvm_pkg::*;
  `include "uvm_macros.svh"

  `uvm_analysis_imp_decl(_exp)
  `uvm_analysis_imp_decl(_act)

  localparam bit [1:0] RESP_OKAY = 2'b00, RESP_SLVERR = 2'b10;

  // Every knob a test may change, in one object (A-UVM-7 pattern).
  class axi_rd_cfg extends uvm_object;
    `uvm_object_utils(axi_rd_cfg)
    int unsigned n_reads         = 40;
    int unsigned max_outstanding = 8;    // master: reads in flight at once
    int unsigned rready_pct      = 60;   // master: RREADY HIGH this often
    int unsigned ar_ready_pct    = 70;   // responder: ARREADY HIGH this often
    int unsigned r_gap_pct       = 25;   // responder: idle R cycles
    bit          interleave      = 1;    // responder: RID may change mid-burst
    bit [31:0]   err_lo          = 32'h0000_3000;  // SLVERR window
    bit [31:0]   err_hi          = 32'h0000_30FF;
    string       mutant          = "NONE";
    function new(string name = "axi_rd_cfg");
      super.new(name);
    endfunction
  endclass

  // The reference memory. A word's value is a fixed function of its address,
  // so the responder and the predictor agree without sharing state. Beats
  // inside [err_lo, err_hi] answer SLVERR, a legal response (A3.4.4).
  class axi_mem_model;
    static function bit [31:0] data_at(bit [31:0] addr);
      return addr ^ 32'hC0DE_0000;
    endfunction
    static function bit [1:0] resp_at(axi_rd_cfg cfg, bit [31:0] addr);
      return (addr >= cfg.err_lo && addr <= cfg.err_hi) ? RESP_SLVERR : RESP_OKAY;
    endfunction
  endclass

  class axi_rd_item extends uvm_sequence_item;
    `uvm_object_utils(axi_rd_item)
    rand bit [3:0]  id;
    rand bit [31:0] addr;
    rand bit [7:0]  len;                 // ARLEN: the burst has len + 1 beats
    bit [31:0]      data[$];             // RDATA, one entry per beat
    bit [1:0]       resp[$];             // RRESP, one entry per beat (A3.4.4)
    // Filled by the monitor, in ACLK cycles, for coverage and performance.
    longint unsigned ar_cycle, first_cycle, last_cycle;
    int unsigned     stall_cycles;       // edges with RVALID HIGH, RREADY LOW
    int unsigned     outstanding_at_ar;  // reads already open at this AR
    int unsigned     same_id_ahead;      // of those, how many share this ID

    // INCR, 4-byte beats (ARSIZE = 2) on a 32-bit bus, so every lane is
    // active on every beat. Few IDs make same-ID reuse common.
    constraint c_shape {
      id inside {[0:3]};
      len inside {[0:7]};
      addr[1:0] == 2'b00;
      addr dist {[32'h0000_0000:32'h0000_2FFF] :/ 85,
                 [32'h0000_3000:32'h0000_30FF] :/ 15};
      (addr % 4096) + (len + 1) * 4 <= 4096;     // never cross 4KB (A3.4.1)
    }

    function new(string name = "axi_rd_item");
      super.new(name);
    endfunction

    function string convert2string();
      return $sformatf("id=%0d addr=0x%08h len=%0d beats=%0d",
                       id, addr, len, data.size());
    endfunction

    // "" when act matches this expected read, else the first difference.
    // Each beat's response is compared first. RDATA is compared only on OKAY
    // and EXOKAY beats: A3.4.4 sets no RDATA value for SLVERR or DECERR.
    function string diff(axi_rd_item act);
      if (act.id != id || act.addr != addr || act.len != len)
        return $sformatf("header: exp %s, act %s",
                         convert2string(), act.convert2string());
      if (act.data.size() != data.size())
        return $sformatf("beat count: exp %0d, act %0d",
                         data.size(), act.data.size());
      foreach (data[i]) begin
        if (act.resp[i] != resp[i])
          return $sformatf("beat %0d resp: exp %0d, act %0d",
                           i, resp[i], act.resp[i]);
        if (!resp[i][1] && act.data[i] != data[i])
          return $sformatf("beat %0d data: exp 0x%08h, act 0x%08h",
                           i, data[i], act.data[i]);
      end
      return "";
    endfunction
  endclass

  // Master: issues ARs up to an outstanding window, drives a random RREADY.
  class axi_rd_master_drv extends uvm_driver #(axi_rd_item);
    `uvm_component_utils(axi_rd_master_drv)
    virtual axi_rd_if vif;
    axi_rd_cfg        cfg;
    int unsigned      outstanding;      // AR handshakes not yet ended by RLAST

    function new(string name, uvm_component parent);
      super.new(name, parent);
    endfunction

    function void build_phase(uvm_phase phase);
      super.build_phase(phase);
      if (!uvm_config_db#(virtual axi_rd_if)::get(this, "", "vif", vif))
        `uvm_fatal("NO_VIF", "virtual interface not set")
      if (!uvm_config_db#(axi_rd_cfg)::get(this, "", "cfg", cfg))
        `uvm_fatal("NO_CFG", "axi_rd_cfg not set")
    endfunction

    task run_phase(uvm_phase phase);
      bit         ar_vld, r_rdy;        // what this driver drives this cycle
      axi_rd_item it;
      do @(vif.mst_cb); while (!vif.mst_cb.ARESETn);   // start after reset
      forever begin
        // Handshakes at this edge: our own outputs plus the sampled inputs.
        if (ar_vld && vif.mst_cb.ARREADY) begin
          ar_vld = 0;
          outstanding++;
          seq_item_port.item_done();       // the AR has been accepted
        end
        if (r_rdy && vif.mst_cb.RVALID && vif.mst_cb.RLAST && outstanding > 0)
          outstanding--;
        // ARVALID never waits for ARREADY (A3.3.1). It waits only for room in
        // the outstanding window, which is the master's own choice.
        if (!ar_vld && outstanding < cfg.max_outstanding) begin
          seq_item_port.try_next_item(it);
          if (it != null) begin
            vif.mst_cb.ARID    <= it.id;
            vif.mst_cb.ARADDR  <= it.addr;
            vif.mst_cb.ARLEN   <= it.len;
            vif.mst_cb.ARSIZE  <= 3'd2;     // 4-byte beats
            vif.mst_cb.ARBURST <= 2'b01;    // INCR
            ar_vld = 1;
          end
        end
        vif.mst_cb.ARVALID <= ar_vld;
        // A random RREADY is legal (A3.3.1) and makes the slave hold R.
        r_rdy = ($urandom_range(99) < cfg.rready_pct);
        vif.mst_cb.RREADY <= r_rdy;
        @(vif.mst_cb);
      end
    endtask
  endclass

  // Responder: a reordering, interleaving slave with random ARREADY, random
  // R gaps and an SLVERR window. It stands in for the slave DUT.
  class axi_rd_responder extends uvm_component;
    `uvm_component_utils(axi_rd_responder)

    typedef struct {
      bit [3:0]    id;
      bit [31:0]   addr;
      int unsigned beats;               // ARLEN + 1
      int unsigned sent;                // beats already transferred
      bit          bad_rid;             // WRONG_RID: send every beat with a bad ID
    } rd_req_t;

    virtual axi_rd_if vif;
    axi_rd_cfg        cfg;
    rd_req_t          pend[int unsigned][$];   // per ARID, arrival order
    int unsigned      n_accepted;              // AR handshakes so far
    bit               mutated;                 // each mutant fires once

    function new(string name, uvm_component parent);
      super.new(name, parent);
    endfunction

    function void build_phase(uvm_phase phase);
      super.build_phase(phase);
      if (!uvm_config_db#(virtual axi_rd_if)::get(this, "", "vif", vif))
        `uvm_fatal("NO_VIF", "virtual interface not set")
      if (!uvm_config_db#(axi_rd_cfg)::get(this, "", "cfg", cfg))
        `uvm_fatal("NO_CFG", "axi_rd_cfg not set")
    endfunction

    task run_phase(uvm_phase phase);
      bit          ar_rdy, r_vld;       // what this responder drives
      int unsigned cur;                 // ARID of the beat on R
      do @(vif.slv_cb); while (!vif.slv_cb.ARESETn);
      forever begin
        if (ar_rdy && vif.slv_cb.ARVALID) accept_ar();
        if (r_vld && vif.slv_cb.RREADY) begin   // the beat on R was taken
          r_vld = 0;
          beat_done(cur);
        end
        // Start a beat only when none is waiting: RVALID and the payload
        // hold until the handshake (A3.2.1). Random gaps idle the channel.
        if (!r_vld && $urandom_range(99) >= cfg.r_gap_pct) next_beat(cur, r_vld);
        vif.slv_cb.RVALID <= r_vld;
        // ARREADY is random; it may fall before ARVALID rises (A3.2.1).
        ar_rdy = ($urandom_range(99) < cfg.ar_ready_pct);
        vif.slv_cb.ARREADY <= ar_rdy;
        @(vif.slv_cb);
      end
    endtask

    function void accept_ar();
      rd_req_t r;
      r.id    = vif.slv_cb.ARID;
      r.addr  = vif.slv_cb.ARADDR;
      r.beats   = vif.slv_cb.ARLEN + 1;
      r.sent    = 0;
      r.bad_rid = 0;
      pend[r.id].push_back(r);          // behind older reads with this ID
      n_accepted++;
    endfunction

    // Only the oldest read of each ID may send (same-ID order, A5.3.1). Any
    // ID may go next, so reads overtake and, with interleave set, the RID
    // can change between the beats of one burst (A5.3.1).
    task next_beat(inout int unsigned cur, output bit vld);
      int unsigned ids[$];
      rd_req_t     h;
      bit [31:0]   a;
      vld = 0;
      if (!cfg.interleave && pend.exists(cur) && pend[cur].size() > 0 &&
          pend[cur][0].sent > 0)
        ids.push_back(cur);             // finish the burst under way
      else
        foreach (pend[i]) if (pend[i].size() > 0) ids.push_back(i);
      if (ids.size() == 0) return;
      cur = ids[$urandom_range(ids.size() - 1)];
      inject_swap(cur);
      inject_wrong_rid(cur);
      h = pend[cur][0];
      a = h.addr + 4 * h.sent;          // INCR, 4-byte beats
      vif.slv_cb.RID   <= h.bad_rid ? cur ^ 8 : cur;
      vif.slv_cb.RDATA <= axi_mem_model::data_at(a);   // not compared on SLVERR
      vif.slv_cb.RRESP <= axi_mem_model::resp_at(cfg, a);   // per beat
      vif.slv_cb.RLAST <= last_flag(h);
      vld = 1;
    endtask

    function void beat_done(int unsigned id);
      pend[id][0].sent++;
      if (pend[id][0].sent < pend[id][0].beats) return;
      void'(pend[id].pop_front());
      inject_extra_beat(id);
    endfunction

    // ---- Mutants: each breaks one rule once, to prove the checks see it.
    function void inject_swap(int unsigned id);           // SAME_ID_SWAP
      rd_req_t t;
      if (cfg.mutant != "SAME_ID_SWAP" || mutated || pend[id].size() < 2) return;
      if (pend[id][0].sent != 0 || pend[id][1].sent != 0) return;
      // Two equal-length reads answered SLVERR on every beat cannot be told
      // apart (RDATA is not compared there). To stay simple, skip every pair
      // whose reads both start in the error window.
      if (axi_mem_model::resp_at(cfg, pend[id][0].addr) != RESP_OKAY &&
          axi_mem_model::resp_at(cfg, pend[id][1].addr) != RESP_OKAY) return;
      t           = pend[id][0];
      pend[id][0] = pend[id][1];        // the younger read answers first
      pend[id][1] = t;
      mutated     = 1;
    endfunction

    // WRONG_RID marks one read so all its beats carry an ID never issued
    // (8..15). It waits for the last AR and picks a read that is the last
    // with its ID, so no later read is attributed to the stale monitor entry.
    function void inject_wrong_rid(int unsigned id);      // WRONG_RID
      if (cfg.mutant != "WRONG_RID" || mutated) return;
      if (n_accepted != cfg.n_reads || pend[id].size() != 1) return;
      if (pend[id][0].sent != 0) return;
      pend[id][0].bad_rid = 1;
      mutated = 1;
    endfunction

    function bit last_flag(rd_req_t h);                   // DROP_RLAST
      bit last = (h.sent + 1 == h.beats);
      if (last && h.beats > 1 && cfg.mutant == "DROP_RLAST" && !mutated) begin
        mutated = 1;
        return 0;                       // the final beat goes out without RLAST
      end
      return last;
    endfunction

    function void inject_extra_beat(int unsigned id);     // EXTRA_BEAT
      rd_req_t ghost;
      if (cfg.mutant != "EXTRA_BEAT" || mutated || pend[id].size() != 0) return;
      ghost.id    = id;
      ghost.addr  = 32'h0;
      ghost.beats   = 1;                // one more beat, with RLAST, nobody asked for
      ghost.sent    = 0;
      ghost.bad_rid = 0;
      pend[id].push_back(ghost);
      mutated = 1;
    endfunction
  endclass

  // Monitor: rebuilds reads from AR and R handshakes. Records, never judges
  // a response: SLVERR and DECERR are legal (A3.4.4).
  class axi_rd_monitor extends uvm_monitor;
    `uvm_component_utils(axi_rd_monitor)
    virtual axi_rd_if vif;
    uvm_analysis_port #(axi_rd_item) req_ap;   // each AR, at its handshake
    uvm_analysis_port #(axi_rd_item) ap;       // each completed read
    axi_rd_item      open_q[int unsigned][$];  // per ARID: a queue, never a slot
    int unsigned     n_open;                   // open reads, all IDs
    longint unsigned cycle;                    // ACLK edges since time 0

    function new(string name, uvm_component parent);
      super.new(name, parent);
      req_ap = new("req_ap", this);
      ap     = new("ap", this);
    endfunction

    function void build_phase(uvm_phase phase);
      super.build_phase(phase);
      if (!uvm_config_db#(virtual axi_rd_if)::get(this, "", "vif", vif))
        `uvm_fatal("NO_VIF", "virtual interface not set")
    endfunction

    task run_phase(uvm_phase phase);
      forever begin
        @(vif.mon_cb);
        cycle++;
        if (!vif.mon_cb.ARESETn) begin
          open_q.delete();              // reset policy: drop open reads, never publish
          n_open = 0;
        end else begin
          // R first: a beat at this edge can only belong to a read whose AR
          // handshake happened at an earlier edge (A3.3.1).
          if (vif.mon_cb.RVALID)                        on_r_valid();
          if (vif.mon_cb.RVALID && vif.mon_cb.RREADY)   on_r_beat();
          if (vif.mon_cb.ARVALID && vif.mon_cb.ARREADY) on_ar();
        end
      end
    endtask

    function void on_ar();
      axi_rd_item t  = axi_rd_item::type_id::create("t");
      axi_rd_item rq = axi_rd_item::type_id::create("rq");
      if (vif.mon_cb.ARSIZE != 3'd2 || vif.mon_cb.ARBURST != 2'b01)
        `uvm_error("UNSUPPORTED", "this environment models INCR, 4-byte reads only")
      t.id                = vif.mon_cb.ARID;
      t.addr              = vif.mon_cb.ARADDR;
      t.len               = vif.mon_cb.ARLEN;
      t.ar_cycle          = cycle;
      t.outstanding_at_ar = n_open;
      t.same_id_ahead     = open_q.exists(t.id) ? open_q[t.id].size() : 0;
      open_q[t.id].push_back(t);        // same-ID reads may repeat (A5.3.1)
      n_open++;
      rq.id   = t.id;                   // a separate object for the predictor:
      rq.addr = t.addr;                 // t keeps changing as beats arrive
      rq.len  = t.len;
      req_ap.write(rq);
    endfunction

    // RVALID at this edge: note when the slave first offered data, and count
    // the edges the master stalled it (RREADY LOW).
    function void on_r_valid();
      int unsigned id = vif.mon_cb.RID;
      axi_rd_item  t;
      if (!open_q.exists(id) || open_q[id].size() == 0) return;  // see on_r_beat
      t = open_q[id][0];
      if (t.first_cycle == 0) t.first_cycle = cycle;   // 0 means "not yet"
      if (!vif.mon_cb.RREADY) t.stall_cycles++;
    endfunction

    function void on_r_beat();
      int unsigned id = vif.mon_cb.RID;
      axi_rd_item  t;
      bit          last_expected;
      if (!open_q.exists(id) || open_q[id].size() == 0) begin
        `uvm_error("UNEXPECTED_R",
                   $sformatf("RID %0d with no outstanding read (A5.3.1)", id))
        return;
      end
      t = open_q[id][0];                // same-ID data returns in order (A5.3.1)
      t.data.push_back(vif.mon_cb.RDATA);
      t.resp.push_back(vif.mon_cb.RRESP);       // recorded here, judged later
      last_expected = (t.data.size() == t.len + 1);
      if (vif.mon_cb.RLAST != last_expected)
        `uvm_error("RLAST", $sformatf("RID %0d: RLAST=%0b on beat %0d of %0d (A3.2.2)",
                   id, vif.mon_cb.RLAST, t.data.size(), t.len + 1))
      // Close on RLAST or on the last expected beat: one fault, one error.
      if (vif.mon_cb.RLAST || last_expected) begin
        t.last_cycle = cycle;
        void'(open_q[id].pop_front());
        n_open--;
        ap.write(t);                    // a new object per read, never reused
      end
    endfunction
  endclass

  // Predictor: at each AR, computes every expected beat and response.
  class axi_rd_predictor extends uvm_subscriber #(axi_rd_item);
    `uvm_component_utils(axi_rd_predictor)
    uvm_analysis_port #(axi_rd_item) exp_ap;
    axi_rd_cfg cfg;

    function new(string name, uvm_component parent);
      super.new(name, parent);
      exp_ap = new("exp_ap", this);
    endfunction

    function void build_phase(uvm_phase phase);
      super.build_phase(phase);
      if (!uvm_config_db#(axi_rd_cfg)::get(this, "", "cfg", cfg))
        `uvm_fatal("NO_CFG", "axi_rd_cfg not set")
    endfunction

    function void write(axi_rd_item t);
      axi_rd_item e = axi_rd_item::type_id::create("e");
      e.id   = t.id;
      e.addr = t.addr;
      e.len  = t.len;
      for (int unsigned k = 0; k <= t.len; k++) begin
        e.data.push_back(axi_mem_model::data_at(t.addr + 4 * k));
        e.resp.push_back(axi_mem_model::resp_at(cfg, t.addr + 4 * k));
      end
      exp_ap.write(e);
    endfunction
  endclass

  // Scoreboard: one ordered queue of expected reads per ARID.
  class axi_rd_scoreboard extends uvm_scoreboard;
    `uvm_component_utils(axi_rd_scoreboard)
    uvm_analysis_imp_exp #(axi_rd_item, axi_rd_scoreboard) exp_imp;
    uvm_analysis_imp_act #(axi_rd_item, axi_rd_scoreboard) act_imp;
    axi_rd_item  exp_q[int unsigned][$];
    int unsigned n_match, n_mismatch, n_pending;

    function new(string name, uvm_component parent);
      super.new(name, parent);
      exp_imp = new("exp_imp", this);
      act_imp = new("act_imp", this);
    endfunction

    function void write_exp(axi_rd_item e);
      exp_q[e.id].push_back(e);         // the predictor built a new object
      n_pending++;
    endfunction

    function void write_act(axi_rd_item a);
      axi_rd_item e;
      string      d;
      if (!exp_q.exists(a.id) || exp_q[a.id].size() == 0) begin
        `uvm_error("SCB_UNEXPECTED", $sformatf("no expected read for %s",
                                               a.convert2string()))
        return;
      end
      e = exp_q[a.id].pop_front();      // the oldest read with this ID (A5.3.1)
      n_pending--;
      d = e.diff(a);
      if (d == "") n_match++;
      else begin
        n_mismatch++;
        `uvm_error("SCB_MISMATCH", $sformatf("ID %0d addr 0x%08h: %s",
                                             e.id, e.addr, d))
      end
    endfunction

    // End-of-test accounting: a read that never completed is a failure.
    function void check_phase(uvm_phase phase);
      super.check_phase(phase);
      foreach (exp_q[id])
        if (exp_q[id].size() != 0)
          `uvm_error("SCB_PENDING", $sformatf("ID %0d: %0d read(s) never completed",
                                              id, exp_q[id].size()))
    endfunction

    function void report_phase(uvm_phase phase);
      super.report_phase(phase);
      `uvm_info("SCB_SUMMARY", $sformatf("matches=%0d mismatches=%0d pending=%0d",
                n_match, n_mismatch, n_pending), UVM_NONE)
    endfunction
  endclass

  // Coverage: one sample per completed read.
  class axi_rd_cov extends uvm_subscriber #(axi_rd_item);
    `uvm_component_utils(axi_rd_cov)

    covergroup cg with function sample(bit [7:0] len, int unsigned ahead,
                                       int unsigned depth, bit err, bit stalled);
      cp_len:   coverpoint len   { bins single = {0}; bins short_b = {[1:3]};
                                   bins long_b = {[4:7]}; }
      cp_ahead: coverpoint ahead { bins fresh = {0}; bins one = {1};
                                   bins two_plus = {[2:$]}; }
      cp_depth: coverpoint depth { bins idle = {0}; bins some = {[1:3]};
                                   bins deep = {[4:$]}; }
      cp_err:   coverpoint err;
      cp_stall: coverpoint stalled;
      x_len_ahead: cross cp_len, cp_ahead;   // same-ID reuse at every length
      x_err_len:   cross cp_err, cp_len;     // errors on short and long bursts
    endgroup

    function new(string name, uvm_component parent);
      super.new(name, parent);
      cg = new();
    endfunction

    function void write(axi_rd_item t);
      bit err = 0;
      foreach (t.resp[i]) if (t.resp[i] inside {2'b10, 2'b11}) err = 1;
      cg.sample(t.len, t.same_id_ahead, t.outstanding_at_ar, err,
                t.stall_cycles > 0);
    endfunction

    function void report_phase(uvm_phase phase);
      super.report_phase(phase);
      `uvm_info("COV", $sformatf("read coverage %0.1f%%", cg.get_coverage()),
                UVM_NONE)
    endfunction
  endclass

  // Performance: latency, stalls, bandwidth and mean outstanding, in cycles.
  class axi_rd_perf extends uvm_subscriber #(axi_rd_item);
    `uvm_component_utils(axi_rd_perf)
    int unsigned     n, lat_min, lat_max;
    longint unsigned lat_sum, beats, stalls, busy_sum, first_ar, last_r;

    function new(string name, uvm_component parent);
      super.new(name, parent);
    endfunction

    function void write(axi_rd_item t);
      // Slave latency: AR handshake edge to the first edge with RVALID HIGH.
      // Master stalls are counted apart, so RREADY never inflates it.
      int unsigned lat = t.first_cycle - t.ar_cycle;
      if (n == 0 || lat < lat_min)        lat_min  = lat;
      if (lat > lat_max)                  lat_max  = lat;
      if (n == 0 || t.ar_cycle < first_ar) first_ar = t.ar_cycle;
      if (t.last_cycle > last_r)          last_r   = t.last_cycle;
      lat_sum  += lat;
      beats    += t.data.size();
      stalls   += t.stall_cycles;
      busy_sum += t.last_cycle - t.ar_cycle;   // cycles this read was open
      n++;
    endfunction

    function void report_phase(uvm_phase phase);
      longint unsigned window;
      super.report_phase(phase);
      if (n == 0) return;
      window = last_r - first_ar;               // first AR edge to last RLAST edge
      `uvm_info("PERF", $sformatf(
        "reads=%0d latency min/avg/max=%0d/%0.1f/%0d stalls=%0d",
        n, lat_min, real'(lat_sum) / n, lat_max, stalls), UVM_NONE)
      `uvm_info("PERF", $sformatf(
        "window=%0d cycles bandwidth=%0.2f bytes/cycle mean_outstanding=%0.1f",
        window, 4.0 * beats / window, real'(busy_sum) / window), UVM_NONE)
    endfunction
  endclass
```

How to read the less obvious logs:
- **`SAME_ID_SWAP` with different lengths.** The younger read's two beats go to the older read's entry, and its RLAST closes that entry two beats early: the first `RLAST` error, and a `beat count` mismatch. The first two beats of the older read then fill the younger read's entry, which closes on its last expected beat without RLAST: the second `RLAST` error, and a `beat 0 data` mismatch. The older read's last two beats have no open read left, so each raises `UNEXPECTED_R`; if another read with ID 2 were open, they would go to it and give a further mismatch instead.
- **`EXTRA_BEAT`.** The extra beat raises `UNEXPECTED_R` when no read with its ID is open. If a new read with that ID was accepted before the extra beat went out, the beat is attributed to that read instead, and the log shows `RLAST` or `SCB_MISMATCH`. The extra beat also carries RLAST, so the checker's `rlast_done` counts one more read completion than really happened and stays one ahead of `ar_done` for the rest of the run. `a_r_after_ar` then fires at the extra beat itself if no real read is open, and later at every RVALID edge with exactly one real read in flight, which always happens near the end of the run. `AXI_CHK` comes from an assertion in an interface, not from a component, so the log shows UVM's top-level reporter, named `reporter`.
- **`WRONG_RID`.** The answered read never receives a beat, so it stays open in the monitor and expected in the scoreboard; the test waits `EOT_TIMEOUT` cycles, warns, and end-of-test accounting reports it.

Every mutant run fails, which is the point.

**Run it.** Compile `tb_top.sv` with `tb_top` as the top module in a simulator that supports IEEE 1800.2 UVM (uvm-core 2020.3.1 or your vendor's library), concurrent assertions and covergroups. The test name is already passed to `run_test`; `+UVM_TESTNAME=axi_rd_test` would override it (IEEE 1800.2-2020 Annex G.2.1). Run once without plusargs, then once with each of `+MUTANT=SAME_ID_SWAP`, `+MUTANT=DROP_RLAST`, `+MUTANT=EXTRA_BEAT` and `+MUTANT=WRONG_RID`. `MUTANT` is this testbench's own plusarg, read with `$value$plusargs` (IEEE 1800-2023 §21.6). Change the seed with your simulator's seed option (tool-dependent) and confirm the clean run stays clean. UVM, assertion and coverage support in open-source simulators varies by tool and version (tool-dependent); this example has not been run on one.

### How to build an AXI checking environment, step by step

1. **Write the interface first**, with a clocking block for each role (monitor, master, slave). Everything that samples uses the monitor clocking block.
2. **Write the monitor and run it on a passive bench.** Per-ID queues for reads; AW and W FIFOs plus per-AWID queues for writes. Process response channels before request channels at each edge. Publish a new object per transaction.
3. **Write the predictor and reference model.** Predict at the request; produce data and a response per beat. Make data a function of the address, so reads of different addresses never compare equal by accident.
4. **Write the scoreboard** with one ordered queue per ID, `exists()` before every read of the array, a value compare that names the first difference, `check_phase` accounting and the `SCB_SUMMARY` line.
5. **Bind the checker**: B-AXI-1's channel checks (hold, stability, reset, dependencies), plus the burst and X checks, each labelled `[Protocol §]` or `[Policy]`. The Make It Work checker has only the second group; the kata "Close the hold gap" adds the read-path hold and stability checks.
6. **Write the responder** with random READY, reordering, interleaving and an error window, and the master with an outstanding window and random RREADY.
7. **Add coverage and performance subscribers** on the monitor's port.
8. **Prove the checks with mutants.** One mutant per rule you claim to check; each must produce at least one named error, and the clean run must stay clean across seeds.

### Debugging AXI checking failures

| Symptom | Likely cause | Fix |
|---|---|---|
| `UNEXPECTED_R` or "no pending write" on a correct DUT, only when traffic is heavy | one slot per ID: a second same-ID request overwrote the first | per-ID queues (`open_q[id][$]`) |
| `SCB_MISMATCH` on a correct DUT that reorders across IDs | one queue for all IDs, in the monitor or the scoreboard | key every queue by ID |
| `SCB_MISMATCH` where the "actual" is the previous read's data | monitor reused one handle and kept writing into it after publishing | `type_id::create` a new object for every transaction |
| `WLAST` errors only when W arrives before AW | the monitor drops or misfiles W beats while no AW is queued | hold complete W bursts in `w_bursts` until an AW arrives |
| A slave that answers a read in the same cycle as its AR handshake is not flagged by the monitor | AR (or AW) processed before R (or B) at the same edge, so the new read is already open when the beat is processed | process R (and B) before AR (and AW) |
| One `UNEXPECTED_R`, then `SCB_MISMATCH` and `RLAST` errors on later reads of one ID | the slave answered a read with a wrong RID; that read stays at the head of `open_q[ID]`, and later reads of that ID are attributed to it | debug the first error; the later ones are its consequences |
| Errors on every narrow write | whole-bus X check or whole-bus compare | gate by WSTRB, compare only active lanes |
| `uvm_error` on every error-injection test | the monitor flags SLVERR or DECERR | record responses; let the scoreboard compare them with the prediction |
| `SCB_MISMATCH ... beat k data` on a predicted SLVERR beat, only with a real slave | the scoreboard compares RDATA on error beats, where IHI0022E sets no value | compare the response first; skip RDATA on SLVERR and DECERR beats |
| A test that passes with zero reads, or with reads that never returned | no end-of-test accounting, or the test ends on a fixed delay | `check_phase` leftovers and a compared-count check; wait on `n_pending` with a cycle timeout |
| Latency looks long only when RREADY is random | master stalls counted as slave latency | measure AR to first RVALID; count stalls separately |
| `NO_VIF` fatal at build | the `uvm_config_db` scope does not match the component's full name | set with `"uvm_test_top*"` or set from the test for `"env.*"` |

## Push Further

### Expert: monitors on both sides of an interconnect

An SoC environment puts a passive monitor on every master port and every slave port of an interconnect and scoreboards the hops end to end. The orders differ by side:
- **IDs grow.** The interconnect appends master-port bits to ARID and AWID and strips them from RID and BID on the way back (§A5.3.5). A slave-side scoreboard keys on the wide ID; an end-to-end scoreboard must map master-side `(port, ID)` to slave-side IDs, and must not assume the mapping is "append bits": an interconnect may remap IDs, provided "the ordering requirements of the original ID values are maintained" (§A6.3).
- **W order is per slave.** When the interconnect merges writes from several masters to one slave, "it must ensure that it forwards the write data in address order" (§A5.3.2), so the slave-side monitor pairs W with AW in the order AWs *arrive at that slave*, which differs from any one master's order. The pairing code is the same; only the stream differs.
- **Same-ID reads to two slaves.** The interconnect must return them to the master in issue order (§A5.3.1), so a master-side scoreboard still pops the oldest read per ID, even though the two slaves answered in the other order.
- **Unmapped addresses.** The interconnect must answer DECERR, typically from a default slave, and "the AXI protocol requires that all data transfers for a transaction are completed, even if an error condition occurs" (§A3.4.4). A default slave that answers B without accepting the W beats leaves the master's W channel stuck. The predictor predicts DECERR from the address map; the checker checks that every beat still transferred.

### Expert: read-after-write races and the reference memory

The Make It Work memory never changes, so every read has one correct answer. With writes, it does not:
- "AXI has no ordering restrictions between read and write transactions", even with ARID equal to AWID (§A5.3.4). A read issued while an overlapping write is outstanding may return the old or the new data.
- A slave must make a write for which it "has issued a response" observed by "any subsequent write or read transaction, regardless of the transaction IDs" (§A6.4), and an intermediate component that responds early must keep that visibility (§A6.5). So a read whose AR comes after the write's B must see the new data, or something written later.
- A multi-beat write may update memory in pieces of the **single-copy atomicity size**, which "the AXI4 protocol does not require" to be any specific value: it is a property of the system (§A7.1). A racing read may see some blocks new and some old.

So the reference model keeps, per atomic block, the **set of legal values** (the last value observed as complete, plus every in-flight write's value) and accepts any member; at each B it collapses the set for later reads. The predictor therefore needs B times and AR times, which is why a production predictor subscribes to both the request and response streams. [B-AXI-3](/curriculum/T3_Advanced/B-AXI-3_AXI_Ordering_and_IDs/index) states the ordering rules; this is the scoreboard that applies them.

### Expert: coverage closure at scale

- **Targeted crosses only.** Cross what interacts: length × same-ID reuse, response × length, stall × outstanding depth. Use `ignore_bins` for combinations that cannot occur in this DUT (IEEE 1800-2023 §19.6.2) and `illegal_bins` for combinations the protocol forbids (§19.6.3), and use cross-bin selection to name only the cells you care about (§19.6.1). On a single coverpoint's values the same keywords are §19.5.5 and §19.5.6.
- **Transitions.** Back-to-back same-ID reads, or an error followed at once by a normal read, are **transition bins** over successive samples (§19.5.2), not crosses.
- **Sample at the right time.** Outstanding depth must be recorded at the AR handshake; sampled at completion, it measures something else. The covergroup in Make It Work takes those values as `sample()` arguments recorded by the monitor (§19.8.1).
- **Reachability is a design parameter.** A slave's read reordering depth is "a static value that must be specified by the designer of the slave", and no master can discover it (§A5.3.1). So reordering coverage targets come from the DUT's documentation; a bin above that depth is unreachable and belongs in `ignore_bins` with a comment, not in a waiver spreadsheet.
- **Closing holes.** A hole in `x_len_ahead` at long bursts with two same-ID reads ahead needs stimulus that keeps reads queued: fewer IDs, a deeper window, a slower responder. Random seeds alone close it only by luck. [I-SV-3B](/curriculum/T2_Intermediate/I-SV-3B_Advanced_Functional_Coverage/index) covers closure strategy in general.

### Expert: performance verification

- **Distributions, not averages.** Keep a latency histogram per ID or per QoS class; a mean hides the long tail that a real-time master cares about. Report percentiles over a stated window, in cycles.
- **Attribution.** Split each read's life into slave latency, RVALID gaps (slave), and RVALID-and-not-RREADY cycles (master). A bandwidth shortfall is then traceable to one side.
- **Little's law** (a queueing identity, not an AXI rule): mean outstanding = throughput × mean time open. If each read of S bytes stays open for L cycles and the window allows N reads open at once, read throughput is at most N × S / L bytes per cycle. The Make It Work `mean_outstanding` checks the identity on real traffic.
- **QoS is a hint.** AxQOS is a 4-bit value whose use "the protocol does not specify"; the specification recommends treating it as a priority, higher meaning more urgent (§A8.1.1). Any fairness or starvation bound is a system contract, checked as such.
- **Monitor cost.** A monitor that creates and publishes an object per beat costs more simulation time than one per transaction; how much more is **tool-dependent**. Publish per transaction, and give beat-level detail only to subscribers that need it.

### Expert: tool-dependent behaviour

- **Commercial AXI VIP and protocol-checker packs** exist from the major simulator vendors and from Arm; their feature sets, check names and configuration switches differ by vendor and version (**tool-dependent**). Before trusting one, read which rules it checks, which it leaves to the user, and what it does with SLVERR by default.
- **2-state simulation.** If signals are declared 2-state, or a simulator option makes them 2-state, X cannot exist, so every `$isunknown` policy check always passes, and so checks nothing (**tool-dependent** options). Keep interface signals `logic`.
- **Assertion messages.** An assertion's action block that calls `` `uvm_error `` needs `import uvm_pkg::*` and the macros in that scope; its messages are then counted in the UVM report summary. Assertion failures reported by the simulator's default action (`$error`) are counted by the simulator, not by UVM, and may not fail the UVM test unless you connect them (**tool-dependent**; [A-UVM-7](/curriculum/T3_Advanced/A-UVM-7_VIP_Construction/index) shows both).
- **Binding into an interface.** When the bind target is an interface, the bound unit must be an interface or a checker, not a module (IEEE 1800-2023 §23.11). That is why `axi_rd_checker` is an `interface`.

### Kata: pair the W bursts

These handshakes are seen at one AXI4 slave interface, in edge order. All READY signals are HIGH.

| Edge | Handshake |
|---|---|
| 1 | W `d0` |
| 2 | W `d1`, WLAST |
| 3 | AW P: AWID 0, AWLEN 1 |
| 4 | AW Q: AWID 0, AWLEN 3 |
| 5 | W `e0` |
| 6 | W `e1` |
| 7 | W `e2`, WLAST |
| 8 | AW R: AWID 1, AWLEN 0 |
| 9 | B: BID 0 |
| 10 | W `f0`, WLAST |
| 11 | B: BID 1 |
| 12 | B: BID 0 |

Using the `on_aw`, `on_w_beat`, `pair` and `on_b` functions from the write-monitor section (write them yourself first, with plain queues if you like), fill in, for each write: its W burst, the result of the WLAST check, and which B completes it. Then write the one error line the monitor prints.

<details>
<summary>Worked solution</summary>

| Write | W burst | WLAST check | Completed by |
|---|---|---|---|
| P (AWID 0, 2 beats) | `d0 d1` (held from edge 2 until P arrives at edge 3) | 2 beats = AWLEN 1 + 1: pass | B at edge 9, the oldest AWID 0 write |
| Q (AWID 0, 4 beats) | `e0 e1 e2` (paired at edge 7) | 3 beats, expected 4: **error** | B at edge 12 |
| R (AWID 1, 1 beat) | `f0` (paired at edge 10) | 1 beat = AWLEN 0 + 1: pass | B at edge 11 |

The error line: `WLAST AWID 0: WLAST on beat 3 of 4`. The monitor still pairs the burst and moves Q to `open_b[0]`, so the B at edge 12 completes it and the error is reported once. Every B is legal for AXI4: each follows its write's AW and WLAST handshakes (§A3.3.1). The structures after each edge: after edge 2 `w_bursts` holds `d0 d1`; edge 3 pairs it with P; edge 4 queues Q in `aw_q`; edge 7 pairs Q; edge 8 queues R; edge 9 pops P from `open_b[0]`; edge 10 pairs R; edge 11 pops R; edge 12 pops Q.

</details>

### Kata: close the hold gap

Quiz question 9 calls a responder that lowers RVALID before the handshake a protocol violation, yet the Make It Work environment cannot see it: the monitor sees no handshake, and `axi_rd_checker` has no hold check. Add the read-path hold and stability checks to `axi_rd_checker`, in its style (its default clocking and `disable iff`, and `` `uvm_error `` with the id `AXI_CHK`), using B-AXI-1's rules: VALID stays HIGH until the handshake, and the information it qualifies stays stable (§A3.2.1). Then answer: which input does the checker lack, and which responder change would fire each new check? None of the four mutants does.

<details>
<summary>Worked solution</summary>

```systemverilog
// snippet: add inside axi_rd_checker, after its default clocking and disable.
// [Protocol A3.2.1] Once VALID is HIGH it stays HIGH until the handshake,
// and the source keeps its information stable (B-AXI-1's p_hold, p_stable).
a_ar_hold:   assert property (ARVALID && !ARREADY |=> ARVALID)
  else `uvm_error("AXI_CHK", "ARVALID dropped before its handshake (A3.2.1)")
a_ar_stable: assert property (ARVALID && !ARREADY
                              |=> $stable({ARID, ARADDR, ARLEN, ARSIZE, ARBURST}))
  else `uvm_error("AXI_CHK", "AR information changed during a stall (A3.2.1)")
a_r_hold:    assert property (RVALID && !RREADY |=> RVALID)
  else `uvm_error("AXI_CHK", "RVALID dropped before its handshake (A3.2.1)")
a_r_stable:  assert property (RVALID && !RREADY
                              |=> $stable({RID, RDATA, RRESP, RLAST}))
  else `uvm_error("AXI_CHK", "R information changed during a stall (A3.2.1)")
```

- `|=>` is non-overlapping implication: the right side is checked at the next edge (IEEE 1800-2023 §16.12.7). `$stable` is true when the sampled value equals the one at the previous edge (§16.9.3).
- The missing input is `RDATA`. Add `input logic [31:0] RDATA` to the port list; the `bind ... (.*)` line then connects it, because `axi_rd_if` has a signal with that name.
- What would fire them: a responder that clears `r_vld` while RREADY is LOW fires `a_r_hold`; one that calls `next_beat` while a beat is still waiting fires `a_r_stable`; a master driver that drives a new item while its AR waits fires `a_ar_stable`. The Make It Work components hold by construction, so the clean run stays clean.
- B-AXI-1 also checks that every VALID is LOW during reset; that check needs its own `disable iff`, because this checker's default one turns every check off during reset.

</details>

### Kata: turn the knobs

A test changes two knobs of the Make It Work bench, `cfg.rready_pct = 100` and `cfg.interleave = 0`, and leaves the rest at their defaults. Predict, before you look:
1. the `stalls=` value on the first `PERF` line;
2. which bin of `cp_stall` stays empty, and what that does to the `COV` line;
3. which coverpoint shows that the responder stopped interleaving;
4. the `SCB_SUMMARY` line.

<details>
<summary>Worked answer</summary>

1. `stalls=0`. A stall is an edge with RVALID HIGH and RREADY LOW, and `$urandom_range(99) < 100` is always true, so once the master runs, RREADY is HIGH at every edge.
2. The bin for `stalled = 1` is never hit, so `cp_stall` is at 50% and the `read coverage` figure drops. That is the right reading: this run never tested the slave's hold logic.
3. None. No coverpoint records whether another ID's beat came between a read's first and last beat, so the model cannot tell that interleaving stopped. A coverage model measures only what it samples; to cover interleaving, the monitor must record it per read (for example, the number of other-ID beats between the first and the last beat), and a coverpoint must sample that value.
4. Unchanged: `matches=40 mismatches=0 pending=0`. Knobs change the traffic, not what is correct. A run that passes is not a run that tested much, which is why the knobs and the coverage model are reviewed together.

</details>

### Debug challenge: the one-slot monitor

This is the core of a monitor that an earlier version of this lesson taught:

```systemverilog
// snippet: the buggy monitor (do not copy)
axi_transaction pending_writes[int];   // keyed by AWID

// at each AW handshake:
pending_writes[vif.AWID] = txn;

// at each B handshake:
if (pending_writes.exists(vif.BID)) begin
  write_ap.write(pending_writes[vif.BID]);
  pending_writes.delete(vif.BID);
end else
  `uvm_error("MON", "B with no pending AW")
```

A master issues write U (AWID 3, address 0x100), then write V (AWID 3, address 0x200), and both complete. Predict the log, name the misconception, and fix it.

<details>
<summary>Worked answer</summary>

- At V's AW handshake, `pending_writes[3] = txn` overwrites U.
- The first B (which belongs to U, the older same-ID write, §A6.4) publishes V's transaction: the scoreboard sees "write to 0x200 completed" when U, at 0x100, did.
- The second B finds no entry: `UVM_ERROR [MON] B with no pending AW`.
- Misconception: "one outstanding entry per ID is enough". AXI allows many outstanding transactions per ID (§A5.3).
- Fix: `axi_transaction pending_writes[int unsigned][$];`, `push_back` at AW (after pairing with W, as in the write-monitor section), `pop_front` at B, and `exists()` checked before reading.

</details>
