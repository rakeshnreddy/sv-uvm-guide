# AXI Burst Math & Address Calculation

In the previous module you learned that AXI uses five independent channels with VALID/READY handshakes.
Now we focus on *what travels on those channels* — specifically, how burst parameters control address generation and byte-lane selection.

Getting burst math wrong causes **silent data corruption** — the most dangerous class of bug in interconnect design.

<QuickTake>
- **AxLEN** sets the number of transfers minus one. AXI4 INCR bursts carry up to 256 transfers (`AxLEN = 255`); FIXED and WRAP up to 16; AXI3 up to 16 for every type.
- **AxSIZE** sets the bytes per beat (encoded as 2^N: size=2 means 4 bytes per beat).
- **AxBURST** controls address progression: FIXED, INCR, or WRAP.
- After the first transfer, every address is **aligned** to the transfer size, even if the burst starts unaligned.
- **WSTRB** marks the byte lanes that carry valid data. It may be any subset of the lanes that the address and size select, never a lane outside them.
- **No burst may cross a 4 KB address boundary.** Only INCR bursts can actually do it.
</QuickTake>

---

## 1. Burst Parameters

Every AXI address-channel transaction carries three burst control fields:

### AxLEN — Burst Length

`AxLEN` encodes the number of data beats **minus one**:

| AxLEN Value | Number of Beats |
|---|---|
| 0 | 1 |
| 1 | 2 |
| 3 | 4 |
| 7 | 8 |
| 15 | 16 (AXI3 max) |
| 255 | 256 (AXI4 max) |

> [!NOTE]
> AXI3 limits bursts to 16 transfers. AXI4 extends this to 256 transfers for INCR bursts only; FIXED bursts stay at 1 to 16 and WRAP bursts must be exactly 2, 4, 8 or 16 transfers (IHI0022E A3.4.1).
> No component can terminate a burst early. A master that needs fewer writes deasserts all the write strobes for the remaining transfers, but still completes them.

### AxSIZE — Bytes per Beat

`AxSIZE` is encoded as a power of 2:

| AxSIZE Value | Bytes per Beat |
|---|---|
| 0 | 1 byte |
| 1 | 2 bytes |
| 2 | 4 bytes (32-bit) |
| 3 | 8 bytes (64-bit) |
| 4 | 16 bytes (128-bit) |

The transfer size **must not exceed the data bus width**.  A 32-bit data bus cannot use `AxSIZE = 3` (8 bytes).

### AxBURST — Burst Type

| AxBURST Value | Type | Address Behavior |
|---|---|---|
| 0 | **FIXED** | Same address for every beat (used for FIFO access) |
| 1 | **INCR** | Address increments by `2^AxSIZE` each beat |
| 2 | **WRAP** | Address increments then wraps at a calculated boundary |

## 2. Address Calculation

### The Spec Equations

IHI0022E A3.4.1 defines every address with a few variables. Transfer numbers start at `N = 1`:

```
Start_Address   = AxADDR
Number_Bytes    = 2 ^ AxSIZE
Burst_Length    = AxLEN + 1
Aligned_Address = INT(Start_Address / Number_Bytes) x Number_Bytes

Address_1 = Start_Address
Address_N = Aligned_Address + (N - 1) x Number_Bytes    // INCR, and WRAP before it wraps
```

The first transfer may be unaligned. **Every later transfer is aligned**, because the equation starts from `Aligned_Address`.

### INCR Bursts

**Example (aligned):** a 4-beat INCR burst with `AxSIZE = 2` (4 bytes) starting at `0x1000`:

| N | Calculation | Address_N |
|---|---|---|
| 1 | Start_Address | **0x1000** |
| 2 | 0x1000 + 1 x 4 | **0x1004** |
| 3 | 0x1000 + 2 x 4 | **0x1008** |
| 4 | 0x1000 + 3 x 4 | **0x100C** |

**Example (unaligned, IHI0022E A3.4.1):** the same burst starting at `0x1003` on a 32-bit bus. `Aligned_Address` is `0x1000`:

| N | Calculation | Address_N | Byte lanes |
|---|---|---|---|
| 1 | Start_Address | **0x1003** | 3 |
| 2 | 0x1000 + 1 x 4 | **0x1004** | 0-3 |
| 3 | 0x1000 + 2 x 4 | **0x1008** | 0-3 |
| 4 | 0x1000 + 3 x 4 | **0x100C** | 0-3 |

Adding 4 to the start address each time (`0x1003, 0x1007, 0x100B, 0x100F`) is the classic driver bug: it keeps the offset in every transfer.

### WRAP Bursts

Wrapping bursts are used for **cache line fills**.  The address increments normally but wraps at a boundary calculated as:

```
Wrap_Boundary = INT(Start_Address / (Number_Bytes x Burst_Length)) x (Number_Bytes x Burst_Length)
Upper limit   = Wrap_Boundary + Number_Bytes x Burst_Length
```

When `Address_N` reaches the upper limit, that transfer uses `Wrap_Boundary`, and later transfers continue from there (IHI0022E A3.4.1).

**Example:** A WRAP4 burst with `AxSIZE = 2` (4 bytes) starting at `0x1004`:

```
Number_Bytes x Burst_Length = 4 x 4 = 16 bytes
Wrap_Boundary = INT(0x1004 / 16) x 16 = 0x1000
Upper limit   = 0x1000 + 16 = 0x1010
```

| N | Raw Address | Address_N | Explanation |
|---|---|---|---|
| 1 | 0x1004 | **0x1004** | Start address |
| 2 | 0x1008 | **0x1008** | Normal increment |
| 3 | 0x100C | **0x100C** | Normal increment |
| 4 | 0x1010 | **0x1000** | Reached the upper limit, so it wraps to Wrap_Boundary |

> [!IMPORTANT]
> **WRAP bursts must start aligned** to the transfer size and have **2, 4, 8 or 16** transfers (IHI0022E A3.4.1).
> A WRAP4 burst of 4-byte transfers starting at `0x1003` is illegal because 0x1003 is not 4-byte aligned.

### FIXED Bursts

All transfers use `Start_Address`, and the valid byte lanes are the same on every beat (IHI0022E A3.4.1). Within those lanes the strobes may differ per beat. FIXED bursts are used for FIFO-mapped peripherals where repeated writes to the same address push data into a hardware queue, and are limited to 16 transfers.

## 3. WSTRB — Write Strobe Generation

`WSTRB` is a bitmask where each bit corresponds to one byte lane of the data bus.
A bit set to `1` means that byte lane contains valid write data.

For a 32-bit (4-byte) data bus, `WSTRB` is 4 bits wide:
- `WSTRB = 4'b1111` — all 4 bytes valid (full-word write)
- `WSTRB = 4'b0011` — lower 2 bytes valid (half-word write to bytes 0-1)
- `WSTRB = 4'b0100` — only byte 2 valid (single byte write)

### Which Lanes Can Carry Data

The address of each transfer selects its byte lanes. IHI0022E A3.4.1 gives `Lower_Byte_Lane` and `Upper_Byte_Lane`. The upper lane of an unaligned transfer stops at the end of its size-aligned container, so a 4-byte transfer at `0x1001` uses lanes 1 to 3, not 1 to 4:

```systemverilog
// IHI0022E A3.4.1: byte lanes a transfer may use. addr = Address_N.
// For aligned transfers this is lanes addr%DATA_BYTES .. +nbytes-1.
function automatic logic [DATA_BYTES-1:0] active_lanes(
  input logic [31:0] addr,
  input logic [2:0]  size
);
  int unsigned nbytes  = 1 << size;
  int unsigned aligned = (addr / nbytes) * nbytes;              // Aligned_Address
  int unsigned lower   = addr % DATA_BYTES;                     // Lower_Byte_Lane
  int unsigned upper   = aligned % DATA_BYTES + nbytes - 1;     // Upper_Byte_Lane
  logic [DATA_BYTES-1:0] lanes = '0;
  for (int unsigned lane = lower; lane <= upper; lane++) lanes[lane] = 1'b1;
  return lanes;
endfunction
```

`WSTRB` must be a **subset** of these lanes: "A master must ensure that the write strobes are HIGH only for byte lanes that contain valid data" (IHI0022E A3.4.3). A sparse write that leaves some active lanes LOW is legal, so a checker tests containment, not equality:

```systemverilog
// w_addr / w_size: the address and size of the current W beat, tracked by the monitor
a_wstrb_subset: assert property (@(posedge ACLK) disable iff (!ARESETn)
  WVALID |-> (WSTRB & ~active_lanes(w_addr, w_size)) == '0);
```

**Example on a 64-bit (8-byte) data bus**, with every active lane written:

| Address | AxSIZE | Bytes | WSTRB |
|---|---|---|---|
| 0x1000 | 2 (4B) | 4 | `8'b0000_1111` |
| 0x1004 | 2 (4B) | 4 | `8'b1111_0000` |
| 0x1001 | 0 (1B) | 1 | `8'b0000_0010` |
| 0x1000 | 3 (8B) | 8 | `8'b1111_1111` |
| 0x1001 | 2 (4B) | 3 | `8'b0000_1110` |

> [!WARNING]
> **Two common bugs:** computing WSTRB from AxSIZE alone, which picks the wrong lanes for narrow transfers on wide buses; and filling lanes `start..start+size-1` for an unaligned start, which spills into the next container.
> A third bug is in checkers: requiring WSTRB to *equal* the active lanes rejects legal sparse writes.

## 4. The 4 KB Boundary Rule

The AXI specification mandates:

> **A burst must not cross a 4 KB (0x1000) address boundary.** Every byte the burst carries must sit in the same 4 KB page as the first.

### Why 4 KB?

IHI0022E A3.4.1 gives the reason: the rule "prevents a burst from crossing a boundary between two slaves. It also limits the number of address increments that a slave must support." Slaves are decoded on 4 KB granularity, so a slave never has to hand a burst over to its neighbour.

### INCR Boundary Check Formula

For INCR bursts, compute the last byte from the **aligned** start, because every transfer after the first is aligned:

```
Last_Byte = Aligned_Address + Burst_Length x Number_Bytes - 1

// LEGAL if INT(Start_Address / 4096) == INT(Last_Byte / 4096)
```

Using `AxADDR + total` instead overshoots for unaligned starts and fails legal bursts.

### WRAP Burst Alignment & Boundaries

The rule applies to every burst type, but only INCR can break it. A legal WRAP burst stays inside its aligned container of at most 16 x 128 = 2048 bytes, which never straddles a 4 KB boundary. A FIXED burst never moves. So a checker computes the crossing for INCR only; for WRAP it checks the alignment and length rules instead.

**Examples:**
- `0x0FF0`, AxLEN=3, AxSIZE=2: last byte `0x0FFF`. **Legal**, right up to the edge.
- `0x0FF4`, AxLEN=3, AxSIZE=2: last byte `0x1003`. **Illegal**: it crosses `0x1000`.
- `0x0FFE`, AxLEN=0, AxSIZE=2: the single transfer carries only `0x0FFE` and `0x0FFF`. **Legal**, although `0x0FFE + 4` is `0x1002`.
- WRAP4 of words at `0x0FFC`: addresses `0x0FFC, 0x0FF0, 0x0FF4, 0x0FF8`. **Legal**.

### SVA Assertion

```systemverilog
// IHI0022E A3.4.1. Gate on INCR (2'b01) and start from the aligned address.
property p_incr_no_4kb(valid, addr, len, size, burst);
  logic [31:0] aligned;
  @(posedge ACLK) disable iff (!ARESETn)
    (valid && burst == 2'b01, aligned = (addr >> size) << size) |->
      (aligned[11:0] + ((len + 1) << size)) <= 32'h1000;
endproperty

a_aw_4kb: assert property (p_incr_no_4kb(AWVALID, AWADDR, AWLEN, AWSIZE, AWBURST))
  else $error("INCR write burst crosses 4 KB at 0x%08h", AWADDR);

a_ar_4kb: assert property (p_incr_no_4kb(ARVALID, ARADDR, ARLEN, ARSIZE, ARBURST))
  else $error("INCR read burst crosses 4 KB at 0x%08h", ARADDR);
```

It passes a WRAP at the page edge, a FIXED burst at `0xFFC`, and an unaligned INCR that ends at `0xFFF`, and it fails an INCR that crosses by a single byte.

### How Masters Handle This

When a master needs to transfer data that *would* cross a 4 KB boundary, it must **split the burst** into two separate bursts:

1. First burst: from the start address up to the boundary, `(boundary - Aligned_Address) / Number_Bytes` transfers.
2. Second burst: from the 4 KB boundary to the end address.

This splitting logic is a common source of bugs in DMA controllers and bridge adapters.

## 5. Narrow Transfers

A **narrow transfer** occurs when `AxSIZE` is smaller than the data bus width.
For example, a 2-byte transfer on a 4-byte bus.

During narrow transfers:
- Only a subset of byte lanes carry valid data (controlled by WSTRB).
- The active byte lanes **shift** on each beat of an INCR burst, cycling through the data bus.

**Example:** 2-byte INCR burst on a 4-byte bus starting at `0x1000`:

| N | Address | Active Bytes | WSTRB |
|---|---|---|---|
| 1 | 0x1000 | Bytes 0-1 | `4'b0011` |
| 2 | 0x1002 | Bytes 2-3 | `4'b1100` |
| 3 | 0x1004 | Bytes 0-1 | `4'b0011` |
| 4 | 0x1006 | Bytes 2-3 | `4'b1100` |

Reads use the same lanes of `RDATA`; the master ignores the other lanes.

## Summary

| Parameter | What It Controls | Key Rule |
|---|---|---|
| **AxLEN** | Number of transfers (AxLEN+1) | AXI4 INCR: up to 256; FIXED: up to 16; WRAP: 2, 4, 8, or 16 |
| **AxSIZE** | Bytes per beat (2^N) | Must not exceed data bus width |
| **AxBURST** | Address progression | FIXED, INCR, or WRAP |
| **WSTRB** | Byte-lane enables | A subset of the lanes that address + size select |
| **Address_N** | Address of transfer N | First may be unaligned; the rest are aligned |
| **4 KB rule** | Boundary constraint | No burst may cross a 4 KB page boundary (check INCR from the aligned start) |
