## Quick Take

- **What it is:** the arithmetic that turns one AXI address-channel request into the address and byte lanes of every data transfer in a burst, plus the rules that make a burst legal. A master sends one start address (AxADDR) and three control fields (AxLEN, AxSIZE, AxBURST); the slave works out everything else from them with the equations in Arm IHI0022E §A3.4.1.
- **Why it matters:** every piece of an AXI testbench (TB) recomputes these numbers. The driver needs them to place data and strobes, the monitor to pull bytes off the bus, the scoreboard to know which memory bytes changed, and the protocol checker to judge legality. An off-by-one or an unaligned start silently writes the wrong bytes while every handshake looks clean.
- **The Analogy:** a burst books a run of equal-width seats in one theatre row. AxSIZE is the seat width, AxLEN + 1 is the number of seats, and AxBURST says how the usher moves: FIXED re-books the same seat, INCR moves along the row, and WRAP circles inside one block of seats. The 4KB boundary is the aisle between two ushers (two slaves): a booking that keeps moving along the row must not continue across the aisle. *Where it breaks:* an unaligned first booking covers only part of its seat, and you may leave any of your booked seats empty (a sparse write strobe), which a theatre would not notice but a memory does.

**You will be able to:**
1. Calculate the address of every transfer of a FIXED, INCR or WRAP burst from AxADDR, AxLEN, AxSIZE and AxBURST with the IHI0022E §A3.4.1 equations, including unaligned starts.
2. Calculate the byte lanes each transfer uses (an unaligned first transfer, narrow transfers), and decide whether a WSTRB value is legal: any subset of those lanes.
3. Decide whether a burst is legal: the length limits for each burst type, WRAP alignment, AxSIZE within the bus, and the 4KB rule, which only INCR bursts can break.
4. Write a 4KB check that gates on INCR and counts from the aligned start, and split a crossing transfer into legal bursts.
5. Debug a burst-math bug from its symptom: a scoreboard mismatch with no assertion failure, or a checker that fires on legal traffic.

### Vocabulary: one address, many transfers

IHI0022E uses **master** (the component that starts a transaction, such as a CPU or a DMA engine) and **slave** (the component that answers it, such as a memory). Later Arm issues say *manager* and *subordinate*; this track follows the issue it cites.

- **Burst:** one request on an address channel (AW for writes, AR for reads) followed by one or more data transfers. In this lesson **AxADDR**, **AxLEN**, **AxSIZE** and **AxBURST** mean the AW or AR version of each signal (x stands for W or R).
- **Transfer** (also called a **beat**): one data handshake on the W or R channel. Transfers are numbered from **N = 1**, exactly as in the specification: "N is 1 for the first transfer in a burst" (§A3.4.1).
- **Byte lane:** one 8-bit slice of the data bus. Lane *n* is `DATA[8n+7:8n]`, so a 32-bit bus has lanes 0 to 3 and a 64-bit bus has lanes 0 to 7. The bus has **Data_Bus_Bytes** lanes.
- **Aligned:** an address is aligned to a size when it is a whole multiple of that size. 0x1004 is aligned to 4 bytes; 0x1003 is not, so a 4-byte transfer starting there is **unaligned**.

The single most important fact on this page comes from the first paragraph of §A3.4.1: "The master begins each burst by driving control information and the address of the first byte in the transaction to the slave. As the burst progresses, the slave must calculate the addresses of subsequent transfers in the burst." Only one address ever crosses the wires per burst. Every later address exists only inside the components that compute it.

### The three burst fields

**AxLEN: the burst length.** AxLEN holds the number of transfers **minus one**, so `Burst_Length = AxLEN + 1` (§A3.4.1). AXI3 uses AxLEN[3:0] and AXI4 widens it to AxLEN[7:0]:

| AxLEN Value | Number of Beats | Where it is legal |
|---|---|---|
| 0 | 1 | INCR and FIXED (a WRAP needs at least 2) |
| 1 | 2 | every type |
| 3 | 4 | every type |
| 7 | 8 | every type |
| 15 | 16 | every type; the AXI3 maximum for all types |
| 255 | 256 | AXI4 INCR only |

AXI4 extends INCR bursts to 1 to 256 transfers; FIXED stays at 1 to 16, and WRAP must be exactly 2, 4, 8 or 16 transfers (§A3.4.1). The beat count is visible on the data channels: the master must assert **WLAST** "while it is driving the final write transfer in the burst", and the slave must assert **RLAST** on the final read transfer (§A3.2.2). So a write burst always has exactly AxLEN + 1 W transfers, and a monitor that counts anything else has found a bug.

**No early termination.** "No component can terminate a burst early" (§A3.4.1). A master that needs fewer bytes in a write burst deasserts all the write strobes for the remaining transfers but still completes them. In a read burst it may discard data, but it must still accept every transfer.

**AxSIZE: the maximum bytes per transfer.** AxSIZE is "the maximum number of bytes to transfer in each data transfer" (§A3.4.1). It is encoded as a power of two, `Number_Bytes = 2 ^ AxSIZE` (Table A3-2):

| AxSIZE Value | Bytes per Beat (maximum) |
|---|---|
| 0b000 | 1 |
| 0b001 | 2 |
| 0b010 | 4 (32-bit) |
| 0b011 | 8 (64-bit) |
| 0b100 | 16 (128-bit) |
| 0b101 | 32 |
| 0b110 | 64 |
| 0b111 | 128 (1024-bit) |

It is a maximum because an unaligned first transfer carries fewer bytes, as you will see below. "The size of any transfer must not exceed the data bus width of either agent in the transaction" (§A3.4.1): a 32-bit bus cannot carry `AxSIZE = 3`.

**AxBURST: how the address moves** (Table A3-3):

| AxBURST Value | Type | Address Behavior |
|---|---|---|
| 0b00 | **FIXED** | Every transfer uses the start address (FIFO-style ports) |
| 0b01 | **INCR** | Address_N = Aligned_Address + (N − 1) × Number_Bytes; only an aligned start steps by exactly 2^AxSIZE every time |
| 0b10 | **WRAP** | Like INCR, but wraps back inside an aligned window (cache-line fills) |
| 0b11 | Reserved | Never legal; a checker flags it |

### Where each transfer lands: the A3.4.1 equations

IHI0022E §A3.4.1 defines every address with a few variables. Transfer numbers start at `N = 1`:

```text
Start_Address   = AxADDR
Number_Bytes    = 2 ^ AxSIZE
Burst_Length    = AxLEN + 1
Aligned_Address = INT(Start_Address / Number_Bytes) x Number_Bytes

Address_1 = Start_Address
Address_N = Aligned_Address + (N - 1) x Number_Bytes    // INCR, and WRAP before it wraps
```

`INT(x)` rounds down. The first transfer may be unaligned. **In INCR and WRAP bursts every later transfer is aligned**, because the equation starts from `Aligned_Address`. FIXED bursts are the exception: they never move, so an unaligned FIXED start stays unaligned on every transfer (see FIXED bursts below).

**Example (aligned):** a 4-beat INCR burst with `AxSIZE = 2` (4 bytes) starting at `0x1000`:

| N | Calculation | Address_N |
|---|---|---|
| 1 | Start_Address | **0x1000** |
| 2 | 0x1000 + 1 x 4 | **0x1004** |
| 3 | 0x1000 + 2 x 4 | **0x1008** |
| 4 | 0x1000 + 3 x 4 | **0x100C** |

**Example (unaligned, IHI0022E A3.4.1):** the same burst starting at `0x1003` on a 32-bit bus. `Aligned_Address` is `0x1000`:

| N | Calculation | Address_N | Byte lanes |
|---|---|---|---|
| 1 | Start_Address | **0x1003** | 3 |
| 2 | 0x1000 + 1 x 4 | **0x1004** | 0-3 |
| 3 | 0x1000 + 2 x 4 | **0x1008** | 0-3 |
| 4 | 0x1000 + 3 x 4 | **0x100C** | 0-3 |

The first transfer carries one byte (0x1003), not four: that is why AxSIZE is a *maximum*. Adding 4 to the start address each time (`0x1003, 0x1007, 0x100B, 0x100F`) is the classic driver bug: it keeps the start offset in every transfer.

### WRAP bursts

A **cache line** is the fixed-size block (for example 16 or 64 bytes) that a cache fills or evicts as a unit. When a processor misses on one word, it wants that word first, so the fill starts at the requested (critical) word and then **wraps** to fetch the rest of the line. That is what a WRAP burst does. The address increments normally but wraps inside an aligned window:

```text
Wrap_Boundary = INT(Start_Address / (Number_Bytes x Burst_Length)) x (Number_Bytes x Burst_Length)
Upper limit   = Wrap_Boundary + Number_Bytes x Burst_Length
```

When `Address_N` reaches the upper limit, that transfer uses `Wrap_Boundary`, and later transfers continue from there (IHI0022E A3.4.1). The upper limit is never itself used as an address.

**Example:** A WRAP4 burst with `AxSIZE = 2` (4 bytes) starting at `0x1004`:

```text
Number_Bytes x Burst_Length = 4 x 4 = 16 bytes
Wrap_Boundary = INT(0x1004 / 16) x 16 = 0x1000
Upper limit   = 0x1000 + 16 = 0x1010
```

| N | Raw Address | Address_N | Explanation |
|---|---|---|---|
| 1 | 0x1004 | **0x1004** | Start address |
| 2 | 0x1008 | **0x1008** | Normal increment |
| 3 | 0x100C | **0x100C** | Normal increment |
| 4 | 0x1010 | **0x1000** | Reached the upper limit, so it wraps to Wrap_Boundary |

**A WRAP that starts on its boundary never wraps.** The specification says "the address wraps for any WRAP burst for which the first address is higher than the wrap boundary" (§A3.4.1). Start the same WRAP4 at 0x1000 and the addresses are 0x1000, 0x1004, 0x1008, 0x100C: identical to INCR4, because the fourth address (0x100C) is still below the upper limit. A checker that expects every WRAP to wrap, or a coverage model that counts this burst as "wrapped", is wrong.

> [!IMPORTANT]
> **WRAP bursts must start aligned** to the transfer size and have **2, 4, 8 or 16** transfers (IHI0022E A3.4.1).
> A WRAP4 burst of 4-byte transfers starting at `0x1003` is illegal because 0x1003 is not 4-byte aligned. In the visualizer, pick "WRAP4 at 0x1008" and predict the last address (0x1004), then pick "WRAP of 3" and predict the legality verdict (illegal length).

### FIXED bursts

In a FIXED burst "the address is the same for every transfer in the burst", and "the byte lanes that are valid are constant for all beats in the burst. However, within those byte lanes, the actual bytes that have WSTRB asserted can differ for each beat" (§A3.4.1). FIXED bursts carry at most 16 transfers. They serve repeated accesses to one location, such as filling or emptying a **FIFO** (a first-in, first-out hardware queue) behind a single register address.

The A3.4.2 pseudocode only realigns the address when it increments, which FIXED never does. So an unaligned FIXED burst keeps its unaligned address and the first transfer's lanes on every transfer. Traced on a 32-bit bus with `AxLEN = 3`, `AxSIZE = 2`:

| N | Address_N | Byte lanes | Full-lane WSTRB |
|---|---|---|---|
| 1 | 0x2001 | 1-3 | `4'b1110` |
| 2 | 0x2001 | 1-3 | `4'b1110` |
| 3 | 0x2001 | 1-3 | `4'b1110` |
| 4 | 0x2001 | 1-3 | `4'b1110` |

Pick the "FIXED unaligned" preset in the visualizer and predict the last address before you reveal it: it is 0x2001, not 0x200D (INCR behaviour) and not 0x2000 (a realigned address). The classic FIXED bug lives in monitors: one that increments the address on every transfer files three of these four transfers under the wrong address.

### Byte lanes: narrow and unaligned transfers

Two kinds of transfer use only part of the bus:

- A **narrow transfer** is narrower than the data bus: `2 ^ AxSIZE` is less than Data_Bus_Bytes, for example a 2-byte transfer on a 4-byte bus.
- An **unaligned transfer** starts at an address that is not a multiple of its size; only the first transfer of an INCR or WRAP burst, or every transfer of a FIXED burst, can be unaligned.

For both, "the address and control information determine which byte lanes the transfer uses: in incrementing or wrapping bursts, different byte lanes are used on each beat of the burst; in a fixed burst, the same byte lanes are used on each beat" (§A3.4.3). WSTRB does not choose the lanes; it marks which bytes inside them are valid.

§A3.4.1 gives the lanes as two numbers. For the first transfer:

```text
Lower_Byte_Lane = Start_Address - INT(Start_Address / Data_Bus_Bytes) x Data_Bus_Bytes
Upper_Byte_Lane = Aligned_Address + (Number_Bytes - 1)
                  - INT(Start_Address / Data_Bus_Bytes) x Data_Bus_Bytes
```

For every later transfer, `Lower_Byte_Lane = Address_N mod Data_Bus_Bytes` and `Upper_Byte_Lane = Lower_Byte_Lane + Number_Bytes - 1`. "Data is transferred on `DATA((8 x Upper_Byte_Lane) + 7 : (8 x Lower_Byte_Lane))`" (§A3.4.1). So a monitor extracts exactly those bits of WDATA or RDATA for each transfer.

The upper lane of an unaligned first transfer stops at the end of its size-aligned block. On a 64-bit (8-byte) bus, a 4-byte transfer at `0x1001` uses lanes 1 to 3, not lanes 1 to 4: lane 4 belongs to the next 4-byte block (0x1004 to 0x1007).

Reads use the same lanes of `RDATA`; the master ignores the other lanes. In code, the two lane equations collapse into one function. `DATA_BYTES` is the bus width in bytes, a `localparam` in the package that holds the function (the full package is in Make It Work):

```systemverilog
// snippet: from axi_burst_pkg in Make It Work, where DATA_BYTES is a localparam.
// IHI0022E A3.4.1: byte lanes a transfer may use. addr = Address_N.
// Precondition: (1 << size) <= DATA_BYTES (AxSIZE fits the bus).
function automatic logic [DATA_BYTES-1:0] active_lanes(
  input logic [31:0] addr,
  input logic [2:0]  size
);
  int unsigned nbytes  = 1 << size;
  int unsigned aligned = (addr / nbytes) * nbytes;            // Aligned_Address
  int unsigned lower   = addr % DATA_BYTES;                   // Lower_Byte_Lane
  int unsigned upper   = aligned % DATA_BYTES + nbytes - 1;   // Upper_Byte_Lane
  logic [DATA_BYTES-1:0] lanes = '0;
  for (int unsigned lane = lower; lane <= upper; lane++) lanes[lane] = 1'b1;
  return lanes;
endfunction
```

For an aligned address `aligned` equals `addr`, so this gives `Lower_Byte_Lane + Number_Bytes - 1`, the later-transfer equation. Called with `Address_N`, it covers every transfer of every burst type.

### WSTRB: any subset of the active lanes

**WSTRB** is the write strobe: one bit per byte lane, where "WSTRB[n] corresponds to WDATA[(8n)+7: (8n)]" (§A3.4.3). A HIGH bit says that lane carries valid write data. The rule is one sentence: "A master must ensure that the write strobes are HIGH only for byte lanes that contain valid data" (§A3.4.3). Combined with the lanes above, that gives the legal set:

- WSTRB may be **any subset** of the active lanes of that transfer, including all zeros. A **sparse** write (some active lanes LOW) is legal, and all-zero strobes are how a master writes fewer bytes in a burst it must still complete (§A3.4.1).
- A strobe on a lane **outside** the active lanes is illegal.
- "When WVALID is LOW, the write strobes can take any value" (§A3.4.3), so a checker only looks at WSTRB on a handshake.

So a checker tests containment, `(WSTRB & ~lanes) == '0`, not equality. Here is the W channel for the burst from 0x1003, with a sparse second transfer and one wait cycle:

> **Two common bugs:** computing WSTRB from AxSIZE alone, which picks the wrong lanes for narrow transfers on wide buses; and filling lanes `start..start+size-1` for an unaligned start, which spills into the next block.
> A third bug is in checkers: requiring WSTRB to *equal* the active lanes rejects legal sparse writes.

### The 4KB rule

§A3.4.1 states it plainly: "A burst must not cross a 4KB address boundary." A **4KB boundary** is any address that is a multiple of 4096 (0x1000), so memory is divided into 4KB **pages** (0x0000 to 0x0FFF, 0x1000 to 0x1FFF, and so on). Every byte a burst carries must sit in the same page as its first byte.

**Why 4KB.** The specification's note gives the reason: the rule "prevents a burst from crossing a boundary between two slaves. It also limits the number of address increments that a slave must support." In practice this means an interconnect (the switch that routes requests to slaves) can place slaves on 4KB boundaries and route a whole burst by its start address, and a slave never has to hand half a burst to its neighbour.

**Only INCR can cross.** The rule applies to every burst, but only INCR can break it:

- A legal WRAP burst stays inside its window of Number_Bytes × Burst_Length bytes, at most 128 × 16 = 2048. The window is aligned to its own size, which divides 4096, so it never straddles a page.
- A FIXED burst never moves.

So a checker computes the crossing for INCR only. For WRAP it checks the alignment and length rules instead, and for FIXED the length.

**INCR boundary check formula.** Count the last byte from the **aligned** start, because every transfer after the first is aligned:

```text
Last_Byte = Aligned_Address + Burst_Length x Number_Bytes - 1

// LEGAL if INT(Start_Address / 4096) == INT(Last_Byte / 4096)
```

Using `AxADDR + total bytes` instead overshoots for unaligned starts and fails legal bursts.

**Examples:**
- `0x0FF0`, AxLEN=3, AxSIZE=2: last byte `0x0FFF`. **Legal**, right up to the edge.
- `0x0FF4`, AxLEN=3, AxSIZE=2: last byte `0x1003`. **Illegal**: it crosses `0x1000`.
- `0x0FFE`, AxLEN=0, AxSIZE=2: the single transfer carries only `0x0FFE` and `0x0FFF`. **Legal**, although `0x0FFE + 4` is `0x1002`.
- WRAP4 of words at `0x0FFC`: addresses `0x0FFC, 0x0FF0, 0x0FF4, 0x0FF8`. **Legal**: the window is 0x0FF0 to 0x0FFF.

**The 4KB assertion.** This checker property uses an assertion local variable (`aligned`, IEEE 1800-2023 §16.10) to hold the aligned start, gates on INCR (`2'b01`), and fires only on the address handshake so that a request held waiting for READY reports once, not on every cycle. (A concurrent assertion starts a new evaluation attempt at every clock, §16.14.5.)

```systemverilog
// snippet: inside a checker module bound to the AXI interface (ACLK, ARESETn, AW*, AR*).
// [Protocol IHI0022E A3.4.1] Gate on INCR (2'b01) and start from the aligned address.
property p_incr_no_4kb(valid, ready, addr, len, size, burst);
  logic [31:0] aligned;
  @(posedge ACLK) disable iff (!ARESETn)
    (valid && ready && burst == 2'b01, aligned = (addr >> size) << size) |->
      (aligned[11:0] + ((len + 1) << size)) <= 32'h1000;
endproperty

a_aw_4kb: assert property (
  p_incr_no_4kb(AWVALID, AWREADY, AWADDR, AWLEN, AWSIZE, AWBURST))
  else $error("INCR write burst crosses 4KB at 0x%08h", AWADDR);

a_ar_4kb: assert property (
  p_incr_no_4kb(ARVALID, ARREADY, ARADDR, ARLEN, ARSIZE, ARBURST))
  else $error("INCR read burst crosses 4KB at 0x%08h", ARADDR);
```

The comparison adds the page offset of the aligned start to the total bytes; it is legal when the sum is at most 4096. The literals `1` and `32'h1000` are 32 bits wide, so the sum keeps its carry (IEEE 1800-2023 §11.6.1); Push Further shows what happens when it does not. The property passes a WRAP at the page edge, a FIXED burst at `0xFFC` and an unaligned INCR that ends at `0xFFF`, and fails an INCR that crosses by a single byte. The action blocks use `$error` because this is a plain SystemVerilog checker; inside a UVM environment you would report through `` `uvm_error `` so the failure counts in the UVM report summary.

### How masters keep bursts legal: splitting at 4KB

When a master such as a **DMA engine** (a block that copies memory without the CPU) must move data that would cross a 4KB boundary, it issues several bursts. Each burst carries:

**min**(transfers left in the 4KB page, the length cap, transfers still needed)

- Transfers left in the page = (4096 − page offset of the aligned start) / Number_Bytes.
- The length cap is 256 for an AXI4 INCR burst and 16 in AXI3 (§A3.4.1).
- So a long copy may need more than two bursts: a 4KB page holds 1024 four-byte transfers, far more than one burst can carry.

**Worked example:** a master writes 100 bytes from 0x0FF3 with 8-byte transfers on a 64-bit bus.

1. Aligned_Address = 0x0FF0. Transfers left in the page = (0x1000 − 0x0FF0) / 8 = 2.
2. Burst A: AWADDR 0x0FF3, AWLEN 1. Transfer 1 carries 0x0FF3 to 0x0FF7 (lanes 3 to 7) and transfer 2 carries 0x0FF8 to 0x0FFF: 13 bytes.
3. 87 bytes remain, which take 11 transfers. Burst B: AWADDR 0x1000, AWLEN 10. Its last transfer, at 0x1050, carries 0x1050 to 0x1056 (lanes 0 to 6).

| Burst | AWADDR | AWLEN | Bytes | Last byte | First WSTRB | Last WSTRB |
|---|---|---|---|---|---|---|
| A | 0x0FF3 | 1 | 13 | 0x0FFF | `8'b1111_1000` | `8'b1111_1111` |
| B | 0x1000 | 10 | 87 | 0x1056 | `8'b1111_1111` | `8'b0111_1111` |

### Pitfalls and misconceptions

1. **"Every transfer address is start + (N − 1) × size."** Wrong for an unaligned start: from 0x1003 the addresses are 0x1003, 0x1004, 0x1008, 0x100C, because later transfers start from Aligned_Address (§A3.4.1).
2. **"A WRAP or FIXED burst can break the 4KB rule, so check them too."** A legal WRAP stays in an aligned window of at most 2048 bytes and a FIXED burst never moves; a 4KB crossing check on them only produces false failures. Check WRAP alignment and length instead.
3. **"WSTRB must equal the active lanes."** It may be any subset, including all zeros (§A3.4.3). Test `(WSTRB & ~lanes) == '0`.
4. **"Check 4KB with AxADDR + total bytes."** That overshoots for unaligned starts: INCR, AxLEN = 0, AxSIZE = 2 at 0x0FFE carries only 0x0FFE and 0x0FFF, and is legal.
5. **"An unaligned transfer uses lanes start to start + size − 1."** The upper lane stops at the end of the size-aligned block: 4 bytes at 0x1001 on a 64-bit bus use lanes 1 to 3, not 1 to 4.
6. **"AxLEN is the number of transfers."** It is one less. A driver that sends AxLEN transfers leaves WLAST missing; a monitor that expects AxLEN reports an extra transfer.
7. **"FIXED realigns after the first transfer, like INCR."** It does not: an unaligned FIXED burst at 0x2001 uses 0x2001 and lanes 1 to 3 on every transfer.
8. **"Every WRAP wraps."** A WRAP that starts on its wrap boundary is address-for-address identical to INCR.

| Parameter | What It Controls | Key Rule |
|---|---|---|
| **AxLEN** | Number of transfers (AxLEN+1) | AXI4 INCR: up to 256; FIXED: up to 16; WRAP: 2, 4, 8, or 16; AXI3: up to 16 for all |

| **WSTRB** | Byte-lane enables | A subset of the lanes that address + size select |
| **Address_N** | Address of transfer N | INCR and WRAP: first may be unaligned, the rest are aligned; FIXED: always Start_Address |
| **4KB rule** | Boundary constraint | No burst may cross a 4KB page boundary; check INCR from the aligned start, and split long transfers |

## Make It Work

### Example: burst math that a driver, monitor and checker can share

One package of functions implements the §A3.4.1 equations. A self-checking `tb_top` tests them against the numbers on this page, then plans two 4KB splits and checks that every planned burst is legal. Put the package in your verification IP (VIP) so the driver, the monitor and the checker all use the same equations.

```systemverilog
// compile
// IHI0022E A3.4.1 burst equations, shared by a driver, a monitor and a checker.
package axi_burst_pkg;
  localparam int unsigned DATA_BYTES = 8;  // 64-bit data bus: lanes 0..7

  // AxBURST encodings (Table A3-3). 2'b11 is reserved, so it has no name.
  typedef enum logic [1:0] {FIXED = 2'b00, INCR = 2'b01, WRAP = 2'b10} burst_e;

  // Address_N for N = 1 .. AxLEN+1 ("Burst address", A3.4.1).
  function automatic logic [31:0] beat_addr(
    input logic [31:0] start, input logic [2:0] size,
    input logic [7:0] len, input burst_e burst, input int unsigned n);
    int unsigned nbytes  = 1 << size;
    int unsigned total   = nbytes * (len + 1);
    logic [31:0] aligned = (start / nbytes) * nbytes;  // Aligned_Address
    logic [31:0] wrap_lo = (start / total) * total;    // Wrap_Boundary
    logic [31:0] addr;
    if (n == 1 || burst == FIXED) return start;       // FIXED never moves
    addr = aligned + (n - 1) * nbytes;                // later transfers are aligned
    // A legal WRAP starts aligned, so it can pass the upper limit only once.
    if (burst == WRAP && addr >= wrap_lo + total) addr -= total;
    return addr;
  endfunction

  // Lower_Byte_Lane .. Upper_Byte_Lane of the transfer at addr (A3.4.1).
  // Precondition: (1 << size) <= DATA_BYTES.
  function automatic logic [DATA_BYTES-1:0] active_lanes(
    input logic [31:0] addr, input logic [2:0] size);
    int unsigned nbytes  = 1 << size;
    int unsigned aligned = (addr / nbytes) * nbytes;
    int unsigned lower   = addr % DATA_BYTES;
    int unsigned upper   = aligned % DATA_BYTES + nbytes - 1;  // end of the block
    logic [DATA_BYTES-1:0] lanes = '0;
    for (int unsigned lane = lower; lane <= upper; lane++) lanes[lane] = 1'b1;
    return lanes;
  endfunction

  // Only INCR can cross 4KB; count the last byte from Aligned_Address.
  function automatic bit crosses_4kb(
    input logic [31:0] start, input logic [2:0] size,
    input logic [7:0] len, input burst_e burst);
    int unsigned nbytes  = 1 << size;
    logic [31:0] aligned = (start / nbytes) * nbytes;
    logic [31:0] last    = aligned + (len + 1) * nbytes - 1;
    return burst == INCR && start[31:12] != last[31:12];
  endfunction

  // Transfers an INCR burst from start can make before the next 4KB
  // boundary. The caller also caps it at 256 (AXI4) or 16 (AXI3).
  function automatic int unsigned beats_to_4kb(
    input logic [31:0] start, input logic [2:0] size);
    int unsigned nbytes = 1 << size;
    int unsigned off    = (start[11:0] / nbytes) * nbytes;  // aligned page offset
    return (4096 - off) / nbytes;
  endfunction
endpackage

module tb_top;
  import axi_burst_pkg::*;
  int unsigned pass_n, fail_n;

  function automatic void check_eq(input string what, input logic [63:0] got,
                                   input logic [63:0] want);
    if (got === want) pass_n++;
    else begin
      fail_n++;
      $display("FAIL %s: got 0x%0h, expected 0x%0h", what, got, want);
    end
  endfunction

  // A master's split: each burst carries min(transfers left in the 4KB page,
  // the length cap, transfers still needed), and each must pass crosses_4kb().
  task automatic plan_split(input logic [31:0] start, input int unsigned total_bytes,
                            input logic [2:0] size, input int unsigned max_beats);
    logic [31:0] addr   = start;
    int unsigned left   = total_bytes;
    int unsigned nbytes = 1 << size;
    while (left > 0) begin
      int unsigned offset = addr % nbytes;  // nonzero only for an unaligned start
      int unsigned beats  = (offset + left + nbytes - 1) / nbytes;  // still needed
      int unsigned carried;
      if (beats > beats_to_4kb(addr, size)) beats = beats_to_4kb(addr, size);
      if (beats > max_beats) beats = max_beats;
      carried = beats * nbytes - offset;  // bytes this burst can move
      if (carried > left) carried = left;
      $display("SPLIT AWADDR=0x%h AWLEN=%0d bytes=%0d", addr[15:0], beats - 1, carried);
      check_eq("split stays in 4KB", crosses_4kb(addr, size, 8'(beats - 1), INCR), 0);
      addr += carried;
      left -= carried;
    end
  endtask

  initial begin
    check_eq("INCR 0x1003 N=2", beat_addr(32'h1003, 3'd2, 8'd3, INCR, 2), 32'h1004);
    check_eq("INCR 0x1003 N=4", beat_addr(32'h1003, 3'd2, 8'd3, INCR, 4), 32'h100C);
    check_eq("WRAP 0x1004 N=4", beat_addr(32'h1004, 3'd2, 8'd3, WRAP, 4), 32'h1000);
    check_eq("WRAP 0x1000 N=4", beat_addr(32'h1000, 3'd2, 8'd3, WRAP, 4), 32'h100C);
    check_eq("FIXED 0x2001 N=4", beat_addr(32'h2001, 3'd2, 8'd3, FIXED, 4), 32'h2001);
    check_eq("lanes 0x1001 4B", active_lanes(32'h1001, 3'd2), 8'b0000_1110);
    check_eq("lanes 0x1004 4B", active_lanes(32'h1004, 3'd2), 8'b1111_0000);
    check_eq("0x0FF0 x4 legal", crosses_4kb(32'h0FF0, 3'd2, 8'd3, INCR), 0);
    check_eq("0x0FF4 x4 cross", crosses_4kb(32'h0FF4, 3'd2, 8'd3, INCR), 1);
    check_eq("0x0FFE x1 legal", crosses_4kb(32'h0FFE, 3'd2, 8'd0, INCR), 0);
    check_eq("WRAP no cross",   crosses_4kb(32'h0FFC, 3'd2, 8'd3, WRAP), 0);
    check_eq("0x0FF3 8B fits",  beats_to_4kb(32'h0FF3, 3'd3), 2);
    plan_split(32'h0FF3, 100, 3'd3, 256);   // the worked example above
    plan_split(32'h0F00, 2048, 3'd2, 256);  // hits the page edge, then the 256 cap
    $display("PASS=%0d FAIL=%0d", pass_n, fail_n);
    $finish;
  end
endmodule
```

### The burst-legality checker

The 4KB property above is one of five legality checks. Each gates on the address handshake so that one bad burst reports once; the AR side mirrors the AW side.

```systemverilog
// snippet: in the same checker module; DATA_BYTES comes from axi_burst_pkg.
// [Protocol IHI0022E A3.4.1] One report per burst: gate on the AW handshake.
wire aw_hs = AWVALID && AWREADY;

a_aw_size:  assert property (@(posedge ACLK) disable iff (!ARESETn)
  aw_hs |-> (32'd1 << AWSIZE) <= DATA_BYTES)
  else $error("AWSIZE %0d is wider than the %0d-byte bus", AWSIZE, DATA_BYTES);
a_aw_burst: assert property (@(posedge ACLK) disable iff (!ARESETn)
  aw_hs |-> AWBURST != 2'b11)
  else $error("AWBURST 2'b11 is reserved");
a_aw_wrap:  assert property (@(posedge ACLK) disable iff (!ARESETn)
  aw_hs && AWBURST == 2'b10 |->
    AWLEN inside {8'd1, 8'd3, 8'd7, 8'd15} && (AWADDR & ((32'd1 << AWSIZE) - 1)) == 0)
  else $error("WRAP needs 2, 4, 8 or 16 transfers and an aligned start");
a_aw_fixed: assert property (@(posedge ACLK) disable iff (!ARESETn)
  aw_hs && AWBURST == 2'b00 |-> AWLEN <= 8'd15)
  else $error("FIXED burst longer than 16 transfers");
```

### Where each check lives in a UVM environment

Each burst rule has one natural home. (Driver, monitor, sequencer and scoreboard roles are introduced in [I-UVM-2A](/curriculum/T2_Intermediate/I-UVM-2A_Component_Roles/index).)

- **Sequence item:** legality constraints, so random stimulus is legal by construction (Push Further shows a width trap).
- **Driver:** computes Address_N for its own bookkeeping, places each byte on its lane, drives a full-lane or deliberately sparse WSTRB, and asserts WLAST on transfer AxLEN + 1.
- **Monitor:** pairs W transfers with their AW request in order (W may arrive first, §A3.3), counts transfers against AxLEN + 1, checks WSTRB containment, and extracts bytes Lower_Byte_Lane to Upper_Byte_Lane from WDATA and RDATA:

```systemverilog
// snippet: monitor, after pairing W transfer n with its AW item aw (fields addr,
// len, size, burst) and sampling its strobes into w_strb.
logic [DATA_BYTES-1:0] lanes;
lanes = active_lanes(beat_addr(aw.addr, aw.size, aw.len, aw.burst, n), aw.size);
if ((w_strb & ~lanes) != '0)
  `uvm_error("AXI_WSTRB", $sformatf("transfer %0d: WSTRB %b outside lanes %b",
                                    n, w_strb, lanes))
```

- **Scoreboard:** a reference memory keyed by **byte** address that writes only strobed bytes. A memory keyed by the transaction address never lines up narrow and unaligned accesses.
- **Coverage:** burst type, length, narrow or full width, aligned or unaligned start, bursts that end exactly at a page edge, and sparse, full or zero strobes (see Push Further).

### How to work any burst

1. Write down Number_Bytes = 2^AxSIZE, Burst_Length = AxLEN + 1 and Aligned_Address.
2. Compute Address_N for each transfer: FIXED keeps Start_Address; INCR uses the equation; WRAP uses it until the upper limit, then returns to Wrap_Boundary.
3. Compute each transfer's lanes, Lower_Byte_Lane to Upper_Byte_Lane.
4. Check that WSTRB is a subset of those lanes.
5. Check legality: AxSIZE fits the bus, AxBURST is not 0b11, the length suits the type, a WRAP starts aligned, and an INCR stays in its 4KB page.
6. If a transfer you need would cross 4KB, split it: min(transfers left in the page, the cap, transfers still needed) per burst.

## Push Further

### Expert: two ways to signal an unaligned start

§A3.4.3 ("Unaligned transfers") lets a master signal an unaligned start in two ways: "use the low-order address lines to signal an unaligned start address", or "provide an aligned address and use the byte lane strobes to signal the unaligned start address". So a write of 3 bytes from 0x1001 may arrive as AWADDR 0x1001 with `4'b1110`, or as AWADDR 0x1000 with `4'b1110`. The low-order address bits "must be consistent with the information on the byte lane strobes", and "the slave is not required to take special action based on any alignment information from the master".

Consequences for a TB: the scoreboard must apply strobes, not trust AxADDR, to find the first written byte; the 4KB check is unchanged because both forms have the same Aligned_Address; and leading zero strobes on transfer 1 of an aligned burst are legal, not a bug.

### Expert: what an interconnect may do to your burst

The burst a master sends is not always the burst a slave sees. §A4.3.1 defines AxCACHE[1] as the **Modifiable** bit:

- A **Modifiable** transaction may be split into several transactions or merged with others, a read may fetch more data than required, and a write may access a larger range "using the WSTRB signals to ensure that only the appropriate locations are updated". AxADDR, AxSIZE, AxLEN and AxBURST may all change, so a WRAP can arrive at the slave as INCRs.
- A **Non-modifiable** transaction must not be split or merged, except that one longer than 16 transfers may be split; each piece keeps every characteristic except a reduced burst length and an adapted address (§A3.4.1, §A4.3.1). A Non-modifiable exclusive access may have AxSIZE and AxLEN changed if the total bytes stay the same.
- No modification may cause "accesses to a different 4KByte address space than that of the original transaction", or split a single-copy-atomic access (§A4.3.1).

So an end-to-end scoreboard (master side to slave side) compares **bytes per address**, never bursts or transfers one for one. Which transformations a given interconnect performs (splits for AXI3 slaves, WRAP to INCR, width conversion) is implementation-defined: read the interconnect's documentation, and make the scoreboard tolerant of every legal form. A checker on the slave side can still assert that a split Non-modifiable burst kept its type, size, lock and protection.

### Expert: exclusive accesses tighten the burst rules

An **exclusive access** is a read-then-conditional-write pair used for semaphores (taught in [B-AXI-4](/curriculum/T3_Advanced/B-AXI-4_AXI_Expert_Features_Cache_Atomics/index)). §A7.2.4 adds burst-math rules on top of this lesson's:

- the number of bytes is a power of two: 1, 2, 4, 8, 16, 32, 64 or 128;
- the address is aligned to that total (Number_Bytes × Burst_Length);
- in AXI4 the burst length must not exceed 16 transfers;
- the exclusive read and write use identical addresses and control signals.

Breaking these "causes UNPREDICTABLE behavior". A legality checker therefore needs AxLOCK as an input, and the exclusive alignment check uses the total size, not AxSIZE: an exclusive INCR of 4 words must start on a 16-byte boundary.

### Expert: read-sensitive targets and no early termination

Bursts never end early (§A3.4.1). A master that does not need all the read data still completes every transfer and discards the extra. The specification's note warns that "discarding read data that is not required can result in lost data when accessing a read-sensitive device such as a FIFO": each read pops an entry. The rule is to "use a burst length that exactly matches the size of the required data transfer".

For a TB: a FIFO model in the scoreboard must pop on every completed R transfer, including discarded ones; and a sequence that reads a FIFO status register and then the data port must size the second burst from the status, typically with a FIXED burst.

### Expert: width conversion and byte invariance

The size rule says "the data bus width of either agent" (§A3.4.1), because an interconnect may connect a 64-bit master to a 32-bit slave. When a width converter (downsizer) must carry a transfer wider than the narrow side, the transaction "must be modified" even if it is Non-modifiable (§A4.3.1 note): an INCR of 8-byte transfers becomes twice as many 4-byte transfers.

AXI is **byte invariant** (§A3.4.3): "any byte transfer to a given address passes the eight bits of data on the same data bus wires to the same address location, regardless of the endianness". So the lane equations on this page hold for big-endian and little-endian data alike, and a byte-addressed scoreboard is correct for both. Bridges and width converters are covered in [B-AMBA-F1](/curriculum/T3_Advanced/B-AMBA-F1_Bridges_and_System_Integration/index).

### Expert: legal-by-construction stimulus and burst coverage

A sequence item can carry the legality rules as constraints (IEEE 1800-2023 §18.5; constraints are taught in [I-SV-2A](/curriculum/T2_Intermediate/I-SV-2A_Constrained_Randomization_Fundamentals/index)):

```systemverilog
// snippet: legality constraints for a 64-bit bus (DATA_BYTES = 8).
rand bit [31:0] addr;
rand bit [7:0]  len;
rand bit [2:0]  size;
rand bit [1:0]  burst;
constraint c_legal {
  size <= 3;                                         // 2^size <= 8 bytes
  burst != 2'b11;                                    // reserved
  burst == 2'b10 -> len inside {1, 3, 7, 15} && (addr & ((1 << size) - 1)) == 0;
  burst == 2'b00 -> len <= 15;
  burst == 2'b01 -> ((addr[11:0] >> size) << size) + ((len + 1) << size) <= 4096;
}
```

**The width trap.** The INCR constraint works because the unsized literals `1` and `4096` are 32 bits wide, so the sum is evaluated in at least 32 bits and keeps its carry (§11.6.1, Table 11-21; §11.6.2 shows the same carry loss with a 16-bit add). Write the "last byte offset" version with every operand 12 bits wide, `addr[11:0] + ((len + 12'd1) << size) - 12'd1 <= 12'hFFF`, and the whole expression is evaluated in 12 bits. The carry out of bit 11, which *is* the crossing, is lost, every 12-bit value is at most 12'hFFF, and the constraint is always true: the solver produces crossing bursts and the checker catches them only if it was written correctly. How fast a solver handles random shift amounts is tool-dependent; measure it in your simulator.

**Coverage** (covergroups, coverpoints and crosses, §19.5 and §19.6; taught in [I-SV-3A](/curriculum/T2_Intermediate/I-SV-3A_Functional_Coverage_Fundamentals/index)): cover burst type × length bins (1, 2 to 15, 16, 17 to 255, 256), narrow versus full width, aligned versus unaligned start, a WRAP that starts on versus above its boundary, an INCR whose last byte is exactly the last byte of a page, and sparse, full and all-zero strobes. These are the corners the bugs on this page live in.

### Expert: checker versus scoreboard

Protocol assertions judge each transfer on its own; they cannot know what the master *meant* to write. The driver bug in the debugging table shows the gap: the driver sends transfer 2 of an INCR from 0x1003 with `4'b1000`, a legal sparse strobe for the real Address_2, 0x1004, so every protocol assertion passes. Only a byte-level scoreboard, which compares memory contents with what the sequence asked for, sees bytes 0x1004 to 0x1006 never written. A complete AXI environment needs both: assertions for rules, a scoreboard for intent. [B-AXI-6](/curriculum/T3_Advanced/B-AXI-6_AXI_Verification_Performance/index) builds both.

### Kata: `calc_lanes()` against the visualizer

Write `calc_lanes(addr, size, data_bytes)` that returns the active lanes of one transfer as a 16-bit mask, for buses of 4, 8 or 16 bytes. Check it in a self-checking `tb_top` against these vectors, then set each one in the visualizer (address, AxSIZE and bus width) and compare with its lanes column.

| addr | AxSIZE | Bus | Expected lanes |
|---|---|---|---|
| 0x1003 | 2 | 32-bit | `4'b1000` |
| 0x1004 | 2 | 64-bit | `8'b1111_0000` |
| 0x2001 (FIXED, every transfer) | 2 | 32-bit | `4'b1110` |
| 0x1001 | 0 | 64-bit | `8'b0000_0010` |
| 0x1001 | 2 | 64-bit | `8'b0000_1110` |
| 0x1002 | 1 | 32-bit | `4'b1100` |
| 0x100D | 3 | 128-bit | `16'b1110_0000_0000_0000` |

<details>
<summary>Worked solution</summary>

```systemverilog
// compile
module tb_top;
  // Lanes a transfer at addr may use on a bus of data_bytes lanes (A3.4.1).
  // Precondition: (1 << size) <= data_bytes <= 16.
  function automatic logic [15:0] calc_lanes(input logic [31:0] addr,
                                             input logic [2:0] size,
                                             input int unsigned data_bytes);
    int unsigned nbytes  = 1 << size;
    int unsigned aligned = (addr / nbytes) * nbytes;           // Aligned_Address
    int unsigned lower   = addr % data_bytes;                  // Lower_Byte_Lane
    int unsigned upper   = aligned % data_bytes + nbytes - 1;  // Upper_Byte_Lane
    logic [15:0] lanes   = '0;
    for (int unsigned lane = lower; lane <= upper; lane++) lanes[lane] = 1'b1;
    return lanes;
  endfunction

  int unsigned pass_n, fail_n;

  task automatic check(input logic [31:0] addr, input logic [2:0] size,
                       input int unsigned data_bytes, input logic [15:0] want);
    logic [15:0] got = calc_lanes(addr, size, data_bytes);
    if (got === want) pass_n++;
    else begin
      fail_n++;
      $display("FAIL addr=0x%h size=%0d: got %b, want %b", addr, size, got, want);
    end
  endtask

  initial begin
    check(32'h1003, 3'd2,  4, 16'b0000_0000_0000_1000);
    check(32'h1004, 3'd2,  8, 16'b0000_0000_1111_0000);
    check(32'h2001, 3'd2,  4, 16'b0000_0000_0000_1110);  // FIXED: same every time
    check(32'h1001, 3'd0,  8, 16'b0000_0000_0000_0010);
    check(32'h1001, 3'd2,  8, 16'b0000_0000_0000_1110);
    check(32'h1002, 3'd1,  4, 16'b0000_0000_0000_1100);
    check(32'h100D, 3'd3, 16, 16'b1110_0000_0000_0000);
    $display("PASS=%0d FAIL=%0d", pass_n, fail_n);
    $finish;
  end
endmodule
```

Expected output (computed, not simulated): `PASS=7 FAIL=0`. The two vectors that catch the classic bugs are 0x1001 with AxSIZE = 2 (a spill to lane 4 gives `8'b0001_1110`) and 0x1004 on the 64-bit bus (lanes from AxSIZE alone give `8'b0000_1111`). The last vector exercises the first-transfer equation on a wide bus: Aligned_Address 0x1008 puts the block at lanes 8 to 15, and the start at lane 13 trims it to lanes 13 to 15.

</details>

### Debug challenge: the strobe that passed every check

A driver builds its W transfers with this loop, and a regression on an INCR4 of words from 0x1003 shows the scoreboard log below while every protocol assertion passes. Explain why no assertion fired, and give the one-line fix.

```systemverilog
// snippet: the buggy driver loop (32-bit bus)
for (int unsigned n = 1; n <= req.len + 1; n++) begin
  logic [31:0] addr = req.addr + (n - 1) * (1 << req.size);  // bug
  drive_w(addr, req.size, n == req.len + 1);                 // lanes from addr
end
```

```text
UVM_ERROR @ ... [SCB_MISMATCH] addr 0x1004: expected 0x11, memory never written
UVM_ERROR @ ... [SCB_MISMATCH] addr 0x1005: expected 0x22, memory never written
UVM_ERROR @ ... [SCB_MISMATCH] addr 0x1006: expected 0x33, memory never written
```

<details>
<summary>Answer</summary>

The driver's model puts transfers 2 to 4 at 0x1007, 0x100B and 0x100F, so `drive_w` lights only lane 3 and drives WSTRB `4'b1000` each time. But only AWADDR travels on the bus: the slave computes 0x1004, 0x1008 and 0x100C (§A3.4.1), and `4'b1000` is a legal sparse strobe for each of them (§A3.4.3). So no protocol rule is broken; the slave simply writes bytes 0x1007, 0x100B and 0x100F and leaves the other nine bytes untouched. The fix is one line:

```systemverilog
// snippet: the fixed address computation
logic [31:0] addr = (n == 1) ? req.addr
                  : (req.addr >> req.size << req.size) + (n - 1) * (1 << req.size);
```

The log lines are illustrative. The lesson: protocol assertions check rules, the scoreboard checks intent.

</details>
