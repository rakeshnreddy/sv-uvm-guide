## Quick Take

- **What it is:** The **register abstraction layer (RAL)** is UVM's model of the design's registers. A **register** is a storage location that software reaches at a bus address; a **field** is a named group of bits inside it, such as an enable bit or a 2-bit mode. The model is a tree of objects: a `uvm_reg_block` holds registers (`uvm_reg`), each register holds fields (`uvm_reg_field`), the block can hold memories (`uvm_mem`), and an **address map** (`uvm_reg_map`) places all of them at bus addresses (IEEE 1800.2-2020 Clause 18). A bus **adapter** (`uvm_reg_adapter`, §19.2.1) turns the model's generic reads and writes into items for your bus agent.
- **Why it matters:** Without a model, every test hard-codes addresses, bit positions and bus protocol details, and nothing records what the **design under test (DUT)** should currently hold. With one, a test writes `ral.CTRL.write(status, 'h5)` on any bus, a spec change is one regenerated file, and the model keeps a belief of every register's value that you can check against the hardware.
- **The one idea to keep:** every field holds two values in the model: the **desired** value (what the test wants the DUT to hold) and the **mirrored** value (what the model believes the DUT holds). Neither one is the DUT. Each register call moves desired, mirrored and the DUT in its own way, and a bus access moves the mirror only when something *predicts* it. Backdoor calls, `predict()` and `reset()` set the mirror directly.
- **The Analogy:** A checkbook register. The *desired* value is the amount you have decided to pay; the *mirror* is the balance in your own ledger; the *DUT* is the bank's real balance. Going to the teller is a **frontdoor** access: the bank applies its own rules. Writing the transaction into your ledger is **prediction**. Fees and interest that the bank applies without telling you are **volatile** fields. Reconciling your ledger with the statement is `mirror(UVM_CHECK)`. *Where it breaks:* your ledger only changes if someone actually writes in it, so with no prediction set up, the mirror never moves after a bus access; `set()` replaces the amount you plan to pay rather than queuing a second payment; and starting a fresh ledger (`reset()`) does nothing to the bank's balance.

**You will be able to:**
1. **Write** a register model from a small spec (RW, RO, W1C, RC, reserved and volatile fields, reset values and one memory) with `uvm_reg_field::configure`, `uvm_reg`, `uvm_mem`, `uvm_reg_block`, `create_map`/`add_reg`/`add_mem` and `lock_model`, choosing map rights, offsets, bus width and endianness.
2. **Write** a bus adapter (`reg2bus`/`bus2reg` with status) and **integrate** the model into an environment and a `uvm_reg_sequence` (`set_sequencer`, the model handle, a temporary auto-prediction).
3. **Predict** the desired, mirrored and DUT values after `set`/`update`, `write`/`read`, `mirror`/`predict`, `peek`/`poke` and `reset`, with and without prediction.
4. **Explain** frontdoor and backdoor access, and **attach** HDL paths (`configure`'s `hdl_path`, the block's `add_hdl_path`, `add_hdl_path_slice`) so `peek` and `poke` work.
5. **Debug** the first-day failures of a new register environment from the log: a missing sequencer, a missing HDL path, read data of 0, a mirror mismatch, a NOT_OK status and the wrong map rights.

Words from earlier lessons that this page uses:
- A **sequence item** is the transaction object a **sequence** creates and a **driver** turns into pin activity; a **sequencer** passes items from sequences to the driver ([I-UVM-3A](/curriculum/T2_Intermediate/I-UVM-3A_Fundamentals/index)).
- An **agent** groups a sequencer, a driver and usually a **monitor**, which watches the pins and publishes each transfer through an **analysis port** ([I-UVM-2B](/curriculum/T2_Intermediate/I-UVM-2B_TLM_Connections/index)).
- The **factory** creates objects by type with `::type_id::create` ([I-UVM-1B](/curriculum/T2_Intermediate/I-UVM-1B_The_UVM_Factory/index)); **phases** such as `build_phase` and `connect_phase` run in a fixed order, and an **objection** keeps `run_phase` alive ([I-UVM-1C](/curriculum/T2_Intermediate/I-UVM-1C_UVM_Phasing/index)).
- A **predictor** in a scoreboard computes what the DUT should do ([A-UVM-6](/curriculum/T3_Advanced/A-UVM-6_Scoreboards_and_Reference_Models/index)). The *register* predictor of this module is a different, narrower thing: it keeps the register model's mirror up to date.

New words, defined once here:
- A **frontdoor** access uses the real bus, through the agent, exactly as software would. It takes simulation time and the DUT applies its normal behaviour.
- A **backdoor** access reads or deposits the value of the HDL variable that implements the register, directly, through the simulator. It uses no bus and no simulation time.
- An **HDL path** is the hierarchical name of that variable, such as `tb_top.dut.ctrl_q`.
- An **access policy** says what a write and a read do to a field: `RW` stores the written value, `RO` ignores writes, `W1C` clears each bit written with 1, and so on.
- A **volatile** field is one the hardware changes by itself, so no bus access tells the model when it changed.

### Why a register model exists

Picture a test for an I2C controller without a model. It writes `'h5` to address `'h0` to enable the controller, waits, reads address `'h8` and masks bit 0 to see whether the transfer finished, then writes `'h1` to `'h8` to clear the flag. Every number in that test is a fact copied from the spec, and three things go wrong:
- **The spec changes.** When the interrupt register moves to `'hC`, every test that hard-coded `'h8` must be found and edited.
- **The bus changes.** The same block on an AXI bus needs every test rewritten, because the tests built APB items directly.
- **Nobody knows what the DUT should hold.** To check a register, the test needs an expected value. Without a model, each test keeps its own scattered copy.

The register model fixes all three. Addresses, bit positions, reset values and policies live in one place, usually generated from the spec. Tests call methods on named registers. The adapter is the only code that knows the bus. And the mirror is a single, shared belief of every register's value.

### The model's structure

This lesson uses one running example from start to finish: the register block of a small I2C controller, the same block the model lab uses later.

| Register | Offset | Fields (bits) | Policy | Who changes it |
| --- | --- | --- | --- | --- |
| `CTRL` | `'h00` | `EN` [0], `IE` [1], `MODE` [3:2], `RSVD` [31:4] | RW, RW, RW, RO | software; `RSVD` is reserved and reads 0 |
| `STATUS` | `'h04` | `BUSY` [0], `TX_EMPTY` [1], `RX_FULL` [2] | RO, volatile | hardware only |
| `INT_STATUS` | `'h08` | `DONE` [0], `ERR` [1] | W1C, volatile | hardware sets; software clears by writing 1 |
| `NACK_CNT` | `'h14` | `COUNT` [7:0] | RC, volatile | hardware counts; a read clears it |
| `BUF` (memory) | `'h100` | 256 words of 32 bits | RW | software |

The model of that block is a tree of objects with one more piece, the map:

| Level | Class | What it holds |
| --- | --- | --- |
| Block | `uvm_reg_block` (§18.1) | Registers, memories, sub-blocks and address maps. The first map created becomes its `default_map` (§18.1.2.5). |
| Register file | `uvm_reg_file` (§18.3) | An optional group of registers (for example, one per channel) that contributes a piece of the HDL path. This lesson does not need one. |
| Register | `uvm_reg` (§18.4) | Its fields, its size in bits and its HDL path. `write()`, `read()`, `get()` and `get_mirrored_value()` act on the whole register. |
| Field | `uvm_reg_field` (§18.5) | Size, bit position, access policy, volatility and reset value. The desired and mirrored values live here. |
| Memory | `uvm_mem` (§18.6) | An array of words reached by offset. Memories are *not* mirrored, "because of the potentially large data space" (§18.6). |
| Map | `uvm_reg_map` (§18.2) | The base address, bus width and endianness, plus an offset and access rights for each register. A map *references* registers; it does not own them. |

### Building the model in code

Model classes are ordinary UVM objects: registered with `` `uvm_object_utils `` and created with the factory, except `uvm_mem`, which has no factory registration because "it has a complex constructor signature" (§18.6). This package is the whole model of the I2C block; it compiles on its own against uvm-core 2020.3.1.

```systemverilog
// compile: i2c_reg_pkg.sv (needs only uvm-core 2020.3.1)
package i2c_reg_pkg;
  import uvm_pkg::*;
  `include "uvm_macros.svh"

  // CTRL @ 'h00: EN, IE and MODE are RW; bits [31:4] are reserved and read 0.
  class ctrl_reg extends uvm_reg;
    `uvm_object_utils(ctrl_reg)
    rand uvm_reg_field EN;
    rand uvm_reg_field IE;
    rand uvm_reg_field MODE;
    uvm_reg_field      RSVD;  // RO: nothing for randomize() to change

    function new(string name = "CTRL");
      super.new(name, 32, UVM_NO_COVERAGE);  // 32 bits, no coverage model
    endfunction

    // build() is our own method, not inherited; the block calls it.
    virtual function void build();
      EN   = uvm_reg_field::type_id::create("EN");
      IE   = uvm_reg_field::type_id::create("IE");
      MODE = uvm_reg_field::type_id::create("MODE");
      RSVD = uvm_reg_field::type_id::create("RSVD");
      //             parent size lsb access vol reset has_rst rand indiv
      EN.configure  (this,   1,  0, "RW",   0, 1'b0,  1,      1,   0);
      IE.configure  (this,   1,  1, "RW",   0, 1'b0,  1,      1,   0);
      MODE.configure(this,   2,  2, "RW",   0, 2'h0,  1,      1,   0);
      RSVD.configure(this,  28,  4, "RO",   0, 28'h0, 1,      0,   0);
    endfunction
  endclass

  // STATUS @ 'h04: driven only by hardware, so every field is RO and volatile.
  class status_reg extends uvm_reg;
    `uvm_object_utils(status_reg)
    uvm_reg_field BUSY;
    uvm_reg_field TX_EMPTY;
    uvm_reg_field RX_FULL;

    function new(string name = "STATUS");
      super.new(name, 32, UVM_NO_COVERAGE);
    endfunction

    virtual function void build();
      BUSY     = uvm_reg_field::type_id::create("BUSY");
      TX_EMPTY = uvm_reg_field::type_id::create("TX_EMPTY");
      RX_FULL  = uvm_reg_field::type_id::create("RX_FULL");
      BUSY.configure    (this, 1, 0, "RO", 1, 1'b0, 1, 0, 0);
      TX_EMPTY.configure(this, 1, 1, "RO", 1, 1'b1, 1, 0, 0);  // resets to 1
      RX_FULL.configure (this, 1, 2, "RO", 1, 1'b0, 1, 0, 0);
    endfunction
  endclass

  // INT_STATUS @ 'h08: hardware sets DONE and ERR; software writes 1 to clear.
  class int_status_reg extends uvm_reg;
    `uvm_object_utils(int_status_reg)
    uvm_reg_field DONE;
    uvm_reg_field ERR;

    function new(string name = "INT_STATUS");
      super.new(name, 32, UVM_NO_COVERAGE);
    endfunction

    virtual function void build();
      DONE = uvm_reg_field::type_id::create("DONE");
      ERR  = uvm_reg_field::type_id::create("ERR");
      DONE.configure(this, 1, 0, "W1C", 1, 1'b0, 1, 0, 0);
      ERR.configure (this, 1, 1, "W1C", 1, 1'b0, 1, 0, 0);
    endfunction
  endclass

  // NACK_CNT @ 'h14: hardware counts NACKs; reading the register clears it.
  class nack_cnt_reg extends uvm_reg;
    `uvm_object_utils(nack_cnt_reg)
    uvm_reg_field COUNT;

    function new(string name = "NACK_CNT");
      super.new(name, 32, UVM_NO_COVERAGE);
    endfunction

    virtual function void build();
      COUNT = uvm_reg_field::type_id::create("COUNT");
      COUNT.configure(this, 8, 0, "RC", 1, 8'h0, 1, 0, 0);
    endfunction
  endclass

  class i2c_reg_block extends uvm_reg_block;
    `uvm_object_utils(i2c_reg_block)
    rand ctrl_reg       CTRL;
    rand status_reg     STATUS;
    rand int_status_reg INT_STATUS;
    rand nack_cnt_reg   NACK_CNT;
    uvm_mem             BUF;  // `buf` is a keyword (a gate), so the name is upper case

    function new(string name = "i2c_reg_block");
      super.new(name, UVM_NO_COVERAGE);
    endfunction

    virtual function void build();
      // configure(parent block, register file, HDL path relative to the block)
      CTRL = ctrl_reg::type_id::create("CTRL");
      CTRL.configure(this, null, "ctrl_q");
      CTRL.build();
      STATUS = status_reg::type_id::create("STATUS");
      STATUS.configure(this, null, "");  // computed in the DUT: no flop to peek
      STATUS.build();
      INT_STATUS = int_status_reg::type_id::create("INT_STATUS");
      INT_STATUS.configure(this, null, "int_q");
      INT_STATUS.build();
      NACK_CNT = nack_cnt_reg::type_id::create("NACK_CNT");
      NACK_CNT.configure(this, null, "nack_q");
      NACK_CNT.build();

      // uvm_mem: name, words, bits per word, access, coverage. Built with new().
      BUF = new("BUF", 256, 32, "RW", UVM_NO_COVERAGE);
      BUF.configure(this, "mem_q");

      // base address 'h0, a 4-byte bus, little endian, byte addressing
      default_map = create_map("default_map", 'h0, 4, UVM_LITTLE_ENDIAN);
      default_map.add_reg(CTRL,       'h00, "RW");
      default_map.add_reg(STATUS,     'h04, "RW");  // fields are RO already
      default_map.add_reg(INT_STATUS, 'h08, "RW");  // "RW": W1C clears get predicted
      default_map.add_reg(NACK_CNT,   'h14, "RW");
      default_map.add_mem(BUF,        'h100, "RW");
      lock_model();  // no structural change after this point
    endfunction
  endclass
endpackage
```

The field's `configure()` takes nine arguments (§18.5.3.2):

| Argument | `EN` | Meaning |
| --- | --- | --- |
| `parent` | `this` | The register that owns the field. |
| `size` | `1` | Width in bits. |
| `lsb_pos` | `0` | Position of the field's lowest bit in the register. |
| `access` | `"RW"` | The access policy (next section). |
| `volatile` | `0` | 1 if hardware changes the field by itself. |
| `reset` | `1'b0` | The `"HARD"` reset value. |
| `has_reset` | `1` | 0 means the field has no reset value, and `reset` is ignored. |
| `is_rand` | `1` | Whether `randomize()` may choose a value. Ignored, and randomization turned off, for policies that cannot be written, such as RO. |
| `individually_accessible` | `0` | 1 if the field is alone in its byte lanes, so it could be accessed on its own (A-UVM-4B). |

Three rules about building that catch every newcomer:
- **`uvm_reg::configure(blk_parent, regfile_parent = null, hdl_path = "")`** (§18.4.2.2). The *second* argument is an optional register file, and the *third* is the HDL path. Writing `CTRL.configure(this, "ctrl_q")` puts a string where a class handle belongs, which does not compile; the opposite slip, `configure(this, null)`, compiles and leaves the register with no backdoor.
- **Call each register's `build()`.** It is a naming convention, not a base-class method, so nothing calls it for you. Forget one and the register silently has no fields: a write still goes out on the bus, but the mirror never changes and `mirror(UVM_CHECK)` can never fail, because there are no fields to compare (uvm-core 2020.3.1, by source reading).
- **`lock_model()` comes last** (§18.1.2.6). It freezes the structure and builds the tables that turn an address back into a register. A map created after it fails with `Cannot add map to locked model`.

### Access policies, reserved bits and volatility

A field's access policy describes what the *hardware* does on a write and on a read. The model uses the same policy twice: `set()` adjusts the desired value with it, and prediction applies it to the mirror. The policies a working engineer meets most (§18.5.4.6):

| Policy | Write | Read | `set(v)` makes desired | Mirror after a predicted write of `v` |
| --- | --- | --- | --- | --- |
| `RW` | stores `v` | no effect | `v` | `v` |
| `RO` | no effect | no effect | unchanged | unchanged |
| `WO` | stores `v` | error | `v` | `v` |
| `RC` | no effect | clears all bits after returning them | unchanged | unchanged; a predicted *read* makes it 0 |
| `WRC` | stores `v` | clears all bits | `v` | `v`; a predicted read makes it 0 |
| `W1C` | each 1 clears that bit | no effect | `desired & ~v` | `mirror & ~v` |
| `W1S` | each 1 sets that bit | no effect | `desired \| v` | `mirror \| v` |
| `W1T` | each 1 toggles that bit | no effect | `desired ^ v` | `mirror ^ v` |
| `W0C` | each 0 clears that bit | no effect | `desired & v` | `mirror & v` |
| `WC` / `WS` | any write clears / sets all bits | no effect | all 0 / all 1 | all 0 / all 1 |
| `W1` | only the first write after a `"HARD"` reset takes effect | no effect | `v` if not yet written, else unchanged | the same |

The standard lists 26 predefined policies, items a) to z), the last being `NOACCESS` (§18.5.4.6). uvm-core 2020.3.1 pre-defines 25 of them: there, `NOACCESS` is only the *effective* access a field gets through a map that forbids it, and `configure(…, "NOACCESS", …)` reports that the policy "is not defined. Setting to RW". Custom policies are declared with `uvm_reg_field::define_access()` (§18.5.4.7).

**Reserved bits.** Model reserved bits as an `RO` field with reset 0, like `RSVD`. Then a write of `'hFFFF_FFFF` predicts `RSVD` unchanged, a later read that finds a 1 there is a real mismatch, and the bit is visible in every print. Bits that belong to no field, like `STATUS`[31:3], are never compared, and `update()` writes them as 0.

**Volatility.** A field is volatile when the hardware changes it with no bus access the model could observe: `STATUS.BUSY`, `INT_STATUS.DONE`, `NACK_CNT.COUNT`. For such a field "the mirrored value … cannot be trusted" (§18.5.4.10). uvm-core 2020.3.1 acts on that in three places that the standard does not specify:
- `configure()` sets the field's compare mode to `UVM_NO_CHECK` when `volatile = 1`, so `mirror(UVM_CHECK)` does not compare it. Call `set_compare(UVM_CHECK)` (§18.5.5.15) on the field to compare it anyway.
- `get_mirrored_value()` on a volatile field logs `UVM_WARNING [UVM/FLD/GET_MIRRORED_VAL/VOL] Mirrored value returned for volatile field "…" may not reflect the actual current value.` That includes the internal call that `mirror(…, UVM_CHECK)` makes, so checking a register with volatile fields prints one warning per volatile field.
- `needs_update()` returns 1 for every *writable* volatile field, whether or not its desired value differs from the mirror (§18.5.5.8 has no such clause).

That last point is the volatile pitfall. `INT_STATUS` is writable (W1C) and volatile, so `ral.update()` always writes it, and for a W1C field the update value is the inverse of the desired value. After `ral.reset()` the desired value is 0, so `update()` writes `'h3` and clears any `DONE` or `ERR` flag the hardware has raised and the test has not yet handled. Keep such registers out of bulk `update()` calls and write them explicitly. The map rights matter here too: with `"RO"` rights the same field would act as RO, so `update()` would never write it, but the W1C clear would not be predicted either (Push Further explains why). That is why `INT_STATUS` above is added with `"RW"`.

### Address maps: offsets, rights, bus width and endianness

`create_map(name, base_addr, n_bytes, endian, byte_addressing = 1)` (§18.1.2.3) creates a map with:
- `base_addr`: every register and memory in the map sits at an offset from it;
- `n_bytes`: the width of the bus in bytes, 4 for a 32-bit APB bus;
- `endian`: the byte order (§17.2.2.4): `UVM_LITTLE_ENDIAN` puts the least-significant bytes at the lower address, `UVM_BIG_ENDIAN` the most-significant; the `_FIFO` variants reuse one address; `UVM_NO_ENDIAN` means byte order does not apply;
- `byte_addressing`: 1 (the default) means consecutive addresses are bytes; 0 means they are whole bus words.

`add_reg(rg, offset, rights = "RW")` (§18.2.3.3) places a register. Its address is the map's base address plus the offset, so `INT_STATUS` sits at `'h0 + 'h08`. Moving the whole block is `set_base_addr()` (§18.2.3.9). The **rights**, `"RW"`, `"RO"` or `"WO"`, are the register's accessibility *through this map*, and "whether a register field can be read or written depends on both the field's configured access policy … and the register's rights in the map" (§18.2.3.3). Use `"RO"` only for a genuinely read-only view, such as a debug port, never to describe a register whose fields are read-only: the fields already say that.

**Registers wider than the bus.** A 64-bit register on this 4-byte map takes two bus accesses. Take a 64-bit `TIMESTAMP` at offset `'h10` in a map whose base is `'h1000`:

| Endianness | Address `'h1010` carries | Address `'h1014` carries |
| --- | --- | --- |
| `UVM_LITTLE_ENDIAN` | bits [31:0] | bits [63:32] |
| `UVM_BIG_ENDIAN` | bits [63:32] | bits [31:0] |

In uvm-core 2020.3.1 the access carrying bits [31:0] is issued first in both cases (by source reading of `uvm_reg_map.svh`). So one `TIMESTAMP.read()` becomes two APB reads, and a wrong endianness swaps the halves. (`TIMESTAMP` is not part of the I2C block; the visualizer's block has a `TX_DATA` register at `'h10`.)

**One register, one mirror.** A register can be added to several maps, for example a CPU bus and a debug bus. It still has one set of fields and one mirror, shared by every map. When a register is in more than one map, a frontdoor call must name the map, as in `write(status, v, .map(cpu_map))` (§18.4.4.9). uvm-core silently uses the default map if you forget. Multiple maps, sub-maps and memories in depth belong to [A-UVM-4B](/curriculum/T3_Advanced/A-UVM-4B_Advanced_RAL_Techniques/index).

### Three values per field: desired, mirrored, DUT

**What the lab showed.** The table is the summary. "Predicted\*" means the mirror changes only if prediction is set up: either the map has `set_auto_predict(1)` (implicit, or auto, prediction: §18.2.5.2), or a `uvm_reg_predictor` sees the transfer from a bus monitor (explicit prediction: §19.3). By default neither is set up, so a frontdoor access leaves the mirror alone. Auto-prediction updates the mirror before `write()` or `read()` returns. An explicit predictor updates it when the monitor publishes the transfer, which can happen in the same time slot as `write()` returning, in either order (IEEE 1800-2023 §4.7), or later; with one, read the mirror only after the predictor has seen the transfer. Choosing between the two is the first topic of A-UVM-4B; this lesson uses auto-prediction.

| Call | Bus access | Desired, `get()` | Mirrored, `get_mirrored_value()` | DUT |
| --- | --- | --- | --- | --- |
| `set(v)` | none | `v`, adjusted per policy (W1C clears, RO keeps) | unchanged | unchanged |
| `randomize()` | none | random values for the `rand` fields | unchanged | unchanged |
| `update()` | a write, only if `needs_update()` | unchanged | predicted\* | written |
| `write(v)` | frontdoor write | `write()` calls `set(v)` first | predicted\* through each field's policy | applies its own policy |
| `read()` | frontdoor read | follows the mirror once predicted | predicted\*: the read value; RC fields become 0 | read side effects happen (RC clears) |
| `mirror(UVM_CHECK)` | frontdoor read | as `read()` | the *old* mirror is compared with the read value, then predicted\* | as `read()` |
| `predict(v)` | none | `v` | `v` | unchanged |
| `peek()` | none (backdoor) | the DUT value | the DUT value (see below) | unchanged |
| `poke(v)` | none (backdoor) | `v` | `v`, raw: no policy applied (see below) | `v`, raw |
| `write(v, UVM_BACKDOOR)` | none (backdoor) | the "mimicked" value | the mimicked value | the mimicked value: the policy applied to the current DUT value |
| `reset()` | none | the reset value | the reset value | **unchanged** |

Three consequences to memorize:
- **`set()` never touches the DUT.** It changes the desired value only; `update()` or `write()` sends it. With auto-prediction on, `set('h5); update(); set('h5); update();` sends *one* write: after the first `update()`, the mirror equals the desired value, so `needs_update()` returns 0.
- **The mirror does not track the DUT by itself.** With no prediction, `write(status, 'h5)` puts `'h5` in the DUT and leaves the mirror at 0, and a following `mirror(status, UVM_CHECK)` reports a mismatch.
- **The mirror is computed field by field from the policy, not copied from the bus.** Writing `'hFFFF_FFFF` to `CTRL` predicts `'h0000_000F`, because `RSVD` is RO.

**Implementation notes, labelled.** The standard says `read()`, `peek()` and `poke()` are "affected by the auto-prediction configuration" (§18.4.4.10 to §18.4.4.12). In uvm-core 2020.3.1, `peek()` and `poke()` update the mirror themselves, always, whenever the backdoor access succeeds; only a bus-monitor predictor misses them, because nothing appears on the bus. Portable code may call `predict()` after `poke()`; in uvm-core it is harmless. Likewise §18.4.4.14 says `mirror()` updates the mirror with `predict()` unconditionally, while uvm-core predicts a frontdoor `mirror()` only under auto-prediction (a backdoor `mirror()` always predicts).

### Reset: the model's reset, not the DUT's

`reset(kind = "HARD")` exists on the block, the register and the field (§18.1.5.3, §18.4.4.5, §18.5.5.4). It sets each field's desired and mirrored values to its reset value for that **reset kind**, a string naming a reset event: `"HARD"` is the power-on reset that `configure()` describes, and you may add others, such as `"SOFT"`, with `set_reset(value, "SOFT")` (§18.4.4.8). Four rules:
- It "does not actually set the value of the registers in the design" (§18.1.5.3). It is pure bookkeeping.
- A field with no reset value for the kind you name is unchanged (§18.5.5.4).
- The map's `reset()` defaults to `"SOFT"`, unlike every other `reset()` (§18.2.3.10).
- `configure()` only *stores* the reset value; `lock_model()` does not apply it. Until the first `reset()`, every mirror is 0, so `TX_EMPTY`'s mirror is 0 although the hardware resets it to 1. Call `ral.reset()` right after building the model.

The DUT is reset by its reset pin; the model learns about it only when you call `reset()`. Trace `CTRL` (reset value 0) through a reset in the middle of a test, with auto-prediction on:

| Step | Desired | Mirrored | DUT |
| --- | --- | --- | --- |
| `ral.reset()` after building the model | `'h0` | `'h0` | `'h0` (held in reset) |
| `ral.CTRL.write(status, 'h5)` | `'h5` | `'h5` | `'h5` |
| The testbench pulses the DUT's reset pin; no model call | `'h5` | `'h5` | `'h0`: the model is now stale |
| *Option A:* `ral.CTRL.mirror(status, UVM_CHECK)` | `'h0` | `'h0` | `'h0` |
| *Option B:* `ral.reset()` instead | `'h0` | `'h0` | `'h0` |

Option A first reports `UVM_ERROR … value read from DUT (0x0000000000000000) does not match mirrored value (0x0000000000000005)`, then predicts the read value. Option B is the fix: whoever resets the DUT in the middle of a test also calls `ral.reset()`. Reset-aware drivers, monitors and scoreboards are the subject of [A-UVM-9: Reset Handling and Error Injection](/curriculum/T3_Advanced/A-UVM-9_Reset_and_Error_Injection/index). A register's or block's `reset()`, of any kind, also releases the register's access lock if a thread was killed in the middle of an access (§18.4.4.5, §18.1.5.3); a `"HARD"` reset also re-arms `W1` and `WO1` fields (§18.5.5.4).

### Status, door and check arguments

Every access task shares one argument list. For `uvm_reg::write` (§18.4.4.9):

```systemverilog
// snippet: the full signature of uvm_reg::write (read, update and mirror are alike)
task write(output uvm_status_e      status,
           input  uvm_reg_data_t    value,
           input  uvm_door_e        path      = UVM_DEFAULT_DOOR,
           input  uvm_reg_map       map       = null,
           input  uvm_sequence_base parent    = null,
           input  int               prior     = -1,
           input  uvm_object        extension = null,
           input  string            fname     = "",
           input  int               lineno    = 0);
```

- **`status`** (`uvm_status_e`, §17.2.2.1) is `UVM_IS_OK`, `UVM_NOT_OK` ("completed with error") or `UVM_HAS_X` ("completed successfully, but had unknown bits"). Check it after every call: a failed access does not stop the test by itself.
- **`path`** (`uvm_door_e`, §17.2.2.2) is `UVM_FRONTDOOR`, `UVM_BACKDOOR` or `UVM_DEFAULT_DOOR`, which uses the block's default (the frontdoor unless changed). The fourth value, `UVM_PREDICT`, marks accesses a register predictor observed.
- **`map`** chooses the map when the register is in several.
- **`parent`** is the sequence the bus items run under; `uvm_reg_sequence` fills it in for you.
- `mirror()` and `mirror_reg()` take a **`check`** argument (`uvm_check_e`, §17.2.2.3) right after `status`. It defaults to `UVM_NO_CHECK`, so a plain `mirror(status)` only reads and updates. Pass `UVM_CHECK` to compare. The map can also check every read with `set_check_on_read(1)` (§18.2.5.3).

**A non-OK access is not predicted.** In uvm-core 2020.3.1 `do_predict()` skips any status other than `UVM_IS_OK`, so a write that ends with `PSLVERR` leaves the mirror where it was. With auto-prediction on, the log looks like this (illustrative):

```text
UVM_WARNING @ 345: reporter [PREDICT_NOK] status UVM_NOT_OK; skip prediction.
UVM_ERROR @ 345: reporter@@smoke [REGSTS] write CTRL returned UVM_NOT_OK
```

The warning text says `UVM_NOT_OK` even when the status was `UVM_HAS_X`; `HAS_X` accesses are skipped too.

**Who can see an X?** Not the map. The model's data type, `uvm_reg_data_t`, is 2-state (§17.2.1.1), and when a 4-state value becomes 2-state "any unknown or high-impedance bits shall be converted to zeros" (IEEE 1800-2023 §6.11.2). An X on the read data bus therefore reaches the test as 0 with `UVM_IS_OK`, unless the adapter, which still holds the 4-state bus item, tests for it and sets `UVM_HAS_X` itself. The adapter below does exactly that.

### The bus side: one APB transfer

The adapter in this lesson targets APB, the simplest AMBA bus and the most common register bus (Arm IHI0024, the AMBA APB Protocol Specification). It needs only these signals:
- `PSEL` selects the target; `PENABLE` marks the second cycle of a transfer; `PWRITE` is 1 for a write.
- `PADDR` is the address; `PWDATA` carries write data and `PRDATA` read data.
- `PREADY` lets the target extend a transfer; `PSLVERR` reports an error at the end of it.

Every transfer has a **setup** cycle (`PSEL` = 1, `PENABLE` = 0) and then an **access** cycle (`PSEL` = 1, `PENABLE` = 1), and it completes at the first rising edge of `PCLK` where `PSEL`, `PENABLE` and `PREADY` are all 1. That edge is where the DUT stores write data and where the driver samples `PRDATA` and `PSLVERR`.

### The adapter

The model speaks in `uvm_reg_bus_op`, a generic bus operation (§19.1.2) with the fields `kind` (`UVM_READ` or `UVM_WRITE`), `addr`, `data`, `n_bits`, `byte_en` and `status`. Your agent speaks in its own sequence item. The adapter translates both ways (§19.2.1):

```systemverilog
// snippet: the adapter (the full testbench in Make It Work contains it unchanged)
class apb_reg_adapter extends uvm_reg_adapter;
  `uvm_object_utils(apb_reg_adapter)

  function new(string name = "apb_reg_adapter");
    super.new(name);
    supports_byte_enable = 0;  // this apb_item carries no byte strobes
    provides_responses   = 0;  // the driver returns read data in the request item
  endfunction

  // Model -> bus: the map calls this for every bus access it needs.
  virtual function uvm_sequence_item reg2bus(const ref uvm_reg_bus_op rw);
    apb_item item = apb_item::type_id::create("item");
    item.write = (rw.kind == UVM_WRITE);
    item.addr  = rw.addr;
    item.data  = rw.data;  // the driver ignores it on a read
    return item;
  endfunction

  // Bus -> model: the map calls this on the finished item.
  virtual function void bus2reg(uvm_sequence_item bus_item,
                                ref uvm_reg_bus_op rw);
    apb_item item;
    if (!$cast(item, bus_item)) begin
      `uvm_fatal("NOT_APB", "bus2reg received an item that is not an apb_item")
      return;
    end
    rw.kind = item.write ? UVM_WRITE : UVM_READ;
    rw.addr = item.addr;
    rw.data = item.data;  // 4-state to 2-state: X and Z bits become 0
    if (item.slverr)
      rw.status = UVM_NOT_OK;  // PSLVERR: no prediction follows
    else if (!item.write && $isunknown(item.data))
      rw.status = UVM_HAS_X;   // only the adapter can still see the X
    else
      rw.status = UVM_IS_OK;
  endfunction
endclass
```

How the fields correspond:

| `uvm_reg_bus_op` | `apb_item` | APB signal |
| --- | --- | --- |
| `kind` (`UVM_WRITE` / `UVM_READ`) | `write` (1 / 0) | `PWRITE` |
| `addr` | `addr` | `PADDR` |
| `data` | `data` | `PWDATA` on a write, `PRDATA` on a read |
| `status` | `slverr`, plus an X test on `data` | `PSLVERR` |
| `byte_en` | (none: `supports_byte_enable = 0`) | `PSTRB` on APB4, not modelled here |

What to know about each part:
- **The register map calls `reg2bus()`**, not the sequencer and not the test. It then starts the returned item on the sequencer given to `set_sequencer()`. If `reg2bus()` returns `null`, the map stops with `UVM_FATAL [RegMem] adapter [adapter] didnt return a bus transaction`.
- **The map calls `bus2reg()`** when the item finishes, to get the status and, for a read, the data. With `provides_responses = 0` it passes the *request* item, so the driver must copy the read data into the request (this driver does). With `provides_responses = 1` (§19.2.1.2.3) it waits for a separate response item from the driver's `put_response()`. A `uvm_reg_predictor` also calls `bus2reg()` on every item a monitor publishes (A-UVM-4B).
- **`supports_byte_enable`** (§19.2.1.2.2) says whether the bus item can carry `byte_en`. Byte-enable details and response routing are A-UVM-4B's.
- **`parent_sequence`** (§19.2.1.2.4) lets the map run every bus item under a sequence you supply; most environments leave it `null`.

### Backdoor access and HDL paths

The backdoor reads or deposits the HDL variable directly. By default it uses the UVM HDL access routines (`uvm_hdl_read`, `uvm_hdl_deposit` and friends, §19.6), which are DPI functions compiled with uvm-core; a user-defined `uvm_reg_backdoor` (§19.5) can replace them. A backdoor access takes no simulation time, puts nothing on the bus, runs no protocol checks, and is invisible to a bus monitor.

**Building the path.** The register's HDL path is its block's path, a dot, then its own path:
- the root block gets its path from `configure(null, "tb_top.dut")` or `add_hdl_path("tb_top.dut")` (§18.1.2.2, §18.1.6.5);
- a register implemented by one variable gets it from `configure()`'s third argument, `"ctrl_q"`, so `CTRL` lives at `tb_top.dut.ctrl_q`;
- a register implemented by several variables, typically one flop per field, lists them with `add_hdl_path_slice(name, offset, size)` (§18.4.6.5), for example `CTRL.add_hdl_path_slice("en_q", 0, 1);`.

Each path belongs to an abstraction **kind**, `"RTL"` by default; you can add `"GATE"` paths for a netlist (§18.1.6.5).

**Four backdoor calls, two behaviours.**
- `poke(status, v)` deposits `v` "as is" (§18.4.4.11), reserved and RO bits included, and in uvm-core sets the mirror to `v`.
- `write(status, v, UVM_BACKDOOR)` *mimics* a bus write (§18.4.4.9): it reads the current value, applies each field's policy, deposits the result, and needs `"RW"` or `"WO"` rights. On `CTRL` holding 0, `write('hFF, UVM_BACKDOOR)` deposits `'h0F`, while `poke('hFF)` deposits `'hFF`.
- `peek(status, v)` samples the variable without changing it (§18.4.4.12).
- `read(status, v, UVM_BACKDOOR)` also writes back read side effects: an RC field is cleared in the DUT. In uvm-core its mirror keeps the value read *before* the clear (A-UVM-4B explores this).

A backdoor deposit also skips the DUT's own write logic. In the worked example, writing `CTRL.EN = 1` through the bus starts a transfer, but poking it does not.

**When the path is missing.** `peek()` and `poke()` fail with `UVM_ERROR … No backdoor access available to poke register 'ral.CTRL'` and return `UVM_NOT_OK`. A backdoor `read()` or `write()` instead warns `No backdoor access available for register 'ral.CTRL' . Using frontdoor instead.` and quietly uses the bus. When the path exists but the simulator cannot find or write the signal, the DPI layer reports it; in uvm-core's VCS implementation the message is `UVM_ERROR [UVM/DPI/HDL_SET] set: unable to locate hdl path (…) Either the name is incorrect, or you may not have PLI/ACC visibility to that name`. Read and write access to design signals is a compile or elaboration option whose name depends on the simulator (tool-dependent).

### The model in a testbench

Five decisions turn the model into part of an environment. The worked example makes each of them.
1. **Who builds it.** The environment, in `build_phase`: create the block with the factory, call `configure(null, <HDL path of the DUT>)`, then its `build()`, then `reset()`. A register block is a `uvm_object`, not a component, so it takes no parent and has no phases of its own.
2. **When it meets the bus.** In `connect_phase`, call `default_map.set_sequencer(agent.sequencer, adapter)` (§18.2.3.6). Not in `build_phase`: the agent creates its sequencer in *its* `build_phase`, which runs after the environment's, so the handle would still be `null` (`UVM_ERROR [REG_NULL_SQR] Null reference specified for bus sequencer`). With sub-maps, only the root map's sequencer and adapter are used.
3. **How the mirror is kept.** This lesson calls `default_map.set_auto_predict(1)`: the register predicts its own accesses before `write()` or `read()` returns. It is simple and needs no monitor, but it never sees bus traffic the model did not start, such as firmware running on a processor model. A-UVM-4B replaces it with explicit prediction.
4. **How tests reach it.** Tests reach registers through the environment's handle, `env.ral`. Register sequences extend `uvm_reg_sequence` (§19.4.1) and receive the block in their `model` member (§19.4.1.3.1). Its helper tasks `write_reg`, `read_reg`, `mirror_reg`, `update_reg`, `peek_reg` and `poke_reg` (§19.4.1.5.1 to §19.4.1.5.6) call the register methods with `parent` set to the sequence, so you never pass it by hand. The map must have a sequencer before any such sequence starts (§18.2.3.6). The sequence itself can be started with `start(null)`, because every bus item gets its sequencer from the map.
5. **Where the model comes from.** In real projects the model is **generated** from a machine-readable register description, and nobody types the classes above. Common inputs are IP-XACT (IEEE 1685) and SystemRDL (an Accellera standard). Generators include open-source tools such as PeakRDL and commercial tools from the simulator vendors; check each tool's documentation for the formats it reads. Treat the output as read-only: fix a wrong policy or volatility in the description and regenerate. Whether to commit the generated files or regenerate them at build time with a pinned generator version is a team decision (Push Further).

The mistakes this lesson guards against, each with its reason:
- *"`set()` writes the register."* It changes the desired value only; nothing reaches the DUT until `update()` or `write()`.
- *"The mirror follows the DUT."* It changes only when an access is predicted, or when you call `predict()`, `reset()` or a backdoor method.
- *"`configure()`'s second argument is the HDL path."* It is the register file; the path is the third.
- *"Map rights are documentation."* `"RO"` rights turn a W1C field into an RO field for prediction and for `update()`.
- *"The model resets with the DUT."* Only `reset()` resets the model.
- *"`update()` writes only what I changed."* It also writes every writable volatile field (uvm-core).

## Make It Work

### A complete register testbench

This testbench puts the whole lesson into one run. It has a small APB register block as the DUT, a minimal APB agent (sequencer and driver only, because auto-prediction needs no monitor), the adapter, an environment that builds and connects the model, one `uvm_reg_sequence` that exercises every call in the three-value table, and a test. The environment matches the diagram in "Backdoor access and HDL paths". Compile it after `i2c_reg_pkg.sv` from "Building the model in code".

The toy DUT behaves like a tiny I2C controller: writing `CTRL` with `EN` = 1 starts a "transfer" that ends one clock later. Ending it sets `INT_STATUS.DONE` and adds 1 to `NACK_CNT`, because this toy target always answers with one NACK.

// compile: i2c_tb.sv (compile after i2c_reg_pkg.sv)
`timescale 1ns/1ps

interface apb_if (input logic pclk, input logic presetn);
  logic        psel, penable, pwrite, pready, pslverr;
  logic [31:0] paddr, pwdata, prdata;

  // The driver drives and samples only through this clocking block (F4C).
  clocking drv_cb @(posedge pclk);
    output psel, penable, pwrite, paddr, pwdata;
    input  prdata, pready, pslverr;
  endclocking
endinterface

// The DUT: the I2C register block on an APB target port.
module i2c_regs (
  input  logic        pclk, presetn,
  input  logic        psel, penable, pwrite,
  input  logic [31:0] paddr, pwdata,
  output logic [31:0] prdata,
  output logic        pready, pslverr
);
  logic [31:0] ctrl_q;   // EN [0], IE [1], MODE [3:2]; [31:4] reserved
  logic [1:0]  int_q;    // DONE [0], ERR [1]: W1C
  logic [7:0]  nack_q;   // RC counter
  logic        busy_q;   // a toy transfer runs for one clock
  logic [31:0] mem_q [256];
  logic        wr, rd, is_mem;
  logic [7:0]  widx;

  assign wr     = psel && penable && pwrite;
  assign rd     = psel && penable && !pwrite;
  assign is_mem = (paddr >= 32'h100) && (paddr < 32'h500);
  assign widx   = 8'((paddr - 32'h100) >> 2);
  assign pready = 1'b1;  // never adds wait states
  assign pslverr = psel && penable && !is_mem &&
                   !(paddr inside {32'h00, 32'h04, 32'h08, 32'h14});

  always_comb begin
    prdata = 32'h0;
    if (is_mem) prdata = mem_q[widx];
    else case (paddr)
      32'h00:  prdata = ctrl_q;
      32'h04:  prdata = {29'h0, 1'b0, 1'b1, busy_q};  // RX_FULL, TX_EMPTY, BUSY
      32'h08:  prdata = {30'h0, int_q};
      32'h14:  prdata = {24'h0, nack_q};
      default: prdata = 32'h0;
    endcase
  end

  always_ff @(posedge pclk or negedge presetn) begin
    if (!presetn) begin
      ctrl_q <= '0;
      int_q  <= '0;
      nack_q <= '0;
      busy_q <= 1'b0;
    end else begin
      busy_q <= 1'b0;
      if (wr && paddr == 32'h00) begin
        ctrl_q[3:0] <= pwdata[3:0];         // writes to [31:4] are ignored
        if (pwdata[0]) busy_q <= 1'b1;      // EN = 1 starts a transfer
      end
      if (wr && paddr == 32'h08) int_q <= int_q & ~pwdata[1:0];  // W1C
      if (rd && paddr == 32'h14) nack_q <= 8'h0;                 // RC
      if (busy_q) begin                     // the transfer ends: placed last,
        int_q[0] <= 1'b1;                   // so a hardware set wins over a
        nack_q   <= nack_q + 8'd1;          // clear in the same cycle
      end
      if (wr && is_mem) mem_q[widx] <= pwdata;
    end
  end
endmodule

  class apb_item extends uvm_sequence_item;
    `uvm_object_utils(apb_item)
    rand bit          write;
    rand bit   [31:0] addr;
    rand logic [31:0] data;    // 4-state, so the adapter can see X on PRDATA
    bit               slverr;  // response: PSLVERR at the end of the transfer

    function new(string name = "apb_item");
      super.new(name);
    endfunction

    virtual function string convert2string();
      return $sformatf("%s addr='h%0h data='h%0h slverr=%0b",
                       write ? "WR" : "RD", addr, data, slverr);
    endfunction
  endclass

  typedef uvm_sequencer #(apb_item) apb_sequencer;

  class apb_driver extends uvm_driver #(apb_item);
    `uvm_component_utils(apb_driver)
    virtual apb_if vif;

    function new(string name, uvm_component parent);
      super.new(name, parent);
    endfunction

    virtual function void build_phase(uvm_phase phase);
      super.build_phase(phase);
      if (!uvm_config_db #(virtual apb_if)::get(this, "", "vif", vif))
        `uvm_fatal("NOVIF", "apb_if not set for the driver")
    endfunction

    virtual task run_phase(uvm_phase phase);
      vif.drv_cb.psel    <= 1'b0;
      vif.drv_cb.penable <= 1'b0;
      wait (vif.presetn === 1'b1);
      forever begin
        seq_item_port.get_next_item(req);
        @(vif.drv_cb);                       // setup cycle
        vif.drv_cb.psel    <= 1'b1;
        vif.drv_cb.penable <= 1'b0;
        vif.drv_cb.pwrite  <= req.write;
        vif.drv_cb.paddr   <= req.addr;
        vif.drv_cb.pwdata  <= req.data;
        @(vif.drv_cb);                       // access cycle
        vif.drv_cb.penable <= 1'b1;
        do @(vif.drv_cb); while (vif.drv_cb.pready !== 1'b1);
        // The adapter reads both from this same item (provides_responses = 0).
        if (!req.write) req.data = vif.drv_cb.prdata;
        req.slverr = vif.drv_cb.pslverr;
        vif.drv_cb.psel    <= 1'b0;
        vif.drv_cb.penable <= 1'b0;
        seq_item_port.item_done();
      end
    endtask
  endclass

    `uvm_object_utils(apb_reg_adapter)

    function new(string name = "apb_reg_adapter");
      super.new(name);
      supports_byte_enable = 0;  // this apb_item carries no byte strobes
      provides_responses   = 0;  // the driver returns read data in the request
    endfunction

    virtual function uvm_sequence_item reg2bus(const ref uvm_reg_bus_op rw);
      apb_item item = apb_item::type_id::create("item");
      item.write = (rw.kind == UVM_WRITE);
      item.addr  = rw.addr;
      item.data  = rw.data;
      return item;
    endfunction

    virtual function void bus2reg(uvm_sequence_item bus_item,
                                  ref uvm_reg_bus_op rw);
      apb_item item;
      if (!$cast(item, bus_item)) begin
        `uvm_fatal("NOT_APB", "bus2reg received an item that is not an apb_item")
        return;
      end

      rw.addr = item.addr;
      rw.data = item.data;
      if (item.slverr)

      else if (!item.write && $isunknown(item.data))
        rw.status = UVM_HAS_X;
      else
        rw.status = UVM_IS_OK;
    endfunction

    endfunction

    `uvm_object_utils(i2c_reg_smoke_seq)

      super.new(name);
    endfunction

    // A failed access is not predicted and does not stop the test: check it.
    function void check_ok(uvm_status_e status, string what);
      if (status != UVM_IS_OK)
        `uvm_error("REGSTS", $sformatf("%s returned %s", what, status.name()))
    endfunction

    // Only for CTRL: get_mirrored_value() warns on volatile fields.

      `uvm_info("RAL", $sformatf("%s: desired='h%0h mirrored='h%0h",
                                 what, rg.get(), rg.get_mirrored_value()), UVM_LOW)
    endfunction

    virtual task body();
      i2c_reg_block  blk;
      uvm_status_e   status;
      uvm_reg_data_t value;
      if (!$cast(blk, model))
        `uvm_fatal("NOMODEL", "model is not an i2c_reg_block")

      show("after reset()", blk.CTRL);

      write_reg(blk.CTRL, status, 'h5);           // EN = 1, MODE = 1
      check_ok(status, "write CTRL");
      show("write CTRL 'h5", blk.CTRL);

      read_reg(blk.INT_STATUS, status, value);    // the transfer set DONE
      check_ok(status, "read INT_STATUS");
      `uvm_info("RAL", $sformatf("read INT_STATUS = 'h%0h", value), UVM_LOW)

      write_reg(blk.INT_STATUS, status, 'h1);     // W1C: clears DONE
      check_ok(status, "clear DONE");

      read_reg(blk.NACK_CNT, status, value);      // RC: this read clears it
      check_ok(status, "read NACK_CNT");
      `uvm_info("RAL", $sformatf("read NACK_CNT = 'h%0h", value), UVM_LOW)

      mirror_reg(blk.CTRL, status, UVM_CHECK);    // read and compare: no error
      check_ok(status, "mirror CTRL");

      poke_reg(blk.CTRL, status, 'h9);            // backdoor: no bus, no transfer
      check_ok(status, "poke CTRL");
      peek_reg(blk.CTRL, status, value);
      check_ok(status, "peek CTRL");
      show($sformatf("poke 'h9, peek 'h%0h", value), blk.CTRL);

      blk.CTRL.set('h6);                          // desired only
      show("set 'h6", blk.CTRL);
      update_reg(blk.CTRL, status);               // mirror 'h9 != desired 'h6
      check_ok(status, "update CTRL");
      show("update", blk.CTRL);
      update_reg(blk.CTRL, status);               // needs_update() is 0: no access
      check_ok(status, "second update CTRL");

      write_mem(blk.BUF, status, 3, 'hCAFE);      // word 3 is at 'h100 + 3*4
      check_ok(status, "write BUF[3]");

Read it against the rules:
- **Timing.** Reset ends at 22 ns. A clocking-block drive with no output skew takes effect in the same time step as the clock edge (IEEE 1800-2023 §14.16), so each APB transfer takes three clock edges from the driver's first edge, so accesses complete at 45, 75, 105, 135, 165, 195, 225 and 255 ns. The `INT_STATUS` clear completes at 105 ns and `write_mem` at 225 ns; they print nothing. `peek` and `poke` take no time, and the second `update_reg()` sends nothing, so no transfer completes at 165 ns from them.
- **`write CTRL 'h5`.** The desired value moved first (`write()` calls `set()`), and auto-prediction moved the mirror before `write_reg()` returned.
- **`INT_STATUS = 'h1`.** The CTRL write started a transfer that set `DONE` at 55 ns; the read at 75 ns sees it. The W1C write of `'h1` then clears it in the DUT and in the mirror.
- **`NACK_CNT = 'h1`.** The read returns the value before the clear; the DUT and the predicted mirror are now 0.
- **`mirror_reg(…, UVM_CHECK)`** printed nothing: the old mirror (`'h5`) matched the DUT.
- **`poke 'h9`.** The DUT and the mirror took the raw value. `EN` became 1 without a transfer starting, because a deposit bypasses the DUT's write logic.
- **`set 'h6` then `update`.** `set()` moved only the desired value; `update()` found desired and mirror different and wrote once. The second `update()` found them equal and sent nothing.
- **`BUF[3]`.** Memory accesses use an offset in words; word 3 is at `'h10C`. No mirror was involved.

### Debug it: symptom, cause, fix

These are the first-day failures of a register environment. The messages are quoted from uvm-core 2020.3.1.

| Symptom in the log | Likely cause | Fix |
| --- | --- | --- |
| `UVM_FATAL [SEQ] neither the item's sequencer nor dedicated sequencer has been supplied to start item in …` | `set_sequencer()` never called on the root map | Call `ral.default_map.set_sequencer(agent.sequencer, adapter)` in `connect_phase` |
| `UVM_ERROR [REG_NULL_SQR] Null reference specified for bus sequencer` | `set_sequencer()` ran before the sequencer existed, or the agent is passive | Move it to `connect_phase`; register traffic needs an active agent |
| `UVM_INFO [REG_NO_ADAPT] Adapter not specified for map …` | `set_sequencer()` was given no adapter, so the map sends `uvm_reg_item`s to the bus sequencer | Pass the adapter (layering without one is an expert pattern, Push Further) |
| `UVM_FATAL [RegMem] adapter [adapter] didnt return a bus transaction` | `reg2bus()` returned `null` | Create and return the item on every path |
| A frontdoor call never returns | `provides_responses = 1` but the driver never calls `put_response()`; or the driver never calls `item_done()` | Make the adapter and the driver agree; the item must end |
| `read()` returns 0 with `UVM_IS_OK`; the waveform shows data | `bus2reg()` sees a request item the driver never filled | Copy read data into the request, or set `provides_responses = 1` and send a response |
| `UVM_ERROR … No backdoor access available to poke register '…'` (or `peek`) | No HDL path on the register | Pass `configure()`'s third argument, or add slices |
| `UVM_ERROR … Block does not have hdl path defined for abstraction 'RTL'` | The block (or a parent) has no HDL path | `ral.configure(null, "tb_top.dut")` or `add_hdl_path()` |
| `UVM_WARNING … No backdoor access available for register '…' . Using frontdoor instead.` | `write`/`read(…, UVM_BACKDOOR)` without an HDL path | As above; the access silently used the bus |
| `UVM_ERROR [UVM/DPI/HDL_SET]` or `[UVM/DPI/HDL_GET]` "unable to locate hdl path" (VCS text; other simulators differ) | Wrong path string, or no simulator read/write access to it | Compare the path with the hierarchy; enable signal access (tool-dependent) |
| `UVM_FATAL [UVM_HDL_CHECK_PATH] uvm_hdl DPI routines are compiled off. Recompile without +define+UVM_HDL_NO_DPI` (or the same text from another `uvm_hdl` routine) | uvm-core compiled with `UVM_HDL_NO_DPI` | Recompile with the DPI |
| `UVM_WARNING [PREDICT_NOK] status UVM_NOT_OK; skip prediction.` | The access returned `UVM_NOT_OK` or `UVM_HAS_X` (`PSLVERR`, or an X on read data) | Check `status`; find out why the DUT answered with an error |
| `UVM_ERROR … Register "…" value read from DUT (0x…) does not match mirrored value (0x…) (valid bit mask = 0x…)` | No prediction set up; the model was not reset after a DUT reset; a real DUT bug; or a wrong policy | Read the per-field `mismatch read=… mirrored=…` lines, then check prediction, `reset()`, and the spec |
| `UVM_WARNING [UVM/FLD/GET_MIRRORED_VAL/VOL] Mirrored value returned for volatile field "…"` | `get_mirrored_value()` or `mirror(UVM_CHECK)` on a register with volatile fields | Expected; don't print or check volatile mirrors |
| `UVM_ERROR … Cannot add map to locked model` | `create_map()` after `lock_model()` | Create every map before locking |
| `UVM_WARNING … Register '…' is not registered with any map`, then an error ending `Unable to physically access register with null map` | The register was never added to a map | `add_reg()` it |
| A W1C clear reaches the DUT but the mirror keeps the 1; `update()` never writes the register | The register was added with `"RO"` rights | Use `"RW"` (the default) |
| The mirror never changes and `mirror(UVM_CHECK)` never fails for one register | That register's `build()` was never called, so it has no fields | Call `build()` for every register |
| `ral.update()` clears interrupt flags nobody serviced | A writable volatile field (W1C) always needs an update in uvm-core | Write such registers explicitly; leave them out of bulk updates |

### How to bring up a register model

1. **Generate or write the model.** One class per register with its fields, one block with its maps, `lock_model()` last. Model reserved bits as RO fields and hardware-driven fields as volatile.
2. **Check the map.** Base address, bus width and endianness as in the spec; `"RW"` rights unless the bus really is read-only.
3. **Give it HDL paths.** Root block path in the environment, register paths in `configure()` or as slices.
4. **Write the adapter.** Map every `uvm_reg_bus_op` field, including `status`, and decide where read data comes from (`provides_responses`).
5. **Build, lock and reset it in the environment** (`build_phase`), and **connect it** with `set_sequencer()` in `connect_phase`. Choose prediction: auto-prediction now, explicit prediction in A-UVM-4B.
6. **Smoke-test it with a `uvm_reg_sequence`:** write, read and `mirror(UVM_CHECK)` one RW register, peek and poke it, and check `status` after every call.
7. **Then run the built-in register tests** (reset values, bit-bash, access), which A-UVM-4B covers.

**Checklist before moving on:**
- [ ] I can write a field's `configure()` call from one row of a register spec, including volatility and the reset value.
- [ ] I can say which map rights a register with a W1C field needs, and what `"RO"` rights would do to it.
- [ ] I can predict desired, mirrored and DUT after each call in the three-value table, with and without prediction.
- [ ] I can explain why `ral.reset()` must follow a DUT reset, and why it does not reset the DUT.
- [ ] I can write an adapter whose `bus2reg()` sets `status`, and say where read data comes from.
- [ ] I can find a missing HDL path, a missing sequencer and a missing prediction from the log alone.

## Push Further

### Expert: where IEEE 1800.2 and uvm-core 2020.3.1 differ

The standard sometimes says less than the reference implementation, or something else. Teams that run more than one UVM library, or move between versions, need to know which behaviour is standard.

| Topic | IEEE 1800.2-2020 says | uvm-core 2020.3.1 does |
| --- | --- | --- |
| `peek()` and `poke()` prediction | "affected by the auto-prediction configuration" (§18.4.4.11, §18.4.4.12) | always predicts after a successful access (`uvm_reg.svh`, `poke` and `peek`) |
| Frontdoor `mirror()` | the mirror "is then updated using the uvm_reg::predict method" (§18.4.4.14) | predicts only with auto-prediction on; a backdoor `mirror()` always predicts |
| Predefined policies | 26, including `NOACCESS` (§18.5.4.6) | 25; `NOACCESS` only as an effective access through a map |
| Volatile fields | the mirror "cannot be trusted" (§18.5.4.10) | `UVM_NO_CHECK` by default; `needs_update()` always 1 if writable; a warning from `get_mirrored_value()` |
| Backdoor read of a WO field | the mirror of a WO field is "the value last written" (§18.5.5.3) | `peek()` puts the raw HDL value in the mirror; `read(…, UVM_BACKDOOR)` masks WO bits and the mirror becomes 0 |
| Failed accesses | not specified | not predicted, including `UVM_HAS_X` (`PREDICT_NOK`) |

Portable habits: call `predict()` yourself after a backdoor access when it matters, check `status` after every call, and never rely on a volatile field's mirror.

### Expert: map rights, the default map and `needs_update()`

One mechanism ties three surprises together. A field's *effective* access depends on the map (§18.5.4.5): through `"RO"` rights, `RW`, `W1C`, `W1S` and similar become `RO`; through `"WO"` rights, `RW`, `WRC` and `WRS` become `WO`; a field whose policy contradicts the rights becomes `NOACCESS`. Prediction uses the effective access of the map the access went through.

Methods that take no map, such as `needs_update()` and `get_access()`, resolve to the register's default map, and so does a frontdoor call with `map = null`. When a register is in several maps, §18.5.4.5 and §18.4.4.9 say a map "shall be specified"; uvm-core quietly picks the block's default map instead. So "why did `update()` stop writing my W1C register?" usually has the answer "it was added to the default map with `"RO"` rights". The frontdoor does not refuse the write itself: only the backdoor branch checks rights. Two registers may share one address when every field of one is read-only and every field of the other is write-only (uvm-core 2020.3.1, `uvm_reg_map.svh`), which models a read-status and write-command pair; any other overlap draws a `RegModel` warning that the register "maps to same address as" another.

### Expert: bus width, byte addressing and endianness

The number of bus accesses for a register is its width in bytes divided by the map's `n_bytes`, rounded up (§19.1.2: "there shall be multiples of these bus operations"). `byte_addressing = 0` makes offsets count bus words, so `'h1` is the next 4-byte word; designs that index registers by word number use it. The `_FIFO` endianness values send every access to the same address, for a data port fed by a FIFO.

By source reading of uvm-core 2020.3.1: a map with `UVM_NO_ENDIAN` reports `UVM/REG/MAPNOENDIANESS` for every register when the model locks, even registers that fit the bus, although the standard describes it only as "byte ordering not applicable". `` `UVM_REG_DATA_WIDTH `` and `` `UVM_REG_ADDR_WIDTH `` default to 64 bits (`uvm_reg_defines.svh`); a model with a wider register or field stops at `lock_model()` with `Register model requires that UVM_REG_DATA_WIDTH be defined as N or greater`, so wide-register projects redefine the macro for the whole compile.

### Expert: hierarchical models and relocatable blocks

A system model nests blocks. A sub-block calls `configure(parent, "u_i2c0")` (§18.1.2.2), so its HDL path is relative to its parent. Its map joins the parent's with `parent_map.add_submap(child_map, offset)` (§18.2.3.5), so the same `i2c_reg_block` class can sit at `'h4000_0000` and again at `'h4001_0000`. `set_base_addr()` (§18.2.3.9) relocates a map, and `set_hdl_path_root()` (§18.1.6.11) overrides the path its ancestors would give.

Two rules follow from uvm-core's implementation. Bus traffic always uses the **root** map's sequencer and adapter, so you call `set_sequencer()` once, at the top. And root block names must be unique: two top-level blocks both named `ral` give `UVM/REG/DUPLROOT` at lock time. System-level register strategy, including what auto-prediction cannot see when several masters share a bus, is in [E-SOC-1](/curriculum/T4_Expert/E-SOC-1_SoC-Level_Verification_Strategies/index).

### Expert: backdoor writes, backdoor reads and HDL path forms

`write(…, UVM_BACKDOOR)` is a *simulated* bus write: it peeks, applies each field's policy, and deposits the result, and it fails with `UVM_NOT_OK` unless the map rights are `"RW"` or `"WO"` (uvm-core, `do_write`). `poke()` is a raw deposit with no policy. On `INT_STATUS` holding `'h3`, `write('h1, UVM_BACKDOOR)` deposits `'h2`: W1C clears `DONE`, as software writing `'h1` would. `poke('h1)` deposits `'h1`, which clears `ERR` and keeps `DONE`, the opposite flag. Use `poke()` to force a state, and the backdoor `write()` to imitate software quickly.

`read(…, UVM_BACKDOOR)` writes read side effects back into the DUT: RC fields are cleared and RS fields set. In uvm-core its prediction uses the value read before that write-back, so an RC field's mirror keeps the old count while the DUT is 0, and WO fields are masked to 0 in the returned value and the mirror. `peek()` writes nothing back.

Path forms worth knowing: one variable per register (`configure()`'s third argument); slices per field for flops scattered by synthesis-friendly RTL (§18.4.6.5); several paths of different kinds, `"RTL"` and `"GATE"`, so the same test runs on a netlist; and `get_full_hdl_path()` to print the paths the model will use when a deposit fails. Backdoor access depends on the simulator's signal-access implementation of the `uvm_hdl` DPI functions and on the access you grant at compile time. Those details are tool-dependent: check your simulator's UVM documentation.

### Expert: concurrent access and the register lock

Each register serializes its own accesses with an internal lock (a semaphore). Two sequences that write the same register at once are queued, not interleaved. Three consequences, from uvm-core 2020.3.1:
- `set()` on a field while its register is mid-access warns `UVM/FLD/SET/BSY … may result in loss of desired field value`, a sign of two threads sharing one register without coordination.
- `uvm_reg::predict()` on a busy register warns, returns 0 (failure) and changes nothing; `uvm_reg_field::predict()` with `UVM_PREDICT_DIRECT` warns and returns 0, yet still overwrites the field's mirror and desired value.
- If a thread is killed mid-access, for example by a reset handler that kills the running sequences, the lock stays taken and the next access to that register hangs. A register's or block's `reset()` releases it, whatever the reset kind (§18.4.4.5, §18.1.5.3), which is one more reason the reset handler calls `ral.reset()`.

### Expert: methodology trade-offs

- **Generated or hand-written.** Generate anything larger than a handful of registers: generators keep the model, the RTL and the documentation consistent from one description. Hand-written models suit tiny blocks and teaching.
- **Commit the output or generate at build time.** Committing makes diffs reviewable and builds independent of the generator; generating at build time with a pinned generator version guarantees the model matches the description. Either works if the version is pinned and the description is the only thing anyone edits.
- **Who owns the model.** Usually the environment builds it and exposes a handle; the test may replace classes with factory type overrides before the build, for example to add a `uvm_reg_cbs` callback ([A-UVM-5](/curriculum/T3_Advanced/A-UVM-5_UVM_Callbacks/index); register callbacks in A-UVM-4B) without editing generated code.
- **Handing the model to sequences.** `uvm_reg_sequence::model`, set by whoever starts the sequence, keeps sequences reusable across environments; a `uvm_config_db` handle is the alternative for components.
- **Adapter or layering.** `set_sequencer(sqr)` *without* an adapter makes the map send `uvm_reg_item`s to a register sequencer; a `uvm_reg_sequence` running there as a translation sequence turns them into bus items (§19.4.1, `REG_NO_ADAPT`). It suits stacks where the register traffic must pass through a protocol layering scheme ([I-UVM-3B](/curriculum/T2_Intermediate/I-UVM-3B_Advanced_Sequencing_and_Layering/index)). The adapter is simpler and is what most environments use.

### Debug challenge: three bugs on the first day

A colleague's block and environment produce the symptoms below. Name the bug behind each one from the log alone, then give the one-line fix. Try it before opening the answer.

```systemverilog
// snippet: excerpts from i2c_reg_block::build() and i2c_env
CTRL = ctrl_reg::type_id::create("CTRL");
CTRL.configure(this, null, "ctrl_q");
INT_STATUS = int_status_reg::type_id::create("INT_STATUS");
INT_STATUS.configure(this, null, "int_q");
INT_STATUS.build();
default_map = create_map("default_map", 'h0, 4, UVM_LITTLE_ENDIAN);
default_map.add_reg(CTRL,       'h00, "RW");
default_map.add_reg(INT_STATUS, 'h08, "RO");
lock_model();
// ...
function void i2c_env::build_phase(uvm_phase phase);
  // ... agent, ral and adapter created as on this page ...
  ral.default_map.set_sequencer(agent.sequencer, adapter);
endfunction
```

1. The first run stops at time 0 with `UVM_ERROR [REG_NULL_SQR] Null reference specified for bus sequencer` and then a `UVM_FATAL [SEQ] … neither the item's sequencer nor dedicated sequencer has been supplied …`.
2. After that is fixed, writing `'h1` to `INT_STATUS` clears `DONE` in the waveform, but the model still believes `DONE` is 1 until the next read of the register.
3. `write_reg(CTRL, status, 'h5)` reaches the DUT, which now holds `'h5`, but `CTRL.get()` and `CTRL.get_mirrored_value()` both stay 0 with auto-prediction on, and `mirror_reg(CTRL, status, UVM_CHECK)` never reports anything, whatever the DUT holds.

<details className="my-4 rounded-xl border border-border/70 p-3">
<summary className="cursor-pointer font-semibold">Show the answers</summary>

1. `set_sequencer()` runs in the environment's `build_phase`, before the agent's `build_phase` has created `agent.sequencer`, so it receives `null`. The map then has no sequencer, and the first frontdoor call cannot start its item. **Fix:** move the call to `connect_phase`.
2. `INT_STATUS` is added with `"RO"` rights, so its W1C fields predict as RO: the clear is sent and works, but the mirror keeps the old value (and `update()` would never write the register). **Fix:** `add_reg(INT_STATUS, 'h08, "RW")`.
3. `CTRL.build()` is missing, so the register has no fields. Writes still go out on the bus with the value you pass, but `set()`, prediction and the compare all work field by field, and there are none: the compare mask is 0, so it can never fail. **Fix:** call `CTRL.build()` after its `configure()`.

</details>
