   - The "interoperability via DPI" section and flashcard 9 attribute an SV↔Python DPI bridge to pyuvm and cocotb.

**Expert: absent.** Add these `### Expert:` items:
1. *Liveness in simulation versus formal.* In `assert property`, an unqualified sequence is weak (§16.12.2), so `req |-> ##[1:$] resp` can never fail on a finite run. Use `s_eventually`/`strong(...)` (§16.12.13) for formal, and a bounded `##[1:MAX]` safety property for regression. How a pending strong obligation is reported at the end of simulation is tool-dependent.
2. *SoC register models and prediction at scale.*
   - One predictor holds one map (`uvm_reg_predictor.svh:114,172`), so each bus needs its own predictor.
   - Bridges translate addresses.
   - Memories are not predicted (§19.3).
   - `poke` predicts unconditionally in uvm-core (`uvm_reg.svh:2696`) although §18.4.4.11 says it "is affected by the auto-prediction configuration".
   - §18.2.5.2 states both "default value of on shall be 1" (the argument default) and "When on is False (the default)" (the map's mode; uvm-core `m_auto_predict = 0`).
3. *Firmware/testbench synchronization races.* `wait_trigger` (§10.1.1.2.4) misses a trigger that already happened. `wait_on` (§10.1.1.2.2) returns at once if the event is on. Put a firmware image hash in the log.
4. *What block checks need at SoC.* ID widening at the interconnect (§A5.3.5); DECERR from a default slave for unmapped holes (§A3.4.4); AxPROT-based security coverage (§A4.7). Each scoreboard needs an owner and a decision: keep, adapt or disable.
5. *CDC/RDC sign-off awareness.* Structural CDC/RDC analysis is a sign-off flow outside UVM. RTL simulation shows no metastability unless the tool injects it (tool-dependent). IP teams can hand over abstract models under Accellera's CDC/RDC Standard 1.0 (approved 2026-03-02).
6. *Scaling: emulation and portable tests.* Which SoC tests move to emulation and what must change in the bench (E-EMU-1). Where PSS fits (E-PSS-1, `pss.mdx`).
7. *Regression economics and closure gates.* Flaky-test policy, seeds (I-SV-2B), first-failure signatures (E-DBG-1), and gates as project policy (no invented industry percentages).
8. *Interview angles* (attempt-first, InterviewQuestionPlayground):

### Assessment plan

**Quiz.** Add 7 questions in the canonical `<Quiz questions={[…]}/>` format, each with `objective`. Nothing exists to keep.
1. **Obj 3, predict; misconception 1.** "The SoC map has `set_auto_predict(1)` and no predictor. Boot firmware writes `'h9` to CTRL. What does `rm.ctrl.get_mirrored_value()` return?"
   - **Key:** the value before the write. Auto-predict covers only accesses the register model starts (§18.2.5.2).
   - **Distractors:** `'h9` (auto-predict sees the bus); `'h9` after a `get()` call (`get` returns the desired value, §18.4.4.1); X (the mirror is stale, not invalidated).
2. **Obj 2, debug; misconception 2.** "A block AXI scoreboard reused across the interconnect reports every response as unmatched. Most likely cause?"
   - **Key:** slave-side IDs carry extra master-port bits (A5.3.5); translate IDs or correlate at the master side.
   - **Distractors:** the monitor is off (that gives no transactions, not mismatches); AXI forbids reordering (it does not, across IDs); the scoreboard must be made active.
3. **Obj 4/5, misconception 3.** "Every block closed 100% functional coverage in its own regressions. What does that prove about SoC closure?"
   - **Key:** nothing about integration; SoC closure needs system goals collected at SoC.
   - **Distractors:** merged databases at 100% = closed; re-close every block coverpoint at SoC (the trap at `:89`); only code coverage matters.
4. **Obj 2, predict.** "A virtual sequence runs `spi_seq.start(p_sequencer.spi_sqr)` while `spi_agent` is passive. What happens?"
   - **Key:** `UVM_FATAL [SEQ]` at the first `start_item`, because the sequencer handle is null (uvm-core `uvm_sequence_base.svh:1062`).
   - **Distractors:** it runs while the driver idles (the built-but-idle misconception, which the visualizer also targets); items go to the monitor; the agent turns active.
5. **Obj 4, predict.** "`assert property (@(posedge clk) req_accepted |-> ##[1:$] resp_valid);` and one response is lost in a 2 ms run. Does the assertion fail?"
   - **Key:** no. In an assert the sequence is weak (§16.12.2); use `s_eventually` for formal or a bounded `##[1:MAX]` for simulation.
   - **Distractors:** fails at the end of simulation (true only of a strong property, and reporting is tool-dependent); fails one cycle later; passes vacuously.
6. **Obj 5, debug.** "A scoreboard mismatch appears in nightly. Which first step is right?"
   - **Key:** capture the evidence package and bucket by first divergence; it can be RTL, reference model, test intent, firmware or infrastructure.
   - **Distractors:** file an RTL bug (the old `:102`); rerun with a new seed; waive the bin.
7. **Obj 3, debug.** "Firmware writes BOOT_DONE at 2 µs and the decoder triggers `fw_boot_done`. The test reaches `ev.wait_trigger()` at 5 µs. What happens?"
   - **Key:** it waits forever (missed trigger); use `wait_on` (§10.1.1.2.2) or `is_on`.
   - **Distractors:** it returns at once; `UVM_FATAL`; it returns at the next firmware write.
