  - No symptom → cause → fix debugging.
  - Nothing on how a real bench uses plusargs, vector files, severity counting or waveform dumps.
  - To add: the two worked examples and the debug sections in the target outline below.
- **Expert: absent.** index Push Further is two one-line suggestions; the other two pages have no Push Further. Items to add, all verified:
  1. Output copy-out at task return, and why a task cannot drive a pin through an `output` argument (§13.3: "output // copy value out at end").
  2. `ref` corner cases (§13.5.2):
     - illegal on static subroutines;
     - only variables, class properties, unpacked struct members and unpacked array elements can be passed by reference, never nets;
     - a `ref` argument "shall not be used in any context forbidden for automatic variables, unless it is `ref static`". Combined with §6.21, this means no NBA to a plain `ref` argument;
     - outdated references to elements of dynamic arrays and queues.
  3. Formal-list inheritance (§13.3): once a direction is given, later formals inherit it (`task t(output int a, int b)` makes `b` an output); the default type is `logic`.
  4. Lifetime corner cases:
     - explicit `static`/`automatic` locals (§13.3.1);
     - a static initializer runs once (the LRM `top_legal` example prints 1…9; §6.21);
     - per-instance storage of static tasks (§13.3.2);
     - automatic items cannot be referenced hierarchically (§13.3.1);
     - automatic variables cannot be traced by `$monitor`/`$dumpvars` (§13.3.2);
     - `program automatic` (§6.21).
  5. Class methods: the lifetime is always automatic, and "It shall be illegal to declare a class method with a static lifetime" (§8.6). `static task` (a class method) is not `task static` (illegal in a class) (§8.10).
  6. Functions that schedule work (§13.4.4): NBA, event triggers, clocking drives and `fork…join_none` are allowed; constant functions (§13.4.3); recursion needs `automatic` (factorial example, §13.4.2).
  7. `$monitor` details (§21.2.3): one active list; `$monitoron/$monitoroff`; `$time/$stime/$realtime` changes do not trigger; one line per time step. `$fmonitor` can have many active (§21.3.2). `$strobe` of `$sampled` (§21.2.2 example).
  8. Pass/fail you can trust: `$fatal` takes finish_number 0/1/2 first and calls `$finish` implicitly (§20.10); `final` still runs (§9.2.3); simulator exit status on `$error` is tool-dependent (label it as such).
  9. File descriptors vs multichannel descriptors (§21.3.1): MCD bit 0 is stdout, MCDs can be OR-ed, at most 31 MCD files; an fd has the MSB set; STDIN/STDOUT/STDERR = 32'h8000_0000/1/2.
  10. Robust parsing:
      - `$fscanf` returns the item count, 0 on an early mismatch, or EOF (-1) (§21.3.4.3);
      - `%*` suppresses assignment (§21.3.4.3);
      - `$fgets` (§21.3.4.2) and `$sscanf`;
      - `$feof` is true only after a read has hit EOF (§21.3.8), hence the classic "last vector processed twice" bug;
      - `$ferror` (§21.3.7) and `$fflush` (§21.3.6).
  11. Plusargs at regression scale (§21.6): prefix matching (the LRM's `+HELLO` example matches `"HE"` and `"H"`); `$value$plusargs` leaves the variable unmodified and warns nothing on a miss. UVM preview: `uvm_cmdline_processor::get_inst().get_arg_value()` (uvm-core 2020.3.1).
  12. Random stability (§18.14.1-2): per-thread RNGs and hierarchical seeding; `$urandom`/`$urandom_range` are thread stable; add new threads at the end of a block to keep earlier values.
  13. Dump scope and cost: `$dumpvars` levels (§21.7.1.2), `$dumpoff/$dumpon` (§21.7.1.3), `$dumplimit` (§21.7.1.5). Vendor formats and their speed cost are tool-dependent; label them.
  14. Staff-level interview questions (listed in the target outline).
