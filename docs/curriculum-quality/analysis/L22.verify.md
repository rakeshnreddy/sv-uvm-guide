## Completeness and depth gaps the analyst missed

**I-UVM-2C**
1. **Which resource types automatic configuration accepts.** This is the substance of the must-cover item "automatic field configuration caveats"; see the L22-2C-03 adjustment. The classic traps:
   - `` `uvm_field_object(cfg) `` with `uvm_config_db#(bus_agent_cfg)::set` leaves `cfg` null;
   - `` `uvm_field_int(n) `` with `uvm_config_db#(bit [7:0])::set` is ignored.
2. **uvm-core diverges from 1800.2 here (expert, library-dependent).** The default mode is `CONFIG_CHECK_NAMES` (`UVM_COMPONENT_CONFIG_MODE_DEFAULT`). `+define+UVM_COMPONENT_CONFIG_MODE_DEFAULT=CONFIG_STRICT` restores the LRM behaviour. Sources: `uvm_global_defines.svh:42-53`; `uvm_component.svh:1505-1530`, `:3245-3324`.
3. **Precedence comes from `cntxt`** (L22-2C-V01). This includes how one sibling configures another, a detail the analyst's "sibling build order" debug case and explorer preset depend on.
4. **`wait_modified` wakes regardless of precedence.**
   - It wakes on any later `uvm_config_db` set with the same `T` and the exact field name, because `set()` calls `trigger_modified` unconditionally (`:418`).
   - During build, a lower-precedence set therefore wakes the waiter while `get()` still returns the older value.
   - `uvm_resource_db` sets never wake it (`uvm_resource_db_implementation.svh:332-346`).
   - Add this to expert item 5.
5. **Trace noise.** The trace includes failed lookups made by the library itself (see the plan-item adjustment). The debug walk-through must say which failed lookups to ignore. The `(type …)` text comes from `$typename` and its format depends on the simulator, so label sample logs illustrative.
6. **The optional `get()` idiom** (L22-2C-V03).
7. **`print_config` and `check_config_usage` semantics** (L22-2C-V04).
8. **Field names are matched exactly** (through the `rtab[name]` name map). The header of `uvm_config_db.svh` (`:96-97`) says `field_name` "may be glob style or regular expression style", so warn experts not to glob field names in `set()`.
9. **`uvm_config_db_options::turn_on_tracing()`** is the code alternative to the plusarg (uvm-core impl.; `uvm_config_db.svh:246-252`).
