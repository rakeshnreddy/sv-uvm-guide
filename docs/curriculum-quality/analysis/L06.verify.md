## Completeness and depth gaps the analyst missed

**F3A**
1. **Core: when simulation stops.** The §4.5 outer loop runs only while some time slot is non-empty. A simulation ends when no activity remains (§9.6.1) or when `$finish` exits (§20.2). Learners need this to see why a free-running clock never stops (L06-F3A-V01). It is absent from the target outline.
2. **Practitioner: `$timeunit` and `$timeprecision` (§20.4.1).** They return the unit and precision as an exponent from 2 to −15; `$root` gives the simulation time unit. The analyst lists §20.4.1 as verified, but no objective, card or example uses them. Use: a time-0 check that a package's unit is what its callers assume.
3. **Practitioner: `$printtimescale($unit)` (§20.4.2).** It shows the compilation-unit time scope, which pairs with the proposed compilation-unit `timeunit`. Also teach precedence rule (a), nested inheritance (see L06-F3A-02).
4. **Expert: delay-value corner cases (§9.4.1).** An x or z delay is treated as zero. A negative delay is reinterpreted as an unsigned time-sized value, which is a very long wait.
5. **Expert: real-to-integer ties round away from zero (§6.12.1).** This governs `$time` and any real passed into a `time` argument; for example, `wait_t(1.5ns)` in the debug challenge becomes 2. The analyst's tie caution (L06.md:987) is right for delays, because §3.14.1 has no tie rule, but integer conversions should cite §6.12.1.

**F3B**
6. **Practitioner/expert: program termination (§24.3, §9.6.1).** When all program `initial` threads finish, the run ends by an implicit `$finish`. It belongs in the program-block material, and every program example must allow for it (see L06-F3B-01).
7. **Practitioner pitfall: `$finish` in the same slot as `$strobe` or `$monitor` loses that slot's Postponed output** (§20.2, §9.2.3). Pair it with "Use `$strobe` for debug" (index.mdx:45). It is also why the worked example ends with `#1 $finish`.
8. **§4.9.7 (subroutines).** Arguments are copied in at the call and copied out at return, and the copy-out behaves like a blocking assignment. The analyst's spine suggestion (L06.md:950) keeps §4.9.1–§4.9.4 and §4.9.6 but drops §4.9.7 without a reason. Tasks are T1 scope (F2D), so keep it.
9. **"Where each construct runs" table.** Add the delayed NBA `q <= #d e`, whose update lands in the NBA region of a later slot (§4.4.2.4, §4.9.4).

**F3C**
10. **Expert: zero-delay glitches.** A combinational process can run more than once in a slot, so an immediate assertion inside `always_comb` can report a transient value. Deferred assertions exist to suppress such glitch reports (§16.4, §16.4.1). This ties delta cycles to assertion design.
11. **Practitioner: an opposite-edge drive row.** The "Which testbench patterns race?" table lacks `@(negedge clk) din = v;`, which is deterministic for posedge flops. Spine §5.2(6) endorses this style before F4C.
