## Completeness and depth gaps the analyst missed

1. **The AHB-side ordering rules are the normative basis for the posting interlock.**
   - IHI0033B.b §3.8.4: "All read and write transfers from the same master to the same slave must remain ordered."
   - IHI0033B.b §3.8.5 gives the overlapping-address rule for Normal memory.
   - The analyst's objective 2, expert item 4, the F2 SequenceDiagram and Q5 cite only IHI0022E A5.3.4. The bridge must preserve AHB order because AHB requires it; A5.3.4 says AXI will not do it for the bridge.
2. **IHI0022E is internally inconsistent on same-ID read/write ordering** (A4.4.1 vs A5.3.4).
   - The expert layer should say so in one sentence and tell the reader to design to the stricter rule: wait for BRESP or address-check outstanding writes, as the A5.3.4 note suggests.
   - Later issues' ordering model is unverified here.
   - Answer keys must avoid making this the discriminator.
3. **AXI ID assignment in an AHB-to-AXI bridge is missing from the expert layer.** Options include:
   - a single fixed AWID/ARID;
   - separate IDs per direction;
   - IDs per HMASTER on AHB5.

   This decides write-response ordering, the read/write hazard above, and the exclusive pairing (A7.2.4: "The ARID value of the exclusive read must match the AWID value of the exclusive write").
4. **AXI channel-handshake dependencies** are absent from the bugs, the plan and the checks, for both bridge roles (L39-F1-V05, L39-LAB-V01). The objective-4 list ("outstanding overflow") should become "outstanding overflow and channel-dependency deadlock".
5. **The unknown-length INCR (L39-F1-06) has no picture in the analyst's Visual coverage.** Add a short `<TimingDiagram>`: an AHB INCR write that ends when HTRANS goes from SEQ to NONSEQ or IDLE. It shows that the bridge learns the length only in the last transfer's address phase. Pair it with a prediction: "when can the bridge drive AWLEN?".
