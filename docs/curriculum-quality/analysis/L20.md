### Depth ladder

- **Core (present, needs repair).** The register → override → create story, the `new()` trap and type vs instance overrides read well. Add:
  - a definition of the proxy (`type_id`) before it is used;
  - a "where it breaks" for the analogy;
  - an objectives block and prerequisites.
- **Practitioner (partial).** The precedence rules are right (1B:131-139). Missing:
  - a complete compiling worked example with expected `UVM/FACTORY/PRINT` and `UVMTOP` output;
  - all call forms with their argument orders:
    - registry statics (§8.2.3.2.5-6), preferred by D.2.1;
    - `uvm_factory::set_*_override_by_type/_by_name` (§8.3.1.4);
    - `uvm_component::set_type_override_by_type` / `set_inst_override_by_type(relative_inst_path, orig, ovr)` (D.2.1.3/D.2.1.4);
  - object overrides and the `contxt` argument. `uvm_registry_common::create` uses `parent.get_full_name()` only when `contxt==""` (`uvm_registry.svh:591-596`). Items made by `create_item` (the `uvm_create`/`uvm_do` path) use the sequence's `get_full_name()` (`uvm_sequence_base.svh:1015`). Link I-UVM-3A.
  - command-line overrides (G.2.7);
  - a symptom → cause → fix table.
- **Expert (partial).** "Advanced Factory Dynamics" holds verified corner cases but is not a `## Push Further` with `### Expert:` items. Add these:
  1. **Command line vs code (uvm-core impl.).** `+uvm_set_*_override` is applied in `uvm_root::build_phase` (`uvm_root.svh:782`, `m_do_factory_settings`). That is before the test's `build_phase` but after `run_test` created the test (`uvm_root.svh:566`). Three consequences:
     - a later `set_type_override` with `replace=1` replaces the command-line type override (`uvm_factory.svh:1166`, TPREGR at UVM_MEDIUM);
     - a command-line instance override wins over the test's override for the same path, because it was registered first (§8.3.1.4.1);
     - a command-line override of the test class has no effect. An override registered in `tb_top` before `run_test` does apply, and `run_test` logs `Running test X (via factory override for test "Y")`.
  2. **Parameterized and abstract classes** (B.2.1.3, §8.2.5). A param class has no type name, and `factory.print()` shows `<unknown>`. `uvm_component_abstract_utils` gives `UVM/ABST_RGTRY/CREATE_ABSTRACT_CMPNT` ("Check for missing factory overrides") when the class is created without an override (`uvm_registry.svh:327-330`).
  3. **Who owns the factory.** `uvm_coreservice_t` and `uvm_factory::set` (§8.3.1.2.2, F.4.1.4.3).
  4. **Corner cases.** Aliases (§8.3.1.6). A path of `"*"` acts as a type override (§8.3.1.4.1). A by-name override with a misspelled original name never matches. A misspelled override name gives TYPNTF and then a null-object crash. No registered ancestor gives NOTYPID then NULLWR.
  5. **Scale (implementation observation, labelled).**
     - Every `create` scans the instance-override queue in order (`uvm_factory.svh:1809-1822`).
     - Wildcard paths go through `uvm_is_match`.
     - Prefer type overrides and few, specific instance paths.
  6. **Factory vs callbacks vs `config_db`.** A methodology trade-off; link A-UVM-5 and I-UVM-2C. The precedence rules differ: factory = first registered match, while `config_db` uses its own precedence rules (owned by I-UVM-2C).
  7. Attempt-first staff interview questions.

### Objectives

**You will be able to:**
1. Predict the call order and direction of the common phases for a component tree: build and final top-down; connect, end_of_elaboration, start_of_simulation, extract, check and report bottom-up; run a task phase.
2. Explain how `run_phase` runs in parallel with the twelve run-time phases, and predict when each phase ends.
3. Write end-of-test control in the test (raise before any delay, drop after the stimulus) with `set_drain_time` and `phase_ready_to_end` for in-flight traffic, and predict when `run_phase` ends.
4. Debug a test that ends at 0 ns or hangs using `set_timeout`/`+UVM_TIMEOUT`, `+UVM_OBJECTION_TRACE`, `+UVM_PHASE_TRACE` and `display_objections` (the last three uvm-core impl.).
5. Use `uvm_event` and `uvm_barrier` to synchronize threads independently of phases, and explain why domains and phase jumps are advanced and hazardous.
