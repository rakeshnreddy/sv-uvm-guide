**Expert: absent.** "Push Further: Common Pitfalls" (:213) holds junior pitfalls only. Add these `### Expert:` items:
1. **Compilation units and directive leakage.** Quote §3.12.1: "compiler directives from one separately compiled unit shall not affect other compilation units. This may result in a difference of behavior…". Include guards protect only within one unit. Compile a package once and `import` it; do not `` `include `` it into several units. Tool switches that choose single-file or multi-file units are tool-dependent: label them and verify their names in each manual.
2. **IEEE 1800-2023 directive features.**
   - `` `ifdef (A && !B) `` with `&&`, `||`, `->`, `<->` and `!` (§22.6).
   - `` `""" `` triple-quoted strings inside macro text (§22.5.1).
   - Tool support varies; say so.
3. **`let` vs macro vs parameter vs function.**
   - §11.12 says a `let` "can replace the text macros in many cases" and is "safer because it has a local scope".
   - The result of a `let` substitution is parenthesized, and recursive `let` is not permitted.
   - A macro is still needed to generate declarations or statements, to stringify, and for the UVM utility macros.
4. **Time-unit precedence.**
   - Precedence for a design element without its own `timeunit`: inherit from the enclosing module if nested, else the last `` `timescale `` in the compilation unit, else the compilation-unit `timeunit`, else the default (§3.14.2.3).
   - §3.14.2.3: "It shall be an error if some design elements have a time unit and precision specified and others do not."
   - With no `` `timescale ``, or after `` `resetall ``, the default unit and precision are tool-specific (§22.7).
5. **Generate at scale.**
   - Recursive instantiation (§27.2).
   - Sparse generate arrays (§27.4).
   - `defparam` cannot reach outside its generate-block instance (§23.10.1); avoid `defparam`.
   - Elaboration time and memory for large N: tool-dependent, label it.
   - Generated per-agent virtual interfaces.
6. **Debugging macro-heavy code.**
   - Preprocess-only output: verified for Verilator (`-E`, `-P`); other tools should be labelled and their switches verified.
   - `` `__FILE__ `` is "the path by which a tool opened the file", with an implementation-dependent format (§22.13).
   - uvm-core's `UVM_REPORT_DISABLE_FILE_LINE` (`uvm_message_defines.svh`).
   - `` `line `` (§22.12) in generated code.
7. **Interview angles** (attempt-first; see the assessment plan for keys):
   - why `` if (c) `uvm_info(…); else … `` does not compile;
   - what `genblk2` is and how to avoid it;
   - how to configure N generated interfaces;

**`## Build Your Mental Model`**
1. `### When is each knob turned?`
   - Context first: preprocessing (macros, `` `ifdef ``), elaboration (parameters, generate, bind), run time (plusargs, config).
   - Picture: an `<ArchitectureDiagram>` pipeline (spec in Visual coverage).
2. `### How compiler directives work`
   - Backtick syntax.
   - Scope runs "from the point where it is processed, across all files processed in the current compilation unit" (§22.2).
   - Text directives vs state directives (fixes -09).
   - Picture: the compilation-unit diagram.
   - Define "compilation unit" (§3.12.1).
3. `### Text macros`
   - Every form in §22.5.1: object-like and with arguments, default arguments, backslash-newline continuation, comments stripped, no substitution inside `"…"`, `` `" ``, `` `\`" ``, ``` `` ```, macro usages in the text expanded at use, recursion is an error, redefinition allowed (last wins).
   - Each form with a traced-expansion table (code → expansion → result).
   - Pitfalls with why each is wrong: missing parentheses (`SQ`), double evaluation (`MAX` with a side-effect function), trailing `;`, begin–end plus `;` in if/else, commas in arguments (need matched brackets).
   - Macro vs `parameter` vs `let` (§11.12) in one table.
4. `### Macro hygiene, the way UVM does it`
   - The uvm-core excerpts listed in L18-ISV6-05, each with one rule it teaches:
     - wrap statements in `begin … end` and document "no semicolon at use";
     - prefix macro-local names;
     - stamp `` `__FILE__ ``/`` `__LINE__ `` at the use site;
     - stringify type names with `` `" ``.
   - The include guard and flag cascade in `uvm_dpi.svh` (`` `ifndef UVM_DPI_SVH ``; `UVM_NO_DPI` defines `UVM_HDL_NO_DPI`, `UVM_REGEX_NO_DPI`, `UVM_CMDLINE_NO_DPI`).
   - Keep the five existing rules.
5. `### Conditional compilation and include files`
   - `` `ifdef/`ifndef/`elsif/`else/`endif ``, nesting, and the 1800-2023 expression form (§22.6, tool support varies).
   - Feature flags as independent blocks (the `` `elsif `` trap, -11).
   - `` `include "…" `` vs `<…>` (§22.4); nesting allowed to at least 15 levels.
   - Include guards and their limit (one compilation unit). Packages are compiled once and imported.

**`## Make It Work`**

A complete example: a C CRC reference model (`pure`) checked against a small SystemVerilog CRC "DUT", plus a context task that waits N clocks. A sketch:

```systemverilog
// compile (with crc_model.c)
package crc_dpi_pkg;
  // Depends only on its inputs and keeps no C state: pure (§35.5.2)
  import "DPI-C" pure function int unsigned crc32_step(input int unsigned crc,
                                                      input int unsigned word);
endpackage
// tb_top: crc_dut computes the same step in RTL (`ifdef CRC_BUG flips one bit);
// crc_checker calls crc32_step() for every accepted word and compares;
// prints PASS=<n> FAIL=<m>.
// The same module also holds:
//   export "DPI-C" task sv_wait_clks;
//   task automatic sv_wait_clks(input int n); repeat (n) @(posedge clk); endtask
//   import "DPI-C" context task c_poll_model(input int max_polls, output int status);
```

```c
#include "svdpi.h"
unsigned int crc32_step(unsigned int crc, unsigned int word) {   /* no state, no I/O */
  for (int b = 0; b < 32; b++) {
    unsigned int bit = (word >> b) & 1u;
    crc = (crc >> 1) ^ (0xEDB88320u & (0u - ((crc ^ bit) & 1u)));
  }
  return crc;
}
extern int sv_wait_clks(int n);               /* exported SV task: returns 1 if disabled */
int c_poll_model(int max_polls, int *status) {
  for (int i = 0; i < max_polls; i++)
    if (sv_wait_clks(2)) return 1;            /* disabled: acknowledge (§35.9) */
  *status = 0;
  return 0;
}
```

**Expected values** (computed and cross-checked against `zlib.crc32` of the little-endian bytes): for the words `32'h0000_0001`, `32'hDEAD_BEEF` from reset value `FFFF_FFFF`, the register is `66074786` after word 1, `6d699f0b` after word 2, and the final inverted CRC is `929660f4`. Print time with `$time` and `%0d` rather than `%t`. By default, `%t` uses "the smallest time precision argument of all the `` `timescale `` compiler directives" (§20.4.3, Table 20-3), so it prints `55000` for 55 ns under `1ns/1ps`.
