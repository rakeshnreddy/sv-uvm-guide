## Completeness and depth gaps the analyst missed

1. **Narrow integral key types alias keys (expert).**
   - §7.8.4: "The index expression shall be evaluated in terms of a cast to the index type". With `int aa[byte]`, `aa[300] = 1` therefore writes key 44, and 44 and 300 share one entry.
   - The analyst covers only the §7.9.8 case, a narrow *traversal variable*.
2. **Deleting during a `first()`/`next()` traversal is defined; deleting inside `foreach` is not.**
   - `next()` "finds the smallest index whose value is greater than the given index argument" (§7.9.6), and that index need not exist. Deleting the visited key before calling `next()` is therefore well-defined for integral and string keys, unlike `foreach` (§12.7.3). This is the one-pass alternative to the two-pass delete.
   - For user-defined key types with no relational operators, the order may change once indices are added or deleted (§7.8.5).
3. **Traversal return values and `last()`/`prev()` (objective 2: predict `first`/`next`).**
   - `first()` and `last()` return 0 on an empty array.
   - `next()` and `prev()` return 0 and leave the index unchanged at the end.
   - All four reject wildcard arrays (§7.9.4–§7.9.7).
   - The outline has only "a `first()/next()` loop".
4. **The 2023 `index_argument`.** Syntax 7-5 adds `[ , index_argument ]`, which renames `index` when the element struct has a member of that name. §7.12.4's example: `arr.find(item, iter_index) with (item.index != item.iter_index)`. The page's `:315` names "iterator and index arguments"; the analyst teaches only `item.index`.
5. **Whole-array equality for in-order checkers.**
   - §7.4.6 allows `A == B` on whole arrays, associative arrays included, so `if (act_q != exp_q)` and `%p` printing are the natural M0 end-of-test check.
   - This is practitioner content; link F2A if F2A owns §7.4.6.
6. **`$left`/`$right` on integral-keyed associative arrays (§20.7).** `$left` returns 0 and `$right` returns "the highest possible index value" (2147483647 for `int`), not the largest key. The proposed query-function table must show this, or authors will write 9.
7. **Other ways a size changes.** `randomize()` resizes a constrained `rand` dynamic array or queue (§18.4), and a streaming unpack resizes a dynamic target (§11.4.14.4). At minimum, give a forward link to I-SV-2 in the dynamic-array section.
8. **A debugging row the analyst omits: "the tracker passes with leftovers".** If leftover items are only printed, a regression that greps for `FAIL=0` passes with lost responses. Spine §5.2 item 14 puts `pending=0` in the scoreboard signature. Add it to the debugging table, the kata acceptance and quiz Q9.
9. **A UVM expert contrast to add.** `uvm_pool::delete()` warns `POOLDEL` when the key is missing, while native `delete(k)` is silent (§7.9.2). uvm-core 2020.3.1 `uvm_pool.svh` shows both behaviours: `get()` allocates and `delete()` warns.
10. **The wildcard restriction is broader than the depth ladder says.** See the adjusted row: §7.8.1 bars `foreach` and all array-returning methods, `map()` included.
