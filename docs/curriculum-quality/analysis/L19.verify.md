## Completeness and depth gaps the analyst missed

1. **uvm-core's automatic configuration diverges from 1800.2** (1A expert item 4; an I-SV-9 "What UVM costs" example that needs no figures).
   - uvm-core says its `apply_config_settings` "diverges from the 1800.2 standard definition" (`uvm_component.svh:877–881`). Its default mode is `CONFIG_CHECK_NAMES`, "a divergence from 1800.2, however the performance increase is drastic"; `+define+UVM_COMPONENT_CONFIG_MODE_DEFAULT=CONFIG_STRICT` restores the standard behaviour (`uvm_global_defines.svh:42–53`). The strict scan carries the comment "VERY expensive" (`uvm_component.svh:3312`).
   - Derived from the source, not yet confirmed in a simulator: only names reported by `do_execute_op(UVM_CHECK_FIELDS)` are looked up (`:3254–3310`), so a member set only through a hand-written `set_local` (§13.1.5.1 b) may never receive its setting.
2. **Ports, exports and imps are hierarchical children** (1A practitioner). §5.5: `uvm_port_base` "possess[es] the properties of components in that they have a hierarchical instance path and parent". uvm-core builds a `uvm_port_component` child (`uvm_port_base.svh:75`, `:293–303`). So ports show up in `get_children` and `print_topology`, share the child-name space (`CLDEXT`), and hit `ILLCRT` if built after build. A sequencer's internal FIFOs set `print_enabled = 0` (`uvm_sequencer_param_base.svh:260–262`), so they do not print. Teach this before the `print_topology` prediction.
3. **Errors during build stop the run** (1A debugging). F.7.3.6: if the root's error count at end of elaboration is greater than 0, "a UVM_FATAL message is generated so the simulation does not continue to the uvm_start_of_simulation_phase". uvm-core reports `UVM_FATAL [BUILDERR] stopping due to build errors` (`uvm_root.svh:331–345`). An `ILLCLN` or `INVSTNM` error in `build_phase` therefore surfaces as `BUILDERR`; put it in the symptom → log → fix table.
4. **Bottom-up order: standard vs uvm-core** (1A explorer debrief; expert item 1). §9.5 describes bottom-up informally as "first on components without any children; once finished, … on each of the first sets' parents". uvm-core is depth-first post-order (`uvm_bottomup_phase.svh:68–74`), so `agt`'s subtree finishes before `scb` runs. Teach the invariant "every child before its parent", and label the explorer's exact numbering uvm-core.
5. **The constructor and `create` rules as uvm-core enforces them** (1A practitioner and expert).
   - **Objects** declare `new(string name = "…")`, because `create()` calls both `new()` and `new(name)` (L19-SV9-12).
   - **Components** get only the registry and type name from `` `uvm_component_utils `` (`uvm_object_defines.svh:417–420`); `create_component` calls `new(name, parent)`, and `create()` on a component reports `ILLCRT`. B.2.1.3 says the component macros "Implement create … using a two argument constructor", so cite uvm-core, not B.2.1.3, when you say components have no `create()`.
6. **Names and context of sequences and items** (1A core: objective 3, misconception 2). Add L19-UVM1A-V03's content, and say that `uvm_transaction`'s initiator is an association, not a parent: "The meaning of initiator is up to the user" (§5.4.2.14). This keeps the "no component parent" key of planned Q2 unarguable.
7. **A picture for "What UVM is, and what it is not"** (I-SV-9 core). README §Visuals requires a picture for every core concept, and the outline has none. Use a small stack diagram (IEEE 1800 language and simulator at the bottom; `uvm_pkg` compiled from uvm-core to the IEEE 1800.2 API in the middle; your test, env and agents on top; side notes: not a language, not a simulator mode, no speed-up). This is the picture for misconceptions 1 and 2.

10. **"No later than build" has LRM support** (1A must-cover 4; spine cross-cutting 2). F.7.3.1 f) speaks of components created before phasing "either by run_test or by the user", so top-level components may legally exist before `run_test`; uvm-core's `ILLCRT` fires only once build is `UVM_PHASE_DONE`.
