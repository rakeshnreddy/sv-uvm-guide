## Completeness and depth gaps the analyst missed

1. **uvm-core diverges from the standard in automatic configuration** (I-UVM-1A expert; I-SV-9 "What UVM costs").
   - **The divergence.** uvm-core says its `apply_config_settings` "diverges from the 1800.2 standard definition" (`uvm_component.svh:879–881`). Its default mode is `CONFIG_CHECK_NAMES`: "a divergence from 1800.2, however the performance increase is drastic". `+define+UVM_COMPONENT_CONFIG_MODE_DEFAULT=CONFIG_STRICT` restores the standard behaviour (`uvm_global_defines.svh`, tag). The strict lookup carries the comment "VERY expensive" (`uvm_component.svh:3312`).
   - **The consequence.** In this mode only the names that `do_execute_op(UVM_CHECK_FIELDS)` reports are looked up (:3254–3310). It follows that a member set only through a hand-written `set_local` (§5.3.12, §13.1.5.1 b) never receives its setting unless the hook reports the name. This is derived from the source; confirm it before teaching it as a corner case.
   - **Where it goes.** Add it to "Expert: What the standard requires and what uvm-core enforces" and "Expert: Automatic configuration at scale". I-SV-9 can cite it as a sourced cost example that needs no figures.
2. **TLM ports, exports and imps are child components** (I-UVM-1A practitioner).
   - `uvm_port_base::new` creates a `uvm_port_component`, which extends `uvm_component` (tag).
   - So ports appear in `get_children` and `print_topology`. They share the child-name space: a port and a child with the same name give `CLDEXT`. They also hit `ILLCRT` if built after the build phase.
   - Teach this in "Finding your way around the tree" and the `print_topology` prediction, so the prediction does not fail for a reason the page never stated.
