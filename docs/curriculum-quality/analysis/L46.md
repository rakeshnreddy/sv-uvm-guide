**Headline findings.**
1. **E-EMU-1 teaches the boundary mechanism backwards.** Its table says DPI "cannot cross into emulated DUT" (EMU:193). In SCE-MI 2 the synthesizable HDL-side transactor *calls* imported DPI functions and *implements* exported ones; DPI is the standard emulator transport (§4.7.3). Two flashcards repeat wrong models (DPI must be replaced; speed bridges sit between the emulator and the host).
2. **The two must-cover items of E-EMU-1 fail:** SCE-MI is never mentioned, and the ZeBu and Veloce architectures are still swapped (EMU:37, :44). The core skill of the card, splitting an agent into an HDL BFM and an HVL proxy, is absent: the "transaction-level driver" calls an undeclared `transactor.write(...)`.
3. **E-EMU-1's "standard" pin-level AXI driver sends duplicate write beats** (EMU:68-75): it waits an extra edge with WVALID high after every handshake.
4. **Sourced data makes the lesson's thesis concrete** and should replace the invented numbers: Synopsys's customer table shows signal-based acceleration of 1.5× to 80× against transaction-based 25× to 2091×; Mentor's TBX table shows 60× to 491× co-emulation over simulation.
5. **E-UVM-ML-1 teaches its own card's misconception 1**: "Synopsys (UVM-Connect)" and a "Cadence (ML-Connect)" product (ML:10, :179-180). UVM Connect is Mentor's (now Siemens EDA), Apache-2.0, 2012; I found no "ML-Connect".
6. **E-UVM-ML-1's UVM-ML code is not the real API and would not connect anything** (registration missing; `uvm_ml::connect` from a time-0 `initial` block; invented SystemC imp usage). Its phasing claims are universal, while HPE reports run-time phase synchronization missing up to 1.8 and Xcelium-only in 1.9. The Accellera Multi-Language Working Group is inactive.
7. **E-UVM-ML-1 never teaches UVM TLM-2** (spine gap G19: generic payload, `b_transport`/`nb_transport`, sockets, phases), which the spine assigns to this module.
8. **Neither page has the template structure, objectives, an expert layer, an accessible picture, a hands-on element or a Next link.** Both quizzes have three items with every key at index 1.

**## Quick Take**
- **What it is:** an emulator runs the DUT and the timed part of the testbench in hardware, while the untimed UVM part runs on a host computer. Emulation-aware verification is the set of bench changes that let the two talk in whole transactions, so the emulator is not stopped every clock.
- **Why it matters:** boot, firmware and long-traffic tests need billions of cycles. Give the labelled vendor data: Mentor's TBX table (60×-491×); Synopsys's customer table (signal-based 1.5×-80× vs transaction-based 25×-2091×). The difference between those ranges is this lesson.
- **The Analogy:** a factory floor (emulator) and its head office (host). The office sends whole work orders, not individual hand signals, and the floor runs flat out between orders.
  - *Where it breaks:* while the office is still writing an order, the floor stands still: hardware time is frozen while the HVL side runs (SCE-MI 2.4 §4.4.4).
  - And the office cannot watch every machine all the time: visibility costs.

**## Quick Take**
- **What it is:** connecting models and verification components written in different languages (SystemVerilog/UVM, C/C++, SystemC/TLM-2.0, e) in one run, through DPI, a transaction-level bridge, or co-simulation.
- **Why it matters:** architecture teams deliver SystemC TLM-2.0 models and algorithm teams deliver C++. Reusing them as reference models (M3) avoids a second, divergent model.
- **The Analogy:** a container port. The generic payload is the container that fits every ship (socket), and converters are customs repacking the contents.
  - *Where it breaks:* the two ports keep different clocks (who owns time) and different working days (phases), so someone must decide when the day ends (end of test).
- **You will be able to:** objectives 1-4 below.
- `<BeforeYouStart />`

**## Build Your Mental Model** (core: H3s 1-3; then *Practitioner depth*)
1. **### Three ways across a language boundary.**
   - DPI: recap I-SV-7, an untimed function per transaction.
   - A TLM-level bridge (UVMC, UVM-ML OA, vendor TLI): a SystemC/TLM-2.0 model with sockets and its own processes, run in the simulator's SystemC kernel.
   - Co-simulation: a separate executable or ISS over a tool-specific link.
   - A decision table: model type and timing, who owns time, need for unified hierarchy, configuration or phases, tool support, cost, debug.
   - Pitfall: DPI with C threads (link the I-SV-7 expert section).
   - Picture: options `<ArchitectureDiagram>` (Visual coverage row 1).
2. **### UVM TLM-2 in one page.**
   - The GP (`uvm_tlm_generic_payload extends uvm_sequence_item`; command, address, data, data length, byte enables, response status default `UVM_TLM_INCOMPLETE_RESPONSE`, extensions).
   - `b_transport` with a `uvm_tlm_time` annotation; `nb_transport_fw/bw` with phases and sync values; socket attributes.
   - A compile-able SV example: `uvm_tlm_b_initiator_socket #()` in an initiator, and `uvm_tlm_b_target_socket #(mem_target)` in a target that implements `task b_transport(uvm_tlm_generic_payload t, uvm_tlm_time delay)`.
   - Pictures: `b_transport` and `nb_transport` `<SequenceDiagram>`s (rows 2-3), each with a predict prompt.
   - Pitfalls: reusing a GP across calls; forgetting to set the response status; data length vs array size; reading the annotation as a wait.
3. **### UVM TLM-2 is not SystemC TLM-2.0.**
   - IEEE 1666-2023 (awareness): the TLM-2.0 base protocol, LT and AT coding styles.
   - 1800.2's "not an exact replication".
   - Concrete differences: time type, no DMI or debug transport in `uvm_tlm_if`, GP as a sequence item. So a bridge must convert.
4. **### Practitioner depth: how a bridge connects the two sides.**
   - UVMC: SV `uvmc_tlm #(T,CVRT)::connect(port, "lookup")`, SC `uvmc_connect(port, "lookup")`; lookup strings global; connection "just before UVM's end_of_elaboration phase"; GP converters predefined; DPI-C underneath; Command API.
   - UVM-ML OA: `import uvm_ml::*;`, `uvm_ml_run_test`, registration in build's `phase_ended`, `uvm_ml::connect` in `connect_phase`, `uvm_ml_create_component` for unified hierarchy, `uvm_ml::set_type_match` (Cadence 2018).
   - Vendor TLI.
   - UVM-SystemC (Accellera SystemC Verification WG, 1.0-beta6): UVM written in SystemC, not a bridge.
   - Each item carries its source and version.
   - Picture: bridge `<ArchitectureDiagram>` (row 4).
5. **### Practitioner depth: time, phases and end of test across languages.**
   - Which kernel owns time; common phases vs run-time phases (version- and tool-limits, HPE 2018); objection synchronizers; who decides end of test.
   - Picture: phase-alignment `<SequenceDiagram>` (row 5).
6. **### Practitioner depth: debugging a mixed-language bench.** Symptom → cause → fix:
   - unmatched lookup or unregistered port;
   - connect called too early;
   - garbled fields (converter or packing order);
   - test ends while the SC model is busy (no objection bridging);
   - frozen simulation (blocking C call);
   - crash (C++ exception crossing the boundary).
