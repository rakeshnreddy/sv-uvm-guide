## Completeness and depth gaps the analyst missed

1. **Must-cover "sampling-timing pitfalls" is partial, not "yes".** The page's only "robust" recipe races when the covergroup's event is `@(posedge clk)` (L13-3A-22, now S2). It also offers strobe as an alternative without saying that strobe reads post-edge values.
2. **The concept table contradicts L13-3A-08.** The row "Coverage computation, instance vs type" marks Picture as "yes". The explorer pictures the weighted average, but nothing pictures instance vs type, so mark it "partial".
3. **Expert gap: building bins from expressions.** No expert item covers bins built with `with` clauses or set expressions (§19.5.1.1, §19.5.1.2), for example `bins mod3[] = {[0:255]} with (item % 3 == 0);`. The same goes for `type_option.distribute_first` (Table 19-3: value distribution "prior to application of the with_covergroup_expression"), which changes how fixed-count arrays combine with `with`. Add an `### Expert:` item, or fold it into expert item 4.
4. **Expert gap: inheritance and type coverage.** "For the purposes of get_coverage(), a derived covergroup and its base covergroup are separate types … no aggregation occurs across the base and derived covergroups." A base cross also keeps contributing when its base coverpoint is overridden, unless the derived covergroup declares a cross with the same name. Add both to expert item 5 (§19.4.1).
5. **Practitioner predict items for objective 1:**
   - a fixed-count array with more bins than values leaves empty bins: `bins fixed[5] = {1,4,7}` gives `<1>, <4>, <7>, <>, <>`, and the empty bins drop out;
   - duplicate values are kept: `bins fixed[4] = {[1:10], 1, 4, 7}` gives `<10,1,4,7>` as its last bin.

   Sources: §19.5.1 ("some of the bins will be empty"; "Duplicate values are retained") and §19.11.1.
6. **Transition rules missing from expert item 3:**
   - unbounded or varying-length sequences (such as `3[=2]`) cannot be declared with `[]`;
   - `default sequence` cannot be an array;
   - `default sequence` increments only when no other transition bin increments and none is still pending. The LRM stream `4 5 7 11 8 12 2 2 3` increments `allother` twice; add it to the transitions traced table.

   Source: §19.5.2.
7. **Option-rule gaps.** Option assignments in a definition "are evaluated at the time that the covergroup is instantiated", so covergroup arguments can set them (§19.4's `option.at_least = arg` example). Setting the same option twice in one definition is an error (§19.7). Add both to the options subsection.
8. **Per-instance numbers under merge.** The rule is in expert item 6, but no issue flags the page lines that contradict it. They are V02.
