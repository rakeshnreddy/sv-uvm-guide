## Completeness and depth gaps the analyst missed

1. **Must-cover "sampling-timing pitfalls" is partial, not "yes".** The page's only "robust" recipe races under `@(posedge clk)` (-22). It also offers strobe without saying that strobe reads post-edge values.
2. **Concept table, row "Coverage computation, instance vs type".** It marks Picture as "yes". The explorer pictures the weighted average of items, but nothing pictures instance vs type, so mark it "partial".
3. **Automatic bins and exclusions (V08).** The `ct` example is the natural predict item for objective 1: "which automatic bins count after `ignore_bins`?".
4. **Bins built from expressions.** No item covers the following:
   - `with` clauses and set expressions (§19.5.1.1, §19.5.1.2), for example `bins mod3[] = {[0:255]} with (item % 3 == 0);`;
   - `type_option.distribute_first`: distribution "prior to application of the with_covergroup_expression" (Table 19-3).

   Add them to expert item 4, or make a new expert item.
5. **Wildcard transition bins.** §19.5.4: `wildcard bins T0_3 = (2'b0x => 2'b1x);` counts 00=>10, 00=>11, 01=>10 and 01=>11, "as if by (0,1 => 2,3)". Add this to expert item 2.
6. **Inheritance and type coverage.** §19.4.1: "For the purposes of get_coverage(), a derived covergroup and its base covergroup are separate types … no aggregation occurs". A base cross also keeps contributing after its base coverpoint is overridden, unless the derived covergroup declares a cross with the same name. Add both to expert item 5.
7. **Fixed-count arrays (§19.5.1, §19.11.1).**
   - `bins fixed[5] = {1,4,7}` gives `<1>, <4>, <7>, <>, <>`, and the empty bins drop out.
   - Duplicates are kept: `bins fixed[4] = {[1:10], 1, 4, 7}` makes `<10,1,4,7>` its last bin.
8. **Transition rules missing from expert item 3 (§19.5.2).**
   - Unbounded or varying-length sequences (such as `3[=2]`) cannot use `[]`.
   - `default sequence` cannot be an array.
   - `default sequence` increments only when no other transition bin increments and none is still pending. The LRM stream `4 5 7 11 8 12 2 2 3` increments `allother` twice; add it to the transitions traced table.
