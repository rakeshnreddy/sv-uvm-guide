**Practitioner and expert items missing from the depth ladder:**
1. **Which weight applies where.** L14-3B-10 covers only part of this.
   - `option.weight` on a covergroup weights the instance in the type average (§19.11.3) and in "the overall instance coverage of the simulation" (Table 19-1).
   - `option.weight` on a coverpoint or cross weights the item inside its instance. Under the default average it also weights the item's own type number (§19.11.3).
   - `type_option.weight` on a covergroup weights the type in "the overall cumulative (or type) coverage of the saved database" (Table 19-3).
   - `type_option.weight` on a coverpoint or cross weights the merged type number. In the §19.7.1 example, with `merge_instances = 1`, type coverage is ((merge of a) × 3 + (merge of b) × 5) / (3 + 5), while each instance uses its `option.weight` values (2 and w).
   - Under the default average, "the covergroup type coverage depends on the instances only, not its coverpoints or crosses" (§19.11.3).
2. **Merged bins need the largest `at_least`.** A bin counts as covered only when its summed count reaches the largest `at_least` of all accumulated instances (§19.11.1, last paragraph). The model already implements this (`coverage-model.ts:1102`); add it as an expert corner case and as an instances-mode preset.
3. **Type options are per type.** "Different instances of a covergroup cannot assign different values to type options" (§19.7.1). This is why `merge_instances` is a choice for the whole type.
4. **Illegal-bin errors are simulator errors, not UVM reports.** The LRM issues a run-time error (§19.5.6, §19.6.3), so a regression gated only on `UVM_ERROR : 0` can pass with illegal-bin hits. Gate on tool errors too, or mirror the condition in a checker that calls `` `uvm_error ``. Message format and exit status are tool-dependent. Teach this next to L14-3B-02's "`illegal_bins` is not a checker".
5. **Merging across code revisions.** A seed does not reproduce its stimulus after the code or constraints change (I-SV-2B misconception 4; that card's must-cover "why adding one `randomize()` call can change later values"). Databases merged across a steering change mix stimulus that may no longer occur. This is methodology with a tool-dependent merge policy; put it under "Expert: Closure at regression scale".
6. **Aggregated `(covered, total)` at the coverpoint level.** This is L14-3B-V04. Add it to quiz A3 and to card i-sv-3b-9, next to the covergroup-level caveat.
7. **Code-coverage types and their sources.**
   - **Standard:** statement, toggle, FSM (states and transitions) and assertion coverage (§40.2.1 b, §40.2.2).
   - **Tool-defined:** branch and condition coverage.
   - **Sign-off role** (methodology): read both families; an unhit line is either a missing plan row or dead code.
8. **Illegal bins take precedence.** An illegal value errors even when another bin also contains it (§19.5.6). An illegal cross product errors even when it is also ignored or inside another cross bin (§19.6.3). This is an expert corner case, and the reason ALU-5 belongs in `illegal_bins`. Cite §19.6.2 and §19.6.3 for cross exclusions; §19.6.1 covers only the select syntax.
9. **Stay within the I-SV-3A boundary.** I-SV-3A already teaches the goal and weight table, `weight = 0` for feed-only coverpoints, and procedural `cg_pkt::type_option.merge_instances = 1;` (coverage-options.mdx:39-44, 84; index.mdx:187). 3B should link these rather than re-teach them.
10. **Optional LRM footnote; tool behaviour unverified.** §19.11.1 divides automatically created bins by MIN(auto_bin_max, 2^M), but §19.5.3 sets N to the enum's cardinality. For `op_t` (7 named values, M = 3) the formula would give a denominator of 8. The lesson and lab assume 7. Mention this, if at all, only as a labelled expert footnote.
