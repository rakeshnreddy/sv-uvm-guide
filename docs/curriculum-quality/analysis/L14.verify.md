**Practitioner and expert items not in the depth ladder:**
1. **Which weight applies where.** L14-3B-10 covers only the covergroup level. The full set, as the expert table "weight by level" (Table 19-1, Table 19-3, §19.7.1, §19.11.3):
   - `option.weight` on a covergroup is the instance's weight in the type average (§19.11.3) and in "the overall instance coverage of the simulation" (Table 19-1).
   - `option.weight` on a coverpoint or cross weights the item within its instance, and within the item's type number under the default average.
   - `type_option.weight` on a covergroup weights the type in "the overall cumulative (or type) coverage of the saved database" (Table 19-3).
   - `type_option.weight` on a coverpoint or cross is used in the merged type number. §19.7.1's example is ((merge of a) × 3 + (merge of b) × 5) / (3 + 5).
   - Under the default weighted average, "the covergroup type coverage depends on the instances only, not its coverpoints or crosses" (§19.11.3).
2. **Merged bins need the maximum `at_least`.** Under `merge_instances = 1`, a bin counts as covered only when its summed count reaches the largest `at_least` of all instances (§19.11.1, last paragraph). Add it as an expert corner case and as an instances-mode preset; the model already implements it at `coverage-model.ts:1102`.
3. **Type options are per type.** "Different instances of a covergroup cannot assign different values to type options" (§19.7.1). This explains why `merge_instances` is a type-wide choice.
4. **`illegal_bins` errors are tool errors, not UVM reports.**
   - **Hazard:** a regression that passes on `UVM_ERROR : 0` can pass with illegal-bin hits. Gate on tool errors too, or mirror the condition in a checker that calls `` `uvm_error ``.
   - **Tool-dependent:** the message format and error limits.
   - **Unverified:** that the report server counts only UVM messages; `uvm_report_server.svh` was not re-read in this session.

   Teach this with L14-3B-02's "`illegal_bins` is not a checker".
5. **Merging across code revisions.** Random stability (§18.14) does not keep a seed's stimulus when constraints change; this is also I-SV-2B's misconception 4. Databases merged across a steering change mix stimulus that may no longer occur. This is methodology with a tool-dependent policy; put it under "Expert: Closure at regression scale".
6. **Aggregated `(covered, total)` at coverpoint level.** This is L14-3B-V04. Add it to quiz A3 and to card i-sv-3b-9 next to the covergroup-level caveat.
7. **Optional LRM footnote; tool behaviour unverified.**
   - §19.11.1 divides automatically created bins by MIN(auto_bin_max, 2^M).
   - For an enum with fewer named values than 2^M (`op_t`: 7 of 8), that disagrees with §19.5.3, which sets N to the cardinality of the enumeration.
   - The lesson and lab assume 7 bins, as tools are believed to do. Mention it only as an expert footnote, labelled.
8. **3A boundary.** I-SV-3A already teaches the `goal`/`weight` table, `weight = 0` for feed-only coverpoints and procedural `cg_t::type_option.merge_instances = 1` (coverage-options.mdx:39-44, 84; index.mdx:187). 3B should link these rather than re-teach them.
