1. **`## Quick Take`**
   - **What it is:** AHB (AHB-Lite and AHB5, IHI0033B.b) is a pipelined bus. Every transfer has an address phase and a data phase, and the next transfer's address phase overlaps the current data phase (§3.1).
   - **Why it matters:** every AHB monitor, checker and driver in B-AHB-2 and B-AHB-3 depends on knowing which edge completes each phase.
   - **The Analogy:** a waiter takes the next table's order (address) while the kitchen plates the current dish (data). If the kitchen is slow (HREADY low), the waiter stands at the next table holding that order. *Where it breaks:* the waiter may drop the held order only in the cases §3.6 lists (IDLE, BUSY, after an ERROR first cycle). And on a multi-layer interconnect, a slow kitchen blocks only its own path.
   - **You will be able to:** see Objectives.
   - **Before you start:** see Objectives.

  - **Vacuity and coverage of a checker.** `cover property (HRESP && !HREADY)` proves the ERROR checks were exercised (IEEE 1800-2023 §16.14.8 "Nonvacuous evaluations", §16.14.3 cover).
  - **`$past`, `disable iff` and the first edge after reset.** `$past` returns the value from a "strictly prior time step", or the default sampled value if there is none (§16.9.3). `disable iff` is not sampled (§16.12). Default disable resolution (§16.15).
  - **AHB5 exclusive transfers as checks.** HEXOKAY "must only be asserted in the same cycle as HREADY" and "must not be asserted in the same cycle as HRESP" (§8.3.1). An exclusive transfer is a single data transfer, SINGLE or INCR, with no BUSY, and aligned (§8.4).
  - **Locked sequences in real systems.**
    - Locked IDLEs at the start, middle or end of a sequence are permitted but not recommended.
    - All transfers in a locked sequence go to the same slave region. That requirement did not exist in Issue A, so legacy components must be verified for it.
    - An MPMC must implement HMASTLOCK.

    All from §3.3. Add a checker for "same slave region within a lock".
  - **Incomplete bursts.** A multi-layer interconnect may terminate a burst, and slaves "must be designed to work correctly if the burst is not completed" (§3.5.2). A slave prefetch or burst counter that assumes completion is a bug. A checker must not demand completion.
  - **Integration bugs.**
    - A multiplexor select that is not retimed to the data phase (§2.4 Note) routes the wrong slave's HREADY, HRESP or HRDATA.
    - HSELx can be high while HREADY is low and the selection can change before the transfer completes (§4.2).
  - **What "stable" means.** SVA `$stable` compares values at edges, which matches §7.1.1. Glitch-free between edges is the AHB5 Stable_Between_Clock property, which `$stable` cannot check.
  - **Latency budgets.** Worst-case wait = the predetermined maximum wait states (§5.1.2 Note) plus the longest locked sequence. Show how to measure it in a UVM environment (link B-AHB-3's starvation detector).
  - **Interview angles**, attempt-first.

1. **`## Quick Take`**
   - **What it is:** the AHB failures that reach silicon or waste debug time, and the checks that catch them.
   - **Why it matters:** a check that is too weak passes a broken slave (one-cycle ERROR). A check that is too strict flags behaviour the spec requires (cancel after ERROR, BUSY→SEQ) and ends up disabled.
   - **The Analogy:** tuning a smoke detector. Too sensitive and people pull the battery; too dull and it sleeps through the fire. *Where it breaks:* protocol rules are not tunable; only integration budgets (wait states, lock length) are.
   - **Objectives** and **Before you start:** see Objectives.

### Objectives

**You will be able to:**
1. Diagnose from a waveform a slave stuck with HREADYOUT low, write data acted on at the wrong edge, and an illegal control change during a wait state, telling it apart from the changes §3.6.1 and §3.6.2 allow.
2. Write an assertion set for the two-cycle ERROR response that also catches a single-cycle ERROR, and explain why a one-directional check passes vacuously (IHI0033B.b §5.1.3; IEEE 1800-2023 §16.14.8).
3. Classify each check as a protocol rule [Protocol §x] or an integration policy (wait-state budget, lock length), and report the two differently.
4. Write a per-beat 1KB check that applies only to incrementing bursts and an alignment check for every transfer, both of which accept legal WRAP bursts (§3.5, §4.2).
5. Diagnose reset faults (HTRANS not IDLE, HREADYOUT low during reset, §7.1.2) and keep grant-after-reset rules as policy.

**Before you start:** [B-AHB-1](/curriculum/T3_Advanced/B-AHB-1_AHB_Design_Timing_Mechanics/index) (phases, waits, BUSY, bursts, ERROR timing), [I-SV-4A](/curriculum/T2_Intermediate/I-SV-4A_SVA_Fundamentals/index) (implication, `$past`, `$stable`, `disable iff`).
