## Completeness and depth gaps the analyst missed

**Spot check of the analyst's tables.**
- The items marked missing really are missing. A grep of all five module files finds:
  - no `extern` method, no `struct` and no `const` class property;
  - no `vif` or virtual interface;
  - `protected` only in prose.
- The items marked covered are covered, with one exception. "index: handle assignment, 8 Debugging = yes" is too generous: no log or tool output appears anywhere. Mark it partial, and give Make It Work's break-it step a log line.

**Gaps:**
1. **Handles as subroutine arguments (V01).** Practitioner layer; add it to objective 1's predict items.
2. **Handle equality versus value comparison (V02).** This links the index's null test to `compare()` on copying-and-cloning, and to M3.
3. **Implicit constructors and UVM constructor requirements (V03).** Constructors, practitioner and transfer.
4. **`extern` rules beyond the qualifiers** (the -03 adjustment): same scope as the class and after it, an exact match, the default-argument rule, `C::T` return types, one body per method (§8.24).
5. **Nested classes** (§8.23: "Like modules, classes are scopes and can nest"; `class_item` includes `class_declaration`). One expert line in "Class anatomy": declare a nested class or typedef and reach it as `Outer::Inner`.
6. **Deep copy of linked structures.** An expert item for copying-and-cloning.
   - A `copy()` that follows back-pointers (a parent handle, a linked list) recurses or duplicates shared nodes. Copy back-pointers as references.
   - uvm-core's copier tracks recursion per object pair (`m_recur_states` in `copy_object`).
   - It refuses with `UVM_COPY_POLICY` when the recursion policy is `UVM_REFERENCE` (`uvm_copier.svh`).
7. **Inheritance versus composition.** A methodology trade-off for the index's expert layer.
   - Today's Push Further mentions composition; the analyst's replacement list drops it.
   - Contrast a transaction that *has* a header (as on copying-and-cloning) with one that *extends* a header class, and say when each is cleaner.
8. **A picture for "Classes, structs and modules"** (new section). None is proposed. A comparison table is the right form:
   - static versus dynamic storage;
   - value versus handle copy;
   - inheritance and polymorphism;
   - ports, procedures and instances, which only a module has.
   - Sources: §8.28 (a)–(c) and Syntax 8-1.
