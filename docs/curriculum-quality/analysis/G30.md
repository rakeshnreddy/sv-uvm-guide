# G30 Navigation and information architecture: analysis

**Analyst:** G30 (navigation and information architecture). **Date:** 2026-10-03. **Branch:** `curriculum-quality-program`.

**Scope:** the order source, the lesson page, the layout and navbar, the curriculum overview, every internal link in all 105 lesson MDX files, learner routes, practice linkage, search and shortcuts, and redirects and URLs.

**Method.** I read the code and content statically and ran read-only Python and Node scripts from the session scratchpad. Nothing in the repo was changed except this report. The link audit:

- parses every MDX file outside fenced code;
- resolves every internal link with a re-implementation of `normalizeSlug`, the `src/app` route tree and the lab registry;
- resolves relative links from every URL form a lesson can be reached at;
- walks the hand-written Next chain hop by hop.

Redirect sources were compiled with the matcher that ships with the installed Next.js 14.2.35 (`node_modules/next/dist/shared/lib/router/utils/path-match.js` and `next/dist/compiled/path-to-regexp`). The trailing-slash behaviour was read from `node_modules/next/dist/lib/load-custom-routes.js`. The protocol-order claims were checked in the Arm IHI0022E and IHI0033B.b text extracts listed in the brief.

`docs/curriculum-quality/curriculum-spine.md` does not exist yet, so the order proposed here is input for the spine. Lesson codes such as `F2D/ipc` stand for `content/curriculum/<tier>/<module folder>/<lesson>.mdx`.

## Summary

- **The order is alphabetical, not pedagogical.** `scripts/generate-curriculum-data.ts` sorts folder and file names. The `order:` frontmatter in 16 files is validated but never read. This causes five prerequisite violations:
  - In the AMBA track, bridges, ACE/CHI and the interview clinic come before any AXI lesson.
  - In I-UVM-3B, the capstone lab is lesson 2 of 9, while the handshake it builds on is lesson 7. The module page says "Each one builds on the previous".
  - In A-UVM-4B, the built-in sequences that need backdoor access come before frontdoor and backdoor access is taught.
  - In I-SV-3B, the closure loop comes before V-plan linking.
  - In T4, E-AI-1 comes first, but it names E-PYUVM-1 (lesson #101) as a prerequisite.
- **The in-content Next links do not work as a path.**
  - Only 17 of 105 lessons have a Next link that matches the generated order and is robust.
  - 13 more match but are relative links. 25 point somewhere else, 48 are missing and 2 are text only.
  - 58 of the 62 relative links in 24 lessons resolve one level too high when the page is reached at its two-segment module URL.
  - That URL is where the breadcrumb's module crumb, 82 content links, redirect destinations and Next.js's own trailing-slash 308 send learners. Following the hand-written Next links from F1A gives a 404 on the second hop. Most T1 and T2-SV chains end in a 404 within one to four hops; the rest stop at a lesson that has no Next link.
- **13 of 27 legacy redirects can never fire.** Next 14 compiles `(/:slug*)` as the literal regex group `(\/:slug*)$`. The unit test re-implements matching and hides this.
- **Orientation is incomplete.**
  - Breadcrumbs and "Lesson k of N" exist.
  - Only 1 of 105 lessons has "Before you start".
  - Headings get no ids, so there are no in-page anchors and no table of contents. Experts cannot jump to Push Further.
  - Breadcrumb icons show authoring status as if it were learner progress.
  - There is no custom 404 page; every dead end lands on a bare page with no navigation.
- **Learner routes are broken or missing.**
  - `/curriculum` offers no start-here route and no expert jump-in.
  - The placement quiz result links to three lessons that do not exist, and to a dashboard that returns 404 with the default flags.
  - "Diagram View" is a placeholder.
  - "Recommended For You" lists recently visited modules.
  - Progress is never recorded: `completeLesson` has no caller.
- **Practice linkage is one-way.**
  - All 21 available labs are linked from their owning lesson.
  - Only 2 lessons link an exercise and 1 links a practice visualizer.
  - None of the 18 exercise, visualizer and tool pages links back to a lesson.
  - For 17 of 21 labs, "Back to module" goes to `/curriculum`.
  - The 6 interview banks have no route.
- **Search does not exist.** The navbar input has no handler and the mobile search button does nothing. The Alt shortcuts do not fire on macOS.

## generated-order

**How it works today.** The generator builds one list from `readdirSync(...).sort()`: tiers T1 to T4, then modules, then lesson files, with `index` first. `findPrevNextTopics` walks that flat list of 105 lessons (69 modules) across tier boundaries. Frontmatter `order` is ignored. Nothing checks the order against prerequisites.

## lesson-page-navigation

**How it works today.** `src/app/(learning)/curriculum/[...slug]/page.tsx` renders:

- a breadcrumb bar (`Breadcrumbs.tsx`), with a "Jump to" menu at sm and wider;
- a header showing "Tier • Module", the H1, the description, "Lesson k of N", read time and word count;
- the MDX body;
- flashcards (when a deck exists) and "Teach it back";
- prev/next cards;
- an aside with "Module quick facts" and "Lessons in this module". This list uses `aria-current="page"` and a visible "Current" label, which is good.

Sub-lessons are reached in four ways:

- the aside list (right column on desktop; below the whole lesson on phones);
- "Jump to" (hidden below sm);
- prev/next;
- hand-written track lists in module indexes. These use relative links, which break (see G30-LINK-01).

The sidebar and the overview cards do not list sub-lessons.

## Proposed information architecture

### Order principles

1. **Order is data, not file names.** The machine-readable spine (`curriculum.manifest.json`) is the single source of truth for tier, module and sub-lesson order, prerequisites, track (core or elective), level, milestones and practice items. Folders and URLs stay as they are.
2. **A tier is an audience and competency stage; a module is one competency; a sub-lesson is one concept step.** Module prerequisites form a graph whose edges must point backward in the linear order. The generator rejects forward edges.
3. **The core path is linear; electives sit beside it.** Electives (UPF, DPI if the spine chooses, Python, AI, RISC-V, emulation) appear in the outline and on the overview, but the core Next skips them, and an elective's Next returns to the path.
4. **The sub-lesson order is the module index's numbered "Track contents" list.** That list is generated from the manifest, or validated against it.
5. **Spiral, but explicit.** When a concept appears early and returns in depth (F2D/ipc then I-SV-5; E-SOC-1/pss then E-PSS-1), the early page labels itself an introduction and links forward. The later page says what it adds.
6. **Boundaries are visible.** Next cards say when a module ends or a tier begins, and the overview names each tier's audience.
