## Completeness and depth gaps the analyst missed

1. **State variables** (see V03). This is a core term of §18.3/§18.5.8. It is a prerequisite for `local::`, for configuration knobs and for the heatmap's debug toggle.
2. **`inside` traps** (§11.4.13):
   - a reversed range is empty;
   - `$` is a bound for the type's lowest or highest value;
   - all members of the set are equally likely (§18.5.3, first paragraph).
   Add "a reversed range" as a cause in the debugging table.
3. **Weighted modes with run-time weights.** A weight is any integral expression, read as unsigned (§18.5.3). §18.10 lists changing weights as a way to modify constraints at run time. So a test can tune modes through non-rand knobs, for example `op dist { READ := rd_w, WRITE := wr_w }`, without a new class. Add this to the pattern table, and note that a total weight of 0 excludes the value.
4. **External-block rules beyond L11-2A-01's fix:**
   - it is an error for a constraint block with the prototype's name to appear in the same class (§18.5.1);
   - `static` goes on both the prototype and the body, or on neither (§18.5.10);
   - the 1800-2023 `initial`, `extends` and `final` specifiers must also match on both (§18.5.2). I-SV-2B teaches them; mention them in the expert note.
5. **`randc` and object copies (expert layer).** In 1800-2023, a shallow copy (`p2 = new p1;`) copies the internal randomization state: the RNG state, the `constraint_mode` and `rand_mode` status, and the `randc` cyclic state (§8.12). Under the same constraints, `p1` and `p2` then return the same next values. This sharpens misconception 4: "a new object starts a new cycle" holds for `new()`, not for a shallow copy. Whether UVM `copy()` or `clone()` carries this state is unverified; check uvm-core before teaching it.
6. **Signed `rand int`, a junior mistake.** `rand int len; constraint c { len < 64; }` allows negative values. The spine leaves signedness debugging to I-SV-2B, which the junior path skips (V02). Add it to "Mistakes to avoid", with a link.
7. **Two must-cover rows are over-scored.**
   - "Obj 1: `rand` fields" (L11.md:56) says yes, but its own note says `rand` is never defined: partial.
   - "Assessment: misconception 3" (L11.md:76) says yes, but no quiz or IQP distractor states the misconception; only explanations do (constraint-blocks.mdx:93; heatmap feedback): partial. The analyst's Q3 fixes it.
8. **Objective verb.** Objective 4 (L11.md:542) starts with "Use", which is not in spine §5.4's verb list. Prefer "Write … and predict …".
9. **Objective 2 and coupled `dist`.** Keep the frequency predictions to `dist` variables whose weights no other constraint conflicts with. §18.5.3 leaves the conflicting case to the tool.
