  1. **Precedence corner cases.**
     - A `set(null, …)` made during build has precedence 1000, because `uvm_root` has depth 0 (`uvm_config_db_implementation.svh` set; `uvm_component.svh` `get_depth`).
     - Sets made before phasing starts (in `tb_top`, or in the test's constructor) have precedence 1000. `run_test` creates `uvm_test_top` before it forks `m_run_phases` (`uvm_root.svh`).
     - A second set from the same context with the same inst_name and field reuses and overwrites one resource (pool key `{inst_name,"__M_UVM__",field}`).
     - Siblings build in instance-name order (`m_children[string]`, `uvm_topdown_phase.svh` traverse), so one sibling's build-time `set()` can arrive after the other's `get()`.
  2. **Type matching.**
     - Two `uvm_config_db#(T)` specializations are the same class only when their type parameters are matching types (IEEE 1800-2023 §8.25 with §6.22.1). Typedef aliases match. `int unsigned` matches `bit [31:0]` (rule e). `int` does not match `bit [31:0]` (signedness).
     - A modport is part of a virtual interface type (§25.9).
     - Fix pattern: set and get the base `virtual bus_if`, then assign it to a modport-typed member. §25.9 allows assigning a virtual interface with no modport to one with a modport.
  3. **Command-line configuration (G.2.8).** `+uvm_set_config_int`/`_string` are applied in `uvm_root::build_phase` as `uvm_config_int::set(uvm_root,…)`.
     - They are typed `uvm_bitstream_t` (`logic signed [4095:0]` by default) and have precedence 1000.
     - They reach `uvm_field_*` fields, which automatic configuration converts, and `uvm_agent`'s `is_active`, which `uvm_resource_enum_read` reads as enum, string or integral.
     - They do **not** reach a hand-written `uvm_config_db#(int)::get`.
     - Value prefixes `'h 'b 'o 'd 0x 0b` (`uvm_root.svh` `m_process_config`).
  4. **Automatic configuration and its cost.** §13.1.4.1.1, §13.1.5.1, §13.1.5.2.
     - `apply_config_settings` looks up every registered field by name with no type check. The source comments that the scope-only mode is "VERY expensive".
     - Overriding `use_automatic_config()` to return 0 turns it off.
  5. **Run-time reconfiguration.**
     - `wait_modified` (C.4.2.2.4, annotation) wakes only for a later `set()` of the same `T` whose scope glob matches the waiter's path; then `get()` again.
     - The alternative is to change fields of a shared config-object handle: no database traffic, but every holder sees the change at once.
  6. **Tool and build dependence.**
     - `+` globs and `/regex/` scopes need the DPI regex library. With `UVM_NO_DPI`/`UVM_REGEX_NO_DPI`, the SV fallback matches only `*` and `?` (`src/dpi/uvm_regex.svh`).
     - `+UVM_CONFIG_DB_TRACE`, `+UVM_RESOURCE_DB_TRACE`, `check_config_usage()` and `print_config()` are uvm-core features, not IEEE 1800.2.
     - The database implementation can be replaced by a factory override of `uvm_config_db_implementation_t#(T)` (uvm-core, `@uvm-contrib`).
  7. **Methodology trade-offs.**
     - The config DB versus handing config-object handles down (env assigns `agt.cfg = env_cfg.agt_cfg[i]`).
     - Objects versus scalars.
     - Per-agent scopes versus `uvm_test_top.*`.
     - `uvm_resource_db` for data not keyed by the component tree.
  8. **Staff-level interview questions** (attempt-first; listed under `### Expert: Interview angles` in the target outline).

**`## Quick Take`**
- **What it is.** `uvm_config_db#(T)` is a typed store that understands the component hierarchy (Annex C.4.2), built on the resource pool. `set()` publishes a value for a scope; `get()` retrieves it.
- **Why it matters.** It enables late binding. The vif crosses from the module world to the class world, and one test reconfigures an environment without editing it.
- **Analogy.** Keep DNS, with "Where it breaks" (L22-2C-22).
- **You will be able to** (see Objectives) and **Before you start** (I-UVM-2A, F4B, I-UVM-1C).

**`## Build Your Mental Model`**
1. `### Why components need configuration`
   - Static module instances versus dynamic class objects.
   - What breaks without it: hard-coded hierarchical paths, one env copy per test, a null-vif fatal (§25.9).
2. `### set() and get(): the four arguments`
   - Signatures; scope = `{cntxt.get_full_name(), ".", inst_name}`; `null` means `uvm_root`; an empty `inst_name` means the context's own path.
   - The typedefs `uvm_config_int`/`_string`/`_object`/`_wrapper` (C.4.2.3, annotation).
   - Minimal example: `tb_top` sets the vif; the driver's `build_phase` gets it with `uvm_fatal`.
   - Picture: ArchitectureDiagram 1.
3. `### What a get() can see`
   - The three filters (keep line 12 and the SVG 116-129).
   - Glob table: `*`, `?`, `+`, `/regex/`; "`agt0.*` excludes `agt0`".
   - Exact field string.
   - Exact type: modport is part of the type (§25.9); `int` vs `bit [31:0]`. Fix: get the base type and assign it to a modport member.
   - Pitfalls listed with why.
4. `### Who wins when several set() calls match`
   - Keep 93-97 verbatim (verified). Add "sets made before phasing (tb_top, the test's constructor) also have 1000".
   - Add a one-line contrast with the factory (I-UVM-1B: first registered matching instance override).
   - Keep `<ConfigDbExplorer />` with its prediction line, then add the debrief paragraph.

     - `get()` calls `item_done()` at once, so `finish_item()` returns before the item is driven (`uvm_sequencer.svh` `get`).
     - `put(rsp)` = `put_response`.
     - `try_next_item` waits `m_wait_for_sequences_count` (default 1) `wait_for_sequences()` calls and reports `TRY_NEXT_BLOCKED` if a sequence consumes time between `start_item` and `finish_item`.
     - A concurrent `get_next_item` gives a `SQRSNDREQGNI` fatal, because the request FIFO holds one item (`uvm_sequencer_param_base.svh` `send_request`).

     - `send_request` assigns `transaction_id` and `sequence_id`; `set_id_info` copies them (§14.1.2.4).

     - Depth 8 (§14.2.7.6/7, annotation); silent drop unless `set_response_queue_error_report_enabled(1)` (§14.2.7.5, annotation).
     - `get_response(rsp, transaction_id)`.
     - The `rsp_port` → `rsp_export` path (`uvm_driver.svh`, `uvm_sequencer_param_base.svh`).
     - Response handlers are taught in I-UVM-3B.
  4. **Objections, starting phase and default sequences.**
     - Calling `set_starting_phase` after `get_starting_phase` has locked the value gives the error `UVM/SEQ/SP/SET`.
