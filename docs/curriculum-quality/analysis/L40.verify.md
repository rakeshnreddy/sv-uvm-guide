## Completeness and depth gaps the analyst missed

**F2**
1. **Scope guard (card).** The card limits F2 to "concept level", M8 awareness, with "detailed transaction flows beyond awareness" out of scope. The analyst's plan puts full encoding tables, ten expert items and an eight-preset visualizer on one page. The core path must stay at concept level: states and rules, one read and one write trace, CHI basics, global invariants. The encodings, snoop-filter legal-state columns and forward-progress rules go under Push Further. Otherwise the core path fails the "reads cleanly on its own" rule.
2. **Expert, missing: overlapping stores.**
   - When two masters race to store to a shared line, the interconnect orders them. The loser's copy is removed by the winner's snoop, so its own CleanUnique completes with no copy. That allows only a full-line store; otherwise it must re-issue as ReadUnique.
   - This is the classic CleanUnique race, and it has a debug angle: a partial store after a lost race corrupts data.
   - Sources: IHI0022E C1.3.4 "Overlapping store operations"; the C4.6.1 text after Table C4-13 ("If the cache line was in the Invalid state … the store must be a full cache line size").
3. **Expert, missing: exclusive sequences.** A snooped line that is part of an exclusive sequence must remain valid in the snooped master (C5.3, text before Table C5-8). CleanUnique can be used for exclusives (C4.6.1 → C9). Link B-AXI-4.
4. **Practitioner, missing: CleanShared and the CMO group.** Snoopee end states are Clean or Invalid (Table C5-3). A dirty copy must be supplied, and the snoopee may keep a clean copy (C1.4.4). The page's CMO rows are wrong (V03, V04), and the analyst's outline lists CMOs only as a group name.
5. **Visual P1 split (see V01)**, plus a picture for "MakeInvalid discards dirty data". That is a good debug mutant for the requested visualizer; the analyst's preset 7 is close but is framed around CleanUnique.
6. **Analyst's completeness table, C2:** "Pitfalls: partial". The page's only pitfall (:88) is correct, but the core pitfall "Clean ≠ equal to memory" is entirely absent, as F2-06 notes. I agree with "partial". No change.
