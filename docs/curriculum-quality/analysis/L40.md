- domain and snoop signalling: AxDOMAIN encodings (Table C3-2), CRRESP[4:0] (Table C3-22), RRESP[3:2] (Table C3-15), RACK/WACK (C3.3, C1.3.3);

- the CHI basics, correctly: layers (§1.1.2), the nodes including the MN (§1.6), four channels (§13.4), L-Credits (§14.2.1), Request Retry (§2.11), CHI states (§4.1), DCT (§1.7, §5.1.3);
- a checker architecture that compiles: passive monitors on every port feeding one line model with a golden memory, checked procedurally;
- a debug playbook (ownership timeline per line, then channels).

**Expert: absent.** Add these `### Expert:` items:
1. Snoop channel dependencies: the master must not wait for CRREADY/CDREADY before CRVALID/CDVALID, and the interconnect must not wait for ACREADY before ACVALID (C3.9).
2. RACK/WACK, and the guarantee that a master sees no snoop to a line between its response and its acknowledge (C3.3, C6.2, C6.2.1).
3. A snoop that crosses a WriteBack/WriteClean: answer with PassDirty=0 and IsShared=1, or delay the response (C5.2.3, Table C5-6).
4. Forward progress: a snooped master must complete snoops before its own AR transactions can be guaranteed to complete (C5.2.5); the interconnect's WriteBack and Evict must progress without pending snoops (C6.6.1). CHI equivalents: an RN-F answers snoops without a protocol-layer dependency on its outstanding requests (§4.11.1); the per-channel forward-progress rules (§13.4.1).
5. Permission to update memory, and why the interconnect orders the write-back before it grants a Unique response (C6.5.3).
6. Snoop filters: legal end states differ with and without a snoop filter (C4.2, C4.3, the "With Snoop Filter" column of Tables C4-9 and C4-13). CHI back-invalidation snoops: the interconnect may itself send SnpUnique or SnpCleanInvalid, for example when a snoop-filter or interconnect-cache entry is evicted (§4.4).
7. CHI Request Retry corner cases: PCrdGrant may arrive before RetryAck; the retry waits for both and uses AllowRetry=0 with the granted PCrdType (§2.11, §2.11.3). Snoops are never retried; the snoop flit has no AllowRetry field (§13.9.3).
8. Partial and empty lines: UCE and UDP (§4.1, §4.1.1, §4.1.2). ACE line size is a design parameter (C3.1.5); CHI's line is 64 bytes (§1.5.1).
9. Methodology trade-offs, labelled as methodology:
   - a commercial coherency VIP vs an in-house line model;
   - formal on a 2-cache, 1-line abstraction for the state invariants;
   - memory-consistency litmus tests belong to the processor architecture, not to the interconnect protocol;
   - scale: snoop-filter capacity and back-invalidation traffic.
10. Staff-level interview questions, attempt-first (see the Assessment plan).

**`## Quick Take`**
- **What it is:** ACE (AMBA 4, IHI0022E Part C) adds hardware cache coherency to AXI. It adds snoop channels into every cached master and coherency signalling on the existing channels. CHI (AMBA 5, IHI0050) does the same job as a layered, packet-based protocol for large networks.
- **Why it matters:** verification moves from "is each interface legal?" to "do all caches together still obey the coherency rules?", which no per-interface checker can see.
- **The Analogy:** a shared design document. Anyone may keep a read-only printout (Shared). One person at a time holds the editable copy (Unique). Whoever edited last owes the file server an upload (Dirty). Snoops are the "hand back or shred your copy" requests.
  - *Where it breaks:* the unit is a cache line, 64 bytes in CHI, not a document. Copies are invalidated, not updated. A "clean" printout can still differ from the server when someone else owes the upload (SC next to SD).
- **You will be able to:** the four objectives (Objectives).
- `<BeforeYouStart />`.

**`## Build Your Mental Model`**

### Why AXI alone is not enough
- **The fixed scenario:** CPU0 holds an old copy (SC), CPU1 has written the line (UD), and a DMA reads memory and gets the stale value.
- **Definition:** hardware coherency means every component observes the writes to one memory location in the same order, maintained per cache line (IHI0050E.b §1.5, §1.5.1).
- **The fix:** the DMA is an ACE-Lite master issuing ReadOnce, the interconnect snoops CPU1, and CPU1's data comes back (C1.4.2, C11.1).
- **Picture P1** (Visual coverage), introduced with a prediction: "What does the DMA read with plain AXI4? With ACE-Lite ReadOnce?" Debrief after the picture.
- **Pitfalls:**
  - ordering is not coherence;
  - software cache maintenance is the alternative and costs software effort.

### What ACE adds to an AXI interface
- **On AR and AW:** ARSNOOP/AWSNOOP, ARDOMAIN/AWDOMAIN, ARBAR/AWBAR, and AWUNIQUE only for WriteEvict (Table C1-3).
- **On R:** RRESP[3:2] PassDirty and IsShared (Table C3-15). Nothing new on W or B (C1.3.1 note).
- **New channels:** AC (input to the cached master), CR (one response per snoop) and the optional CD (C1.3.2, Table C1-4).
- **Acknowledges:** RACK and WACK (Table C1-5, C1.3.3).
- **Domains:** encodings 0b00–0b11 (C1.6.1, Table C3-2).
- **ACE-Lite** (C11.1): the AR/AW additions only.
- **Picture P2.**

### The five cache states
- **Characteristics:** Valid/Invalid, Unique/Shared, Clean/Dirty, with the spec definitions (C1.2.3).
- **States:** the five states and their permissions (Table C1-2).
- **Rules:** the six cache state rules (C1.2.3).

### How coherency changes verification
- **Two kinds of check:** per-interface checks (protocol checkers in VIP) vs global checks across every port.
- **Global invariants:**
  - a Unique holder has no other valid copy;
  - at most one Dirty holder;
  - read data equals the golden value: the dirty owner's data if there is one, else memory;
  - the snoop filter never misses a holder;
  - liveness: every snoop is answered and credits are returned.
- **Checker architecture:** a passive monitor on every coherent port feeds one line model (states plus golden memory). Run procedural checks after every update. Concurrent SVA is not used inside the scoreboard (§16.6, §16.14).
- **Picture P9.**
- **Misconception callout:** "coherency can be checked per interface".

**`## Make It Work`**
- **Worked example:** a compile-ready (`// compile`) SystemVerilog package `coh_pkg` and a `tb_top`.
  - `coh_pkg` holds `typedef enum {ACE_I, ACE_UC, ACE_UD, ACE_SC, ACE_SD} ace_state_e;` and a class `coh_line_model`. The class keeps one line's per-cache states and a golden value, and has `apply()` and `check_line()`.
  - `tb_top` replays the 5-step kata (Hands-on plan), then one mutant: the interconnect answers a ReadShared with a ReadOnce snoop, leaving CPU1 UD and CPU0 SC.
  - Expected output (label it "illustrative; no simulator run"): one `CHK` line per step, ending in a violation line for the mutant.
  - The check must count Unique holders and Dirty holders and test "a Unique holder is the only valid copy". This compiles by inspection:

```systemverilog
// snippet: the global check, called after every observed state change
function automatic bit check_line(input ace_state_e st[], output string why);
  int unsigned valid_n = 0, unique_n = 0, dirty_n = 0;
  foreach (st[n]) begin
    if (st[n] != ACE_I)                valid_n++;
    if (st[n] inside {ACE_UC, ACE_UD}) unique_n++;
    if (st[n] inside {ACE_UD, ACE_SD}) dirty_n++;
  end
  why = "";
  if (unique_n > 1 || (unique_n == 1 && valid_n > 1))
    why = "a Unique copy coexists with another copy (IHI0022E C1.2.3)";
  else if (dirty_n > 1)
    why = "more than one Dirty owner (IHI0022E C1.2.3)";
  return (why == "");
endfunction
```

- **UVM placement** (`// snippet`): a `coh_checker extends uvm_scoreboard` with `` `uvm_analysis_imp_decl(_port0) `` and `` `uvm_analysis_imp_decl(_port1) `` (verified in uvm-core 2020.3.1). It has one `write_port0`/`write_port1` per monitored port, each calling the model's `apply()` and then `check_line()`, with `` `uvm_error("COH", why) `` on failure.
- **How-to, numbered:**
  1. Monitor every coherent port, including ACE-Lite.
  2. Publish requests, snoops, CRRESP and RRESP[3:2] with time stamps.
  3. Update the line model.
  4. Check the invariants.
  5. Check read data against the golden value.
  6. Cover start state × snoop type × CRRESP/RRESP.

### Hands-on plan

**Kata "Two caches, one line"** (objective 2; add it to Practice & Reinforce with a fill-in table and a worked solution in `<details>`). Every step is verified against IHI0022E. Start with A = I, B = I and memory = M0.

1. **A loads.** ReadShared; there are no other copies, so the interconnect reads memory. RRESP IsShared=0, PassDirty=0 → A = UC (Table C4-9).
2. **A stores.** UC → UD silently (Table C1-2). A holds M1; memory still holds M0.
3. **B loads.** ReadShared; the interconnect snoops A with ReadShared (Table C5-1). A answers DataTransfer=1, PassDirty=0, IsShared=1 and goes UD → SD (Table C5-8). B gets M1 with RRESP IsShared=1, PassDirty=0, becomes SC (Table C4-9) and sends RACK (C3.3). Memory = M0, golden = M1.
4. **B stores 4 bytes.** B issues CleanUnique; the interconnect snoops A with CleanInvalid (Table C5-1).
   - A must return the dirty line and invalidate its copy (C1.4.4; Table C5-6): CRRESP DataTransfer=1, PassDirty=1 (C3.7), A = I.
   - The interconnect writes M1 to memory before granting B a Unique response (C1.3.4, C6.5.3).
   - B gets one response-only R transfer with RRESP=00 (C3.2) and goes SC → UC (Table C4-13). The store makes it UD with M2, then RACK.
5. **B evicts.** WriteBack on AW/W, then B response and WACK. B = I (C4.8.4), and memory = M2.

**Debug variant (mutant).** At step 3 the interconnect sends a ReadOnce snoop instead. A may keep UD (C1.4.2, ReadOnce), yet B is told IsShared=1 and holds SC. The learner must find the violated rule: a Unique line may be held in only one cache (C1.2.3).
