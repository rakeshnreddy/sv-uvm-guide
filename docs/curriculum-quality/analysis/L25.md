### Depth ladder

- **Core: partially present.** The five-policy table, the order rule and the flag rule are present, along with the visualizer and the "check the return value" rule. **Add:**
  - objectives and prerequisites;
  - a definition of "field automation" before :19 uses it;

  - `convert2string` and `sprint`;
  - a short pack/unpack round trip with the symmetry rule.
- **Practitioner: partial.** It has a manual `do_print`/`do_compare` and the threshold/show_max knobs. **Add:**
  - a complete worked example with an "Expected output" block;
  - hand-written `do_copy` (with `super.do_copy` and `$cast`, §5.3.8.2) and `do_pack`/`do_unpack`;
  - the severity and verbosity knobs;
  - table, tree and line printers with their knobs;
  - a debugging table (symptom → cause → fix);
  - a criteria table for choosing macros or hooks.
- **Expert: missing** (two snippets, no `### Expert:` items). Add:
  1. **Where the threshold lives.** The threshold gate is in the macros (`m_uvm_compare_threshold_begin`, `uvm_comparer_defines.svh`). §16.3.6 says compare "may return as quickly as possible". `compare_field*()` and `compare_object()` themselves never stop.
     - Portability caveat: uvm-core 2020.3.1's `uvm_comparer::flush()` keeps the threshold.
     - IEEE 1800.2 §16.3.6 says `get_threshold` returns 1 after `flush`, and `compare()` flushes the comparer at depth 0 (§5.3.9.1 a).
     - So a literally conforming library would undo `set_threshold(0)` on every `compare()`. Label this tool-dependent. The robust pattern is a comparer subclass whose `flush()` calls `super.flush()` and then re-applies the threshold.
  2. **Tolerance and filtering.** Keep the `tolerant_comparer` (:155-180). Add the 1800.2 alternative, **policy extensions** (§16.1.2.3, `set_extension`/`get_extension`): `do_compare` reads a configuration object from the comparer. Extensions are not cleared by `flush`.
  3. **Packer streams are implementation-defined** (§16.5.3.1–§16.5.3.2).
     - uvm-core keeps the pack/unpack iterators in the first 64 bits (`flush` sets `m_pack_iter = 64`; `get_packed_*` writes them into `m_bits[63:0]`).
     - `pack_object` writes `4'hF` (or `0` for a null) before every object.
     - Fields are stored LSB first, and the UVM 1.2 `big_endian`/`use_metadata` knobs are gone.
     - `uvm_compat_pkg::uvm_compat_packer` reproduces 1.2 streams (kit README, `compat/README.md`).
     - For a C model, pass a packed struct or the fields through DPI, or build bytes with streaming operators (IEEE 1800-2023 §11.4.14).
  4. **Field-macro semantics changed in 1800.2.**
     - Mantis 7187: a `UVM_NO*` flag without positive flags is a no-op, with warning `UVM/FIELDS/NO_FLAG`.
     - uvm-core's compile define `UVM_LEGACY_FIELD_MACRO_SEMANTICS` restores the 1.2 behaviour (uvm-core impl.).
     - The kit README shows how to silence the warning with `set_report_severity_id_action(UVM_WARNING, "UVM/FIELDS/NO_FLAG", UVM_NO_ACTION)`.
  5. **Recursion and type checks.**
     - Recursion policies: `UVM_DEEP`, `UVM_SHALLOW`, `UVM_REFERENCE` (§16.3.4.1).
     - `set_check_type` (§16.3.4.2): it compares `get_object_type()`, so a derived object compared with a base object miscompares on type.
     - Loop detection: the comparer warns with ID `UVM/COPIER/LOOP`.
     - In uvm-core, the copy macro copies **into** an existing destination sub-object and creates one only when the handle is null (`uvm_copy_object`, `uvm_copier_defines.svh`).
  6. **`do_execute_op` as one hook for all operations** (§5.3.13, §5.7.2.2–§5.7.2.8).
     - Use `op.get_op_type()`, `get_policy()` and `get_rhs()`.
     - `op.disable_user_hook()` suppresses the `do_*` call.
     - `` `uvm_object_utils_begin `` already defines `do_execute_op`, so override it only in a class that registers with `` `uvm_object_utils ``.
  7. **Performance at scale.**
     - LRM B.2.2 NOTE: field macros "may not be as run-time efficient nor as flexible" as direct `do_*` code.
     - Avoid `sprint()` in hot paths (prefer `convert2string`), and print MISCMP sparingly.
     - Any speed figure must be measured and labelled tool-dependent.
  8. **Interview angles (attempt-first).**
     - "Two fields differ but `get_result()` is 1. Why?"
     - "Your scoreboard passes with mismatching data. Where do you look?"
     - "Deep vs shallow copy of an item that holds a config handle."
     - "Why might the same item pack to different bytes under UVM 1.2 and 1800.2?"

## Cross-cutting observations

1. **Spine I-UVM-4 card and Appendix A comparer note.** The card says the comparer "counts all miscompares while limiting printing". That is incomplete:
   - every field-macro and `` `uvm_compare_* `` comparison is skipped once `get_result() >= get_threshold()`, and the default threshold is 1 (`m_uvm_compare_threshold_begin`; §16.3.6);
   - with the default comparer, field macros therefore stop after the first miscompare;
   - direct `compare_field*()` calls in `do_compare` always count.

   There is also a portability trap:
   - uvm-core 2020.3.1's `flush()` keeps the threshold;
   - the standard says `get_threshold` returns 1 after `flush` (§16.3.6), and `compare()` flushes at depth 0 (§5.3.9.1 a).

   Any lesson that teaches `set_threshold(0)` (I-UVM-4, A-UVM-6) should label it as uvm-core behaviour or show the `flush()` override.
2. **uvm-core `@uvm-ieee` tags are not always the clause numbers.** `set_recording_enabled`/`get_recording_enabled` are tagged "13.1.6.13/14" in `uvm_component.svh`. The standard has §13.1.7.13/§13.1.7.14; §13.1.6 is the objection interface with three subclauses.
   - Analysts and authors who take numbers from the tags (some reports say they had no 1800.2 text) should cross-check against `scratchpad/spine/uvm_lrm.txt`.
   - Spine Appendix A lists 13.1 subclauses but not 13.1.7. Add "13.1.7 recording interface (13.1.7.1 accept_tr … 13.1.7.14 get_recording_enabled)".
3. **Spine I-UVM-5 card.** Add §10.4.2 (`uvm_barrier_pool`) to objective 3, and the threshold-0 trap of pool-created barriers (§10.3.2.1).
4. **Spine I-UVM-6 card kata.** "record monitor transactions with a parent-sequence link" cannot work as worded: a monitor builds new transaction objects with no parent sequence. Parent links come from:
