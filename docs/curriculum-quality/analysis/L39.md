**Expert: absent.** Add these `### Expert:` items. Every source below was verified unless it is marked tool-dependent.

1. **Undefined-length INCR: the bridge cannot know the length.**
   - HBURST=INCR signals no length (IHI0033B.b Table 3-3).
   - It may end after BUSY with NONSEQ or IDLE (§3.5.1).
   - Bridge options:
     - single-transfer AXI bursts;
     - buffer writes until the burst ends, the buffer fills, the 1KB region ends or 256 transfers are reached;
     - speculative read bursts, only when the transfer is Modifiable or Normal: IHI0022E A4.3.1 ("a read transaction can fetch more data than required") and IHI0033B.b §3.8.5 ("Reads can fetch more data than required");
     - never for Device memory (§3.8.4: "Reads must not be prefetched or performed speculatively").
   - The read-sensitive FIFO warning applies (A3.4.1 note).
2. **Early termination on AHB, none on AXI.**
   - An AHB master may cancel after ERROR (§3.5.2). A multi-layer interconnect may also terminate a burst, and "slaves must be designed to work correctly if the burst is not completed" (§3.5.2).
   - AXI has no early termination (A3.4.1). A bridge that already issued AWLEN or ARLEN must:
     - pad the missing W transfers with all strobes low ("the master can disable further writing by deasserting all the write strobes … must complete the remaining transfers");
     - drain the unwanted R transfers.
3. **What a bridge may change: Modifiable, Device and Normal transactions.**
   - AXI side (A4.3.1, Table A4-2): Non-modifiable must not be split or merged, except INCR > 16. Downsizing below AxSIZE forces a modification. No modification may cross 4KB or split a single-copy-atomicity access.
   - AHB5 side: HPROT[3] Modifiable (§3.7). For Device (§3.8.4), a burst may be broken into smaller bursts if the NONSEQ+SEQ count is preserved, HSIZE must not change, and writes must not be merged.
   - When a bridge may merge AHB SINGLEs into one AXI burst.
4. **Posted writes, ordering and latency.**
   - Read-after-write hazard (A5.3.4).
   - Early write response only when bufferable: IHI0033B.b §3.8 Table 3-5 (with HPROT[4:3] both deasserted, that is Device memory, HPROT[2] deasserted means "the write response must be given from the final destination"; §3.8.4 Device-nE); IHI0022E A4.4.1 and A4.6.
   - The same choice in the AXI→AHB direction: an early BRESP only when AWCACHE marks the write bufferable. Device Non-bufferable and Normal Non-cacheable Non-bufferable writes need the response from the final destination (A4.4.1); bufferable types do not (A4.6).
   - A non-posted write holds HREADYOUT low for the whole AXI round trip, beyond the "no more than 16 wait states" recommendation (IHI0033B.b §5.1.2 note). On a single-layer AHB that stalls every master.
5. **Strobes, alignment and narrow transfers.**
   - IHI0033B.b has no write-strobe signal (Table 2-2 lists none). AHB transfers must be aligned (§3.5).
   - So an AXI→AHB bridge sends a sparse WSTRB as several narrower aligned transfers and skips all-zero-strobe transfers (IHI0022E A3.4.1, A3.4.3).
   - Narrow AHB transfers become narrow AXI transfers with lanes taken from each transfer's address (A3.4.3).
6. **Exclusive and locked accesses across a bridge.**
   - AXI→AHB-Lite: the bridge cannot support exclusives, so it returns OKAY, which means not supported (A7.2.5). An exclusive write sent anyway "always updates the memory location" (A7.2.5).
   - AXI→AHB5:
     - HEXCL only for a single-transfer exclusive (§8.4);
     - AXI exclusive bursts may be up to 16 transfers and 128 bytes (A7.2.4);
     - a Non-modifiable exclusive may change AxSIZE and AxLEN if the byte count is unchanged (A4.3.1);
     - HMASTER must keep threads distinct (§8.3).
   - AHB HMASTLOCK (§3.3) has no AXI4 equivalent (A7.3).
7. **Reset domain crossing in a bridge.**
   - AXI: masters drive ARVALID, AWVALID and WVALID low in reset; the first VALID only after a rising edge with ARESETn high (A3.1.2).
   - AHB: masters drive IDLE, and slaves drive HREADYOUT high in reset; reset is asserted asynchronously and deasserted synchronously (§7.1.2).
   - The policy when one side resets with transfers in flight: the bridge cannot abort an AXI burst, so it drains it, and it keeps the live side protocol-legal.
   - RDC tools are tool-dependent.
8. **Formal verification of a bridge that converges** (replaces :237–290):
   - assume-guarantee: assume the input-side protocol, assert the output-side protocol (§16.14.1, §16.14.2);
   - a fairness assumption for every AXI handshake and response;
   - liveness with `s_eventually` (§16.12.13);
   - a symbolic tracked address and byte for data integrity;
   - over-constraint and vacuity checks with `cover` (§16.14.3);
   - bounded proofs and convergence (tool-dependent).
   - Link E-INT-1 for methodology.
9. **Performance and sizing.**
   - Non-posted round-trip latency.
   - Posting buffer depth.
   - AXI→AHB outstanding queue depth (Bug 5).
   - Read prefetch for Normal memory.
   - Measure with the B-AXI-6 latency method. These are engineering trade-offs; no clause.

#### `## Quick Take`
- **`<QuickTake>` box.** It may stay. Rewrite the bullets:
  - a bridge converts between an AHB pipeline (separate HWDATA/HRDATA buses) and AXI's five channels;
  - keep :16–18 verbatim;
  - add one response bullet: one BRESP per AXI write, an RRESP per read beat, and a two-cycle AHB ERROR;
  - replace :19 with "formal proves the split and handshake rules; simulation with a reference model checks the data".
- **What it is:** an AHB↔AXI bridge is a protocol converter. It is a slave on one bus and a master on the other. It re-shapes bursts to each protocol's limits and translates responses.
- **Why it matters:** bridges sit on most SoC paths between a CPU or DMA and peripherals. Their bugs show up as data corruption, lost errors or hangs, which look like master or slave bugs.
- **The Analogy:** a freight broker between a railway and a trucking firm.
  - The railway (AHB) checks each wagon as it passes, while the next wagon's paperwork is already being read.
  - The trucking firm (AXI) sends the order, the cargo and the receipt separately.
  - The broker repacks loads to each carrier's limits (256 transfers; 1KB) and decides when to sign the receipt (posted or non-posted).
  - *Where it breaks:*
    - AHB has separate read and write tracks;
    - an AXI load can never be cancelled once announced;
    - the broker can delay a wagon only while it unloads (HREADYOUT in the data phase), never at the gate (the address phase).
- **You will be able to:** see Objectives.
