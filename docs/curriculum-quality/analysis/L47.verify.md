## Notes for the implementation author

1. **Bus model (E-SOC-1 and `soc-vip-reuse`).** Use one coherent topology everywhere: the CPU drives the SPI block's APB port, the reused APB-side agent goes passive there, and any SPI-pin agent is an off-chip model. Reconcile the names across:
   - the visual (`"env.spi_agent"`);
   - the lab (`"env.spi_agt"`);
   - the analyst's worked example (`"env.spi_env.spi_agent"`).
   If the worked example adds the `spi_env` level, say in the VIPReuseVisualizer debrief that the visual omits that level.
2. **Liveness TimingDiagram (Visual coverage, liveness row).** The proposal shows the AW handshake at edge 2 and BVALID never rising. In AXI the slave "must wait for both WVALID and WREADY to be asserted before asserting BVALID" and also for WLAST (IHI0022E §A3.3.1). Draw the W handshake (WVALID, WREADY, WLAST) as well. Without it, a bounded failure at edge 10 means a missing W beat (a bench bug), not a lost response. With the antecedent at edge 2, `##[1:8]` covers edges 3 to 10, so "fails at edge 10" is correct.
3. **RAL prediction diagram.** The auto-predict edge comes from RAL `read()` and `write()` through the map (§18.2.5.2: "Before a uvm_reg::write … or uvm_reg::read operation … returns"), not only from `write()`. Quote both §18.2.5.2 sentences ("default value of on shall be 1" and "When on is False (the default)") only with the uvm-core resolution (argument default 1, map mode 0).
4. **Quiz wording.**
   - E-SOC-1 Q7 (`wait_trigger`): say that no further `BOOT_DONE` trigger occurs. Otherwise the distractor "returns at the next firmware write" can be true (§10.1.1.2.4: "does not return until the next trigger").
   - E-PYUVM-1 Q2 (duplicate AW): state when AWVALID rises relative to edges 1–3, so the count is uniquely determined.
5. **E-SOC-1 Q4 key verified.** `seq.start(null_sequencer)` passes `start()` (`start()` only guards its uses of `m_sequencer` with `if (m_sequencer != null)`, `uvm_sequence_base.svh:341`, `:357`, `:450`, `:476`) and fails at the first `start_item` with `uvm_report_fatal("SEQ", "neither the item's sequencer nor dedicated sequencer has been supplied to start item …")` (`:1062`).
