**Expert: absent.** Add these eight `### Expert:` items:
1. **Synchronous-drive corner cases.**
   - Last value wins in one Re-NBA region (§14.16.2). When the drives come from two processes, "last" is decided by process order (§4.7), which makes it a TB race.
   - Re-NBA glitch when the scheduler loop iterates (§14.16.2, the `bit a` example).
   - A synchronous drive and a procedural NBA to one variable in the same time step land in arbitrary order (§14.16.2).
   - Illegal forms: `<= #4 r`, concatenation targets, and `assign`/`force` to a clockvar (§14.16); a continuous assignment to a variable that is an output clockvar (§14.16.2).
   - A net target gets an implicit (strong1, strong0) driver initialized to `'z` (§14.16).
   - Reading an `inout` clockvar returns the last sample, not the value just driven (§14.16.1).
   - Two clocking blocks (posedge and negedge) driving one variable model DDR (§14.16.2).
2. **Cycle-delay corner cases.**
   - `##0` waits only if the clocking event has not yet occurred in this time step (§14.11).
   - `##1` issued off-edge waits only a fraction of a cycle (§14.11).
   - `##` is illegal as an intra-assignment delay (§14.11).
   - Default-clocking scope covers nested modules, interfaces and checkers but not instantiated ones; one default per scope (§14.12).
   - Counting from an off-edge drive, per the LRM example: `#1 cb.v <= ##2 expr3;` matures in cycle 3 (§14.16.2).
3. **Input-sampling corner cases.**
   - Explicit-`#0` inputs are not resampled when Observed runs again without a new clocking event (§14.13).
   - A program that reads a clockvar without waiting on the clocking event does not race when the clocking event is triggered from a module; the NOTE warns only about clocking events triggered from a program (§14.13 NOTE).
   - Module code waiting on the same clock does race (§14.4 NOTE).
   - `@(cb.sig)` uses sampled values (§14.15).
   - Clockvars used in concurrent assertions are sampled only in the clocking block (§16.18).
   - `1step` equals the global time precision (§3.14.3).
4. **Multiple clocks and TB-internal races.**
   - Per §24.4, sampling through a clocking block covers only that block's clock. With several clocks, the order in which simultaneous clocks are processed is still a race source.
   - Blocks on one clock share a synchronization event (§14.6), so a driver and a monitor woken by it run in arbitrary order (§4.7). Hand data between them through queues or mailboxes with a defined order.
5. **Skews as timing models.**
   - Input skew is a setup window: compare it with DUT output delays and the visualizer's "+9 ns path" case.
   - Output skew is clock-to-output and hold margin in gate-level simulation.
   - Label all tool behaviour as tool-dependent and quote no vendor figures.
6. **Methodology trade-offs** (label as practice):
   - clocking blocks vs `<=` drives vs opposite-edge drives;
   - one clocking block per role;
   - modport-typed virtual interfaces (§25.5.5, §25.9.2);
   - passive agents need only `mon_cb`;
   - a program vs a module TB top: `run_test()` called from a module puts UVM threads in the active region set (§24.3.1). uvm-core `uvm_root.svh` calls `$finish` when `finish_on_completion` is set.
7. **Scale.** Every input clockvar is sampled at every clocking event (§14.13), so keep monitor clocking blocks narrow. The cost is tool-dependent; give no numbers.
8. **Interview angles.** Attempt-first, using `InterviewQuestionPlayground`. Questions are in the Target outline.

#### `## Quick Take`
- **What it is.** Define two terms in the standard's words:
  - **Clocking block:** a declaration that names a clocking event and the signals sampled and driven relative to it (§14.2, §14.3).
  - **Program block:** a TB scope whose code runs in the reactive region set (§24.3.1).
- **Why it matters.**
  - TB and DUT wake on the same edge in arbitrary order (§4.7).
  - A clocking block reads pre-edge samples and drives in Re-NBA whatever that order is.
  - This lesson is the M1 gate.
- **The Analogy.** Use photo and delivery, matching the visual and the recap. Where it breaks:
  - the `#1step` photo is the value at the end of the previous time slot, not a fixed time earlier (§4.4.2.1, §14.3);
  - a `#0` delivery stays in the same time slot (Re-NBA);
  - only the last parcel addressed to one signal in a Re-NBA region is delivered (§14.16.2).
- **You will be able to:** the five objectives below.
- **Before you start:** linked prerequisites (Objectives section).

#### `## Make It Work`

**`### Worked example: a race-free pipeline bench (M1)`.** I checked this code by inspection and traced it by hand.

```systemverilog
// compile
`timescale 1ns/1ns

// DUT: two-stage pipeline, out_data = in_data + 1, two cycles of latency.
module pipe2 (
  input  logic       clk,
  input  logic       rst_n,
  input  logic       in_vld,
  input  logic [7:0] in_data,
  output logic       out_vld,
  output logic [7:0] out_data
);
  logic       vld_q;
  logic [7:0] data_q;

  always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
      vld_q    <= 1'b0;
      data_q   <= '0;
      out_vld  <= 1'b0;
      out_data <= '0;
    end else begin
      vld_q    <= in_vld;
      data_q   <= in_data + 8'd1;
      out_vld  <= vld_q;
      out_data <= data_q;
    end
  end
endmodule

interface pipe_if (input logic clk);
  logic       rst_n = 1'b0;  // set before any process starts (§6.8); driven directly, never via a cb
  logic       in_vld, out_vld;
  logic [7:0] in_data, out_data;

  // Driver view: sample at #1step, drive at #0 (the defaults, written out).
  default clocking cb @(posedge clk);
    default input #1step output #0;
    output in_vld, in_data;
    input  out_vld, out_data;
  endclocking

  // Monitor view: inputs only, so a monitor cannot drive the DUT.
  clocking mon_cb @(posedge clk);
    input in_vld, in_data, out_vld, out_data;
  endclocking
endinterface

module tb_top;
  logic clk = 1'b0;
  always #5 clk = ~clk;          // rising edges at 5, 15, 25, ... ns

  pipe_if bus (.clk(clk));
  pipe2   dut (.clk(clk), .rst_n(bus.rst_n),
               .in_vld(bus.in_vld), .in_data(bus.in_data),
               .out_vld(bus.out_vld), .out_data(bus.out_data));

  logic [7:0] expected [$];      // expected outputs, oldest first
  int pass_count;
  int fail_count;

  // Call right after @(bus.cb): the drive matures in Re-NBA of this edge (§14.16).
  task automatic send(input logic [7:0] data);
    bus.cb.in_vld  <= 1'b1;
    bus.cb.in_data <= data;
    expected.push_back(data + 8'd1);
    @(bus.cb);                   // the DUT captures the item at this edge
  endtask

  // Reads only #1step samples, after the clocking-block event (§14.10, §14.13).
  task automatic monitor();
    logic [7:0] exp;
    forever begin
      @(bus.mon_cb);             // never @(posedge clk) before reading mon_cb
      if (bus.mon_cb.out_vld === 1'b1) begin
        if (expected.size() == 0) begin
          $error("unexpected output %h", bus.mon_cb.out_data);
          fail_count++;
        end else begin
          exp = expected.pop_front();
          if (bus.mon_cb.out_data === exp) begin
            pass_count++;
            $display("[%0d ns] PASS data=%h", $time, exp);
          end else begin
            fail_count++;
            $error("[%0d ns] FAIL got=%h exp=%h", $time, bus.mon_cb.out_data, exp);
          end
        end
      end
    end
  endtask

  initial begin
    pass_count = 0;
    fail_count = 0;
    bus.cb.in_vld <= 1'b0;       // issued before any clocking event: matures at 5 ns (§14.16)
    #12 bus.rst_n = 1'b1;        // asynchronous release between edges, outside the cb
    fork
      monitor();
    join_none
    @(bus.cb);                   // the 15 ns edge
    send(8'h10);
    send(8'h20);
    send(8'h30);
    bus.cb.in_vld <= 1'b0;
    repeat (4) @(bus.cb);        // drain the pipeline
    fail_count += expected.size();
    $display("PASS=%0d FAIL=%0d", pass_count, fail_count);
    $finish;
  end

  initial begin                  // watchdog: a hung bench must fail loudly
    #1000 $fatal(1, "TIMEOUT");
  end
endmodule
```

**Racy variant**, for Kata 1, not for copying:

```systemverilog
// snippet
@(posedge clk);
bus.in_vld = 1'b1;
bus.in_data = data;
```

- Its capture edge depends on process order (§4.7).
- The in-order queue above hides a one-cycle shift. The kata therefore adds a cycle-accurate check: predict `out` exactly two edges after the `mon_cb` sample of `in_vld/in_data`.

**`### Convert a racy bench in six steps`.**
1. Add a driver clocking block (the outputs the TB drives, plus the inputs it reacts to) and a monitor clocking block (inputs only) to the interface.
2. Make the driver wait on `@(bus.cb)`, and turn every `bus.sig = v` into `bus.cb.sig <= v`.
3. Make the monitor wait on `@(bus.mon_cb)` and read only `bus.mon_cb.sig`.
4. Replace `@(posedge clk)` waits in the TB with `@(bus.cb)`. Use `##N` only where a default clocking is in scope.
5. Leave asynchronous signals (reset) as direct drives between edges.
6. Rerun, compare the logs, and run the mutant.

**"Run it" box.**
- Compile `pipe2`, `pipe_if` and `tb_top` in one compilation with your simulator's SystemVerilog mode, and run `tb_top`.
- Open-source support for clocking blocks is unverified. Name a tool only after running it there (spine §5.2(15)).
