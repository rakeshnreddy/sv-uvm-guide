  1. **What the base classes really add.** In uvm-core 2020.3.1:
     - `uvm_test` (§13.2.1), `uvm_env` (§13.3.1), `uvm_monitor` (§13.5.1) and `uvm_scoreboard` (§13.6.1) are `virtual class`es with only a constructor and `` `uvm_component_abstract_utils ``;

     - `uvm_driver` (§13.7.1) adds `seq_item_port`, `rsp_port`, `req`/`rsp` and a `DRVCONNECT` warning;
     - `uvm_subscriber` (§13.9.1) adds `analysis_export`, an imp whose instance name is `"analysis_imp"`, and pure virtual `write(T t)` (§13.9.3.2).

     Sources: `src/comps/*.svh`.
  2. **How `is_active` is really read.**
     - `uvm_agent::build_phase` queries the resource pool and reads `is_active` with `` `uvm_resource_enum_read ``. That accepts the enum, a string (`"UVM_PASSIVE"`) or any integral type (`uvm_agent.svh` build_phase; `uvm_resource_defines.svh:112-145`).
     - So `uvm_config_db#(int)::set(..., "is_active", 0)`, `+uvm_set_config_int=uvm_test_top.env.out_agt,is_active,0` and `+uvm_set_config_string=...,is_active,UVM_PASSIVE` all work (`uvm_root.svh` `m_process_config`, which calls `uvm_config_int::set(m_uvm_top, ...)`). The Annex G clause is unverified by L21; the spine cites G.2.8.
     - The setting must be made before the agent's `build_phase` runs.
     - `get_is_active()` called from the constructor returns the default.
     - Overriding `get_is_active()` to return `cfg.is_active` is the A-UVM-7 pattern.
     - Precedence between a test-level and an env-level set belongs to I-UVM-2C; link it.
  3. **Monitor sampling skew.** IEEE 1800-2023 §14.13: with an explicit `#0` input skew, "the value sampled corresponds to the signal value in the Observed region", which is after NBA updates. `#1step` samples the Preponed (pre-edge) value (§14.4). Mixing pre-edge and post-edge state misclassifies transfers. The capstone reference monitor is a worked case (LAB-C1 below). Link F4C's `ClockingBlockSkewVisualizer`.
  4. **Where checks and coverage live** (methodology, labelled as practice):
     - protocol (cycle) checks in the monitor behind `checks_enable`, or as SVA bound to the interface (link I-SV-4C);
     - data checks in the env-level scoreboard;
     - coverage in subscribers, or in the monitor behind `coverage_enable`;
     - trade-offs for passive reuse at SoC.
  5. **Reactive, passive and scale.**
     - Responder (slave) agents are active but driven by observed requests.
     - At SoC the same agents are reused all-passive.
     - Component count costs wall-clock time, not simulated time; label any figures as tool-dependent.
  6. **Interview questions** (staff level, with model answers):
     - "A block agent reused at SoC drives X onto a bus the CPU owns. Name three root causes." (missing `super.build_phase`; wrong set path; a set made after build)
     - "Why is the scoreboard not in the agent?"
     - "Why must a monitor create a new item per transfer?"
     - "Design one agent class that can be active, passive or reactive."
     - "How do you check in regression that topology matches intent?" (an `end_of_elaboration_phase` check of `get_is_active()` against the config, or the `print_topology` listing)

     - Default sizes:

       | Endpoint | min | max |
       |---|---|---|
       | TLM port | 1 | 1 |
       | `uvm_seq_item_pull_port` | 0 | 1 |
       | analysis port | 0 | unbounded |
       | analysis export | 1 | unbounded |
       | imp | 1 | 1 |

       Sources: `uvm_tlm_imps.svh:192-220`, `uvm_analysis_port.svh:71-73,149-151`.

Consequence: analysis connections that reach two levels down (as in the capstone lab) are silently accepted. Discuss the encapsulation trade-off.
  3. **`write()` corner cases.**
     - IEEE 1800-2023 §13.4 a)/b): no time control and no task calls. But §13.4.4 allows `fork…join_none` in a function, and that block may contain delays and task calls. This is legal but spawns an unmanaged process per item; prefer a FIFO.
     - Subscriber order is the lexical order of imp full names in uvm-core (`m_imp_list[string]`; `uvm_port_base.svh:272, 914-930`; `uvm_analysis_port.svh:82-95`), not `connect()` order. Do not rely on it.
     - A subscriber that modifies `t` changes what later subscribers see.
     - `write()` costs wall-clock time, not simulated time.
  4. **FIFO sizing, memory and end-of-test.**
     - `uvm_tlm_fifo` defaults to `size = 1`; 0 means unbounded (`uvm_tlm_fifos.svh:81-85`, §12.2.8.2).
     - `uvm_tlm_analysis_fifo` is always unbounded (`super.new(name, parent, 0)`) and its `write()` is `void'(try_put(t))` (`uvm_tlm_fifos.svh:280-287`, §12.2.8.3). A consumer that stops means unbounded growth, so check `used()`/`is_empty()` in `check_phase`.
     - `flush()` with blocked gets errors (`uvm_tlm_fifos.svh:220-230`).
