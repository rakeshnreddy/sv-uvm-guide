**Expert: absent.** No `## Push Further` on any of the four pages. Add these `### Expert:` items, all checked against the sources named:
1. **The standard vs uvm-core on backdoor prediction.**
   - IEEE 1800.2-2020 §18.4.4.11 (poke): "This method is affected by the auto-prediction configuration value (see 18.2.5.2)". §18.4.4.12 (peek) is the same.
   - uvm-core 2020.3.1 `uvm_reg::poke` and `peek` call `do_predict(rw, UVM_PREDICT_WRITE/READ)` unconditionally (`uvm_reg.svh`).
   - Teach the implementation, quote the wording, and tell portable code to check `get_mirrored_value()` rather than assume either.
2. **Backdoor `read()`/`write()`/`mirror()` are policy-aware; `peek()`/`poke()` are raw.**
   - `do_write` with `UVM_BACKDOOR` does a backdoor read, then `XpredictX` per field, then deposits the result. It deposits only if the map rights are RW or WO; otherwise it returns `UVM_NOT_OK`. Then it calls `do_predict`. LRM §18.4.4.9: "read-only bits in the register will remain unchanged".
   - `do_read` with `UVM_BACKDOOR` clears the RC/WRC/WSRC/W1SRC/W0SRC fields and sets the RS-family fields in the DUT by a backdoor write. LRM §18.4.4.10: "clear-on-read bits in the registers are set to 0".
   - It then predicts with door `UVM_BACKDOOR`. `uvm_reg_field::do_predict` applies the RC clear only for `UVM_FRONTDOOR`/`UVM_PREDICT`, so in uvm-core 2020.3.1 the mirror keeps the pre-clear value while the DUT holds 0. This is by source inspection; confirm on a simulator before stating it as fact.
   - `mirror(…, UVM_BACKDOOR)` takes the same path, so it clears RC interrupt bits.
   - Use `peek()` for non-destructive inspection.
3. **Explicit prediction is asynchronous to the RAL call.**
   - The mirror moves when the monitor publishes. If that happens after the driver's `item_done()`, `write()` returns before the prediction.
   - uvm-core's `uvm_reg_single_access_seq` waits `#1` after its frontdoor write before the backdoor `mirror(UVM_CHECK)` (`uvm_reg_access_seq.svh`). The source gives no reason; letting a monitor-fed predictor catch up is the likely one.
   - Effects: an `update()` or `mirror(UVM_CHECK)` issued straight after a `write()` may see the old mirror.
   - Remedies: publish at transfer completion, or synchronise on `predictor.reg_ap`.
4. **Inside `uvm_reg_predictor::write()`** (`uvm_reg_predictor.svh`; §19.3.2.1-§19.3.3.3). The steps:
   1. `bus2reg()` (with `byte_en` defaulted to all ones).
   2. `map.get_reg_by_offset(addr, kind == UVM_READ)`. This needs a locked model; otherwise it raises `uvm_error` "Cannot get register by offset: Block … is not locked.". It uses only the **root** map's address table, which `Xinit_address_mapX` fills in `top_map`.
   3. Registers wider than the bus are collected over beats. Errors here are `REG_PREDICT_COLLISION`, and `PENDING REG ITEMS` in `check_phase`.
   4. Check-on-read.
   5. `pre_predict()` (§19.3.3.2: "change the value or redirect the target register").
   6. Coverage sampling.
   7. `do_predict()` with door `UVM_PREDICT`, logging `REG_PREDICT` at UVM_HIGH.
   8. `reg_ap.write()` (§19.3.2.2).

   Other behaviour: an unmapped address is logged as `REG_PREDICT_NOT_FOR_ME` **only at UVM_FULL**; memories are never predicted; `UVM_NOT_OK` gives the `PREDICT_NOK` warning; `flush()` exists for reset but is uvm-core only (`@uvm-contrib`, not 1800.2).
5. **Passive checking with check-on-read.**
   - `map.set_check_on_read(1)` (§18.2.5.3: "useful when the register model is used passively") makes the predictor compare every observed read with the mirror before predicting.
   - With it, the register model becomes a passive register checker for firmware-driven SoC tests. This needs an explicit predictor on every bus and correct volatile settings.
6. **Field-level access and byte enables** (`uvm_reg_field.svh` `is_indv_accessible`, `do_write`).
   - In uvm-core 2020.3.1, `field.write()` is a field-only access only if all of these hold:
     - the access is frontdoor;
     - `individually_accessible = 1`;
     - the register has no user frontdoor;
     - `adapter.supports_byte_enable = 1` (§19.2.1.2.2);
     - the field is the only field within its bus-width word.
   - So on a typical 32-bit register with several fields on a 32-bit bus, `supports_byte_enable = 1` alone does not make field writes individual.
   - Otherwise uvm-core writes the whole register with a warning: "Target bus does not support byte enable…" or "…is not the only field within the entire bus width…". The other fields get:
     - their **mirrored** values (RW and similar);
     - 0 (W1C/W1S/W1T);
     - all ones (W0x);
     - a side-effect warning (WC/WS/WCRS/WSRC/WOC/WOS).
   - So a stale mirror corrupts the neighbouring fields. `UVM_REG_NO_INDIVIDUAL_FIELD_ACCESS` forces whole-register writes.
7. **Built-in sequences at scale, and their false passes** (`sequences/*.svh`; Annex E).
   - **Cost:** bit-bash makes 4 frontdoor accesses per bit per map (`repeat (2)` write then read). The access sequence makes 2 frontdoor and 2 backdoor accesses per register per map. The memory walk makes about 3 frontdoor accesses per word per map.
   - **Exclusion semantics:** `uvm_resource_db#(bit)::get_by_name(...) != null` tests whether the resource exists; its value is ignored.
   - **No DUT reset:** `reset_blk()` is empty, so the sequences reset the model, not the DUT.
   - **Idle DUT required:** source comment, "The DUT should be idle and not modify any register during this test."
   - **Missing backdoor:** `uvm_reg_access_seq` skips registers with no backdoor with only a `uvm_warning`. `uvm_reg_mem_hdl_paths_seq` (E.7) validates only registers that have paths. Promote that warning (report catcher, §6.6) or assert `has_hdl_path()` before you trust a pass.
   - **Selection:** `uvm_reg_mem_built_in_seq.tests` (E.8.2.2) is a `UVM_DO_*` mask.
8. **Aliased, indirect and FIFO registers.**
   - An RO and a WO register may share one address. The map adds `uvm_reg_read_only_cbs`/`uvm_reg_write_only_cbs`, and the predictor picks by direction. Any other overlap warns "maps to same address as register" (`uvm_reg_map.svh`).
   - The predictor redirects `uvm_reg_indirect_data` to its target (`ireg.get_indirect_reg()`).
   - `uvm_reg_fifo` models FIFO data registers.
   - A user frontdoor for index/data access leaves the target to auto-predict or to `predict()`: an explicit predictor sees only INDEX and DATA.
9. **HDL-path portability** (tool-dependent; label it).
   - `+define+UVM_HDL_NO_DPI` compiles the backdoor off. The message reads "uvm_hdl DPI routines are compiled off. Recompile without +define+UVM_HDL_NO_DPI" (`dpi/uvm_hdl.svh`).
   - Simulators need signal read/write visibility switches, which are vendor-specific: name them as such and verify them in the tool manual.
   - Unnamed generate blocks get the implicit names of IEEE 1800-2023 §27.6, so name generate blocks used in paths.
   - A deposit bypasses RTL write-strobe logic: a poked GO bit starts nothing.
10. **RAL coverage (awareness).**
    - `uvm_reg::include_coverage(scope, models)` is a static call (§18.4.7.1) made before the model is built.
    - The block API is `build_coverage`/`add_coverage`/`has_coverage`/`get_coverage`/`set_coverage` (§18.1.4).
    - The models are `UVM_CVR_REG_BITS`, `UVM_CVR_ADDR_MAP`, `UVM_CVR_FIELD_VALS` and `UVM_CVR_ALL` (`uvm_reg_model.svh`; type §17.2.2.9).
    - The base `sample()` is empty: generators emit the covergroups. The predictor's `XsampleX` path samples them.
11. **Reset and the mirror.** Link proposed A-UVM-9. On a mid-test DUT reset, call `ral.reset()` and `predictor.flush()` (the latter uvm-core only); otherwise the mirror keeps pre-reset values.
12. **Methodology trade-offs.**
    - Explicit plus check-on-read on every bus, versus auto-predict for RAL-only buses.
    - Backdoor setup with frontdoor checks, per regression stage.
    - Running bit-bash per IP, not per SoC.
    - Register scoreboard from `reg_ap`, versus scattered `mirror(UVM_CHECK)` calls.
13. **Interview angles (attempt-first),** staff level:
    - "Firmware, a DMA and the UVM test all program one register file over two buses; design the prediction and checking";
    - "Why does auto-predict plus a predictor break W1T but not W1C?";
    - "The access sequence passed on a block with no HDL paths. Why is that a red flag?";
    - "Verify a hardware-set W1C interrupt register without false mismatches";
    - "Model an index/data indirect register".
