**Missing items.**
1. **Restriction on process control (§9.7, expert).** "The methods kill(), await(), suspend(), and resume() shall be restricted to a process created by an initial procedure, always procedure, or fork block from one of those procedures." Add this to X2.
2. **`kill()` can race with normal completion (§9.7, expert).** "…due to nondeterminism (see 4.7), the processes may terminate normally while kill() is executing." After `kill()`, `status()` can therefore read FINISHED. Word the Make It Work checklist, P2 and `isv5-8` as "terminated". Say KILLED only for a process that was blocked, as worker 1 is.
3. **A circular wait can be latent (§4.7, expert).** Two `get()` calls with no delay between them usually run back to back. But §4.7 lets a simulator suspend a process between statements, so opposite acquisition orders can deadlock on a conforming simulator. Passing on every simulator tried proves nothing, so fix the order anyway. The course model cannot show this case, because it runs each process until it blocks.
4. **Mailbox messages must be singular (§15.4.3–§15.4.5; Annex G.4).** An unpacked struct, union or array cannot be a message; send a class handle or a packed struct. This belongs in "Typed and typeless mailboxes", and the page's own code breaks the rule (V02).
