**`## Quick Take`**
- **What it is:** UVM (IEEE 1800.2-2020) is a standard SystemVerilog base class library and methodology. This lesson maps the layered class bench you can already write onto UVM.
- **Why it matters:** each UVM mechanism removes one specific pain of a hand-built bench at scale. Without that map, UVM looks like ceremony.
- **The Analogy:** standard plumbing fittings and building codes. *Where it breaks:* UVM does not build the house (no checks, models or coverage of its own), and a garden shed does not need building codes.
- **You will be able to:** the five objectives below.
- **Before you start:** the linked prerequisites below. Say that the generated Prev page, I-SV-8 (UPF), is an elective and not required.

     - §13.1.2.1: the full name must be unique; leaf names use only A–Z, a–z, 0–9 and `_ - [ ] ( ) { }`; a duplicate child "shall" generate an error; a null parent attaches to the implicit top.
     - uvm-core 2020.3.1 (`uvm_component.svh` `new`):
       - `CLDEXT` is a `uvm_fatal`;
       - an empty name becomes `COMP_<n>`;
       - a component that is its own parent is a fatal `THISPARENT`;
       - `ILLCRT` is a fatal when the build phase state is `UVM_PHASE_DONE`;
       - the leaf-name characters are not checked;
       - `set_name` on a component reports the error `INVSTNM`.
     - §5.1 calls components "quasi-static".
     - Siblings are visited in instance-name order (`m_children[string]`, iterated by `first/next` in `uvm_topdown_phase.svh`), and §1.4.4 makes that order implementation-defined.
     - Candidate corner case, derived from source and **not** yet confirmed in a simulator: a component created with a `null` parent during build whose name sorts before `uvm_test_top` is not visited by that build traversal. Verify it before teaching it.
  2. **clone, create and the factory.**
     - `clone()` = `create(get_name())` then `copy(this)` (`uvm_object.svh:961–973`).
     - The macro's `create()` calls `new()`/`new(name)` (`uvm_object_defines.svh:525–531`), so clone never applies overrides.
     - A subclass without its own utils macro inherits its parent's `create()`, so its clone is the parent type and `$cast` fails.
     - If `create()` returns null, clone warns `CRFLD`.
     - On a component, `create()` reports `ILLCRT` "Use create_component instead" (D.2.1.1) and `clone()` reports `ILLCLN` and returns null.
     - Handle members are copied shallowly unless `do_copy` deep-copies them.
  3. **Hooks must use the policy APIs.**
     - §5.3.6 and §5.3.9: `do_print`/`do_compare` implementations "shall use the policy's APIs" (`printer.print_field_int` §16.2.3.9; `comparer.compare_field_int` §16.3.3.2). I-UVM-4 already does this.
     - uvm-core's default comparer reports miscompares as `UVM_INFO` `MISCMP` at `UVM_LOW` with `show_max = 1` (`uvm_comparer.svh:130–151`). A failing `compare()` is not a `UVM_ERROR`; the scoreboard must report it.
     - Field macros vs `do_*`: the B.2.2 NOTE on efficiency and flexibility, `do_execute_op` (§5.3.13), and mixing the two (link I-UVM-4).
  4. **Automatic configuration at scale.**
     - §13.1.5.1: `apply_config_settings` passes a `UVM_SET` field op to `do_execute_op` and, when the user hook is enabled, calls `set_local`.
     - §13.1.5.2: `use_automatic_config()` returns 1 by default; returning 0 makes you responsible for configuration.
