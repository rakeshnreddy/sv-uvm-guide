1. **Value-resolution corner cases (§19.5.7, §19.5):**
   - The effective type is self-determined, or the coverpoint's type when one is declared (`bit [7:0] d: coverpoint y[31:24];`).
   - Bin expressions are statically cast to that type, and enum values act as their base type.
   - There are three warning cases: a negative value for an unsigned type, a value that changes when assigned, and x/z bits.
   - A warned singleton is dropped, and a range is intersected with the representable values.
   - Use the LRM example: for `bit [2:0] p1`, `{1,[2:5],[6:10]}` becomes `{1,[2:5],[6:7]}` and `{-1,[1:10],15}` becomes `{[1:7]}`. For `bit signed [2:0] p2`, they become `{1,[2:3]}` and `{-1,[1:3]}`.
2. **4-state values in bins (§19.5.3, §19.5.4):**
   - Without `wildcard`, an x or z in a bin matches only with `===`.
   - With `wildcard`, x, z and ? match 0 or 1.
   - Automatic bins ignore samples that contain x or z.
   - `wildcard bins g[] = {4'b11??}` gives four bins.
3. **Transition semantics in depth (§19.5.2, §19.5.5, §19.5.6, §19.6.1):**
   - Set transitions; `[* n]`, `[-> n]` and `[= n]`, with the traced table (Visual coverage); `default sequence`; "incremented at most once per sample"; length-0 transitions are illegal.
   - An ignored or illegal *sequence* removes covered sequences that contain it (`2=>3` removes `1=>2=>3=>4`), while an ignored *value* "has no effect on a transition that includes the value".
   - Ignored and illegal transition bins cannot be unbounded.
   - `binsof` uses a transition's last value.
   - How an `iff`-false sample affects a pending transition is not stated in the LRM text; label it tool-dependent.
4. **Cross bins in depth (§19.6, §19.6.1–§19.6.1.4, §19.6.2, §19.6.3, Table 19-1):**
   - User-defined `bins` selections, with automatic bins retained only where they do not intersect a user bin. `option.cross_retain_auto_bins = 0` removes them all.
   - `with (…) matches n` selections and `CrossQueueType` enumerations.
   - An illegal cross product beats an ignore. A cross may have an `iff` guard, and each cross bin a per-bin `iff`.
   - A crossed variable becomes an implicit coverpoint. A cross across covergroups is a compile error.
5. **Covergroup inheritance and real-valued coverpoints (§19.4.1, §19.5, §19.5.1, Table 19-3):**
   - `covergroup extends cg;` in a derived class replaces the base instance and inherits its arguments and event. A same-name coverpoint overrides, and a derived covergroup "shall not define a new coverage model for class properties that are local to the base class".
   - Real coverpoints need explicit bins, and cannot have transition or wildcard bins.
   - `type_option.real_interval` defaults to 1.0. Tolerance ranges are written `[x +/- y]` and `[x +%- y]`.
   - Both features are in the 1800-2023 text; the revision that introduced each is unverified and tool support varies, so label them.
6. **Weights, goals and instance vs type numbers (§19.7, §19.7.1, §19.11, §19.11.1, §19.11.3, Tables 19-1–19-4):**
   - `weight`, `goal`, `comment` and `per_instance` never propagate from the covergroup to its items. `at_least`, `auto_bin_max`, `detect_overlap`, `cross_num_print_missing` and `cross_retain_auto_bins` do.
   - `per_instance` and `get_inst_coverage` can be set only in the definition. Other instance options may be assigned procedurally (`g1.a.option.weight = 3`).
   - Type options are constant expressions. `strobe` and `real_interval` are definition-only; the others may be assigned through `::` (`gc::a::type_option.weight = 3`).
   - With `merge_instances = 0`, type coverage is the instances' average weighted by `option.weight`. With 1, it is the union of bins (matched by name), weighted by `type_option.weight`, and a merged bin needs the maximum `at_least` of all instances.
   - Consequence: `option.weight = 0` removes a coverpoint from instance coverage and from the default type number. Under `merge_instances = 1`, also set `type_option.weight = 0`.
   - Under merge, `get_inst_coverage()` equals `get_coverage()` unless `option.get_inst_coverage = 1`.
   - Zero-denominator rules: an item weighted nonzero returns 0.0; one weighted zero returns 100.0.
7. **`illegal_bins` versus assertions (methodology):**
   - An illegal bin fires only on a sampled value (§19.5.6), so guarded idle cycles are never checked.
   - Whether illegal bins still report while a covergroup is `stop()`ped (Table 19-5) is not stated; behaviour when a tool option disables functional coverage is also tool-dependent.
   - Use SVA (I-SV-4A) or a checker for protocol rules. Keep `illegal_bins` as the coverage model's own statement of what must never be observed.
8. **Coverage-model size and simulation cost (tool-dependent; give no figures):**
   - `bins v[] = {[0:$]}` on a 16-bit field creates 65,536 bins.
   - Automatic bins on a 32-bit field are 64 ranges of 2^26 values each.
   - A cross of three 16-bin coverpoints has 4,096 bins.
   - Sample once per transaction, not per clock.
   - `per_instance` grows the database.
   - Use `detect_overlap` as a lint and `cross_num_print_missing` to list holes.
9. **Sampling corner cases (sub-lesson; §19.3, §19.5, §19.8.1, §14.10, §14.13):**
   - Several clocking events in one time step give several samples. `strobe` filters them, but it does not affect `sample()` calls or block events.
   - `@@(end task)` is not triggered if the task is disabled.
   - Coverpoint expressions are evaluated in a procedural context, so virtual-interface access is legal.
   - A `#0`-skew clocking input gives Observed-region values.
   - Sample formal arguments may appear only in coverpoints and guards.
   - `cg.sample()` can be called from a `cover property` match item to cover assertion local variables (§19.8.1 example).
10. **Interview angles (attempt-first `InterviewQuestionPlayground`):** see the Assessment plan.

**`## Quick Take`**
- **What it is:** functional coverage counts *observed* values of plan-relevant expressions each time a covergroup samples. Define four terms:
  - a **covergroup**: a type you instantiate;
  - a **coverpoint**: one sampled expression;
  - a **bin**: a set of values or transitions with a counter;

- **Why it matters:** the plan's rows become numbers, and code coverage is the complement (F1B). 100% means the listed scenarios were observed, not that the DUT was checked (link I-SV-3B).

**`## Make It Work`**

`### Worked example: four plan rows on a small bus` (L13-3A-06). Plan rows:
- VP-1: every address region (low 0–3, mid 4–7, 8–11, high 12–15);
- VP-2: address 15 is reserved;
- VP-3: reads and writes;
- VP-4: every region read and written, except that low is read-only.

```systemverilog
// compile
`timescale 1ns/1ps

typedef enum bit {READ, WRITE} op_e;

interface bus_if (input logic clk);
  logic [3:0] addr;
  op_e        op;
  logic       valid;

  clocking drv_cb @(posedge clk);
    output addr, op, valid;
  endclocking

  // Default #1step input skew: the monitor reads the values from before the edge
  clocking mon_cb @(posedge clk);
    input addr, op, valid;
  endclocking
endinterface

class bus_txn;
  bit [3:0] addr;
  op_e      op;
endclass

class bus_cov;
  covergroup cg with function sample(bus_txn t);
    option.per_instance = 1;   // keep this instance's numbers in the database
    cp_addr: coverpoint t.addr {
      option.comment = "VP-1 address regions";
      bins low    = {[0:3]};
      bins mid[2] = {[4:11]};          // mid[0] = 4..7, mid[1] = 8..11
      bins high   = {[12:15]};
      illegal_bins reserved = {15};    // VP-2: 15 is reserved; also leaves high
    }
    cp_op: coverpoint t.op {
      option.comment = "VP-3 reads and writes";   // enum: one automatic bin each
    }
    addr_x_op: cross cp_addr, cp_op {
      option.comment = "VP-4 every region read and written; low is read-only";
      ignore_bins no_wr_low = binsof(cp_addr.low) && binsof(cp_op) intersect {WRITE};
    }
  endgroup

  function new();
    cg = new();   // an embedded covergroup exists only if new() builds it
  endfunction
endclass

module tb_top;
  logic clk = 1'b0;
  always #5 clk = ~clk;

  bus_if  bif (clk);
  bus_cov cov = new();

  task automatic drive(bit [3:0] a, op_e o);
    @(bif.drv_cb);
    bif.drv_cb.addr  <= a;
    bif.drv_cb.op    <= o;
    bif.drv_cb.valid <= 1'b1;
    @(bif.drv_cb);
    bif.drv_cb.valid <= 1'b0;   // one transfer, then an idle cycle
  endtask

  // Coverage sees what the monitor observed, once per transfer
  task automatic monitor();
    forever begin
      @(bif.mon_cb);
      if (bif.mon_cb.valid === 1'b1) begin
        bus_txn t = new();
        t.addr = bif.mon_cb.addr;
        t.op   = bif.mon_cb.op;
        cov.cg.sample(t);
      end
    end
  endtask

  function automatic void report();
    int covered, total;
    void'(cov.cg.addr_x_op.get_inst_coverage(covered, total));
    $display("cp_addr   : %6.2f%%", cov.cg.cp_addr.get_inst_coverage());
    $display("cp_op     : %6.2f%%", cov.cg.cp_op.get_inst_coverage());
    $display("addr_x_op : %6.2f%% (%0d of %0d cross bins)",
             cov.cg.addr_x_op.get_inst_coverage(), covered, total);
    $display("cg        : %6.2f%%", cov.cg.get_inst_coverage());
  endfunction

  initial begin
    fork
      monitor();
    join_none
    drive(4'd2,  READ);
    drive(4'd5,  WRITE);
    drive(4'd9,  READ);
    drive(4'd12, WRITE);
    drive(4'd0,  WRITE);   // <low, WRITE> is ignored by the cross
    drive(4'd6,  READ);
    drive(4'd13, READ);
    drive(4'd15, WRITE);   // reserved: a run-time error, no cp_addr bin counts it
    @(bif.drv_cb);         // let the monitor sample the last transfer
    report();
    $finish;
  end
endmodule
```

`### How to turn a plan into a covergroup` (numbered; keep lines 174-177 and add):
1. One coverpoint per plan dimension, with IDs in `option.comment`.
2. Named ranges before `[]` arrays.

`### Debugging coverage` (new; L13-3A-16):

| Symptom | Likely cause | Fix |
|---|---|---|
| 0%, no bin ever hit | embedded covergroup never built in `new()`, `sample()` never called, or `iff` always false | build in `new`; call `sample()` per transaction; check the guard |
| 100% too early; counts far above the number of transfers | clocked covergroup without `iff` samples idle cycles | add `iff (valid)` or sample from the monitor |
| Every count exactly doubled | clocking event plus a manual `sample()` | keep one sampling style |
| A value you drove appears nowhere | outside every bin, ignored, or never observed by the monitor | temporarily add `bins others = default`; check the ignores and the monitor |
| A planned bin vanished and the percentage still reads 100% | value resolution emptied it (elaboration warning) | read the warning; fix the bin or the plan (D1) |
| Run-time error naming an illegal bin | a forbidden value was observed, or the `illegal_bins` list is wrong | check the spec first, then the list |
| Thousands of bins, slow runs | `[]` over wide ranges, automatic bins on wide fields, big crosses | named ranges, `auto_bin_max`, fewer crossed bins |

  typedef struct packed {
    bit       valid;
    bit [1:0] kind;
    bit [7:0] length;

                       '{0, 3, 5},  '{1, 0, 30}, '{1, 0, 40}};

    $display("cp_len : %6.2f%%", cov.cp_len.get_inst_coverage());
    $display("cg_pkt : %6.2f%% (goal 90)", cov.get_inst_coverage());
  end

| i-sv-3a-1 | What is a covergroup, and what happens if an embedded one is never constructed? | A user-defined type holding coverpoints, crosses, a sampling event and options; you create instances with `new` (§19.3). An embedded covergroup must be built in its class's `new()`, or it never exists and samples nothing (§19.4). |
| i-sv-3a-2 | How many bins do `bins a = {[0:3]};`, `bins b[] = {[0:3]};` and `bins q[3] = {[0:9]};` create? | 1 (all four values together), 4 (`b[0]`…`b[3]`), and 3: `{0,1,2}`, `{3,4,5}`, `{6..9}`. B = floor(10/3), and the last bin takes the rest (§19.5.1). |
| i-sv-3a-3 | A value lies outside every bin and there is no default bin. What happens? | Nothing: no bin counts it and the percentage does not change. It is invisible, not a hole (§19.5). |
| i-sv-3a-4 | Do default, `ignore_bins` and `illegal_bins` count toward coverage? | No. Default bins are neither counted nor crossed; ignored and illegal values are removed from every bin after the bins are built, and bins left empty drop out (§19.5, §19.5.5, §19.5.6, §19.11.1). |
| i-sv-3a-5 | What does a hit on `illegal_bins` do? | The value counts in no bin and the simulator issues a run-time error. Illegal bins beat every other bin; whether the run stops depends on the tool (§19.5.6). |
| i-sv-3a-6 | When are automatic bins created, and how many? | Only when a coverpoint declares no bins other than ignore and illegal bins. N is the enum's cardinality, else min(2^M, `auto_bin_max`) (default 64); samples with x or z are skipped (§19.5.3). |
| i-sv-3a-7 | What do `[* n]`, `[-> n]` and `[= n]` mean in a transition bin? | `[* n]`: n consecutive samples of the value. `[-> n]`: n occurrences with gaps, and the next transition must follow the last one immediately. `[= n]`: the same, but the next value may come later if the repeated value does not recur (§19.5.2). |
| i-sv-3a-8 | What does a value-resolution warning on a bin mean? | A bin value does not fit the coverpoint's type. A warned singleton is dropped and a range shrinks to the representable values, so a bin can silently become empty and leave the percentage (§19.5.7, §19.11.1). |
| i-sv-3a-9 | What does `binsof(cp_op) intersect {BURST}` select? | Every cross bin whose `cp_op` bin contains the value `BURST`. `intersect` takes values; `binsof(cp_addr.high)` selects by bin name (§19.6.1). |
| i-sv-3a-10 | A cross declares `bins i_zero = binsof(i) intersect {0};`. What happens to the automatic cross bins? | They are kept only where they do not intersect a user-defined bin (`cross_retain_auto_bins`, default 1). With 0, any user bin removes them all (§19.6.1, Table 19-1). |

| i-sv-3a-14 | `option` vs `type_option`? | `option.*` is per instance: values can differ between instances, and many can be set procedurally. `type_option.*` describes the covergroup type, is set with constant expressions, and is assigned through `::`, e.g. `cg::type_option.merge_instances = 1;` (§19.7, §19.7.1, §19.10). |
