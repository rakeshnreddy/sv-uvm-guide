## Completeness and depth gaps the analyst missed

Spot-check of the analyst's tables. The "covered" and "missing" marks hold:
- `parallel` is named but never coded (`:33`).
- `schedule` is absent.
- Misconception 2 appears only as a code comment (`:228`).
- The syntax row is "yes": every PSS construct on the page checks against the 3.0 BNF, including `constraint expr;` (`constraint_declaration ::= constraint constraint_set`), `constraint id { dist … }`, and a `select` with at least two branches.

Gaps not listed:

1. **The `dist` exclusion rule belongs in the core/practitioner text, not only in the quiz and the bar chart** (V01). Today the page teaches the opposite impression.
2. **The realization layer at practitioner level (objective 3).** `exec declaration SV` and `exec header C` are the standard places for the declarations and includes that templates need. `declaration` and `header` are valid in action, flow/resource object and struct types (§22.1.2, §22.5).
   - `exec declaration SV` is a clean alternative fix for L44-PSS-16 (`wr`/`rd` undeclared): with it, the tool emits the declarations, and nobody has to hand-edit the generated class.
   - The analyst places exec kinds only in the expert layer.
3. **Imported functions (§22.4) as the other realization mechanism.** "What stays hand-written" (objective 3) is either exec templates or a foreign API that imported functions call (the C HAL, a DPI layer). That belongs in the core picture (row 1), not only in Expert item 5. Link I-SV-7.
4. **Hierarchical flow-object binding (§12.10).** A compound action with its own input or output delegates it to a sub-action with `bind`. Buffer timing then follows the outer action. This is needed once the learner composes scenarios from compound actions; add it as an expert note.
5. **Input formats.** The PSS 3.0 text defines a single DSL (§1.2). The 2018 tool announcements advertise both "DSL and C++ syntaxes" for PSS 1.0. Add one line to the tool landscape, "3.0 defines only the DSL; check what your tool accepts". When the C++ format was dropped is unverified.
6. **A picture for pools and static binding** (V11).

Depth ladder: I agree with the analyst. Core is partial, practitioner is partial and expert is missing. The nine expert items are accurate as cited; I verified each normative number above. Two exceptions:
- the 2.1-release-notes claim about `atomic` is unverified;
- the `pssparser` "3.1 B.14 / 13.1.12" citation for `soft` is unverified (the analyst already says so).
