**Expert (absent).** Add these `### Expert:` items:
- **E1. Where the LRM imposes a solve order.** `randc` is solved first and "this can sometimes cause randomize() to fail" (§18.4.2). Sizes are solved before `foreach` and reductions, which "can cause the solver to fail" (§18.5.7.1, §18.5.7.2). Function arguments are solved first, which "subdivides the solution space… can cause the overall constraints to fail" (§18.5.11). Contrast `solve…before`, which "does not change the solution space and, therefore, cannot cause the solver to fail" (§18.5.9).
- **E2. Arithmetic width and sign inside constraints.**
  - Sizing (§11.6) and sign rules (§11.8.1) apply unchanged.
  - §18.6.1's `SimpleSum` (`rand bit [7:0] x, y, z; z == x + y`) admits x = 200, y = 100, z = 44.
  - `sum()` returns the element type unless `with` is used (§18.5.7.2), and `rand int` lengths can go negative (§6.11.3).
- **E3. Object graphs.**
  - Active random objects are collected recursively (§18.5.8).
  - "Randomization shall not modify the actual object handle", and `randomize()` "does not allocate any class objects" (§18.4).
  - Null handles need guards (§18.5.12).
  - `rand_mode(0)` on a handle does not change the modes inside the object (§18.8).
  - Hooks run on enabled members (§18.6.2).
- **E4. Constraint reuse by inheritance.**
  - Override by name and `pure constraint` (§18.5.2); prototypes and external blocks (§18.5.1).
  - Derived-class and inline soft constraints outrank base ones (§18.5.13.1).
  - Static constraint modes are shared by all instances, and override specifiers are illegal on static constraints (§18.5.10).
  - IEEE 1800-2023 lets a constraint carry `:initial`/`:extends`/`:final` (Syntax 18-2; the semantics section is unverified, and tool support varies).
  - Trade-off: derived item + factory override vs `constraint_mode()` knobs vs inline `with`.
- **E5. `randomize()` as a checker.** `randomize(null)` (§18.11.1) and no-argument `std::randomize() with { … }` (§18.12). Pattern: load observed fields into an item and check them against the item's legal space.
- **E6. Random stability under code change.**
  - Thread and object RNGs (§18.14.1–§18.14.3) and determinism (§18.13.1).
  - Self-seeding in `new`. The LRM notes "there is no guarantee that the creating thread can change the object's random state before another thread accesses the object" (§18.15).
  - Snapshot and replay with `get_randstate()`/`set_randstate()`. The strings are implementation-dependent (§18.13.4–§18.13.5).
- **E7. UVM seeding (uvm-core 2020.3.1 implementation; IEEE 1800.2 clause unverified).**
  - Components reseed in `new`.
  - Each component's task-phase process is reseeded in `uvm_task_phase::execute`.
  - Sequences and items reseed in `set_item_context`, which `start`, `create_item` and `start_item` call.
  - The seed is a hash of type name, full name and `uvm_global_random_seed`, plus a per-name counter.
  - Consequence: adding a component does not shift other components' run-phase streams, but a plain `new` in a build function or a renamed sequence does.
- **E8. Silent failures in UVM flows.**
  - The `` `uvm_do `` family warns (`RNDFLD`) and still sends the stale item (uvm-core `uvm_sequence_defines.svh`).
  - `assert(randomize())` disappears under assertion control (§20.11).
  - Regression gate: promote `RNDFLD` with `set_report_severity_id_override` (IEEE 1800.2-2020 §6.3.7) or `+uvm_set_severity=*,RNDFLD,UVM_WARNING,UVM_ERROR` (Annex G.2.5; four-field format verified in uvm-core).
- **E9. Tool-dependent behaviour (labelled).**
  - Solver engines, contradiction reports and debug switches. Name them only after checking the vendor manual.
  - Solver time and memory on large arrays and `unique`.
  - `dist` distribution when the variable is coupled to others: the visual's own assumption says "tools may differ".
  - Seeds do not transfer between simulators: the default seed is implementation-dependent (§18.14.1) and the RNG state format is implementation-dependent (§18.13.4).
  - This item backs the interview question `sv-senior-staff-constraint-perf`, which `src/lib/practice-links.ts` (`INTERVIEW_QUESTION_LESSONS`) maps to these pages.
- **E10. IEEE 1800-2023 currency.** `rand real` variables are allowed but not `randc` (§18.4). Real `dist` ranges use `:/` (§18.5.3). Constraint override specifiers (Syntax 18-2).

**Flashcards.** New `content/flashcards/I-SV-2B_Advanced_Constrained_Randomization.json`, ids `i-sv-2b-1` … `i-sv-2b-15`. Nothing in the existing deck needs fixing for this module.

1. **Q:** In a constraint, what is `a -> b` equivalent to, and can `b` affect `a`? **A:** `!a || b` (§18.5.5). Both sides are solved together, so if `b` cannot hold the solver makes `a` false, and a narrow `b` makes `a` rare.
2. **Q:** `rand bit w; rand bit [7:0] addr; constraint c { w -> addr < 16; }`: how often is `w == 1`? **A:** 16/272 ≈ 5.9%, because the solver picks uniformly among legal `(w, addr)` pairs (§18.5.9). `solve w before addr;` makes it 50%.
3. **Q:** How does an `if`/`else` constraint relate to implication? **A:** It is equivalent to two implications, and the condition is solved together with the branches (§18.5.6). An `else` binds to the nearest `if` without one.
4. **Q:** An array has both a `size()` constraint and `foreach` constraints. What is solved first? **A:** The size, which is a state variable inside the `foreach` (§18.5.7.1). If the element rules cannot hold for the chosen size, `randomize()` can fail, so bound the size directly.
5. **Q:** Why can `rand bit [7:0] a[]; constraint c { a.sum() < 100; }` accept bytes adding up to 300? **A:** Without `with`, `sum()` has the element type, so the total wraps at 8 bits (§18.5.7.2). Write `a.sum() with (int'(item)) < 100`.
6. **Q:** What does `unique {a, b, arr}` require? **A:** No two members are equal; all members have equivalent types; no `randc` member (§18.5.4). Too few legal values for the members makes every call fail.
7. **Q:** What is a constraint guard? **A:** A condition on constants, state variables, handle comparisons or loop indices that decides whether a constraint is created, for example `if (next != null)` (§18.5.12). A condition on a random variable is a constraint, not a guard.
8. **Q:** Why can `x > F(y)` fail where `x > y` would not? **A:** Function arguments are solved first and become state, which subdivides the solution space (§18.5.11). A `y` with no legal `x` makes the call fail.
9. **Q:** `c_len.constraint_mode(0)` vs `len.rand_mode(0)`? **A:** The first makes the solver ignore the block (§18.9). The second makes `len` a state variable whose current value is a constant (§18.8).
10. **Q:** What happens on a failed `randomize()`? **A:** It returns 0, the random variables keep their previous values, and `post_randomize()` is not called; `pre_randomize()` has already run (§18.6.3).
11. **Q:** How do you replace a base-class constraint? **A:** Declare a constraint with the same name in the derived class; a new name adds a constraint (§18.5.2). `randomize()` is virtual, so a base handle still uses the derived constraints.
12. **Q:** What do `obj.randomize(v)` and `obj.randomize(null)` do? **A:** `randomize(v)` makes `v` the only random variable for that call, even if it is not `rand` (§18.11). `randomize(null)` changes nothing and returns 1 only if every active constraint holds (§18.11.1).
13. **Q:** Why can one extra `new()` early in a test change every later random value? **A:** Each new object or thread is seeded from the next value of its creating thread's RNG (§18.14.1). Add new objects at the end, or seed them with `srandom()`.
14. **Q:** Does an extra `obj.randomize()` change other objects' values? **A:** No: each object has its own RNG (§18.14.3). An extra `$urandom` or `std::randomize()` draws from the thread's RNG, so it shifts the seeds of objects and threads created after it in that thread (§18.14.1, §18.14.2).
15. **Q:** Your `` `uvm_do_with `` constraints conflict, yet the test passes. Why? **A:** In uvm-core 2020.3.1 the `` `uvm_do `` family reports a failed `randomize()` only as `UVM_WARNING` `RNDFLD` and still sends the item. Randomize explicitly and call `` `uvm_fatal `` on failure.
