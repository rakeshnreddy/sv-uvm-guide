- **Expert: absent.** No Push Further and no `### Expert:` items. *Add*, with sources:
  1. **Master-port vs slave-port checking.** At a slave, acceptance is `HSELx && HREADY`, and HSELx may be high while HREADY is low and the selected slave may change (IHI0033B.b §4.2). Slave obligations (two-cycle ERROR §5.1.3; zero-wait OKAY for IDLE/BUSY, Table 3-1; HREADYOUT high in reset §7.1.2) are checked on that slave's HREADYOUT/HRESP (§2.3), not on the multiplexed HREADY. A multi-layer interconnect may terminate a burst at a slave port (§3.5.2), so beat-count rules differ by side.
  2. **Burst tracking FSM:**
     - beat count per Table 3-3;
     - fixed-length bursts end with SEQ, and no BUSY follows a SINGLE (§3.5.1);
     - BUSY only between beats (§3.6.1 Note, Table 3-1), and SEQ only inside a burst;
     - WRAP SEQ address = wrap(prev + size) at beats × size (§3.5);
     - cancel after ERROR (§3.5.2).
  3. **Formal reuse (assume-guarantee):** for a slave DUT, the master-side rules (hold, SEQ address, 1KB, alignment) become `assume property` (IEEE 1800-2023 §16.14.2) and the slave obligations stay `assert`. A `ROLE` parameter switches them. Vacuity shows through `cover` on the antecedents (§16.14.3, §16.14.8).
  4. **Assertions in a UVM regression:**
     - `$error` vs `` `uvm_error `` (A-UVM-7 L142);
     - demotion with `uvm_report_catcher` (IEEE 1800.2-2020 §6.6.1, `catch` §6.6.5);
     - `$assertcontrol`/`$assertoff` for deliberate violations (IEEE 1800-2023 §20.11);
     - a `checks_enable` knob;
     - expected-error accounting (link proposed A-UVM-9).
  5. **Specification corner cases:**
     - IDLE addresses must be aligned too (§3.5);
     - HSIZE ≤ bus width (§3.4);
     - HWRITE, HSIZE and HPROT constant through a burst (Table 2-2, §3.4, §3.7);
     - a locked sequence stays in one slave region (§3.3);
     - signals required to be stable are compared at rising edges only; glitches between edges are allowed unless Stable_Between_Clock is True (§7.1.1);
     - BE8 uses the little-endian lanes, BE32 does not (§6.2.2, §6.2.3, Tables 6-2 and 6-3), which matters for the scoreboard;
     - a component may need a minimum number of reset cycles before its reset values hold (§7.1.2);
     - a module cannot be bound into an interface, only an interface or a `checker` can (IEEE 1800-2023 §23.11 footnote 4);
     - WRAP16 of 1024-bit transfers spans a 2KB block. This is derived from Table 3-2, §3.5 and §6.3; the spec states the 1KB rule only for incrementing bursts. Label it "derived".
     - Awareness: exclusive transfers (Chapter 8) and HNONSEC (§3.9). Later AHB issues add optional write strobes (unverified: IHI0033 Issue C not checked).
  6. **Scale and performance:**
     - sample pin-level covergroups only on accepted beats (`iff`);
     - per-beat vs per-burst items (the monitor can publish both);
     - start property attempts only on qualified antecedents;
     - gated `$past` vs auxiliary state;
     - sparse associative memory in the scoreboard.
  7. **Interview angles (attempt-first):**
     - "Your checker is green but a FIFO slave double-pushes: why, and how do you catch it?" (B-AHB-2 Pitfall 1B; §6.1.1; pin-invisible.)
     - "Which ERROR assertion catches a one-cycle ERROR?"
     - "Can a legal AHB burst cross 1KB?"
     - "Where do you put the checker in a multi-layer system?"
     - "UVM summary clean, log full of assertion errors: explain."
     - "Design the scoreboard for a 2-master, 3-slave interconnect with a default slave."

**`## Quick Take`**
- **What it is:** a pipelined monitor turns pins into transfers; a checker judges every cycle against IHI0033B.b; coverage records which planned scenarios ran; a scoreboard checks the data. A master driver and a slave responder produce every legal timing.
- **Why it matters:** AHB bugs live in the pipeline (wait states, BUSY, ERROR). A checker that fires on legal cancel-after-ERROR, or misses a one-cycle ERROR, gives false confidence.
- **The Analogy:** a station clerk pairs each ticket (address phase) with the passenger who boards later (data phase, after any delay), while a signal box checks every signal against the rulebook. *Where it breaks:* the signal box sees only the track (the pins). A slave that writes twice internally (B-AHB-2 Pitfall 1B) is invisible to it, which is why a scoreboard or white-box check exists.
- **You will be able to:** the five objectives below.
- **Before you start:** the prerequisites below, linked.
