## Completeness and depth gaps the analyst missed

1. **I-UVM-4, pack/unpack symmetry (must-cover).** Cite the normative sentence in §5.3.10.2: "While the unpacking order needs to match the packing order, the packing order does not need to match declaration order". Also cite the §5.3.10.1 NOTE that the return value may differ from the stream size because the stream may hold metadata. Neither is in the analyst's source list.
2. **I-UVM-4, nested objects in pack/unpack.**
   - `unpack_object` needs an allocated destination: check `is_null()`, create the object if needed, then call `unpack_object` (§16.5.4.3–§16.5.4.4).
   - uvm-core errors `UVM/BASE/PACKER/UNPACK/NN2N` when it unpacks a non-null object into a null handle.
   - uvm-core's `uvm_field_object` instead packs through `pack_object_with_meta`: a 32-bit reference id plus the type name, and the object is created on unpack. B.2.4 has no `` `uvm_pack_object `` macro, so this is uvm-core only.
   - The analyst's L25-UVM4-02 fix names `pack_object`/`is_null`/`unpack_object` without these rules.
3. **I-UVM-4, which comparer knobs survive `compare()`.**
   - In uvm-core, `flush()` keeps the threshold, `show_max`, verbosity, severity and recursion policy, but resets `check_type` to 1.
   - In 1800.2, `flush` resets the threshold to 1.
