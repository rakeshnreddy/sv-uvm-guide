**Expert: absent.** Add each item as `### Expert: <topic>`. Sources were checked unless marked otherwise.
1. **The end-of-test machinery, exactly:**
   - `phase_ready_to_end` is called again after each all-drop that follows a raise, up to `get_max_ready_to_end_iterations()` (default 20) (§13.1.4.3.2; §9.3.1.3.4–§9.3.1.3.5; `uvm_phase_hopper.svh:503-545`).
   - A drain time is cancelled by a raise (§10.5.1.3.7).
   - When `run_phase` ends, its processes are killed (`uvm_phase_hopper.svh:690`), so late monitor writes never happen.
   - The global timeout is `set_timeout` (F.7.3.3) or `+UVM_TIMEOUT` (uvm-core impl.), with a default of 9200 s (`uvm_global_defines.svh:85`). It ends the run with `UVM_FATAL [PH_TIMEOUT]` (`uvm_phase_hopper.svh:587`), and `die()` then runs `pre_abort()` and the report summary but no `check_phase` or `report_phase` (`uvm_root.svh:157-185`).
   - Override `pre_abort()` (§13.1.4.6) to print `SCB_SUMMARY` and the pending keys.
2. **Configuring `compare()` for a scoreboard:**
   - With a null comparer, `compare()` uses the default comparer and flushes it at depth 0 (§5.3.9.1).
   - Defaults are normative: `show_max` 1 (§16.3.5.1), verbosity `UVM_LOW` (§16.3.5.2), severity `UVM_INFO` (§16.3.5.3) and threshold 1 (§16.3.6, "potentially skipping additional field comparisons").
   - Field-macro compares stop once the result reaches the threshold (`uvm_comparer_defines.svh:45-47`).
   - Use a scoreboard-owned comparer with `set_threshold(0)` and report `get_miscompares()` (§16.3.3.8) in your own `` `uvm_error ``.
3. **uvm-core's built-in comparators (uvm-core impl., not in IEEE 1800.2-2020):**
   - `uvm_in_order_class_comparator` and `uvm_algorithmic_comparator` exist in `src/comps` (`uvm_in_order_comparator.svh:242`, `uvm_algorithmic_comparator.svh:81`). The 1800.2 text has no occurrence of either name.
   - A mismatch is a `uvm_report_warning("Comparator Mismatch", …)` (`:172`).
   - Nothing checks leftovers: `flush()` only zeroes counters (`:201`). So a mismatch or a dropped item passes.
4. **Keyed matching at scale:**
   - Associative array of queues (IEEE 1800-2023 §7.8, §7.10). A read of a missing key warns and returns the default (§7.8.6), so guard with `exists()`, as :238 does.
   - Allocation through `aa[k].push_back()` is not among the §7.8.7 cases (assignment target, `ref` argument). Major simulators allocate the entry, so label it tool behaviour.
   - Delete emptied keys.
   - Bound or key the held queue; its `foreach` search is O(held).
   - Search-any matching lets a same-key reorder escape (the visual's exhaustive check) and costs O(n) per item.
   - At high transaction counts, light expected records (struct with key, data and timestamp) instead of a `uvm_object` per item. Label this as guidance to measure, not as a figure.
5. **Protocol ordering versus DUT policy:**
   - AXI: same-ID transactions stay ordered and different IDs are unrestricted (IHI0022E §A5.1). The read-data reordering depth is a static property of the slave design (§A5.3.1).
   - The scoreboard encodes the protocol rule and accepts any legal policy. A stricter promise in the DUT specification (for example "always in order") is a separate, switchable check.
   - Per-interface ordering belongs to SVA and protocol checkers (B-AXI-3, B-AXI-6).
6. **Reference-model independence and DPI-C:**
   - Common-mode errors (the model and the RTL share one misreading of the spec); mitigations: a different author, directed tests with hand-computed expectations, specification review.
   - `pure` imports only for stateless functions (§35.5.2); `context` when the C code calls exported SV (§35.5.3).
   - A stateful C model must be called in DUT order, so a predictor component serialises the calls.
   - Marshalling cost per call.
7. **Scoreboards across reset and injected errors (basic version):**
   - On reset, stop predicting and flush the expected queues, held items and analysis FIFOs (`flush()`, §12.2.8.2.6).
   - Report flushed items separately rather than as missing.
   - Predict error responses as expected results, and never demote `SCB/*` errors wholesale.
   - The strategy and the catchers (§6.6) belong to proposed A-UVM-9.
8. **Where checking belongs in a large environment:**
   - Assertions for time-local interface rules; scoreboards for end-to-end data.
   - One input split to N outputs: route expected items by destination. N inputs merged into one output: per-source queues.
   - Scoreboard knobs (ordering mode, maximum latency, enable) for passive reuse at SoC level (link E-SOC-1).
9. **Interview angles** (attempt-first; listed in the Target outline).

- **Participants:** `test`, `run phase`, `scb`, `objection`.
