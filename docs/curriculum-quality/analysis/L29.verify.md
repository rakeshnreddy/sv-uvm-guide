2. **What the drain's `wait` is sensitive to (practitioner).** The comment at :332 is right, but the rule behind it is never taught.
   - A `wait` re-evaluates only when an operand changes. Only non-virtual methods and built-in aggregate methods may appear in an event expression (LRM §9.4.2; §15.5.3).
   - So `wait (exp_fifo.used() == 0)` is not allowed, because `used()` is virtual (`uvm_tlm_fifos.svh:102`). `wait (outstanding == 0)` on a class member and `wait (exp_q.size() == 0)` on a queue are allowed.
   - With FIFO inputs, `outstanding` must also count items still waiting in the FIFO (see the AUVM6-02 row).
3. **Why the drain checks for the run phase.** In uvm-core 2020.3.1 the ready-to-end loop sits in the task-phase branch (`uvm_phase_hopper.svh:473-546`). So `phase_ready_to_end` is called for `run` and for every run-time task phase (`uvm_task_phase.svh:136`).
