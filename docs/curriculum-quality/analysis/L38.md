**Headline findings.**
1. **B-AXI-5 teaches the WSTRB misconception that its spine card names.** The page states that a 2-byte write at 0x1 "must" use `4'b0110` and gives no AxSIZE (L151-153). With AxSIZE=1, only lane 1 is active. The interconnect-deadlock section describes no mechanism that closes a loop, and it omits the AXI4 write-data-ordering deadlock (A5.3.2, A5.4.1).
2. **B-AXI-6's monitor stores one transaction per ID** (L41, L65): `pending_writes[vif.AWID] = txn`. This is the card's misconception 1, and it contradicts A-UVM-6 (L191) and B-AXI-3. Its code does not compile. The page has no W/R reassembly, no coverage, no responder, no error policy, no responsibility matrix, no picture and no references.

The starter still does not compile (LAB-P1).
4. **The deadlock lab's "legal" slave makes AWREADY a combinational function of WVALID** (testbench.sv:323). IHI0022E A3.1.1 and A3.2.1 forbid combinational input-to-output paths. Waiting for WVALID is a legal policy; this implementation of the wait is not.

  1. **Proving deadlock freedom.** Strong liveness `s_eventually` (IEEE 1800-2023 §16.12.13) under environment `assume` properties (§16.14.2), vs bounded `##[0:N]` simulation checks, which are safety checks against a contract. Formal liveness support, and the abstraction it needs, is tool-dependent; label it so.
  2. **Interconnect ordering obligations and their cost.**
     - Same-ARID reads to different slaves must return in issue order (A5.3.1), so the interconnect must stall or buffer.
     - "Any manipulation of the AXI ID values … must ensure that the ordering requirements of the original ID values are maintained" (A6.3).
     - Throughput trade-offs of stall vs reorder buffer; ID compression and truncation hazards (A5.3.5, A5.3.6).
  3. **Write-data ordering at scale.**
     - AXI4 W follows AW order (A5.4.1). An interconnect merging writes "must ensure that it forwards the write data in address order" (A5.3.2).
     - W can arrive before its AW, and the interconnect must realign them before routing (A3.3 note).
     - AXI3 legacy: a slave that supports interleaving "must continuously accept interleaved write data" (A5.3.3).
  4. **Latent violations and the most restrictive legal partner** (methodology derived from A3.3.1).
     - Against a slave that withholds AWREADY and WREADY until it has seen both AWVALID and WVALID (legal), a master that waits on READY hangs.
     - Against a master that withholds BREADY/RREADY until BVALID/RVALID (legal), a slave that waits on BREADY/RREADY hangs.
  5. **Errors, early termination and default slaves.** "Early termination of bursts is not supported" (A3.4.1). "The required number of data transfers must be performed, even if an error is reported" (A3.4.4). A DECERR default slave must still complete all data transfers (A3.4.4).
  6. **Interview angles** (attempt-first `InterviewQuestionPlayground`):
