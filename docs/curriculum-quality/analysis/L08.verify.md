**Missing practitioner and expert items** (add them to the Target outline):
1. **Program termination (§24.3).**
   - When all `initial` procedures of a program end, that program immediately kills their descendant threads. A monitor started with `fork … join_none` from a program `initial` dies with it, a classic program-bench pitfall.
   - The implicit `$finish` waits for every thread, and every descendant, of the `initial` procedures in all programs.
   - Put both in the program subsection, card f4c-12 and a Q2 distractor.
2. **Program scope rules.** Awareness level only:
   - design code may not call program subroutines (§24.5);
   - program signals may not be referenced from outside a program (§24.3);
   - concurrent assertions in a program keep Preponed sampling and Observed evaluation (§24.3.1).
3. **Clocking blocks through a modport-typed virtual interface (§25.9.2).**
   - Dot access to `vif.cb` works for an interface with no modports. With a modport-typed handle, the modport must list `clocking cb` (§25.5.5).
   - Add a debugging row: "`vif.cb` not found through `virtual pipe_if.mon`" → add `clocking mon_cb` to that modport.
   - Link F4B, which shows the working case (F4B:126 and :133).
4. **Off-edge cycle-delayed drives (§14.16, and the example in §14.16.2).**
   - A drive executed between edges with `<= ##N` matures at the N-th clocking event after it executes, or at the next event if there is no cycle delay. The LRM line `#1 cb.v <= ##2 expr3;` matures in cycle 3.
   - Do not teach "acts as if executed at the next clocking event, then N cycles later": that rule gives cycle 4 and contradicts the LRM.
5. **`##0` on the right-hand side of a drive has no effect (§14.11).**
6. **Skew legality (§14.3, §14.4).**
   - A skew must be a time literal, or a constant expression that evaluates to a non-negative integer.
   - Skews can be parameters (§14.4), which lets VIP expose them; that is practice and should be labelled so.
7. **No automatic clocking signals.** A clocking signal must not designate a variable restricted to a procedural block (§14.3, §6.21).
8. **A clockvar before its first clocking event.**
   - §14.13 defines an input clockvar's value only as the sample from the most recent clocking event.
   - The visualizer assumes X and labels that "clause unverified" (`ClockingBlockSkewVisualizer.tsx:36`).
   - Teach it as tool-dependent.
9. **Global clocking details for the awareness subsection (§14.14):**
   - not allowed in a generate block;
   - the NOTE on incompatibility with IEEE 1800-2009, which allowed only one global clocking in the whole elaborated design.
10. **Reset release practice** (optional, labelled as practice). Assert reset asynchronously, and release it away from the active edge. Gate-level timing checks (recovery and removal) are tool-dependent; give no figures.
