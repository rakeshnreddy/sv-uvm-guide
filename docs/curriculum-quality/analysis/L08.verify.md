**Missing items.** Add them to the Target outline. The layer is given in brackets.
1. **[core]** "Clocking event" and "clocking block event" as two defined terms (§14.3, §14.10). See V01.
2. **[practitioner]** Program termination (§24.3): the per-program kill of descendant threads, and the conditions for the implicit `$finish`. See -07. Use it as a pitfall ("a forked monitor dies when the program's `initial` procedures end"), in card f4c-12 and as a Q2 distractor.
3. **[expert, awareness]** Program scope rules:
   - program signals cannot be referenced from outside a program (§24.3);
   - design code cannot call program subroutines (§24.5);
   - programs can be nested in modules or interfaces, and are implicitly instantiated when they have no ports or are top-level and not explicitly instantiated (§24.3);
   - anonymous programs exist (§24.6).
4. **[expert]** Concurrent assertions in a program still sample in Preponed and evaluate in Observed (§24.3.1).
5. **[practitioner]** Modport-typed virtual interfaces. §25.9.2 says dot access to a clocking block through a virtual interface "only works for interfaces with no modports"; otherwise the modport must list the clocking block (§25.5.5). Link F4B (F4B:126, :133) and add the debugging row in V05.
6. **[expert]** Off-edge `<= ##N` drives. Teach the §14.16.2 example as written: `#1 cb.v <= ##2 expr3;` matures in cycle 3. Do not derive it from §14.16's general sentence ("as if they had executed at the time of the next clocking event"): applying that sentence and then counting two cycles gives cycle 4. State the result as "the drive matures at the N-th clocking event after it executes, or the next one when there is no cycle delay". This matches both LRM examples.
7. **[expert]** `##0` on the right-hand side of a drive has no effect (§14.11).
8. **[practitioner]** Skew legality: a skew is a time literal or a constant expression that evaluates to a non-negative integer (§14.3), and it can be a parameter (§14.4). That VIP expose skews as parameters is practice; label it so.

11. **[practitioner]** "Declarations in unnamed clocking blocks may not be referenced" (§14.3). An unnamed default clocking therefore serves only `##` and the default assertion clock (§16.16).
12. **[expert, awareness]** Properties and sequences can be declared inside a clocking block (§14.3 `assertion_item_declaration`; §16.16 `primary_clk.p3`; §25.5.5 `property p1` inside `sb`). Link I-SV-4A.
13. **[practitioner]** One copy of a clocking block is created per instance of the enclosing block (§14.7). Each interface instance, for example one per agent, has its own `cb`.
14. **[awareness]** Global clocking details:
    - not allowed in a generate block;
    - the NOTE on incompatibility with IEEE 1800-2009, which allowed one global clocking for the whole design (§14.14).
15. **[expert]** A clocking `inout` is shorthand for an input plus an output, not an inout port, so it may name a variable (§14.5).
16. **[practitioner, labelled practice]** Reset release: assert asynchronously, and release away from the active edge. Recovery and removal checks are tool- and library-dependent, so give no figures.
