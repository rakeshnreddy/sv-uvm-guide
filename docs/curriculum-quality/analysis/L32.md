    - the AXI4-Lite rule set (§B1.1–§B1.1.4) and the AXI4-Stream signal set (IHI0051A §2.1);
    - what an interconnect does (§A1.3.2, §A5.3.5, §A3.4.4) and the responses of each protocol;
    - a verification-consequence table per protocol: driver threads, monitor pairing, checker rules, scoreboard ordering model, coverage axes;
    - a worked selection and a compilable wire-count example (Target outline).
- **Expert: absent.** Add these as `### Expert:` subsections:
  - **AXI3 vs AXI4, what a VIP must be told.**
    - INCR bursts up to 256 beats, with AxLEN[7:0] (§A3.4.1).
    - Write interleaving and WID removed (§A5.4, §A5.4.1).
    - Locked transactions removed; AxLOCK is one bit (§A7.3, Table A7-2).
    - AxQOS and AxREGION added (§A8.1.1, §A8.2.1).
    - The AXI4 write-response dependency, and AXI3 legacy slaves that respond before accepting the address (§A3.3.1, §A3.3.2).
  - **AXI4-Lite in a full-AXI system.**
    - ID reflection (§B1.2.1) and direct connection (§B1.2.2).
    - Conversion (§B1.3, §B1.4).
    - A converted write may arrive with all strobes low (§B1.1.3).
  - **Interconnect topologies and IDs.**
    - The three topologies (§A1.3.2) and register slices (§A1.3.3).
    - ID extension, so slave-side IDs are wider than master-side IDs (§A5.3.5).
    - Same-ARID order across slaves, kept by the interconnect (§A5.3.1).
    - DECERR, ideally from a default slave, with every beat still completed (§A3.4.4).
  - **AHB-Lite, multi-layer AHB and AHB5.**
    - Single master, decoder and multiplexor (§1.1, §4.1).
    - Multi-master interconnects are outside the spec (§1.1.3, §4.1). ARM DVI 0045 is unverified.
    - The AHB5 properties (§1.2): Extended_Memory_Types, Secure_Transfers, Endian, Stable_Between_Clock, Exclusive_Transfers, Multi_Copy_Atomicity.
  - **APB versions.**
    - APB2, APB3 and APB4 (IHI0024C §1.2.1–§1.2.3).
    - PSLVERR is optional and valid only in the last ACCESS cycle; an erroring write may still have changed the register (§3.4).
    - APB has two independent data buses, yet cannot use both at once (§2.1.1).
  - **Coherent protocols: what changes in verification.**
    - ACE adds snoop channels AC, CR and CD (§C1.3.2), plus RACK and WACK (§C1.3.3).
    - ACE-Lite has no snoop channels (§C11.1).
    - CHI uses layered packets with credits (IHI0050, sections unverified).
    - The plan gains coherency checking, snoop stimulus, cache-state scoreboards and system-level tests. VIP availability is tool-dependent.
  - **Verification cost and build vs buy.** Engineering practice; label it as such.
  - **Interview angles.** Attempt-first; see the Assessment plan.

**`## Quick Take`**
- **What it is:** AMBA is Arm's family of on-chip interface specifications: APB, AHB, AXI (with AXI4-Lite and AXI4-Stream), ACE and CHI.
- **Why it matters:** the protocol a block uses fixes its area, latency and concurrency, and also the testbench you build: the agent, the checker rules, the scoreboard's ordering model and the coverage.
- **The Analogy:** standard plugs and sockets. Any block with the right socket plugs into the interconnect, and a bridge is an adapter. *Where it breaks:* a socket standard only fixes the shape. AMBA also fixes timing, handshakes and ordering, which a bridge must translate, not just rewire (B-AMBA-F1).
- **You will be able to:** the four objectives below.

**`## Build Your Mental Model`**
1. `### Why standard interfaces, and what an interconnect does`
   - The problem: about n² custom links for n blocks.
   - The solution: one interface definition (IHI0022E §A1.3.2: master–interconnect, slave–interconnect, master–slave).
   - What the interconnect does:
     - decodes addresses;
     - arbitrates between masters;
     - routes responses back, extending IDs (§A5.3.5);
     - returns DECERR for unmapped addresses (§A3.4.4);
     - bridges to other protocols.
   - Interconnect topologies are a design choice (§A1.3.2). This fixes L32-AMBA1-04.
   - VIP reuse: one agent per protocol, reused active on every block with that interface and passive on interconnect ports.

2. `### A handshake you can run`: this unit, an **Expected output** block labelled "by inspection; no simulator run", then two "break it" steps.

```systemverilog
// compile
// One VALID/READY channel, the handshake every AXI channel uses
// (IHI0022E A3.2.1). The source raises VALID without looking at READY and
// holds VALID and data until the transfer. The receiver's READY pattern is a
// free choice. Both ends are modelled in one process with nonblocking
// updates, so there is no DUT and no race; B-AXI-1 drives a real DUT.
module tb_top;
  timeunit 1ns;
  timeprecision 1ps;

  localparam logic [8:1] READY_AT = 8'b1110_1100; // READY at edges 3, 4, 6, 7, 8
  localparam int unsigned N_ITEMS  = 3;

  logic        clk   = 1'b0;
  logic        valid = 1'b1;   // item 0 is offered from time 0
  logic        ready = 1'b0;   // receiver's choice for edge 1
  logic [7:0]  data  = 8'hA0;
  int unsigned k     = 0;      // index of the current rising edge
  int unsigned sent  = 0;      // items transferred so far

  always #5 clk = ~clk;

  always @(posedge clk) begin
    k++;
    if (valid && ready) begin  // handshake at edge k
      $display("edge %0d: transfer of 8'h%h", k, data);
      sent++;
      if (sent < N_ITEMS) data  <= data + 8'h01;  // next item; VALID stays 1
      else                valid <= 1'b0;
    end
    // The receiver picks READY for edge k+1 without looking at VALID.
    ready <= (k < 8) ? READY_AT[k + 1] : 1'b1;
    if (k == 9) $finish;
  end

  // Hold rule: a stalled VALID stays high with the same data (A3.2.1).
  a_hold: assert property (@(posedge clk) valid && !ready |=> valid && $stable(data))
    else $error("VALID dropped or data changed before the transfer");
endmodule
```

```text
edge 3: transfer of 8'ha0
edge 4: transfer of 8'ha1
edge 6: transfer of 8'ha2
```

   "Break it" steps:
   - **(a) Deadlock.** Start with `valid = 1'b0`. Make the source raise VALID only after seeing READY: `if (!valid && ready && sent < N_ITEMS) valid <= 1'b1;`. Make the receiver wait for VALID: `ready <= valid;`. Add `final if (sent == 0) $error("no transfer: VALID waited for READY while READY waited for VALID");`. Expected: no transfer lines, then that error. This is the §A3.3.1 deadlock in one channel.
   - **(b) Dropped VALID.** Add `if (!ready) valid <= 1'b0;` to the source. Expected: `a_hold` fails at edge 2, the edge after the first stall.

   Trace of the original unit:
   - edges 1–2: READY low, D0 held;
   - edge 3: transfer of A0;
   - edge 4: transfer of A1;
   - edge 5: READY low, A2 held;
   - edge 6: transfer of A2; VALID falls;
   - edge 9: `$finish`.

3. `### How to read any AMBA waveform with the hooks`
   1. Find the clock edges where VALID && READY: those are the transfers.
   2. Between them, check that VALID and its payload hold.
   3. Mark the AW, W(LAST), B and AR, R handshakes.
   4. Check B after AW and WLAST, and R after AR.
   5. On AHB, find HREADY-low edges and remember that both the current data phase and the next address phase are held.
