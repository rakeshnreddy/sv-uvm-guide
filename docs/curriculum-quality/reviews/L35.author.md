I then fetched the IHI0022E PDF from Arm's own documentation service (`documentation-service.arm.com/static/5f915b62f86e16515cdc3b1c`; the title page reads "ARM IHI 0022E (ID033013)"), extracted its text in the scratchpad, and confirmed these quotes verbatim in it:
  - §A3.2.1: "A source is not permitted to wait until READY is asserted before asserting VALID"; "If READY is asserted, it is permitted to deassert READY before VALID is asserted"; "there must be no combinatorial paths between input and output signals" (also §A3.1.1).
  - §A3.1.2: "deassertion must be synchronous with a rising edge of ACLK"; earliest VALID "is at a rising ACLK edge after ARESETn is HIGH".
  - §A3.3.1: "To prevent a deadlock situation"; "the slave must wait for AWVALID, AWREADY, WVALID, and WREADY to be asserted before asserting" BVALID; the arrow definitions ("single-headed arrows point to signals that can be asserted before or after…").
  - §A3.3: "the write data can appear at an interface before the write address".
  - §A3.2.2: "forces the transfer to take at least two cycles"; RVALID "only in response to a request for data".
  - §A1.3.3: "a register slice can be inserted at almost any point in any channel".
  - §A3.3.2: "Any AXI3 master complies with the AXI4 write response requirements".
  - §A3.4.4: "the required number of data transfers must be performed".
  - §A5.4.1: "All write data must be in the same order as the associated write addresses".
