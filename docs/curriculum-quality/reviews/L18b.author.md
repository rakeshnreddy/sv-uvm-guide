## Corrections made in the verification pass

The resumed run checked the inherited page clause by clause and changed these points:

1. **`c_read40` did not write its `output` on the X/Z path**, against the page's own §35.5.1.2 rule. It now writes `*value = 0` first.
2. **Context property wording.** "The property belongs to each call, not to the chain" contradicted §35.5.3 ("adheres to the calling chain, not to an individual imported subroutine"). It was rewritten: each import call takes its own import's property, the property is never promoted, and the same C function can run in context and non-context chains.
3. **Exports outside a call chain.** The page said "such as a C thread" for the simulator-defined case. §35.5.3's example is a VPI callback. The page now says so, and the expert item says a C thread of your own is not covered at all.
4. **Exported-task return value.** "1 if the calling thread was disabled" was made precise: 1 when it returns because a disable stopped the import's thread. A new expert note covers the §35.9 corner case: a disable that targets the export itself returns 0 and does not disable the import.
5. **Disabled imported functions.** The expert item presented "an export it calls can disable a block that encloses the call" as a technique. §9.6.2 makes a disable inside a function of a block or task that called it undefined. The page now says to code defensively for that path, not design for it.
6. **Outputs after a disable** are undefined (§35.9). This was missing from the core disable section; it is added.
7. **"No C thread ever runs beside the simulator"** became "DPI never runs your C code alongside SystemVerilog", so it no longer contradicts the C-threads item.
8. **UVM bridge.** The package-level export is now called from a context import "declared in the same package" (the same-scope rule of §35.5.3). This is in the expert bullet and in the interview playground.
9. **Explorer instructions** now use the control labels (`bit [7:0]`, `logic [31:0]`, "output / inout").
10. **Bug-run log.** The "(at 45 ns)" annotations looked like printed text. A `<error at 45 ns>` placeholder now stands in for the tool-specific prefix, which §20.10 says includes file, line, scope and time.
11. **New pitfall row**: a returned or output string that points at C stack memory (H.8.10).
12. **Small additions:** `s_vpi_vecval` encoding cited as Figure 38-8 (§38.15); `disable`/`disable fork` cited (§9.6.2, §9.6.3) and added to References; the H.9.4 example's `function integer` result added to the standard-contradiction note (H.7.3, §35.5.5); debug answer 1 no longer refers to call values the item does not give.
13. **Card `isv7-3`**: "a VPI routine" became "a VPI routine that reads or writes the design", citing H.9.5. The print and file routines are exempt from `context`.

Verified as correct and kept: the worked-example timing, the kata predictions (`t=65 polls=2`; timeout at 58 ns, no error), every CRC value, all uvm-core and Verilator claims, the explorer's nine scenarios, and every clause number on the page.
