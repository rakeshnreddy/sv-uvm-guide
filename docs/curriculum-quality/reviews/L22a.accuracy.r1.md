## Lab `config-debug`: traced by hand

- **Starter.** `tb_top` sets `vif` (`virtual my_if`, scope `uvm_test_top.env.agt.*`, 1000) and `num_pkts` (`int unsigned`, scope `uvm_test_top.env.agt`, 1000). The test's `build_phase` sets `num_pkts = 6` at `uvm_test_top.env.agt.*` (999). The agent gets 4, since only the `tb_top` entry matches its own path, prints `[AGT] num_pkts=4`, and creates `drv` and `mon`. `drv` builds first (name order); its `#(virtual my_if.driver_mp)` get misses → `UVM_FATAL [NO_VIF]` from `uvm_test_top.env.agt.drv`. This matches README Step 1.
- **Fix 1.** `mon` misses on field `mon_vif` (type and scope match) → `NO_VIF` from `mon`. Matches Step 2.
- **Fix 2.** Build completes. `find_unused_resources` returns only the test's `num_pkts` → `CFGNRD`. The driver drives 4 (edges 5…35 ns), the monitor counts 4 (15…45 ns), and `done` is set at 55 ns → `[CHK] expected 6 transfers, monitor saw 4`. Matches Step 3 and `lab.json` step 3.
- **Fix 3.** Both entries reach the agent, and 1000 (`tb_top`) beats 999 → still 4, with the test's entry unread → `CFGNRD`. Matches Step 4's prediction.
- **Fix 4.** num_pkts = 6: six `[DRV]` lines, monitor 6 (15…65 ns), `done` at 75 ns, PASS, no `CFGNRD`. Matches Step 5 and `lab.json` step 5.
- README question 3 is correct: a set in the test's constructor gets 1000, sits in a different context pool, and is more recent, so `PRI_HIGH` puts it in front and it wins the tie.
- `lab.json` assets match the files on disk; `src/dv/solution.sv` is gone and nothing references it. Both `testbench.sv` files compile by inspection, with `+incdir+.` as in the Makefile.
