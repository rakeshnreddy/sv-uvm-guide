### L03-VIS-02 · S3 · `index.mdx:94`
- **Problem.** The sublabel of the dynamic-array answer, `int lane_errs [] = new[n_lanes]`, is a declaration initializer.
  - In a static scope, such as the module-level `tb_top` every example on this page uses, it runs before any `initial` procedure (IEEE 1800-2023 §6.8).
  - A lane count read at run time (a plusarg read in `initial`) is therefore not known yet. The array is sized with `n_lanes`'s initial value (0), and every later `lane_errs[lane] = v` is silently ignored (§7.4.5).
  - The node sits on exactly that path: "Count fixed at compile?" no. The matrix at `:111` and flashcard f2b-3 use the statement form instead.
- **Fix.** Write the sublabel as a statement: `lane_errs = new[n_lanes]`.
- **Sources checked.** IEEE 1800-2023 §6.8: "Setting the initial value of a static variable as part of the variable declaration … shall occur before any initial or always procedures are started". Also A.2.4 (`variable_decl_assignment … = dynamic_array_new`) and §7.4.5.

### L03-VIS-03 · S4 · `index.mdx:685-695` (tracker SVG, step-7 rows)
- **Problem.** The SVG's colours and glyphs disagree with the site's encodings.
  - The matched key 2 has the same rose dashed outline and strike-through as the mismatched key 1, although its note says "✓ B1 matched". Rose is the site's mismatch/error encoding.
  - ▲ marks "still pending" here, but in the visual language ▲ means "value just changed".
  - The text labels carry the meaning, so no cue is colour-only.
- **Fix.**
  - Draw deleted keys with a neutral dashed outline (`stroke="currentColor" strokeOpacity="0.4"`), and keep rose only on key 1's mismatch note.
  - Mark the pending item with a word or a glyph other than ▲.
- **Source checked.** `docs/visual-learning/visual-language.md` §2 (Match / mismatch: emerald / rose with ✓ / ✕; Value just changed: ▲).
