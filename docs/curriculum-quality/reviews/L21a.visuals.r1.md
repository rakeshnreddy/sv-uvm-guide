## Findings

### S3

1. **S3 · index.mdx:70 · The caption describes the vif links as dashed, but they are drawn solid.** The caption says "The dashed vif links show which interface instance each driver and monitor uses". The vif edges use `style: "structural"`, which the kit draws as a thin solid line with no arrow. The only dashed edge in the picture is `start(sqr)` (`causal`). A learner looking for dashed vif links finds the wrong edge.
   *Fix:* change the caption to "The thin plain lines labelled vif show which interface instance each driver and monitor uses", or say "lines" without a style.
   *Source:* `BlockDiagram.tsx:125-128` (`structural: { width: 1.2 }`, `causal: { dash: "6 4" }`); `visual-language.md` §9 edge styles.

2. **S3 · index.mdx:74, 76, 77, 83 (and 120) · Container class names never render, so the picture cannot show "one `bus_agent` class appears twice".** The `sublabel`s `bus_test`, `bus_env`, `bus_agent` (twice) and `module` are on container nodes. The kit draws a container as "TAG · label" only and drops the sublabel. The first debrief bullet (l.120) says "One `bus_agent` class appears twice", but nothing in the drawing says so. Rendered output confirmed this.
   *Fix (lesson):* put the type in the container label, for example `label: "in_agt : bus_agent"`, `"out_agt : bus_agent"`, `"uvm_test_top : bus_test"`, `"env : bus_env"`. *Or (lead):* have `BlockDiagram` render container sublabels after the label.
   *Source:* `BlockDiagram.tsx:278-282` (container branch); `diagram-layout.ts:13-27`.

3. **S3 · index.mdx:326 (caption l.320) · `in_if.data` at edge 0 is z but is drawn as X.** The caption explains that the value is z and is "drawn as unknown". The kit has a high-Z rendering (a dashed amber mid-level line, value `"z"`), so the picture can show the real value. Showing z next to x also previews the z-versus-x distinction that "Expert: one interface type on both sides of the DUT" depends on.
   *Fix:* `values: ["z", "10", "10", "20", "20"]` for `in_if.data`. Caption: "in_if.data has not been driven yet (z, drawn as a dashed mid-level line); out_if.data holds no valid byte yet (x, hatched)."
   *Source:* `CycleWaveform.tsx:82-83` (`isHighZ`), `:198-200`; IEEE 1800-2023 §14.16 (the clocking-block driver of a net starts at `'z`); `bus_if` declares `wire data` (index.mdx:487).

4. **S3 · index.mdx:68-116 · The full-bench diagram cannot be read at 390 px.** The layout is 992 px wide. `ArchitectureDiagram` passes `minWidth = Math.min(width, 360)`, so on a phone the SVG shrinks to about 360 px, a scale of about 0.36. The 11.5 px node labels become about 4 px, and the 9 px port labels about 3 px. README §Visuals requires "readable at 390 px". The caption and the three bullets carry the meaning, so this is not S2, but this is the lesson's main structural picture.
   *Fix (lead, kit):* let wide diagrams scroll instead of shrinking, for example `minWidth = Math.min(width, 640)`; the wrapper already has `overflow-x-auto`. *Lesson (optional):* `gapX` 96 → 72 saves about 70 px, which does not fix it alone.
   *Source:* `DiagramKit.tsx:51-58`; `BlockDiagram.tsx:247-248`; layout re-run: width 992.

### S4

5. **S4 · index.mdx:76-77, 83, 95, 98, 100 · Labels collide in the rendered diagram.** Rendered and inspected:
   - (a) `in_agt`'s top border runs through the "ENV · env" label. The kit adds a 12 px margin per nesting depth, but each container label needs 18 px.
   - (b) The `cov` port label "analysis_export" overlaps the node label "cov". Port labels are drawn inside the node, at mid-height for side ports.
   - (c) The `out_agt.ap` label "ap" runs into `out_mon`'s "MON" tag and is crossed by `out_mon`'s border. `in_agt.ap`'s "ap" is crossed by `in_mon`'s border.

   *Fix (lesson):* set `at: 0.6` on `in_agt.ap` and `out_agt.ap`, so the port and its label sit in the gap between the two rows (y about 344). For `cov.imp`, use `at: 0.85` (label below "cov", above nothing) or put the port on `side: "top"`. *(a) is a kit fix (lead):* add `CONTAINER_LABEL` clearance per nesting depth in `layoutGridDiagram`. The kit doc's own env/agent example has the same clash.
   *Source:* `diagram-layout.ts:69-70, 120-126`; `BlockDiagram.tsx:278-282, 360-366`; node geometry: env y=180, label baseline y=196; in_agt y=192.

6. **S4 · index.mdx:318-329 · `out_if.ready` is not drawn.** The learner is told that a monitor publishes where `valid` and `ready` are both 1. For `out_agt`'s markers at edges 2 and 4, the picture shows only `valid`. The tie-off `assign out_if.ready = 1'b1` (l.825) is not mentioned in the caption.
   *Fix:* add `{ name: "out_if.ready", kind: "bit", values: [1, 1, 1, 1, 1] }`, or add "out_if.ready is tied to 1 in tb_top" to the caption.
   *Source:* index.mdx:619, 825.

7. **S4 · index.mdx:324-328 · Signal names run into the first waveform cell.** The kit's name column is 76 px with the text starting at x=6. At 11 px monospace, "out_if.valid" (12 characters, about 79 px) and "in_if.valid", "in_if.ready" and "out_if.data" (11 characters, about 73 px) overlap the edge-0 cell, including the hatched X of `out_if.data`.
   *Fix (lead, kit):* size `LABEL_W` from the longest name. The names must stay equal to the code, so the lesson cannot shorten them.
   *Source:* `CycleWaveform.tsx:59, 183-185`.

8. **S4 · index.mdx:103 · The edge label `start(sqr)` abbreviates the call.** The code calls `seq.start(env.in_agt.sqr)` (l.797). The section claims "Every name in the picture below is the name used in the code" (l.66).
   *Fix:* `label: "seq.start(env.in_agt.sqr)"`, or `"start(in_agt.sqr)"`. The longer label fits in the 92 px row gap at 10 px.
   *Source:* index.mdx:66, 797.

9. **S4 · index.mdx:439 · "create env (env creates out_agt)" places out_agt's creation inside the test's build_phase.** `out_agt` is created later, in `env.build_phase`, after the test's `build_phase` returns. That ordering (top-down build) is exactly what the caption relies on.
   *Fix:* `{ kind: "self", from: "test", label: "create env" }`, then `{ kind: "divider", label: "env.build_phase creates out_agt; then out_agt.build_phase runs" }` in place of the current divider.
   *Source:* index.mdx:371-377, 780-786; I-UVM-1C (build is top-down).

10. **S4 · index.mdx:1046 · Non-descriptive link text, and the exercise is linked twice.** "([open it](/exercises/uvm-agent-builder))" reads as "open it" in a screen reader's link list. The same exercise is linked again at l.1276, and the route's practice panel lists it a third time.
    *Fix:* drop the inline "(open it)" link (l.1276 has a descriptive one), or make the link text "UVM Agent Builder".
    *Source:* WCAG 2.2 SC 2.4.4 (link purpose in context).

11. **S4 · lead (kit) · The ArchitectureDiagram legend omits the dotted `control` style.** The `get_next_item` edge (l.104) uses that style. The legend lists only data flow and causal.
    *Fix (lead):* add "··· control / pull" to the legend in `BlockDiagram.tsx`.
    *Source:* `BlockDiagram.tsx:128, 409-416`.
