    - `pmu_drv` and `pmu_mon` see the acknowledge at edge 4.
    - The `a_iso_before_off` pass at edge 1 is right: `$past(cpu_iso_en)` is the value at edge 0, which is 1, because ISO_ON was driven at 175 ns.
  - **"Isolation released before the restore" waveform (:428-446).** I replayed the order PWR_ON, RST, CLK_ON, ISO_OFF, RESTORE through `pmu_drv::do_op`, with edge 0 at 365 ns.
    - `cpu_rst_n` is sampled 0 at edges 1-2, and `reset_seen` reads 1 from edge 2.
    - `cpu_clk_en` reads 1 from edge 4, `cpu_iso_en` reads 0 from edge 5, `cpu_restore` reads 1 at edge 6 and `restored` reads 1 from edge 7.
    - So `a_release_after_wake` fails at edge 5, as the marker says. Every row matches.
  - **Scoreboard trace table (:250-261), Expected output (:1393-1419), "Prove it can fail" (:1430-1440) and the Kata 1 log (:1678-1683).** Each one agrees with my trace, including these times:

    - the end at 625 ns.
