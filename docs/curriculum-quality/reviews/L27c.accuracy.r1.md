## Make It Work trace (checked by hand)

I traced each step through the uvm-core source, using the bench's clocking-block timing: the drive lands at edge+1 ns, the DUT acts and the monitor samples at the next edge, and the driver waits one idle cycle before `item_done`. Results:
- Step 1: CTRL `F`/`F`. Step 2: mirror `ffffffff`, DUT `f`. Step 3: returns 3, mirror 3, DUT 0. Step 4: mirror 0, DUT 0. Step 5: 0/0. Step 6: passes.
- The monitor sees 2 transfers.
- No warnings: every `do_predict` is a READ or WRITE kind, so the busy warning is never reached, and the predictor's own messages are only `uvm_info`.
- The first deposit happens at a clock edge, but the RTL assigns nothing at that edge (`sel` = 0, no hardware events), so there is no race.

Kata 2's log, traced with `configure(null, "")`, also matches line for line: the item keeps the written value through the empty backdoor read, and `peek` returns the item's initial value 0.

All signatures are real: `poke`/`peek` with `.parent()`, `write`/`read`/`mirror` arguments, `uvm_reg_field::configure`, `create_map`, `add_reg`, `uvm_reg_predictor #(reg_item)`, `get_registers`, `get_full_hdl_path`, `uvm_hdl_check_path`, and `paths[p].slices[s].path`.
