## Findings

### F1 (S3): passive checking has no picture of its own
- **Where:** explicit-vs-implicit.mdx:208-224.
- **Problem:** Objective 5 (passive checking with `set_check_on_read(1)`) is a core concept, and quiz Q8 tests its key mechanism: check-on-read compares the observed read with the *old* mirror, then predicts. The concept has no picture that shows this.
  - The wiring diagram (:117-147) shows the active set-up, where the register model drives `sqr`/`drv`.
  - The predictor SequenceDiagram (:161-186) traces a write. Its check-on-read step is only a "reads only … if enabled" self-call.
  - The author's own completeness table credits the passive concept with "Architecture diagram applies (monitor path only)".
- **Fix:** add a small traced table, or a second SequenceDiagram, for "firmware reads STATUS after hardware set BUSY, passive predictor, check-on-read on":
  - steps: `bus_in.write(tr)` → `bus2reg` → `get_reg_by_offset` → `do_check(mirror, read data)` → `pre_predict` → `do_predict(item, UVM_PREDICT_READ)`;
  - one row or note each for `volatile = 0` (RegModel mismatch, a false failure) and `volatile = 1` (masked out of the valid bit mask, still predicted).

  A one-line caption that tells the learner to read step 6 of the predictor diagram as the passive check is the minimum.
- **Source checked:** uvm-core 2020.3.1 `uvm_reg_predictor.svh` `write()` (check-on-read before `pre_predict`/`do_predict`); README §Visuals ("every core concept has an accurate picture").

### F2 (S3): the wiring diagram has the adapter sending items to the sequencer
- **Where:** explicit-vs-implicit.mdx:139.
- **Problem:** The edge `adp → sqr` "item (set_sequencer)" tells the learner that the adapter sends items to the sequencer. In uvm-core the map does it: it calls `adapter.reg2bus()` and then `start_item`/`finish_item` on the sequencer given to `set_sequencer()` (`uvm_reg_map.svh:1958-1975`). The adapter only converts. The page's own implicit SequenceDiagram (:82-84) shows this correctly, so the two pictures disagree.
- **Fix:** draw the item edge from `ral` (whose sublabel already names `default_map`) to `sqr`, labelled "map starts item (set_sequencer)". Keep `ral`–`adp` as "map: reg2bus / bus2reg".
- **Source checked:** `uvm_reg_map.svh` `do_bus_write`/`do_bus_read`; visual-language.md §9 accuracy rule.

### F3 (S4): the `get_next_item` arrow points the wrong way
- **Where:** explicit-vs-implicit.mdx:140.
- **Problem:** The edge `sqr → drv` is labelled `get_next_item`, but the driver is the caller (`drv.seq_item_port` → `sqr.seq_item_export`, connected at :525). The kit's own example draws it from driver to sequencer.
- **Fix:** reverse it to `{ from: "drv", to: "sqr", style: "control", label: "get_next_item" }`, or relabel it "item (driver pulls)".
- **Source checked:** Make It Work `rbus_agent::connect_phase`; visual-language.md §9 example.

### F4 (S4): the `write(tr)` line runs through the agent's label
- **Where:** explicit-vs-implicit.mdx:134-135, 143.
- **Problem:** In the rendered layout, the vertical `mon.ap` → `pred.bus_in` line crosses the "AGT · agent (rbus_agent)" container label. `mon` sits in column 0, where the container label is drawn, and both ports default to `at: 0.5`.
- **Fix:** add `at: 0.75` to both ports. The line stays straight and clears the label.
- **Source checked:** `layoutGridDiagram` output rendered with `BlockDiagram` (scratch render).

### F5 (S4): the visualizer's names differ from the page's code
- **Where:** explicit-vs-implicit.mdx:196-198.
- **Problem:** The visual labels its nodes `ral.CTRL`/`ral.GPIO`, `apb_agent` and "DUT registers". The rest of the page uses `ral.ctrl`, `rbus_agent` and `rdut`. The prompt correctly says `ral.CTRL.get_mirrored_value()`, but a learner moving between the visual and the bench sees two naming schemes without being told why.
- **Fix:** add one sentence to the introduction: "The visual uses upper-case register names and a generic APB agent; its CTRL and GPIO behave like the Make It Work bench's `ctrl` and `gpio`."
- **Source checked:** `RALPredictorVisualizer.tsx:95-103`; `src/lib/ral-model.ts:1312-1316`.

### F6 (S4): the recap list relies on symbols
- **Where:** explicit-vs-implicit.mdx:328-333.
- **Problem:** The recap list encodes yes/no with the glyphs ✓ and ✕. They are not colour-only, but screen readers announce them as "check mark" and "multiplication x", which reads badly ("implicit multiplication x").
- **Fix:** write "implicit: yes · explicit: yes", or keep the glyphs with `aria-hidden` and add the words.
- **Source checked:** README rules for pictures (accessible text equivalent).
