**Accuracy fixes this run made to the interrupted draft.**
- **`->>` and processes woken by an NBA update.** The draft said such a process "still misses" a `->>` trigger. Per §4.5 the NBA events move to the Active region together and run in any order (§4.7), so that process races with the trigger. The callout now says so; Kata 1 solution 3 and flashcard `isv5-ev-4` no longer claim the opposite.
- **Merging.** The draft hinted that a stranded waiter could wake if the old object kept another name. §15.5.5.1 says it "shall never unblock"; the sentence now states the rule without an exception.
- **Zero-delay loops.** The draft said some simulators stop such a loop with an iteration-limit message. A `wait` whose condition is true does not block (§9.4.3), so the loop never returns to the scheduler. The note is now tool-neutral and labelled tool-dependent.
