## Findings

### 1. S3, references: the GoldMine author list is wrong (carried from the 2026-10-11 notes, unfixed)
- **Where:** `index.mdx:138` and `index.mdx:970`.
- **Problem:** The page credits GoldMine to "Sheridan, Liu and Vasudevan" and "D. Sheridan, L. Liu and S. Vasudevan". The DATE 2010 paper is by S. Vasudevan, D. Sheridan, S. Patel, D. Tcheng, W. Tuohy and D. Johnson, pp. 626-629. L. Liu co-authored later GoldMine papers, not this one.
- **Fix:**
  - Line 138: "GoldMine (Vasudevan et al., DATE 2010)".
  - Line 970: "S. Vasudevan, D. Sheridan, S. Patel, D. Tcheng, W. Tuohy and D. Johnson, 'GoldMine: Automatic Assertion Generation Using Data Mining and Static Analysis', DATE 2010, pp. 626-629."
- **Source:** Crossref record for DOI 10.1109/DATE.2010.5457129 (fetched 2026-10-18).

### 2. S3, accuracy: invented plusargs are not caught by the compiler
- **Where:** `index.mdx:160`, also `index.mdx:637`.
- **Problem:** Line 160 says "Only item 8 is caught by the compiler", and item 8 (line 158) includes plusargs. How-to step 2 says compiling "catches invented APIs". But an invented plusarg compiles and runs silently: `$test$plusargs` and `$value$plusargs` just return zero when nothing matches, and a plusarg nobody reads is ignored. The page itself names "a plusarg nothing reads" as a hallucination at line 147.
- **Fix:** At line 160: "The compiler catches invented methods, macros and system functions (unless the name exists and is misused). An invented plusarg compiles and is silently ignored, so check the code that reads it." Narrow step 2 in the same way.
- **Source:** IEEE 1800-2023 §21.6.

### 3. S3, accuracy: the alternatives to `starting_phase` fail silently in the stated scenario
- **Where:** `index.mdx:912`.
- **Problem:** The solution says "use `get_starting_phase()` with a null check, or `set_automatic_phase_objection(1)`", directly after stating that the test calls `seq.start(sqr)`. In that scenario both raise nothing:
  - `start()` never sets the starting phase;
  - `m_safe_raise_starting_phase` returns quietly when `get_starting_phase()` is null.

  A learner who takes the "automatic" option swaps a loud null access for a phase that can end with no objection. The closing "Here, simply raise and drop in the test" is correct.
- **Fix:** After the two alternatives, add: "Both work only when the sequence has a starting phase: it runs as a default sequence, or the test calls `seq.set_starting_phase(phase)` before `start()`. Otherwise nothing is raised."
- **Source:** uvm-core 2020.3.1 `uvm_sequence_base.svh:301-420` (`start`) and `:701-720`; `uvm_sequencer_base.svh:1472`; IEEE 1800.2-2020 §14.2.4.2 and §14.2.4.4.

### 4. S3, accuracy: the width trap holds only for a power-of-two depth (carried, unfixed)
- **Where:** `index.mdx:189`.
- **Problem:** "If `fifo_count` is declared with `$clog2(MAX_DEPTH)` bits, it cannot represent `MAX_DEPTH`, and `fifo_count <= MAX_DEPTH` can never fail." This is true only when MAX_DEPTH is a power of two. For MAX_DEPTH = 5, `$clog2(5)` = 3 bits, which hold up to 7, so the check can fail.
- **Fix:** "If MAX_DEPTH is a power of two (as in most FIFOs) and `fifo_count` has `$clog2(MAX_DEPTH)` bits, …".
- **Source:** IEEE 1800-2023 §20.8.1; arithmetic.

### 5. S4, precision: the reason not to put `$past` in `disable iff` is incomplete
- **Where:** `index.mdx:908`.
- **Problem:** "Do not put `$past` in the `disable iff` condition: it uses current values." The LRM's rule is that a sampled value function in a disable condition "shall be explicitly clocked" (§16.9.3), and the disable condition itself is not sampled. As written, the reason reads as if `$past` returned current values.
- **Fix:** Use the wording `sva-model.ts` already uses: "the disable condition uses current values, and a sampled value function in it needs an explicit clocking event; put the guard in the antecedent, where sampled values apply."
- **Source:** IEEE 1800-2023 §16.9.3; `src/lib/sva-model.ts:1781`.

### 6. S4, labelling: what a null-handle call does is tool-dependent
- **Where:** `index.mdx:824` (Q8 option feedback), `index.mdx:827`, `index.mdx:912`.
- **Problem:** The page says the `starting_phase.raise_objection(this)` call "is a null-handle access and the simulation stops with an error". `raise_objection` is virtual. The LRM makes a virtual call through a null handle illegal, with an indeterminate result, and implementations *may* issue an error. Every mainstream simulator stops with a null-object error, but the page states this as a rule. The Q8 key is unaffected: this option does not skip randomization in any case.
- **Fix:** Write "a null-handle access (illegal per IEEE 1800-2023 §8.4; simulators stop with a null-object error)".
- **Source:** IEEE 1800-2023 §8.4; uvm-core 2020.3.1 `uvm_phase.svh:312`.

### 7. S4, completeness of a worked solution: review item 3's spec has a second clause no property checks
- **Where:** `index.mdx:864` and `index.mdx:908`.
- **Problem:** The spec says "q is d delayed by one cycle; q is 0 while rst is 1". The fixed property is disabled while `rst` is 1, so the second clause goes unchecked, and the solution does not say so. The solution's other statements are correct.
- **Fix:** Add one line, "The reset clause needs its own check, for example `rst |=> q == 0` without the `disable iff`". Or drop the clause from the spec, to match `sva-model.ts:1759`.
- **Source:** IEEE 1800-2023 §16.12 (`disable iff`), §16.12.7.
