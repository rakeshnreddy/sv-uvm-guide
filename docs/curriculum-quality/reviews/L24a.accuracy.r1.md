## Findings

### S3

1. **S3 `layered-sequences.mdx:710` (also :757, Q8 feedback :850, card iuvm3b-layer-12).** The reset procedure says to call `stop_sequences()` on both sequencers and restart, but omits the lower driver. `uvm_sequencer::stop_sequences()` flushes `eth_agt.sqr`'s request FIFO (`uvm_sequencer.svh:177-187`); if `eth_agt.drv` is mid-frame and later calls `item_done()` for it, `item_done()`'s `m_req_fifo.try_get` fails and the run stops with `UVM_FATAL [SQRBADITMDN]` (`uvm_sequencer.svh:319-325`). A learner following the expert item literally with a driver like the page's loopback driver hits that fatal.
   **Fix:** add one sentence to the expert item (and optionally to the interview feedback): "The lower driver must also react to reset: abandon the frame it holds without calling `item_done()` (for example, kill its drive thread on reset), because `stop_sequences()` has already removed that request and a late `item_done()` gives `UVM_FATAL [SQRBADITMDN]`."
   **Source:** uvm-core 2020.3.1 `uvm_sequencer.svh:177-187`, :315-336; IEEE 1800.2-2020 §15.3.2.14.

### S4

2. **S4 `layered-sequences.mdx:558`.** Comment `// never returns: body() is a forever loop`. In this unit `phase_ready_to_end()` calls `xlate.kill()`; `m_kill()`/`m_killed()` set `UVM_STOPPED` and `start()` then completes its post-join path and returns after a `#0` (`uvm_sequence_base.svh:428-475`, :965-987). So `start()` does return at the end of the test.
   **Fix:** `// returns only when kill() stops it: body() is a forever loop`.
   **Source:** uvm-core 2020.3.1 `uvm_sequence_base.svh` `start()`, `m_kill()`, `m_killed()`.

3. **S4 `layered-sequences.mdx:677` (drill 1).** The drill quotes "`Default timeout of … hit`" and then suggests `uvm_root::get().set_timeout(1us)` to shorten the wait. With a non-default timeout uvm-core prints "`Explicit timeout of … hit, indicating a probable testbench issue`" (`$time == UVM_DEFAULT_TIMEOUT` selects "Default", otherwise "Explicit"). A learner who shortens the wait and searches for "Default timeout" will not find it.
   **Fix:** after the parenthetical, add "(the message then reads `Explicit timeout of …`)".
   **Source:** uvm-core 2020.3.1 `uvm_phase_hopper.svh:556-590`.
