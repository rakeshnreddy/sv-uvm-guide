## Findings

### F1 (S3): quiz Q10 stem gives a fresh object an unaligned address

- **Where:** `controlling-randomization.mdx:755`
- **Problem:** The stem reads "right after new(), while addr is still 1, a test calls item.addr.rand_mode(0)". `bus_item` (the class this quiz refers to) has no constructor, and a `bit [15:0]` property starts at 0. Right after `new()`, `addr` is therefore 0, which is aligned. Freezing it then would make every call succeed, not fail. The stem asserts the value 1, so the key is consistent with the stem, but the stem suggests that `new()` leaves `addr` at 1, which is wrong.
- **Fix:** Reword the stem as "After a test sets item.addr = 1 (or an earlier error-injection call left addr unaligned), it calls item.addr.rand_mode(0). The class has c_align: addr[1:0] == 0. From then on every randomize() call returns 0. Why?" Keep the key and the distractors.
- **Source:** IEEE 1800-2023 §6.8 Table 6-7 (the default initial value of a 2-state variable is 0); §8.7 (no constructor means default initialization); page :374 (`bus_item` has no `new`).

### F2 (S4): prose expression parses differently in SystemVerilog

- **Where:** `controlling-randomization.mdx:78`
- **Problem:** The page writes "`c_align` would require `16'h0001 & 3 == 0`". In SystemVerilog, `==` binds tighter than `&`, so the code-formatted expression parses as `16'h0001 & (3 == 0)`. It still evaluates false, but it models an expression that a learner might copy.
- **Fix:** "`c_align` would require `addr[1:0] == 2'b00` with `addr[1:0]` equal to `2'b01`, which is false", or write `(16'h0001 & 3) == 0`.
- **Source:** IEEE 1800-2023 §11.3.2, Table 11-2 (operator precedence).

### F3 (S4): IQP feedback says "Legal only if"

- **Where:** `controlling-randomization.mdx:642`
- **Problem:** The IQP 2 option-2 feedback says "Legal only if chk is a rand variable…". The constraint `chk == payload.xor()` is legal whether `chk` is `rand` or not. What changes is its effect, and the rest of the sentence explains that correctly.
- **Fix:** "Computes the checksum only if chk is a rand variable…".
- **Source:** IEEE 1800-2023 §18.5.8 (state variables are constants in the solve); §18.3.
