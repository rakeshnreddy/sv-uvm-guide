Source: spine §5.5 (answer must not be guessable); `src/components/ui/Quiz.tsx` (no shuffle).

2. **S3 explicit-vs-implicit.mdx:1039 (with :346, :260, :266, :752) - Kata 1's worked solution gives the wrong reason for step 4, and the page describes step 4 inconsistently.** The solution says "Step 4 reports nothing because ERR is volatile", but step 4 of the bench never calls `mirror(UVM_CHECK)`: it calls `env.ral.int_status.read(st, rd)` (L752), and with check-on-read off a `read()` checks nothing, volatile or not. L346 also says the test checks the mirror "after each [change] with `mirror(UVM_CHECK)`", and the traced table (L260 "as in the Make It Work example") uses `ral.int_status.mirror(st, UVM_CHECK)` at step 2, which the bench does not do. A junior comparing the three learns the wrong reason for "no error". **Fix (either):** (a) make step 4 call `check_reg(env.ral.int_status, "4 after MODE=3")` instead of the first `read()`, so volatility is what prevents the error, matching L266 and the kata (update Expected output L799-800 and the table row L818); or (b) keep the code and change L346 to "checks steps 1-3 with `mirror(UVM_CHECK)` and step 4 with a plain `read()`", L1039 to "Step 4 reports nothing because it uses `read()`, which checks nothing while check-on-read is off; ERR's volatility would also keep a `mirror(UVM_CHECK)` quiet", and L260 to "a variant of the Make It Work example". Source: page code L749-757; uvm-core `uvm_reg::do_read` (check only in the auto-predict branch with check-on-read on), `uvm_reg::mirror`.

3. **S3 explicit-vs-implicit.mdx:811-819, :1034 - Kata 1 asks the learner to predict a table they have already read.** The per-mode result table is printed in full in Make It Work with no predict-first prompt; the kata then says "cover it and predict". Source: README §Visuals (predict, then debrief); spine §5.8.
