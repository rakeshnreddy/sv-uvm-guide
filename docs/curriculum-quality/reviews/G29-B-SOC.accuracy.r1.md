| 1 | **S2** | soc-coherency-verification (`:481` code; the answer's data invariant at `:483`) | The snippet says it runs "after each snoop response". Its check `if (dirty == 0 && memory != golden)` then fails on the flow the specification recommends by default. Take a ReadShared snoop to a line in UD, answered PassDirty=1, IsShared=1, so the snooped cache moves to SC. Until the initiator's read completes and it moves to SD/UD, no cache is Dirty, but memory is still stale, so the checker raises a false "memory is stale" error. ReadClean behaves the same way: with PassDirty=1, responsibility passes to the interconnect, which writes the line back "immediately", but that write has not finished at the time of the snoop response. The answer says to check what is permitted, yet this code flags a permitted transient. A related problem: if `data[c]` comes from white-box probes, a UD owner's local stores never appear on the bus, so a golden model updated only from bus traffic falsely flags the owner. | Treat dirty responsibility that is in transit as an owner. That covers a PassDirty=1 response until the initiator's R with PassDirty completes, and the interconnect's write-back until it completes. Alternatively, run the memory check only when the line is quiescent (no coherent transaction, snoop, WriteBack/WriteClean or interconnect memory update outstanding). Word the invariant as "if no cache and no in-flight transaction holds dirty responsibility, memory holds the latest value". Update the golden copy from the same probes as `data[c]`, or compare a UD/SD owner's data only when it is passed or written back. | IHI0022E C1.2.3 (cache state rules; "When clean, the cache does not have responsibility for updating main memory"); C5.3.2 ReadClean and ReadShared text and Table C5-8; C4.3 (PassDirty moves the initiator's line to Dirty only when its read completes) |

## Checked and correct (no change needed)

- **soc-address-map-decode.** The DECERR quote and the default-slave recommendation are exact (A3.4.4). The 4KB note is exact (A3.4.1). AxPROT[1]=1 is Non-secure (Table A4-6). The AHB 1KB region and the Default Subordinate ERROR/OKAY behaviour are correct (IHI0033C §4.2, §4.2.1). The boundary-address table matches the given map.
- **soc-firmware-tb-sync.** The `wait_trigger` and `wait_on` quotes match 10.1.1.2.4 and 10.1.1.2.2 exactly. The `wait_ptrigger` follow-up is consistent with 10.1.1.2.5 (same time slice only). The `get_global`/`get` create-on-miss behaviour matches 10.4.1.2.3 and 10.4.1.2.4. The isolated `fork begin ... join_any; disable fork; end join` is legal and correct (§9.6.3).
- **soc-lost-response-liveness.** The trace reads correctly: AW at edge 2, the last W at edge 3, and `##[1:8]` spans edges 4 to 11, so the bounded assertion fails at edge 11. "Weak in `assert property`" matches the §16.12.2 text. `s_eventually` is §16.12.13.
- **soc-interconnect-id-mismatch.** The trace is self-consistent (0x13 = port 1 above ID 0x3). The A5.3.5 quote is exact. The A5.3.1 interconnect rule and the A5.3.2 "forwards the write data in address order" quote are exact.
- **soc-ral-firmware-prediction**, apart from #6. `get` and `get_mirrored_value`, auto-predict, the predictor quote (§19.3), `map` (§19.3.2.3) and "memories are not mirrored" (§18.6) are all exact.
- **soc-reset-boot-sequencing.** The A3.1.2 reset rules are exact. `reset(string kind = "HARD")` matches §18.4.4.5.
- **soc-interrupt-basics.** The W1C definition matches §18.5.4.6 k).
- **soc-cdc-rdc-verification.** The synchronizer and `$onehot0` Gray-code assertion are legal (§20.9, §16.9.3), and the synchronizer structures are labelled as practice.
- **soc-coherency-verification**, apart from #1. The five states and the MOESI mapping, the cache state rules (C1.2.3) and the Table C5-8 UD end states (I 1/0, SC 1/1, SD 0/1) are right. So are the C5.2.3 options (PassDirty low and IsShared high, or delay) and the C4.10.3 lost-line rule. The exclusive-sequence rule matches the C5.3.2 text, and the C4.2 snoop-filter broadcast requirement is right.
- **soc-security-verification.** The AxPROT bit encoding (Table A4-6) is correct.
- **soc-performance-qos.** The A8.1.1 quote and the 0b0000 meaning are exact. The monitor snippet is legal: `time ar_time[id_t][$]` is an associative array of queues. Little's law is labelled as practice.
- **soc-pss-hw-sw-coverification.** All six PSS 3.0 section titles match. The version and date were verified on accellera.org.
- **soc-signoff-strategy-review**, **soc-block-to-system** (§13.3 quote, §18.2.3.5, §23.11), **soc-emulation-strategy** (SCE-MI marked unverified) and **soc-integration-only-bugs**: no accuracy issues.
