## Hand trace of Make It Work (re-done independently)

- **Clock and reset.** `clk` starts at 0, so rising edges are at 5, 15, 25 ns and so on. `rst_n` rises at the negedge at 20 ns.
- **The time-0 drive.** The driver's `drv_cb.valid <= 0` at time 0 is not on a clocking event, so it takes effect at the next one, 5 ns (§14.16, "as if they had executed at the time of the next clocking event").
- **Item 1.** `get_next_item` returns at 20 ns. `@drv_cb` waits to 25 ns, and the item is driven in Re-NBA at 25 ns. At 35 ns `ready` is sampled as 1 and the item is accepted. The DUT registers 11.
- **Why item 2 waits a clock.** `item_done` and the next `get_next_item` take zero time inside 35 ns. The drv_cb event for 35 ns has already fired, so the next drive is at 45 ns.
- **Results.** Accepts are at 35, 55, 75 and 95 ns. Outputs are sampled at 45, 65, 85 and 105 ns as 11, 21, 80 and 00. `compared == 4` at 105 ns.
- **Report order.** `report_phase` runs bottom-up with children in name order, so `cov` reports before `scb`.
- **Coverage.** The outputs hit all three bins, giving 100.0%.
- **Topology listing.**
  - Type names: `uvm_sequencer`, `uvm_seq_item_pull_port`, `uvm_seq_item_pull_imp`, `uvm_analysis_export`, `uvm_analysis_imp_exp`/`_act` and the `analysis_imp` instance name all match the sources.
  - Order: children print in name order (`get_first_child`/`get_next_child`).
  - Root row: the `<unnamed>` row comes from `print(printer)` on the root, which has an empty name.
  - Hidden children: `req_fifo` and `sqr_rsp_analysis_fifo` have `print_enabled = 0`, so they are correctly absent.
- **"Prove the checks can fail."**
  - Removing `super.build_phase` leaves `is_active` at `UVM_ACTIVE`.
  - The guarded connect runs, so `DRVCONNECT` stays silent.
  - On the net, the clocking driver at 0 and the DUT at 1 resolve to X (§14.16, §14.16.2).
  - The monitor's `=== 1'b1` never matches, so `compared` stays 0 and the run ends with `PH_TIMEOUT`.
- **Kata 2.** Trace, fix and message (`item 2: expected 80, got 7f`) are all correct. Quiz Q6, Q8 and Q9-Q11 agree with the trace.
- **Language legality.**
  - A variable on a clocking output may not also be continuously driven (§14.16.2 last sentence), and a DUT output port implies such a driver (§23.3.3.2). So the `wire` choice in `bus_if` is required, and the comment at 478-482 is right.
  - §8.20 argument names: `write(bus_item t)` keeps the name `t`.
  - Waiting on a class property (`wait (env.scb.compared == ...)`) is legal under §9.4.2.
