## Findings

### F1 (S3) index.mdx:641: the edge-1 attempts in the worked example are disabled, not enabled

**Problem.** The page says: "`rst_n` is released by a nonblocking write at edge 1, so the attempts at edge 1 are already enabled (they sample `valid` = 0 and succeed vacuously)." This is wrong for this bench.
- The `initial` block resumes from `@(bus.drv_cb)`. That is a clocking block event, which "shall be triggered in the Observed region". A process waiting on it runs "in the first Active region after the Observed region" (§14.10).
- So `rst_n <= 1'b1` (line 617) updates rst_n only after the edge-1 attempts have started in Observed with `rst_n` = 0.
- Those attempts are therefore disabled (§16.12: "between the start of the attempt in the Observed region, inclusive…").

This applies the page's correct flop-release rule (line 364) to a case where it does not hold, and a reader may generalize the error. The expected output is unaffected.

**Fix.** Rewrite the Reset bullet: "Every attempt at edges 0 and 1 is disabled. The `initial` block resumes from `@(bus.drv_cb)`, a clocking-block event triggered in the Observed region (§14.10), so its write to `rst_n` lands after the edge-1 attempts have started with `rst_n` = 0. The first enabled attempts are at edge 2." The line 616 comment ("edges 0 and 1 in reset") is already consistent with this. Alternatively, release with `@(posedge clk) rst_n <= 1'b1;`, which resumes in Active before Observed and so behaves like a flop release, and keep the sentence.

**Source.** IEEE 1800-2023 §14.10, §14.13, §16.12.

### F2 (S3) index.mdx:803: Q1 distractor B can also stop the false report

**Problem.** Option B is "Replace it with `assert property ($onehot(sel))` inside the always_comb". Its feedback says no clock can be inferred, "with a default clocking the check would run only at clock ticks". But §16.14.6.2 uses this very pattern (a procedural concurrent assertion in `always_comb` with `default clocking`) as its example of how flushing avoids glitch reports. So, with a default clocking, B also stops the false failure, as a different, clock-sampled check. The key (deferred) is still the best answer, but the feedback reason is incomplete.

**Fix.** Either state in the stem that the module has no default clocking, or reword B's feedback. For example: "With no default clocking this is an error: always_comb has no event control, so no clock can be inferred (§16.14.6). With one, the check is flushed on re-runs and then judged only at clock ticks on sampled values (§16.14.6.2). That is a different rule from 'sel is one-hot whenever it settles'."

**Source.** §16.14.6, §16.14.6.2.

### F3 (S4) index.mdx:890, deck isv4a-10: "its success count … include[s] those"

**Problem.** §16.14.3 lists "Number of times succeeded" and "Number of times succeeded because of vacuity" as separate counters. It does not say that the first includes the second. The pass-statement half of the claim is right ("executed once for each successful evaluation attempt", and §20.11 runs pass actions on vacuous success by default).

**Fix.** At line 890, write "its pass statement runs on those (§16.14.3, §20.11), and its counts mix in vacuous successes, so a nonzero count proves nothing". In isv4a-10, write "runs its pass statement on those successes".

**Source.** §16.14.3, §20.11.

### F4 (S4) index.mdx:322: "disable iff (1'b0) is the only way to cancel the default"

**Problem.** §16.15 says only that an explicit `disable iff` overrides the default. "The only way" is stronger than the text. Any explicit clause whose condition is never true has the same effect.

**Fix.** "an explicit `disable iff (1'b0)` cancels the default for one assertion."

**Source.** §16.15.
