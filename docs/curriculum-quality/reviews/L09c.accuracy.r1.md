## Claim-by-claim verification (all correct unless listed under Findings)

- §8.12: a new object of the source's class is allocated; no constructor runs and no declaration initializer runs (step 1, verbatim). Every property is copied, including randomization state (RNG, `constraint_mode`, `rand_mode`, `randc`) (step 2). An embedded covergroup's handle is null in the copy (step 2 and the NOTE). The typed-constructor ban is in the text ("It shall be illegal to use a typed constructor call for a shallow copy"). The deep-copy convention `p2.copy(p1)` also matches the text.
- Syntax 8-2 footnote 23: "the expression shall evaluate to an object handle". `class_new` appears only in a blocking assignment or a variable declaration assignment, so `c = new tmpl; sent.push_back(c);` is the right form.
- §7.6: a queue-of-values assignment copies the elements. Rule 5 (a queue of handles gets a new container holding the same handles) follows from that.
- §8.6: "The lifetime of methods declared as part of a class type shall be automatic". So `packet c = new;` builds a new object on every call.
- §8.20: overrides need matching argument types, identical names, qualifiers and directions. The return type may be a derived class type. `:extends` implies virtual and is an error when nothing is overridden. `:final` stops further overrides. The syntax `virtual function :extends void copy(...)` matches Example 3.
- §8.18: "a local method or class property of the same class can be referenced, even if it is in a different instance".
- §8.19: an instance constant is assigned once, in the constructor.
- §11.4.5: `==` is legal when one operand is assignment compatible with the other, and it "compares the values of the class handles".
- §6.24.2: as a task, a failing `$cast` is a run-time error and the destination is left unchanged; as a function it returns 0 and never errors.
- §18.14.3 and §18.15: each object has its own RNG, seeded from the creating thread when the object is created.
- §20.10: `$fatal` terminates with an implicit `$finish`.
- uvm-core 2020.3.1: `clone()` is virtual, calls `create(get_name())` and then `tmp.copy(this)`. `copy()` is non-virtual: it does the null check with `` `uvm_error("OBJ/COPY",...) `` and returns, picks `get_default_copier()` when no copier is passed, flushes at active depth 0, then calls `m_copier.copy_object(this, rhs)`. `copy_object` checks `UVM_COPY_POLICY` and `UVM_COPY_NULL_OBJ`, sets `m_recur_states` to STARTED, calls `lhs.do_execute_op`, then `lhs.do_copy(rhs)` if the user hook is enabled, then sets FINISHED. The UVM SequenceDiagram (:392-412) matches this order and these argument roles. The `` `uvm_fatal `` inside an `if` (:429) is legal because the macro expands to a `begin`/`end` block.
