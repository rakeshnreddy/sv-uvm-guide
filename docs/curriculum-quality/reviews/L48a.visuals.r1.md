## Findings

### F1 — S3 — index.mdx:439-451 — riscv-formal has no picture
**Problem.** riscv-formal (half of objective 5) is the only core concept without a picture: the checks table and engine table carry facts, not a structure or a trace the learner uses. The analyst proposed a harness ArchitectureDiagram (L48.md:447); the author deferred it to avoid unused names.
**Fix.** Either (a) a small ArchitectureDiagram: `core wrapper (RVFI outputs)` (dut) → `check: insn / reg / causal / liveness ...` (scoreboard) inside a `SymbiYosys, mode bmc, depth N` container, with a `checks.cfg` → `genchecks.py` edge; names already appear on the page in lines 439-449, so nothing new is introduced; or (b) reuse the RVFI TimingDiagram: add a `highlights={[{ from: 0, to: 7, tone: "info", label: "bmc explores every input sequence inside this window from reset" }]}` and a predict asking whether the illustrative `a_add_effects` property holds at edge 4 (`0x108`, `pc_wdata == pc_rdata + 4`).
**Source.** README "Visuals" and R5; L48.md:447; `procedure.rst` (mode, `[depth]`) as cited on the page.

### F2 — S3 — index.mdx:156 — flow diagram feeds the ISS trace into the lock-step compare
**Problem.** Edge `isssim -> cmp` is labelled "ISS trace", and the target node's sublabel is "post-run or lock-step". In lock-step the ISS runs inside the RTL simulation via DPI (diagram 1, the SequenceDiagram and `rv_cosim_scb` all show this); it does not read `iss_sim`'s trace. The diagram blurs the post-run/lock-step distinction the page is built on.
**Fix.** Relabel the edge "ISS trace (post-run only)" and add to the caption: "In lock-step the ISS is not run by iss_sim; the scoreboard steps it through DPI inside the RTL simulation." Alternatively split `cmp` into `post-run compare` (fed by the trace) and `lock-step scoreboard` (sublabel "ISS via DPI").
**Source.** Page lines 312, 355, 645; Ibex `cosim.rst` as cited on the page.

### F3 — S3 — index.mdx:139 — generator node carries the SEQ role tag
**Problem.** Node `gen` has `kind: "sequence"`, so the kit draws a `SEQ` tag, but its sublabel `riscv_instr_base_test` is the `gen_test`, a UVM test (testlist table, line 172). The role tag contradicts the code.
**Fix.** `kind: "test"` (draws `TEST`) or `kind: "generic"`.
**Source.** `BlockDiagram.tsx` role tags (`sequence: "SEQ"`, `test: "TEST"`); page line 172; riscv-dv `yaml/base_testlist.yaml` (`gen_test: riscv_instr_base_test`).

### F4 — S4 — index.mdx:114 — memory edge points one way for loads and stores
**Problem.** `mem -> core` labelled "fetch, load, store" is a single data arrow into the core; store data flows core → memory.
**Fix.** Label it "fetch, load data" and add `{ from: "core", to: "mem", style: "data", label: "store" }` (the layout has room), or use `style: "structural"` (no arrowhead).
**Source.** Kit edge styles (visual-language.md §9).

### F5 — S4 — index.mdx:386-392 vs 365, 703-704 — step arguments named three ways
**Problem.** The SequenceDiagram writes `riscv_cosim_step(rd_addr, rd_wdata, pc, trap, suppress)`, the DPI table writes `sync_trap, suppress_reg_write`, the code passes `t.trap, t.rf_wr_suppress`. The diagram also omits `set_debug_req`, `set_nmi`, `set_nmi_int`, which the code calls before `set_mip`, without saying so.
**Fix.** Use the code's names in the diagram (`trap, rf_wr_suppress`) and add to the caption "(set_debug_req, set_nmi and set_nmi_int, called first, are omitted)".
**Source.** visual-language.md §9 accuracy rule ("must match the code on the page").

### F6 — S4 — index.mdx:426 — `rvfi_order` starts at 10 without explanation
**Problem.** The program table and the compare number `0x100` as retirement #0, but the TimingDiagram shows `rvfi_order` 10 at `0x100`. Correct if boot code ran first, but unexplained.
**Fix.** Add to the caption: "rvfi_order starts at 10 because ten boot instructions retired before 0x100; it counts from reset."
**Source.** `rvfi.rst` (`rvfi_order` is the instruction index), as quoted on line 411.

### F7 — S4 — index.mdx:114-118 — edge labels wider than the column gap
**Problem.** "fetch, load, store", "interrupt lines" and "set_mip, then step" render as 100–120 px label boxes on a 64 px gap, so their backgrounds cover the node borders (and come within about 5 px of the `rv_cosim_scb` label).
**Fix.** Pass `gapX={110}` to this ArchitectureDiagram, or shorten the labels ("fetch/load", "irq", "set_mip; step").
**Source.** `BlockDiagram.tsx` label width `length * 6.2 + 8`; layout default `gapX = 64`.

### F8 — S4 — index.mdx:369-371 — SequenceDiagram has no prediction prompt
**Problem.** The diagram is introduced and debriefed, but the learner is not asked to predict before seeing the failing half.
**Fix.** Before the diagram: "*Predict:* if the scoreboard skips `set_mip`, which PC does the ISS expect at the step for the handler's first instruction?" The lower half is then the answer.
**Source.** spine §5.3 Visuals; README R5.
