## Changes in the resumed pass

1. **Pictures readable at 390 px.** Figures 1 and 2 and the VisualRecap picture used 9–9.5-unit text in a 320–360-unit viewBox, about 8 px on a phone, and in figure 1 the `put(1)` and "next key" labels touched the boxes. 2. **Accuracy and precision.**
   - The debug-mode debrief said `new(2)` "lets two senders onto the bus at once". In the model's run it does not: the run ends without a hang but one key short (1 of 2), which is what the learner sees. The debrief now says that, and keeps the general point.
   - `final` procedures at a quiet end: the draft called this tool-dependent. §9.2.3 runs final procedures before any end-of-simulation callback, and §38.36.3 defines the end of simulation as an empty event queue or `$finish`. The page now says a `final` check also reports on a run that stopped quietly, which also makes it consistent with `events.mdx`.
   - A leaked key makes every later `get()` wait only for a one-key lock; the page now says so. The wait-for rule "a loop means deadlock" now holds for one-key semaphores, with a pointer to the counting-semaphore caveat.
   - Quiz Q4 said the test stops "with no error" while its own code prints `$error`; the stem now matches the code.
   - The get(2) prompt said A "returns" keys it never took; it now says A calls `put(1)`.
   - Smaller wording fixes: `new()` (the bench stalls unless someone calls `put()` first, not "forever"), the source of the "no owner" rule (§15.3.2 sets no check), Q6's feedback (hand-off policy as well as process order), and Kata 1's summary line (computes `FAIL` instead of printing a constant).
3. **Expert layer.** "Keys survive a kill" now shows uvm-core's cure as well as the `UVM/REG/ZOMBIE` symptom: `uvm_reg::reset()` restores the key with a clamp, and `uvm_reg_block::reset()` reaches every register. "Deadlock conditions" now cites Coffman, Elphick and Shoshani (1971) and adds that with counting semaphores a loop in the wait-for graph is necessary but not sufficient for deadlock.
4. **Visual use.** The semaphore-game debrief now names the one behaviour that is the model's choice (a new `get(1)` passing an older `get(2)`; X21). The debug debrief links the lab.
5. **Navigation.** References gained a **Prerequisites:** line (spine §5.9), matching what `<BeforeYouStart />` renders (Mailboxes, F2C, I-SV-1) plus the module overview for `process` handles. The duplicate F2C entry left Related. "Killed while holding" now links the module overview.
6. **Lab blurb.** L17a rebuilt `ipc-deadlock` into two parts (Part 1 a leaked key, Part 2 a circular wait, ending `PASS=2 FAIL=0`). The page's description now matches it.
7. **Deck.** Code in backticks (spine §5.6, as in the sibling `I-SV-5_Events` deck); "the usual fix" replaces "the standard fix", which could be read as "the IEEE standard's fix"; two new cards: the wait-for graph (`isv5-sem-13`) and who returns a credit (`isv5-sem-14`).
