## Findings

### S2

**S2-1. The key is always option 1: 17 of 17 graded items.**
- **Where:** `index.mdx:993-1126` (quiz keys at `:998, :1009, :1020, :1031, :1042, :1053, :1064, :1075, :1086, :1097, :1108, :1119`) and `index.mdx:932-985` (interview keys at `:936, :947, :958, :969, :980`).
- **Problem.**
  - `Quiz.tsx` renders the options in the authored order (`src/components/ui/Quiz.tsx:89`, `:182`), and so does `InterviewQuestionPlayground.tsx` (`:31-40`, `:97`). Neither shuffles.
  - On this page the right answer is therefore always the first button. The pattern shows after two questions. From then on, the quiz no longer tests objectives 1–5, the misconception distractors are never weighed, and the "answer before you open the feedback" design of the interview angles is defeated.
  - A second cue: Q10's key (122 characters) and Q11's key (125) are far longer than their distractors (37–89).
  - The other rewritten W1 pages vary the key position (F1A, F1B, F1C, F2C, F2E, F3A, F3B), so this is not the program norm.
- **Fix.**
  - Reorder the answer objects so the keys spread evenly, for example Q1–Q12 → positions 2, 4, 1, 3, 3, 1, 4, 2, 4, 2, 3, 1, and the five playgrounds → 3, 1, 4, 2, 2. Keep each `correct`/`isCorrect` flag on its option. Explanations and feedback need no change, because none refers to a position.
  - Shorten the Q10 and Q11 keys, or lengthen one distractor in each, so that length does not cue the key.
  - No spec pins these options: `grep` over `tests/` finds no F2B quiz or playground text.
- **Sources checked:** spine §5.5 ("the answer must not be guessable…"; the per-option `correct` flag exists so that "reordering options cannot break the key"); README rubric R6; the two renderers named above; scratch parse of all T1 quizzes.

### S3

**S3-1. The core path uses `ref` and "outdated reference" before either is defined.**
- **Where:** `index.mdx:199` ("references to the old elements are outdated… a task holding an element by `ref`"), `:253`, `:261` ("a `ref` to the element 20 stays valid") and `:328` ("being passed to a `ref` argument").
- **Problem.**
  - `ref` is first defined at `:534`, in the practitioner layer, and "outdated reference" at `:888`, in Push Further.
  - A junior on the core path meets the term four times with no gloss, against README quality requirement 4 ("Define every term before using it") and plan §1.2 ("The core path reads cleanly on its own").
- **Fix.** Add one sentence to the "Reading the code" NOTE at `:34`. For example: "A `ref` argument passes the variable itself rather than a copy (taught below and in F2D); a reference becomes *outdated* when its element is removed or the array is reallocated." Alternatively, move the `:253`/`:261` reference remarks into "Expert: Stale references and hidden copies".
- **Sources checked:** README "Quality requirements" 4; plan.md §1.2 "Depth ladder on every page".

**S3-2. Objective 4's sparse-memory half is shown but never practised.**
- **Where:** `index.mdx:24` (objective 4: "**Write** a sparse memory model and an expected-transaction tracker").
- **Problem.**
  - The memory model appears only as given code (`:370-380`, `:707`, `:734-737`).
  - The how-to (`:802-809`) and the checklist (`:826-834`) cover only the tracker.
  - The kata leaves the memory out explicitly (`:1157`).

- **Fix.** Add one how-to step ("model memory as `mem[bit [31:0]]`; read through `exists()` so that an unwritten address returns x quietly") and one kata extension (write `mem_write`/`mem_read`, then show that an unwritten read returns `'x` with no warning while `num()` counts only written addresses). - **Sources checked:** spine §5.4 "Coverage"; spine F2B card, objective 3 and hands-on; IEEE 1800-2023 §7.8.6, §7.9.1, §7.9.3.

**S3-3. The debug table has no row for the plain queue's classic silent bug.**
- **Where:** `index.mdx:815-824`.
- **Problem.**
  - `pop_front()` on an empty queue returns the Table 7-1 value and only *may* warn (`:210`; §7.10.2.4).
  - In an in-order checker that pops an expected queue of 2-state data without checking `size()` first, an unexpected response with data 0 passes, and the log may show nothing.
  - This is the M0 bug that F2E's expected-value queue is exposed to. The table covers the missing-key version (row 2) but not the queue version, so the queue concept's checklist item 8 (debugging) is only partly met. The kata's checker A guards against it in code (`:1178`), but the page never names the bug.
- **Fix.** Add a row:
  - **Symptom:** "A response passes although nothing was expected".
  - **Cause:** "`pop_front()` on an empty queue returned 0 (§7.10.2.4)".
  - **Fix:** "check `size()` before popping and report UNEXPECTED".
  - **Log:** "Nothing, or an optional warning".
  - Optionally, add the case to the debug challenge.
- **Sources checked:** IEEE 1800-2023 §7.10.2.4, §7.10.2.5 (LRM text: the return value is the Table 7-1 value; the call "may cause a warning to be issued"); README checklist item 8.

### S4

- **S4-2. `index.mdx:518-526`: "Predict each row, then check it" shows the answers in the same table.** **Fix:** put the values in a `<details>` block, as the slice exercise does (`:226-240`).

  - **Fix:** extend the NOTE at `:34` by one sentence (`do…while`, `void'`, `output`), and move the §4.7 interleaving clause to Push Further, or gloss it as "the order in which waiting processes resume is not fixed".
  - *Source:* README quality requirement 4.
- **S4-4. `index.mdx:134` uses "Table 7-1" before `:139` defines it.** **Fix:** move the definition paragraph above the debrief list, or define the table at its first use.

The five angles (`:932-985`) cover choice, associative order, reductions, `ref` and memory. **Optional fix:** add a sixth playground, for example "A FIFO model lost its oldest entry after an urgent `push_front`.
