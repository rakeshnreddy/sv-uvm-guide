## Findings

### S3

1. **`index.mdx:160`, edges at `:152-153`: `iss_sim` writes ISS logs, not trace CSVs.**
   - **Problem.**
     - The text says `iss_sim` "writes trace CSV files", and both edges out of `iss_sim` are labelled "trace CSV".
     - In fact `iss_sim` writes one commit log per ISS and test (`run.py` `iss_sim`: `{iss}_sim/{test}_{i}.log`). `iss_cmp` converts the two logs to CSV and compares them (`compare_iss_log` → `process_spike_sim_log` → `compare_trace_csv`), and returns without comparing unless exactly two ISSes were given.
     - The `cov` flow also starts from the ISS log directory (`cov --dir out/spike_sim`). It "parses the instruction trace log and converts it to a CSV trace format" (`coverage_model.rst`).
     - This finding was open in the 2026-10-11 notes.
   - **Fix.** Write "`iss_sim` runs the ELF on each ISS and writes its log; `iss_cmp` (with exactly two ISSes) converts both logs to trace CSVs and compares them; `cov` converts the logs and samples coverage". Relabel the two edges "ISS log".
   - **Source.** riscv-dv `run.py` (`iss_sim`, `iss_cmp`, `compare_iss_log`); `docs/source/coverage_model.rst`.

2. **`index.mdx:349` (and card `e-riscv-1-9`): the description of `instr_trace_compare.py` misses its own blind spots.**
   - **Problem.**
     - "Counts leftover register-writing entries as mismatches" is true for the **second** CSV only. The in-order loop breaks as soon as trace 2 is exhausted (`if trace_2_index == len(instr_trace_2): break`), so extra entries in trace 1 are never examined. That is the "extra retirement" case this lesson teaches.
     - The script also skips register writes that leave the register's value unchanged, not only instructions that write no register: `check_update_gpr` returns 0 when `rd_val` equals the tracked value, or when a first write is 0.
     - This finding was open in the 2026-10-11 notes.
   - **Fix.** Write "it compares only register writes that change a register's value, never compares stores directly, and counts leftover entries in the second trace only; extra entries in the first trace pass unnoticed". Card 9 can add "and only writes that change a value".
   - **Source.** riscv-dv `scripts/instr_trace_compare.py` (`compare_trace_csv`, `check_update_gpr`).

3. **`index.mdx:174`, `:212` and `:903` (Q4 feedback): `iterations` does not give each program its own seed.**
   - **Problem.**
     - The page says `iterations` is "how many programs to generate, each with its own seed", and that `iterations: 2` gives "two programs, two seeds".
     - With the default `--batch_size 0`, `run.py` makes one generator run per test, with a single seed (`seed_gen.get(test_id, 0)`) and `+num_of_tests=<iterations>`. `riscv_instr_base_test` then generates the programs one after another in that one simulation.
     - A program can therefore be reproduced only by re-running the whole batch. Only `--batch_size`/`-bz` splits the programs into runs with separate seeds, one per batch.
   - **Fix.** Write "`iterations`: how many programs to generate. By default all are generated in one generator run with one seed; `--batch_size` splits them into runs with separate seeds." Change Q4's feedback to "iterations is the number of programs to generate".
   - **Source.** riscv-dv `run.py` `do_simulate` (batch and seed logic), `parse_args` (`-bz/--batch_size`, default 0), `SeedGen.get`; `test/riscv_instr_base_test.sv` `run_phase` loop over `cfg.num_of_tests`.

4. **`index.mdx:180`: `asm_tests` is not the key `run.py` reads.**
   - **Problem.**
     - The table copies the testlist header's spelling, `asm_tests`.
     - `run.py` tests `if 'asm_test' in t` and reads `test_entry.get('asm_test')`; C tests use `c_test`. The examples in `configuration.rst` also use `asm_test:`.
     - An entry written with `asm_tests:` and no `gen_test` is not treated as a directed test. It falls through to the generator path, which needs `gen_test`. On a page whose must-cover item is "verified tool facts only", this is the same class of error as an invented key.
   - **Fix.** Write `asm_test` (and add `c_test`), noting that the header comment spells them in the plural but `run.py` reads the singular.
   - **Source.** riscv-dv `run.py` (directed-test split in `main`; `asm_directed_list` handling); `docs/source/configuration.rst` ("You can also add directed assembly/C test in the testlist"); `target/rv32imc/testlist.yaml` header.

5. **`index.mdx:970` (Q10 distractor feedback), and the list at `:252`: `rd_val` does exist in CGF on riscv-isac's default branch.**
   - **Problem.**
     - The feedback says "There is no rd_val variable in CGF; val_comb uses rs1_val, rs2_val, imm_val and ea_align."
     - That holds only for the old `master` branch (last commit 2023-07-27). The archived repository's default branch `dev` (last commit 2024-11-04) adds `rd_val` to the documented `val_comb` variables in `cgf.rst` ("The value (as of the end of previous instruction) in the register specified in the *rd* field"), along with `mode`, `mnemonic` and others. `InstructionObject.py` evaluates `rd_val`.
     - The analysis (RV-05) and the verification both read `master`, so the error came in through them.
     - The answer key is unaffected. The distractor is still wrong, but for a different reason: no CGF condition can count an instruction that is missing from the trace.
   - **Fix.**
     - Change the feedback to "No val_comb condition can count an instruction the trace never logged; the gap comes from the trace source, not from the CGF."
     - At line 252, write "`val_comb` uses value variables such as `rs1_val`, `rs2_val`, `imm_val` and `ea_align`", or name the branch the list was taken from.
   - **Source.** riscv-isac `docs/source/cgf.rst` on `dev` vs `master`; `riscv_isac/InstructionObject.py` (`dev`); GitHub API (`default_branch: dev`, `archived: true`).

    - **Fix.** Prefix the list with "(after `riscv_cosim_set_iside_error`, when a fetch error is queued for this instruction)", and write "a separate thread notifies every data-side access; separate threads track fetch bus errors, which are notified just before the faulting instruction's step".
