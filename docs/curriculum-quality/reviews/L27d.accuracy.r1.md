## Spot checks that passed

- **Make It Work, by inspection.** It compiles: the field `configure` argument order, `uvm_reg::new(name, 32, UVM_NO_COVERAGE)`, `create_map(name, 'h0, 4, UVM_LITTLE_ENDIAN)`, the adapter signatures `reg2bus(const ref uvm_reg_bus_op)` and `bus2reg(uvm_sequence_item, ref uvm_reg_bus_op)`, the clocking-block drives and samples, and `provides_responses = 0` with the read data written into `req` before `item_done()`.
- **Expected-output timing.** Reset releases at 25 ns, so the first access runs 35→45 and each access takes 20 ns. The "Verifying" lines therefore fall at 0, 45 and 65, bit-bash starts at 85, and VERSION starts at 85 + 128×20 = 2645. These all match the page.
- **Reset-test masks.** `do_check` skips `UVM_NO_CHECK` and `WO*` fields, which gives CTRL `'h1f`, VERSION `'hff` and BOOT `'hff00`. Kata step 1 gives `'hff03`, `read=2'h2 mirrored=2'h0` and exactly one error. The message formats match `do_check_error`.
- **Bit-bash counts.** CTRL is 32 bits × 4 = 128 accesses. Unmodelled bits are tested and expected to read 0. A read-only VERSION.ID passes, because `set()` leaves an RO field's desired value unchanged. With PINS set to `UVM_NO_CHECK`, BOOT has 30 testable bits, so 30 × 4 = 120 accesses.
- **Memory-walk trace.** The trace matches `uvm_mem_single_walk_seq`: 3n − 1 accesses, which is 11 for 4 words. The walk skips silently when the access is not `"RW"`.
- **Exclusion rules.** These match the source: existence is tested with `!= null`, the resource must be of type `bit`, field level applies only to `NO_REG_HW_RESET_TEST` in the reset test, `uvm_config_db` with `this` adds the `uvm_test_top.` prefix, and the glob metacharacters `* ? +` follow Table F.1. The traced exclusion table is correct row by row.
- **`uvm_reg_mem_built_in_seq`.** The fixed order, the model-level checks, the `START_SEQ`/`FINISH_SEQ` IDs and the `UVM_DO_*` values (1, 2, 4, 8, 16, 32) all match the source.
- **Flashcards.** All 16 cards are accurate. Card 16 is labelled correctly: uvm-core predicts in `poke`/`peek`/backdoor `write`, while §18.4.4.9 leaves the mirror update to auto-prediction.
- **Registers appear in creation order.** This is correct: `regs[int unsigned]` is keyed by `get_inst_id()`.
