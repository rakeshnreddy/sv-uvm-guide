## Findings

### S3

**S3-1** `immediate-vs-concurrent.mdx:687` — The page authors its own `### Reinforce the essentials` heading. The layout's practice slot (`src/lib/curriculum/remark-practice-slot.ts`, `lesson-mdx.ts:19-20`) also inserts an H3 "Reinforce the essentials" with the fixed id `reinforce-the-essentials` at the end of Practice & Reinforce. The learner sees two headings with the same text back to back, the "On this page" list shows it twice, and the DOM has two elements with id `reinforce-the-essentials`. `lesson-orientation.spec.ts:99` requires each TOC anchor id to occur exactly once, so this page would fail that check if it were added to the walked set. **Fix:** rename the authored heading to `### Flashcards` and point down to the deck ("The deck follows below, under 'Reinforce the essentials'"), as `I-UVM-3B/sequence-libraries.mdx:792-794` does. Or drop the heading and move the sentence into the quiz intro. (Source: `remark-practice-slot.ts:1-13, 93-106`; `lesson-orientation.spec.ts:92-100`.)

**S3-2** `immediate-vs-concurrent.mdx:19` with Q2 and Q3 (`:563-584`) — Objective 2 has two parts: predict *how many reports* each kind prints, and *in which scheduling region* each report is printed. Q2 tests only the count. Q3 tests concurrent timing (when and which values), not regions. No quiz item asks for a region (Active vs Reactive vs Postponed). The region part appears only in the checklist (`:454`) and in card 5. **Fix:** add a predict item on the 20 ns case of the four-kinds bench: "In which region does each of `a_simple`, `a_obs`, `a_fin` print?" Key: Active, Reactive, Postponed. Distractors: "all in Active" (deferral delays nothing), "`a_obs` in Observed" (confuses maturing with reporting), "`a_fin` in the final procedure at end of simulation" (see S3-4). Or extend Q2 to ask for both. (Source: README target lesson §6, plan §4 item 5; IEEE 1800-2023 §16.4.1.)

**S3-3** `immediate-vs-concurrent.mdx:20`, `:280-287` — Objective 3 says "write legal action blocks *for each kind* with severity tasks (`$fatal`, `$error`, `$warning`, `$info`)". Q4 and Q5 test only deferred action-block legality, and Q6 tests placement. No quiz item tests choosing a severity task, nor the action-block rules for the simple or concurrent kinds. Severity is drilled only by card 11. **Fix:** add one item, for example "A corrupted reference model makes every later compare meaningless. Which fail statement fits?" Key `$fatal(1, …)`, with distractors `$error` (the simulation continues on garbage) and `$warning`. Or narrow objective 3 to deferred action blocks and placement, which is what the quiz tests. (Source: spine §5.4 coverage rule; §20.10.)

**S3-4** `immediate-vs-concurrent.mdx:139-160` — The page never separates `assert final` from the `final` procedure (`final begin … end`, §9.2.3), which runs once at the end of simulation. Juniors confuse the two, and the keyword collision invites it. The lead's scheduling lint exists because of this exact confusion ("final blocks run in Postponed"; author lead request 2). **Fix:** add one sentence after the syntax snippet. Suggested text: "`assert final` has nothing to do with a `final` procedure (§9.2.3), which runs once when simulation ends. A final deferred assertion reports at the end of the *current time slot*, every time slot it fails in." Optionally add it as a Q-new distractor (S3-2). (Source: IEEE 1800-2023 §9.2.3, §16.4.)

**S3-5** `immediate-vs-concurrent.mdx:29` — "A **process** is one running thread of a procedure; each procedure is one process." This is incomplete exactly where the lesson depends on it. Deferred report queues are per *process* (§16.4.1), and a `fork` inside a procedure creates child processes with their own queues. A junior who reads "each procedure is one process" will mis-predict flushes in forked code. **Fix:** "A **process** is one running thread of code. Each `initial`, `always`, `always_comb`, `always_ff` procedure starts one, and each branch of a `fork` starts another (§9.5)." (Source: IEEE 1800-2023 §9.5, §16.4.1.)

**S3-6** `immediate-vs-concurrent.mdx:31-50, 99-137` — Some terms are used before they are defined, on the core path. In the Quick Take, "time slot" (`:13`), "Observed or Postponed" (`:15`) and "property" appear first; they are defined at `:29`, or only in F3B. "Active region set" (`:50`) is never defined. "Pending report", "queued" and "flush point" appear in the glitch trace (`:131-133`) one section before the deferred section defines them (`:143-148`). The trace gives inline glosses, so this is not blocking. But README rule 4 says "define every term before using it". **Fix:** add a parenthetical gloss for time slot in the Quick Take ("all the work at one simulation time, F3B"). Define "Active region set" at `:50` ("Active, Inactive and NBA"). Add one line before the trace table: "A deferred assertion puts its report in a per-process queue (a *pending report*); running the process again (*a flush point*) empties the queue. The next section gives the full rules." (Source: README "Easy to understand", target lesson tone.)
