## Lab `assertions-1` (owning module I-SV-4A)

### Verdict handled

**Rewrite** (L16 verifier: "major → rewrite"; plan row L16; group notes). Every file was rebuilt from scratch. The old concept, a local-variable data-integrity check across a pipeline, belongs to I-SV-4B. The group notes keep this lab in I-SV-4A and ask it to teach the I-SV-4A objectives. So the new lab uses only I-SV-4A constructs: implication timing, `$stable`/`$past`/`$sampled`, `disable iff`, `assert`/`assume`/`cover`, deferred assertions, action blocks and assertion control. No local variables, repetition or `s_eventually` appear in it.

**Design of the lab.**
- `hs_slice` is a one-word valid/ready register slice, the kind of block a junior meets first.
- **Seeded bug:** the payload register loads whenever `in_valid` is 1, even when the slice is full and stalled. During a downstream stall the source's next word overwrites the held word. The held word is lost and the next word reaches the sink twice.
- A scoreboard notices this only at 85 ns, when the word leaves. R2 (`$stable` under a stall) names the rule, the edge (75 ns) and both values (a2 → a3).
- **Pedagogical sequence:**
  1. Run the starter: a scoreboard error with no explanation.
  2. Predict `|->` vs `|=>`, then write R1 and R2.
  3. Add the assumption and the covers, then run without stalls: green and vacuous, with C2 = 0 as the evidence.
  4. Run with stalls: exactly one assertion failure.
  5. Fix one line and get a clean run.

**Hand trace (buggy DUT, default stall of 2).** The sink samples a0 at 45 ns and a1 at 55 ns, then drives `out_ready` 0 for the edges at 65 and 75 ns.
- At 65 ns: `in_ready` = 0, but the buggy line loads a3.
- At 75 ns: R2's attempt from 65 ns compares a2 with a3 and fails.
- At 85 ns: the sink takes a3 while a2 was expected.
- At 95, 105 and 115 ns: a3, a4 and a5 arrive. Six words in all, so `a_end_of_test` runs at 135 ns and reports FAIL.
- R1, R3 and R4 pass. C1 hits 6 times (45, 55, 85, 95, 105, 115 ns) and C2 once (stall at 75 ns, transfer at 85 ns).

**Other traced runs:**
- `+NO_STALL`: the last word arrives at 95 ns, so PASS at 115 ns, with C2 = 0.
- Fixed DUT: a2 is held through 75 ns and arrives at 85 ns, so PASS at 135 ns.
- `+PAUSE=6` on the fixed DUT: the assumption fails at 105 ns and 115 ns, and the run ends with FAIL at 175 ns.

Converting the bench to a clocking block changed no value in these traces:
- `cb` inputs give the same pre-edge samples.
- Zero-skew outputs mature in Re-NBA of the same edge, as the old nonblocking assignments did.
- `@(cb)` resumes after Observed, so every read in the bench goes through `cb`.

### Expert items added (Push further), with sources

1. **An assumption catches the environment.** `+PAUSE=6` breaks R3: it fails at 105 and 115 ns while the design is correct (§16.14.2: an assumed property is checked and reported in simulation).
2. **Assertion control.** `$assertoff(0, tb_top.u_sva.a_out_data_stable)` stops new attempts until `$asserton`; attempts in flight are not affected (§20.11, Off), while `$assertkill` aborts them (§20.11, Kill). Fix round 1 adds the 70 ns variant and expected logs.
3. **Asynchronous disable.** A reset at 78 ns disables an attempt in flight: neither pass nor fail, no action block (§16.12, §16.14.1).
4. **When a `$past(rst_n)` guard is needed.** It is not needed when reset is released between edges. It is needed when reset is released by a flop at an edge (§16.12 current-value disable, §16.5.1 samples).
5. **Why `$sampled`/`$past` in action blocks** (Step 2, hint 3; §16.9.3, the a1_bad/a2_ok example).
6. **Choose a severity** (fix round 1). `$fatal(1, ...)` in R2 ends the run at 75 ns through an implicit `$finish`; the checker's `final` summary still prints (§20.10, §9.2.3).
