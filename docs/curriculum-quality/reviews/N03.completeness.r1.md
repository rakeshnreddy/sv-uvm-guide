## Findings

### S3-1: Message forms and reporting from non-components are missing (checklist item 4, syntax and variants)
- **Where:** index.mdx L41–60 (the four macros) and L373 (global report functions).
- **Problem:** The page teaches only the four basic macros. A learner will soon meet three other things, none of them mentioned:
  - the `uvm_report_info/warning/error/fatal` methods that the macros call (§6.3.3.3);
  - the `` `uvm_*_context(ID, MSG, VERB, RO) `` macros (Annex B.1.1.5–B.1.1.8);
  - reporting from a non-component class (a `uvm_object`, transaction or config object). There the macros fall back to the global functions and report through `uvm_root` as `reporter` (F.3.2.1).

  The author deferred the sequence case to I-UVM-3A. Even so, the plain-object case and the `_context` macros belong to this module's "syntax and variants".
- **Fix:** Add a short "Other forms you will meet" bullet list after L60. Name the `uvm_report_*` methods, the `_context` macros (one example: `` `uvm_info_context("CFG", msg, UVM_LOW, env) ``), and the rule that in a non-component class the report comes from `reporter` unless you supply a context. Forward-link sequences to I-UVM-3A. Optionally add one flashcard.
- **Source:** IEEE 1800.2-2020 B.1.1.5 (`` `uvm_info_context ``), §6.3.3.3, F.3.2.1 (checked in uvm_lrm.txt).

### S3-2: The "Write" half of objective 1 is never practised
- **Where:** L21 (objective 1), quiz L741–852, katas L854–945.
- **Problem:** Objective 1 is "Write `uvm_info/warning/error/fatal` with meaningful IDs, and predict…". Q1 tests the prediction. No quiz item, kata step or Break-it row asks the learner to *choose* a severity, ID or verbosity, or to *write* a macro call. Make It Work only shows finished code.
- **Fix:** Add a Kata 2 step 0 or a short Kata 3: "Convert this legacy checker (`$display("got %0d")`, `$error("bad")`, a per-transaction debug print) to UVM macros. Pick severity, ID and verbosity, and justify each choice." Put a worked solution in `<details>`. Alternatively, add a quiz item with `objective: 1` that asks which severity and verbosity fit given messages, with distractors such as "`uvm_fatal` for a single mismatch" and "per-transaction info at `UVM_LOW`".
- **Source:** plan §1.2 and spine §5.4 (every objective exercised).

### S3-3: The "Run it" box cannot be followed without outside help
- **Where:** L614–629.
- **Problem:** The card's must-cover says "compiling uvm-core into a run, with tool-specific switches labelled". The page gives only `<compile>` and `<simulate>` placeholders. A junior gets no concrete command for any simulator, so the "runnable" example cannot be run from the page alone. The author deferred this because the switches are unverified here. Spine §5.2 rule 3 does allow vendor switches when they are labelled with the tool name.
- **Fix:** Add one row per major simulator, each labelled with the tool and verified against that vendor's public documentation, for example Xcelium `xrun -uvm …` and VCS `-ntb_opts uvm-1.2`. Mark each "check your version's documentation". If they cannot be verified, say explicitly which document the learner should open (for example the simulator's UVM user guide), and record the item as a lead-tracked deferral.
- **Source:** spine §4.2 card must-cover; spine §5.2 rules 3 and 15; gap G15.
