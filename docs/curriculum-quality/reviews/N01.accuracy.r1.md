## Findings

| # | Sev | Location | Problem | Fix | Source checked |
|---|---|---|---|---|---|
| 1 | S3 | `index.mdx:127` | "If your DUT resets asynchronously, assert reset at any time but release it the same way" (that is, with `<=` just after the active edge). That is deterministic in zero-delay RTL simulation. But F4C, the page it links, tells learners to release an asynchronous reset with a direct write **away from** the active clock edge (F4C `index.mdx:334`, recovery/removal), because a release that coincides with the clock edge is a recovery/removal violation in hardware and at gate level. The two modules give different advice for the same case. | Reword to: "If your DUT resets asynchronously, you may assert reset at any time; release it between clock edges, away from the active edge, as F4C explains." Or say that the `<=` release is race-free in RTL simulation but sits on the clock edge, which real asynchronous-reset flops forbid. | F4C `index.mdx:329-336`; IEEE 1800-2023 §4.9.4 |
| 2 | S4 | `index.mdx:445` (compile-unit comment) | `// every module needs one (1800-2023 3.14.2.3)` overstates the clause. §3.14.2.3 makes a mix of design elements with and without a time unit an error, and a module can also get its unit from a `` `timescale `` directive. The prose at line 115 and card f2e-15 state the rule correctly. | `// tb_top has one, so the DUT must too (1800-2023 3.14.2.3)`. | §3.14.2.3 |
| 3 | S4 | `index.mdx:788` | "Only a result nobody expected can meet an empty queue at that moment, and it fails in either order, just with a different message." If `send()` runs first, the unexpected result pops the expectation that was just pushed. If the values happen to match, that compare passes, and the failure only appears later (the real result finds an empty queue, or a leftover). So the run still fails, but not always at that compare. | "…and the run fails in either order, though possibly one result later and with a different message." | Reasoning from §4.7, §7.10.2.4, §7.10.2.7 and the page's `check_result()`/`report()` |
