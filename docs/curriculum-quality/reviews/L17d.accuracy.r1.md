## Sources checked

- **IEEE 1800-2023**, read from the extracted text:
  - §15.3.1: default `keyCount = 0`; the count "can increase beyond keyCount"; the start may be negative, but available keys "shall be positive" before `get`/`try_get`.
  - §15.3.2: a negative value is an error; a suspended process "shall execute if enough keys have been returned".
  - §15.3.3: FIFO; "does not guarantee the order in which processes arrive at the queue".
  - §15.3.4: returns a positive integer or 0; a negative count "returns 0 and shall result in an error".
  - §4.7: the simulator may suspend a process while it evaluates a statement.
  - §6.8: static initializers run before any initial or always procedure.
  - §9.2.3: final procedures run on an explicit or implicit `$finish` and before end-of-simulation PLI callbacks, and allow only function statements.
  - §9.6.1: "Simulation automatically terminates when there is no further activity of any kind".
  - §9.7: "the processes may terminate normally while kill() is executing".
  - §20.10: `$fatal` makes an implicit `$finish`; the tool message includes file, line, scope and time.
  - §38.36.3: `cbEndOfSimulation` fires when no events remain or `$finish` executes.
  - Annex B Table B.1: no `try`, `catch`, `finally` or `throw`; `release` is reserved.
- **uvm-core 2020.3.1**, downloaded from the tag (`raw.githubusercontent.com/accellera-official/uvm-core/2020.3.1/src/reg/uvm_reg.svh`):
  - :113-122 declare `m_atomic`, `m_process` and `m_atomic_cnt`; :701 has `m_atomic = new(1)`.
  - :1706-1720: `reset()` carries the comment "in case a thread was killed during an operation" and runs `void'(m_atomic.try_get(1)); m_atomic.put(1);`.
  - :2910-2938: `XatomicX` uses the re-entry counter, raises `UVM/REG/ZOMBIE` only for `process::KILLED` and then calls `get(1)`, and releases through the clamp.
  - `XatomicX(1)` is called from `write` (:1829), `do_write` (:1873), `read` (:2116), `poke` (:2663), `peek` (:2732) and `mirror` (:2855).
  - All of the page's claims (:504, :767, :776, :813) match.
- **IEEE 1800.2-2020** §14.2.5.5 and §14.2.5.6: taken as verified by `L17.verify.md`.
