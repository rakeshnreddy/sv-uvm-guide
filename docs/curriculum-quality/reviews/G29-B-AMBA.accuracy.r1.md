| 1 | **S2** | amba-axi4-lite-stream (model_answer, item 2) | The answer says WSTRB is present "so sparse writes still happen and a Lite slave must honour the strobes". B1.1.3 says the opposite: "Any slave component can choose whether to use the write strobes." The permitted options are to use them fully, to ignore them and treat every write as full width, or to return an error for unsupported combinations. Only "a slave that provides memory access must fully support write strobes". A candidate who repeats the model answer states a rule that does not exist, and a VIP built on it flags compliant register slaves. The answer key, "(2) True", is right. | Replace the clause with: "Masters and interconnect must drive correct strobes. A Lite slave may use them, ignore them (treating every write as full width), or return an error for strobe patterns it does not support; a memory slave must support them fully. A write with every strobe low can also arrive after conversion from full AXI (B1.1.3)." Add "§B1.1.3 Write strobes" to `sources`. Optionally add "requiring every Lite slave to honour WSTRB" to `common_mistakes`. | IHI0022E B1.1.3 |
| 2 | **S2** | amba-ace-snoop-flow (rubric; common_mistakes[1]; model_answer step 2) | The rubric requires "a ReadShared snoop, not an invalidating snoop", and `common_mistakes` lists "Sending an invalidating snoop for a ReadShared". Both are wrong. For a ReadShared, Table C6-1 requires the snooped line to end "Shared or Invalid". ReadShared is the *recommended* snoop. ReadUnique and CleanInvalid are listed as *optional* snoops. The C5.1 Note also allows "other mappings that force the same cache line state changes". So an invalidating snoop is legal: it costs the holder its copy, but it is not an error. The rubric therefore marks a correct answer wrong. It also contradicts the bank's own `amba-ace-state-transition-debug` common mistake ("Checking the snoop name instead of the required state change"). Step 2 of the model answer presents the ReadShared snoop as the only choice. | Rubric: "the interconnect snoops the other caches on AC; ReadShared is the recommended snoop (Table C5-1), and an invalidating snoop (ReadUnique, CleanInvalid) is also permitted because the required end state is Shared or Invalid (Table C6-1)". Model answer step 2: add "the recommended snoop; Table C6-1 also permits ReadUnique or CleanInvalid, which leave B in I". Replace the common mistake with "Checking the snoop opcode instead of the required end state, or letting a ReadShared snoop leave the holder Unique". Add "§C6.3 Table C6-1" to `sources`. | IHI0022E C5.1 Table C5-1 and Note; C6.3 Table C6-1 (ReadShared row: "Shared or Invalid"; recommended ReadShared; optional ReadClean, ReadNotSharedDirty, ReadShared, ReadUnique, CleanInvalid) |
| 3 | S3 | amba-chi-credit-deadlock (model_answer "How a loop forms"; rubric "Separates senior staff") | The answer says "The specification lists channel rules only for Request and Subordinate Nodes, so treat this as a design requirement for the Home". In the loop, the Home withholds RSP L-Credits until the RN-F (the RSP Transmitter) accepts more snoops, so it ties credit return to an action by the Transmitter.
