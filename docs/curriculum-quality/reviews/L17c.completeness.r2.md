## New findings (round 2)

### S4

**S4-A. Q6's distractors share a pattern that gives the key away.**
- **Where:** `mailboxes.mdx:847-850` (Q6 answers).
- **Problem:** The stem asks what happens and "what changes if m is declared `mailbox #(int)`". All three distractors end "…in both cases", and only the key treats the two cases differently. A learner can pick the key by its form without knowing §15.4.5 or §15.4.9. Spine §5.5 says the answer must not be guessable. The item's content is right, and objective 2 is also tested by Q8, so this is polish.
- **Fix:** Make one distractor a half-right split, for example: "Typeless: `s` becomes "5"; typed: `m.get(s)` does not compile". It keeps the conversion misconception and breaks the "in both cases" pattern. Feedback: "The typed half is right, but a typeless mailbox never converts. It reports a run-time error (§15.4.5)."
- **Source checked:** spine §5.5 rules ("the answer must not be guessable from the stem"); the quiz parse above.

**S4-B. Kata "Done when" expects a timeout line that no task asks for.**
- **Where:** `mailboxes.mdx:923` (task 3) and `:930` (Done when).
- **Problem:** Task 3 asks the driver to stop after 50 ns without an item, print `PASS=`/`FAIL=` and call `$finish`. "Done when" then requires "exactly one timeout line … at 130 ns". The worked solution prints `drv: no item for 50 ns, stopping`, but a junior following only the task text would not know to print it.
- **Fix:** In task 3, add "print one line when the driver stops", or reword the criterion to "the driver stops at 130 ns, after the last item".
- **Source checked:** spine §5.8 (a hands-on item with clear acceptance criteria); analysis hands-on plan item 2 (acceptance: "exactly one timeout line after the last item").

**S4-C. "Predictor" is used without a definition.**
- **Where:** `mailboxes.mdx:303`, depth table row "generator or predictor → scoreboard (expected items)".
- **Problem:** At I-SV-5 a learner has not met a predictor or reference model (A-UVM-6 teaches it). Spine §5.1 says to define "reference model; predictor (scoreboard)" before use. The word appears only here.
- **Fix:** Write "generator or predictor (the model that computes expected values) → scoreboard", or drop "or predictor" and link A-UVM-6 from Related, which the page already does.
- **Source checked:** README quality requirement 4 ("define every term before using it"); spine §5.1 terminology row for predictor.
