## Findings

### S3-1 Objective 4 ("Write the portable-stimulus entry") has no worked example and no writing exercise
- **Where:** `pss.mdx:25` (objective), `:300` (how-to step 7), `:443-450` (kata).
- **Problem:** The objective's verb is *write*, but the page only lists what the entry contains (step 7, checklist `:318`) and tests it by recognition (Q2 picks a correct line; Q6). No example shows a filled-in entry, and the kata stops at "your decision". A junior cannot see the target artifact.
- **Fix:** After how-to step 7, add a 5–6 line example entry for the DMA library (standard: Accellera PSS 3.0, August 2024; tool and accepted version: "<tool> x.y, PSS 2.1/3.0"; categories in PSS; owner of each realization; coverage reported next to closure evidence, not merged). Add kata step 6 "Write the strategy's PSS line for this use case" with a solution row.
- **Source checked:** spine §5.4 (objectives exercised), README target lesson §2 and §4.

### S3-2 No tool-neutral "Run it" step in Make It Work
- **Where:** `pss.mdx:265-300`.
- **Problem:** Spine §5.2 item 15 asks Make It Work to name the compile and run steps tool-neutrally. The page explains the solved output but never says how a learner gets from `dma_soc.pss` to a running test (generate per target, compile the C into the boot image, compile the SV sequence with the bench, run).
- **Fix:** Add a short "Run it" list, labelled tool-dependent, with no vendor switches: (1) generate target C and target SV for `pss_top::dma_under_load_a` with a seed; (2) compile the C test with `dma_driver` into the boot image, or the SV sequence into the subsystem bench package; (3) run; (4) archive seed, schedule and image hash (links forward to Expert: reproducibility). State that no open-source PSS tool was verified.
- **Source checked:** spine §5.2 item 15; E-PSS-1 "From model to UVM and to C".
