## Findings

### S3-1 The first picture omits the realization packages, the main thing the predict prompt asks about
- **Where:** `pss.mdx:63-88` (nodes and edges), caption `:68`; compare Run it `:324`, `:326`.
- **Problem:** The predict prompt (:61) asks "which boxes does the SoC team write by hand". The caption answers "the whole realization row at the bottom, including the template packages dma_real_sv.pss and dma_real_c.pss and the subsystem env with its active APB agent", but the bottom row has only two boxes, "UVM sequences" and `dma_driver.h`. The template packages and the subsystem env have no box. The only input edge to the tool is `dma_soc.pss → tool: read`, so the picture shows the tool generating both targets from the scenario library alone. Run it (:324, :326) says the tool reads `dma_soc.pss` plus one realization package per test. The picture teaches objective 1 and the page's one new construct, so a learner who trusts it gets the generation flow wrong. The text corrects it, so this is S3 rather than S2.
- **Fix:** Draw the two packages as inputs to the tool. For example, put `dma_soc.pss` in row 0 cols 0-1 (`colSpan: 2`), and `dma_real_sv.pss` (sublabel "SV templates, subsystem team") at col 2 and `dma_real_c.pss` (sublabel "C templates, firmware team") at col 3, each with a `causal` edge to `tool`; label one edge "one per test". Then reword the caption so it names only boxes that exist, keeping "the subsystem env with its active APB agent" as a separate clause ("not drawn: …"). Check label widths against the 150 px cell, as the visuals reviewer did.
- **Source checked:** README §Visuals ("must match the code on the page exactly"); `pss.mdx:262-314`, `:323-327`; PSS 3.0 §22.5.1 as cited on the page.
