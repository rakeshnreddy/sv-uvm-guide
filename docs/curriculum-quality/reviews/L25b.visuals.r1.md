## Notes for the lead

1. **Kit (repeats earlier rounds).** `ArchitectureDiagram` never scales below 360 px; it scrolls horizontally instead, and its text has no minimum size. Any diagram with three or more columns at the default grid becomes hard to read on a phone. A scale-to-fit mode, or a minimum rendered font size, would remove F1 and F2 at the source.
2. **Generated data and snapshot.** `npx vitest run tests/curriculum-generator.test.ts` fails (2 tests) because the generated curriculum data and `tests/__snapshots__/curriculum-generator.test.ts.snap:889` still hold the old I-UVM-5 description ("Learn when uvm_pool and uvm_queue add value …"). The same failure appears for I-UVM-6 and other groups, so this is the program-wide `npm run generate:curriculum` + snapshot refresh at integration, not an author defect.
3. **Author request 2 (manifest).** I agree that I-UVM-1C should be a manifest prerequisite of I-UVM-5. The page leans on `uvm_event`/`uvm_barrier` semantics and objections, and `<BeforeYouStart />` will show I-UVM-1C only after that change. Related (861) covers it until then.
4. **Model text (F5).** Change `containerPolicySupport[0].print` in `src/lib/uvm-container-model.ts:477`. Optionally add `pack`/`record` columns to match the page's table.
