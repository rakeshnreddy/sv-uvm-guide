## Findings

### S1

**S1-1. Q14's key is wrong: a child sequence's automatic phase objection raises nothing unless the child has a starting phase.**
- **Where:** `index.mdx:1630-1640` (Q14). The same unstated assumption appears in the debugging-table row `index.mdx:589`, in Expert "who may object" `index.mdx:1423-1424`, and in card `a-uvm-8-17` (`A-UVM-8_Multi_Agent_Topologies.json:83-85`).
- **Problem:** Q14's stem says "A background `irq_responder_seq` with a forever body calls `set_automatic_phase_objection(1)`" and keys "The test never ends". On this page the responder is a child started by `soc_vseq` with `irq_seq.start(p_sequencer.irq_sqr, this)`. The automatic objection is raised on the sequence's **starting phase** (§14.2.4.4: "automatically object to starting phase"). §14.2.4.1 says the starting phase is set automatically only when the sequence is started as a **default sequence**. uvm-core 2020.3.1 `start()` calls `m_safe_raise_starting_phase()`, which raises only `if (starting_phase != null)`. `start()` does not copy the parent's starting phase, and the only caller of `set_starting_phase()` in the library is `uvm_sequencer_base::start_phase_sequence()`. So with the stem as written, no objection is raised, the run phase ends when the test drops its objection, and the keyed distractor "The run phase ends normally once the test drops its objection" is the correct answer. A learner who reasons correctly is marked wrong, and the page teaches that every automatic objection on a child is a hang.
- **Fix:**
  - Put a starting phase in Q14's stem. For example: "`irq_responder_seq` (forever body) is the default sequence of `irq_sqr`'s `run_phase` and calls `set_automatic_phase_objection(1)`…", or "the virtual sequence calls `irq_seq.set_starting_phase(phase)` and `irq_seq.set_automatic_phase_objection(1)` before starting it…". Keep the key.
  - Optionally change distractor A's feedback so it teaches the condition: "That is what happens to a child with no starting phase; this one has one."
  - In the debugging-table row (`:589`) and Expert "who may object" (`:1423`), add one clause: "the automatic objection applies only when the sequence has a starting phase (a default sequence, or `set_starting_phase()`); a child started from a virtual sequence has none unless you set it."
  - Card 17: begin the answer with "If it has a starting phase (a default sequence, or one set with `set_starting_phase()`) and raises the automatic objection, that objection is dropped only when `body()` returns…".
- **Source:** IEEE 1800.2-2020 §14.2.4.1 and §14.2.4.4 (extracted text); uvm-core 2020.3.1 `src/seq/uvm_sequence_base.svh` `start()` (raise at the `#0` after the fork), `m_safe_raise_starting_phase()`, `get_starting_phase()`; `src/seq/uvm_sequencer_base.svh` `start_phase_sequence()` (`seq.set_starting_phase(phase)`, the only setter call).

### S3

**S3-1. Quiz and interview keys can be guessed from length and position.**
- **Where:** `index.mdx:1486-1641`; `index.mdx:1449-1480`.
- **Problem:** Neither `Quiz` nor `InterviewQuestionPlayground` shuffles options. In 11 of 14 quiz questions the correct option is the longest, often twice the length of any distractor (Q4: 169 characters against 53-72; Q12: 167 against 47-57; Q14: 146 against 53-67). The key is never in position D, and it is in position B 8 times. In all three interview playgrounds the correct option is first and the longest. Spine §5.5 says "the answer must not be guessable from the stem". A test-wise learner can score well without the concepts, which weakens objective traceability.
- **Fix:**
  - Trim the keys to the deciding fact and move the "why" into `feedback`. For example, Q4's key becomes "The order of the statements in `body()`".
  - Lengthen two or three distractors with plausible detail.
  - Spread the keys across A-D, putting about a quarter in D.
  - In each interview playground, move the correct option off position 1.
- **Source:** spine §5.5 rules; measured option lengths and positions; `Quiz.tsx` and `InterviewQuestionPlayground.tsx` (no shuffle).

- **Problem:** Block to subsystem reuse is taught with a diagram, prose, pitfalls, Q9, card 7 and an expert item, but no code. A junior cannot see these steps in code:

  - how it flips `blk_b_cfg.in_agt_cfg.is_active`;
  - how `sub_vsqr` gets `a_vsqr` and `b_vsqr` in `connect_phase`;
  - how a subsystem virtual sequence starts block A's virtual sequence as a child.

  Horizontal reuse does have a `dual_env` snippet (`:271-297`), so the two reuse forms are unevenly served.
- **Fix:** Add a `// snippet` of about 20 lines: the `sub_env` `build_phase`, where the test or `sub_env` sets `cfg.blk_b_cfg.in_agt_cfg.is_active = UVM_PASSIVE`, then sets each block config at `"blk_a_env"` and `"blk_b_env"` and creates them; `connect_phase` with `v_sqr.a_vsqr = blk_a_env.v_sqr;`; and a `sub_vseq::body()` line `a_seq.start(p_sequencer.a_vsqr, this);`. Add one pitfall row with a log signature, for example an absolute path → `UVM_FATAL [NO_CFG]` in `blk_b_env`.
- **Source:** README concept completeness checklist items 4 and 5; spine card must-cover; analysis L31-A8-04.
