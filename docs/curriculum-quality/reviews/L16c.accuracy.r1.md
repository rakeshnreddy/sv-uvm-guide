| 1 | S2 | `multi-clocking.mdx:146` | "In the Make It Work bench, a `\|->` version fails falsely for pulses on the 30, 60 and 90 ns edges and passes for every other pulse." This is false for the bench's assertion. With the `##[0:3]` window, a `\|->` attempt on a coincident edge t checks the `dst_clk` ticks t, t+15, t+30 and t+45. The synchronizer delivers at d1+2, where d1 = t+15 is the first strictly later tick, so `dst_pulse` is sampled 1 at t+45, which is inside the window. Hand trace with the fixed stimulus: event at 90 ns, `\|->` window 90/105/120/135, `dst_pulse` sampled 1 at 135, so it **passes**. With the original stimulus, the 90 ns event is a real loss, not a false failure. The one-tick margin absorbs the early start, so only the exact-latency `##2` check fails (kata part 2 and Q9 are correct). The bench also has no pulses at 30 or 60 ns. A learner who runs the `\|->` variant will see the opposite of what the page predicts, in the core path. | Reword, for example: "With the exact-latency window `##2` (kata part 2), a `\|->` version fails falsely for every pulse on a coincident edge (30, 60, 90 ns ...) and passes for all the others.
