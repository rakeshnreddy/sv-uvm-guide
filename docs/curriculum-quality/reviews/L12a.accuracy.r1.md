**Lab.**
- Starter:
  - IPV4 always gets length 32 (the only value in both [20:60] and {16, 32, 64, 128, 256}).
  - IPV6 fails. A new object then prints proto IPV4, length 0 and size 0 (§18.6.3, enum default).
  - RAW comes from the FIFO set.
- Switching off any one of the three blocks makes IPV6 solvable, and the smallest conflicting set has four members, including the inline `with` (§18.9).
- The step-2 fix, which switches the block off only for IPV6 rows (L12a-LAB-N1), is correct. Switching `c_hardware_limit` off on RAW rows would leave `length` an unbounded `int unsigned`.
- Solution:
  - IPV4 lengths are {24, 32, 40, 48, 56}.
  - IPV6 is 40.
  - RAW lengths are multiples of 8 from 8 to 256.
- Push Further: with no inline `with`, the problem is never infeasible and IPV6 is never picked.
- `packet::IPV6` and `packet::protocol_t'(i % 3)` are legal class-scope references.
