## Findings

### F1 (S4): a MAM label sits at the left edge of the viewBox
- **Where:** index.mdx:250.
- **Problem:** The label "new region: 64 words at 192 to 255" is centred at x = 75.6 and is 133 to 156 units wide.
  - In Cal Sans it starts at x = 8.9, and in Inter at x = 0.8.
  - In the system-ui fallback (fonts not yet loaded, or blocked) it starts at x = −2.4, so the "n" is clipped.
- **Fix:** `x="10" textAnchor="start"` (the leader line at x = 75.6 still points at the region), or shorten the label to "new region: words 192 to 255".
- **Source checked:** `getBBox()` with each font loaded from `public/fonts`.

### F2 (S4): example ArchitectureDiagram, an edge crosses the agent label and a port label is crowded
- **Where:** index.mdx:541, :550 and :554.
- **Problem:**
  - The `set_sequencer(agent.sqr, adapter)` control edge runs diagonally from `ral` (col 1) to `sqr` (col 0) through the "AGT · agent (rb_agent)" container label.
  - The `bus_in` port label on the predictor's bottom edge almost touches the long sublabel "uvm_reg_predictor #(rb_item)".
- **Fix:**
  - Add `via: [[1, 1]]` to the `ral → sqr` edge, so it drops through the empty centre cell and enters `sqr` from the right.
  - Shorten the predictor sublabel to "#(rb_item)", or move both ports with `at: 0.75`.
- **Source checked:** `layoutGridDiagram` output rendered with `BlockDiagram` (scratch render).

### F3 (S4): multi-map diagram, short port edges and phone-width legibility
- **Where:** index.mdx:302-305 and :312-313.
- **Problem:**
  - Each `mon.ap → pred.bus_in` edge is about 40 units long, because it crosses the gap between adjacent columns. Its "write(t)" label sits on top of the ap and bus_in glyphs.
  - The diagram is 848 units wide. At 390 px it scales to about 0.42 (kit `minWidth` 360), so the 11-unit labels render at about 5 px. This is kit behaviour, but this is the widest diagram on the page.
- **Fix:**
  - Drop the two "write(t)" labels; the port labels already say ap → bus_in.
  - For phone width, I concur with L27b F8 (lead/kit): give wide ArchitectureDiagrams a horizontal-scroll floor at 390 px.
- **Source checked:** scratch render; `DiagramKit.tsx:55` (`minWidth={Math.min(layout.width, 360)}`).

### F4 (S4): the visualizer prompt promises a log message for every suspect
- **Where:** index.mdx:505 and :509.
- **Problem:** The prompt asks "which log message each *other* suspect would have produced instead".
  - Two of the four other suspects produce no message in the model. The `set_sequencer` feedback says the write would not reach the bus. The `set_auto_predict(0)` feedback says the line is right (`RALPredictorVisualizer.tsx:309-310`).
  - The debrief's "the W1T LED" is GPIO.LED in the visual, but CTRL.LED in Make It Work.
- **Fix:**
  - Reword the prompt to "what each other suspect would have done instead (a fatal, a crash, no bus traffic, or nothing)".
  - Write "the W1T LED (GPIO.LED in the visual)".
- **Source checked:** `RALPredictorVisualizer.tsx:308-366`.

- **Fix:** Reword the legend to "into the mirror: dashed = implicit, solid = explicit", or draw the RAL → map arrow dashed as well.
