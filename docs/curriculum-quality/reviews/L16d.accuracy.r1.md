## Findings

| # | Sev | File:line | Problem | Fix | Source checked |

| 1 | S4 | `index.mdx:323` | "Never write `bind` inside a generate loop to do it: every iteration would add the same instance name to the same target." This is true when the target does not depend on the genvar, which is the per-port case. But `bind_target_instance` takes a `hierarchical_identifier` with constant selects, and `bind_directive` is a legal generate item. So a loop whose target is indexed by the genvar (`bind tb_top.dut.g_lane[i].u_fifo …`) targets a different instance on each iteration and does not clash. The page states the rule more broadly than the standard. | "…: if the target does not change with the genvar, every iteration adds the same instance name to the same target, which is an error (§23.11). A genvar-indexed target avoids the clash, but tool support varies (tool-dependent), and one bind of a wrapper module is simpler." Keep the wording aligned with I-SV-6:761, which makes the same claim. | §23.11 (Syntax 23-9, name-clash rule); A.9.3; A.1.4 `module_common_item` includes `bind_directive` |
| 2 | S4 | `index.mdx:547` | "Only `u_tx` holds two items, so only its checker fails". `u_rx` and `u_dbg` also hold two items, and then three. The point is capacity. | "Only `u_tx` has room for just two items, so only its checker fails". | Hand trace of the bench (lines 507-526) |
| 3 | S4 | `index.mdx:597` | "A checker variable declared `rand` is a free variable: a value no code assigns, which … a simulator randomizes." §17.7.1 allows nonblocking assignments to free variables (the standard's toggling `rand bit a; always_ff @clk a <= !a;`). Such variables are *inactive*: §17.7.2 randomizes only their initial value. | "…a free variable. When no code assigns it, a formal tool treats it as any value the assumptions allow, and a simulator randomizes it (§17.7.2); a free variable assigned with `<=` is randomized only at initialization." | §17.7.1 (toggle example), §17.7.2 (active and inactive free variables) |

The instantiation grammar that has no `parameter_value_assignment` is Syntax 17-2 in §17.3 (A.4.1.4). §17.2 / A.1.8 support only "no parameter items in the declaration". | Cite "§17.3 (Syntax 17-2)" for the instance half; keep §17.2 / A.1.8 for declarations. | §17.2 Syntax 17-1; §17.3 Syntax 17-2 |
