| A1 | S3 | flow-control.mdx:519 | "A time-0 corner" says: "The standard does not say whether Off discards a violation report that is already queued … so whether that one report still appears is tool-dependent." | A2 | S3 | flow-control.mdx:267 | The break/continue trace table's last row (`none \| 4 \| not reached \| not reached \| the loop has ended`) shows `i` = 4. `break` at `i` = 3 leaves the loop without running the step `i++`, so `i` never becomes 4. ## Checked and correct (selected, where an error was plausible)

- §9.2.2.2: `always_comb` runs once at time 0 "after all initial and always procedures have been started".
- The five §9.2.2.2.2 differences.
- `final`: arbitrary but deterministic order; the NOTE; "No remaining scheduled events shall execute"; `$finish` in `final` ends the run immediately; automatic termination cited correctly to §9.6.1.
- The k/m example's late copy is 4, the loop's final value.
- `kill()` on a FINISHED process still kills its live descendants (§9.7).
- `disable` on a block that is not executing has no effect, and a loop-body disable acts like `continue` (§9.6.2 Example 3).
- §12.4.2 and §12.5.3: on an overlap, the first matching item or true condition runs.
- A single item with several matching expressions is not an overlap.
- A violation may be reported at compile time.
- §12.7.2: a negative count is treated as zero.
- §12.8: multi-dimensional `foreach` `break` and `continue`; no jumps across a fork.
- Table 9-2 matches the LRM exactly.
- §3.14.2.3: "It shall be an error if some design elements have a time unit and precision specified and others do not", so the comment in both compile units is correct.
