### Fixes in this run (re-verification of the interrupted run's draft)

- **Reactive sequence.** It now calls `rsp.c_aligned.constraint_mode(0)` before `randomize(wait_cycles, rdata, slverr)`. Otherwise an unaligned DUT address makes `randomize()` fail, because class constraints still apply to state variables (§18.11). The text explains why.
- **Expected output.** It now includes the three `APB_CFG` lines (`UVM_MEDIUM` is the default verbosity) and states that the log is abridged. It also explains the banner order: `start_of_simulation` is bottom-up (§9.8.1.4), and uvm-core visits siblings in name order.
- **Debug challenge.** X appears on `PSEL`/`PENABLE` only when the bridge drives 1 against the idle driver's 0, not "from the first edge". `PWRITE`/`PADDR` stay correct (their clocking drivers are still `'z`). The interview feedback and the debug-table row were aligned with this.
- **Passive SoC snippet.** It now shows where `soc_vif` comes from (a `set` in the same `initial` block as `run_test()`, avoiding the race the page warns about).
- **Citations.** §9.8.1 → §9.8.1.1 (`uvm_build_phase` is top-down); §18.7 → §18.7.1 (`local::`). The APB power note is corrected: IHI0024C §3.1.2 recommends holding the address and write signals, and does not mention PWDATA.
- **Wording and navigation.** The B-AXI-6/B-AHB-3 sentence is softened to "apply the same pattern". The hand-written "Next comes A-UVM-5" line is removed (A-UVM-5 moved to Related).
- **Terms and style.** Re-NBA (F3B link) and objection (I-UVM-1C link) are defined at first use. Three code lines over 90 columns are wrapped.
- **New picture.** A self-test topology ArchitectureDiagram was added. Layouts were checked with `layoutGridDiagram`/`layoutSequence` (no problems) and by a static render.
